# 動作確認

## 前提条件

- `docker compose up -d`（postgres起動）・`cd backend && uv run alembic upgrade head`・`docker exec -i naw-fastapi-postgres psql -U root -d postgres < backend/seed.sql` を実行済み
- `cd backend && uv run uvicorn app.main:app --port 8000 --reload` でバックエンドを起動
- `cd frontend && npm run dev` で開発サーバーを起動
- 確認はヘッダレスブラウザ（Playwright）を用いてClaude Codeが実施。`chromium-cli` は環境に未導入だったため、Playwrightで簡易ドライバスクリプトを作成して代用した

## 動作確認中に判明した既存バグ（issue-17スコープ外）

実ブラウザからログインを試みたところ、以下2件の**既存バグ**により、ブラウザからの実ログインが一切成立しないことが判明した。いずれもissue-17（共通レイアウト）の実装以前からの問題であり、今回の対応範囲外のため別途Issue化し、今回は修正していない。

1. **CORS未設定**: `backend/app/main.py` にCORSミドルウェアが設定されておらず、`http://localhost:5173` からのAPIリクエストがブラウザにブロックされる
2. **セッションAPIのパス重複**: `frontend/src/lib/constants/api-paths.ts` の `API_PATHS.AUTH.SESSION` が `/api/auth` になっており、`api-client.ts` が付与する `/api` プレフィックスと重複し `http://localhost:8000/api/api/auth` にリクエストされる

このため、今回の共通レイアウト自体（issue-17の実装物）の検証は、上記2件の影響を受けないよう `/api/auth/login` と `/api/auth` へのリクエストをブラウザ側でスタブ（正常レスポンスを返すモック）した上で実施した。ログインフォームの入力・送信自体は実施しており、フォームからログインAPIを呼び出す既存の導線（issue-15実装分）は変更していない。
