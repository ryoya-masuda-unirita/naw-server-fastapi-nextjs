# 02_基本設計

## 変更対象レイヤー

- フロントエンドのみ（バックエンドの変更なし）
  - ルーティング層（ルート定義・認証ガード）
  - レイアウト層（共通シェル・サイドバー・ユーザーメニュー）
  - UI状態管理層（サイドバーの開閉状態）
  - i18nリソース（サイドバー・ユーザーメニューの文言）

## 画面構成の方針

### レイアウトコンポーネントの構成

Angular実装を調査した結果、実際の挙動としては「ユーザー向け」「管理者向け」の2つの独立したレイアウトコンポーネントが使い分けられているのではなく、**1つの共通シェルが、渡された設定（表示するナビゲーション項目・ユーザーメニュー項目などのまとまり）に応じて表示内容を出し分ける**という構成になっている。今回のReact移植でもこの構成を踏襲し、共通シェル1つに対して設定を渡す形で実装する。

シェルの責務は以下の3つに限定する。

1. サイドバー（ロゴ・折りたたみ操作・ナビゲーション領域・ユーザーメニュー）の表示
2. メインコンテンツ領域への画面切り替え（ルーティングされた子画面をそのまま表示する領域）
3. サイドバーの開閉状態（折りたたみ・モバイル表示）の参照

管理者モードへの切替に伴う表示変更（前述の「URLベースの自動モード判定」「管理者画面切替」）は、管理者コンソール本体の実装時にあわせて追加する。今回はロールに応じたメニュー項目の出し分けの土台（設定を差し替えられる構造）のみを用意し、実際に差が出る項目は作らない。

### ナビゲーション項目

チャット・ライブラリなど、対応する機能がまだ存在しない項目は表示しない。将来項目を追加する際は、設定に項目を追加するだけで反映できる構造とする。今回のスコープでは、サイドバーのナビゲーション領域は実質的に空、もしくはダッシュボードへの導線のみとなる。

### ユーザーメニュー

表示する項目は「パスワード設定」「ログアウト」の2つのみとする。いずれも既存の認証まわりの処理（パスワードリセット画面への遷移・ログアウト処理）に接続する。クレジット確認・管理者切替は今回作らない。

### ダッシュボード画面

共通レイアウト配下に、内容を持たないプレースホルダー画面を1つ用意する。ログイン・パスワードリセット完了後の遷移先として機能することの確認のみを目的とする。

## ルーティング・認証ガードの変更概要

- 既存の認証ガード（未認証時にログイン画面へリダイレクトする仕組み）を、共通レイアウト配下の画面群に適用できるよう拡張する
- 認証済みの状態で共通レイアウト配下の画面へアクセスした場合に、レイアウトとプレースホルダー画面が表示されることを確認できるようにする

## UI状態管理の方針

サイドバーの折りたたみ状態・モバイル表示状態は、画面をまたいで参照される可能性がある（将来チャット等の機能でも同じ状態を参照する見込み）ため、既存の認証状態管理と同様の方式（グローバルなUI状態ストア）で管理する。今回管理する状態は「折りたたみ状態」「モバイル表示の開閉状態」の2つに限定し、Angular実装にある管理者モード・戻るモード・ライブラリ詳細モードは含めない。

## 影響範囲

- 既存の認証画面（ログイン・パスワードリセット）・認証状態管理には変更を加えない（遷移先が実際に表示されるようになる点のみ影響）
- 既存のAPIクライアント・バックエンドには変更なし
- 新規追加となるレイアウト・ナビゲーション・ユーザーメニューまわりの見た目は、既存のデザイントークン（認証画面ですでに移植済みのカラー・コンポーネントクラス）を再利用する
