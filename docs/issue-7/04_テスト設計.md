# 04 テスト設計

## テスト方針

- **ユニットテスト**: サービスレイヤーのビジネスロジック
- **統合テスト**: DB を含むエンドポイント動作確認
- **例外ケース**: 認証失敗・パスワード不一致・ポリシー違反など

テストフレームワーク: `pytest` + `pytest-asyncio`

## テスト実行コマンド

```bash
# 全テスト実行
pytest backend/tests/ -v

# 特定ファイルのテスト実行
pytest backend/tests/services/test_password_service.py -v
pytest backend/tests/services/test_auth_service.py -v
pytest backend/tests/api/test_auth.py -v

# カバレッジ報告
pytest backend/tests/ --cov=backend/app --cov-report=html
```

## テスト用フィクスチャ

### conftest.py で提供する主要フィクスチャ

| フィクスチャ | 用途 |
|---|---|
| `db_session` | DB セッション |
| `test_tenant` | テナント（tenant_id="test"） |
| `test_user` | ユーザー（login_id="test"） |
| `test_user_with_password` | パスワード履歴付きユーザー |
| `valid_jwt_token` | 有効な JWT トークン |
| `expired_jwt_token` | 有効期限切れ JWT |
| `invalid_jwt_token` | 不正な JWT |

## テスト前提条件

1. **bcrypt コスト**: テスト用に低コスト設定（コスト=4）を使用する
2. **タイムゾーン**: UTC で統一
3. **シード データ**: 各テスト前に初期化（admin テナント・ユーザー）
