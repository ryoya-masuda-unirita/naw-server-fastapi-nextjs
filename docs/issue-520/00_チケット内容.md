# waha-emulator をノードと線でワークフローを組める GUI 付きに作り変える

## 概要

waha-emulator を、Waha! Transformer の Designer のように、GUI（ノードと線）でワークフローを組める作りに作り変える。SecuAiGent の画面で設定したサービス ID（アシスタント ID、フォルダの学習・削除・同期のサービス名）で、組んだワークフロー（エージェント含む）を呼び出せるようにする。

## 説明

### 背景

- 今の waha-emulator は、サービス ID ごとに決まった流れ（検索 → 生成AI、埋め込みの学習・削除・同期）を `workflows.json` に書いて起動時に読む作り。流れを自由に組めず、変えるたびに再起動が要る
- 本物の Waha! Transformer は、Designer 上でアイコンと矢印でジョブを組む。この体験を、検証用に再現したい
- 目的は、Dify のように対話的にワークフローを組み、SecuAiGent（server-local）から呼んで動作を確かめること

### 本家（Waha! Transformer）の調査結果

公開ページ（https://waha-transformer.com/ ）と、体験版の画面のスクリーンショット 2 枚から分かったこと。

- 画面は MDI。左にジョブのツリー、右に点のグリッドのキャンバス。メニューは ジョブ / オブジェクト / 編集 / 表示 / 実行 / ツール / ウィンドウ / ヘルプ
- 流れは、データ（DB・ファイル・ビュー）と処理（標準・分割・結合）が交互に並び、矢印でつなぐ。処理が処理へ直接つながることはない
- 左ペインは、ジョブ・ビュー（列定義）・構成情報（接続定義）の 3 区分（旧版の画面から読み取り。解像度が低く、見出しは読み違えの可能性がある）
- 処理ノードの中身（ビューフィルタ 9 パターン、140 種類以上の関数）、サービス ID の付け方、REST 連携の仕組みは、公開資料に記載なし

### SecuAiGent 側の設定項目（合わせる対象）

- チャット: アシスタント ID（server-local は `assistantId`、旧名 `wahaServiceId`）を、そのまま `/execute/{serviceId}` のサービス ID にする
- 学習データ: フォルダごとに、追加（`creationServiceName`）・削除（`deletionServiceName`）・取得（`syncServiceName`）のサービス名を持つ

### 巻き戻しの方針

- 着手前の状態にタグ `waha-emulator-before-studio` を付けた（`origin/develop` の時点）。このタグから、作り変え前に戻せる
- 作り変えは PR 単位で小さく分け、各 PR は revert できる状態にする
