# 02_基本設計

## 方針：1 つの内容は、1 か所だけに書く

「正」とする場所を決め、ほかはリンクにする。

| 内容 | 正とする README | ほかの README |
|---|---|---|
| 社内（オンプレ）側の Docker での起動・停止、エミュレーターへの `curl` | オンプレ | リンクのみ |
| エミュレーターをホストで動かす手順、API、ワークフローの設定、環境変数 | エミュレーター | リンクのみ |
| server-local 単体の起動・環境変数 | server-local | ルートのデモ節は、デモ固有の値（接続先のキーなど）だけを残す |
| E2E 探索・E2E 仕様の実行方法 | 各 E2E の README | ルートは入口の 1〜2 行 |
| このリポジトリの概要・構成・入口 | ルート | 各 README は、リンクと固有の 1 文 |
| アダプタの構成・プロバイダ・Tika・Bedrock | 生成AIアダプタ | 相互リンク（今のまま） |

## 変更対象

| README | 変更 |
|---|---|
| 生成AIアダプタ | 「Docker で通して確かめる」を、オンプレのリンクと、アダプタ固有の内容（サービス ID の切り替え・LLM の接続先）だけにする。ログの見方のコンテナ名を直す。「上 2 つ」を直す |
| エミュレーター | 「Docker で起動する」「両方とも Docker で動かす」の手順と `curl` を、オンプレへのリンクにする。ホストで動かす手順は残す |
| ルート | Waha! エミュレーターの節・E2E 探索の節を要約にする。「未移植」「後続の Issue」を直す。「Codex 運用」を末尾の関連ドキュメントへ |
| E2E 仕様・E2E 探索 | 冒頭の同文を短くする |
| 共通部品 | 先頭に目次を付ける（案） |
| チャット | 実装のある場所へ移す（案） |

## 第1承認で決めること（案と推奨）

| 論点 | 案 | 推奨と理由 |
|---|---|---|
| 共通部品 README（約 1,090 行） | A. 分割せず目次を付ける。B. 部品群ごとに分割する | **A**。見出し構造は明瞭で、書かれた部品はすべて実在する。「探しにくい」は目次で解決する。分割は、部品名とファイルの対応が増え、今後の更新（部品を追加するたびにどこに書くか）が重くなる。参照元がないので、あとで分割したくなっても影響は小さい |
| チャット README（200 行） | A. 実装のある場所へ移す。B. そのまま | **A**。いまの場所には、この README しかなく、実装は別の場所にある（読む人が実装を探して迷う）。参照元がないので、移しても壊れるものはない。冒頭の「ここにはこの README だけを置く」の注記は不要になる |
| アシスタントの通信経路・部品ごとの担当（ルートの約 30 行と図 2 枚） | A. ルートに残す。B. `docs/` へ移し、ルートはリンクにする | **A**。ルートにしか書かれておらず、重複ではない。短く、この製品の全体像を知るために最初に読む内容。移すとファイルとリンクが増える |

## 影響範囲

- 変更するのは、README だけ。コード・設定・`docs/issue-*` には触らない
- ほかのファイルからの参照は、ない（確認済み）。チャット README を移すときだけ、README 自身の中の記述を直す
- ルートの節を縮小・削除しても、アンカー参照は壊れない

## 確かめ方

- 変更した箇所のコマンド・パスは、実在・実行を確かめる。オンプレの `curl` は、稼働中の環境に対して実行する
- 全 README の相対リンクの先が実在することを、スクリプトで確かめる
