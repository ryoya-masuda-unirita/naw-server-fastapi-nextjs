## 詳細

### 1. 途中経過ファイルの名前（🔵 提案）→ 対応済み

指摘は正しかった。稼働中の `onprem` で確かめた結果と照合した。`ls` に出たファイル名（`86fd9156….txt`・`a8545ab8….txt`）は、curl の応答の `message_content` の `id` と一致し、curl に渡した `messageId`（`m-509-1`・`m-509-2`）とは違った。README の記述を「`<応答の message_content の id>.txt`。curl の `messageId` ではない」に直し、`08_動作確認.md` の記述（私が「メッセージ ID.txt」と書いていた）も訂正した。README どおりに `m-1.txt` を探すと、見つからず、失敗したと誤解する。

### 2. core の行の「#299」（🔵 提案）→ 対応済み

「検索側（retrieval・検索で使う graphrag）は #299 で移植」に直した。直前に「4 つとも移植済み」と直したのに、同じ表の中に古い言い方が残っていた。

### 3. 「ワークスペースにした理由」（🔵 提案）→ 対応済み

「2 つのテスト」を「複数のパッケージのテスト」に直した。さらに、同じ段落の「エミュレーターは adapter だけをパス依存で入れ」も古かった（エミュレーターの `pyproject.toml` で確認: adapter・retrieval・embedding の 3 つをパス依存で入れる）ので、あわせて直した。「両方をイメージへコピーする」も「各パッケージを」に直した。

### 4. 冒頭の説明（🔵 提案）→ 対応済み

「生成AI・検索・埋め込みのアダプタの Python 移植（Issue #298・#299・#300）」に直した。ルート README の入口の表と範囲が合う。

### 5. ルートから E2E 探索の実行コマンドが消えた（🔵 提案）→ 対応しない

設計（`02_基本設計.md`）で決めた「1 つの内容は 1 か所だけに書く」の結果。実行コマンドは `e2e-explorer/README.md` の「実行方法」にあり、ルートの入口の表からその README へ 1 回のリンクで着く。ルートにも残すと、同じコマンドが 2 か所になり、コマンドが変わったときに古くなる（この Issue で直した問題と同じ種類）。入口としての手数が 1 つ増えることは、承知のうえで、この方針を優先した。PR 本文にも書いてある。
