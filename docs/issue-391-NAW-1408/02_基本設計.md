# 02_基本設計

## 変更対象

- 追加学習の振り分け（新規）: `feedback-local-learning.ts`。フォルダを取り、LOCAL ならローカル用サーバーへ送る。回答精度・満足度で共通
- ローカル用サーバー向けの通信: `local-training-api.ts` に `addLocalAdditionalLearning` を追加
- ローカル用サーバーの失敗の扱い（`viaLocalServer`・`requireUserId`）を `use-training-data-detail.ts` から `local-server-call.ts` へ移し、学習データ詳細と追加学習で共有
- フォルダの取得を `fetchTrainingFolder` として切り出し（詳細画面の `useQuery` と共有）
- `useAddAdditionalLearning`: 送る前に振り分けを呼ぶ
- 型 `AdditionalLearningTarget`、API パス `LOCAL_SERVER.ADDITIONAL_LEARNING`

## 画面 / API 変更概要

- 画面: 変更なし
- クラウド API: 変更なし（フォルダ詳細 `GET /api/admin/indexes/{id}` と接続先 `GET /api/tenants/endpoints/local/{id}` を追加学習の前に呼ぶ）
- ローカル用サーバー API: `POST api/admin/indexes/{id}/additionalLeaning`（`X-Server-Auth-Key`、`X-Tenant-ID`）

## 影響範囲

- フィードバック一覧の追加学習。クラウドのフォルダでも、追加学習の前にフォルダ詳細を 1 回取る呼び出しが増える（移植元と同じ）

## 移植方針

- Angular の `FeedbackLocalLearningService.addIfLocalFolder` を、mutation の中から呼ぶ関数にする（Service は関数に置き換える）
- 移植元の `HttpErrorResponse` 判定は `ApiError` 判定に置き換える

## 不明点・要確認

- 実際のローカル用サーバー（Java）との通信と、https の画面から http の接続先を呼ぶ制約は、#390 と同じく未確認
