# 02_基本設計

## 変更対象

- メッセージ送信リクエストスキーマ（`MessageContentCreateRequest`）
- メッセージ送信サービス（`MessageService.stream_message_content`）
- メッセージ内容の永続化処理（`MessageService._persist_message_content`）
- メッセージ内容リポジトリ（`MessageContentRepository`）

## 画面 / API 変更概要

`POST /api/messages/content`のリクエストボディに`messageContentId`（任意, 既存回答再生成用）を追加する。エンドポイントのパス・レスポンス形式・SSEイベント列は変更しない。

- `messageId`のみ指定: 従来通り新規`MessageContent`を作成する。
- `messageContentId`のみ指定: 指定された既存`MessageContent`を再生成対象とし、ストリーミング完了後にその内容を上書きする。
- どちらも未指定: 400エラー。

## 影響範囲

- `POST /api/messages/content`を呼び出す既存クライアント（`messageId`のみ指定するケース）の挙動に変更はない。
- `messageContentId`の検索をテナントスコープで行うため、他テナントの`messageContentId`を指定した場合は404になる（情報漏洩防止）。

## 移植方針

移植元（Spring Boot）の設計方針をそのまま踏襲する。新規エンドポイントを追加せず、既存の`POST /api/messages/content`にオプショナルフィールドを追加する形で対応する。

- リクエスト解決部分（`resolveStreamContext`相当）: `stream_message_content`冒頭で`messageContentId`が指定されている場合は`MessageContentRepository`経由で既存`MessageContent`を検索し、そこから`message_id`を逆引きして`Message`を解決する。以降の処理（ルームアクセス権チェック・アシスタント解決・クレジット上限チェック・SAAS_CHAT/SAAS_RAG分岐）は共通のまま利用する。
- 永続化部分（`persistMessageContent`相当）: `_persist_message_content`に`existing_content_id: str | None`引数を追加し、指定時は既存レコードをUPDATE、未指定時は従来通りINSERTする。
- トークン使用量（`_persist_token_usage`）は変更不要（常に新規追加のため）。
