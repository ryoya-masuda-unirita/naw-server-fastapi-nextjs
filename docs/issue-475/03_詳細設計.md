# 03_詳細設計

| ファイル | 変更内容 |

## 並べ替えのロジック

### 回答精度評価（`find_feedback_messages`）

- `assistant_name`: `message_feedbacks` に、`Message` を外部結合したうえで `Assistant`（`Assistant.id == Message.assistant_id` かつ `Assistant.tenant_id == tenant_id`）を外部結合し、`Assistant.name` で並べる（小文字化しない。移植元は照合順序に従う）
- `folder_name`: `Index`（`Index.id == MessageFeedback.index_id` かつ `Index.tenant_id == tenant_id`）を外部結合し、`Index.name` で並べる
- 外部結合は、並べ替えに必要なときだけ追加する。件数を数えるクエリには入れない（主キーでの外部結合で行数は変わらないため）
- 同順位は、これまでどおり `MessageFeedback.id` の昇順

### チャット満足度（`find_feedback_rooms`）

- `assistant_name`: 既に外部結合している `Assistant` の `lower(name)` で並べる
- `rating_stars`: `CASE Room.rating WHEN EXCELLENT THEN 5 ... WHEN POOR THEN 1 END` で並べる。星の数は、評価と星の数の対応表（定数）から作る
- 同順位は、これまでどおり `Room.id` の昇順

## 定数

評価と星の数の対応（EXCELLENT=5、VERY_GOOD=4、GOOD=3、AVERAGE=2、POOR=1）を、`RoomRating` に近い場所の定数として 1 か所に置く。

## 削除するコード

呼ばれなくなる `assistant_id` の並べ替え（回答精度評価・チャット満足度）、チャット満足度の `rating`（文字列順）の並べ替えと、対応するテストを削除する。回答精度評価の `rating`（accuracy）の文字列順は変えない。
