# 02_基本設計

## 変更対象

| 一覧 | 並べ替えの項目 | 現状 | 変更後 |
|---|---|---|---|
| 回答精度評価 | アシスタント表示名順 | アシスタント ID | アシスタントの表示名 |
| 回答精度評価 | 学習先フォルダ名順 | 学習先フォルダ ID | 学習先フォルダの名前 |
| チャット満足度 | アシスタント表示名順 | アシスタント ID | アシスタントの表示名（大文字・小文字を区別しない） |
| チャット満足度 | 満足度順 | 評価名の文字列 | 星の数（星 1〜5） |

## 画面 / API 変更概要

- 画面の変更はない（`client/` の変更は #476）
- API のパラメータ・レスポンスの形は変えない。並び順だけが変わる
- 並べ替えは、一覧を取得する 1 回のクエリの中で、アシスタント・学習先フォルダを外部結合して表示値で行う
  - 外部結合にするため、アシスタントが削除された行・学習先フォルダが無い行も一覧に残る
  - 結合条件にテナントを含め、他テナントの値で並ばないようにする
- 満足度順は、評価を星の数（EXCELLENT=5、VERY_GOOD=4、GOOD=3、AVERAGE=2、POOR=1）に置き換えた値で並べる
- 値が無い行（アシスタントや学習先フォルダが無い）は、データベースの NULL の扱いに従う（昇順は末尾、降順は先頭）
- 並び値が同じ行は、これまでどおり ID の昇順にして、ページをまたいでも順序を安定させる

## 影響範囲

- 回答精度評価の一覧 API とチャット満足度の一覧 API の並び順のみ
- 絞り込み・件数・ページ分割・レスポンスの中身は変わらない
- 回答精度評価の「追加学習順」、他の並べ替え（更新日時順・チャット名順）は変えない
- 並べ替えの項目名を内部の列名に対応づける部分は、アシスタント・学習先フォルダ・満足度の 3 項目の対応先が変わる

## 移植方針

- 移植元の方針に合わせる: 表示する名前（アシスタント名・フォルダ名）は名前の列で並べ、満足度は星の数で並べる
- 移植元の大文字・小文字の扱いに合わせる。チャット満足度のアシスタント名は小文字化して比べ、回答精度評価のアシスタント名・学習先フォルダ名はデータベースの照合順序に従う（移植元がそうしているため）
- 移植元は JPA の関連（読み取り専用）で外部結合を作っている。こちらは SQLAlchemy のクエリで外部結合する（移植元と同じ結果になればよい）
- テストを先に書き、修正前に失敗することを確認してから実装する
