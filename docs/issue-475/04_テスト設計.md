# 04_テスト設計

## テスト方針

統合テスト（API 経由・SQLite）で、内部 ID の順と表示値の順が逆になるデータを作り、表示値の順に並ぶことを確かめる。実装前に失敗することを確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| T-01 | 回答精度評価のアシスタント表示名順（昇順） | 内部 ID の順と表示名の順が逆の 3 件 | 表示名の昇順 |
| T-02 | 同（降順） | 同上 | 表示名の降順 |
| T-03 | アシスタントが削除された行 | `assistant_id` が空の行を含める | 一覧に残る（件数は変わらない） |
| T-04 | 回答精度評価の学習先フォルダ名順（昇順・降順） | 内部 ID の順とフォルダ名の順が逆の 3 件 | フォルダ名の順 |
| T-05 | フォルダが無い行 | `index_id` が空の行を含める | 一覧に残る |
| T-06 | 追加学習順 | `sortField=add` | 従来どおり内部のフォルダ ID の順 |
| T-07 | アシスタント絞り込みとの併用 | 1 つのアシスタントで絞り込んで表示名順 | そのアシスタントの行だけが返る |
| T-08 | 他テナントの値 | （実施しない）アシスタント・フォルダの ID は全テナントで一意のため、他テナントの名前と衝突するデータを作れない。結合条件にテナントを含めることはコードで担保する | － |
| T-09 | チャット満足度のアシスタント表示名順 | 大文字・小文字が混ざる名前 | 大文字・小文字を区別せず並ぶ（昇順・降順） |
| T-10 | チャット満足度の満足度順 | 星 1〜5 の 5 件 | 昇順は星 1→5、降順は星 5→1 |
| T-11 | 複数ページ | ページサイズ 2 で全ページを取得 | 重複・欠落がなく、全体が表示値の順 |
| T-12 | 既存の満足度順テスト | `test_sorts_by_level_ascending` | 星の数順の期待に直して成功 |
