## 詳細

### 1. 大文字・小文字の扱い（🔵 提案）→ コメントで明記

移植元は、回答精度評価では `message.assistant.name`（小文字化なし）、チャット満足度では `lower(name)` の相関サブクエリで並べている（`FeedbackSortSpecification`、NAW-1448・NAW-1449）。移植元に合わせたため、挙動は意図どおり。誤って揃えられないように、リポジトリのコメントに理由を書いた。両方を小文字化する案は、移植元と挙動が変わるため見送った（`02_基本設計.md` の移植方針）。

### 2. 値が無い行の位置（🔵 提案）→ 対応しない

移植元（JPA の左結合）も NULL の並びをデータベースの既定に任せており、移植元の設計記録（NAW-1448 の §3）に「昇順は末尾・降順は先頭」と書かれている。`02_基本設計.md` にも同じ方針を書いた。固定すると移植元と挙動が変わる。PostgreSQL の実機で、昇順は末尾・降順は先頭になることを確認した（`08_動作確認.md`）。

### 3. 追加学習順（🔵 提案）→ 対応しない

移植元の `FeedbackMessageListRequest` は `add` を `indexId` のまま残している（NAW-1451 のコミットでも「追加学習順は変更せず」）。画面からの選択肢の削除は client の #476 で扱う。`01_要件定義.md` のスコープ外に書いた。

### 4. 満足度順の `CASE`（🔵 提案）→ 対応しない（確認済み）

指摘は「実 DB で確認する」「降順と 5 件のテストを足す」という趣旨。どちらも済んでいる。

- PostgreSQL 18（ネイティブ enum の `roomrating`）で、星 1〜5 の 5 件を昇順・降順の両方で取得し、期待どおりの順になった（`08_動作確認.md`）
