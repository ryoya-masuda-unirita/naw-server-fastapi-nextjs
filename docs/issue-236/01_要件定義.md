# 01_要件定義

## 背景

移植元（Spring Boot）は、アシスタント種別・インデックス種別・評価などの列挙値を varchar 列に文字列で保存している（JPA の `EnumType.STRING`）。そのため、これらの列での並べ替えは文字列順（辞書順）になる。

移植先は同じ列を PostgreSQL のネイティブ ENUM 型で持つ。ネイティブ ENUM の並べ替えは型を宣言したときの値の順序になるため、文字列順と並びが変わる。

| 列 | 移植先の宣言順（現状の昇順） | 移植元の文字列順（あるべき昇順） |
|---|---|---|
| アシスタント種別 | SECURE → SAAS_CHAT → SAAS_RAG | SAAS_CHAT → SAAS_RAG → SECURE |
| インデックス種別 | SAAS_GLOBAL → LOCAL | LOCAL → SAAS_GLOBAL |
| ルームの評価 | EXCELLENT → VERY_GOOD → GOOD → AVERAGE → POOR | AVERAGE → EXCELLENT → GOOD → POOR → VERY_GOOD |
| メッセージの評価 | GOOD → BAD | BAD → GOOD |

ユーザー一覧の権限（role）での並べ替えは、同じ理由で既に文字列にしてから並べる対応が入っている。

自動テストの DB（SQLite）は列挙値を文字列で持つため、この差は自動テストの実行結果には現れない。

## 機能要件

1. アシスタント一覧で種別（`type` とその別名）を並べ替えに指定したとき、種別の文字列順で並ぶこと
2. インデックス一覧で種別（`type`）を並べ替えに指定したとき、種別の文字列順で並ぶこと
3. グループのアシスタント一覧で種別（`type` とその別名）を並べ替えに指定したとき、種別の文字列順で並ぶこと
4. 横展開: ネイティブ ENUM 列で並べ替えるほかの一覧も、移植元が varchar で持つ列であれば文字列順で並ぶこと
   - フィードバックのルーム一覧（評価 `level` での並べ替え）
   - フィードバックのメッセージ一覧（評価 `accuracy` での並べ替え）
5. ユーザー一覧の権限での並べ替えは現状の挙動（文字列順）を変えないこと
6. 並べ替え以外（絞り込み・件数・レスポンス形式）は変えないこと

## 非機能要件

- データベースの型変更（マイグレーション）は行わない
- 文字列にする処理は共通化し、各一覧で同じ書き方にする
- PostgreSQL で実行される SQL に文字列への変換が入ることを自動テストで確認できること（SQLite では並びの差が出ないため）

## スコープ外

- 列挙値を数値で持つ列（ファイルの状態など。移植元も序数で持つ）
- 真偽値での並べ替え（チーム所属ユーザー一覧の権限など）
- 並べ替えを指定できない一覧
