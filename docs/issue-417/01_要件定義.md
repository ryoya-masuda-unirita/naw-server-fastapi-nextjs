# 01_要件定義

## 背景

- e2e-spec の専用環境では、画面を開発サーバー（Vite）で配信している。開発サーバーは通し実行中にアイドルでも CPU・メモリを大きく使う（CPU 46%・メモリ 1.3GB）。一方 backend は CPU 2% でほぼ遊んでおり、ボトルネックは画面の配信側と考えられる（#397 の動作確認）。
- 並列 2 の通し実行で、14-24（一覧が空のまま）・14-28（ページ遷移の中断）・15-08（削除後も行が残る）が負荷で落ちる。単独実行では OK。
- 本番は CloudFront + S3 によるビルド済みの静的配信で、開発サーバーは使わない。専用環境も同じ形にすれば、負荷の質が本番に近づく。

## 機能要件

- 専用環境の画面を、ビルド済みの静的ファイルとして配信する。
- 画面の URL・ポートは今のまま（ブラウザから同じアドレスで開ける）にし、テスト側の接続先を変えなくてよいようにする。
- 画面から backend への通信先は、今と同じく専用環境の backend の公開ポートにする。
- 画面の URL を直接開いても（ブラウザの再読み込み・別タブ・直接遷移）、画面が表示される。
- 既存の開発用環境・手元のデモ・e2e-explorer には影響を与えない。

## 非機能要件

- 通し実行（並列 2）を 2 回続けて、07-16・17-16〜17-21 を除き NG 0。
- 期待値や待ち時間を緩めて NG を隠さない。静的配信にして応答が速くなったことで、テスト側の待ち方の不備が表に出た場合は、実ブラウザでも起こる問題かを見極めたうえで、待ち方を直す。
- 起動・破棄の手順（`npm run spec:all`）は変えない。

## スコープ外

- 07-16（項目書と移植元の食い違い。#396）と 17-16〜17-21（テストが古い。別 Issue）。
- 並列数の見直し、backend の性能改善。
- 本番・開発用の画面配信の変更。
