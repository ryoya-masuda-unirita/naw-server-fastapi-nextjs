# 02_基本設計

## 変更対象

専用環境（e2e-spec が起動する Docker 環境）の「画面を配信する部分」だけ。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 画面の配信 | 開発サーバーが起動し、ソースを都度変換して配信 | 画面を 1 回ビルドし、静的配信用の軽量な Web サーバーでビルド結果を配信 |
| 配信ポート | 5173 | 5173（変更なし） |
| backend の呼び先 | 専用環境の backend の公開ポート | 同じ（ビルド時に画面へ埋め込む） |
| 起動の健全性確認 | 開発サーバーの応答 | 静的配信サーバーの応答 |

## 画面 / API 変更概要

- 画面・API の仕様変更はない。
- 画面は、ビルド時に backend の URL を埋め込む。本番用の設定（配信元と同じドメインの別パスを呼ぶ前提）は専用環境には合わないため、専用環境ではビルド時に backend を直接指す値で上書きする。
- 画面の URL を直接開いたときに画面が出るよう、存在しないパスは画面の入口に戻す設定（SPA 用）を入れる。
- 静的配信にして応答が速くなると、これまで遅さで隠れていたテスト側の待ち方の不備が出る可能性がある。その場合は、実ブラウザでも起こる現象（例: 入力欄のフォーカス移動に伴うレイアウトのずれ、ログイン直後の画面遷移への割り込み、再描画の途中での読み取り）かを確認し、期待値は変えずに待ち方だけを直す。

## 影響範囲

- 専用環境の起動に、画面のビルドが加わる。初回は起動が長くなる（キャッシュが効けば短縮）。
- テストの接続先・ポート・起動コマンドは変わらない。
- 他の環境（開発用・デモ・e2e-explorer）、本番、アプリ本体のコードには触れない。
- 既存の画面のテスト（e2e-spec の全項目）が、配信方式の変更後も同じ期待値で通ること。
