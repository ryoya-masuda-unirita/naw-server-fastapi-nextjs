# 04_テスト設計

## 方針

この Issue はテスト環境の変更なので、確認の対象は「専用環境で e2e-spec の全項目が、負荷でぶれずに通ること」。アプリ本体のテストは変えない。

## 確認項目

| # | 確認 | 期待結果 |
|---|---|---|
| 1 | 専用環境の起動 | 画面が静的配信で立ち上がり、起動の健全性確認を通る。開発サーバーのプロセスは使われない |
| 2 | 画面の表示と直接アクセス | 画面の URL を直接開いても、再読み込みしても、画面が表示される |
| 3 | backend の呼び先 | ログインなどの API 呼び出しが、専用環境の backend に届く |
| 4 | 通し実行（並列 2）1 回目 | 07-16・17-16〜17-21 を除き NG 0 |
| 5 | 通し実行（並列 2）2 回目 | 同上 |
| 6 | 配信側の負荷 | 通し実行中の画面コンテナの CPU・メモリが、開発サーバー（CPU 46%・メモリ 1.3GB）より大きく下がる |
| 7 | 他の環境への影響 | 開発用・デモ・e2e-explorer の環境が起動中でも、専用環境の起動・破棄でそれらを壊さない |
| 8 | 静的検査 | e2e-spec の lint・型チェックが通る |

## 失敗時の扱い

- 落ちた項目は、単独で再実行して負荷によるものか、待ち方の不備か、テストが古いかを切り分ける。
- 待ち方の不備は、実ブラウザでも起こるかを確かめたうえで、期待値を変えずに直す。
