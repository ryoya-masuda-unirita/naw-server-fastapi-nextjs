# 03_詳細設計

## DBマイグレーション

### 011_add_rooms_and_room_pins.py

移植元Liquibase（`rooms/changeset-001〜008`、`room_pins/changeset-001〜003`）の最終形に合わせて、RLS関連を除いた1本のAlembicマイグレーションを追加する。

```
rooms
  id                    varchar(32) PK
  tenant_id             varchar(32) not null, FK -> tenants.id ON DELETE CASCADE
  name                  varchar(255) nullable
  default_assistant_id  varchar(32) not null, FK -> assistants.id ON DELETE RESTRICT
  user_id               uuid not null, FK -> users.id ON DELETE CASCADE
  created_at            timestamptz not null default now()
  updated_at            timestamptz not null default now()
  rating                varchar(32) nullable
  UNIQUE (id, tenant_id)

room_pins
  user_id               uuid not null
  tenant_id             varchar(32) not null, FK -> tenants.id ON DELETE CASCADE
  room_id               varchar(32) not null, FK -> rooms.id ON DELETE CASCADE
  PK (user_id, tenant_id, room_id)
```

- `rooms.rating` は移植元最終スキーマに存在するためカラム自体は持たせるが、本Issueでは利用しない
- `share_url` は移植元最終形で削除済みのため追加しない
- 移植元のRLS changesetは本バックエンドの既存方針に合わせて取り込まない
- `room_pins.user_id` は移植元最終形に合わせて `users.id` と同じ `uuid` 型で作成する

## モデル

### `app/models/room.py`（新規）

```python
class RoomRating(str, Enum):
    EXCELLENT = "EXCELLENT"
    VERY_GOOD = "VERY_GOOD"
    GOOD = "GOOD"
    AVERAGE = "AVERAGE"
    POOR = "POOR"


class Room(SQLModel, table=True):
    __tablename__ = "rooms"

    id: str = Field(max_length=32, primary_key=True, default_factory=lambda: uuid.uuid4().hex)
    tenant_id: str = Field(sa_column=sa.Column(sa.String(32), sa.ForeignKey("tenants.id", ondelete="CASCADE"), nullable=False))
    name: str | None = Field(default=None, max_length=255)
    default_assistant_id: str = Field(sa_column=sa.Column(sa.String(32), sa.ForeignKey("assistants.id", ondelete="RESTRICT"), nullable=False))
    user_id: uuid.UUID = Field(sa_column=sa.Column(sa.UUID, sa.ForeignKey("users.id", ondelete="CASCADE"), nullable=False))
    created_at: datetime = Field(sa_column=sa.Column(sa.DateTime(timezone=True), nullable=False, server_default=sa.func.now()))
    updated_at: datetime = Field(sa_column=sa.Column(sa.DateTime(timezone=True), nullable=False, server_default=sa.func.now(), onupdate=sa.func.now()))
    rating: RoomRating | None = Field(default=None, sa_column=sa.Column(sa.Enum(RoomRating, name="roomrating", create_type=True), nullable=True))


class RoomPin(SQLModel, table=True):
    __tablename__ = "room_pins"

    user_id: uuid.UUID = Field(sa_column=sa.Column(sa.UUID, primary_key=True, nullable=False))
    tenant_id: str = Field(sa_column=sa.Column(sa.String(32), sa.ForeignKey("tenants.id", ondelete="CASCADE"), primary_key=True, nullable=False))
    room_id: str = Field(sa_column=sa.Column(sa.String(32), sa.ForeignKey("rooms.id", ondelete="CASCADE"), primary_key=True, nullable=False))
```

- `RoomPin` は `GroupAssistant` と同様の中間テーブルモデルとして定義する
- `rooms` の `UNIQUE (id, tenant_id)` は、移植元最終形との互換性維持のためマイグレーション側で付与する

## スキーマ

### `app/schemas/room.py`（新規）

```python
class RoomCreateRequest(BaseModel):
    name: str
    assistantId: str


class RoomUpdateRequest(BaseModel):
    name: str


class RoomResponse(BaseModel):
    id: str
    tenantId: str
    name: str | None
    defaultAssistantId: str
    userId: UUID
    createdAt: datetime
    updatedAt: datetime


class RoomListItemResponse(RoomResponse):
    pinned: bool


class PagedRoomResponse(BaseModel):
    content: list[RoomListItemResponse]
    totalElements: int
    number: int
    size: int
```

- `assistant.py` と同様、レスポンスは camelCase に統一する
- リクエストの `name` は Pydantic では必須のみを担保し、255文字超過時の切り詰めは移植元準拠でサービス層で行う
- `GET /api/rooms` は `PagedRoomResponse`、`GET /api/rooms/{roomId}`・`POST /api/rooms`・`PATCH /api/rooms/{roomId}` は `RoomResponse` を返す

## ルーター

### `app/routers/rooms.py`（新規）

`assistants.py` と同じ依存注入パターンで、一般ユーザー向けルーターを追加する。

| メソッド | パス | レスポンス |
|---|---|---|
| GET | `/api/rooms` | `PagedRoomResponse` |
| GET | `/api/rooms/{room_id}` | `RoomResponse` |
| POST | `/api/rooms` | `RoomResponse` |
| PATCH | `/api/rooms/{room_id}` | `RoomResponse` |
| DELETE | `/api/rooms/{room_id}` | `204 No Content` |
| POST | `/api/rooms/{room_id}/pin` | `204 No Content` |
| DELETE | `/api/rooms/{room_id}/pin` | `204 No Content` |

- 依存関係は全エンドポイントで `get_verified_tenant_id`、`get_current_user`、`get_session` を使う
- クエリパラメータは移植元と同様に `page=0`、`size=20`、`name=None` を受ける
- `page` は `ge=0`、`size` は `ge=1, le=100` とし、移植元コントローラの手動バリデーションを FastAPI 側の宣言的バリデーションへ置き換える

## リポジトリ

### `app/repositories/room_repository.py`（新規）

- `find_page_by_login_id(tenant_id, login_id, page, size, name, session) -> tuple[list[Room], int]`
  - `users` と `room_pins` を利用して、対象ログインユーザー所有ルームのみに絞り込む
  - ソートは `CASE WHEN room_pins.room_id IS NOT NULL THEN 0 ELSE 1 END, rooms.updated_at DESC`
  - `name` 指定時は `LOWER(name) LIKE %...%` で部分一致
  - `count` と `limit/offset` は既存 `AssistantService` と同じく手動で返す
- `find_by_id_and_login_id(room_id, tenant_id, login_id, session) -> Room | None`
- `find_by_id_and_tenant_id(room_id, tenant_id, session) -> Room | None`
- `create(room, session) -> Room`
- `delete(room, session) -> None`

### `app/repositories/room_pin_repository.py`（新規）

- `find_pinned_room_ids_by_login_id(tenant_id, login_id, session) -> set[str]`
- `find_by_login_id_and_room_id(tenant_id, login_id, room_id, session) -> RoomPin | None`
- `create(room_pin, session) -> None`
- `delete(room_pin, session) -> None`

`login_id` から `user_id` への解決は、各メソッド内で `users` をサブクエリまたは JOIN して1クエリで行い、サービス層でユーザー解決用の追加クエリを増やさない。

## サービス

### `app/services/room_service.py`（新規）

`backend/AGENTS.md` の「service から別 service を呼ばない」方針に従い、移植元の `RoomAccessService` は別サービスとしては作らず、`RoomService` 内の private helper で所有者・テナント検証を行う。

- `list_rooms(tenant_id, current_user, page, size, name, session) -> PagedRoomResponse`
  - `RoomRepository.find_page_by_login_id` で一覧と総件数を取得
  - `RoomPinRepository.find_pinned_room_ids_by_login_id` で固定済みID集合を取得
  - 各ルームを `RoomListItemResponse` に変換し、`pinned` を設定する
- `get_room(room_id, tenant_id, current_user, session) -> RoomResponse`
  - 自ユーザー所有のルームのみ取得し、見つからなければ404
- `create_room(tenant_id, current_user, req, session) -> RoomResponse`
  - `assistantId` が同一テナントの既存アシスタントを指すことを確認し、不正なら400
  - `name` は255文字超過時に切り詰める
  - `Room` を新規作成して保存する
- `update_room(room_id, tenant_id, current_user, req, session) -> RoomResponse`
  - 自ユーザー所有のルームのみ更新可能
  - `name` は255文字超過時に切り詰める
- `delete_room(room_id, tenant_id, current_user, session) -> None`
  - 自ユーザー所有のルームのみ削除可能
  - `rooms.user_id` と `room_pins.room_id` の FK/CASCADE により関連固定レコードは自動削除される
- `pin_room(room_id, tenant_id, current_user, session) -> None`
  - 自ユーザー所有ルームのみ対象
  - 既存固定レコードがある場合は何もせず成功とする
  - 未固定時のみ `RoomPin` を追加する
- `unpin_room(room_id, tenant_id, current_user, session) -> None`
  - ルーム自体が存在しない場合は404
  - ルームは存在するが固定されていない場合も移植元準拠で404

### `app/services/assistant_service.py`（既存修正）

- `delete_assistant` に `IntegrityError` ハンドリングを追加する
- `rooms.default_assistant_id` の FK 制約違反で削除失敗した場合は `session.rollback()` のうえ、`400 Bad Request` として返す
- メッセージは「このアシスタントを使用中のルームが存在するため削除できません。」相当の業務エラーとし、素の500を出さない

## 参照実装との差分メモ

- 移植元の `/api/admin/histories*` と `/api/rooms/{roomId}/feedback` は本Issueでは実装しない
- 移植元の share 情報（`shareUrl`、`teamIds`）は share ドメイン未移植のため今回のレスポンスから除外する
- 移植元では room と pin のアクセス判定を `RoomAccessService` に分けているが、本バックエンドでは service 間呼び出し禁止ルールに合わせて `RoomService` 内で閉じる
