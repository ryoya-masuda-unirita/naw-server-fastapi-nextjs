# 01_要件定義

## 背景

- チャット機能（room/message）は本SaaSの中核機能だが、いずれも未移植。まずルーム管理（room）を先行して実装し、メッセージ送受信（SSEストリーミング）機能の土台とする
- 移植元にはルーム管理者向け履歴一覧、フィードバック（評価）、共有（share）、ルーム作成時のテナント別クレジット上限チェックといった関連機能があるが、依存ドメイン（フィードバック集計、共有、プラン・サブスクリプション・トークン利用量）が未移植のため対象外とする

## 機能要件

- 認証済みユーザーが自分のルーム一覧を取得できる（ページネーション、ルーム名の部分一致検索、固定ルームを先頭に表示した上で更新日時降順）
- 認証済みユーザーが自分のルームを単体取得できる
- 認証済みユーザーがルームを作成できる（ルーム名・デフォルトアシスタントIDを指定）
- 認証済みユーザーが自分のルームの名前を更新できる
- 認証済みユーザーが自分のルームを削除できる
- 認証済みユーザーが自分のルームを固定・固定解除できる
  - 既に固定済みのルームを再度固定した場合は冪等に成功する
  - 固定されていないルームの固定解除は失敗する（移植元仕様に合わせる）
- ルームは常にテナント・ログインユーザー単位でスコープされ、他ユーザーのルームは操作・参照できない

## 非機能要件

- 全エンドポイントで認証（JWT）とテナントID（`X-Tenant-ID`）検証を必須とする
- ルーム名は255文字を超える場合は切り詰める（移植元と同じ挙動）
- ルームのデフォルトアシスタントは既存のアシスタントを参照する必要があり、参照されている間はそのアシスタントの削除を拒否する（移植元の最終スキーマ準拠）。アシスタント削除APIが素のDB制約違反により500を返すことのないよう、参照エラー時は400を返すようにする

## スコープ外

- メッセージ送受信API（SSEストリーミング、LLM連携）
- ルーム共有API（share）、およびルーム一覧・単体取得レスポンスの共有先情報（共有URL・共有先チーム一覧）
- ルームフィードバック（評価）作成API、および評価値を保持するカラム
- 管理者向けルーム履歴一覧・詳細取得API
- ルーム作成時のテナント月次クレジット上限チェック（プラン・サブスクリプション・トークン利用量が未移植のため）
- フロントエンド対応（React／Angular）
