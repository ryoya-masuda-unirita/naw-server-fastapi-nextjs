# 02_基本設計

## 変更対象

- 新規テーブル: ルーム（rooms）、ルーム固定（room_pins）
- 新規API: ルーム一覧取得・単体取得・作成・更新・削除、固定・固定解除

## 画面 / API 変更概要

| メソッド | パス | 概要 |
|---|---|---|
| GET | /api/rooms | ルーム一覧取得（ページネーション・ルーム名絞り込み、固定優先→更新日時降順） |
| GET | /api/rooms/{roomId} | ルーム単体取得 |
| POST | /api/rooms | ルーム作成 |
| PATCH | /api/rooms/{roomId} | ルーム名更新 |
| DELETE | /api/rooms/{roomId} | ルーム削除 |
| POST | /api/rooms/{roomId}/pin | ルーム固定 |
| DELETE | /api/rooms/{roomId}/pin | ルーム固定解除 |

## 影響範囲

- アシスタント: ルームのデフォルトアシスタントとして参照されるようになる。参照中のアシスタント削除がDB制約で拒否されるようになるため、既存のアシスタント削除処理に、参照エラー発生時は400を返すハンドリングを追加する必要がある
- ユーザー: ルーム所有者としての参照が増える（ユーザー削除時、所有するルームも削除する）
- テナント: テナント削除時、配下のルームも削除する

## 移植方針

- 移植元は複数のchangesetを経てスキーマが進化しているが、本バックエンドは既存の他テーブル同様、最終形を1本のAlembicマイグレーションとして作成する
- ルームは、ID・所属テナント・ルーム名（任意）・デフォルトアシスタントID・所有ユーザー・作成日時・更新日時を持つ。ルーム名は移植元と同様に必須項目とする
- ルーム固定は、ユーザー・テナント・ルームの組で一意な固定レコードとして表現する（移植元同様の複合キー）
- フィードバック（評価）機能が対象外のため、評価値を保持するカラムは今回は追加しない
- Row Level Security（PostgreSQLのセッション変数によるテナント分離）は移植元で導入されているが、本バックエンドの既存テーブルはいずれも未導入のため、本Issueでも導入しない。アプリケーション層での`X-Tenant-ID`検証によるテナント分離という既存方針を踏襲する
- 一覧レスポンスは既存の`Paged*Response`（`content`/`totalElements`/`number`/`size`）パターンに合わせて新設する
