# 04_テスト設計

## テスト方針

インフラと CI の設定変更なので、自動テストは追加しない。静的な検証（フォーマット・構文・参照の残り）と、別アカウントでの手動確認で担保する。AWS への `apply` は実行しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | state 用構成の整合 | フォーマットと構文の検証 | エラーなし |
| 2 | 本体の整合 | backend を使わずに初期化したうえで検証 | エラーなし |
| 3 | 参照の残り | 削除した state バケットのリソースを参照する箇所を検索 | 残っていない |
| 4 | 暗号化・保護 | state 用構成の内容を確認 | バージョニング、AES256、public block、`prevent_destroy` がある。DynamoDB がない |
| 5 | バケット名 | 構成の内容を確認 | アカウント ID を含む |
| 6 | push で apply されない | ワークフローの条件を確認 | push のとき、インフラのジョブがスキップされる |
| 7 | 手動実行の既定 | 入力を指定せずに手動実行する想定の条件を確認 | インフラのジョブはスキップされる |
| 8 | 手動実行（明示） | 入力を true にした想定の条件を確認 | インフラのジョブが実行される |
| 9 | backend・frontend の自動デプロイ | push のとき、インフラのジョブがスキップされた条件 | backend・frontend のジョブは、変更があれば実行される |
| 10 | 変数未登録 | state バケット名の変数が空 | 原因が分かるメッセージで失敗する |
| 11 | 秘密の混入 | 追加・変更したファイルを確認 | バケット名の実値、アカウント ID、認証情報が含まれない。backend 設定の実体は git 管理されない |
| 12 | 手順の再現性 | README の手順を、別アカウント（`oic`）で実施 | state バケットが作られ、本体の初期化が通る（ユーザーが実施） |
