# 03_詳細設計

## 1. state 用バケットの構成（新規）`infra/bootstrap/`

| ファイル | 内容 |
|---|---|
| `main.tf` | `terraform`（`required_version >= 1.5.0`、aws `~> 5.0`）、provider、変数、リソース、出力 |
| `.terraform.lock.hcl` | `terraform init` で生成し、git 管理する |

- 変数: `region`（既定 `ap-northeast-1`）、`project_name`（既定 `naw-fastapi`）
- `data.aws_caller_identity.current` のアカウント ID から、`local.bucket_name = "${var.project_name}-tfstate-${account_id}"` を作る
- リソース（移植元 `bootstrap/main.tf` と同じ構成。DynamoDB は作らない）
  - `aws_s3_bucket.tfstate`（`lifecycle { prevent_destroy = true }`。`force_destroy` は付けない）
  - `aws_s3_bucket_versioning.tfstate`（Enabled）
  - `aws_s3_bucket_server_side_encryption_configuration.tfstate`（AES256）
  - `aws_s3_bucket_public_access_block.tfstate`（4 項目すべて true）
  - 各リソースの説明コメントは「なぜ」を書く（現行 `tfstate_backend.tf` のコメントを引き継ぐ）
- 出力: `state_bucket_name`、`backend_config`（`bucket = "…"` の1行。`infra/backend.hcl` にそのまま貼れる形）
- state はローカルのまま（`.gitignore` の `infra/**/*.tfstate` で除外済み）。失うと管理から外れるので、README に「bootstrap の state は消さない。消えても `terraform import` で復元できる」と書く

## 2. インフラ本体の backend（`infra/main.tf`）

- `backend "s3"` を部分設定にする（`bucket` は書かない）

```hcl
backend "s3" {
  key          = "infra/terraform.tfstate"
  region       = "ap-northeast-1"
  use_lockfile = true
}
```

- 現行の「移行手順（初回のみ…）」コメントを削除し、「バケット名は `terraform init -backend-config=backend.hcl`（CI は `-backend-config="bucket=…"`）で渡す。backend ブロックでは変数が使えないため」と書く
- provider 直上のコメントのプロファイル名 `naw-fastapi-issue158` を `oic` に直す（固定しない方針は変えない）
- `infra/tfstate_backend.tf` を削除する。削除前に、`aws_s3_bucket.tfstate` を参照している箇所（出力・IAM・README など）を grep し、残っていれば同時に消す

## 3. backend 設定ファイル

- `infra/backend.hcl.example`（新規。git 管理）: `bucket = "<bootstrap の出力 state_bucket_name>"`
- `.gitignore` に `infra/**/backend.hcl` を足す（実体は git 管理しない）

## 4. ワークフロー

### `deploy.yml`
- `workflow_dispatch` に入力を足す

```yaml
workflow_dispatch:
  inputs:
    run_infra:
      description: "インフラ（terraform apply）も実行する"
      type: boolean
      default: false
```

- `infra` ジョブの条件を `if: github.event_name == 'workflow_dispatch' && inputs.run_infra` にする（push では常にスキップ）。手動実行のときは、パスの変更判定に頼らない（push 以外ではフィルタの比較元が定まらないため）
- 不要になる `changes` ジョブの `infra` 出力と、paths-filter の `infra` フィルタ（`infra/**`・`!infra/route53/**`）を削除する（呼び出し元がなくなるため）。backend・frontend の判定は変えない
- `backend`・`frontend` ジョブの `needs.infra.result == 'success' || 'skipped'` の条件は維持する
- ファイル先頭のコメント（「develop への push で自動デプロイされるトリガーを有効化」）を、「インフラは手動実行のみ」の説明に直す

### `deploy-infra.yml`
- `Terraform Init` を `terraform init -backend-config="bucket=${{ vars.TF_STATE_BUCKET }}"` にする
- `workflow_call` のまま変えない。`vars.TF_STATE_BUCKET` が未登録のときに原因が分かるよう、init の前に空チェックのステップを足し、空ならメッセージを出して失敗させる

## 5. README（`infra/README.md`）

- 「鶏卵問題」の節と作り直し手順（backend のコメントアウト → apply → 戻す）を、次の手順に置き換える
  1. `AWS_PROFILE=oic` で `infra/bootstrap` を `init` / `apply`（初回のみ）
  2. 出力 `backend_config` を `infra/backend.hcl` に保存し、`terraform init -backend-config=backend.hcl`
  3. GitHub の Secrets / Variables を登録（`AWS_ROLE_ARN` などの既存分に加え、Variable `TF_STATE_BUCKET`）
  4. `terraform apply`（ローカル）。2 回目以降の CI からの適用は、Actions の `Deploy` を手動実行し `run_infra` を true にする
- 「develop への push で自動適用される」という趣旨の記述を直す
- プロファイル名の記述を `oic` にする
