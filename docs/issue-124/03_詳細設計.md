# 03_詳細設計

## 状態

- Zustand `useTemplateListStore`: `filter`（`pageSize 10`・`pageIndex 1`・`sortField 'updatedAt'`・`sortOrder 'desc'`）と `selectedIds`。`updateFilter` と `updatePageIndex` は選択を解除し、`updateFilter` は 1 ページ目へ戻す（移植元 `TemplateListStore` と同じ）
- 表示中のページにない選択は無効（`items` との積集合で導出。移植元は読み込み時に落とす）

## 絞り込みの値の扱い（移植元どおり）

- フィルターは `query`・`team`・`sortField`・`sortOrder` の 4 つを毎回まとめて通知する。初期の `sortField` は `null` のため、最初に検索などをした時点で並べ替えなし（`sort` 未送信）になる。移植元と同じ挙動
- `team` はグループ名で持ち、親で ID に変換して API へ渡す。「全て」は未指定、「所属チームなし」は `__none__`（backend が対応済み）

## 追加・編集

- 作成は `name`・`systemPrompt`・`description` を trim して送り、成功後に選択グループへ `Promise.all` で紐付け
- 編集は PATCH 後、前回のグループ ID と今回の差分で、解除を終えてから追加。編集前のグループは一覧の所属チーム名を `name→id` で戻す（一致しなければ名前のまま）
- 確認ボタンは入力に誤りがある間は無効（追加は初期状態で無効）。エラー文言はフィールドを触った（blur した）後か、送信を試みた後に出る
- `required` は Angular と同じく空文字だけを弾く（空白のみは通り、送信時の trim で空になる）。移植元と同じ挙動のまま移した
- グループ選択肢が未取得ならダイアログを開く前に取得する（移植元 `loadGroups`）

## 判断と理由（移植元との差）

1. 一覧の更新: 移植元は作成・更新・削除後にストアを手元で書き換えるが、React は TanStack Query で `['prompt-templates']` を無効化して再取得する。並び順・ページ境界は常にサーバーの結果になる。無効化の key をサイドバーが使うものと揃えたため、チャットのテンプレート一覧も更新される
2. ローディング: 移植元は `mat-spinner`（40px）を出す。共通 UI に `mat-spinner` がないため `CircularLoading`（40px のリング）で代替。再取得中（変更後を含む）もリストの位置にスピナーを出す
3. `openMenuId`・`toggleMenu`: 移植元は保持するが一覧の描画に使っておらず、メニューの開閉は `ContextMenu` が持つ。移植しない
4. ダイアログの `maxHeight: '90vh'`: 共通 `Dialog` に対応する prop がないため指定していない。幅は `min(100%, 800px)`（移植元の `width: 100%; maxWidth: 800px`）
5. 名前の最大長: 移植元は 100 文字。backend（`PromptTemplateCreateRequest`）は 32 文字までで、超えると 400 になり、画面は「作成に失敗しました」のトーストを出す。backend は直さない（`docs/issue-279/api-backend-diff.md` の方針）。後続 Issue の候補
6. backend の応答は移植元と一致（`PagedResponse`、グループ一覧は `{ data }`、`groups` は一覧が名前・作成更新が ID）。画面側の吸収は不要
