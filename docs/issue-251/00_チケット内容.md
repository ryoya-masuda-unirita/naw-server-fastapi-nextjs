# #251 issue-251 server-localのファイル差し替え中にSQLiteの書き込みロックを持ち続けないようにする

## 概要

`server-local/` のファイル差し替え（PATCH でファイルを付けた場合）で、SQLite の書き込みロックを Waha! の処理が終わるまで持ち続ける。

- `app/services/file_service.py` の差し替え処理は、`_run_waha_delete(commit=False)` で旧ファイルの DELETE を flush した後、`_run_waha_create` で Waha! の upload・学習ジョブの完了を待ち、最後に commit する
- SQLite は WAL モードでも書き込みは 1 本だけ。この間、他の書き込みは `busy_timeout`（5 秒）を過ぎると `database is locked` で失敗する
- 移植元（`service/FileService.java`）は H2 で行ロックのため、他の書き込みは止まらない

## 説明

### 再現シナリオ

大きいファイルを PATCH で差し替え、学習ジョブが数分かかっている間に別のユーザーがチャットすると、SSE の回答が DB に保存されず、他の登録・削除 API も 500 になる。

### 対応

Waha! の削除・登録（外部 API 呼び出し）を DB のトランザクションの外で先に済ませ、DB の削除・保存を最後に短い 1 回のトランザクションで行う。Waha! が途中で失敗したときの DB と Waha! の整合も設計で決める。新規登録・削除の経路にも同じ問題がないか確認する。
