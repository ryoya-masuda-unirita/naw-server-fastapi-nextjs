# 01_要件定義

## 背景

インデックス（RAG検索対象の情報源）はアシスタント（Assistant）が参照する中核リソースであり、テナント管理者・グループ管理者がこれを一覧・作成・更新・削除できる必要がある。Spring Boot版にはすでに実装があり、これをFastAPI(`backend/`)へ移植する。

## 機能要件

- インデックス一覧をページネーション・グループフィルタ・検索文字列フィルタ付きで取得できる
- グループ管理者（テナント管理者ではない）は、自分が管理するグループに紐づくインデックス、または自分の管理グループのアシスタントが使用しているインデックスのみが見える（移植元のアクセス制御ロジックをそのまま踏襲する）
- インデックス詳細を取得できる（一覧と同じ可視性ルールを適用する）
- インデックスを新規作成できる（LOCAL/SAAS_GLOBALの種別ごとにエンドポイント数・WahaサービスID指定のバリデーションを行う。SAAS_GLOBALは新規作成時のみテナントあたり15件までの上限チェックを行う）
- インデックスを更新できる（移植元同様、部分更新ではなく全フィールド置換とする）
- インデックスを削除できる（`indexes_endpoints`・`indexes_groups`はDBのON DELETE CASCADEにより連動削除される）
- 作成・更新時、指定されたテナントエンドポイントID・グループIDが実在することを検証する

## 非機能要件

- 一覧取得はDBクエリ側でページネーション・ソート・検索を行う（既存の `assistants`/`prompt_templates` 系一覧APIと同じ実装パターンに合わせる。移植元Javaはメモリ上で全件ロード後にフィルタ・ソート・ページングしているが、これは踏襲しない）
- 権限チェックは既存の `require_admin_or_group_admin`（テナント管理者 or いずれかのグループの管理者）を用いる
- N+1問題を発生させない（グループ経由・アシスタント経由の可視性判定はIN句でまとめて取得する）

## スコープ外

- `POST /api/admin/indexes/{id}/sync`（同期）
- `POST /api/admin/indexes/{id}/additionalLearning`（追加学習）
- フロントエンド（React/`frontend/`）対応
