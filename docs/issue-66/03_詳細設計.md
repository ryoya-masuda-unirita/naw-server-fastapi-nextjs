# 03_詳細設計

## 実装対象ファイル

### モデル

`backend/app/models/index.py`

- `IndexType(str, Enum)`: `SAAS_GLOBAL`, `LOCAL`
- `Index(SQLModel, table=True)` `__tablename__ = "indexes"`
  - `id: str`（max_length=32, primary_key, default_factory uuid4().hex）
  - `tenant_id: str`（FK `tenants.id` ondelete CASCADE, not null）
  - `type: IndexType`（not null）
  - `name: str`（max_length=255）
  - `description: str | None`（max_length=255）
  - `add: str | None`（max_length=32、アップロード用WahaサービスID）
  - `delete: str | None`（max_length=32、削除用WahaサービスID）
  - `get: str | None`（max_length=32、一覧取得用WahaサービスID）
  - `created_at`, `updated_at`（timestamptz, server_default now, updated_atはonupdate now）
  - `__table_args__`: `UniqueConstraint("id", "tenant_id", name="uq_indexes_id_tenant_id")`（移植元最終形のFKターゲット用ユニーク制約を再現）
- `IndexEndpoint(SQLModel, table=True)` `__tablename__ = "indexes_endpoints"`
  - `index_id: str`（primary_key）, `tenant_id: str`, `endpoint_id: str`（FK `tenant_endpoints.id` CASCADE, primary_key）
  - `__table_args__`: `ForeignKeyConstraint(["index_id", "tenant_id"], ["indexes.id", "indexes.tenant_id"], ondelete="CASCADE")`
- `IndexGroup(SQLModel, table=True)` `__tablename__ = "indexes_groups"`
  - `index_id: str`（primary_key）, `tenant_id: str`, `group_id: str`（FK `groups.id` CASCADE, primary_key）
  - `__table_args__`: `ForeignKeyConstraint(["index_id", "tenant_id"], ["indexes.id", "indexes.tenant_id"], ondelete="CASCADE")`

### リポジトリ

`backend/app/repositories/index_repository.py`（`IndexRepository`）

- `find_by_id_and_tenant_id(index_id, tenant_id, session) -> Index | None`
- `find_page(tenant_id, search, group_id, allowed_index_ids, allowed_group_ids, sort_col_name, sort_dir, page, size, session) -> tuple[list[Index], int]`
  - `group_id`指定時: `indexes_groups`にEXISTS条件で絞り込み
  - `group_id`未指定かつ`allowed_index_ids is not None`（グループ管理者スコープ）の場合: `id IN allowed_index_ids OR EXISTS(indexes_groups WHERE group_id IN allowed_group_ids)`
  - 両方Noneの場合（テナント管理者、または管理グループなしの一般ユーザー）: テナント全件
  - 検索文字列は `name`/`description` の部分一致（大文字小文字無視、`escape_like_pattern`使用）
  - ソート許可カラム: `updatedAt`（既定）・`name`・`type`
- `count_saas_indexes(tenant_id, session) -> int`（`type == SAAS_GLOBAL`の件数、Validator用）
- `create(index, session) -> Index`
- `update(index, session) -> Index`
- `delete(index, session) -> None`
- `find_tenant_endpoints_for_index(index_id, session) -> list[TenantEndpoint]`（`indexes_endpoints`結合、N+1回避のため一覧表示時はIN句でまとめて取得する`find_tenant_endpoints_grouped_by_index_ids`を用意）
- `find_group_ids_grouped_by_index_ids(index_ids, session) -> dict[str, list[str]]`
- `replace_endpoints_for_index(index_id, tenant_id, endpoint_ids, session) -> None`
- `replace_groups_for_index(index_id, tenant_id, group_ids, session) -> None`

### 依存リポジトリへの追加

`backend/app/repositories/group_assistant_repository.py` は既存の `find_assistant_ids_by_group_ids` をそのまま利用する（新規追加不要）。

`backend/app/repositories/assistant_repository.py` に以下を追加する（移植元`AssistantSpecification.inGroups`経由の`indexIdsFromAssistants`相当。既存の`find_by_ids_and_tenant_id`を経由せず、IN句で直接distinctなindex_idのみ取得することでN+1・過剰なデータ取得を避ける）:

- `find_distinct_index_ids_by_ids(assistant_ids, tenant_id, session) -> list[str]`

### スキーマ

`backend/app/schemas/index.py`

- `IndexRequest(BaseModel)`（作成・更新共用）
  - `name: str`, `description: str | None = Field(default=None, max_length=255)`, `add: str | None`, `delete: str | None`, `get: str | None`, `type: IndexType`, `endpointIds: list[str]`, `groupIds: list[str] | None = None`
  - `@model_validator(mode="after")` でLOCAL/SAAS_GLOBALのエンドポイント数・Wahaサービス ID必須チェックを実施（移植元`IndexRequestValidator`の日本語メッセージをそのまま使用）。SAAS上限チェックはテナント内件数が必要なためサービス層で行う
- `TenantEndpointItemResponse(BaseModel)`: `id`, `tenantId`, `type`, `endpointName`, `endpoint`
- `IndexResponse(BaseModel)`: `id`, `tenantId`, `type`, `name`, `description`, `tenantEndpoints: list[TenantEndpointItemResponse]`, `groupIds: list[str]`, `add`, `delete`, `get`, `createdAt`, `updatedAt`
- `PagedIndexResponse(BaseModel)`: `content: list[IndexResponse]`, `totalElements: int`, `number: int`, `size: int`

### サービス

`backend/app/services/index_service.py`（`IndexService`）

- `_resolve_visibility_scope(tenant_id, current_user, session) -> tuple[list[str] | None, list[str] | None]`
  - テナント管理者、またはいずれの管理グループも持たない一般ユーザーの場合は `(None, None)`（絞り込みなし。移植元の「グループ管理者でないなら全件」を踏襲）
  - グループ管理者（テナント管理者でない）の場合は `(allowed_index_ids, admin_group_ids)` を返す
    - `admin_group_ids = GroupUserRepository.find_admin_group_ids_for_user(...)`
    - `assistant_ids = GroupAssistantRepository.find_assistant_ids_by_group_ids(admin_group_ids, tenant_id, session)`
    - `allowed_index_ids = AssistantRepository.find_distinct_index_ids_by_ids(assistant_ids, tenant_id, session)`
- `list_indexes(tenant_id, current_user, group_id, search, sort, page, size, session) -> PagedIndexResponse`
  - `group_id`指定時: テナント管理者でなく`admin_group_ids`に`group_id`が含まれなければ空ページを返す（`IndexRepository`を呼ばない）
  - 上記以外は`_resolve_visibility_scope`の結果を`IndexRepository.find_page`に渡す
- `get_index(index_id, tenant_id, current_user, session) -> IndexResponse`
  - `IndexRepository.find_by_id_and_tenant_id`で404判定後、`_resolve_visibility_scope`の結果で可視性を再チェック（見えなければ404、移植元と同じ扱い）
- `create_index(tenant_id, req, session) -> IndexResponse`
  - `req.type == SAAS_GLOBAL`かつ新規作成時、`IndexRepository.count_saas_indexes(tenant_id) >= 15`なら400
  - `TenantEndpointRepository.find_by_ids_and_tenant_id`でエンドポイント実在確認（不一致なら404 "指定されたテナントエンドポイントが見つかりません。"）
  - `GroupRepository.find_by_tenant_id_and_ids`でグループ実在確認（不一致なら404 "指定されたグループの一部が見つかりません。"）
  - `Index`作成 → `replace_endpoints_for_index` → `replace_groups_for_index`
- `update_index(index_id, tenant_id, req, session) -> IndexResponse`
  - SAAS上限チェックなし（更新時はスキップ、移植元と同様）
  - 対象取得後、全フィールド置換
- `delete_index(index_id, tenant_id, session) -> None`
  - 存在しなければ何もしない（移植元は`deleteById`のみで存在チェックなしだが、FastAPI側は`find_by_id_and_tenant_id`で取得してから削除する形にして冪等にする）

### ルーター

`backend/app/routers/indexes.py`

- `admin_router = APIRouter(prefix="/api/admin/indexes", tags=["admin-indexes"])`
- 全エンドポイント `Depends(require_admin_or_group_admin)` + `Depends(get_verified_tenant_id)`
- `GET ""` → `list_indexes`（クエリ: `groupId`, `searchText`, `page`, `size`, `sort`）
- `GET "/{index_id}"` → `get_index`
- `POST ""` → `create_index`
- `PATCH "/{index_id}"` → `update_index`
- `DELETE "/{index_id}"` status_code=204 → `delete_index`

`main.py`に`from app.routers import indexes`を追加し、`app.include_router(indexes.admin_router)`を登録する。

## 設計上の判断（移植元との差分）

- 一覧のページング・ソート・検索をDBクエリに寄せる（移植元はメモリ上処理）。ソート未指定時は`updatedAt desc`をデフォルトとする（他ドメインの一覧APIと同じ規約に統一するための意図的な判断。移植元は「ソート未指定なら可視性計算時の内部順序のまま」という未規定の挙動だったため、決定的な順序に倒す）
- DELETEは移植元にはない「対象が存在しない場合は何もしない」という冪等な扱いにする（挙動としては同じ204を返す）
