# 01_要件定義

## 背景

Issue #66でインデックスの基本CRUD（一覧・詳細・作成・更新・削除）は移植済みだが、同期・追加学習の2エンドポイントは、依存するFileドメイン（Issue #87）とMessageFeedbackの移植が未完了だったためスコープ外としていた。両者が揃ったため、本Issueで対応する。

## 機能要件

- インデックス同期API（`POST /api/admin/indexes/{id}/sync`）を提供する。
  - 移植元は常に「ファイル一括同期機能はローカルAPIサーバしか対応していません。」というエラーを返すスタブ実装であり、その挙動をそのまま踏襲する。
- インデックス追加学習API（`POST /api/admin/indexes/{id}/additionalLearning`）を提供する。
  - リクエストは`multipart/form-data`で、`feedbackId`・`roomId`（いずれも任意文字列）・`content`（アップロードファイル、必須）を受け取る。
  - `feedbackId`・`roomId`はどちらか一方が必須。両方未指定・両方指定のいずれもエラーとする。
  - `feedbackId`指定時: ファイル名`追加学習_{feedbackId}.md`、参照情報`フィードバック_{feedbackId}`としてファイルを新規作成する。
  - `roomId`指定時: ファイル名`追加学習_ルーム_{roomId}.md`、参照情報`フィードバック_{roomId}`としてファイルを新規作成する（移植元のreference文字列は、roomId指定時も接頭辞が「フィードバック_」のままになっている。移植元の挙動としてそのまま踏襲する）。
  - ファイル作成は、対象インデックスが存在しない場合404、`LOCAL`タイプの場合400、当月クレジット上限超過の場合429を返す（Issue #87の`create_file`と同じ制約）。
  - `feedbackId`指定時のみ、ファイル作成後に該当する`MessageFeedback`の`index_id`を対象インデックスIDへ更新する。該当フィードバックが存在しない場合は何もしない（移植元の`Optional#ifPresent`相当）。
- いずれのエンドポイントも既存の`/api/admin/indexes`配下と同様、テナント管理者またはグループ管理者のみ実行可能とする。

## 非機能要件

- 既存の`backend/app/routers/indexes.py`のルーティング・DI（`get_verified_tenant_id`・`require_admin_or_group_admin`・`get_session`）パターンを踏襲する。
- router:service 1対1規約を維持する（`routers/indexes.py`は`IndexService`のみを呼び出す。`FileService`を直接呼ばない）。
- ファイルのストレージ保存・DB作成という、`FileService.create_file`と共通する処理は、サービス間呼び出し禁止規約に反しないよう`core/`層の共通ロジックとして切り出し、双方から再利用する（`core/credit_quota.py`と同様のパターン）。
- 動作確認はブラウザ操作を行わず、自動テスト（pytest）の実行結果で代替する。

## スコープ外

- ファイル一括同期の実運用実装(ローカルAPIサーバ向け機能自体の実装は対象外。移植元同様スタブのまま)。
- コンテンツ抽出（Tika相当）・チャンク分割・ベクトルDB登録（Issue #88スコープ）。
- フロントエンド（React/Angular）側の対応。
