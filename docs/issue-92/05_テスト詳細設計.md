# 05_テスト詳細設計

## 対象ファイル

- `backend/tests/integration/test_indexes.py`（`TestSync`・`TestAdditionalLearning`クラスを追加）

## テストケース詳細

`TestSync`

- `test_sync_always_returns_bad_request`: 「常に400・所定のメッセージを返すこと」（04のNo.1）

`TestAdditionalLearning`

- `test_neither_feedback_id_nor_room_id_raises_error`: 「feedbackId・roomIdどちらも未指定だとエラーになること」（No.2）
- `test_both_feedback_id_and_room_id_raises_error`: 「feedbackId・roomIdを両方指定するとエラーになること」（No.3）
- `test_create_file_with_feedback_id`: 「feedbackId指定で追加学習ファイルが作成されること」（No.4）
- `test_update_message_feedback_index_id`: 「feedbackId指定後にMessageFeedback.index_idが更新されること」（No.5）
- `test_create_file_with_room_id`: 「roomId指定で追加学習ファイルが作成されること」（No.6）
- `test_index_not_found_raises_404`: 「存在しないindex_idを指定すると404になること」（No.7）
- `test_local_index_raises_bad_request`: 「LOCALタイプのインデックスを指定すると400になること」（No.8）
- `test_member_user_forbidden`: 「一般ユーザーは追加学習APIを呼べないこと」（No.9）

「存在しないfeedbackId」ケースは、`files.feedback_id`のFK制約により実運用のスキーマ上到達しないため、04のテスト方針補足の通りテストケースとしては追加しない。

## 既存テストへの影響確認

- `backend/tests/unit/test_file_storage.py`・`backend/tests/integration/test_files.py`は、`core/file_creation.py`への抽出後も既存の公開API（`FileService.create_file`等）の挙動が変わらないことの回帰確認として、変更なしのまま再実行しグリーンであることを確認する。
