# 01_要件定義

## 背景

SECURE アシスタントの回答の生成は、#436 で、社内側から Bedrock Mantle の Anthropic 形式の入口を直接呼べるようになった。認証は、Bedrock の API キーを、キー用ヘッダーと Bearer の両方で送る作りにした。実機で確かめられなかったためである。

その後、実機で確かめたところ、Bedrock Mantle は 2 種類の認証ヘッダーが同時にあるリクエストを拒否し、Bearer だけなら受け付けることが分かった。そのため、現状では Bedrock（Claude）の回答生成が実機で失敗する。

## 機能要件

| No | 要件 |
|---|---|
| F1 | Bedrock（Claude）の呼び出しは、認証に Bearer の API キーだけを送り、キー用ヘッダーは送らない |
| F2 | 認証以外の送信内容（バージョンのヘッダー・本文・宛先の組み立て）は変えない |
| F3 | 呼び出しが成功したとき、回答・使用量・終了理由の読み取りは、現状と同じ |
| F4 | 設計書と README の「2 種類を送る」という記述を、実機で確かめた結果に合わせて直す |

## 非機能要件

- 既存のプロバイダ（OpenAI・Azure・SecuAiGent・Echo）と、#439 の Bedrock の埋め込みの挙動は変わらない
- 外部通信を行うテストは、モックで行い、本物の Bedrock には接続しない
- 追加・変更する関数・メソッド・クラスに、日本語の NumPy 形式の docstring を書く
- Bedrock の部品は、目印（`bedrock-ext`）つきの範囲に収め、取り除いても既存のテストが通る状態を保つ

## スコープ外

- Bedrock Mantle 以外の接続先の追加
- 埋め込み（#439）の認証の変更（すでに Bearer だけ）
- 実機の接続確認を自動化すること（手順を残し、ユーザーが確認する）
