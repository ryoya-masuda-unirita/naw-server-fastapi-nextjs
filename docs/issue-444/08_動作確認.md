# 08_動作確認

## 確認環境

- macOS、`feature/issue-444`
- テストは `generative-ai-adapter/`・`waha-emulator/` の `uv run pytest`（外部通信はモック）
- 実機の確認は、ユーザーの端末の `curl`（Bedrock Mantle、`ap-northeast-1`、`anthropic.claude-haiku-4-5`）

## 確認手順

1. 実機で、認証ヘッダーの組み合わせを変えて Mantle の `/anthropic/v1/messages` を呼ぶ（ユーザーが実行）
2. テストを先に直し、修正前のコードで失敗することを確かめる
3. 実装を直し、テストと ruff を実行する

## 確認結果

### 実機（ユーザーの端末での `curl` の出力）

- `x-api-key` と `Authorization: Bearer` の両方 → `authentication_error`（`request must not include both 'authorization' and 'x-api-key' headers`）
- `Authorization: Bearer` だけ → 応答が返り、`model` は `claude-haiku-4-5-20251001`（`stop_reason` が `max_tokens` なのは、確認のため `max_tokens` を 32 にしたため）

### テスト

- 修正前のコードで、直したテスト 3 件が失敗した
  - core の `test_headers_carry_bearer_and_version_without_api_key_header`・`test_chat_sends_messages_api_request`
  - waha-emulator の `test_run_bedrock_calls_messages_endpoint`
- 修正後
  - `generative-ai-adapter`: 1431 passed, 3 skipped
  - `waha-emulator`: 173 passed
  - 両方で `ruff format --check`・`ruff check` が通った

### #439 の Titan（範囲外の付随確認）

- ユーザーの端末で、Bedrock Runtime の `/model/amazon.titan-embed-text-v1/invoke` を `Authorization: Bearer` の API キー（`ABSK` で始まる 132 文字）で呼んだ。`{"embedding":[...` が返った（先頭の値は、AWS の署名つきの呼び出しの結果と同じ）
- 先に「通らない」としたのは、このセッションのシェルでキーが空だったためで、誤りだった
- 次元数 1536 は、出力を先頭 200 文字で切っているため未確認
