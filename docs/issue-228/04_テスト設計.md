# 04_テスト設計

## テスト方針

- 例外ハンドラは、最小のアプリにハンドラを登録して単体で確かめる
- 実際の API での変化は、既存の結合テストの 422 / `detail` の確認を 400 / `message` に書き換えて確かめる（入力エラー・業務エラーの代表を網羅しているため、新規の結合テストは最小限）
- テストの意図（入力エラーか業務エラーか）は変えない

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 業務エラー | ステータス・メッセージを指定したエラー | 指定ステータスで `{"timestamp", "message"}`。`detail` キーが無い |
| 2 | 業務エラーのヘッダー | 追加のヘッダーを指定したエラー | ヘッダーが応答に付く |
| 3 | 本文を持てないステータス | 304 を指定したエラー | 本文なしで返る |
| 4 | 存在しない URL | 未定義のパスへのリクエスト | 404 で `message` が「Not Found」 |
| 5 | 許可されていないメソッド | 定義の無いメソッド | 405 で `message` を持つ |
| 6 | ボディの入力エラー | 必須項目なし | 400 で最初の 1 件のメッセージ |
| 7 | 複数の入力エラー | 複数の項目がエラー | 400 で最初の 1 件だけ（連結しない） |
| 8 | 独自チェックのメッセージ | 独自チェックで日本語メッセージのエラー | 接頭辞なしの日本語メッセージ |
| 9 | クエリ・JSON の入力エラー | 型の違うクエリ・JSON として読めないボディ | 400 |
| 10 | エラー一覧が空 | 一覧が空の入力エラー | 「リクエストが不正です」 |
| 11 | `timestamp` | 任意のエラー | 現在の UNIX 秒（整数） |
| 12 | 既存 API の入力エラー | 既存テストの入力エラー（テンプレート名 32 文字超、textData 不正など） | 400 で `message` |
| 13 | 既存 API の業務エラー | 既存テストの業務エラー（削除済みファイル、不正な role など） | ステータスは変わらず `message` に同じ文言 |
| 14 | 全体 | 単体・結合テスト全件 | すべて成功 |
