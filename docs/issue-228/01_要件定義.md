# 01_要件定義

## 背景

- 移植元 Spring Boot は、コントローラーで発生した例外を共通の例外ハンドラ（`APIControllerAdvice`）でエラー応答に変換している。応答の本文は `ErrorResponse` で、`timestamp`（UNIX 秒）と `message`（エラーメッセージ）の 2 項目を持つ
- 入力チェックのエラーは 400 で返す。複数の項目でエラーがあっても連結はせず、**最初の 1 件のメッセージだけ**を返す
- backend（FastAPI）は FastAPI 標準のまま、業務エラーを `{"detail": "..."}`、入力チェックのエラーを 422 `{"detail": [{"loc": ..., "msg": ..., ...}, ...]}` で返している
- クライアントは移植元の形（`message`）でエラーを扱うため、backend のエラー応答を移植元に揃える（2026-11-12 ユーザー判断「完全に揃える」）

## 移植元の例外とエラー応答の対応（参照実装を読んだ結果）

| 移植元の例外 | ステータス | `message` |
|---|---|---|
| `ResponseStatusException` | 例外に指定したステータス | 例外の理由（reason） |
| `IllegalArgumentException` | 400 | 例外のメッセージ |
| `MethodArgumentNotValidException`（リクエストの入力チェック） | 400 | エラーのうち最初の 1 件のメッセージ |
| `ConstraintViolationException`（サービスのメソッド検証） | 400 | 違反のうち最初の 1 件のメッセージ。違反が無ければ「リクエストが不正です」 |
| `EntityNotFoundException` | 404 | 例外のメッセージ |
| `RestClientException` / `IllegalStateException` | 500 | 例外のメッセージ |
| `AccessDeniedException` | 403 | 例外のメッセージ |
| `CreditQuotaExceededException` 等 3 種 | 429 | 例外のメッセージ |
| `AssistantInUseException` | 409 | 例外のメッセージ |

本文はいずれも `{"timestamp": <UNIX 秒>, "message": "..."}`。

## 機能要件

1. 業務エラー（ステータスとメッセージを指定して返すエラー）は、指定したステータスのまま、本文を `{"timestamp", "message"}` にする。`message` は指定したメッセージ
2. 存在しない URL・許可されていないメソッドなど、フレームワークが返す HTTP エラーも同じ本文にする
3. 入力チェックのエラー（ボディ・クエリ・パス・ヘッダーの必須・型・形式・独自チェック、multipart の `textData` の解釈エラーを含む）は、すべて **400** で、本文を `{"timestamp", "message"}` にする
   - `message` は最初の 1 件のエラーのメッセージ（移植元と同じく連結しない）
   - 独自チェックで指定した日本語メッセージは、そのまま `message` にする（フレームワークが付ける接頭辞は付けない）
   - エラーが 1 件も無い場合は「リクエストが不正です」
4. 本文に `detail` キーは残さない（移植元に無いため）
5. 業務エラーで指定した追加のレスポンスヘッダーは、これまでどおり返す
6. 既存テストの 422 / `detail` の確認は 400 / `message` に書き換える。テストの意図（入力エラーか業務エラーか）は変えない
7. backend の規約にエラー応答の規約（`{"message"}`・入力チェックは 400）を追記する

## 非機能要件

- 既存の業務エラーの呼び出し側（約 140 か所）は変更しない（例外ハンドラで変換し、変更範囲を小さくする）
- 入力チェックのエラーのログには、入力値（パスワード・添付ファイルの中身を含み得る）を出さない

## スコープ外

- **ストリーミング（SSE）内のエラーイベントの形式**: 変えない。HTTP のエラー応答だけが対象
- **入力チェックのメッセージの文言**: 移植元は項目ごとに日本語のメッセージ（例:「タグ名は255文字以内で入力してください」）を指定しているが、backend のうちフレームワーク組み込みの制約（文字数上限など）は英語の既定文言のまま。文言を項目ごとに揃えるのは本 Issue の対象外（形・ステータス・組み立て方だけ揃える）
- **予期しない例外（500）**: 移植元でもハンドラ外の例外は Spring Boot 既定の応答になり `ErrorResponse` ではないため、変えない
- **`IllegalArgumentException` 相当**: backend は移植時に業務エラー（400）へ置き換え済みで、リクエスト処理から素の値エラーがそのまま外に出る経路は無い（ストリーミング内の 1 か所は捕捉済み）。任意の値エラーを 400 にすると内部の不具合が入力エラーとして見えてしまうため、変換は追加しない
- frontend（React）は変更しない
