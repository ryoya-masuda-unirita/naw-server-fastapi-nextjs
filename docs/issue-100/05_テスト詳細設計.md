# 05_テスト詳細設計

## `backend/tests/unit/test_response_format_schema.py`（新規）

既存テストディレクトリはフラット構成（`tests/unit/schemas/`のようなサブディレクトリを
切らない）のため、この規約に合わせてフラットな新規ファイルとして作成する。

- `TestResponseFormatRequest`
  - `test_accepts_json_object_type`: `type="json_object"`でモデル生成できること
  - `test_accepts_json_schema_type`: `type="json_schema"`でモデル生成できること
  - `test_rejects_invalid_type`: `type="text"`で`ValidationError`になること
  - `test_rejects_empty_type`: `type=""`で`ValidationError`になること
- `TestLlmChatRequestResponseFormat`
  - `test_defaults_to_none`: `responseFormat`未指定時は`None`になること
  - `test_accepts_response_format`: `responseFormat`指定時に`ResponseFormatRequest`として保持されること
- `TestMessageContentCreateRequestResponseFormat`
  - 上記と同一観点を`MessageContentCreateRequest`に対して実施

## `backend/tests/unit/test_llm_client.py`（既存へ追記）

- `TestAzureLlmChatClient`
  - `test_omits_response_format_when_not_specified`: `response_format`未指定（デフォルト）で呼び出した場合、`create()`の`kwargs`に`"response_format"`キーが含まれないこと
  - `test_passes_response_format_when_specified`: `response_format={"type": "json_object"}`を指定して呼び出した場合、`create()`の`kwargs["response_format"]`がそのまま渡ること

## `backend/tests/unit/test_llm_chat_service.py`（既存へ追記）

- `TestStreamChat`
  - `test_passes_response_format_and_prepends_instruction_when_specified`: `_request(responseFormat={"type": "json_object"})`で呼び出し、`AzureLlmChatClient.stream_chat`の呼び出し引数を検証する
    - `response_format`引数が`{"type": "json_object"}`であること
    - `messages`引数の先頭が`ChatMessage(role="system", content="回答は JSON 形式で出力してください。")`であること
  - `test_does_not_pass_response_format_when_not_specified`: `responseFormat`未指定時、`AzureLlmChatClient.stream_chat`の`response_format`引数が`None`であること（先頭メッセージがsystemのJSON指示文にならないこと）
