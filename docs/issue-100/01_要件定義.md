# 01_要件定義

## 背景

issue-88（LLMチャットAPI移植）・issue-93（メッセージ送信API移植）は、いずれもresponse_format（構造化出力指定）を明示的にスコープ外としていた。この2つのAPI（`POST /api/llm/chat` → `LlmChatService.stream_chat`、`POST /api/messages/content` → `MessageService.stream_message_content`）は、いずれもSSEストリーミングでAzure OpenAIの応答を返す実装が既にdevelopに存在するため、本Issueではこの2つのサービスにresponse_format対応を追加する。

移植元（Spring Boot、コミット `96d926af` `NAW-1100 AIのレスポンス形式を指定できるようにする`）の実装は次の通り。

- リクエストDTO（`ResponseFormatRequest`）で `type`（`json_object` / `json_schema`）と `json_schema`（`name`/`strict`/`schema`）を受け取る
- ただし `json_schema` の中身は現時点では未使用で、`type` の値にかかわらず実際には常に「JSON形式で出力する」という指定（OpenAI Responses APIの `ResponseFormatJsonObject`）としてLLM呼び出しに反映される
- `responseFormat` が指定された場合、チャットメッセージの先頭に `"回答は JSON 形式で出力してください。"` というsystemメッセージを前置する
- `type` が空・`json_object`/`json_schema` 以外の値の場合は400
- `createLibrary`（ライブラリ生成）と同時指定はできない（400）

移植先（FastAPI）は、Chat Completions API（`AsyncAzureOpenAI.chat.completions.create`）に統一されており、移植元のResponses API固有の実装（`ResponseTextConfig`等）は存在しない。Chat Completions APIでは `response_format={"type": "json_object"}` を `create()` の引数にそのまま渡す形でJSON出力を強制できる。

## 機能要件

- `POST /api/llm/chat`（`LlmChatRequest`）・`POST /api/messages/content`（`MessageContentCreateRequest`）の両リクエストに、任意項目 `responseFormat` を追加する
  - `responseFormat.type` は `json_object` または `json_schema` のいずれかの文字列（必須）。それ以外の値・空文字は422（Pydanticバリデーションエラー）とする
  - `responseFormat.type` が `json_schema` の場合でも、移植元と同様に現時点ではJSON Schemaによる構造強制までは行わず、`json_object`と同じ「JSON形式で出力させる」動作にとどめる（将来の拡張余地として `type` のみ受け取る）
- `responseFormat` が指定された場合、Azure OpenAI呼び出し時に `response_format={"type": "json_object"}` を渡し、Chat Completions APIのJSONモードを有効にする
- `responseFormat` が指定された場合、LLMへ送るメッセージ列の先頭に `"回答は JSON 形式で出力してください。"` というsystemメッセージを前置する（移植元同様。OpenAIのJSONモードは、メッセージ内に "json" という語を含めることが要件のため）
- `responseFormat` 未指定時の挙動（自由文応答）は変更しない

## 非機能要件

- 既存のストリーミング・トークン使用量永続化・クレジット計算のロジックには影響を与えない
- `AzureLlmChatClient.stream_chat`（`core/llm_client.py`）のシグネチャ変更は、呼び出し元である`llm_chat_service.py`・`message_service.py`の両方に一貫して反映する

## スコープ外

- `responseFormat.json_schema`（`name`/`strict`/`schema`）の中身をLLM呼び出しに反映すること（移植元でも未実装のため踏襲しない）
- `responseFormat` と `createLibrary`（ライブラリ生成）の相関バリデーション（`isCreateLibrary`は現状`LlmChatRequest`・`MessageContentCreateRequest`のいずれにも未実装のスコープ外項目のため、対象外）
- Issue #97〜#99（添付ファイル・tools・ライブラリ生成対応、PR #106〜#108として未マージ）との統合。本Issueは develop の現状実装を対象とする
