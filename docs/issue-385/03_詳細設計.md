# 03_詳細設計

## 1. rds（`secuaigent-infra/modules/rds/main.tf`・`variables.tf`）

変数を追加する（どちらも既定値あり。環境側は変えない）:

| 変数 | 型 | 既定 | 説明 |
|---|---|---|---|
| `engine_version` | string | `"18"` | PostgreSQL のバージョン。メジャーのみを指定し、マイナーは AWS に任せる（`auto_minor_version_upgrade` と矛盾させないため） |
| `backup_retention_period` | number | `7` | 自動バックアップの保持日数 |

```hcl
locals {
  // パラメータグループのファミリは、エンジンのメジャーバージョンから決める(食い違いを防ぐ)
  pg_major = split(".", var.engine_version)[0]
}

resource "aws_db_parameter_group" "main" {
  name   = "${var.project_name}-pg${local.pg_major}"
  family = "postgres${local.pg_major}"

  tags = { Name = "${var.project_name}-pg${local.pg_major}" }

  // メジャーを上げるとnameが変わる。使用中のグループは先に消せないため、新しいものを先に作る
  lifecycle { create_before_destroy = true }
}
```

`aws_db_instance.main` に追加・変更する:

```hcl
engine_version             = var.engine_version
storage_encrypted          = true
backup_retention_period    = var.backup_retention_period
auto_minor_version_upgrade = true
parameter_group_name       = aws_db_parameter_group.main.name
```

- 変えない: `identifier`、`engine`、`instance_class`（`db.t4g.micro`）、`allocated_storage`（20）、`db_name`、`storage_type`（`gp3`）、`username`、`password`（変数）、サブネットグループ、SG、`publicly_accessible`、`skip_final_snapshot`。`multi_az`・`deletion_protection` は、既定（false）のまま明示しない
- 出力（`address`・`username`・`db_name`）は変えない

## 2. elasticache（`secuaigent-infra/modules/elasticache/main.tf`・`variables.tf`）

変数 `engine_version`（string、既定 `"7.1"`）を追加する。`aws_elasticache_replication_group.main` に追加する:

```hcl
engine_version             = var.engine_version
port                       = 6379
automatic_failover_enabled = false  # 1ノード構成のため
at_rest_encryption_enabled = true
transit_encryption_enabled = false  # backendは平文のredis://で接続しているため
```

- 変えない: `node_type`（`cache.t4g.micro`）、`num_cache_clusters`（1）、サブネットグループ、SG、出力
- 注意: `at_rest_encryption_enabled` と `transit_encryption_enabled` は、作成後に変えられない（再作成になる）

## 3. ecr（`secuaigent-infra/modules/ecr/main.tf`）

`aws_ecr_lifecycle_policy.backend` を足す（移植元と同じ内容）:

```hcl
resource "aws_ecr_lifecycle_policy" "backend" {
  repository = aws_ecr_repository.backend.name
  policy = jsonencode({
    rules = [{
      rulePriority = 1
      description  = "Expire untagged images older than 30 days"
      selection    = { tagStatus = "untagged", countType = "sinceImagePushed", countUnit = "days", countNumber = 30 }
      action       = { type = "expire" }
    }]
  })
}
```

既存のリポジトリ設定（タグ上書き可、`force_delete`、プッシュ時のスキャン）は変えない。

## 4. 環境（`secuaigent-infra/environments/dev`）

変更しない（新しいモジュール変数は、既定値で使う）。

## 5. 手順書（`secuaigent-infra/README.md`）

「データストアの設定」の節を足す: RDS（PostgreSQL 18、暗号化、バックアップ 7 日、自動マイナー更新）、ElastiCache（Redis 7.1、保存時の暗号化あり・通信の暗号化なし）、ECR（タグなしを 30 日で削除）。次の注意を書く。
- 暗号化とエンジンのバージョンの明示は、既存の RDS・ElastiCache では再作成になる（新アカウントへの新規構築が前提）
- RDS の PostgreSQL のメジャーバージョンを上げるときは、`engine_version` を変えるだけでは、データの移行が伴うため、スナップショットを取ってから、手動で計画する
- ローカルの開発環境（PostgreSQL 18・Redis 7）と、メジャーバージョンを合わせている
- 移植元の `16.4` は、現在のリージョンに存在しないため、使わない
