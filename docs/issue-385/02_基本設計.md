# 02_基本設計

## 変更対象

1. **rds モジュール**
   - 暗号化・バックアップ・マイナーバージョン更新を、DB インスタンスに設定する
   - パラメータグループ（PostgreSQL 18 のファミリ、パラメータなし）を足し、DB インスタンスに付ける
   - エンジンのバージョンを入力にし、既定値を 18 にする。バックアップの保持日数も入力にし、既定値を 7 にする。パラメータグループのファミリは、エンジンのメジャーバージョンから決める（バージョンとファミリが食い違わないようにする）
2. **elasticache モジュール**
   - エンジンのバージョンを入力にし、既定値を 7.1 にする。暗号化・ポート・フェイルオーバーを明示する
3. **ecr モジュール**
   - タグなしイメージの削除ルール（ライフサイクルポリシー）を足す
4. **環境（dev）**: 新しい入力を、既定値のまま使う（環境側の変数は増やさない。変えたいときに、モジュールの入力を環境の変数として足す）
5. **手順書**: 設定値と、再作成の注意を書く

## 画面 / API 変更概要

なし（インフラのみ）。

## 影響範囲

- **RDS**: 暗号化の有効化、エンジンのバージョンの明示、パラメータグループの付与のため、**既存の RDS には再作成・変更が必要になる**。新アカウントへの新規構築が前提なので問題ない。接続情報（ホスト名など）の出力の名前は変わらない
- **ElastiCache**: エンジンのバージョンの明示と暗号化の有効化で、既存のものには再作成が必要になる。新規構築では問題ない。backend の接続（平文の Redis 接続）は、通信の暗号化を有効にしないので、変わらない
- **ECR**: ライフサイクルの追加のみ。既存のイメージ・リポジトリに影響しない（削除されるのは、タグなしで 30 日を過ぎたイメージのみ）
- **CI・アプリ**: 影響なし。ECS の環境変数に入る接続情報（ホスト・ユーザー・DB 名・Redis のエンドポイント）の出力は変わらない
- **費用**: 暗号化・パラメータグループに追加費用はない。バックアップの保管量が増える分の費用が、わずかにかかりうる。`apply` はしないので、今は費用が発生しない
- **ローカルとの整合**: 開発環境（PostgreSQL 18、Redis 7）と、本番相当の環境が、同じメジャーバージョンになる

## 移植方針

- 移植元の設定値（暗号化、保持 7 日、自動マイナー更新、パラメータグループ、Redis 7.1、保存時の暗号化、6379、ライフサイクル）に揃える
- 移植元との違い
  - エンジンのバージョンは、移植元の既定値 16.4（存在しない版で、パラメータグループとも食い違う）ではなく、**18**。ローカルの PostgreSQL 18 と、移植元のパラメータグループのファミリに合わせる
  - マイナーバージョンを指定しないので、`auto_minor_version_upgrade` と矛盾しない（指定すると、自動更新のたびに差分が出る）
  - DB パスワードの `random_password` と、移植元の Secrets 連携は、#386 で扱う
  - 移植元の `environment == "dev"` による最終スナップショットの切り替えは、環境が dev のみのため、現状の固定値を維持する
  - pgvector の拡張とアプリ用ロールの SQL は、持ち込まない（この Python のサーバーは使わない）
