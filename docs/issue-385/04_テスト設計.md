# 04_テスト設計

## テスト方針

インフラの設定変更なので、自動テストは追加しない。変更前後の `plan` を比べて、変更されるリソースと属性が想定どおりであることを確認する。エンジンのバージョンと機能の提供状況は、`oic` で読み取りだけで確認する。AWS への `apply` は実行しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 構文・書式 | `fmt` と `validate` | エラーなし |
| 2 | リソースの増減 | 変更前後の `plan` | 追加は想定の 2 リソースのみ（DB パラメータグループ、ECR ライフサイクルポリシー）。削除なし。合計 67 → 69 |
| 3 | 変わらないリソース | 上記以外のリソースの、確定している属性値の比較 | 差分があるのは、RDS・ElastiCache のレプリケーショングループの想定の属性だけ。VPC・ECS・ALB・CloudFront・IAM・ECR リポジトリ本体などに差分なし |
| 4 | RDS の設定 | `plan` | `engine_version=18`、`storage_encrypted=true`、`backup_retention_period=7`、`auto_minor_version_upgrade=true`、パラメータグループが付く。`storage_type=gp3`、`db.t4g.micro`、`allocated_storage=20`、`publicly_accessible=false` は不変 |
| 5 | パラメータグループ | `plan` | 名前 `<プロジェクト名>-pg18`、ファミリ `postgres18`、パラメータなし |
| 6 | ElastiCache の設定 | `plan` | `engine_version=7.1`、`port=6379`、`at_rest_encryption_enabled=true`、`transit_encryption_enabled=false`、`automatic_failover_enabled=false`。`node_type` は不変 |
| 7 | ECR | `plan` | ライフサイクルポリシーが付く（タグなし・30 日・期限切れ）。リポジトリ本体は不変 |
| 8 | 提供状況（RDS） | `oic` で、`describe-db-engine-versions`・`describe-orderable-db-instance-options`（読み取りのみ） | PostgreSQL 18 系が提供され、ファミリが `postgres18`、`db.t4g.micro` で `gp3` と暗号化が使える |
| 9 | 提供状況（ElastiCache） | `oic` で、`describe-cache-engine-versions`（読み取りのみ） | Redis 7.1 が提供され、ファミリが `redis7` |
| 10 | 出力・接続情報 | 環境の出力と、ECS の環境変数に入る接続情報の元 | 名前・形が変わらない |
| 11 | ファミリとバージョンの整合 | 変数 `engine_version` を `17` にして `plan` | ファミリが `postgres17`、名前が `pg17` に変わる（食い違わない） |
| 12 | 秘密の混入 | 追加・変更したファイルを確認する | 認証情報・実のアカウント ID なし |
