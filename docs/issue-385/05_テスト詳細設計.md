# 05_テスト詳細設計

| No | 確認方法 | 対象 |
|---|---|---|
| 1 | `terraform fmt -recursive -check -diff`（`secuaigent-infra/`）と、`secuaigent-infra/environments/dev` の `init -backend=false` → `validate` | `secuaigent-infra/` |
| 2〜7・10 | 作業用ディレクトリに、変更前（`develop`）と変更後の `secuaigent-infra/` を置き、`AWS_PROFILE=oic` で backend をローカルに差し替えて `plan -out` → `terraform show -json`。リソースのアドレス（モジュール接頭辞を除く）で突き合わせ、増減と、`values` の差分を出す | 同左 |
| 3 の補足 | `plan` で確定しない値は、`git diff` を読んで確認する | `git diff` |
| 8 | `aws rds describe-db-engine-versions --engine postgres`（メジャー 18 の版とファミリ）、`aws rds describe-orderable-db-instance-options --engine postgres --engine-version <最新18系> --db-instance-class db.t4g.micro`（ストレージ種別と暗号化） | `oic`・`ap-northeast-1`（読み取りのみ） |
| 9 | `aws elasticache describe-cache-engine-versions --engine redis`、`--engine-version 7.1`（ファミリ） | 同上 |
| 11 | 作業用ディレクトリで `plan -var`（モジュールの入力は環境の変数にないので、作業用コピーでモジュールの既定値を `17` に書き換えて `plan`） | 同上 |
| 12 | `git diff` の追加行を目視。12 桁の数字・鍵の文字列を検索する。確認は、文書の最後の更新のあとに行う | 変更ファイル全体 |

注意: `plan` と上の確認は、AWS に読み取りだけを行う。`apply` は実行しない。作業用ディレクトリの `terraform.tfvars` と `tfplan` は、確認後に削除する。
