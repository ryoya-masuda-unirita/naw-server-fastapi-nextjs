# RDS・ElastiCache・ECR の設定値を secuaigent-infra に揃える

## 概要

Issue #385（親: #380。#381〜#384 はマージ済み）。データストア（RDS・ElastiCache）とコンテナレジストリ（ECR）の設定を、移植元 `secuaigent-infra` の設定値に揃える。

## 説明

- RDS: `storage_encrypted=true`、`backup_retention_period=7`、パラメータグループ、自動マイナーバージョンアップグレード。`engine_version` は、移植元の矛盾（16.4 と postgres18）を写さず、バージョンを決めて合わせる。pgvector に必要な拡張・権限（`scripts/db-init`）も確認する
- ElastiCache: Redis 7.1、`at_rest_encryption_enabled=true`、port 6379
- ECR: ライフサイクル（untagged を 30 日で削除）、`scan_on_push`
- 注意: 暗号化は、既存の RDS では再作成になる。新アカウントでの新規構築が前提

- 移植元: `~/Documents/unirita-develop-pj/secuaigent-ref/secuaigent-infra/`（origin/develop 77249de3）の rds・elasticache・ecr モジュール
- サブドメイン前提は持ち込まない。AWS はローカル実行のときだけ `AWS_PROFILE=oic`（別アカウント・新規構築）。`apply` は人が実行する。**費用がかかるため、デプロイはしない**（ユーザーの指示）
- DB パスワードの `random_password` 化と Secrets Manager は #386 の範囲（この Issue では、パスワードは変数のまま）
- 調査（読み取りのみ、`oic`、`ap-northeast-1`）で確認した事実: RDS の PostgreSQL は 18.1〜18.6 が利用可能（パラメータグループのファミリは `postgres18`、`db.t4g.micro` を提供）。16 系は 16.11 以降で、移植元の既定値 `16.4` は存在しない。ElastiCache の Redis は 7.1 が利用可能（ファミリは `redis7`）
