# 02_基本設計

## 変更対象

パスワード再設定画面と、更新成功後のストア処理。

## 画面 / API 変更概要

- 画面: 入力チェックの文言、失敗メッセージの表示位置、成功トースト、ログインID欄の無効化
- API: 変更なし（`POST /auth/password/reset`）

## 影響範囲

- パスワード再設定画面の入力・送信・遷移
- 更新成功後は、ページを読み込み直さずルーターでダッシュボードへ移る（ストアの `completePasswordReset` はユーザー情報を保存するだけになる）

## 移植方針

- 移植元 `pw-reset.component.ts` / `.html` と `form-errors.ts`・`pw-reset.validation.ts` に合わせる
- 判断（05-05）: 移植元の現行はログインID欄が `disabled`（コンポーネントの spec も「編集できないこと」を確かめている）。Angular は無効な欄を検証しないため、ログインIDが空でも必須エラーは出ず、API の応答（エラー）がそのまま欄の下に出る。迷ったら移植元のコードを正とする方針に従い、React も欄を無効にして必須チェックはしない。05-05 の項目書の期待（必須エラー）は現行の移植元と合っていないため、E2E は移植元の挙動を確かめる読み替えにした
- 移植元は画面の上部の帯を持たない。React が独自に出していた帯は削除する
