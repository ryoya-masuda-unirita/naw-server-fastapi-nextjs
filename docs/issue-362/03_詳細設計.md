# 03_詳細設計

## 実装対象ファイル

| ファイル | 内容 |
|---|---|
| `frontend/src/lib/utils/auth-validation.ts`（新規。#360 と同一内容） | 必須・パスワード欄のチェック関数 |
| `frontend/src/routes/auth/pw-reset.tsx` | 欄ごとの touched と計算したエラー、`noValidate`、ログインID欄 disabled（URL → ログイン中ユーザーの ID）、失敗時の `ApiError.body.message` の表示位置、成功トースト、`navigate` での遷移。上部の帯を削除 |
| `frontend/src/store/auth-store.ts` | `completePasswordReset` から `window.location.href` を外す |

## 処理

1. 送信時に全欄を touched にし、旧パスワード・新パスワード・再入力のどれかにエラーがあれば API を呼ばない
2. 成功: `useToastStore` の `success` → `completePasswordReset`（保存のみ）→ `navigate(ROUTES.APP.DASHBOARD)`
3. 失敗: `ApiError` の status で、429 は上限文言（ログインID欄の下）、400 は body の message を新パスワード欄の下、それ以外は body の message をログインID欄の下
4. いずれかの欄の入力が変わったら、失敗メッセージを消す
