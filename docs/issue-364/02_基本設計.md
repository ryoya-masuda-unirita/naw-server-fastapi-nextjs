# 02_基本設計

## 変更対象

- チーム所属アシスタント一覧 API の並べ替え
- 調査の結果、同じ漏れがあった管理者向けアシスタント一覧 API の並べ替え

## 画面 / API 変更概要

- 並べ替えキー `category` を「カテゴリ名順」として解釈する
- 画面・リクエスト・レスポンスの形は変えない

## 影響範囲

- チーム詳細の所属アシスタント一覧
- 管理者向けアシスタント一覧（`category` の並べ替えが更新日時順から、カテゴリ名順に変わる）
- 他の一覧 API（インデックス、グループ、プロンプトテンプレート、グループ所属ユーザー等）は、移植元の並べ替えキーの対応表と突き合わせ、同種の漏れがないことを確認する

## 移植方針

- 移植元（`GroupAssistantSpecification.primaryCategoryNameExpression`）は、結合による行の重複を避けるため、カテゴリIDの昇順で先頭のカテゴリ名を並べ替えのキーにする。これは画面に表示される `category`（`categories[0]`）と同じ
- カテゴリを持たないアシスタントは NULL として扱う（並びの位置は DB の NULL の扱いに従う。移植元と同じ PostgreSQL では昇順で末尾）
- 管理者向けアシスタント一覧は、移植元が Spring Data の結合（`categoryMappings.category.name`）で並べるため複数カテゴリの行が重複しうる。こちらは同じ副問い合わせを使い、1 アシスタント 1 行を保つ（判断: 重複は移植元の副作用であり、画面上のページ数・件数がずれるため揃えない）
