# 03_詳細設計

## レスポンス整形の設計

移植元の `GetMessageFeedbackViewModel` / `FeedbackMessageResponse` を FastAPI 向けに移植する。

```
{
  "feedbacks": {
    "content": [
      {
        "id": "...",
        "tenantId": "...",
        "userId": "...",
        "messageId": "...",
        "message": {
          "assistantId": "...",
          "assistantName": "...",
          "content": {
            "question": "...",
            "answer": "..."
          }
        },
        "rating": "GOOD" | "BAD",
        "indexId": "...",
        "createdAt": "...",
        "updatedAt": "..."
      }
    ],
    "totalElements": 0,
    "number": 0,
    "size": 20
  },
  "assistantIdToServerMap": {
    "assistant-id": {
      "url": "...",
      "authKey": "..."
    }
  }
}
```

- `feedbacks` は `PagedFeedbackMessageResponse` 相当のラッパーとする
- `assistantIdToServerMap` は `LOCAL_SERVER` endpoint を持つ assistant のみ含める
- `message.content` は `message_contents` が見つからない場合でも `question` / `answer` を `null` として返せるようにする
- `indexId` は `message_feedbacks.index_id` をそのまま返し、移植元の `deriveIndexId()` 相当の `File` 補完は実装しない

## 取得クエリの設計

一覧取得は `message_feedbacks` を起点にし、以下の情報をまとめて取得する。

1. `message_feedbacks` 本体
2. 対応する `messages`
3. 対応する `message_contents`

実装上は、まず `message_feedbacks` に対して絞り込み・ソート・ページングを適用して対象行を確定する。
その後、対象 `message_id` 群に対して `messages` / `message_contents` を 1 クエリで取得して突き合わせる。

絞り込み条件:

- `tenant_id = :tenant_id`
- `assistantId` 指定時: `messages.assistant_id = :assistant_id`
- `rating` 指定時: `message_feedbacks.rating = :rating`
- `folderId` 指定時: `message_feedbacks.index_id = :folder_id`

ソート項目マッピング:

- `updatedAt` → `message_feedbacks.updated_at`
- `name` → `messages.assistant_id`
- `accuracy` → `message_feedbacks.rating`
- `add` → `message_feedbacks.index_id`
- `folder` → `message_feedbacks.index_id`

## 補助情報の設計

### assistantName

- 一覧に含まれる `assistantId` 群を集める
- `AssistantRepository.find_by_ids_and_tenant_id` を再利用して1クエリで取得する
- `assistant_id -> assistant.name` のMapに整形し、レスポンスへ流し込む

### assistantIdToServerMap

- 一覧に含まれる `assistantId` 群を集める
- `AssistantEndpointRepository.find_tenant_endpoints_grouped_by_assistant_id` を再利用する
- assistant ごとに `EndpointType.LOCAL_SERVER` を持つ tenant endpoint のみ抽出する
- 移植元同様 `url` / `authKey` を返す

### シードデータ

- `backend/seed.sql` に `feedbackMessage` 動作確認用データを追加する
- 追加対象:
  - `LOCAL_SERVER` endpoint を持つ SECURE assistant
  - message content が存在する feedback 1件
  - message content が存在しない feedback 1件
- これにより、`assistantName` / `assistantIdToServerMap` / `folderId` 絞り込みを `curl` で確認できるようにする

## 移植元との差分

- `indexId` の導出は `message_feedbacks.index_id` のみを使用し、移植元の `File` 補完は行わない
- レスポンスのページング部分は Spring の `Page` ではなく、本リポジトリの `content` / `totalElements` / `number` / `size` 形式に合わせる
