# 02_基本設計

## 変更対象

新規にフィードバックメッセージ一覧取得APIを追加する（新規テーブルなし、既存テーブルの変更なし）。

## 画面 / API 変更概要

| メソッド | パス | 概要 |
|---|---|---|
| GET | `/api/admin/feedbackMessage` | フィードバックメッセージ一覧取得（ページング・ソート・絞り込み対応、管理者限定） |

移植元は `{"feedbacks": Page<...>, "assistantIdToServerMap": {...}}` というラッパーで返す。
本リポジトリの既存APIは `PagedXxxResponse` を直接返す方針だが、今回のAPIは `assistantIdToServerMap` も同時に返す必要があるため、このエンドポイントではラッパー付きレスポンスを採用する。

## 影響範囲

- 新規テーブルはなし。既存の `message_feedbacks` / `messages` / `message_contents` / `assistants` / `tenant_endpoints` を読み取る
- 既存テーブルへの変更はない
- `folderId` 絞り込みは `message_feedbacks.index_id` に対する単純一致で実装する
- `indexId` のレスポンス値は `message_feedbacks.index_id` をそのまま返し、移植元の `File` からの補完導出は行わない

## 移植方針

- 認可は既存の `require_admin_or_group_admin` を使う
- `assistantId` / `rating` / `folderId` の絞り込みは、既存の repository パターンに合わせて SQLAlchemy の `select()` と条件追加で実装する
- メッセージ本文（質問・回答）は `messages` と `message_contents` をまとめて取得し、N+1 を避ける
- `assistantName` は、一覧に含まれる `assistantId` 群を集めて 1 クエリで解決する
- ローカルサーバー接続情報は、移植元と同様に対象アシスタントの endpoint から `LOCAL_SERVER` のみ抽出して `assistantIdToServerMap` として返す
- `sortField` の論理名は以下の実項目へマッピングする
  - `updatedAt` → フィードバック更新日時
  - `name` → アシスタントID相当の並び
  - `accuracy` → 評価
  - `add` / `folder` → `indexId`
- ページングは既存の `page` / `size` クエリ（0始まり）に合わせる
