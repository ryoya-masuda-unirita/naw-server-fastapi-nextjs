## 詳細

### 1. 取得・送信中に閉じられる（対応済み）
`Dialog` の `confirmLoading` は、閉じる操作を止めない。取得・送信中（`isFetchingContents || addMutation.isPending`）は、`onClose` を無視するようにした。以前は、送信中に閉じられた（`isPending` だけ）が、今は取得中も含めて閉じられない。タイミングに依存するため、テストは足していない。

### 2. `ERROR` 以外の状態（対応しない）
移植元が `ERROR` だけを判定している。生成中のやり取りがある状態で、満足度の評価を付けて追加学習する流れは、通常は起きない。回答が空のときの `-` も、移植元の本文の作り方と同じ。移植元と違う基準を、ここで足すかは、別に決める。

### 3. Markdown のエスケープ（対応しない）
移植元も、同じく、そのまま入れている。学習データの構造を壊す入力は、運用上の想定外で、今回の移植の範囲外。

### 4. HTTP 以外の失敗（対応済み）
指摘は正しい。`fetchMessageContents` は、失敗を握って `failures` に入れるため、`ApiError` 以外の失敗（ローカル用サーバーに繋がらない）は、共通のトーストに乗らない（`viaLocalServer` のコメントのとおり）。移植元の「通信の失敗だけのときは出さない」は、Angular の共通の仕組みを前提にしていた。`fetch_failed` の区別をやめ、通信の失敗も `missing` として、`ADD_LEARNING_CONTENT_MISSING` を出すようにした（HTTP のエラーのときは、共通のトーストと重なることがある）。
