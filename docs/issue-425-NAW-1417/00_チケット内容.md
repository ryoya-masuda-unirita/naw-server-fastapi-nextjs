# NAW-1417 満足度タブの追加学習で、ルームのやり取り（最新の版）を学習データにする

## 概要

Issue #425（NAW-1417 の移植、`client/` 側）。フィードバック一覧「満足度」タブの追加学習で、ルームのやり取り（質問と回答）を学習データに入れる。

## 現状（こちら）

- `buildSatisfactionAdditionalLearningContent` が、ルーム情報（ID・名前・ユーザー・評価）だけで、質問と回答を入れていない
- `satisfaction-tab.tsx` の `submitLearning` が、`GET /api/messages?roomId=` を呼ばずに送っている
- 画面に表示中の版を選ぶ関数がない。`FEEDBACK.ADD_LEARNING_ROOM_EMPTY`・`FEEDBACK.ADD_LEARNING_CONTENT_MISSING` の文言が `ja.json`・`en.json` にない

## 移植元の挙動（`feedback-list/`、コミット 86b653027・3a9c0f3aa・7ebc84d06・3d84528a7）

1. `GET /api/messages?roomId=` でメッセージ一覧を取る
2. `selectVisibleThread`: 根（`parentId` なし）から親子をたどり、各段で**最新の版**（同じ親の子の最後）を 1 本の流れにする。段数はメッセージ数まで（循環しても止まる）
3. 流れが 0 件なら、トースト `FEEDBACK.ADD_LEARNING_ROOM_EMPTY` を出して、送らない
4. 流れの各メッセージの本文を取る（ローカルのアシスタントは、ローカル用サーバーから。既存の `fetchMessageContents`）
5. 取れなかったもの（`failures` あり・本文の件数が流れと違う・`status=ERROR` がある）があれば、送らない。通信の失敗だけのときは、共通のエラートーストが出るので、それ以外の理由のときだけ `FEEDBACK.ADD_LEARNING_CONTENT_MISSING` を出す
6. 本文は、既存の項目のあとに、やり取りごとに `## 質問`・`## 回答` を並べる（空は `-`）
7. ローカルのフォルダなら、ローカル用サーバーへ送る（今もある `addIfLocalFolder`）
