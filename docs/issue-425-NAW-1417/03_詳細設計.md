# 03_詳細設計

対象は `client/src/components/features/admin/feedback/`。

## 1. `room-thread.ts`（新規）
`selectVisibleThread(records)`: `parentId = null` から始め、`getSiblingRecords`（`@/lib/chat/message-thread`）で同じ親の子を取り、**最後の 1 件**（最新の版）を流れに足して、その ID を次の親にする。流れの長さがメッセージ数に達するか、子がなくなったら止まる（循環・自己参照でも止まる）。

## 2. `room-learning-contents.ts`（新規）
- `RoomLearningError(reason, message)`: `reason` は `empty` / `missing` / `fetch_failed`
- `fetchRoomContents(roomId)`:
  1. `apiClient.get(API_PATHS.MESSAGES.LIST, { params: { roomId } })`
  2. `selectVisibleThread` → 0 件なら `empty`
  3. `fetchMessageContents({ ...list, messages: thread })`（ローカルのアシスタントは、この中でローカル用サーバーへ振り分けられる）
  4. `failures` あり・本文の件数が流れと違う・`status === 'ERROR'` のどれかなら、投げる。`failures` があり、すべて `fetch_failed` なら `fetch_failed`、それ以外は `missing`

## 3. `additional-learning-content.ts`
`buildSatisfactionAdditionalLearningContent(item, contents)`: 既存の項目のあとに、本文ごとに `## 質問`・`## 回答` を並べる（空は `-`）。

## 4. `satisfaction-tab.tsx`
`submitLearning`: 取得中の状態（`isFetchingContents`）を立て → `fetchRoomContents` → 本文の作成 → `addMutation.mutateAsync` → ダイアログを閉じる。`RoomLearningError` の `empty` → `ROOM_EMPTY`、`missing` → `CONTENT_MISSING` のトースト（`useToastStore`）。`fetch_failed` と、それ以外の通信エラーは、api-client の共通トーストに任せる。ダイアログの「送信中」は、取得中と送信中の両方で効かせる（二重送信を防ぐ）。

## 5. 文言
`ja.json`・`en.json` の `FEEDBACK` に、`ADD_LEARNING_CONTENT_MISSING`・`ADD_LEARNING_ROOM_EMPTY`（移植元の文言のまま）。
