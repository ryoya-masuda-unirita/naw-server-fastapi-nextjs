# 02_基本設計

## 変更対象

- API クライアント（テナントIDの読み出し・保存・削除と、ヘッダ付与）
- 認証ストア（ログイン・ログアウト・パスワードリセット完了・セッション初期化）
- 認証関連の型定義（ログイン入力値の型）
- ログイン画面
- i18n 定義（日本語・英語）
- 上記に対応する単体テスト

## 画面 / API 変更概要

- ログイン画面のタイトル直下（ユーザーIDの上）にテナントID入力欄を追加する。ラベル・プレースホルダーは「テナントID」。
- ログイン API のリクエストボディは変更しない（ユーザーID・パスワードのみ）。テナントIDはヘッダで送る（backend のログイン API はボディにテナントIDを持たない）。
- 送信順序: テナントIDをセッションストレージに保存 → ログイン API 呼び出し（ヘッダ付き）→ 成功時はユーザー情報を保存してダッシュボードへ。
- ログイン成功後に「テナントIDを得るためだけに」行っていたセッション確認 API 呼び出しは、テナントIDが既に保存済みになるため廃止する（パスワードリセット完了時も同様）。
- アプリ起動時のセッション確認の結果ではテナントIDを保存しない。backend のセッション確認 API はテナントIDを返さないため、既存の「セッション確認の結果からテナントIDを保存する」処理は削除する（code-review 指摘 1）。
- セッション確認が失敗した場合（未ログイン）はテナントIDを削除しない。パスワードリセット画面への遷移はフルページ遷移でアプリの初期化（セッション確認）が走るため、ここで削除するとパスワードリセット API にヘッダが付かなくなる。

## 影響範囲

- ログイン画面
- テナントIDを使うすべての API リクエスト（API クライアント経由のもの全部）
- ログアウト処理
- パスワードリセットの流れ（ログイン→リセット画面→リセット完了）
- 既存のログイン画面・認証ストアの単体テスト

## 移植方針

- 移植元は上流 `secuaigent/client` ではなく、このリポジトリの `frontend-angular/`（#193 適用済み）とする。上流はサブドメイン方式のままのため、テナントの決め方は参考にしない。
- Angular → React の対応（`frontend/.claude/CLAUDE.md` の対応表に沿う）:
  - Angular のテナント解決ユーティリティ（読み出し・保存）→ React では API クライアントのモジュール内に読み出し・保存・削除の関数を置く（API クライアントがヘッダ付与の唯一の利用者であり、認証ストアは既に API クライアントに依存しているため。また #223 との衝突を避けるため新しい import を API クライアントに増やさない）。
  - Angular の HTTP インターセプターによるヘッダ付与 → React の API クライアント内の共通ヘッダ生成（既存）をそのまま使う。
  - Angular の signalStore（AuthStore.login で API 呼び出し前に保存）→ React の Zustand 認証ストアの login で同じ順序で保存する。
  - Angular のリアクティブフォーム（tenantId コントロール）→ React の `useState` と共通入力コンポーネント。
- Angular 版との意図的な差分:
  - パスワードリセットが必要なユーザーのとき、Angular 版はテナントIDも含めてセッションストレージを消してからリセット画面へ遷移するが、リセット API はヘッダ必須のため、React 版ではテナントIDを残す（ユーザー情報のみ消す既存動作を維持）。
  - Angular 版はログインリクエストのボディにもテナントIDを含めているが、backend は使わないため React 版ではボディに含めない。
