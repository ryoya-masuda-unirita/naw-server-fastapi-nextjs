# 01_要件定義

## 背景

- backend はログイン・パスワードリセット・セッション確認を含む API で `X-Tenant-ID` ヘッダを必須としている。
- React 版フロントエンドには、テナントIDを入力する手段も、ログイン前にテナントIDを保存する手段もない。API クライアントは保存済みのテナントIDがあればヘッダに付ける作りになっているが、テナントIDを保存するのはログイン成功「後」のセッション確認だけで、最初のログインリクエストにはヘッダが付かない。このため React からはログインできない。
- このリポジトリはテナント識別にサブドメインを使わない方針（#193・#195）であり、Angular 版（frontend-angular）では #193 でログイン画面からテナントIDを入力する方式に変更済み。#223 で frontend-angular を削除し dev 環境を React に切り替えるため、同じ方式を React に移植する。

## 機能要件

1. ログイン画面に、ユーザーID・パスワードと並ぶ入力項目として「テナントID」を追加する（ユーザーIDより上に配置）。
2. テナントIDは必須とし、未入力ではログインリクエストを送らない。
3. ログイン実行時、ログインリクエストを送る前に入力されたテナントIDをブラウザのセッションストレージへ保存する。
4. 保存されたテナントIDを、ログインリクエストを含む以降のすべての API リクエストに `X-Tenant-ID` ヘッダとして付与する（ログイン、セッション確認、パスワードリセットを含む）。
5. ログインに失敗した場合は、保存したテナントIDを削除する（Angular 版で認証エラー時に削除しているのに合わせる）。
6. ログアウト時は、保存したテナントIDを削除する（Angular 版と同じ）。
7. 初回パスワードリセットが必要なユーザーの場合は、パスワードリセット API にもヘッダが必要なため、テナントIDを保持したままパスワードリセット画面へ遷移する。
8. テナントIDの決定にサブドメイン（ホスト名）は使わない。
9. 画面文言は i18n（日本語・英語）で定義する。文言は Angular 版と同じ「テナントID」/「Tenant ID」とする。

## 非機能要件

- 既存のログイン画面のデザイン（共通入力コンポーネント・レイアウト）に揃える。
- #223（未マージ）が同じ API クライアントを変更しているため、マージ時に衝突しにくい変更範囲に留める。
- ブラウザでの実機確認は行わず、自動テスト（Vitest）で代替する。

## スコープ外

- backend の変更（既にヘッダ必須で実装済み）
- URL クエリ `tenantId` によるテナントID受け渡し（Angular 版のログインキー初期化・パスワードリセット画面にある代替経路）。React 側にはログインキー機能自体が未移植のため、必要になった時点で別 Issue とする。
- ログインフォームの文字数バリデーション（Angular 版はテナントID・ユーザーIDともに 3〜50 文字の検証を持つが、React 版はユーザーIDにも未移植のため、テナントIDもユーザーIDと同じく必須チェックのみとする）。
- 401 応答時の共通エラーハンドリング（Angular 版の errorInterceptor に相当する仕組み）は React 側に未移植のため対象外。
- ログアウト API が失敗したときの挙動差（Angular 版はローカル状態を消さずに中断、React 版は消してログイン画面へ遷移）は、テナントIDの扱いと無関係のため変更しない。
