## API クライアント（`frontend/src/lib/api-client.ts`）

#223 が `API_BASE_URL` 定義行（1 行目）と `get` / `post` の URL 組み立てを変更しているため、その範囲は触らない。`resolveTenantId` の直前・直後のみ変更する。

- `const TENANT_ID_STORAGE_KEY = 'TENANT_ID';` を `resolveTenantId` の直前に追加（既存キー名を維持し、文字列リテラルの重複をなくす）
- `resolveTenantId()` を `export` し、キーは定数を参照する
- `persistTenantId(tenantId: string): void` を追加・export（`sessionStorage.setItem`）
- `clearTenantId(): void` を追加・export（`sessionStorage.removeItem`）
- `getHeaders()` は変更しない（`resolveTenantId()` が truthy のときだけ `X-Tenant-ID` を付ける既存動作が Angular の `authInterceptor` と同じ）

## 型定義（`frontend/src/types/auth.ts`）

- `LoginCredentials extends LoginRequest { tenantId: string }` を追加する。`LoginRequest` は API ボディの型として据え置く（backend のボディは `username` / `password` のみ）

## 認証ストア（`frontend/src/store/auth-store.ts`）

- `login(credentials: LoginCredentials)`:
  1. `persistTenantId(credentials.tenantId)`（ログインリクエスト自体に `X-Tenant-ID` を付けるため API 呼び出し前に保存）
  2. `apiClient.post(API_PATHS.AUTH.LOGIN, { username, password })`。失敗したら `clearTenantId()` してから再 throw（Angular の errorInterceptor が login の 401 で削除するのに合わせる）
  3. `REQUIRES_PASSWORD_RESET` の分岐はテナントIDを消さない（既存どおり `AUTH_USER` のみ削除）
  4. 成功時のテナントID取得用 `GET /api/auth` 呼び出しを削除（保存済みのため不要）
- `completePasswordReset()`: テナントID取得用 `GET /api/auth` 呼び出しを削除（ログイン時に保存済みのものを使い続ける）
- `logout()`: `sessionStorage.removeItem('TENANT_ID')` を `clearTenantId()` に置き換え
- `ensureInitialized()`: 成功時の `sessionStorage.setItem('TENANT_ID', session.tenant_id)` を削除する。backend の `AuthResponse` に `tenant_id` はなく、`"undefined"` で上書きしてしまうため（code-review 指摘 1）。失敗時はテナントIDを消さない（02 参照）
- `BackendAuthResponse` 型と MSW の `/api/auth` モックから、backend に存在しない `tenant_id` を削除する

## ログイン画面（`frontend/src/routes/auth/login.tsx`）

Angular の `login.component.html` と同じく、タイトルの直後・ユーザーIDの直前に配置する。

- `const [tenantId, setTenantId] = useState('')` を追加
- `FormInput` を追加: `id="tenantId"`、`label={t('AUTH.LOGIN.TENANT_ID_LABEL')}`、`placeholder={t('AUTH.LOGIN.TENANT_ID_PLACEHOLDER')}`、`autoComplete="organization"`、`required`、`disabled={isLoading}`、`onChange` でエラー表示をクリア（ユーザーIDと同じ）
- `handleSubmit` で `tenantId.trim()` を必須チェックに加え、`login({ tenantId: trim 後の値, username, password })` を呼ぶ（空白だけの入力を弾くため。code-review 指摘 4）
- Tailwind クラスは既存の `FormInput` / `AuthLayout` をそのまま使い、新しいクラスは追加しない

## i18n（`frontend/public/i18n/ja.json` / `en.json`）

- `AUTH.LOGIN` に `TENANT_ID_LABEL` / `TENANT_ID_PLACEHOLDER` を追加（ja: 「テナントID」、en: 「Tenant ID」。Angular 版と同じ）
