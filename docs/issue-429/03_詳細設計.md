# 03_詳細設計

対象は `secuaigent-server-local/`。

## 1. 認証の除外パス（`app/core/security.py`）

- 静的メソッド `_is_same_or_under(path, base)` を足す: `path == base or path.startswith(f"{base}/")`（移植元 `ServerAuthKeyFilter.isSameOrUnder`）
- `_should_not_filter` の `is_health_check` を、`_is_same_or_under(scope["path"], self.health_check_prefix)` にする（`health_check_prefix` は、コンテキストパス込みの `/api/hello`）
- docstring に、配下の扱いと、`/api/helloX` を除外しない理由を書く

## 2. ログ（本文を出さない）

| # | ファイル | 変更 |
|---|---|---|
| A | `app/services/waha_inputs.py` | `histories.json` のログを、`content=%s`（JSON 全文）から `count=%s`（`len(histories)`）にする |
| B | `app/services/message_content_stream_service.py` | `textData.json` のログを、`streamfilepath`・`createLibrary`・`tools`（名前だけ）・`messageId`・`hasAccessToken`（`bool(accessToken)`）にする。アクセストークンの値は出さない |
| C | `app/routers/messages.py`（`_log_received_request`） | 引数から `dto` を外し、`command` から、`endpoint`・`assistantId`・`messageId`・`messageContentId`・`userInputLength`・`additionalPromptLength`・`historyCount`・`tools`（名前）・`createLibrary`・`tenantId`・`hasAccessToken`・添付ファイルの名前とサイズ、を出す。本文は出さない |
| D | `app/services/message_content_stream_service.py` | 出力ファイルの取得のログを、`rawResponse=%s`（先頭 500 文字）から `length=%s`（文字数。`None` なら `None`）にする |
| E | `app/main.py` | `aiosqlite`・`sqlalchemy.engine` のロガーを `WARNING` に固定する（`httpx` と同じ扱い）。`LOG_LEVEL=DEBUG` にすると、SQL の値（質問・回答の本文）が出るため |

## 3. 不要になったコードの削除

- `app/services/message_content_stream_service.py`: `_mask_access_token`・`MASKED_VALUE`（B で本文を出さなくなり、使われない）、`_preview`・`LOG_PREVIEW_MAX_LENGTH`（D で使われない）
- `app/routers/messages.py`: `_parse_message_request` の戻り値の `dto`（ログのためだけに返していた）と、3 つのエンドポイントでの受け取り、`to_compact_json` のインポート。戻り値は `CreateMessageContentCommand` だけにする

## 4. テスト

- 新規 `tests/test_log_privacy.py`
  - 秘密の値（質問・追加のプロンプト・履歴の質問と回答・回答・ツールのサーバー名・アクセストークン）を含むリクエストを処理し、**DEBUG までのログ**に、どの値も出ないこと（値ごとのパラメータ化テスト）
  - Waha! には、質問・履歴・アクセストークンが、そのまま送られること（ログだけが変わり、動作は変わらない）
  - 調査に使う情報（`historyCount=2`・`count=2`・`hasAccessToken=True`・`messageId=msg-1`・`web_search`、`Preparing histories.json`・`Preparing textData.json`・`Waha outputfile downloaded`）が、ログに残ること
- `tests/test_hello_and_security.py`: `/api/helloX`・`/api/hello-world`・`/api/hello.json` が 401、`/api/hello/` が 401 にならない、コンテキストパス付きの `/secuaigent/api/helloX` が 401
- `tests/test_message_content_stream.py`: `test_access_token_is_not_logged` の確認を、`"accessToken":"***"` の有無から、`hasAccessToken=True` の有無に変える

## 5. README（`secuaigent-server-local/README.md`）

- `LOG_LEVEL` の説明に、本文・トークンの値を出さないこと、`aiosqlite`・`sqlalchemy.engine` を `WARNING` に固定していることを書く
- 稼働確認 API の認証除外の説明に、配下だけを除外し、名前の頭だけが一致するパスは除外しないことを書く
