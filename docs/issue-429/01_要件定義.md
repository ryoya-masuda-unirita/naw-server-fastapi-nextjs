# 01_要件定義

## 背景

- ローカル用サーバー（オンプレ配布）は、ユーザーの質問・会話履歴を、Waha!（生成 AI の実行基盤）に渡すために、ファイルとしてアップロードする。そのとき、内容を確かめるために、本文を、ログ（INFO）に出していた
- ログは、運用担当者などが閲覧できる。本文をそのまま出すと、**ログを見られる人に、会話の内容が見える**。レベルを DEBUG に下げても、DEBUG を有効にすれば、同じ漏えいが起きる（移植元の判断）
- 移植元は、これを直した（NAW-1438）が、直したのは、Waha! に渡すファイルの本文のログ（A・B）だけで、リクエストの受信のログ（C）と、出力ファイルのログ（D）は、本文を出したまま残っている
- 認証キーの除外パスは、`/api/hello` で始まるパスをすべて除外している。意図は、ヘルスチェック（`/api/hello`）だけを除外すること

## 機能要件

1. **会話の本文を、INFO を含む、どのレベルのログにも出さないこと**。対象は次のとおり
   - A. 会話履歴のファイル（`histories.json`）の本文 → 件数（ファイル名・スロットなどの、中身を含まない情報は出してよい）
   - B. `textData.json` の本文 → ストリームファイルのパス、ライブラリ作成の有無、ツール名、メッセージ ID、アクセストークンの有無（値は出さない）
   - **C. リクエストの受信のログ** → 質問（`userInput`）、追加のプロンプト、会話履歴の本文、ツールの設定の詳細を出さず、本文を含まない情報（エンドポイント、アシスタント ID、メッセージ ID、メッセージ内容 ID、履歴の件数、質問・追加のプロンプトの有無や長さ、ツール名、ライブラリ作成の有無、テナント ID、アクセストークンの有無、添付ファイルの名前とサイズ）だけを出す
   - **D. Waha! の出力ファイルのログ** → 本文（先頭 500 文字）を出さず、長さなどの、中身を含まない情報だけを出す
2. ログが減って、障害の調査に困らないよう、調査に必要な、本文を含まない情報（セッション ID、メッセージ内容 ID、件数、サイズなど）は、残すこと
3. **ヘルスチェックの除外パスを、完全一致にすること**。`/api/hello`、または `/api/hello/` で始まるパスだけを、認証キーなしで通す。`/api/helloX` などは、認証キーが必要（401）。コンテキストパス付きの場合も同様に判定する
4. 既存のログの出力形式（項目名）は、本文を除いて、極力変えない（運用で検索している可能性があるため）
5. ログに本文が出ないことを、テストで確かめること。認証の除外パスの判定を、テストで確かめること

## 非機能要件

- 動作・API の仕様は変えないこと（ログと、除外パスの判定の厳格化だけ）
- `ruff`・`mypy`・既存のテストが通ること
- ログのためだけに、本文を組み立てる処理（JSON のシリアライズなど）が、無駄に残らないこと
- 費用: なし

## スコープ外

- `server/`（FastAPI）の監査ログ（HTTP リクエストの監査ログのフィルタ自体が未移植）。Issue #429 のとおり、別の Issue とする
- `java -jar` 起動時の除外パス、`/h2-console` の除外（Java 固有）
- ログの出力先・保存期間・閲覧権限の見直し
- DEBUG レベルのログ（`waha_client.py` のポーリングの応答など）の見直し。本文を含むかは、確認できていない
- Waha! へのファイルのアップロードの応答のログ（`waha_client.py`）。会話の本文ではないと見ているが、**中身は未確認**。今回は変えない
