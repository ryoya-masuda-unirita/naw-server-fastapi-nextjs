## 確認の途中で分かったこと

- 実装後も、2 件（質問・回答）が失敗した。原因は、このアプリのログではなく、**外部ライブラリ `aiosqlite` の DEBUG ログ**が、SQL の値（質問・回答の本文）を出していたこと。`LOG_LEVEL=DEBUG` にすると、本番でも同じことが起きる（アプリは `logging.basicConfig(level=…)` でルートのレベルを変えるため）。`aiosqlite` と `sqlalchemy.engine` を `WARNING` に固定した（すでに `httpx` は同じ扱い）。その後、全件が成功した
- 調査の段階で、`routers/messages.py` が、質問・追加のプロンプト・会話履歴の全体を INFO に出していることが分かった（移植元の修正は、これを直していない）。この変更では、直した

## 未確認事項

- **実際の Waha!・本番のログ出力では確認していない**。偽の Waha! を使ったテストで、アプリのログ（DEBUG まで）に本文が出ないことを確認した
- **`waha_client.py` の、アップロードの応答のログ**（`response=%s`）は、Waha! の応答で、会話の本文ではないと見ているが、**中身は確認していない**。今回は変えていない
- **DEBUG のポーリングのログ**（`waha_client.py`、`rawResponse=%s`）は、本文を含むかを確認していない。今回は変えていない（スコープ外）
- **運用の検索・監視**: ログの項目名（`content=`、`rawResponse=` など）で検索している運用があれば、影響を受ける。有無は、確認できていない
- `mypy` は、このプロジェクトの CI では使っていないため、実行していない
