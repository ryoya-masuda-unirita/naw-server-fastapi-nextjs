# NAW-1438 secuaigent-server-local の会話本文のログ出力をやめ、認証の除外パスを完全一致にする

## 概要

Issue #429（NAW-1438 の移植、`secuaigent-server-local/`）。次の 2 点を直す。

1. 会話の本文を、ログに出さない（プライバシー）
2. 認証キーの除外パス（ヘルスチェック）の判定を、完全一致にする（予防の修正）

## 説明

### 1. 会話の本文のログ

調査（`secuaigent-server-local/app/` の、INFO 以下のログ 43 件のうち、本文・履歴・トークンに関わるもの）で、次の 4 か所を確認した。

| # | 場所 | 出ているもの | 移植元の NAW-1438 の修正 |
|---|---|---|---|
| A | `services/waha_inputs.py` | `histories.json` の全文（会話履歴の質問と回答） | 直した（本文をやめ、件数だけにした） |
| B | `services/message_content_stream_service.py`（textData の準備） | `textData.json` の全文（アクセストークンは伏せ済み。ほかは `tools`・`messageId`・`streamfilepath`・`createLibrary`） | 直した（本文をやめ、ストリームファイルのパス・ライブラリ作成の有無・ツール名・メッセージ ID・トークンの有無だけにした） |
| C | `routers/messages.py`（リクエストの受信） | **リクエスト全体**（`userInput`＝質問、`additionalPrompt`、`historyMessages`＝会話履歴の全体、`tools`、`tenantId` など。アクセストークンだけ除外） | **直していない**（移植元も、修正後に、リクエスト全体を INFO に出している） |
| D | `services/message_content_stream_service.py`（出力ファイルの取得） | Waha! が返した出力ファイルの先頭 500 文字（**回答の本文**） | **直していない**（移植元にも同じログがある） |

- 移植元の NAW-1438 は、A と B だけを直した。**C と D は、移植元でも、修正後に、本文が INFO に出る**。したがって、移植元の修正を、そのまま移植しても、「会話の本文を INFO ログに出さない」という目的は、達成できない
- 参考: Waha! へのファイルのアップロードの応答（`waha_client.py`）も、INFO に出ているが、Waha! の応答で、会話の本文ではないと見ている（**中身は未確認**）

### 2. 認証の除外パス

`app/core/security.py` の、ヘルスチェックの除外が、前方一致（`startswith`）。`/api/hello` で始まるパスは、すべて認証キーなしで通る。現在、`/api/hello` で始まるルートは `/api/hello` だけなので、すぐには悪用できないが、将来、`/api/hello-…` のようなルートを足すと、認証なしになる。移植元は、「完全一致、または `/` で始まる」に直した（コミット e31491ed4）。
