# 02_基本設計

## 変更対象

- ライブラリの API（本文取得を追加）
- ライブラリの業務処理（閲覧できるかの判定を取得と本文取得で共有する）
- ライブラリの応答スキーマ（本文取得の応答を追加）

## 画面 / API 変更概要

### `GET /api/libraries/{libraryId}/content`（新規）

| 項目 | 内容 |
|---|---|
| 認証 | 必要（ログインユーザー） |
| 成功 | 200 `{"data": "<本文>"}` |
| ライブラリが無い・閲覧できない | 404 `Library not found` |
| 本文が無い | 404 `Library content not found` |

既存の API の応答・挙動は変えない。

## 影響範囲

- ライブラリの取得（`GET /api/libraries/{libraryId}`）は、閲覧判定を共通化するだけで挙動は変えない

## 移植方針

- 応答の形と文言は移植元 `LibraryController#getLibraryContent`・`LibraryService#getLibraryContent` に合わせる
- 本文の置き場所だけ移植元と違う。移植元は `library_contents` テーブル（行が無ければ 404）、backend は `libraries.content` 列（NULL なら 404）。外から見える挙動は同じになる
