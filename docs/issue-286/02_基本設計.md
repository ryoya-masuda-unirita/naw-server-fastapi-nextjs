### 差し込み方

`ChatInput` の `renderMention`・`renderAddMenu`・`renderToolbar`・`onTextareaKeyDown` を `components/features/chat/chat-input-slots.tsx` の `CHAT_INPUT_SLOTS` にまとめ、`ChatWindow` が `ChatInput` に既定で渡す（`inputSlots` で個別に上書きできる）。`chat-input.tsx` は変更しない。`chat-window.tsx` の変更は、既定スロットの展開と `isChatExamList` の追加だけ。

### 意図的な差分

1. 入力欄の部品どうし（メンション候補・キー処理・ウィジェット）で共有する状態は `store/chat-input-ui-store.ts` に置く。スロットが別々に描画されるため
2. 「状態を持つ項目」（Web 検索・ライブラリ作成・テンプレート）と、有効が 1 つのときのピルは、移植元では `<button>` の中に `<button>`（×）を入れている。入れ子のボタンは不正な HTML（React が警告）なので、外側だけ `div`（メニュー項目は `role="menuitem"`、キーボードは Enter / Space）にした。見た目は同じ
3. 「＋」メニューの添付項目は、移植元の `fileInput.click()` の代わりに、入力欄（`.chat-input-textarea-wrap`）内の `input[type=file]` を探してクリックする。input は添付の領域（#287）にあるため
4. 移植元の「＋」メニューにあるモバイル用の暗幕は `hidden md:hidden!` で常に非表示（かつクリックの処理が呼び出しになっていて何もしない）ため、移さない
5. 日本語変換（IME）中の入力は、Angular の ngModel が確定まで値を更新しないが、React は変換中も値が変わる。そのため変換中でも先頭が「@」なら候補が出る（確定の Enter は変換の確定に使われ、候補の確定にならない点は移植元と同じ）
6. テンプレートのサブメニューの一覧は、開いているときだけ描画する（移植元は常に描画して hidden）
7. アシスタントの説明文が、選択一覧（閉じている）にも載るようになったため、`chat-pages.test.tsx` の 1 件の期待値を調整した
