# 03_詳細設計

## 追加する依存パッケージ

- `aioboto3`（S3/SQSへの非同期アクセス）
- LocalStack CLI互換ツール（キュー・バケットの初期化に使用。専用の追加コンテナ内で完結させ、backend側の依存には加えない）

## ローカル環境構成（`docker-compose.yml`）

- `localstack` サービスを追加する。イメージは `localstack/localstack`、有効化サービスは `s3,sqs` のみに絞る
- コンテナ起動後にバケット・キューを自動作成する初期化スクリプトを用意し、LocalStackの起動時フック（`/etc/localstack/init/ready.d/`）に配置する
  - バケット名・キュー名は `application.yml` の命名（`secuaigent-user-import-jobs-dev` 等）に寄せつつ、ローカル専用のサフィックスを付ける
- `backend` サービスに、S3/SQSのエンドポイントをLocalStackに向ける環境変数を追加する

## backend設定（`app/core/config.py`）

- `Settings` クラスとは別に、既存の `RedisSettings` 等と同様の切り出し方針で `AwsSettings` を追加する
  - `aws_region`（デフォルト `ap-northeast-1`）
  - `aws_endpoint_url`（LocalStack向け。未設定時は指定なし＝実AWSへ向く）
  - `aws_access_key_id` / `aws_secret_access_key`（LocalStackはダミー値で可）
  - `aws_s3_bucket_name`
  - `aws_sqs_queue_url`
  - `aws_sqs_listener_enabled`（`true`/`false`。移植元の `aws.sqs.listener-enabled` に相当）
- `.env.example` に上記のローカル向けデフォルト値を追記する

## ストレージ実装（`app/core/file_storage.py`）

- 既存の `FileStorage` プロトコル・`LocalFileStorage` は**そのまま維持する**（学習データファイル `files.py`・インデックス `indexes.py` が現在も使用しているため、削除・変更しない）
- `S3FileStorage` クラスを新規追加し、`aioboto3` の `client("s3", endpoint_url=..., ...)` でアップロード・ダウンロード・削除を行う
  - `storage_url` の形式は `s3://{bucket}/{key}` とする（移植元がS3の完全URLを保持する方式に相当）
- 既存の `get_file_storage()`（`LocalFileStorage` を返す汎用DI）は変更しない
- ユーザーインポート専用のDIとして `get_user_import_file_storage()` を新規追加し、`S3FileStorage` を返すようにする

## キュー送信（新規: `app/services/user_import_queue_service.py`）

- `UserImportQueueService.send_import_message(import_job_id, tenant_id, storage_url)` を追加する
  - 移植元 `UserImportQueueService.java` の `ImportMessage`（`importJobId`/`tenantId`/`storageUrl`）と同じ構造のJSONを組み立て、`aioboto3` の `client("sqs", ...)` で送信する

## キュー受信（新規: `app/services/user_import_listener.py`）

- `UserImportListener.run_forever(session_factory)` を追加する
  - `aioboto3` の `receive_message`（ロングポーリング、`WaitTimeSeconds` を指定）でループし、メッセージを受信するたびに `process_import_message` を呼び出す
  - `process_import_message` は移植元 `UserImportListener.java` の処理内容（テナントID検証・二重処理防止・CSVパース・行ごとの登録・S3削除）を、現行の `user_import_service.py` にある `_read_and_validate` 相当の検証ロジックとあわせてPython側に再構成する
    - 一時的なエラー（ストレージ未取得等）はメッセージを削除せず再試行に回す（`receive_message` の可視性タイムアウトに任せる）
    - 永続的なエラー（行内容の不正等）はジョブを `FAILED` にして正常終了扱いにする（メッセージは削除する）

## 起動時のバックグラウンドタスク（`app/main.py`）

- FastAPIの `lifespan` コンテキストマネージャを新規に追加し、アプリ起動時に `UserImportListener.run_forever` を `asyncio.create_task` で起動、アプリ終了時にタスクをキャンセルして待ち合わせる
- `aws_sqs_listener_enabled=false` の場合はタスクを起動しない（移植元の `listener-enabled` と同じ挙動）

## 登録処理の変更（`app/services/user_import_service.py`）

- `import_users` を、CSVの構文・必須カラムチェック（`_read_and_validate` 相当）まではその場で行い、以降の行ごとの登録処理は行わずに以下の非同期フローに変更する
  1. バリデーションエラーがあれば即 `FAILED` として返す（移植元・現行と同じくアップロード前検証は同期のまま）
  2. バリデーションを通過したら、ジョブを `PENDING` として保存し、ファイルを `FileStorage`（S3実装）にアップロードして `storage_url` を保存
  3. `UserImportQueueService.send_import_message` でキューに送信し、即座に `PENDING` のレスポンスを返す
- 行ごとの登録処理本体（`_process_rows`/`_process_row`）は `user_import_listener.py` 側に移設する

## ルーター（`app/routers/user_imports.py`）

- 変更なし（サービス層の返り値の意味が変わるのみ）
