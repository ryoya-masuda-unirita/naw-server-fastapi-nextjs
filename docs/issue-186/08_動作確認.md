# 08_動作確認

## 確認環境

- `docker compose up -d`（`naw-fastapi-postgres`/`naw-fastapi-redis`/`naw-fastapi-localstack`/`naw-fastapi-backend`/`naw-fastapi-frontend-angular`の5コンテナ）
- `docker exec naw-fastapi-backend uv run alembic upgrade head` 済み（`022 (head)`）
- `backend/seed.sql` 投入済み（`test-tenant`の`admin`/`admin@1234`を使用）
- APIは`curl`で直接実行して確認した（フロントエンドのブラウザ操作は行っていない）

## 確認手順

1. `docker compose up -d`で全コンテナを起動
2. `docker exec naw-fastapi-localstack awslocal s3 ls` / `awslocal sqs list-queues`でバケット・キューが自動作成されていることを確認
3. `/auth/login`（`X-Tenant-ID: test-tenant`、`admin`/`admin@1234`）でトークンを取得
4. サンプルCSV（`login_id,name,password,role,createLoginKey`の2行）を`POST /api/admin/users/import`でアップロード
5. レスポンスの`status`と、数秒後の`GET /api/admin/users/import/{jobId}`の`status`を確認
6. DBに実際にユーザーが登録されているか、`login_key`の有無がCSV指定（`createLoginKey`）通りかを確認
7. S3（LocalStack）上のアップロード済みファイルが処理完了後に削除されているかを確認
8. `AWS_SQS_LISTENER_ENABLED=false`を指定したbackendコンテナ（別ポート8002で一時起動）で同様にアップロードし、`PENDING`のまま進まないことを確認

## 確認結果

- `docker compose up -d`で5コンテナすべて起動し、LocalStackは`healthy`になった
- 初回確認時、SQS送信で`AWS.SimpleQueueService.NonExistentQueue`エラーが発生した
  - 原因: LocalStackの`awslocal`コマンドがリージョン未指定時に`us-east-1`でキュー・バケットを作成するのに対し、backend側は`AWS_REGION=ap-northeast-1`で問い合わせていたため
  - 対応: `docker-compose/localstack-init/init-aws.sh`の`s3 mb`・`sqs create-queue`に`--region ap-northeast-1`を明示し解消（`docs/issue-186/06_タスクリスト.md`にも記録）
- 修正後、`POST /api/admin/users/import`は即座に`{"status":"PENDING"}`を返した
- 数秒後の`GET .../import/{jobId}`は`{"status":"COMPLETED"}`になった
- DBに`sqs-test-user1`（`createLoginKey=true`→`login_key`あり）・`sqs-test-user2`（`createLoginKey=false`→`login_key`なし）が指定通り登録されていることを確認した
- 処理完了後、LocalStackのS3上の該当ファイルが削除され空になっていることを確認した
- `AWS_SQS_LISTENER_ENABLED=false`のbackend（別ポート8002で一時起動）でアップロードすると、`PENDING`のまま応答が返り、数秒待っても状態が進まないことを確認した（リスナー無効時は受付のみ行われる想定通りの挙動）
