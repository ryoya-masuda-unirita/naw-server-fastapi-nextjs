# #186 issue-186 疑似SQSのローカル対応（LocalStack導入）

## 概要

backend（FastAPI）のユーザー一括インポート機能を、S3/SQSを使った非同期構成へ方針転換するにあたり、まずローカル開発環境でSQS/S3をエミュレートする基盤を整備する。

移植元（naw-server, Spring Boot）は実際のAWS SQS/S3を前提とした実装になっているが、backend（FastAPI）は現状S3/SQSを使わない同期処理に縮小移植されている。今回、非同期構成へ方針転換するための最初のステップとして、開発者がAWSアカウントなしにローカルでSQS/S3の挙動を再現できるようにする。

## 説明

### 背景・目的

- 実際のAWSリソースに依存せず、ローカルでSQS/S3のポーリング〜メッセージ処理の一連の流れを開発・デバッグできるようにする
- 後続チケット（本番AWS構築・Terraform化・CI/CD組み込み）の前提となる、ローカル動作確認環境を先に整える

### スコープ（想定）

- docker-compose.yml に LocalStack（SQS/S3エミュレーション）を追加
- ローカル環境向けのSQS/S3設定（エンドポイントオーバーライド等）をbackend側に追加
- キュー・バケットの初期化手順（作成スクリプト or docker-compose起動時の自動作成）を整備
- ローカルでのユーザーインポートの非同期フロー（アップロード→S3保存→SQS送信→リスナー受信→DB更新）が動作確認できる状態にする

### 参照

- 参照実装（AWS SQS/S3の使い方）: `~/Documents/naw-server/src/main/java/com/example/naw/config/SqsConfig.java`, `S3Config.java`, `SqsListenerConfig.java`, `service/UserImportQueueService.java`, `service/UserImportListener.java`
- 現行のbackend実装（同期処理版）: `backend/app/services/user_import_service.py`, `backend/app/core/file_storage.py`
