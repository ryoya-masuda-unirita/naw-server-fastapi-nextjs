# 01_要件定義

## 背景

backend（FastAPI）のユーザー一括インポート機能は、移植元（Spring Boot / naw-server）がAWS S3へのCSVアップロード＋SQS経由の非同期処理で構成しているのに対し、現状は同期処理に縮小移植されている。

今後この機能をS3/SQSを使った非同期構成へ方針転換するにあたり、まず開発者がAWSアカウントを持たなくてもローカル環境でS3/SQSの挙動を再現できる基盤を用意する。これは後続チケット（実AWS構築・Terraform化・CI/CD組み込み）の前提となる。

## 機能要件

- ローカル開発環境（`docker compose up`）だけで、実AWSアカウントなしにS3バケット・SQSキューに相当する機能を利用できること
- 環境起動時に、ユーザーインポートで使うS3バケット・SQSキューが自動的に用意された状態になること
- ユーザー一括インポートの一連の流れ（CSVアップロード→ストレージ保存→キュー送信→リスナーでの受信→DB更新）が、ローカル環境上で非同期に動作し、動作確認できること
- ローカル環境向けの設定（エンドポイントの向き先など）は環境変数で切り替えられ、本番相当（後続チケットで構築する実AWS環境）に向けた設定変更が容易であること

## 非機能要件

- ローカル環境のセットアップ・起動手順が `docker-compose.yml` に集約され、追加の手動操作（AWS CLIでのキュー作成など）を極力減らすこと
- 既存の同期処理版ユーザーインポート機能のテスト・動作に影響を与えないこと（移行が完了するまでの間、必要に応じて切り替え可能な状態を維持する）
