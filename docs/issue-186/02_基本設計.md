# 02_基本設計

## 変更対象

- ローカル開発環境の構成定義（コンテナ構成）
- backendはファイル保存先を抽象化した仕組みを持ち、現状は「ローカルディスクに保存する」実装のみを備えている。これに加えて「LocalStackが提供する疑似S3に保存する」実装を新規に追加し、差し替えられるようにする
- backendにキュー送信・キュー受信（非同期ワーカー）の仕組みを追加する
- backendの設定（環境変数）にキュー・バケット関連の項目を追加する
- ユーザーインポートの登録処理を、同期処理から「アップロード＋キュー送信のみ即時応答し、キュー受信側で実処理を行う」非同期構成に変更する

## 画面 / API 変更概要

- ユーザーインポートAPI（登録・状態取得）のリクエスト・レスポンス仕様自体は変更しない
- 登録API呼び出し直後のジョブステータスが、現状の「同期処理完了後の結果」から「受付済み（処理待ち）」に変わる。状態取得APIで進捗を確認する既存の仕組みはそのまま活用する

## 影響範囲

- ローカル開発環境の起動手順（新しいコンテナが追加される）
- backendのユーザーインポート機能一式（登録処理・状態取得処理）
- 既存の同期処理版のテストコード（非同期構成への変更に伴い、テストの前提が変わる）

## 移植方針

- 移植元（Spring Boot）はAWSの正式なSDK・リスナーフレームワークを使い、実SQS/実S3を前提とした構成になっている。本チケットではこれをローカルで再現するため、実AWSへの接続と差し替え可能な形でエミュレーション環境（ローカル専用のオブジェクトストレージ・キューサービス）を用意する
- キュー受信（リスナー）に相当する仕組みは、移植元がフレームワーク組み込みのリスナーコンテナに任せているのに対し、FastAPI側では常駐して受信し続けるバックグラウンド処理として用意する
- 既存の同期処理版の実装（バリデーション・行ごとの登録ロジック）は、そのままキュー受信側の処理として再利用する方針とし、重複実装は避ける

---

## 確定事項

第1承認前に確認し、以下の方針で確定した。

1. **AWSクライアントSDK**: `aioboto3`（非同期）を採用する。backendの他のI/Oと同様、`async/await`で統一する
2. **キュー受信（リスナー）の実行形態**: 移植元（naw-server）はSpring Cloud AWSのリスナーコンテナにより、バックエンドアプリと同一プロセス内で常駐ポーリングする構成になっている（`SqsListenerConfig.java`、別ワーカーコンテナなし）。FastAPI側もこれに合わせ、アプリ起動時に立ち上げる同一プロセス内のバックグラウンドタスク（asyncioタスク）としてポーリングを実装する
3. **既存の同期処理版の扱い**: 非同期構成に完全に置き換え、同期処理版の実装は削除する
