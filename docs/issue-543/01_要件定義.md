# 01_要件定義

## 背景

コメントが、存在しないファイル（cloudfront.tf・backend.hcl の旧パス）や、移植元の Angular の仕組みを指している。踏み台の AMI が most_recent で、新しい AMI が出るたびに plan が再作成を出す。user-import モジュールのコメント記法が混在している。

## 機能要件

- コメントの誤りを直す: client/.env.production、modules/frontend/main.tf、bootstrap/main.tf、modules/network/main.tf、client/src/store/auth-store.ts
- 踏み台の aws_instance に、AMI の変更で作り直さない lifecycle（ignore_changes = [ami]）を足す
- user-import モジュールのコメント記法を、他のモジュールと同じ // に揃える

## 非機能要件

- 既存の動作・自動テストを壊さない

## スコープ外

- naw- 接頭辞のボリューム名・コンテナ名の変更（ローカルの DB データが別ボリュームになる）
- ECR のライフサイクル（SHA タグの古いイメージの削除）
- alembic のファイル名、docs/ の派生ファイル名、docker-compose/ ディレクトリ名の変更
