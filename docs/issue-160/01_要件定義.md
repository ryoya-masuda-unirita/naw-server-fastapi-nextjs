# 01_要件定義

## 背景

- Issue #158で、AWSマネジメントコンソール（一部CLI）を使い、dev環境（VPC/SG/ECR/S3/CloudFront/RDS/ElastiCache/踏み台EC2/ECS/ALB/ACM証明書）を手動構築し、動作確認・全削除まで行った
- 手動構築は、設定項目の見落とし（デフォルトVPCとの混同、パブリックIP自動割り当ての設定漏れ、リソースクラスの選び間違い等）が多数発生し、再現性・レビュー可能性に乏しいことがわかった
- `docs/issue-158/構築済みリソース一覧.md`に、実際に使った設定値・リソースIDをすべて記録済みであり、これをそのままTerraformコードの検証材料として使える
- `.claude/CLAUDE.md`のクラウドインフラ方針にも「IaC: Terraform（`infra/`ディレクトリ）」と記載されており、本チケットはその実現の第一歩にあたる
- ユーザーはTerraformが初めてのため、実務対応と学習を両立させる進め方を採る

## 機能要件

- リポジトリに`infra/`ディレクトリを新設し、Terraformコードを配置する
- 以下のリソースをTerraformリソースとして定義する
  - VPC・パブリックサブネット2つ・インターネットゲートウェイ・ルートテーブル
  - セキュリティグループ5つ（`sg-bastion`/`sg-alb`/`sg-ecs`/`sg-rds`/`sg-elasticache`）
  - ECR（backendイメージ用リポジトリ）
  - S3（frontend-angular配信用）+ CloudFront（OACによるS3限定アクセス、`/api/*`・`/auth/*`のALBビヘイビア）
  - RDS（`db.t4g.micro`、Single-AZ、パブリックアクセス無効）
  - ElastiCache for Redis（`cache.t4g.micro`、レプリカ0）
  - 踏み台EC2（`t4g.nano`）
  - ECS（クラスタ・Auto Scaling Group・タスク定義・サービス、EC2起動タイプ）
  - ALB・ターゲットグループ
  - ACM証明書（`*.secuaigent-ryoyamasuda.tech`、us-east-1、DNS検証）
  - ECS用IAMロール（タスク実行ロール・コンテナインスタンス用ロール）
- `terraform apply`で実際にAWS上にリソースを構築し、Issue #158と同等の動作確認（backend起動・ALB疎通・CloudFront経由のログイン等）を行う
- 動作確認後、`terraform destroy`で全リソースを削除し、以下を確認する
  - コマンド一発で全リソースが削除されること
  - 削除後に`aws resourcegroupstaggingapi get-resources`でタグ付きリソースが0件になること
- 各リソースブロックの実装時、Terraformの基本概念（provider/resource/variable/output/state/plan/apply/destroy、`depends_on`、`for_each`等）をユーザー向けに解説する

## 非機能要件

- tfstateの管理方法（ローカルファイル運用とするか、S3バックエンドにするか）は設計時に検討し、第1承認までに確定する
- RDSマスターパスワード等の秘匿情報は、`.tfvars`をリポジトリにコミットしない運用にする（`.gitignore`に追加）
- Issue #158と同様、最安スペック（`t4g.nano`/`db.t4g.micro`/`cache.t4g.micro`、Price Class 100等）をそのままTerraformコードにも反映する
- コード変更はIssue #158の構成をそのまま再現することに限定し、Multi-AZ化等のベストプラクティス構成への拡張は行わない

## スコープ外

- ムームードメインのDNS設定（ワイルドカードCNAME等）: 公式Terraformプロバイダがないため対象外。引き続き手動
- Dockerイメージのビルド・ECRへのpush: Terraformの範囲外
- Alembicマイグレーション・`backend/seed.sql`投入: アプリケーション側の初期化でありTerraformの範囲外
- 作業用IAMユーザー（`naw-fastapi-issue158-operator`相当）: 既存のものをそのまま利用し、Terraform管理下には含めない
- GitHub Actions等によるCI/CD自動化（`terraform plan`/`apply`のパイプライン化）
- 本番環境の構築、Multi-AZ・プライベートサブネット等のベストプラクティス構成への発展
