# 02_基本設計

## 変更対象

- テナントのエンドポイントの種別（DB の列挙型を含む）と、AI モデルの種別
- Bedrock（Titan）の埋め込みを呼ぶクライアント
- 質問の埋め込みを呼ぶ 2 か所（クラウドの RAG のメッセージ送信と、埋め込み API）

## 画面 / API 変更概要

- 画面の変更はない（登録済みの接続先の表示は、既存の画面のまま）
- API の入出力は変えない。埋め込み API（`LlmEmbeddingService`）は、リクエストの `deployName` が、Azure のデプロイ名か、Bedrock のモデル ID かで、使う接続先を決める

## 影響範囲

- Azure OpenAI の埋め込みを使っている既存のテナント: 変わらない
- Bedrock の埋め込みの接続先を登録したテナント: クラウドの RAG の質問の埋め込みが、Bedrock で動く（ベクトルの保存・検索は #461・#462 のあと）
- DB のマイグレーションが 1 つ増える（列挙型に値を足す。`BEDROCK_CHAT` を足したときと同じ形）

## 移植方針

- 移植元にない、Python 版だけの拡張。移植元の設計（接続先の種別ごとに、埋め込みのクライアントを使い分ける）に沿って、種別を 1 つ足す
- Bedrock のチャット（`BEDROCK_CHAT`、#399 の前後で追加）を足したときの形に合わせる（列挙型・マイグレーション・サービスでの使い分け）
- 埋め込みの認証・呼び出しは、オンプレ側（#439）の Bedrock の埋め込みと同じ（Bedrock Runtime の InvokeModel、`Authorization: Bearer`、`x-api-key` は送らない）
- モデルは Titan G1（`amazon.titan-embed-text-v1`、1536 次元）に固定する。Azure の埋め込みも、モデル名が定数（`text-embedding-ada-002`）で決まっており、同じ考え方
- 次元数の確認は、返ってきたベクトルで行い、1536 でなければ失敗にする（Titan V2 を指定して、後段でずれることを防ぐ）
