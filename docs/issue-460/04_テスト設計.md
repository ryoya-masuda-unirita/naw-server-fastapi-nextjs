# 04_テスト設計

## テスト方針

外部通信は、`httpx` のモックの通信（`MockTransport`）で行い、本物の Bedrock には接続しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | リクエストの形 | `create_embedding` を呼ぶ | `POST {endpoint}/model/amazon.titan-embed-text-v1/invoke`、本文 `{"inputText": ...}`、`Authorization: Bearer`、`x-api-key` なし |
| 2 | 正常な応答 | 1536 次元の `embedding` と `inputTextTokenCount` | `EmbeddingResult` が返り、ベクトルとトークン数が一致する |
| 3 | モデル ID の URL エンコード | 記号を含むモデル ID | パスに安全にエンコードされる |
| 4 | 次元数の不一致 | 1024 次元の応答 | 分かる失敗（`BedrockEmbeddingError`） |
| 5 | HTTP エラー | 401・403・429・500 | 分かる失敗。メッセージに API キーが含まれない |
| 6 | 形式の不一致 | `embedding` がない・型が違う応答 | 分かる失敗 |
| 7 | 通信エラー | 接続失敗 | 分かる失敗 |
| 8 | RAG の使い分け | 学習先フォルダの接続先が Bedrock / Azure | Bedrock なら Bedrock のクライアント、Azure なら Azure のクライアントが呼ばれる |
| 9 | RAG の失敗 | Bedrock のクライアントが失敗 | 400（`Failed to create embedding for RAG search`） |
| 10 | 埋め込み API の使い分け | `deployName` が Titan のモデル ID / それ以外 | Titan なら Bedrock、それ以外は従来どおり Azure |
| 11 | トークンの記録 | Bedrock の埋め込みを使う | `TokenUsage.endpoint_type` が `BEDROCK_EMBEDDING`、トークン数が記録される |
| 12 | マイグレーション | 適用する | 列挙型 `endpointtype`・`aimodelendpointtype` に `BEDROCK_EMBEDDING` が入る |
| 13 | 回帰 | 既存のテストをすべて実行する | Azure の埋め込み・RAG の既存のテストの結果が変わらない |
