## 変更の中身

### Bedrock のクライアント

```python
BEDROCK_EMBEDDING_MODEL_ID = "amazon.titan-embed-text-v1"
EMBEDDING_DIMENSIONS = 1536

class BedrockLlmEmbeddingClient:
    @staticmethod
    async def create_embedding(endpoint, api_key, model_id, input_text) -> EmbeddingResult:
        url = f"{endpoint.rstrip('/')}/model/{quote(model_id, safe='')}/invoke"
        headers = {"Authorization": f"Bearer {api_key}", "content-type": "application/json"}
        # x-api-key は送らない（Bedrock は 2 種類の認証ヘッダーを同時に受け付けない。#444）
        body = {"inputText": input_text}
        ... httpx.AsyncClient で POST、HTTP エラーは BedrockEmbeddingError
        embedding = response["embedding"]; tokens = response["inputTextTokenCount"]
        if len(embedding) != EMBEDDING_DIMENSIONS: raise BedrockEmbeddingError(...)
```

- 接続先の URL は、Bedrock Runtime（例: `https://bedrock-runtime.ap-northeast-1.amazonaws.com`）。回答の生成（Mantle）とはホストが別
- タイムアウトは定数で持つ。失敗の文に API キーを含めない

### 使い分け

- `message_service`: `index_endpoints_map` から、種別が `AZURE_OPENAI_EMBEDDING` か `BEDROCK_EMBEDDING` のうち、id が最小のものを選ぶ。Bedrock なら `BEDROCK_EMBEDDING_MODEL_ID`、Azure なら従来の `EMBEDDING_MODEL_NAME` で呼ぶ。失敗は、従来どおり 400（`Failed to create embedding for RAG search`）に変える
- トークンの重み: `AIModelRepository.find_by_endpoint_type_and_name(種別, モデル名)` の結果が無ければ 1.0（既存の挙動）
- `llm_embedding_service`: `req.deployName == BEDROCK_EMBEDDING_MODEL_ID` のときだけ Bedrock の経路。`ai_models` に該当がなくても、重み 1.0 で動く（Azure の経路の「無ければ 400」は変えない）。`TokenUsage.endpoint_type` は `BEDROCK_EMBEDDING`
