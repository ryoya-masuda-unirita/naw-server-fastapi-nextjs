# 01_要件定義

## 背景

クラウドの RAG は、質問を埋め込み（ベクトル）にして、ベクトル DB から近い文書を探し、その結果をもとに LLM が答える。埋め込みを作る接続先は、テナントのエンドポイントとして登録し、学習先フォルダに結びつける。今は、埋め込みの接続先の種別が Azure OpenAI だけなので、Bedrock しか使えない環境では、RAG の最初の段階で失敗する。

## 機能要件

| No | 要件 |
|---|---|
| F1 | テナントのエンドポイントの種別に、Bedrock の埋め込み（`BEDROCK_EMBEDDING`）を足し、登録・保存できる |
| F2 | Bedrock（Titan）で、入力テキストを埋め込み（ベクトル）にできる。認証は Bearer の API キーだけを送る |
| F3 | 返ってきたベクトルの次元数が 1536 でないときは、分かる失敗にする（保存・検索の前に気づけるように） |
| F4 | クラウドの RAG（メッセージ送信）で、学習先フォルダの埋め込みの接続先が Bedrock なら Bedrock、Azure なら Azure で、質問を埋め込む |
| F5 | 埋め込み API（`LlmEmbeddingService`）でも、接続先の種別に応じて、Azure か Bedrock を使う |
| F6 | 埋め込みで消費したトークン数を、既存と同じくクレジットに数える |
| F7 | 失敗（認証・モデル不明・通信・形式の不一致）は、既存の埋め込みと同じ扱いで、分かる失敗にする。API キーなどが出力に出ない |

## 非機能要件

- Azure の埋め込みの挙動と、既存のテストの結果が変わらない
- Bedrock の部品は、専用のファイルと、目印（`bedrock-ext`）つきの少数の行に収め、取り外せる形にする（#436・#439 と同じ）
- 外部通信を行うテストは、モックで行い、本物の Bedrock には接続しない
- 追加・変更する関数・メソッド・クラスに、日本語の NumPy 形式の docstring を書く
- テストのメソッド名は英語、意図は日本語の docstring

## スコープ外

- ベクトルの保存・検索（#461）と、学習データ登録のベクトル化（#462）
- 画面（`client/`）で、クラウドのフォルダの接続先として Bedrock の埋め込みを選べるようにする変更（別の Issue。今回は、DB への登録で確かめる）
- Titan V2 など、1536 次元以外のモデルの対応
- 本物の Bedrock への接続確認の自動化（手順を残し、ユーザーが確認する）
