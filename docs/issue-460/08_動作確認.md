# 08_動作確認

## 確認環境

- macOS、`feature/issue-460`
- テストは `server/` の `uv run pytest`（外部通信は `httpx` のモックの通信）
- 実機: ローカルの docker compose（クラウド側の PostgreSQL・backend）と、本物の Bedrock（Titan、`ap-northeast-1`）

## 確認手順

1. テストを足し、使い分けのテストが、修正前のコードで失敗することを確かめる
2. 実装し、テスト・ruff・mypy を実行する
3. 実際の PostgreSQL で、マイグレーションの upgrade → downgrade → upgrade を実行する
4. 本物の Bedrock で、新しいクライアントを呼ぶ

## 確認結果

### テスト

- `message_service.py`・`llm_embedding_service.py` を `develop` の状態に戻すと、使い分けのテスト 8 件が、すべて失敗した（`8 failed`）。戻すと 8 passed
- 実装後: `server/` 全体で **1509 passed**。`ruff format`・`ruff check`・`mypy`（240 ファイル）が問題なし
- 追加したテスト: クライアント 12 件（リクエストの形・Bearer・`x-api-key` なし・URL エンコード・次元数・HTTP エラー・形式の不一致・通信エラー）、使い分け 8 件（RAG の Azure・Bedrock・id が最小・失敗、埋め込み API の Titan・それ以外・接続先なし・失敗）、マイグレーション 4 件

### マイグレーション（実際の PostgreSQL）

- `issue442` → `issue460` の upgrade が成功し、列挙型 `endpointtype`・`aimodelendpointtype` の両方に `BEDROCK_EMBEDDING` が入った
- downgrade -1 が成功し、値が消えた（既存の `BEDROCK_CHAT` の接続先は 1 件残った）
- 再度 upgrade して、`issue460 (head)` になった

### 本物の Bedrock（Titan）

- `BedrockLlmEmbeddingClient.create_embedding` で「こんにちは」を埋め込んだ → **次元数 1536、トークン数 1**
- 不正な API キーで呼ぶと、`Bedrock の埋め込みが HTTP 403 を返しました` の分かる失敗になり、メッセージにキーは含まれない
- キーは、オンプレのコンテナの環境変数から、クラウドの backend のコンテナへ、標準入力で渡した（画面・ログには出していない）

## 未確認事項

- 画面から、クラウドのフォルダの接続先として Bedrock の埋め込みを選ぶ操作（`client/` の変更は別の Issue。今回は DB への登録で確認する）
- クラウドの RAG（質問 → 検索 → 回答）の通し。ベクトルの保存・検索が必要なため、#461・#462 のあとに確認する
- `ai_models` に Titan のモデルが登録されていないテナントでは、トークンの重みが 1.0 になる（クレジットの計算の既定）
