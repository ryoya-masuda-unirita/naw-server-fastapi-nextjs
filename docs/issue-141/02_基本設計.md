## 影響範囲

- `MessageService`のストリーミング応答生成（`event_stream`内の`finally`節）: 挙動は変えず、mypy上の型エラーのみ解消する
- backend の型チェック運用（`uv run mypy app tests`の出力）

## 移植方針

本Issueは移植作業ではなく、backend自体の型エラー修正。移植元（Spring Boot）との対応関係はないため、Spring Boot側の実装は参照しない。

### 修正方針

1. **`index_service.py:594`**: `additional_learning`のelse節（`feedback_id is None`の場合）に到達する時点で、直前の
   ```python
   learning_source_not_specified = feedback_id is None and room_id is None
   confused_learning_source = feedback_id is not None and room_id is not None
   if learning_source_not_specified or confused_learning_source:
       raise HTTPException(...)
   ```
   により「`feedback_id`と`room_id`のどちらか一方のみが指定されている」ことが確定している。したがって`else`節（`feedback_id is None`）では`room_id`は必ず`str`である。この不変条件を`assert room_id is not None`で明示する。プロジェクト内に同様のパターン（`tenant_service.py:102`の`assert request.tenantName is not None`）が既にあり、それに倣う。

2. **`message_service.py:1028`**: `content_response`は`finally`節内の`try`で`_persist_message_content`（戻り値`MessageContentResponse`、非Optional）の結果を代入した後、`except ValueError`で`None`を代入している。型注釈がないと最初の代入式からmypyが`MessageContentResponse`確定型と推論するため、`try`の直前に`content_response: MessageContentResponse | None`という型注釈のみの文を追加し、以降の代入（`_persist_message_content`の結果 or `None`）の両方を許容する型として明示する。

### 事前準備: mypy設定の先行反映

`develop`には#139/#140が未マージのため、作業ブランチのローカル状態では`[tool.mypy]`が未整備（`plugins = ["pydantic.mypy"]`のみ）だった。PR #144の差分を確認し、同一内容を本ブランチにも反映した。

- `files = ["app", "tests"]`・`python_version = "3.12"`・`warn_unused_ignores = true`・`warn_redundant_casts = true`を追加
- `app.repositories.*`・`app.services.user_service`・`app.services.user_import_service`・`app.core.credit_quota`を対象に、理由コメント付きの`[[tool.mypy.overrides]]`（`ignore_errors = true`）を追加
- `tests/unit/test_azure_cost_client.py`の不要な`# type: ignore[arg-type]`を削除

この結果、反映直後の時点で`uv run mypy app tests`は#140完了時と同じ「2件のみ」の状態を再現できることを確認した上で、本Issue固有の修正（この2件）に着手した。
