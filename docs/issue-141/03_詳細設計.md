## 修正1: `app/services/index_service.py`（`IndexService.additional_learning`）

### 変更前

```python
else:
    room = await RoomRepository.find_by_id_and_tenant_id(
        room_id, tenant_id, session
    )
```

### 変更後

```python
else:
    # 直前の`learning_source_not_specified`/`confused_learning_source`チェックにより、
    # このelse節に到達する時点でfeedback_idがNoneかつroom_idはNoneではないと確定している。
    assert room_id is not None
    room = await RoomRepository.find_by_id_and_tenant_id(
        room_id, tenant_id, session
    )
```

### 修正の妥当性

- `additional_learning`冒頭の`learning_source_not_specified`（両方None）・`confused_learning_source`（両方指定）チェックにより、この関数に到達する時点で`feedback_id`・`room_id`のどちらか一方のみが`None`でないことが保証されている
- `else`節は`if feedback_id is not None:`の否定、すなわち`feedback_id is None`の場合であり、上記の不変条件から`room_id`は必ず`str`（Noneではない）
- `assert`はプロジェクト内の既存パターン（`tenant_service.py:102`の`assert request.tenantName is not None`）と同じ用途（バリデーション済みの不変条件をmypyに伝える）であり、新規の設計判断ではない
- 実行時の挙動は変わらない（`assert`が失敗するケースは元々発生し得ない）

## 修正2: `app/services/message_service.py`（`MessageService.send_message`内`event_stream`）

### 変更前

```python
finally:
    try:
        content_response = await MessageService._persist_message_content(
            ...
        )
    except ValueError:
        ...
        content_response = None
```

### 変更後

```python
finally:
    # ValueError発生時にNoneを代入するため、事前に`| None`を明示しておく
    # （型注釈がないと最初の代入式からMessageContentResponse確定型と
    # 推論され、後続のNone代入が型エラーになる）。
    content_response: MessageContentResponse | None
    try:
        content_response = await MessageService._persist_message_content(
            ...
        )
    except ValueError:
        ...
        content_response = None
```

### 修正の妥当性

- `_persist_message_content`の戻り値型は`MessageContentResponse`（非Optional）であり、型注釈がない状態では`content_response`の型がこの代入式から`MessageContentResponse`と推論される
- `except ValueError`節の`content_response = None`は、再生成対象がストリーミング中に削除される等の稀な競合時に、後続の`complete`イベント送出をスキップするための意図的な設計（既存コメント参照）であり、挙動を変える必要はない
- 変数宣言のみの型注釈文（`content_response: MessageContentResponse | None`）を`try`の直前に追加することで、以降の代入（正常系・`ValueError`系の両方）を型エラーなく受け付けられるようにする。実行時には何も生成しない（アノテーションのみの文）ため挙動は変わらない
