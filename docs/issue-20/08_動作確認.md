# 動作確認

## 前提条件

- `docker compose up -d`（postgres起動済み、追加操作なし）
- `cd backend && .venv/bin/python -m uvicorn app.main:app --reload --port 8001` でバックエンドを起動
- `cd frontend-angular && npm start`（`ng serve --configuration local`）で開発サーバーを起動（`http://localhost:4201`）
- 確認はヘッドレスブラウザ（Playwright）を用いてClaude Codeが実施
- ログイン確認用アカウント: `test-tenant` テナントの `admin` / `admin@1234`（`backend/seed.sql` 記載のシードユーザー。`backend/seed.sql` をローカルDBに再投入して用意した）
- URL: `http://test-tenant.localhost:4201/`（`resolveTenantId()` がサブドメインからテナントIDを解決する仕様のため）

## ブラウザでの実機確認

### API直叩きでのCookie発行確認

```
$ curl -s -i -X POST http://localhost:8001/auth/login -H "Content-Type: application/json" -H "X-Tenant-ID: test-tenant" -d '{"username":"admin","password":"admin@1234"}'

HTTP/1.1 200 OK
set-cookie: access_token=eyJ...; HttpOnly; Max-Age=18000; Path=/; SameSite=lax
{"id":"admin","name":"管理者","role":"ADMIN","token":"eyJ...","groups":[],"loginStatus":"SUCCESS","reason":null}
```

`POST /auth/login` のレスポンスに `access_token` のHttpOnly Cookieが発行されることを確認した。

### Playwrightによる一連のログイン確認

| Step | 操作 | 結果 |
|---|---|---|
| 1 | `http://test-tenant.localhost:4201/` にアクセス | ログイン画面が表示された（未認証のため `GET /api/auth` は401。既知の想定挙動） |
| 2 | ユーザーID `admin` / パスワード `admin@1234` を入力しログイン | `POST /auth/login` が200、`/dashboard` へ遷移した |
| 3 | ログイン直後のCookie確認 | `access_token`（HttpOnly, SameSite=Lax, Secure=false）がブラウザに保存されていた |
| 4 | ページをリロード | `/dashboard` に留まったまま（ログイン画面に戻らなかった） |

リロード後に観測されたAPI呼び出し（抜粋）:

```
200 GET http://test-tenant.localhost:4201/api/auth
200 GET http://test-tenant.localhost:4201/api/users/profile
404 GET http://test-tenant.localhost:4201/api/rooms?page=0&size=20     ← 未実装エンドポイント（今回のスコープ外）
404 GET http://test-tenant.localhost:4201/api/assistants               ← 同上
404 GET http://test-tenant.localhost:4201/api/prompt-templates?size=0  ← 同上
```

`GET /api/auth`・`GET /api/users/profile` がいずれも200になり、issue-20で報告されていた「ログイン直後・リロード時に401になりログイン画面へ戻る」現象が解消されたことを確認した。`/api/rooms` 等の404は該当APIが未実装であることによるもので、認証とは無関係（別スコープ）。

- Cookie（`access_token`）によるブラウザ認証が成立し、リロード時も認証状態が維持されることを確認した
- 既存のBearerトークン認証（テストコード・API直叩き）との後方互換性が保たれていることを確認した
