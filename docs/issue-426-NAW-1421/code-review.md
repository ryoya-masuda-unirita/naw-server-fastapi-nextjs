## 詳細

### 1. 「全てのユーザー」を選んだあとの入力欄（🔴 致命的）→ 対応済み

指摘の再現手順は、一部正確でなかった。別のユーザーを選んでから「全てのユーザー」に戻すと、親の値が変わる（ユーザー ID から `null`）ため、セレクトの内部の値が合う。一方、**最初から未選択のまま**「全てのユーザー」を選ぶと、親の値が `null` のままで変わらず、内部の値が `''` で残り、入力欄にラベルが残った。画面のテスト（未選択のまま全てのユーザーを選んでも、検索できること）で再現した（修正前は失敗）。

修正: 「全てのユーザー」を選んだとき（値が空のとき）、セレクトを `key` で作り直し、内部の値を親の値（未選択）に合わせる。

### 2. タイミング依存のテスト（🟡 注意）→ 対応済み

固定時間のあとに「出ないこと」を確かめると、取得が終わる前でも通る。リクエストの記録を待ってから確かめる形にした。種類が無い応答のテストは、一覧の取得が呼ばれたことを待つ。途中のページの失敗のテストは、1 ページ目と 2 ページ目の両方が呼ばれたことを待つ。そのうえで、短い待ちを入れて応答が処理されるのを待つ。

### 3. 案内文の文言キー（🔵 提案）→ 対応済み

`TENANT.FILTER_USER_SUPPORT` を足した（文言はチャット履歴と同じ）。チャット履歴の文言を変えても、テナントの利用状況タブに影響しない。

### 4. 無関係な整形（🔵 提案）→ 対応済み

`prettier` を通したため、変更していない箇所の改行が変わっていた。`develop` のファイルに、必要な変更だけを当て直した。

### 5. 確認のみ（指摘なし）

- 全ページ取得は、空のページか総数への到達で、有限回で止まる。`size=1000` は backend の上限に収まる。`includeUsage:false` は、ここで合計クレジットを使っていないため問題ない
- `sort=name,asc`・`includeUsage=false` は、並び替えの最終キーに ID を加える分岐を通り、同名のユーザーがページをまたいでも重複・欠落しない。移植元の `tieBreakById` を移植しない判断は妥当
