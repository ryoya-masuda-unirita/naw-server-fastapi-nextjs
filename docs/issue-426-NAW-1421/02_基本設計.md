# 02_基本設計

## 変更対象

- テナント管理の利用状況タブ（利用履歴の利用者名の欄と、利用者の絞り込み）
- 利用履歴の応答の型と変換
- 利用者の絞り込みの選択肢を取る処理
- 表示文言（日本語・英語）
- 画面テスト用のモック

## 画面 / API 変更概要

- 画面: 利用者名の欄を、種類で出し分ける。絞り込みのセレクトを、検索できるセレクトに置き換える
- API: 変更しない。利用履歴の応答の `userName`・`userType` を読む。ユーザー一覧は、1 ページ 1000 件で、最後のページまで順に取る

## 影響範囲

- 利用状況タブの利用者名: 削除済みのユーザーと SYSTEM ユーザーの表示が変わる
- 利用履歴の取得: `userType` が無い応答は失敗になる（backend は常に返す）
- 利用者の絞り込み: ユーザーが 500 人を超えるテナントでも、全員を選べる。ユーザー数に比例して取得に時間がかかる（移植元と同じ）

## 移植方針

- 移植元の最終形に合わせる（API の種類での出し分け、種類が不明なら失敗、全ページ取得、検索つきセレクト）
- 移植元の `tieBreakById` は移植しない（backend が最終キーに ID を加えるため）
