# 01_要件定義

## 背景

利用履歴の利用者名は、画面が取ったユーザー一覧から引いているため、削除済みのユーザーは ID がそのまま出る。絞り込みのユーザーは 500 件までで、ユーザーが多いテナントでは選べない人がいる。API は、利用者名と種類（`userName`・`userType`）を返すようになった（#373）。

## 機能要件

- 利用履歴の利用者名を、API の利用者の種類で出し分ける
  - 通常のユーザー: その名前
  - SYSTEM ユーザー: 「SYSTEMユーザー」（英語は「SYSTEM user」）
  - 削除されたユーザー（利用者の ID が無い行を含む）: 「削除されたユーザー」（英語は「Deleted user」）
  - どの場合も、ユーザーの ID や `-` を出さない
- 利用者の種類が無い・不明な応答は、ID や `-` を出さず、一覧の取得の失敗として扱う。通常のユーザーで名前が無い応答も同じ
- 利用者の絞り込みの選択肢は、テナントの全ユーザーを全ページ取得し、名前順で並べる。先頭は「全てのユーザー」
- 絞り込みのセレクトは、入力で検索できるものにする
- 途中のページの取得に失敗したときは、一部のユーザーだけの選択肢を出さず、失敗として扱う

## 非機能要件

- 使われなくなったコード（500 件の上限の定数・ID から名前を引く対応表）を削除する

## スコープ外

- 利用履歴の API の変更（#373 で対応済み）
- 同名のユーザーの区別（移植元も、そのまま並べる）
- 絞り込みで選んだユーザーの利用履歴の取得（`userId` の送信は既存のまま）
