# 04_テスト設計

## テスト方針

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 利用者名（通常） | `userType=ACTIVE` | `userName` が出る |
| 2 | 利用者名（SYSTEM） | `userType=SYSTEM` | 「SYSTEMユーザー」の文言が出る（名前は使わない） |
| 3 | 利用者名（削除） | `userType=DELETED`、`userId` が無い行を含む | 「削除されたユーザー」の文言が出る。ID や `-` は出ない |
| 4 | 種類が無い | `userType` が無い応答 | ID や `-` を出さず、取得の失敗になる |
| 5 | 種類が不明 | `userType` が 3 値以外 | 同上 |
| 6 | 名前が無い | `ACTIVE` で `userName` が空 | 同上 |
| 7 | 全ページ取得 | ユーザーが 2 ページ以上 | 全ページ分が選択肢に並ぶ。並びは名前順 |
| 8 | 取得の停止 | 総数に達した、または空のページ | それ以上取らない |
| 9 | 途中で失敗 | 2 ページ目が失敗 | 一部だけの選択肢を出さず、失敗になる |
| 10 | 絞り込み | 検索つきセレクトで、ユーザーを入力して選ぶ | そのユーザーの `userId` で利用履歴を取り直す。「全てのユーザー」で戻る |
| 12 | 全てのユーザーを選ぶ | 未選択のまま「全てのユーザー」を選ぶ | 入力欄にラベルが残らず、続けて検索できる |
| 11 | 画面での確認 | デモのテナント管理の利用状況タブ | 利用者名が種類で出し分けられ、絞り込みが検索できる |
