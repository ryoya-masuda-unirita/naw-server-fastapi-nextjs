# 認証方式をRedisセッションストア方式に置き換える

## 概要

現状 FastAPI 側は、JWT をステートレスな署名トークンとして HttpOnly Cookie にそのまま格納し、
都度 `jwt.decode` で検証する方式になっている。
移植元 Spring Boot 側では NAW-944「JWTトークンをHttpOnly Cookieで発行する」対応
（コミット `6c5684b4`）で、Spring Session + Redis によるサーバー側セッションストア方式に
変更されている。この方式を FastAPI 側にも移植し、認証情報をサーバー側（Redis）で管理する
構成に揃える。

## 説明

- 現行のJWTステートレス方式では、ログアウトやパスワード変更時にサーバー側でセッションを
  強制的に無効化する手段がない（Cookieを削除してもトークン自体は有効期限まで有効なまま）
- Spring Boot側は Redis にセッション（認証コンテキスト）を保存し、Cookieにはセッションキー
  （Cookie名: `SESSION`）のみを格納する方式に変更済み
- root `docker-compose.yml` に `redis` サービスを追加し、ローカル開発で動作確認できる
  ようにする（backend / frontend-angular 自体のコンテナ化は別Issue #未発行 で対応予定のため
  対象外）
