## 詳細

### `backend/app/core/session_store.py`（新規）

- `SESSION_COOKIE_NAME = "session_id"`
- `SESSION_TTL_SECONDS = 7200`（移植元 `spring.session.timeout: 7200s` と同じ）
- `async def create_session(login_id: str, tenant_id: str, redis: Redis) -> str`
  - `secrets.token_urlsafe(32)` でセッションIDを生成
  - Redisキー `session:{session_id}` に `{"login_id": ..., "tenant_id": ...}` をJSONで保存し、`SESSION_TTL_SECONDS` のTTLを設定
  - 生成したセッションIDを返す
- `async def get_session(session_id: str, redis: Redis) -> dict | None`
  - Redisキー `session:{session_id}` を取得しJSONデコードして返す。存在しなければ `None`
- `async def delete_session(session_id: str, redis: Redis) -> None`
  - Redisキー `session:{session_id}` を削除する
- `async def touch_session(session_id: str, redis: Redis) -> None`
  - 既存セッションのTTLを `SESSION_TTL_SECONDS` にリセットする（`/api/auth` でのスライディング延長に使用）

### `backend/app/core/redis_client.py`（新規）

- モジュールレベルで `redis.asyncio.Redis.from_url(get_redis_settings().redis_url, decode_responses=True)` を保持
- `async def get_redis_client() -> Redis` という FastAPI `Depends` 関数として提供する（`app.core.database.get_session` と同じ構成に合わせる）

### `backend/app/core/security.py`

- 削除: `ACCESS_TOKEN_COOKIE_NAME`、`set_access_token_cookie`、`clear_access_token_cookie`（Cookieに直接JWTを入れる現行方式）
- 追加: `set_session_cookie(response, session_id)` / `clear_session_cookie(response)`
  - Cookie名は `session_store.SESSION_COOKIE_NAME`（`session_id`）
  - 属性は現行の `set_access_token_cookie` を踏襲しつつ `samesite` を環境変数化する
    （`httponly=True`, `secure=settings.cookie_secure`, `samesite=settings.cookie_same_site`）。
    `max_age` は `SESSION_TTL_SECONDS`
- `get_current_user` の変更:
  1. Cookie `session_id` があれば `session_store.get_session()` でRedisを検索する
     - セッションが見つかれば、そこに保存された `login_id`・`tenant_id` から `UserRepository.find_by_login_id()` でユーザーを取得して返す
  2. Cookie が無い、またはセッションが見つからない場合のみ、現行同様 `Authorization: Bearer` ヘッダーのJWTをdecodeして認証する（既存の `decode_token` ロジックをそのまま使う）
  3. どちらの経路でもユーザーが見つからなければ401を返す（現行と同じ）
- `create_access_token` / `decode_token` はbearerフォールバック用に現行のまま残す

### `backend/app/routers/auth.py`

- `login` / `login_with_login_key` / `reset_password`:
  - 認証成功時、`session_store.create_session(user.login_id, tenant_id, redis)` でセッションを作成し、`set_session_cookie(response, session_id)` を呼ぶ（現行の `set_access_token_cookie(response, auth_response.token)` を置き換え）
  - レスポンスボディの `token`（JWT文字列）は現行通り `AuthService` 側で生成されたものをそのまま返す
- `logout`:
  - Cookie `session_id` を読み取り、存在すれば `session_store.delete_session()` でRedisから削除してから `clear_session_cookie(response)` を呼ぶ
- `get_auth`（`GET /api/auth`）:
  - `get_current_user` の認証経路がセッションだった場合、`session_store.touch_session()` でTTLを延長する（bearer経由の場合はセッションが存在しないため延長不要）
  - レスポンスボディの `token` は現行通り新しいJWTを都度生成して返す（bearer専用クライアント向けの再発行動線を維持するため）

## 移植元との対応整理

| 移植元（Spring Boot） | FastAPI側 |
|---|---|
| `AuthController#establishHttpSession` | ログイン系エンドポイントでの `session_store.create_session` 呼び出し |
| `HttpSessionSecurityContextRepository` によるセッションからのSecurityContext復元 | `get_current_user` でのセッションCookie優先チェック |
| `JwtRequestFilter`（セッション未確立時のみBearerを検証） | `get_current_user` のbearerフォールバック |
| `SecurityConfig#logout`（`invalidateHttpSession` + Cookie削除） | `logout` エンドポイントでの `delete_session` + `clear_session_cookie` |
| `spring.session.timeout: 7200s` | `SESSION_TTL_SECONDS = 7200` |
| `spring.data.redis.host` / `port`（`REDIS_HOST`/`REDIS_PORT`） | `REDIS_URL`（1つにまとめる。既存の `DATABASE_URL` と同じ流儀） |
| `server.servlet.session.cookie.same-site`（ローカル相当 `strict` / dev・production相当 `none`） | `COOKIE_SAME_SITE` 環境変数（デフォルト `lax`。dev/staging環境では `none` を設定する） |
