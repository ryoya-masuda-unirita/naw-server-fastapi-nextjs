# 08_動作確認

## 確認環境

- `docker compose up -d postgres redis` でPostgreSQL・Redisをローカル起動
- `uv run alembic upgrade head` でマイグレーション適用
- `docker exec -i naw-fastapi-postgres psql -U root -d postgres < backend/seed.sql` でシードデータ投入
- `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000` でbackendをローカル起動
- 確認方法: ブラウザ（frontend-angular）ではなく、AIエージェントが`curl`でAPIを直接呼び出して確認した
  （ユーザーからブラウザでの確認結果は受け取っていない）

## 確認手順・結果

### Step 1: ログインでセッションCookieが発行されること

`POST /auth/login`（`admin`/`admin@1234`、`X-Tenant-ID: test-tenant`）を実行。

```
set-cookie: session_id=6MEUXDAePZa_R-F_1uaT6N3UmrxjShdzdyTfeN3AwM0; HttpOnly; Max-Age=7200; Path=/; SameSite=lax
```

✅ `session_id` Cookieが発行された（HttpOnly・Max-Age=7200・SameSite=lax）
✅ レスポンスボディにも`token`（JWT）が引き続き含まれている

### Step 2: Redisにセッションが保存されていること

`redis-cli KEYS "session:*"` で該当キーが存在し、`GET`で中身を確認。

```
session:6MEUXDAePZa_R-F_1uaT6N3UmrxjShdzdyTfeN3AwM0
{"login_id": "admin", "tenant_id": "test-tenant"}
TTL: 7190（≈7200秒）
```

✅ Redis上にログインID・テナントIDを含むセッションが保存されている
✅ TTLが約7200秒（2時間）に設定されている

### Step 3: セッションCookieのみで保護APIを呼び出せること

Cookieのみ（Authorizationヘッダーなし）で`GET /api/auth`を実行。

```
HTTP/1.1 200 OK
{"id":"admin","name":"管理者","role":"ADMIN","token":"...","loginStatus":"SUCCESS"}
```

✅ Cookieのみで認証が成立し200が返った

### Step 4: ログアウトでセッションが削除されること

`POST /auth/logout`を実行後、`redis-cli KEYS "session:*"`を確認。

```
set-cookie: session_id=""; expires=Tue, 14 Jul 2026 12:09:22 GMT; Max-Age=0; Path=/; SameSite=lax
KEYS "session:*" → (empty)
```

✅ Redis上の該当セッションキーが削除された
✅ `Set-Cookie`で`session_id`が`Max-Age=0`により即時失効している

### Step 5: bearerフォールバック経路が機能すること

再ログインしてボディの`token`を取得し、Cookie無し・`Authorization: Bearer <token>`のみで
`GET /api/auth`を実行。

```
HTTP/1.1 200 OK
{"id":"admin","name":"管理者","role":"ADMIN","token":"...","loginStatus":"SUCCESS"}
```

✅ セッションCookieが無くても、Authorizationヘッダーのbearer JWTで認証できた
（セッション優先・bearerフォールバックという設計通りの挙動）
