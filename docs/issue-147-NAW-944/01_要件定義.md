# 01_要件定義

## 背景

- 現状のFastAPI認証は、JWTをステートレスな署名トークンとしてそのままHttpOnly Cookie
  （およびレスポンスボディ）で発行し、都度検証するのみになっている。サーバー側でセッションを
  強制的に無効化する手段がない（ログアウトしてもトークン自体は有効期限まで有効なまま）
- 移植元Spring Boot側の認証は、ログイン時にJWTをレスポンスボディで返しつつ、同時にサーバー側
  セッション（Redisに保存）を確立し、セッションIDのみをCookieで払い出す二重構成になっている
  - ブラウザからのリクエストはセッションCookieによる認証を優先し、既にセッション認証が成立
    していればAuthorizationヘッダーのbearerトークンは検証しない
  - セッション認証が成立していない場合のみ、Authorizationヘッダーのbearer JWTをフォールバック
    として検証する
- 現状のfrontend-angularクライアントはCookie送信（`withCredentials: true`）のみで認証しており、
  Authorizationヘッダーは付与していない。bearer経路は、Cookieを使わない呼び出し（Swagger UI
  からの手動確認や将来的な非ブラウザクライアント等）向けの経路として維持する

## 機能要件

- ログイン成功時、認証情報をサーバー側（Redis）のセッションとして保存し、セッションIDのみを
  HttpOnly Cookieに格納する
- ブラウザからの以降のリクエストは、セッションCookieを優先して認証する。セッションが有効な間は
  Authorizationヘッダーを検証しない
- セッションCookieが無い、またはセッションが無効な場合のみ、Authorizationヘッダーのbearer JWT
  による認証にフォールバックする
- ログイン成功レスポンスには引き続きJWT文字列を含める（bearer認証を利用したいクライアント向け）
- ログアウト時、対応するセッションをサーバー側（Redis）から削除し、Cookieも削除する
- セッションの有効期限は移植元と同じ2時間（7200秒）とする
- ログインキー認証・パスワードリセット・認証トークン再取得など、既存の認証系エンドポイント
  すべてで同様にセッションを確立・更新する
- セッションCookieの `same-site` 属性を環境変数で切り替え可能にする
  - 移植元はローカル相当が `strict`、dev/staging相当が `none`（`https://{テナントID}.dev-app.
    secuaigent.com` のようにテナントごとにサブドメインが変わるクロスオリジン構成のため）
  - 現状のFastAPI実装は `same-site=lax` が固定値になっており、環境による切り替えができて
    いない。既存の `COOKIE_SECURE` 環境変数と同様に、環境ごとに設定できるようにする

## 非機能要件

- ローカル開発環境でRedisに接続して動作確認できること（docker-composeにRedisサービスを
  追加する）
- セッションの保存・破棄・検証に伴うレイテンシが、API全体のレスポンスタイムに大きな影響を
  与えないこと
- Redis接続先は環境変数で設定可能にすること（dev/staging環境ごとにRedisエンドポイントを
  差し替えられるようにする）

## スコープ外

- backend / frontend-angular自体のdocker-compose一括起動対応（別Issueで対応予定）
- パスワード変更時の全セッション一括無効化などの付随機能
- dev/staging環境のRedisインフラ構築（ElastiCache等のTerraform定義）は本Issueでは対象外とし、
  必要であれば別Issueで検討する
