# 08_動作確認

## 確認環境

- `infra/`ディレクトリで、AIエージェントが以下を実行して確認した
- `terraform plan`にはAWS認証情報が必要なため、既存のAWSプロファイル（`naw-fastapi-issue158`）で試みた

## 確認結果

### `terraform fmt -check -recursive -diff`

```
（出力なし＝差分なし）
```

✅ 変更した`.tf`ファイルがTerraform標準フォーマットに従っていることを確認

### `terraform validate`

```
Success! The configuration is valid.
```

✅ 構文エラー・未定義変数参照エラー（`var.domain_name`削除に伴うもの含む）がないことを確認

### `terraform plan`

実行できなかった。`terraform init`の時点で、tfstateを保存しているS3バケット（`naw-fastapi-issue160-tfstate`）自体が現在存在しないことが判明した。

```
Error: Failed to get existing workspaces: S3 bucket "naw-fastapi-issue160-tfstate" does not exist.
```

`aws ecs list-clusters`・`aws s3api head-bucket`でも確認したところ、ECSクラスタも存在せず、インフラは現在完全に破棄された状態（README記載の「動作確認のたびに作っては壊す」運用により、tfstate用バケットを含め何も存在しない状態）だった。このため、既存環境との差分としての`terraform plan`は実行できなかった。

## 未確認事項

- 実際のAWS環境への反映（`terraform apply`）、CloudFrontデフォルトドメインでの実機アクセス確認、ムームードメイン側の設定変更・Route53ホストゾーンのdestroy判断は、方針どおりユーザーが実施する
