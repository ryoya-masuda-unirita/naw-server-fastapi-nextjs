# 03_詳細設計

## ACM証明書の削除（`infra/acm.tf`）

- ファイルごと削除する（`aws_acm_certificate.main`、DNS検証用の`aws_route53_record.cert_validation`、`aws_acm_certificate_validation.main`の3リソース）

## CloudFrontディストリビューション（`infra/cloudfront.tf`）

- `aws_cloudfront_distribution.main`の`aliases`属性を削除する（デフォルト証明書使用時は指定不可のため）
- `viewer_certificate`ブロックを、ACM証明書参照（`acm_certificate_arn`/`ssl_support_method`/`minimum_protocol_version`）から`cloudfront_default_certificate = true`に変更する
- ルート・ワイルドカードのRoute53 Aレコード（`aws_route53_record.root`、`aws_route53_record.wildcard`）を削除する

## Route53ホストゾーン参照の削除（`infra/main.tf`）

- `data "aws_route53_zone" "main"`を削除する（メイン側から独自ドメインを一切参照しなくなるため）
- ACM証明書がus-east-1リージョン必須だったために追加していた`provider "aws" { alias = "us_east_1" ... }`ブロックを削除する（ACM証明書の削除により不要になるため）

## 変数定義の削除（`infra/variables.tf` / `infra/terraform.tfvars` / `infra/terraform.tfvars.example`）

- `variable "domain_name"`を削除する（メイン側での参照箇所がなくなるため）
- `terraform.tfvars`・`terraform.tfvars.example`から`domain_name`の指定行を削除する
- `infra/route53/`配下の同名変数（別state・別モジュール）はスコープ外のため変更しない

## バックエンドのCORS設定（`infra/ecs.tf`）

- `CORS_ALLOWED_ORIGIN_REGEX`環境変数の値を空文字に変更する（既存の`CORS_ALLOWED_ORIGINS`の未使用時と同じパターンに揃える）
- `CORS_ALLOWED_ORIGINS`環境変数の値を、`aws_cloudfront_distribution.main.domain_name`を参照した固定オリジン1つ（`"https://${aws_cloudfront_distribution.main.domain_name}"`）に変更する
  - CloudFrontのデフォルトドメインはディストリビューション作成後に確定する値のため、Terraformのリソース参照を使う。これにより`aws_ecs_task_definition.backend`が`aws_cloudfront_distribution.main`に依存する形になるが、CloudFront側はECSに依存していないため循環参照は発生しない
  - **注意**: `aws_ecs_task_definition.backend`には`lifecycle { ignore_changes = [container_definitions] }`が設定されている。これはCI（`deploy-backend.yml`）がイメージタグ更新のたびに現在登録済みのタスク定義をそのまま複製し画像タグだけ差し替える運用のためで、既存環境に対して`terraform apply`しても`container_definitions`内の環境変数（CORS設定を含む）の差分は無視され反映されない。README記載の「動作確認のたびに作っては壊す」運用（`terraform destroy`→`terraform apply`）であれば新規作成時に反映されるが、壊さず`apply`のみで反映したい場合は、CIと同様に手動で`aws ecs register-task-definition`＋`update-service --force-new-deployment`を行う必要がある旨をREADMEに明記する

## 出力値（`infra/outputs.tf`）

- 既存の`output "cloudfront_domain_name"`はそのまま維持する（独自ドメイン廃止後の動作確認用URLとして引き続き使う）

## 運用ドキュメント（`infra/README.md`）

- 「なぜRoute53だけ別ディレクトリ（別state）にしているか」セクションに、メイン側は独自ドメインを一切参照しなくなった旨を追記する
- 「ムームードメイン側の設定」セクションに、`infra/route53/`はメインの構成からは参照されなくなった（Route53ホストゾーンを完全に不要とするならユーザー判断で別途destroyしてよい）旨を追記する
- 「デプロイ手順」の「4. 動作確認」を、独自ドメイン・テナントサブドメインへのアクセス手順から、`terraform output cloudfront_domain_name`で確認したCloudFrontデフォルトドメインへのアクセス手順に変更する
- 「destroy時の注意」の記載は、Route53ホストゾーンが別stateである点は変わらないため維持する
- 既存環境に対して破棄せず`terraform apply`のみでCORS設定を反映したい場合の手順（`ignore_changes`により自動反映されないため、CIと同様の手動タスク定義再登録が必要）を追記する
