# 02_基本設計

## 変更対象

- カスタムドメイン関連のTerraformリソース定義（ACM証明書・DNS検証レコード・CloudFrontのエイリアス/証明書設定・ルート/ワイルドカードのRoute53 Aレコード・Route53ホストゾーンの参照）
- バックエンドのCORS許可オリジン設定（環境変数）
- 動作確認・デプロイ手順に関する運用ドキュメント

## 画面 / API 変更概要

- エンドユーザー・動作確認者がアクセスするURLが、独自ドメインからCloudFrontのデフォルトドメインに変わる
- バックエンドAPIのCORS許可オリジンが、ワイルドカードサブドメインを許可する正規表現から、CloudFrontのデフォルトドメイン1つの固定値に変わる

## 影響範囲

- CloudFrontディストリビューションの証明書・エイリアス設定
- ACM証明書とそのDNS検証レコード一式（削除）
- Route53のAレコード（ルート・ワイルドカード、削除）とホストゾーンの参照（削除。ホストゾーン自体は別stateのため存続する）
- バックエンドの環境変数（CORS関連）
- 出力値（動作確認用URL）
- デプロイ手順・動作確認手順・ドメイン運用に関する運用ドキュメントの該当セクション

## 移植方針

- 独自ドメイン運用を前提とした既存の設計方針（Route53ホストゾーンを別stateに分離し、メイン側からは参照のみ行う）自体は変更しない。本Issueでは、メイン側からその参照自体を無くす（ホストゾーンの削除は行わない）
- CloudFrontの証明書は、ACM証明書ではなくCloudFrontのデフォルト証明書（`cloudfront_default_certificate = true`相当）に切り替える
- バックエンドのCORS許可オリジンは、Terraform実行時に確定しないCloudFrontのデフォルトドメイン（ディストリビューション作成後に決まる）を参照する必要があるため、Terraformのリソース間参照（CloudFrontディストリビューションの`domain_name`属性）を使って固定オリジンとして設定する
- Route53ホストゾーンの実削除・ムームードメイン側のネームサーバー設定変更は本Issueのスコープに含めず、Terraformコード上の参照を外すところまでとする
