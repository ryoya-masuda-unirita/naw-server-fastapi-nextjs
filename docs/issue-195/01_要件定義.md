# 01_要件定義

## 背景

- Issue #193でfrontend-angularのサブドメインによるテナント識別を廃止した。インフラ側では、テナントごとのサブドメイン（ワイルドカードドメイン）へのアクセスを前提としたACM証明書・CloudFrontエイリアス・Route53レコード・バックエンドCORS設定が存在しており、廃止した機能に紐づく設定が残ったままになっている。
- 本プロジェクトはdev/staging限定運用で本番環境がなく、独自ドメインを維持する強い理由がない。一方で独自ドメイン運用には、ネームサーバー登録・DNS伝播待ち・証明書の維持など相応の運用コストが発生している。
- CloudFrontはデフォルトドメイン・デフォルト証明書を使えば、独自ドメインの設定なしにHTTPS配信ができる。

## 機能要件

- CloudFrontのデフォルトドメインでHTTPS配信できること
- バックエンドのCORS許可設定が、ワイルドカードサブドメインを許可する正規表現ではなく、CloudFrontのデフォルトドメイン1つを許可する固定値になっていること
- 独自ドメイン（ACM証明書・CloudFrontのエイリアス設定・Route53のAレコード・DNS検証レコード）に関するTerraformリソース定義を削除すること
- デプロイ手順・動作確認手順の運用ドキュメントを、独自ドメインを前提としない内容に更新すること

## 非機能要件

- ドメインに依存しない他のインフラ構成（VPC/ECS/RDS/ALB/S3等）には影響を与えないこと
- 本Issueの対応はTerraformコードおよびドキュメントの変更に留め、実際のAWSリソースの削除・変更操作（`terraform apply`/`destroy`の実行、ムームードメイン側のネームサーバー設定変更等）はユーザーが行うこと

## スコープ外

- Route53ホストゾーン自体の削除（`infra/route53/`は別stateのため本Issueでは触れない。README記載の既存運用方針どおり、必要であればユーザーが別途`infra/route53/`で`terraform destroy`する）
- ムームードメインの契約解除・自動更新設定の変更（ユーザー判断）
- React移植版（`frontend/`）のインフラ対応
- 本番環境向け設定（存在しないため対象外）
