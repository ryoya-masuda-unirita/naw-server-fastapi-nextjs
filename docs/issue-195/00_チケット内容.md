# issue-195 サブドメイン廃止に伴いカスタムドメイン（Route53/ACM/CloudFrontエイリアス）を廃止する

## 概要

Issue #193でfrontend-angularのサブドメインによるテナント識別を廃止した。これに伴い、インフラ側でサブドメイン（ワイルドカードドメイン）を前提とした設定が不要になっている。

本Issueでは、サブドメイン関連設定の削除に留まらず、カスタムドメイン（`infra/route53/`のRoute53ホストゾーン、`infra/acm.tf`のACM証明書、`infra/cloudfront.tf`のエイリアス設定）自体を丸ごと廃止し、CloudFrontのデフォルトドメイン（`*.cloudfront.net`）で配信する構成に切り替える。

- 本プロジェクトはdev/staging限定運用で本番環境がなく、独自ドメインを維持する強い理由がないため
- CloudFrontはデフォルトドメイン・デフォルト証明書で追加設定なしにHTTPS配信できるため

## 説明

### 対象箇所

- `infra/route53/`（ムームードメインで取得した独自ドメインのRoute53ホストゾーン。メインの`infra/`とはstateを分離した別モジュール）
- `infra/acm.tf`: CloudFront用ACM証明書（ワイルドカードSAN含む）とDNS検証レコード一式
- `infra/cloudfront.tf`: `aliases`設定、`viewer_certificate`のACM証明書参照、ルート/ワイルドカードのRoute53 Aレコード
- `infra/ecs.tf`: バックエンドの`CORS_ALLOWED_ORIGIN_REGEX`（現状ワイルドカードサブドメインを許可する正規表現）。CloudFrontのデフォルトドメインを`CORS_ALLOWED_ORIGINS`に固定値で設定する形に変更する
- `infra/main.tf` / `infra/variables.tf`: `var.domain_name`の参照箇所全般
- `infra/outputs.tf`: 動作確認用URLの出力（CloudFrontデフォルトドメインの出力に変更）
- ドキュメント類（`infra/README.md`等）にドメイン運用手順の記載があれば更新
