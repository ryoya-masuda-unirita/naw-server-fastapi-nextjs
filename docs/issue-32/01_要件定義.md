# 01_要件定義

## 背景

バックエンドのテスト（`backend/tests/unit/`・`backend/tests/integration/`）は現状ローカルでの手動実行のみで、CIによる自動検証がない。プッシュのたびに素早いフィードバックを得られる単体テストと、マージ前後に厳密な検証を行う結合テストを、タイミングに応じて使い分けたい。

## 機能要件

### トリガーとテスト範囲

- **プッシュ時**（`develop`・`main`以外のブランチへのプッシュ）：`backend/tests/unit/`のみ実行する
- **`develop`ブランチへのプッシュ時**（PRマージによるものを含む）：`backend/tests/unit/`・`backend/tests/integration/`の両方を実行する
- `backend/`配下に変更がない場合はワークフローを実行しない（`paths`フィルタで絞り込む）

### 実行環境

- Python 3.12以上（`backend/pyproject.toml`の`requires-python`に合わせる）
- 依存関係のインストールは`uv sync`を使用する
- テスト実行前に`backend/.env.example`を`backend/.env`としてコピーする（`CORS_ALLOWED_ORIGINS`・`DATABASE_URL`・`SECRET_KEY`等がテスト実行に必要なため。実際のPostgreSQL接続は不要）

### 対象外にすること

- Postgresコンテナの起動（結合テストもSQLite in-memoryで完結するため不要）
- `mypy`・`ruff`等のLint/型チェックの追加（今回はテスト実行のみに絞る。別チケットで検討）
- フロントエンド側のCI（今回はバックエンドのみ）

## 非機能要件

- ワークフロー実行時間を短縮するため、`uv`のキャッシュを活用する
- テスト失敗時はGitHub Actions上でわかりやすく失敗ステップが表示されること

## スコープ外

- Lint・型チェック（`mypy`・`ruff`）のCI化
- フロントエンド（`frontend`・`frontend-angular`）のCI
- デプロイパイプライン（別チケット）
- テストカバレッジレポートの収集・可視化
