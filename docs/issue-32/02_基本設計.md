# 02_基本設計

## 変更対象

- `.github/workflows/backend-tests.yml`（新規）

## ワークフロー構成

1つのワークフローファイルに、2つのジョブを定義する。

### `unit-tests`ジョブ

- トリガー：`push`（全ブランチ対象。`paths: ["backend/**"]`で絞り込み）
- 内容：`backend/tests/unit/`のみ実行

### `integration-tests`ジョブ

- トリガー：`push`だが、`if: github.ref == 'refs/heads/develop'`で`develop`ブランチへのプッシュ時のみ実行
- 内容：`backend/tests/unit/`・`backend/tests/integration/`の両方を実行（結合テストのみでなく、developへのマージ時は単体も含めてフルセットを再実行する）

両ジョブとも同一ワークフローファイル内に定義し、`on.push`イベント1つをトリガーとして共有する。ジョブレベルの`if`条件で実行有無を制御する。

## 処理フロー（共通ステップ）

1. `actions/checkout@v4`でチェックアウト
2. `astral-sh/setup-uv@v3`でuvをセットアップ（キャッシュ有効化）
3. `actions/setup-python@v5`でPython 3.12をセットアップ
4. `working-directory: backend`で以下を実行
   - `cp .env.example .env`
   - `uv sync`
   - `uv run pytest tests/unit -q`（unit-testsジョブ）
   - `uv run pytest tests/unit tests/integration -q`（integration-testsジョブ）

## 影響範囲

- 既存の`.github/workflows/project-status-sync.yml`（PRのProjectsステータス同期）とは独立したワークフローのため、相互の影響はない
- 既存のテストコード・アプリケーションコードへの変更は不要
- Postgresコンテナ等のCIインフラ追加は不要
