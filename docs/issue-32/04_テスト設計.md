# 04_テスト設計

## テスト方針

CI設定自体の検証のため、従来のpytestテストケース設計とは異なり、GitHub Actions上での実行結果を確認する形で動作確認を行う。

## 確認ケース一覧

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | `develop`以外のブランチ（`feature/issue-32`）へプッシュする | `unit-tests`ジョブのみ実行され成功する。`integration-tests`ジョブはスキップされる |
| 2 | ローカルで`.env`なしの状態から`.env.example`をコピーして`pytest tests/unit`を実行する | 全件成功する（事前調査で確認済み） |
| 3 | ローカルで`.env`なしの状態から`.env.example`をコピーして`pytest tests/unit tests/integration`を実行する | 全件成功する（事前調査で確認済み） |
| 4 | `develop`ブランチへのプッシュ（PRマージ） | `unit-tests`・`integration-tests`両方のジョブが実行され成功する |

No.4はPRマージ後にのみ確認可能なため、`08_動作確認.md`にはNo.1〜3の結果とNo.4の確認方法（マージ後にActions画面で確認する旨）を記載する。
