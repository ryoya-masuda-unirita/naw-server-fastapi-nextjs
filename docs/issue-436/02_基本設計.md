# 02_基本設計

## 変更対象

| 対象 | 変更内容 |
|---|---|
| generative-ai-core（プロバイダ） | Bedrock（Claude）を呼ぶチャットのクライアントを、**新しい専用のファイル 1 つ**として追加する。既存の OpenAI・Azure のクライアントと同じ作り（送信を担う部分と、失敗への変換を担う部分）にする |
| generative-ai-core（プロバイダの工場） | 設定のプロバイダに合わせて、新しいクライアントを選ぶ |
| 生成AIアダプタ（ベンダーの登録） | 新しいベンダー `Bedrock` を、Python 版だけのベンダー（Echo と同じ扱い）として、対応表と実行できるプロバイダの一覧に加える。プロパティの保存時チェックが通るようにする |
| Waha! エミュレーター | ワークフロー定義のベンダー名として、新しいベンダーを受け付ける |
| onprem | ワークフロー定義のファイルの読み込みと、Bedrock の API キーの受け渡しを、compose と README に足す |

## 画面 / API 変更概要

画面と HTTP の API の変更はない。変わるのは、ワークフロー定義で `VENDOR` に指定できる値が増えること。

通信の流れ（追加される部分）:

```
アダプタ → Bedrock Mantle の Anthropic 形式の入口 → Claude
```

- 送るもの: 会話（system・user・assistant）、モデル名、最大出力トークン数、温度
- 認証: Bedrock の API キー（Bearer 方式）
- 受け取るもの: 回答の本文。ストリーミングはしない

## 影響範囲

- 既存のプロバイダ: 変更しない。工場の選択に 1 つ分岐が増えるだけ
- 既存の Anthropic（未対応のスタブ）: **変えない**。移植元に合わせたまま残す
- ベンダーの ID・名前の対応表: Python 版だけの ID を 1 つ加える（Echo の 99 と同じ扱い）
- 既存のテスト: 影響しない想定。プロバイダの一覧を全件確かめているテストがあれば、1 行足す
- **後から消せること**: Bedrock の部品は、専用のファイル 1 つと、ほかのファイルの数か所の 1 行だけにする。消すときは、そのファイルと 1 行を削除すれば、元の状態に戻る
- クラウドの server、server-local、client: 影響なし

## 移植方針

移植元に動く実装がないため、次の方針で作る。

1. プロバイダごとのクライアントの構成、設定の項目（URL・API_KEY・MODEL_NAME・TIMEOUT など）、失敗の分類は、移植元と既存の Python 版に揃える
2. 呼び出しの形式と認証は、クラウドの server が Bedrock を呼んでいる処理（Mantle の Anthropic 形式、Bearer の API キー）に合わせる
3. RAG の回答は、既存のプロバイダと同じ方針で、回答 1 回と検証 1 回の 2 回呼ぶ。プロンプトの組み立ては既存の共通部分を使い、プロバイダごとに書き直さない

## 決めること（第1承認の前に確認したい）

### 決めたこと 1: ベンダーの名前

**新しいベンダー `Bedrock` を、Python 版だけの ID（97）で追加する。** 既存の `Anthropic`（ID 2）は動かさない。

理由（ユーザーの指示）: 移植元が Bedrock に対応したときに、移植元の構造に簡単に直せるようにしたい。そのため、既存のファイルに足すのではなく、新しい専用のファイルを作り、消せるようにする。

| | 既存の Anthropic を動かす（前の案 A） | 新しい `Bedrock` を追加する（今回の案） |
|---|---|---|
| 既存ファイルの変更 | 未対応のスタブの削除など、元に戻す作業が要る | 追加だけ。既存のスタブは触らない |
| 消すとき | スタブを復活させる必要がある | ファイルと数か所の 1 行を消すだけ |
| ID の衝突 | 移植元が将来 Anthropic の公式 API に使うと、意味が衝突する | 移植元が使わない ID（Echo の 99 と同じ「Python 版だけ」の枠。既存のテストが「未知の ID」に使う 98・999 などとも重ならない）なので、衝突しにくい |

ID は 97 にする。移植元の ID は 0〜5 と、Python 版だけの Echo の 99 である。

### 決めること 2: 認証のヘッダー

> **訂正（#444）**: 実機で確かめた結果、Mantle は `x-api-key` と `Authorization` が同時にあるリクエストを 401 で拒否し、Bearer だけなら 200 を返した。実装は Bearer だけを送る形に直した。以下の「両方を送る」は、確かめる前の想定として残している。

Bedrock Mantle が、Anthropic 標準のキー用ヘッダーと、Bearer のどちらを受け付けるかを、私は実際には確かめていない。クラウドの server は公式 SDK にキーを渡して動いており、その SDK がどちらを送っているかを、実装時に確認する。確認できなければ、両方のヘッダーを送る案にする。
