# 05_テスト詳細設計

テストの命名規則: クラス・メソッド名は英語、意図は日本語の docstring に書く。外部通信は `respx` でモックする（既存の `test_provider_clients.py` と同じ方式）。

## 新規

| ファイル | 内容（`04` の No） |
|---|---|
| `generative-ai-adapter/generative-ai-core/tests/test_bedrock_transport.py` | 1〜14。respx で `/v1/messages` への POST を受け、リクエストの URL・ヘッダー・本文と、応答の解釈を確かめる。画像は `conftest.py` の PNG を使う。RAG は、回答用と検証用の応答を順に返すモックで、送信回数を確かめる |

## 変更

| ファイル | 変更（`04` の No） |
|---|---|
| `generative-ai-adapter/generative-ai-core/tests/test_provider_model.py` | プロバイダを全件確かめている部分（23 行付近の対応表）に、Bedrock の 1 行を足す（`bedrock-ext` の目印つき）。ほかのプロバイダは変えない |
| `generative-ai-adapter/generative-ai-core/tests/test_provider_runtime.py` | 機能対応表のテストに、Bedrock が chat・RAG・画像説明すべて対応済みであることを足す（15）。Anthropic・VertexAI・GoogleAIStudio の「未対応の証跡」のテストは変えない（17） |
| `generative-ai-adapter/generative-ai-adapter/tests/test_app_provider_capability.py` | 変えない（`"2"` の Anthropic が未対応のままであることを、そのまま確かめる）。Bedrock（`"98"`）が保存時チェックを通ることのテストを足す（16） |
| `waha-emulator/tests/test_workflow_config.py` | `VENDOR: Bedrock` の定義が読め、`${BEDROCK_API_KEY}` が展開されることのテストを足す（18） |

`test_provider_clients.py` は変えない（Anthropic の未対応のテストを、そのまま残す）。

## 確認の手順

```bash
cd generative-ai-adapter && uv run pytest
cd waha-emulator && uv run pytest
uv run ruff check <変更したファイル>
uv run ruff check --select D101,D102,D103,D105,D106,D107,D417 --config 'lint.pydocstyle.convention="numpy"' <変更したファイル>
```

型チェックは、各プロジェクトの既存の設定に従う（`pyproject.toml` を確認して実行する）。
