# #436 アダプタから Bedrock（Claude）を直接呼べるようにする

## 概要

生成AIアダプタから AWS Bedrock（Claude）を直接呼べるようにする。`onprem/` で Azure OpenAI の代わりに Bedrock を使い、SECURE アシスタントの質問が社内で閉じたまま LLM まで届く経路を、Mac 上で通しで確かめられるようにする。

## 説明

### 背景・事実

- 生成AIアダプタが実行できるプロバイダは、OpenAI・Azure OpenAI・SecuAiGent・Echo の 4 つだけ
- Anthropic は ID だけあり、呼ぶと「未対応」の理由つきで失敗する
- **移植元の Anthropic のクライアントも同じ未対応のスタブで、動く実装は移植元にない**。移植元に Bedrock のコードもない。このため、移植ではなく新規の実装になる
- クラウドの server には、Bedrock Mantle（Anthropic 形式の入口）を呼ぶ処理が #149・#249 で入っている。接続の形式と認証の参考にできる
- 今の回避策は SecuAiGent 経由（クラウドの server が Bedrock を呼ぶ）。ただし質問がクラウドを通るため、SECURE の趣旨に合わない

### 対応

- アダプタに、Bedrock Mantle の Anthropic 形式の入口を呼ぶチャットのクライアントを追加する
- Waha! エミュレーターのワークフロー定義で、Bedrock を登録できるようにする
- `onprem/` の compose と README に、設定と手順を足す
- 実機の確認（本物の Bedrock API key が要る）は、手順を残してユーザーが行う

### 対象外

- 埋め込み（ベクトル化）。Claude に埋め込みモデルはなく、別 Issue にする
- クラウド側 server の Bedrock 処理の変更

### 受け入れ条件

- ワークフロー定義に Bedrock を登録すると、アダプタが Bedrock に質問を送り、回答を返す
- 既存のプロバイダ（OpenAI・Azure・SecuAiGent・Echo）の挙動と既存テストが変わらない
- 新しいクライアントに、外部通信をモックしたテストがある
- `onprem/README.md` の手順で、Mac 上の SECURE の経路が Bedrock まで通る（実機確認は手順のみ）
