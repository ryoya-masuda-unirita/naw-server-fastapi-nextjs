# 03_詳細設計

## 方針

- Bedrock は、**新しいベンダー `Bedrock`（ID 98。Python 版だけ。Echo の 99 と同じ扱い）として、専用のファイル 1 つに作る**。既存の `Anthropic`（ID 2、未対応のスタブ）は変えない
- 移植元が将来 Bedrock に対応したときに、**そのファイルと数か所の 1 行を消せば、元の状態に戻る**ようにする
- 認証のヘッダーは、実機で確かめられないため、キー用ヘッダーと Bearer の両方を送る
- 実機の確認は、手順を残してユーザーが行う

## 消せる作りにする（目印と手順）

既存のファイルに足す箇所（`model.py`・`factory.py`・`vendor.py`）には、すべて `bedrock-ext` という目印のコメントを付ける。消すときは、次のとおり。

```bash
grep -rn "bedrock-ext" generative-ai-adapter/    # 足した箇所を全部探す
```

1. `clients/bedrock.py` と `tests/test_bedrock_transport.py` を削除する
2. `bedrock-ext` の目印がある行（`model.py`・`factory.py`・`vendor.py` の各 1〜2 行）を削除する
3. `generative-ai-adapter/README.md` の「移植元にない拡張」の節、`onprem/` の Bedrock の設定、`waha-emulator` の登録例を削除する
4. 移植元の実装に置き換えるなら、それを移植し、`factory.py` の分岐を向ける。ワークフロー定義は、`VENDOR` の値を変えるだけで済む

README にも同じ手順を書く。

## 新規: `bedrock.py`

### 構成（上から、この順に書く）

| 順 | 要素 | 役割 |
|---|---|---|
| 1 | 定数 | `MESSAGES_PATH = "/v1/messages"`、`ANTHROPIC_VERSION = "2023-06-01"`、`DEFAULT_MAX_TOKENS`（最大出力トークンが未指定のときの値）、`EVIDENCE_BEDROCK` |
| 2 | 形式の関数 | Messages API の形式にする関数（リクエスト本文の組み立て、メッセージ・画像の変換、応答の解釈） |
| 3 | 接続先の関数 | **接続先ごとの違い（URL の組み立て・認証のヘッダー）を 1 つにまとめた関数。** Bedrock Mantle 固有の部分はここだけ |
| 4 | `BedrockMessagesTransport(ChatTransportBase)` | `chat`・`rag` を実装する。画像説明は `ChatTransportBase` の既定（chat 1 回）を使う |
| 5 | `BedrockCoreChatClient(GenericCoreProviderChatClient)` | 送信部に委ね、例外を失敗の結果にする。`CoreProviderId.Bedrock` を返す |

ファイルの冒頭の説明に、「移植元に対応する実装がない独自の拡張。移植元が対応したら置き換える」と書く。

`ProviderHttpError` と RAG の共通部分（`parse_rag_answer`・`validation_passed`・`references_in_range`・`validation_messages`・`to_rag_messages`）は、`openai_compatible.py` から import して使う。プロンプトの組み立てを複製しない。

### リクエスト

- URL: `{エンドポイント（末尾の / を除く）}/v1/messages`
  - 例: 設定の URL が `https://bedrock-mantle.ap-northeast-1.api.aws/anthropic` なら、`.../anthropic/v1/messages`（クラウドの server が使う公式 SDK と同じ組み立て）
- 本文:

| 項目 | 内容 |
|---|---|
| `model` | `MODEL_NAME`（例: `anthropic.claude-haiku-4-5`） |
| `max_tokens` | 生成オプションの `max_tokens`。未指定なら `DEFAULT_MAX_TOKENS`（Messages API は必須のため） |
| `system` | role が system のメッセージを、空行 2 つでつないだ文字列。なければ付けない |
| `messages` | system 以外のメッセージ。role は小文字の `user` / `assistant` |
| `temperature`・`top_p` | 指定されたときだけ送る。未指定のときは送らず、サーバーの既定に任せる（OpenAI 系の 0.7 は引き継がない） |
| `stop_sequences` | `stop` が指定されたとき `[stop]` |
| `stream` | `false` |

- 送らないもの: `frequency_penalty`・`presence_penalty`・`reasoning_effort`・`verbosity`（Messages API にない。指定されても無視する）
- 画像の添付: メッセージの content を配列にし、画像は `{"type": "image", "source": {"type": "base64", "media_type": MIME, "data": base64}}` にする
- JSON 応答（候補 JSON・RAG）: Messages API に `response_format` はないため、付けない。RAG は共通のプロンプトに JSON の指示があり、回答の解析も共通の `parse_rag_answer` で行う

### 認証

`x-api-key: {API_KEY}` と `Authorization: Bearer {API_KEY}` の両方に加え、`anthropic-version` を送る。Mantle がどちらを要求するかを実機で確かめられないため。どちらか一方だけが必要な場合も、もう一方は無視される想定。この組み立ては「接続先の関数」にまとめる。

### 応答

- `content` の `type == "text"` のブロックの `text` を、順につないで回答本文にする。なければ None
- HTTP エラー: `ProviderHttpError(f"HTTP {status} - {本文}")`（OpenAI 系と同じ書式）。秘密情報は、既存の失敗の変換で伏せられる

### chat・rag

- `chat`: 1 回呼んで、本文を `CoreChatResult.success` に包む（OpenAI 系と同じ）
- `rag`: 回答 1 回、参照 ID があれば検証 1 回の最大 2 回呼ぶ。検証を通らなければ `no_answer`（OpenAI 系と同じ流れ。ロジックは共通の関数を使う）
- ログは、`provider`・`purpose`・`model`・メッセージ数だけ。本文・キーは出さない

## 足す箇所（目印つき）

```python
# model.py（CoreProviderId の中）
    Bedrock = (98, "Bedrock", "bedrock")  # bedrock-ext

# factory.py
from ...clients.bedrock import BedrockCoreChatClient  # bedrock-ext
        case CoreProviderId.Bedrock:  # bedrock-ext
            return BedrockCoreChatClient(configuration)  # bedrock-ext

# vendor.py
    "98": "Bedrock",  # bedrock-ext
RUNNABLE_PROVIDERS = (..., "Bedrock")  # bedrock-ext
```

（上は形の例。実際の行は実装時に既存の書き方に合わせる。）

## onprem

- `onprem/docker-compose.yml` の waha-emulator に、次を足す:
  - `WAHA_WORKFLOWS_FILE: ${WAHA_WORKFLOWS_FILE:-}`
  - `BEDROCK_API_KEY: ${BEDROCK_API_KEY:-}`
  - volumes に `./config:/app/onprem-config:ro`（存在しないファイルを直接 mount すると、ディレクトリが作られてしまうため、ディレクトリを mount する）
- `onprem/config/workflows.bedrock.example.json`: `default` に `VENDOR: Bedrock` を登録した例
- 使い方: `cp config/workflows.bedrock.example.json config/workflows.json` → `.env` に `WAHA_WORKFLOWS_FILE=/app/onprem-config/workflows.json` と `BEDROCK_API_KEY=...` を書く → `docker compose up -d --build`
- `onprem/config/workflows.json` は `.gitignore` に入れる
