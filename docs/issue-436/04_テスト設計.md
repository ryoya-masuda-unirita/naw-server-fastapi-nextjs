# 04_テスト設計

## テスト方針

- 外部通信は、すべてモックで行う。本物の Bedrock には接続しない
- 既存のプロバイダ（OpenAI・Azure・SecuAiGent・Echo）の既存テストは、変えずに通ることを確かめる
- 既存のテスト（Anthropic の未対応を確かめるものを含む）は変えない。変えない（実装してみて、影響を受けるものはなかった）
- Bedrock の部品を消したとき（`bedrock-ext` の行と専用ファイルを削除したとき）に、既存のテストがそのまま通ることも、確認の対象にする（No 21）

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 通常 chat | system と user のメッセージを送る | 回答の本文が成功の結果になる。system は別の項目で送られ、messages には含まれない |
| 2 | リクエストの形 | chat を 1 回呼ぶ | 送り先が接続先の URL の末尾に `/v1/messages` を付けたもの。本文に `model`・`max_tokens`・`stream=false` がある |
| 3 | 認証のヘッダー | chat を 1 回呼ぶ | キー用ヘッダー・Bearer・バージョンのヘッダーが付く |
| 4 | 最大トークン数 | 最大出力トークン数が未指定 / 指定あり | 未指定なら既定値、指定ありならその値で送られる |
| 5 | 生成オプション | 温度・top_p・stop を指定 / 未指定 | 指定したものだけが送られる。未指定なら温度を送らない |
| 6 | 非対応のオプション | frequency_penalty などを指定 | 送られず、エラーにもならない |
| 7 | 複数の text ブロック | 応答の content が複数の text ブロック | 本文が順につながる |
| 8 | 空の応答 | content が空 / text がない | 空文字の成功（OpenAI 系と同じ扱い） |
| 9 | HTTP エラー | 401・400・500 | 既存と同じ分類の失敗になり、API キーが失敗の文に含まれない |
| 10 | 画像の添付 | メッセージに画像がある | content が配列になり、画像が base64 のブロックで送られる |
| 11 | 画像説明 | 画像説明を実行 | chat 1 回で行われ、結果が返る |
| 12 | RAG の回答 | 回答に参照 ID あり・検証が通る | 回答が成功になり、送信は 2 回（回答 1・検証 1） |
| 13 | RAG の検証失敗 | 検証が通らない | 回答なし（no_answer）になる |
| 14 | RAG の参照なし | 回答に参照 ID がない | 検証を呼ばず、回答なしになる（送信 1 回） |
| 15 | 対応状況 | 機能対応表を作る | Bedrock の chat・RAG・画像説明がすべて対応済み。Anthropic・VertexAI・GoogleAIStudio は未対応のまま |
| 16 | ベンダーの検証 | `VENDOR` に `Bedrock` / `97` を指定 | 保存時チェックを通る。エラー文の対応プロバイダ一覧に Bedrock が入る |
| 17 | 未対応の維持 | `VENDOR` に Anthropic（`2`）・VertexAI を指定 | 従来どおり「未対応」で止まる |
| 18 | ワークフロー定義 | `VENDOR: Bedrock` と `${環境変数}` を含む定義を読む | 読み込めて、環境変数が展開される |
| 19 | 既存の回帰 | generative-ai-core・generative-ai-adapter・waha-emulator の既存テスト | すべて通る |
| 20 | 静的チェック | ruff・型チェック | 通る |
| 21 | 消せること | Bedrock の専用ファイル・専用テスト・`bedrock-ext` の行を取り除く | 既存のテストがすべて通る（確認後、元に戻す） |
