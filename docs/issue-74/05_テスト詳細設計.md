# 05_テスト詳細設計

## 対象ファイル

`backend/tests/integration/test_tenants.py`

## フィクスチャ

- `tenant`: テスト用テナント（`max_usage_based_credits_per_month=500`）
- `admin_user`: `tenant`に属するADMINロールユーザー
- `normal_user`: `tenant`に属するUSERロールユーザー
- `other_tenant` / `other_tenant_admin_user`: 権限不一致検証用の別テナント・別管理者
- `plan`: `max_credits_per_month=1000`のプラン
- `_create_active_subscription(session, tenant_id, plan_id)`: 本日開始の有効なサブスクリプションを作成するヘルパー
- `tenant_resource`: `tenant`に紐づく`TenantResource`（`type=AZURE_OPENAI`）
- `_token_usage(...)`: `test_credit_usage.py`と同様のトークン利用量作成ヘルパー
- `_headers(login_id, tenant_id)`: 認証ヘッダー作成ヘルパー

## テストケース一覧（`TestTenantsRouter`）

### `TestGetTenantDetails`

- `test_get_tenant_details_with_subscription_and_resources`: サブスクリプション・リソースを持つテナントを管理者が取得すると、`tenantId`/`tenantName`/`maxUsageBasedCreditsPerMonth`/`resources`/`subscription.plan`が正しく返ること
- `test_get_tenant_details_without_active_subscription`: 有効なサブスクリプションがない場合`subscription`が`null`になること
- `test_get_tenant_details_without_authentication`: 未認証で401になること
- `test_get_tenant_details_forbidden_for_non_admin`: 一般ユーザーで403になること
- `test_get_tenant_details_forbidden_when_tenant_header_mismatch`: JWTと異なる`X-Tenant-ID`で403になること

### `TestPatchAdminTenant`

- `test_patch_tenant_name_only`: `tenantName`のみ送信すると、名前のみ更新されクレジット上限は変化しないこと
- `test_patch_max_usage_based_credits_only`: `maxUsageBasedCreditsPerMonth`のみ送信すると、上限のみ更新されること
- `test_patch_max_usage_based_credits_null_resets_to_zero`: `maxUsageBasedCreditsPerMonth: null`を送信すると0にリセットされること
- `test_patch_both_fields`: 両キー送信で両方更新されること
- `test_patch_empty_body_does_not_update`: 空ボディで更新されず現状が返ること
- `test_patch_returns_404_when_tenant_not_found`: 存在しない`tenantId`で404になること
- `test_patch_returns_400_when_usage_exceeds_new_limit`: 請求期間内利用クレジットが新上限以上のとき400になること
- `test_patch_returns_422_for_negative_credits`: 負の値で422になること
- `test_patch_forbidden_when_tenant_path_mismatch`: パスの`tenantId`と認証テナントが異なる場合403になること
- `test_patch_forbidden_for_non_admin`: 一般ユーザーで403になること

## Repository/Service層の単体テスト方針

Router層の統合テストでService/Repositoryの挙動を網羅できるため、本Issueでは個別のRepository/Serviceユニットテストは追加しない（既存の`credit_usage`関連実装も同様の方針）。
