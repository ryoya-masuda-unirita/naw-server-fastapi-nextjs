## 処理フロー

### GET /api/admin/tenants

1. `get_verified_tenant_id`でヘッダーとJWTのテナント一致を検証（一致しない場合403、ヘッダー欠落時422）
2. `require_admin`でADMIN/SYSTEMロールを検証（それ以外403）
3. `TenantService.get_tenant_detail_response`を呼び出す
   1. `TenantRepository.find_by_id`でテナント取得。存在しない場合404
   2. `TenantResourceRepository.find_by_tenant_id`でリソース一覧取得
   3. `SubscriptionRepository.find_active_by_tenant_id_with_plan`で有効なサブスクリプション+プランを取得（存在しなければ`subscription`は`null`）
   4. `TenantDetailResponse`を組み立てて返す

### PATCH /api/admin/tenants/{tenantId}

1. `require_admin_for_tenant_path`でパスの`tenantId`とJWTのテナント一致・ADMIN/SYSTEMロールを検証
2. `TenantService.patch_admin_tenant(tenant_id, request, session)`を呼び出す
   1. `TenantRepository.find_by_id`でテナント取得。存在しない場合404
   2. `"tenantName" in request.model_fields_set`の場合、`tenant.name = request.tenantName`
   3. `"maxUsageBasedCreditsPerMonth" in request.model_fields_set`の場合:
      - `effective = request.maxUsageBasedCreditsPerMonth if request.maxUsageBasedCreditsPerMonth is not None else 0`
      - `_assert_new_max_usage_based_credits_not_below_current_usage(tenant_id, effective, session)`を呼び、超過していれば400
      - `tenant.max_usage_based_credits_per_month = effective`
   4. いずれかのキーが送られていれば`TenantRepository.update(tenant, session)`でDB更新
   5. `get_tenant_detail_response`と同じロジックで最新の`TenantDetailResponse`を組み立てて返す

### 上限チェックロジック（`_assert_new_max_usage_based_credits_not_below_current_usage`）

Java版`assertNewMaxUsageBasedCreditsNotBelowCurrentUsage`と同じ計算。

1. `now = datetime.now(timezone.utc)`
2. `SubscriptionRepository.find_active_by_tenant_id_with_plan(tenant_id, now.date(), session)`が`None`なら何もしない
3. `plan.max_credits_per_month`が`None`なら何もしない
4. `current_billing_reset_instant_utc(subscription.start_date, now)`が`None`なら何もしない
5. `TokenUsageRepository.summarize(tenant_id, period_from, now, None, session)`で利用クレジット合計を集計
6. `usage = input_credits + output_credits + embedding_credits`
7. `limit = plan.max_credits_per_month + new_max`
8. `usage >= limit`なら`HTTPException(400, "...")`
