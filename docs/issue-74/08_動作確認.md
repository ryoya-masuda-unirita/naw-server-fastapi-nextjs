# 08_動作確認

## 確認環境

本Issueでは、指示によりブラウザ操作による動作確認は行わず、自動テスト（pytest）の実行結果および実DB（PostgreSQL、`naw-fastapi-postgres`コンテナ）でのAlembicマイグレーション適用結果をもって代替する。

- Python 3.14 / FastAPI（backend/.venv）
- ローカルPostgreSQL（`docker compose up -d`、`naw-fastapi-postgres`、ポート5433）

## 確認手順

1. `docker ps`でPostgreSQLコンテナが起動していることを確認
2. `cd backend && alembic upgrade head`でマイグレーション（020: `tenant_resources`テーブル追加）を適用
3. `alembic downgrade -1` → `alembic upgrade head`でdowngrade/upgradeの往復が正常に行えることを確認
4. `python -m pytest -q`でバックエンド全テスト（新規追加分含む）を実行
5. `python -m ruff check` / `python -m mypy`で新規追加ファイルにコードスタイル・型の新規エラーがないことを確認（既存ファイルに存在するSQLAlchemy/SQLModelの型付けに関する既知のmypy指摘は本Issue範囲外のため対象外）

## 確認結果

- `alembic upgrade head`: `019 -> 020, Add tenant_resources table` が成功
- `alembic downgrade -1` → `alembic upgrade head`: 往復とも成功し、最終的に`020 (head)`であることを確認
- `python -m pytest -q`: **518 passed**（新規追加した`tests/integration/test_tenants.py`14件、`tests/unit/test_tenant_service.py`2件を含む）
- `python -m ruff check`: 新規追加ファイルに指摘なし（未使用importを1件検出し`--fix`で解消済み）
- `python -m mypy`: 新規追加ファイルに新規の型エラーなし（`tenant_repository.py`・`tenant_resource_repository.py`に検出された指摘は、既存の全リポジトリファイル（`user_repository.py`, `subscription_repository.py`, `token_usage_repository.py`等）にも共通して存在するSQLModelの`where()`引数型付けに関する既知のmypy限界であり、本Issueで新規に生じたものではない）
