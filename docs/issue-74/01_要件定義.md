# 01_要件定義

## 背景

管理者向けのテナント詳細画面・設定画面を実現するために、テナント情報（テナント名・利用ベースクレジット上限・リソース一覧・契約中サブスクリプション情報）の取得と、テナント名・利用ベースクレジット上限の部分更新を行うAPIが必要。移植元Spring Bootの`TenantController`にはすでに実装されており、これをFastAPI側に移植する。

GET/PATCHはともに`TenantDetailResponse`という同一のレスポンス形状を返し、更新後にGETと同じロジックで最新状態を再取得して返すという密結合な実装になっているため、1つのIssueとして扱う。

このIssueは、直前のIssue #73で新規移植された`Plan`/`Subscription`ドメイン（`app/models/plan.py`, `app/models/subscription.py`, `app/repositories/subscription_repository.py`, `app/core/billing_cycle.py`）に依存する。

## 機能要件

- `GET /api/admin/tenants`
  - `X-Tenant-ID`ヘッダーで指定されたテナントの`TenantDetailResponse`を返す
  - テナント管理者（ADMIN/SYSTEMロール）のみ許可する
- `PATCH /api/admin/tenants/{tenantId}`
  - パスパラメータ`tenantId`は認証済みテナント管理者の所属テナントと一致する必要がある（不一致は403）
  - リクエストボディで送られたキーのみを更新対象とする（値の`null`有無ではなく、キー自体が存在するかどうかで判定する）
    - `tenantName`キーが存在する場合、その値でテナント名を更新する
    - `maxUsageBasedCreditsPerMonth`キーが存在する場合、その値（0以上）で利用ベースクレジット上限を更新する。値が`null`の場合は0にリセットする
    - どちらのキーも存在しない場合は永続化を行わず、現状の`TenantDetailResponse`を200で返す
  - テナントが存在しない場合は404
  - `maxUsageBasedCreditsPerMonth`を更新する際、契約中サブスクリプションの請求期間内の利用クレジット合計が「プランのクレジット枠 + 新しい利用ベース上限」以上になる場合は、上限を下げすぎているとみなし400を返す（有効なサブスクリプションが存在しない、またはプランのクレジット枠が未設定の場合はこのチェックをスキップする）
  - 更新後、GETと同じロジックで最新の`TenantDetailResponse`を返す
- レスポンス（`TenantDetailResponse`）
  - `tenantId`, `tenantName`, `maxUsageBasedCreditsPerMonth`, `isDeleted`, `createdAt`, `updatedAt`
  - `resources`: テナントに紐づくリソース一覧（`id`, `type`, `description`）。FastAPI側に対応するテーブル・モデルが存在しないため新規に移植する
  - `subscription`: 有効なサブスクリプション（存在すれば1件、`id`, `status`, `startDate`, `endDate`, `createdAt`, `updatedAt`, `plan`）。存在しなければ`null`

## 非機能要件

- 既存の`router:service`1対1規約に従い、`routers/tenants.py` ↔ `services/tenant_service.py`として新規作成する（`tenant_endpoints.py`/`tenant_endpoint_service.py`とは別ドメインとして扱う）
- 利用クレジット合計の算出は、Issue #73で実装済みの請求サイクル算出ロジック（`app/core/billing_cycle.py`）・サブスクリプション取得（`SubscriptionRepository.find_active_by_tenant_id_with_plan`）・トークン利用量集計（`TokenUsageRepository.summarize`）を再利用する。ただし`services/credit_usage_service.py`を直接呼び出すことはしない（service間の呼び出し禁止規約のため）

## スコープ外

- `GET /admin/tenants/resources/{resourceId}/cost`（Azure Cost Management API連携）
- テナントリソース（`TenantResource`）自体の作成・更新・削除API（今回はGETレスポンスに含めるための参照のみ）
- フロントエンド（`frontend/`, `frontend-angular/`）側の対応
