# 01_要件定義

## 背景

Spring Boot 実装（移植元）の `TenantController` には、テナントのローカルサーバーエンドポイント（LOCAL_SERVERタイプ）を1件取得するAPIが存在する。このAPIは既存の移植済みエンドポイント一覧・作成・更新・削除APIとは異なり、レスポンスに `apiKey`（接続用のAPIキー）を含む点が特徴。FastAPI側（`backend/app/routers/tenant_endpoints.py`）にはまだ移植されていないため、本Issueで対応する。

## 機能要件

- `GET /api/tenants/endpoints/local/{endpointId}` エンドポイントを新規追加する
- リクエスト
  - パスパラメータ: `endpointId`（エンドポイントID）
  - 認証: JWT必須（Cookie/Authorizationヘッダー）。移植元は `X-Tenant-ID` ヘッダーからテナントIDを取得するが、既存の類似エンドポイント（`GET /api/admin/tenants/endpoints/{type}` = `get_endpoints_by_type`）の移植時の判断を踏襲し、JWTの `current_user.tenant_id` からテナントIDを取得する
  - 認可: 管理者（ADMIN または SYSTEM ロール）のみ許可する（`require_admin` を使用。既存の類似エンドポイントと同様の理由で、`apiKey` を含む機密性の高いレスポンスのため）
- レスポンス
  - `200 OK`: `id`, `tenantId`, `type`, `endpoint`, `apiKey` を含むJSON
  - `404 Not Found`: 指定した `endpointId` が存在しない、または自テナントに属さない、またはタイプが `LOCAL_SERVER` 以外の場合
- 取得対象は「自テナント かつ `endpointId` 一致 かつ タイプが `LOCAL_SERVER`」のエンドポイントのみ
- 既存の `TenantEndpoint` モデル・`TenantEndpointRepository.find_by_id_and_tenant_id`（既存メソッド）をそのまま流用する
- 既存の一覧・作成・更新・削除・タイプ別一覧エンドポイントとはレスポンス形状が異なるため、新規のレスポンススキーマ（`apiKey` を含む）を追加する

## 非機能要件

- 既存の `TenantEndpointService`（`routers/tenant_endpoints.py` と1対1対応）にメソッドを追加する形で実装し、新たな service ファイルは作らない（既存の `groups.py` が複数 router から1つの `GroupService` を利用する構成を踏襲する）
- 既存のリポジトリメソッドを流用し、N+1やDBアクセスの重複を発生させない

## スコープ外

- `LocalServerEndpointResponse` 以外の既存エンドポイント（一覧・作成・更新・削除・タイプ別一覧）の変更
- フロントエンド（`frontend/` React、`frontend-angular/` Angular）側の対応
- ブラウザでの動作確認（本Issueは自動テストの実行結果で代替する）
