# 01_要件定義

## 背景

移植元が GitLab のモノレポ `secuaigent` に統合され、旧構成の別リポジトリ（`~/Documents/secuaigent/{server,client}`・`~/Documents/naw-server`・`~/Documents/secuaigent-client`）はどれも存在しない。AIエージェント向けのドキュメント・スキルが旧パスを参照しているため、調査・起票・同期が正しく動かない。

## 決定事項（2026-11-12 ユーザー確認）

| 論点 | 決定 |
|---|---|
| 参照先 | 業務の作業ツリー `~/Documents/unirita-develop-pj/secuaigent` は使わず、`origin/develop` に detached した参照専用 worktree `~/Documents/unirita-develop-pj/secuaigent-ref` を参照する（作業中のブランチを切り替えないため） |
| 移植対象 | モノレポのすべて。`server/`→`backend/`、`client/`→`frontend/`、`generative-ai-adapter/`・`secuaigent-server-local/` はルートに別ディレクトリを新設して Python で移植。その他（`secuaigent-infra/`・`e2e-test/` 等）は移植先を着手時に決める |
| 開発方針 | 「バックエンド優先・`frontend/` は当面不問」をやめ、`backend/` と `frontend/` を並行して進める。新しく対象に加わったモジュールは着手前に優先順位を確認する（ユーザー指示「よしなに」を受けて AI が案を作成） |

## 要件

- REQ-1: 参照パスを `secuaigent-ref/{server,client}` に統一する（このリポジトリ自身のパス `~/Documents/personal/naw-server-fastapi-nextjs` も修正）
- REQ-2: 「develop の最新化」手順を、作業ツリーのブランチに影響しない `fetch` + `checkout --detach origin/develop` に変える（スキル・`sync.sh` を含む）
- REQ-3: モノレポの構成・移植対象・移植先の対応表を記載する
- REQ-4: `client/` の git 履歴の記述を実態に合わせる（2026-07-13 にモノレポへ取り込み）
- REQ-5: 開発方針を改定する

## スコープ外

- `docs/issue-*`・`docs/調査結果/` などの過去の記録
- `.claude/settings.json` の権限許可リストにある旧パス（動作に影響しない）
- 新しく対象に加わったモジュールの移植そのもの
