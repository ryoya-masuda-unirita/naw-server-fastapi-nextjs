# 03_詳細設計

## API（backend の実応答との差と画面での吸収）

`docs/issue-279/api-backend-diff.md` と `backend/app/routers/indexes.py`・`tenant_endpoints.py`・`groups.py`、`schemas/index.py` を確認した。

| API | 形 | 移植元との差と対応 |
|---|---|---|
| `GET /api/admin/indexes` | `{ content, totalElements, number, size }`。行は `tenantEndpoints[]`・`groupIds` | 移植元は `endpointIds` を持つ型。`tenantEndpoints[].id` から `endpointIds` を作って吸収した（`indexRowToApiItem`）。`description`・`add`・`delete`・`get` は null あり → 画面側で `''`・undefined に直す。`sort` は `name`・`type`・`updatedAt` を受ける |
| `POST /api/admin/indexes` | 本文 `IndexRequest`、応答 `IndexResponse` | LOCAL は `endpointIds` が 1 件、`get`・`add`・`delete` が必須。SAAS_GLOBAL は 2 件。画面の送信内容はこの条件を満たす。**`description` は backend が 255 文字まで、移植元の画面は 1000 文字まで**。256〜1000 文字だと backend が 422 を返し、共通エラートーストが出る（画面の入力チェックは移植元どおり 1000。申し送り） |
| `GET /api/admin/tenants/endpoints/{type}` | 配列 `[{ id, tenantId, type, endpointName, endpoint }]` | 差なし。移植元は `data` 包みも受けるが、backend は配列のみのため配列だけ扱う。管理者のみ（`require_admin`） |
| `GET /api/admin/groups` | `{ data, total, page, size }` | 移植元の `listAllGroupIds` と同じく 100 件ずつ全ページ取る（`content` 形も受ける）。移植元は総数に届かないまま空のページが返ると無限ループするため、空のページで止める |

## 状態

### `useTrainingDataStore`
`filter`（`pageSize` 5・`pageIndex` 1・`sortField` updatedAt・`sortOrder` desc が初期値）。`updateFilter` は 1 ページ目へ戻す。画面を離れたら `reset()`。検索語・並べ替えの選択表示は画面の `useState`（移植元の signal）。

## 画面の挙動

- 並べ替えの選択は最初どちらも未選択（プレースホルダーは「更新日時順」）。項目をクリアすると `sort` を送らない（backend の既定は更新日時の降順）。方向の選択肢は移植元もテンプレートで渡さず、共通部品の既定（昇順・降順）
- 件数表示（`1-5件 / 7件`）と接続サーバー名（クラウド／ローカル）は移植元でも日本語の固定文字列
- 作成成功後は `setQueryData` で現在の一覧の先頭に足し、総件数を 1 増やす（移植元 `createFolder`）。次に開いたときに取り直される
- サービス ID は、サーバー未選択とローカルでは必須、クラウドでは不要（移植元 `setLocalOnlyValidators`）
- 紐づけるグループはテナントの全グループ（移植元どおり）

## 移植元と変えた点（理由）

1. **画面を離れたら条件を捨てる**（`store.reset()`）。#122 と同じ判断
2. **フォーカスでの再取得をしない**
3. **サーバーを続けて切り替えたとき、古い接続先の応答で上書きしない**（移植元は競合する。見た目は同じ）
4. **読み込み表示を「グループ取得」と「接続先取得」で別に数える**（移植元は 1 つの真偽値で、先に終わった方で消える）
5. 接続先選択のエラー時のスクロール先に、`FormSelect` が id を描画しないため外側の `div#create-folder-endpoint` を置いた
6. **送信中は Esc・背景クリックでダイアログを閉じない**（移植元は閉じられ、結果が見えないまま二重に作りかねない）
7. ダイアログの自動フォーカス無効（`autoFocus: false`）は共通 `Dialog` が対応していないため、開いたとき最初の入力欄へフォーカスが入る

## 移植元の不具合・仕様をそのまま移したもの（申し送り）

- 名前の前後の空白は trim しない（空白だけでも作成できる）
- 作成に失敗したときの個別のトーストはなく、共通エラートーストのみ
