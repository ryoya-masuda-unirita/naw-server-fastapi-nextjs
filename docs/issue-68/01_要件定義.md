# 01_要件定義

## 背景

現在のFastAPI版バックエンドには、パスワードによるログイン（`/auth/login`）は実装済みだが、ログインキーという代替認証手段によるログインAPIが未実装である。移植元のSpring Boot実装にはすでに存在するため、機能差分を埋める。

## 機能要件

- ログインキーを使ってユーザーを認証し、成功時は通常ログインと同じ形式のJWTトークンを含むレスポンスを返す
- リクエストにはテナントIDのヘッダーが必須である
- ログインキーに該当するユーザーが存在しない場合、またはテナントが一致しない場合は認証エラーとして扱う
- 認証成功時はアクセストークンをCookieにも設定する（既存の `/auth/login` と同じ振る舞いに合わせる）

## 非機能要件

- ログインキーが存在しないケースと、テナントが一致しないケースを区別しない（同一の認証エラーレスポンスとする）。ログインキーの存在有無が外部から推測できないようにするため
- 既存の `/auth/login` のレスポンス形式（`AuthResponse`）をそのまま再利用し、フロントエンドとの互換性を保つ

## スコープ外

- ログインキーの発行・更新・失効に関するAPI（本Issueの対象は認証APIのみ）
- パスワードリセット必須フラグ（`is_required_password_reset`）を考慮した分岐（移植元Java実装もログインキー認証ではこの分岐を行っていないため対象外）
- グループ情報を含むレスポンス（既存の `/auth/login` も `groups=[]` 固定であり、本Issueで新たに対応しない）
