# 05_テスト詳細設計

## `backend/tests/unit/test_auth_service.py`

`TestAuthServiceLoginWithLoginKey` クラスを追加する。

- `test_login_with_valid_login_key`: 有効なログインキーで `loginStatus=SUCCESS` かつ `token is not None` を確認
- `test_login_with_nonexistent_login_key`: 存在しないログインキーで `HTTPException(401)` を確認
- `test_login_with_login_key_of_different_tenant`: 別テナントのログインキーで `HTTPException(401)` を確認（Repositoryのモックで `tenant_id` 不一致時は `None` を返すようにする）

## `backend/tests/integration/test_auth.py`

`TestAuthAPI` クラスに以下を追加する。

- `test_post_auth_login_key_success`: `POST /auth/login-key` で200・`loginStatus=SUCCESS`・トークン発行を確認
- `test_post_auth_login_key_with_nonexistent_key`: 存在しないログインキーで401を確認
- `test_post_auth_login_key_with_different_tenant`: 別テナントのログインキーで401を確認（存在しないケースと同一のレスポンスであることを確認）
- `test_post_auth_login_key_missing_header`: `X-Tenant-ID` ヘッダー未指定で422を確認
- `test_post_auth_login_key_sets_access_token_cookie`: 成功時に `access_token` Cookieが設定されることを確認

## fixture

- `backend/tests/integration/conftest.py` に `test_user_with_login_key` fixture を追加する（`login_key` を設定したユーザーを作成する）。既存の `test_user_with_password` を参考に、別テナント検証用に2つ目のテナント・ユーザーも必要に応じて用意する
