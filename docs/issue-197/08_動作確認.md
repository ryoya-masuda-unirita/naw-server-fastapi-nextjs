### CI/CD実機テスト（`04_テスト設計.md` No.1〜7）について

`infra/github_oidc.tf`のIAMロール信頼ポリシーが、OIDCの`sub`クレームを`repo:...:ref:refs/heads/develop`に厳密限定している（このリポジトリの既存の意図的な設計）。そのため、`feature/issue-197`ブランチ上で`deploy.yml`を`workflow_dispatch`で手動起動したところ、マイグレーション実行以前の`Configure AWS credentials`ステップで認証エラーとなり、テストできなかった。

```
##[error]Could not assume role with OIDC: Not authorized to perform sts:AssumeRoleWithWebIdentity
```
（実行ログ: https://github.com/ryoya-masuda-unirita/naw-server-fastapi-nextjs/actions/runs/30695723000）

この制約により、`04_テスト設計.md`のNo.1〜7（マイグレーション自動実行・失敗時の後続停止・seedスクリプト実機確認等）は、**`develop`ブランチへのマージ後に実施する**方針とした。マージ前に用意していたダミー失敗マイグレーション（No.2用）は、`develop`にそのまま持ち込むと通常デプロイを壊すため、マージ前に削除済み。

### 実機テストで発覚し、あわせて修正した不具合

Issue #197自体の実装とは別に、既存環境・既存データの不具合が実機テストで発覚したため、developへ直接修正コミットした。

- `infra/main.tf`の`provider "aws"`に`profile = "naw-fastapi-issue158"`がハードコードされており、GitHub Actions（OIDCの環境変数クレデンシャル）側にはそのプロファイルが存在せず`terraform plan`が失敗していた → `profile`指定を削除
- `infra/README.md`のCIDR系Secrets登録手順が誤り（`list(string)`型に対しカンマ区切り文字列を渡していた）→ HCL/JSON配列表記に修正
- `backend/seed.sql`で、`rooms`が参照する`assistants`のINSERTが後ろにあり、完全に空のDBでは外部キー制約違反になっていた → 順序を修正
- `backend/seed.sql`の`groups_users`に、対応する`users`が存在しない孤立したuser_id行があった → 削除
- `infra/scripts/seed_via_bastion.sh`のAPIキー上書きで、psqlの`-v`/`:'var'`展開がbastion側のpsqlで機能せず構文エラーになっていた → bash側でのエスケープ・直接埋め込み方式に変更
