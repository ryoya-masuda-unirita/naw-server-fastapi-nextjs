# CI/CDにDBマイグレーションを組み込み、seed投入をスクリプト化する

## 概要

CI/CDパイプライン（Issue #161/#189）はbackend/frontend-angular/infraの自動デプロイまでは完成しているが、RDSへのDBマイグレーション（`alembic upgrade head`）・シードデータ投入（`seed.sql`）は依然として手動運用（`infra/README.md`の bastion 経由手順）のままになっている。

本Issueでは以下2点を対応する。

1. **マイグレーションのCI/CD組み込み**: `alembic upgrade head` は冪等な処理のため、`deploy-backend.yml` に組み込み、デプロイのたびに自動実行する
2. **seed投入のスクリプト化**: `seed.sql` の投入は非冪等（再実行で重複・エラーの恐れ）なため、CI/CDには組み込まず、環境構築時（destroy後の再構築含む）に手動実行するシェルスクリプトとして整備する（現状 `infra/README.md` に手順として書かれている、SSHトンネル起動→psql実行の複数ターミナル操作をスクリプト化し、コピペミスを防ぐ）

## 説明

- RDSのセキュリティグループはECSのSG（`rds_postgres_in_ecs`）・bastionのSG（`rds_postgres_in_bastion`）双方からの接続を許可済み
- マイグレーションはECSの一時タスク（`aws ecs run-task`でbackendイメージのコマンドを`alembic upgrade head`に差し替え）として、既存のprivate subnet/SGのまま直接RDSに到達できるため、bastion経由のSSHトンネルは不要
- seedは管理者ユーザー等の初期データ投入で、毎デプロイに含めると重複投入のリスクがあるため、自動化の対象外とする

### 対応方針

**1. マイグレーションのCI/CD組み込み**

- `.github/workflows/deploy-backend.yml` に、ECS one-off task（`aws ecs run-task`）で `alembic upgrade head` を実行するステップを追加する
- GitHub Actions の OIDCロールに `ecs:RunTask` / `iam:PassRole`（task role・execution role分）等、必要なIAM権限を追加する（`infra/`のTerraform側での対応）

**2. seed投入のスクリプト化**

- bastion経由のSSHトンネル起動 → `alembic upgrade head`（初回のみ）→ `seed.sql` 投入、を1本のシェルスクリプトにまとめる
- 配置場所・命名は実装時に検討する（`infra/scripts/` 等）
- `infra/README.md` の該当手順を、スクリプト実行手順に置き換える

## その他

### スコープ外

- seedデータの自動化（CI/CDへの組み込み）は対象外（非冪等なため）
- 本番環境向けの運用は対象外（dev/staging限定）
