# 01_要件定義

## 背景

- 現状のCI/CDは、backend/frontend-angular/infraの自動デプロイまではカバーしているが、DBスキーマ変更（マイグレーション）とテストデータ（seed）の投入は手動運用のままになっている
- マイグレーションはデプロイのたびに必要になりうる冪等な操作であり、人手を介すると反映漏れ・実施忘れのリスクがある
- seedは初期データ投入であり非冪等（再実行で重複・エラーの恐れ）なため、自動化ではなく手動運用の効率化（スクリプト化）が適切と判断する

## 機能要件

- バックエンドの自動デプロイ完了後、DBマイグレーションを自動的に適用できること
- マイグレーション実行環境から、稼働中のデータベースへ到達できること（既存のネットワーク経路を利用し、新たな踏み台や公開経路は追加しない）
- マイグレーション実行の成否がデプロイ結果としてわかること（失敗時はデプロイ全体が失敗として検知できる）
- シードデータ投入手順（接続経路の確立・マイグレーション適用・データ投入）を、1つの操作で実行できるスクリプトとして提供すること
- スクリプトは、環境構築後の初回投入・環境再構築時の再投入のどちらでも使えること

## 非機能要件

- マイグレーション自動実行のために追加する権限は、必要最小限のリソース・操作に限定すること
- 既存のデプロイ所要時間を大きく悪化させないこと
- 既存の踏み台サーバーを使ったシード投入の経路自体は変更しない（スクリプト化のみ行う）

## スコープ外

- シードデータ投入のCI/CD自動化（非冪等なため対象外）
- 本番環境向けの運用（dev/staging限定）
- マイグレーション失敗時の自動ロールバック
