# 05_テスト詳細設計

対象環境: dev（RDSを手動起動した状態で実施する）

| No | 対応するテストNo | 実施方法 |
|---|---|---|
| 1 | 1 | `backend/alembic/versions/` にダミーのカラム追加等の変更を含むリビジョンファイルを作成した状態で `feature/issue-197` からdevelopへのデプロイ（`workflow_dispatch`で `deploy.yml` を手動実行）を行い、GitHub Actionsのログでマイグレーションタスクの実行結果を確認する。あわせてbastion経由で `psql` からスキーマが反映されていることを直接確認する |
| 2 | 2 | 一時的に、存在しないテーブルを参照するなど失敗するダミーリビジョンを用意してデプロイし、ジョブが失敗で止まること、`backend` の `Update ECS service` ステップに到達しないことをGitHub Actionsの実行結果で確認する。確認後はダミーリビジョンを削除する |
| 3 | 3 | ダミーリビジョンを含まない通常の状態でデプロイし、`aws ecs describe-services` でサービスが安定稼働していること、ブラウザ（frontend-angular経由）でログイン・画面遷移ができることを確認する |
| 4 | 4 | マイグレーションタスクの `run-task` 実行前後で `aws ecs describe-container-instances` 等からEC2インスタンスの空きリソースを確認し、タスクが `PROVISIONING`/`PENDING` のまま滞留しないことを確認する |
| 5 | 5 | `terraform destroy` 相当のクリーンな状態（またはseed未投入のRDS）に対し `infra/scripts/seed_via_bastion.sh` を実行し、ログインユーザーでの疎通確認（`admin`でのログイン成功）まで行う |
| 6 | 6 | No.5実施後、同じスクリプトをもう一度実行し、`psql` のエラー出力がターミナルにそのまま表示されることを確認する（スクリプトが `exit 0` で正常終了扱いにしていないことも確認する） |
| 7 | 7 | No.6実行後、`ps aux | grep ssh` 等でSSHトンネルのプロセスが残っていないことを確認する |
