# 01_要件定義

## 背景
- `Settings.secret_key` は必須項目で、`.env.example`・`docker-compose.yml`・CLAUDE.md も「SECRET_KEY で変える」前提だが、`app/` で参照している箇所がなかった
- 実際の JWT の署名・検証は、`app/core/security.py` の定数 `SECRET_KEY = "your-secret-key-change-in-production"` を使っていた。ソースが読める人は、誰でも、この鍵でトークンを作れる

## 機能要件
- JWT の署名・検証に、`get_settings().secret_key` を使う。ソースに、鍵を書かない
- `SECRET_KEY` を変えると、変える前に作った JWT は、検証に通らなくなる
- 以前直書きしていた鍵で署名した JWT は、受け付けない
- 使われていない `python-jose`（`app/` に `jose` の import がない。JWT は `PyJWT`）を、依存から外す
- `server/.env.example` を、`config.py` の全項目に合わせる（任意の項目は、コメントにして、説明を付ける）

## 非機能要件
- 既存のテスト（ユニット 772 件・結合）が、変更なしの意図で通る（テストが `security.SECRET_KEY` を import している箇所だけ、設定の値を使う形に直す）

## スコープ外
- 本番（ECS）への `SECRET_KEY` の注入の変更。`Settings` で必須のため、すでに渡されているはず（念のため確認事項として記録）
- 発行済みのトークンの移行（鍵が変わるので、利用者は、ログインし直しになる）
