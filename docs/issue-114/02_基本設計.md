# 02_基本設計

## 変更対象

- `backend/app/services/message_service.py`
- `backend/app/services/room_service.py`
- `backend/app/repositories/room_repository.py`

## API変更概要

| メソッド・パス | 変更前 | 変更後 |
|---|---|---|
| `GET /api/messages` | 所有者のみ閲覧可（404/403は所有権チェックの結果） | 所有者・テナント管理者・共有先グループメンバーが閲覧可 |
| `POST /api/messages/contents` | 対象メッセージが属する全ルームについて所有者チェック | 対象メッセージが属する全ルームについて閲覧権限チェック（所有者・管理者・共有先グループメンバー） |
| `GET /api/rooms/{roomId}` | 所有者のみ（非所有者は404） | 所有者・テナント管理者・共有先グループメンバーが閲覧可（存在しないルームのみ404、存在するが権限なしは403） |
| `GET /api/rooms` | 所有ルームのみ一覧表示 | 所有ルーム + 共有先グループに共有されたルームを一覧表示（固定順・更新日時降順は維持） |

書き込み系API（メッセージ送信・削除・フィードバック、ルーム更新・削除・固定・フィードバック）は変更なし。

## 影響範囲

- `message_service.py`: `get_messages_and_assistants`・`get_message_contents` の2メソッドのみ変更。書き込み系メソッド（`create_message`・`stream_message_content`・`delete_message`・`delete_message_by_content_id`・`feedback_message`）は無変更
- `room_service.py`: `get_room`・`list_rooms` の2メソッドのみ変更。書き込み系メソッド（`update_room`・`delete_room`・`pin_room`・`unpin_room`・`feedback_room`）が使う `_get_owned_room_or_404` は無変更のまま維持
- `room_repository.py`: `find_page_by_login_id`（`list_rooms`からのみ呼ばれていた）を、共有ルームも含めて取得する新メソッドに置き換える。所有者限定検索用の `find_by_id_and_login_id`（書き込み系で使用中）は変更しない
- 既存の `app/core/room_access.py`（`can_view_room`・`require_viewable_room`）は無変更で流用する
- ルーターファイル（`messages.py`・`rooms.py`）は関数シグネチャの変更なし（Service層のみの変更のため無修正）

## 移植方針

- 移植元 `RoomAccessService.canAccessRoom`（管理者バイパスあり版）相当のロジックは、issue-65で先行実装済みの `app/core/room_access.py` の `can_view_room`/`require_viewable_room` をそのまま再利用する（新規実装は行わない）
- `list_rooms`（一覧）のみ、単一ルーム判定である `can_view_room` をそのまま使えないため、`RoomRepository` に一覧取得用の新規メソッドを追加し、SQLレベルで「所有 or 共有先グループに含まれる」条件を組み込む（N+1を避けるため）
- 移植元の `canAccessRoomForShareLink`（管理者バイパスなし版）は、移植元自身でも未使用のロジックであるため移植しない
