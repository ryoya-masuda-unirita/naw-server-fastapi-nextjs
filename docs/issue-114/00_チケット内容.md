# #114 issue-114 共有リンク経由のグループメンバーによるメッセージ・ルーム閲覧系APIへのアクセス制御反映

## 概要

共有リンク（`shares`/`share_rooms`）を持つグループメンバーが、メッセージ・ルームの閲覧系APIにアクセスできるよう権限チェックを拡張する。

## 説明

issue-50（チャットルーム共有リンクAPI）実装時、既存のメッセージ送受信・ルーム管理APIは所有者限定の簡略化した権限モデルのままで、共有リンク経由のグループアクセス反映は「必要であれば別issueとして検討する」と将来課題化されていた。

### 現状

- 移植元: `~/Documents/naw-server/src/main/java/com/example/naw/service/RoomAccessService.java` に `canAccessRoomForShareLink`/`requireCanAccessRoom` があり、閲覧系（メッセージ一覧取得等）は共有リンク経由のグループメンバーにも許可している（`shareRoomRepository.existsSharedAccess`）。書き込み系（送信・削除）は所有者限定のまま
- FastAPI側: `backend/app/routers/messages.py` / `backend/app/services/room_service.py` に共有リンクベースのアクセス制御ロジックが存在せず、所有者限定のまま

### スコープ（想定）

- メッセージ・ルーム閲覧系API（一覧・詳細取得等）に `RoomAccessService.canAccessRoomForShareLink` 相当のロジックを移植し、共有リンクを持つグループメンバーが閲覧できるようにする
- 書き込み系（送信・削除等）は引き続き所有者限定のままとする
