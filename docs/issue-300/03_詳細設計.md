# 03_詳細設計

移植元はすべて `secuaigent-ref/generative-ai-adapter/`。命名は Java のクラス名を踏襲し、メソッドは snake_case、record は frozen dataclass、公開名は各パッケージの `__init__.py` から import できる。

### EmbeddingController.execute_embedding（分割と TSV）

1. `core.media` で入力ファイルをテキストにする（画像説明のモードが DISABLED 以外なら core の chat runtime を作って渡す）
2. テキストを `\n` で行に分ける（Java の `String.split` と同じ規則: 区切りなしは元の 1 要素、末尾の空要素は捨てる）
3. 行を足していき、`(sentence + line).length() > splitLength` になったら、それまでの `sentence` を 1 チャンクとして確定する（移植元どおり。先頭の行が分割文字数より長いと空のチャンクが 1 つできる挙動も同じ）
4. 出力モード 1・3 ならチャンクを `import_embedding`（ベクトルDB に追加）し、Graph 書き込みが有効ならチャンクごとに `write_graph_chunk`（連番と直前の行 ID を付ける）
5. TSV の 1 行 `"パス"<TAB>"本文（"は'に置換）"<TAB>"行 ID"<TAB>"ファイル ID"` を追記する。Graph Candidate のジョブ出力が有効なら最後までバッファし、拒否されたファイルは書かない

`App.before_execute` は textData（SecuAiGent）の上書き、拒否監査セッションとジョブ出力コンテキストの用意、コントローラーの作成、追記される出力ファイルの削除（出力モード 0・1・3）を行う。`after_execute` は Graph Candidate のジョブ結果マーカーと修復メトリクスを書き、ERROR なら失敗にする。

### 移植元から変えた点

| 点 | 内容と理由 |
|---|---|
| 削除のテナント ID | 移植元は `VectorDBSelectorService` に Graph candidate 用の接続設定だけを渡すため、Graph 書き込みが無効だとストアのテナント ID が空になり、削除（テナント必須）が必ず失敗する。`EmbeddingController` が、空のときだけ埋め込みの接続設定（プロパティ 3）のテナント ID で補う（`use_tenant_id_if_unset`）。Graph 書き込みが有効なら従来どおり |
| 取り込みのテナント | 移植元は `IngestionCoreMapper` が `tenant-default` に固定する。削除側はプロパティ 3 を使うため、Graph 書き込みを有効にする場合はプロパティ 3 を `tenant-default` にしないと GraphRAG 側の行が残る（実 DB で確認した。08）。移植元どおりにしてある |
| Echo 埋め込み（VENDOR=99） | Python 版だけ。キーなしで DB への書き込みを確認するため |
| `Embedding(content, vector)` の 2 引数コンストラクタ | dataclass のため `Embedding(content=..., vector=...)` |
| `getEmbeddingModel()`（Spring AI の型を返す） | 返す型がないため移植しない |
| `InsecureSSLConfig` | core の `CoreNetworkSetting.insecure_ssl_enabled`（プロパティ 10）が担う |
| JDBC | psycopg 3（自動コミット）。Java は 1 文ごとに接続を開く |
| Spring AI・Azure SDK・RestClient・Gson | httpx と標準の `json`。リトライ等の SDK 内部の挙動は再現しない |
| Gson の寛容な JSON 解析 | 再現しない（拒否コードと拒否される入力は同じ） |
| AGE の `cypher()` の引数 | 型キャスト（`::agtype`）なしの文字列で渡す（AGE の要求。実 DB で確認） |
| PowerPoint のスライド描画（FULL_PAGE） | Java は POI の `Graphics2D` で描画する。Python に同等の手段がなく `RENDERING_FAILURE`。DISABLED / EMBED_ONLY は移植元どおり |
| Excel の日付セル | Java の `Date#toString()` と同じ書式。タイムゾーン名はプロセスのもの |
| Excel の画像の部品名 | openpyxl は部品名を持たないため読み込み順に `/xl/media/image{n}.{拡張子}` |
| 移植しなかったテスト | 実 DB・実 API が要る `*IT`・`*LiveIT`・`S05SqlCorrectnessLiveDbIT`、`GraphRagVNextG1G2GateIT`（実 DB で代替確認）、Spring のコンテキストを見るテスト、Java 固有の依存関係ガード（`*DependencyTest`・`Slice5ScopeGuardTest` など） |

## 3. エミュレーター（`waha_emulator`）

### 設定（`workflow_config.py`）

定義に `adapter`（`generative-ai`（既定）/ `embedding`）を足した。`embedding` の定義:

| キー | 内容 |
|---|---|
| `operation` | `learn` / `delete` / `sync`（必須） |
| `outputType` | `learn` のときだけ。`3`（新規登録。既定）か `1`（追加登録）。`delete` は 2 に固定 |
| `defaultSplitLength` | `learn` で `splitLength` が空のときの分割文字数。既定 1000 |
| `properties` | 埋め込みアダプタのプロパティ名 → 値。`VENDOR`・`VDB_VENDOR` は名前でも ID でもよい。`${環境変数}` 展開と `validate_property` の検証は #298 と同じ |

`default` は `generative-ai` の定義でなければならない（登録のないサービス ID と、チャットの既定のため）。`ragContextJson` は埋め込みでは使えない。

学習の出力モードの既定を 3 にした理由: モード 1（追加登録）はテーブルを作らず、最初の学習でテーブルがないと失敗する。モード 3 は `CREATE TABLE IF NOT EXISTS` で、あっても消さずに追記する（移植元の `is_new_creation` はスキーマ作成の指示）。

### ワークフロー（`workflows/embedding.py`）

`EmbeddingWorkflow.run` は同期のアダプタを `asyncio.to_thread` で動かす。

- **learn**: `file` スロットのファイルをジョブの一時ディレクトリに置く（なければ `filepath` のパスを `SOURCE_ALLOWED_DIR` の中でだけ読む）。列 [ID=空、入力ファイル、分割文字数] で `write` し、アダプタの TSV から行 ID が空でない行を取り、`"ファイル ID"<TAB>"パート ID"` を CRLF 区切りで返す（server-local が CRLF で分けるため）。1 行もなければ失敗（取り込みが拒否された）。アップロードの場合は DB の `filepath` を `<filepath>/<ファイル名>` に更新する
- **delete**: `file` スロットの各行（パート ID）を `SELECT id::text, fileid FROM <table> WHERE id::text = ANY(%s)` でファイル ID にし（当たらない行はファイル ID とみなす）、重複を除いて列 [ID=ファイル ID] で出力モード 2 の `write`。事前に GraphRAG のスキーマを `create_if_missing` で用意する（移植元の削除は常に `graphrag_s02` を参照するが、作るのは Graph 有効の取り込みだけのため）
- **sync**: PostgreSQL のとき `SELECT COALESCE(filepath,''), id::text, fileid FROM <table> ORDER BY fileid, id OFFSET start LIMIT end-start` を読み、`"パス"<TAB>"パート ID"<TAB>"ファイル ID"` を CRLF 区切りで返す
- テーブル名は識別子として検証してから SQL に埋め込む。`VDB_VENDOR` が PostgreSQL(PGVector) 以外の削除・同期は失敗にする
- ログ（INFO）: `workflow embedding: serviceId, operation, 要約（接続先・キーは出さない）, params名` → アダプタ・core の各部品のログ → `learn finished` / `delete` / `sync`

### Docker

`waha-emulator/Dockerfile` と `Dockerfile.dockerignore` に `generative-ai-adapter/embedding-adapter/` を足した。`docker-compose.yml` に `SOURCE_ALLOWED_DIR` を渡す。
