# 01_要件定義

## 目的

server-local の学習（ファイル追加）・学習データの削除・学習データの同期を、Waha! の代わりのエミュレーターが**本物の埋め込みアダプタ**で処理できるようにする。#274 では未対応の失敗だった 3 つが、PostgreSQL + pgvector へ実際に書き込む。

## 機能要件

| # | 要件 |
|---|---|
| F1 | 移植元 `embedding-adapter`（App・EmbeddingController・domain・service・audit・output・rollback・AzureAISearch）を Python に移植し、`generative-ai-adapter/embedding-adapter/` に置く |
| F2 | core に embedding（OpenAI・Azure OpenAI・SecuAiGent の埋め込み）を移植する |
| F3 | core に vector（pgvector・Azure AI Search への保存・更新・削除・検索、スキーマ作成、AGE グラフ書き込み、補償削除）を移植する |
| F4 | core に Graph Candidate の取り込み（graphrag の ingestion・ingestion.llm・bootstrap）を移植する |
| F5 | core のファイル前処理に PDF・Word・Excel・PowerPoint を足す（Text・画像は #298 で済み） |
| F6 | エミュレーターのワークフロー設定（サービス ID → 定義）に、埋め込みアダプタの定義（学習・削除・同期）を足す |
| F7 | 学習: 出力は `"ファイル ID"<TAB>"パート ID"`。削除: パート ID を受けてベクトルDB から消す。同期: `"パス"<TAB>"パート ID"<TAB>"ファイル ID"` |
| F8 | 同期の取り込み元は、移植元に根拠のある範囲（`filepath` で渡されたパスと、アダプタがベクトルDB に書いた行）に限る |
| F9 | 学習・削除・同期の流れをワークフローのログ（INFO）で追える |

## 非機能要件

- 自動テストは実際の DB・Azure に接続しない（DB は偽の接続、HTTP は respx）
- Docker のビルドにアダプタを含める（エミュレーターのイメージ）
- 既存のテスト（core・生成AIアダプタ・エミュレーター・server-local）が通り続ける
- docstring は NumPy 形式

## 対象外

- 検索アダプタ（retrieval。#299）、検索側の graphrag・embedding の使用（`CoreQueryEmbeddingGenerator` など）
- 本物の Waha!・本物の Azure OpenAI への接続の確認
- 同期でファイルサーバーなどの外部を探索すること（移植元に根拠がない）
- server-local・backend・frontend の変更
