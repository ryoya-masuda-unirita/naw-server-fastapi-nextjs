# 04_テスト設計

## 方針

- 実際の DB・Azure・OpenAI には接続しない。DB は偽の接続（`ConnectionFactory` / 接続を受け取る引数）、HTTP は `respx`、ベクトルDB はメモリ上の偽物に差し替える
- 移植元の Java のテスト（`src/test`）のうち今回の範囲に当たるものを Python に移し、各テストファイルの先頭に「どの Java のテストを移したか」を書く。Spring の内部を見るテストは、送信する HTTP リクエストや SQL を見るテストに置き換える
- 実 DB での確認は自動テストに含めず、`onprem/vector-db` のイメージで手元確認して 08 に貼る
- テスト名は英語、docstring は日本語 1 行

## 観点

| 層 | 観点 |
|---|---|
| core embedding | リクエスト Builder、結果の成功 / 失敗、プロバイダ（OpenAI・Azure・SecuAiGent・Echo）の送信リクエストと応答の解釈、失敗の伏せ字、空 / 不正ベクトル、リソース名の導出（予約語・長さ・ハッシュ） |
| core vector | 各操作（SAVE・UPDATE・DELETE・SEARCH・GRAPH_WRITE・GRAPH_DELETE）の SQL と引数、テナント必須、スキーマ作成、Azure Search のリクエスト、補償削除の層ごとの結果 |
| core graphrag | 取り込みの許可 / 拒否、決定的な抽出、LLM 候補 JSON の検証（禁止キー・修復用 JSON）、版の置き換え・削除、bootstrap の準備 / 検証 |
| core media | PDF・Word・Excel・PowerPoint のテキスト / 画像抽出、モード別の挙動、失敗コード（暗号化・破損・空） |
| 埋め込みアダプタ | `validate_property` の各 case、`set_property` の対応、実行時チェック（Graph は PostgreSQL のみ、SecuAiGent の必須項目）、列の振り分け、`before_execute` の出力ファイル削除、分割（Java の `split` 規則）、TSV の書式、ベクトルDB の追加 / 削除、Graph の連鎖、拒否ファイルの TSV 抑止、audit・output・rollback、ドメイン |
| エミュレーター | 設定の検証（operation・outputType・プロパティ名・default）、学習（アップロード / filepath の許可 / 既定の分割文字数 / 不正値 / 登録 0 件）、削除（パート ID → ファイル ID）、同期（ページング / PostgreSQL 以外）、server-local の `WahaClient` と TSV 読み取りを通した結合、設定例のサンプル |
