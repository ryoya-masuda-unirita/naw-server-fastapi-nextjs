### 確認で分かった、移植元どおりの挙動

- **削除はテナント ID が必須**: Graph 書き込みが無効だと、移植元はテナント ID をストアに渡さず `tenant metadata is required for graph rag chunk cleanup` で必ず失敗する。埋め込みの接続設定のテナント ID で補うようにした（03 の「移植元から変えた点」）
- **削除は GraphRAG のスキーマが必要**: スキーマがないデータベースでは次のように失敗する。移植元はスキーマを Graph 書き込みが有効な取り込みでしか作らない。エミュレーターの削除ワークフローは事前に作る

```
RuntimeError: relation "graphrag_s02.answer_claim_evidence" does not exist
LINE 1: delete from graphrag_s02.answer_claim_evidence where tenant_...
```

GraphRAG のスキーマ（`graphrag_s01`・`graphrag_s02`・AGE グラフ）を自動で作り、ジョブ結果マーカー（`graph-candidate-job-outcome.tsv`）が出力された。

テナント ID が `tenant-default` でないと、削除後も GraphRAG 側の行が 1 件残った（取り込みのテナントが移植元で `tenant-default` に固定されているため。03 に記載）。
