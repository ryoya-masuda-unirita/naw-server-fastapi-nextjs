# 01_要件定義

## 背景

移植元（naw-server, Spring Boot）には、チャットルームを特定のグループに共有するための共有リンク機能が存在する。
共有リンクを発行すると、対象グループに所属するメンバーがそのルームを閲覧できるようになる。

このリポジトリではこれまで（#45 チャットルーム管理API、#48 メッセージ送受信API）、ルームへのアクセスを
「所有者本人のみ」に簡略化して実装してきた。本issueでは、共有リンクの発行・アクセス解決・削除のAPIを実装するとともに、
共有リンクを経由したグループメンバーのルームアクセス可否判定を新たに実装する。

## 機能要件

- ルーム所有者は、自分が所有するルームに対して共有リンクを発行できる。共有先はグループ（複数可）で指定する
- 同じルームに対して共有リンクを再度発行すると、既存の共有リンクを更新する（共有先グループの入れ替え）。1ルームにつき共有リンクは常に1件
- 共有リンクIDを指定してアクセス解決を行うと、対象ルームのID・ルーム名・閲覧専用かどうか・共有先グループID一覧が取得できる
- アクセス解決は、ルーム所有者本人、または共有先グループに所属するメンバーが行える
- 「閲覧専用かどうか」は、ルーム所有者本人であれば false、共有先グループ経由のアクセスであれば true とする
- ルーム所有者は、自分が発行した共有リンクを削除できる
- いずれの操作もテナント分離を前提とする

## 非機能要件

- 共有先グループは、リクエスト時点でテナント内に実在するグループIDのみ許可する
- 既存の移植済みAPI（アシスタント管理・チャットルーム管理等）の方針に合わせたレスポンス形式・エラーハンドリングとする

## スコープ外

- 共有リンクを経由したグループメンバーによる、メッセージ送受信API（#48）でのルーム閲覧・書き込みへの反映は本issueでは行わない（`_require_owned_room`は所有者のみ許可のまま据え置く）。必要であれば別issueで対応する
- ルーム一覧取得API（#45）に、共有されたルームを含める対応は本issueでは行わない
- テナント管理者による共有ルームの閲覧バイパス（移植元の`RoomAccessService`のadminバイパス）は、共有リンクのアクセス解決では移植元でも適用されない仕様のため、本issueでも対象外
