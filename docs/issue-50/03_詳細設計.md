# 03_詳細設計

## 対象テーブル・カラム定義

移植元の Liquibase changelog（`shares` / `share_rooms`）の最終状態を再現する。

### `shares`

| カラム | 型 | 制約 |
|---|---|---|
| id | varchar(32) | PK |
| tenant_id | varchar(32) | NOT NULL, FK→tenants.id (CASCADE) |
| room_id | varchar(32) | NOT NULL, UNIQUE, FK→(rooms.id, rooms.tenant_id) (CASCADE) |
| created_at | timestamptz | NOT NULL, default now() |
| updated_at | timestamptz | NOT NULL, default now() |

移植元には過去`permissions`カラム（グループIDのCSV文字列）が存在したが、`share_rooms`への移行後に削除されているため、
本issueでは最初から`share_rooms`のみで実装する（`permissions`カラムは作らない）。

### `share_rooms`

| カラム | 型 | 制約 |
|---|---|---|
| id | uuid | PK, default `gen_random_uuid()` |
| tenant_id | varchar(32) | NOT NULL, FK→tenants.id (CASCADE) |
| share_id | varchar(32) | NOT NULL, FK→shares.id (CASCADE) |
| room_id | varchar(32) | NOT NULL, FK→rooms.id (CASCADE)（単一カラムFK。移植元同様`shares`経由で辿るため複合FKにしない） |
| group_id | varchar(32) | NOT NULL, FK→groups.id (CASCADE) |
| created_at | timestamptz | NOT NULL, default now() |

UNIQUE制約: `(share_id, group_id)`。

RLSは既存の方針（#48で確認済み、このリポジトリは現時点でRLS未導入）に合わせ、アプリケーション層の`tenant_id`条件で分離する。

## 実装対象ファイル

### マイグレーション

- `backend/alembic/versions/013_add_shares.py`
  - `shares` / `share_rooms` の2テーブルを作成

### モデル

- `backend/app/models/share.py`
  - `Share`（SQLModel, table=True）
  - `ShareRoom`

### スキーマ

- `backend/app/schemas/share.py`
  - `ShareCreateRequest`（`roomId`, `teamIds`）
  - `ShareDataResponse`（`id`, `roomId`, `teamIds`）
  - `ShareAccessDataResponse`（`roomId`, `roomName`, `isReadOnly`, `teamIds`）

### リポジトリ

- `backend/app/repositories/share_repository.py`
  - `find_by_room_id`：ルームIDから既存の共有リンクを取得（upsert用）
  - `find_by_id_and_tenant_id`：共有リンクIDから取得（アクセス解決・削除用）
  - `delete`：共有リンクを削除
- `backend/app/repositories/share_room_repository.py`
  - `find_group_ids_by_share_id`：共有リンクIDに紐づく共有先グループID一覧を取得
  - `replace_groups_for_share`：既存の共有先グループを全削除し、指定グループ集合で置き換える（`GroupPromptTemplateRepository.replace_groups_for_template`と同じパターン）
  - `exists_shared_access`：指定ルームが、指定グループ集合のいずれかに共有されているかを判定（1クエリ、JOIN）

### サービス

- `backend/app/services/share_service.py`
  - `upsert`：ルーム所有権チェック→共有先グループの実在チェック→共有リンクのupsert→共有先グループの置き換え
  - `resolve_access`：共有リンク存在チェック→アクセス可否判定（所有者 または 共有先グループ所属）→`isReadOnly`（所有者なら`false`）を算出して返す
  - `delete`：共有リンク存在チェック→ルーム所有権チェック→削除

### ルーター

- `backend/app/routers/shares.py`（`prefix="/api/shares"`）

### `main.py`

- `backend/app/main.py` に `shares.router` を追加登録

## 移植元との差分（意図的な仕様変更）

- レスポンスの`{"data": {...}}`ラッパーを廃止し、レスポンスモデルを直接返す
- テナント管理者による閲覧バイパスは実装しない（移植元の共有アクセス解決でも未適用のため差分ではなく踏襲）
