# 02_基本設計

## 変更対象

- グループAPI
- グループサービス
- グループ×アシスタント中間テーブルリポジトリ
- グループ関連リクエストスキーマ
- アシスタント一覧レスポンススキーマ
- グループAPIの統合テスト

## 画面 / API 変更概要

以下の管理者向けAPIを追加する。

| メソッド | パス | レスポンス |
|---|---|---|
| GET | `/api/admin/groups/{group_id}/assistants` | `content` / `totalElements` / `number` / `size` |
| POST | `/api/admin/groups/{group_id}/assistants` | 204 No Content |
| DELETE | `/api/admin/groups/{group_id}/assistants/{assistant_id}` | 204 No Content |

一覧取得は、既存のアシスタント一覧レスポンスを再利用しつつ、グループ紐付け日時を `addedAt` として返す。

## 影響範囲

- 既存の `AssistantGetResponse` に任意の `addedAt` が追加される
- グループAPIに新しいルートが増える
- グループ×アシスタントリポジトリにグループ起点のCRUD・ページング取得が追加される
- 既存のアシスタント一覧・グループ×プロンプトテンプレートAPIの挙動は変更しない

## 移植方針

- 追加・削除・権限確認は既存のグループ×プロンプトテンプレート実装の構造を踏襲する
- アシスタント存在確認は `AssistantRepository.find_by_ids_and_tenant_id` / `find_by_id_and_tenant_id` を使う
- 一覧取得は `GroupAssistant` と `Assistant` をJOINし、検索・種別・カテゴリ条件を SQLAlchemy で組み立てる
- `categoryId="NONE"` はカテゴリ未設定アシスタントのみを返す
- `addedAt` は `GroupAssistant.updated_at` を設定する
- エンドポイント・グループ・カテゴリの付加情報は既存 `AssistantService._build_responses` を活用する
