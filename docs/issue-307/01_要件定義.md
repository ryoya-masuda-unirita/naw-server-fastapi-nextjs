# 01_要件定義

## 背景

移植元（Spring Boot）は、ライブラリのメタデータ（タイトル・作成者など）と本文を別のテーブルに分けている。本文を持たない「スタブ」のライブラリを先に作り、本文は SaaS 側（NAW 本体）か、オンプレのローカルサーバー（server-local）のどちらかに置く設計である。

- NAW 本体で生成したライブラリ: メタデータと本文を同時に保存する
- ローカルサーバーで生成したライブラリ: ローカルサーバーが NAW 本体にスタブ（タイトルなし）を作らせ、生成が終わったらタイトルだけを NAW 本体に送る。本文はローカルサーバーにだけ置く

backend は本文をライブラリの列に持ち、タイトルを必須にしているため、スタブを作れない。またスタブ作成・タイトル更新の API が無く、server-local から呼べない。ライブラリ詳細の応答も、移植元（本文の取得先を決めるためのアシスタント情報と、NAW 本体に本文があるかのフラグ）と違う。

## 機能要件

### データ

- ライブラリの本文を本文専用のテーブルに分ける（ライブラリ 1 件に本文 0〜1 件。ライブラリを消すと本文も消える）
- ライブラリのタイトルを空（NULL）にできるようにする
- 既存のライブラリの本文を本文テーブルへ移す。本文が無い（NULL の）ライブラリは本文テーブルに行を作らない
- 移行を戻せるようにする（本文をライブラリの列に戻し、本文テーブルを消す）

### API（移植元どおりにする）

| API | 変更内容 |
|---|---|
| ライブラリ一覧（ページ） | タイトルが NULL のライブラリ（スタブ）を含めない |
| ルームのライブラリ一覧 | タイトルが NULL のライブラリを含めない |
| ライブラリ詳細 | 応答を `id`・`title`・`messageId`・`userId`・`createdAt`・`updatedAt`・`assistant`・`hasNawContent` にする。`assistant` は紐づくメッセージのアシスタント（種別・履歴を含めるか・モデル・エンドポイント）、`hasNawContent` は NAW 本体に本文があるか |
| ライブラリ本文取得 | 本文テーブルから読む。本文が無ければ 404（従来どおり） |
| ライブラリ更新（名前・共有グループ・タグ） | タイトルの更新先が変わらないことを確認する（本文には触れない） |
| ライブラリ削除 | 本文も一緒に消える |
| スタブ作成（新規） | メッセージ ID を受け取り、タイトル・本文の無いライブラリを作って ID を返す |
| タイトル更新（新規） | タイトルだけを更新して ID を返す |

### LLM チャットのライブラリ生成

- メッセージ送信（ライブラリ生成モード）・LLM チャット（ライブラリ生成）で、ライブラリと本文を同じトランザクションで保存する

## 非機能要件

- 本文テーブルの列・制約名は移植元の Liquibase に合わせる
- RLS（行レベルセキュリティ）のポリシーは作らない。backend の既存マイグレーションはどのテーブルにも RLS を作っていないため、それに合わせる

## スコープ外

- server-local 側のコード（呼び出し側は既に移植元どおりの API を前提にしている）
- メッセージ一覧 API のアシスタント応答に `includeHistory`・`model` が無い差分（メッセージ API の範囲。後続に申し送る）
- ルームの書き込み権限エラーの文言（backend 共通の `Room not found`・`Access Denied` を使う。既存の更新・削除と同じ）
- React 画面からの利用（React はまだライブラリ詳細を使っていない）
