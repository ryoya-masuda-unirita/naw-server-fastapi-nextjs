# 02_基本設計

## 変更対象

- ライブラリのモデル（本文の列を削除・タイトルを任意に）と、本文のモデル（新規）
- マイグレーション（本文テーブルの作成・既存データの移行・列の削除。戻す処理も）
- ライブラリのリポジトリ（スタブを一覧から除く・ライブラリと本文をまとめて保存）
- 本文のリポジトリ（新規。本文の取得・有無の確認）
- アシスタントのエンドポイントのリポジトリ（ライブラリ詳細のアシスタント応答用の取得を追加）
- ライブラリのサービス・ルーター・スキーマ（詳細の応答、スタブ作成、タイトル更新）
- メッセージのサービス・LLM チャットのサービス（ライブラリ生成の保存先）
- 単体テスト・結合テスト（マイグレーションの結合テストを含む）

## 画面 / API 変更概要

| メソッド・パス | 変更前 | 変更後 |
|---|---|---|
| `GET /api/libraries` | 全件 | タイトルが NULL のものを除く |
| `GET /api/libraries/{roomId}/list` | 全件 | タイトルが NULL のものを除く |
| `GET /api/libraries/{id}` | `{title, data}`（本文） | `{id, title, messageId, userId, createdAt, updatedAt, assistant, hasNawContent}` |
| `GET /api/libraries/{id}/content` | ライブラリの列から読む | 本文テーブルから読む |
| `POST /api/libraries` | なし | スタブ作成。`{messageId}` → 200 `{data: {id}}` |
| `PATCH /api/libraries/{id}/title` | なし | タイトル更新。`{title}` → 200 `{data: {id}}` |
| `PUT /api/libraries/{id}`・`DELETE /api/libraries/{id}` | — | 応答は変わらない。削除で本文も消える |

### 入力チェック（移植元の Request の注釈どおり）

- スタブ作成の `messageId`: 必須・空白不可（`メッセージIDは必須です`）
- タイトル更新の `title`: 必須・空白不可（`ライブラリ名は必須です`）・255 文字以内（`ライブラリ名は255文字以内で入力してください`）

### エラー（移植元どおり）

- スタブ作成: メッセージが無い → 404 `Message not found`。ルームが無い → 404、ルームの所有者でない → 403
- タイトル更新: ライブラリが無い・ID の形式が不正・紐づくメッセージが無い → 404 `Library not found`。所有者でない → 403

## 影響範囲

- server-local（`NawApiClient`）は、スタブ作成の応答の `data.id` と、タイトル更新の成功だけを見る。今回の API で動くようになる
- 移植元クライアントは詳細の `assistant` で本文の取得先（NAW 本体かローカルサーバーか）を決め、NAW 本体なら本文取得 API を呼ぶ
- 既存の DB: マイグレーションで本文を移す。戻すと、タイトルが NULL のスタブは既定のタイトル `ライブラリ` を入れて残す（戻した後のスキーマはタイトル必須のため）

## 移植方針

- 移植元の調査結果
  - 本文のエンティティ: 主キーはライブラリ ID、テナント ID・本文（必須）・作成日時・更新日時
  - Liquibase: 本文テーブルの作成（ライブラリ・テナントへの外部キーはどちらも削除時に連動削除）→ 本文が NULL でない行だけ移行し件数を確かめる → RLS → ライブラリのタイトルの NOT NULL を外し本文の列を削除
  - サービス: 一覧・ルーム一覧はタイトルが NULL のものを除く。詳細はアシスタントと本文の有無を返す。本文取得は本文テーブルから読み、無ければ 404。スタブ作成はタイトル NULL で作る。タイトル更新・更新・削除はルームの書き込み権限を確認する
  - メッセージのサービスのライブラリ保存: ライブラリと本文を同じ（新しい）トランザクションで保存する
  - LLM チャットのサービス: 移植元の最新版はライブラリを保存しない（backend は既存の実装で保存している）。保存する場合は本文テーブルにも書く形に揃える（保存をやめるかどうかはこの Issue の範囲外）
- マイグレーションは移植元の 4 つの changeset を 1 つにまとめる。件数の確認は移植元と同じく、移行元と移行先の件数が違えば失敗させる
- タイトル NULL の扱い: 一覧・ルーム一覧から除くのは移植元どおり。詳細・本文取得はタイトル NULL でも返す（移植元どおり）
