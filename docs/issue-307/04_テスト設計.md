# 04_テスト設計

## テスト方針

サービスの判定は単体テスト（リポジトリをモック）、DB を含む API の挙動とマイグレーションは結合テストで確かめる。マイグレーションは PostgreSQL を使わず、インメモリ SQLite に移行前のテーブルを作ってマイグレーションの処理を実行する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | マイグレーション upgrade | 本文ありのライブラリ・本文 NULL のライブラリがある | 本文ありだけ本文テーブルに移り、作成日時・更新日時・テナントも移る。ライブラリの本文の列は無くなり、タイトルが NULL にできる |
| 2 | マイグレーション downgrade | 本文ありのライブラリ・本文なしのライブラリ・タイトル NULL のスタブがある | 本文がライブラリの列に戻り、本文なしは NULL、スタブのタイトルは `ライブラリ`。本文テーブルは消える |
| 3 | マイグレーション往復 | upgrade → downgrade | 本文・タイトルが移行前と同じ |
| 4 | 一覧（ページ） | スタブ（タイトル NULL）がある | スタブを含めない |
| 5 | ルームの一覧 | スタブがある | スタブを含めない |
| 6 | 詳細 | NAW 本体で生成（本文あり）・アシスタントあり | 移植元の項目がそろい、`hasNawContent` が true、`assistant` に種別・履歴・モデル・エンドポイントが入る |
| 7 | 詳細 | スタブ（タイトル NULL・本文なし） | `title` が null、`hasNawContent` が false |
| 8 | 詳細 | メッセージにアシスタントが無い | `assistant` が null |
| 9 | 詳細の API キー | SECURE かつ LOCAL_SERVER | `apiKey` に値が入り、それ以外は空文字 |
| 10 | 本文取得 | 本文あり / 本文なし | 本文を返す / 404 `Library content not found` |
| 11 | スタブ作成 | 自分のルームのメッセージ | 200 で ID を返し、タイトル NULL・本文なしのライブラリができる |
| 12 | スタブ作成 | メッセージが無い / 他人のルーム / `messageId` が空・空白・欠落 | 404 `Message not found` / 403 / 400 `メッセージIDは必須です` |
| 13 | タイトル更新 | 自分のライブラリ（スタブ） | 200 で ID を返し、タイトルが変わり、一覧に出るようになる |
| 14 | タイトル更新 | ライブラリが無い / 他人のライブラリ / タイトルが空白・256 文字 | 404 / 403 / 400（移植元の文言） |
| 15 | 削除 | 本文あり | 本文も消える |
| 16 | 更新（名前・共有・タグ） | 本文あり | 本文はそのまま |
| 17 | ライブラリ生成（メッセージ送信） | ライブラリ生成モード | ライブラリと本文をまとめて保存する |
| 18 | ライブラリ生成（LLM チャット） | ライブラリ生成モード | ライブラリと本文をまとめて保存する |
| 19 | まとめて保存 | ライブラリと本文 | 両方のテーブルに 1 回の保存で入る |
