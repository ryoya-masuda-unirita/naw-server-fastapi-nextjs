## モデル

`user_import_jobs` テーブルを追加する。

- `id`: 32文字文字列、主キー
- `tenant_id`: テナントID
- `status`: `PENDING` / `PROCESSING` / `COMPLETED` / `FAILED`
- `file_name`
- `storage_url`
- `error_details`
- `created_at`, `updated_at`, `queued_at`, `completed_at`

同期縮小版では `storage_url` と `queued_at` は通常 `null` とする。

## CSV処理

- 拡張子 `.csv` のみ許可
- 必須カラム: `login_id`, `name`, `password`, `role`
- 任意カラム: `createLoginKey`, `groupIds`
- 最大100行
- `role` は `USER`, `ADMIN`, `SYSTEM`
- `createLoginKey` は `true` / `false`
- `groupIds` はカンマ区切り。存在しないグループIDは行エラーとして記録する

## ユーザー処理

- 既存ユーザー: `name`, `role`, `login_key` を更新し、パスワードは変更しない
- 新規ユーザー: `users` と `password_histories` を追加する
- グループ所属: 対象ユーザーの既存所属を削除してCSV指定で再登録する

## エラー処理

- CSV形式・必須項目など事前バリデーションで失敗した場合は、ジョブを `FAILED` として保存して `jobId/status` を返す
- 行単位の処理エラーは `error_details` に蓄積し、処理全体は `COMPLETED` とする
- ジョブ取得時にテナント不一致または存在しない場合は404とする
