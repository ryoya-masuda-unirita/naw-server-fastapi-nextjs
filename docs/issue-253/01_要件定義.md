# 01_要件定義

## 背景

server-local（移植元: Spring Boot 3.2.3 の `secuaigent-server-local`）の再レビューで、移植元と挙動が異なる点と不具合が 15 項目見つかった。各項目を移植元のコード・設定で確かめ、移植元に揃える。移植元と同じにすると不都合があるものは、理由を書いて意図的に変える。

## 機能要件

| No | 要件 | 移植元の根拠 |
|---|---|---|
| 1 | multipart のリクエスト全体が 215MB を超えたら 413 にする。サイズが分かっていれば受信前に、分からなければ受信中に超えた時点で返す。multipart 以外には上限をかけない | `application.yml` の `spring.servlet.multipart.max-request-size: 215MB` |
| 2 | 想定外のエラーの 500 にも CORS ヘッダーを付ける | `SecurityConfig` の `.cors(...)`（Spring Security のフィルターで CORS を付けるため、エラー応答にも付く） |
| 3 | 学習ファイル一覧の `status=`（空文字）は未指定として扱う | `IndexController.listFiles` の `@RequestParam(required = false) File.Status status`（Spring は空文字の列挙型を null に変換） |
| 4 | NAW 互換の SSE で、ストリームファイルの空の `data:` は無視する | `MessageContentStreamService.handleStreamChunk` の `objectMapper.readTree(payload)`（空文字は MissingNode になり、type が空で転送も終端判定もされない） |
| 5 | 学習ファイルの登録・更新・追加学習の multipart の文字列項目は、空文字を空文字のまま受け取る（PATCH の `displayName=` で表示名を空にできる） | `@ModelAttribute`（空文字をそのまま束縛）と `FileService.updateFile` の `if (fileDisplayName != null)` |
| 6 | SSE の確定処理（outputfile の取得・解析）が失敗したとき、error イベントを送り ERROR で保存することをテストで確かめる | `MessageContentStreamService` の確定処理の `catch` |
| 7 | 質問 API（`/content`・`/content/sync`・`/content/stream`）に multipart 以外が来たら 415 にする | `MessageController` の `consumes = {"multipart/form-data"}` |
| 8 | textData が UTF-8 として不正なら 400 にする | `@RequestPart` の JSON 解析（Jackson の解析エラー → HttpMessageNotReadableException → 400） |
| 9 | 履歴（`historyMessages[]`）の `type` は省略でき、省略したら Waha! に渡す `role` を null にする | `CreateMessageContentRequestDTO.HistoryMessageContent`（record。省略は null）、`MessageHistoryContent(m.type(), m.content())` |
| 10 | ストリームファイルの読み取りでイベントループを止めない | なし（Python の非同期処理の都合） |
| 11 | ストリームファイルの定期掃除で想定外の例外が起きても、次の回も実行し、アプリの終了処理を妨げない | `StreamFileCleanupScheduler` の `@Scheduled`（例外はログに出され、次の回も実行される） |
| 12 | 学習ファイルの `name` / `userId` が未指定（None）なら登録しない。`userId` は新しくファイルを作るときだけ | `files` の `name`・`user_id` の NOT NULL 制約（未指定だと保存時に失敗する）。`user_id` は `updatable=false` のため、既存のファイルの更新では未指定でも失敗しない |
| 13 | `file_parts.file_id` にインデックスを付ける | H2 は外部キーの列に自動でインデックスを作る（SQLite は作らない） |
| 14 | マイグレーション（alembic）もアプリと同じく `.env` の `DATABASE_URL` を使う | なし（移植元は Liquibase をアプリの起動時に実行するため、常にアプリと同じ DB） |
| 15 | `LOG_LEVEL=WARN` でもコンテナが起動する（code-review 対応で、移植元の他のレベル名 `TRACE`・`FATAL`・`OFF` も） | `logging.level.root`（Spring は `WARN` などと書く） |

## 非機能要件

- 各項目の挙動を自動テストで確かめ、修正前のコードで失敗することを確認する（No.10 は既存の SSE のテストで動作を確認する）
- `docker-entrypoint.sh` を変えるため、Docker でイメージを作り、`LOG_LEVEL=WARN` でコンテナが起動することを確かめる

## スコープ外

- 項目のうち対象外にしたものはない（15 項目すべて対応する）
- 移植元と意図的に変える点（No.12 の 400、No.10・14 の Python 側の都合）は `02_基本設計.md` と README に理由を書く
