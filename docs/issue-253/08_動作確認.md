# 08_動作確認

**ブラウザ・実機での確認は行わず、自動テストで代替した。** Waha! は偽物（`FakeWahaClient`）、DB はテストごとの一時ファイルの SQLite を使う。`docker-entrypoint.sh` を変えたため、Docker でのビルドと `LOG_LEVEL=WARN` での起動だけは実際に確かめた（使い捨てのコンテナで、共有の Postgres・Redis・backend には触れていない）。

## 確認環境

- ブランチ: `feature/issue-253`（`origin/develop` から作成）
- `server-local/`（Python 3.12、uv、pytest + pytest-asyncio、SQLite + aiosqlite）
- Docker 29.8.2

## 確認手順

```bash
cd server-local
uv sync
uv run pytest tests/test_app_middleware.py tests/test_indexes_request_values.py \
  tests/test_message_request_and_finalize.py tests/test_docker_entrypoint.py \
  tests/test_migrations.py tests/test_message_content_sync.py::test_sync_requires_multipart -v
uv run pytest -q
uv run ruff check . && uv run ruff format --check .
uv run --with mypy mypy app tests   # server-local は mypy を依存に持たないため一時的に入れて実行
```

修正前の再現は、`app`・`alembic`・`docker-entrypoint.sh` の変更を `git stash push -u -m <tag> -- app alembic docker-entrypoint.sh` で一時的に退避して新しいテストを実行し、確認後に SHA 指定の `git stash apply` で戻した。Docker は `05_テスト詳細設計.md` の手順で確認した。
