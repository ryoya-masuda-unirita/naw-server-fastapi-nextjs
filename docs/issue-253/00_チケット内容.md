# #253 issue-253 server-localの移植元との差分と不具合をまとめて直す

## 概要

`server-local/`（#210、PR #222）の再レビューで見つかった、移植元との差分と不具合をまとめて直す。根拠はいずれも `secuaigent-server-local/` の移植元コード。

## 説明

### 🟡

1. アップロードにリクエスト全体のサイズ上限がない（`routers/indexes.py`・`routers/messages.py`）。移植元は `max-request-size: 215MB` で、受信中に超えた時点で 413
2. 500 の応答に CORS ヘッダーが付かない（汎用の例外ハンドラーが CORS ミドルウェアの外側で動く）。移植元の挙動を確認して揃える
3. 一覧の `status=`（空文字）が 400 になる（`routers/indexes.py`）。Spring は空文字を null として扱う
4. NAW 互換モードで空の `data:` 行が来ると、`json.loads("")` の例外で回答がエラーで終わる（`message_content_stream_service.py`）。移植元はそのイベントを無視する（要確認）
5. multipart の空文字がフォームで None になり、PATCH で `displayName=` を送っても空にならない（移植元は空文字で上書き。要確認）
6. `_try_finalize` が失敗する分岐のテストがない

### 🔵

7. 非 multipart のリクエストに 400 を返す（移植元は 415）
8. textData が UTF-8 として不正だと 500
9. `historyMessages[].type` を必須にしている（移植元は省略可）
10. tail の読み取りがイベントループ上で同期 I/O
11. cleanup ループが想定外の例外で止まり、終了処理まで巻き込む
12. `name` / `userId` が未指定でも空文字で登録できる（移植元は NOT NULL 制約で失敗）
13. `file_parts.file_id` にインデックスがない
14. `.env` の `DATABASE_URL` が alembic に効かず、README の手順でマイグレーション先とアプリの DB がずれる
15. `LOG_LEVEL=WARN` だとコンテナが起動しない（`docker-entrypoint.sh`）

### 対応

各項目を移植元のコードで確認し、差分は移植元に揃える。意図的に変えるものは docs に理由を書く。
