# 01_要件定義

## 背景

- 管理者向けアシスタント一覧取得 API が、検索キーワードを移植元（Spring Boot）と異なるパラメータ名で受け取っている
- フロントエンド（上流 secuaigent/client のコピー）は移植元の API 仕様どおり `search` で送信しているため、検索が機能しない
- フロントエンドは上流との同期で上書きされるため、移植先のバックエンドを移植元の API 仕様に合わせる

## 機能要件

| No | 要件 |
|---|---|
| 1 | 管理者向けアシスタント一覧取得 API は、検索キーワードをクエリパラメータ `search` で受け取る（移植元と同じ名前） |
| 2 | `search` を指定すると、名前または説明に部分一致するアシスタントだけを返す。大文字小文字は区別しない（既存の検索ロジックのまま。移植元と同じ仕様） |
| 3 | `search` を省略した場合、または空文字の場合は絞り込まない |
| 4 | 移植元にない旧パラメータ名 `q` は受け付けない（指定されても無視する） |

## 非機能要件

- レスポンス形式と、他のクエリパラメータ（`type` / `categoryId` / `groupId` / `excludeGroupId` / `page` / `size` / `sort`）の挙動は変えない
- DB スキーマの変更（マイグレーション）は行わない

## スコープ外

- フロントエンド（frontend-angular / frontend）の変更
- 他の一覧 API で使われている `q` パラメータ（グループ関連 API など）の見直し。移植元との差異があるかは別途確認する
- 検索ロジック自体（対象カラム・一致方法）の変更
