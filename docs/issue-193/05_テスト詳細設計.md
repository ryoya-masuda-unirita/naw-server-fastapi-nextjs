## テスト対象ファイル・テストケース

### `src/app/core/utils/tenant.helpers.spec.ts`（全面書き換え）

- `window.location` のスタブ・復元処理（`stubLocationHostname`/`restoreWindowLocation`）を削除する（サブドメインを参照しなくなるため不要）
- `resolveTenantId`:
  - `test('セッションにテナントIDが保存されているとき、その値を返すこと')`: `sessionStorage.setItem(STORAGE_KEYS.TENANT_ID, 'stored-tenant')` → `resolveTenantId()` が `'stored-tenant'`
  - `test('セッションにテナントIDが保存されていないとき、空文字を返すこと')`: `sessionStorage.clear()` → `resolveTenantId()` が `''`
- `persistTenantId`:
  - `test('渡されたテナントIDをセッションに保存すること')`: `persistTenantId('new-tenant')` 後、`sessionStorage.getItem(STORAGE_KEYS.TENANT_ID)` が `'new-tenant'`

### `src/app/features/admin/management/user-list/utils/user-list-tenant.helpers.spec.ts`（削除）

対応する実装ファイルの削除に伴い、ファイルごと削除する。

### `src/app/core/interceptors/auth.interceptor.spec.ts`（`window.location` スタブ部分を削除して簡略化）

- `stubLocationHostname`/`restoreWindowLocation` とその呼び出しを削除する
- 既存の3ケース（テナントありでヘッダ付与／テナント不明でヘッダなし／常に`withCredentials: true`）はロジック自体は変更しない。`sessionStorage` の設定・クリアのみで条件を作る形に整理する

### `src/app/features/auth/pages/login/login.component.spec.ts`

- `describe('初期値・ゲッター')`:
  - `test('フォームの初期値が空文字列であること')` の期待値に `tenantId: ''` を追加する
  - `test('初期状態ではtenantIdErrorが空文字列であること')` を追加する
- `describe('DOM要素表示')`:
  - `test('ユーザーIDとパスワードのFormInputが2つ表示されること')` を `test('テナントID・ユーザーID・パスワードのFormInputが3つ表示されること')` に変更し、期待件数を `3` にする
- `describe('DOM要素イベント')`:
  - `component.form.setValue(...)` の呼び出し全てに `tenantId: 'test-tenant'` を追加する
  - `expect(mockLogin).toHaveBeenCalledWith(...)` の期待値に `tenantId: 'test-tenant'` を追加する
  - `test('テナントIDが未入力のときonSubmitはauthStore.loginを呼ばないこと')` を追加する（`username`/`password` のみ設定し `tenantId` を空のまま送信）

### `src/app/core/stores/auth.store.spec.ts`

- `FIXTURE_CREDENTIALS` に `tenantId: 'tenant-form'` を追加する
- `describe('login メソッド')`:
  - 既存の `sessionStorage.setItem(STORAGE_KEYS.TENANT_ID, 'tenant-spy')`（呼び出し前の事前セット）を削除する。テナントIDは `login()` 自身が `credentials.tenantId` から保存するようになるため
  - `test('ログインAPI呼び出し前にセッションへテナントIDを保存すること')` を追加する。`mutateAsync.mockImplementation(async () => { expect(sessionStorage.getItem(STORAGE_KEYS.TENANT_ID)).toBe('tenant-form'); return FIXTURE_LOGIN_RESPONSE; })` で呼び出し時点の状態を検証する
  - `test('ログイン成功後、ユーザー情報を保存してダッシュボードへ進む')` の `expect(sessionStorage.getItem(STORAGE_KEYS.TENANT_ID)).toBe('tenant-spy')` を `'tenant-form'` に変更する
  - `test('ログインに失敗したとき、...')` の `expect(sessionStorage.getItem(STORAGE_KEYS.TENANT_ID)).toBeNull()` を `'tenant-form'` に変更する（`persistTenantId` がAPI呼び出し前に実行されるため、失敗時も入力値は残る。ログイン画面での再入力時にテナントID欄だけ再度クリアされないのは許容する）
