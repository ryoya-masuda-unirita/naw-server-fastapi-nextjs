# 08_動作確認

## 確認環境

- 通常はfrontend-angularの規約上、AIはサーバー起動・ブラウザ操作を行わずユーザーに依頼する運用だが、本Issueではユーザーから「そちらで確認してほしい」と明示的な依頼があったため、AIエージェントが以下の環境を自ら構築し、Playwright（実ブラウザ・実バックエンド接続）で動作確認を行った。
- バックエンド: `docker compose up -d postgres redis localstack backend`（`naw-fastapi-backend` 等の既存イメージを利用）
  - `docker exec naw-fastapi-backend uv run alembic upgrade head` でマイグレーションを適用
  - `docker exec -i naw-fastapi-postgres psql -U root -d postgres < backend/seed.sql` でシードデータを投入（`test-tenant` テナントと `admin`/`user01`/`first-login-user`/`expired-password-user` 等のユーザーが作成されることを確認）
- フロントエンド: `npm run start:local`（`http://localhost:4201`、プロキシ経由で `http://localhost:8001` のバックエンドに接続）
- 確認方法: `npx playwright test`（Chromiumプロジェクト）で本Issueに関連するE2Eスイートを実行

### E2E全体（参考実行）

上記に加えて全体スイートも実行した。ログイン・ログアウト・ユーザー管理以外の39件が失敗したが、いずれもテンプレート・チーム・チャット・API設定など**本Issueと無関係な機能のseedデータ不足**が原因と特定した（`backend/seed.sql` が `rooms` テーブルの外部キー制約違反で `assistants` 関連データ投入前に停止しており、`assistants` テーブルが0件だったことを確認済み）。失敗内容はいずれも「該当データが画面に表示されない」という表示系のアサーション失敗であり、テナント解決・認証周りのエラーではないため、本Issueの変更による回帰ではないと判断した。
