# issue-193 frontend-angularのサブドメインによるテナント識別を廃止する

## 概要

frontend-angular（Angular、バックエンド動作確認用フロントエンド）で、ログイン時のテナント識別にサブドメイン（`window.location.hostname`）を使用している実装を廃止し、ログイン画面でテナントID（例: test-tenant）を明示的に入力・送信できるようにする。

バックエンド（FastAPI）は元々 `X-Tenant-ID` ヘッダを必須で受け取る設計になっており、サブドメイン起点の解決ロジックは存在しない。変更はfrontend-angular側に閉じる。

## 説明

- サブドメインはログイン時のテナント識別以外の用途では実質使われていない
- サブドメイン運用を前提とした複雑さ（`hostname` パース、ワイルドカードDNS等）を排除し、開発・動作確認をシンプルにしたい

### 変更対象（frontend-angular）

- `src/app/core/utils/tenant.helpers.ts`: `resolveTenantId()` の `hostname` 抽出ロジックを撤去
- `src/app/features/admin/management/user-list/utils/user-list-tenant.helpers.ts`: `extractTenantIdFromHostname()` の重複実装を撤去（`tenant.helpers.ts` 側の実装に一本化）
- `src/app/core/interceptors/auth.interceptor.ts`: `X-Tenant-ID` ヘッダ付与ロジックの見直し
- ログイン画面（`login.component.ts` ほか）: テナントID入力欄を追加
- `src/app/core/types/auth.types.ts` の `LoginRequest`: `tenantId` 系フィールドの追加要否を検討
- `src/app/core/initializers/login-key.initializer.ts`: クエリパラメータ `tenantId` 経路との整理
- `pw-reset.component.ts`: `sessionStorage['tenantId']` 書き込み箇所の整合性確認
- 上記に対応する `*.spec.ts`（`tenant.helpers.spec.ts` / `user-list-tenant.helpers.spec.ts` / `auth.interceptor.spec.ts` / `login-key.initializer.spec.ts`）の修正

### スコープ外（別途判断）

- `infra/acm.tf` / `infra/cloudfront.tf` のワイルドカードサブドメイン前提のACM証明書・CloudFrontエイリアス設定の見直しは本Issueのスコープ外とする（必要であれば別Issueで対応）
