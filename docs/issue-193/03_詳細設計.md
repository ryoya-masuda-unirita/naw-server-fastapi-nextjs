# 03_詳細設計

## テナント解決ユーティリティ（`src/app/core/utils/tenant.helpers.ts`）

- `resolveTenantId()` からサブドメイン抽出処理（`window.location.hostname` 参照）を削除し、`sessionStorage`（`STORAGE_KEYS.TENANT_ID`）を読むだけの関数にする
- `persistTenantId(tenantId: string): void` を新規追加する。`sessionStorage.setItem(STORAGE_KEYS.TENANT_ID, tenantId)` を行う（`AuthStore.login()` から、ログインAPI呼び出し前にテナントIDを永続化するために使う）

## ユーザー管理一覧専用のテナント解決（`src/app/features/admin/management/user-list/utils/user-list-tenant.helpers.ts`）

- ファイルごと削除する。`extractTenantIdFromHostname` / `resolveUserListTenantId` / `persistUserListTenantId` / `repairUserListTenantIdInStorage` はいずれもサブドメイン起点の処理であり、廃止後は共通の `resolveTenantId()` で代替できるため不要になる
- `isValidUserListTenantId`（`"undefined"`/`"null"` 等の不正値ガード）も、サブドメインからの補修（repair）処理自体が無くなるため合わせて削除する

## ユーザー管理一覧の認証コンテキスト（`src/app/features/admin/management/user-list/services/user-list-auth.service.ts`）

- import元を `user-list-tenant.helpers` から `@core/utils/tenant.helpers` の `resolveTenantId` に変更する
- `repairTenantIdInStorage()` メソッドと、`syncSessionFromAuthStore()` / `prepare()` からの呼び出しを削除する（サブドメインからの補修対象が無くなるため）
- `readContext()` は `tenantId: resolveTenantId()` を使うよう変更する
- `getRequestHeaders()` は `resolveTenantId()` の戻り値が truthy な場合のみ `X-Tenant-ID` ヘッダを付与するよう簡略化する（`authInterceptor` と同じ条件分岐に揃える）

## HTTPリクエストへのヘッダ付与（`src/app/core/interceptors/auth.interceptor.ts`）

- コードの変更なし。`resolveTenantId()` の実装がサブドメイン非依存になることで、挙動が「セッションに保存された値のみを見る」に変わる

## テナントID読み書き箇所の棚卸し

- `src/app/core/stores/auth.store.ts`: `saveToStorage()` / `clearStorage()` は変更なし。ただし `login()` の先頭で、ログインAPI呼び出し前に `persistTenantId(credentials.tenantId)` を呼び出す変更を加える（ログインリクエスト自体に `X-Tenant-ID` ヘッダを付与するため。セッション未確立の最初のリクエストではサブドメインという代替情報源が無くなるため、フォーム入力値を先に保存しておく必要がある）
- `src/app/core/interceptors/error.interceptor.ts`: 変更なし（401時に `TENANT_ID` を削除する既存動作を維持）
- `src/app/core/initializers/login-key.initializer.ts`: 変更なし（URLクエリ `tenantId` によるサブドメイン非依存の代替経路として維持する）
- `src/app/features/auth/pages/pw-reset/pw-reset.component.ts`: 変更なし（同上の理由）
- `src/app/core/mocks/handlers/auth.mock.ts`: `sessionStorage.getItem('user')` / `sessionStorage.getItem('tenantId')` の文字列リテラルを `STORAGE_KEYS.USER` / `STORAGE_KEYS.TENANT_ID` に置き換える（`@core/constants` から import）

## ログイン画面

### 型定義（`src/app/features/auth/types/auth.types.ts`）

- `LoginRequest` に `tenantId: string` を追加する

### フォーム（`src/app/features/auth/pages/login/login.component.ts`）

- `form` に `tenantId` コントロールを追加する。バリデーションは `username` と同じパターン（`Validators.required`, `Validators.minLength(3)`, `Validators.maxLength(50)`）に揃える
- `tenantIdError` computed を `usernameError` / `passwordError` と同じ形で追加する
- `onSubmit()` で `tenantId` もフォーム値から取り出し、`authStore.login({ username, password, tenantId })` に渡す

### テンプレート（`src/app/features/auth/pages/login/login.component.html`）

- `username` の `app-form-input` の直前に、テナントID用の `app-form-input`（`formControlName="tenantId"`）を追加する
- ラベル・プレースホルダーは新規i18nキー（`AUTH.LOGIN.TENANT_ID_LABEL` / `AUTH.LOGIN.TENANT_ID_PLACEHOLDER`）を使う

### i18n（`public/i18n/ja.json` / `public/i18n/en.json`）

- `AUTH.LOGIN` 配下に `TENANT_ID_LABEL` / `TENANT_ID_PLACEHOLDER` を追加する（バリデーションエラーメッセージは既存の共通キー `VALIDATION.REQUIRED` 等を流用するため追加不要）

## Store（`src/app/core/stores/auth.store.ts`）

- `login(credentials: LoginRequest)` の先頭で `persistTenantId(credentials.tenantId)` を呼び出してから `authService.loginMutation.mutateAsync(credentials)` を呼ぶよう変更する
- `handleAuthSuccess` / `loginWithKey` 内の `resolveTenantId()` 呼び出しはそのまま維持する（`login()` の場合はフォーム入力値がすでに保存済みのため同じ値を再取得するだけになる）
