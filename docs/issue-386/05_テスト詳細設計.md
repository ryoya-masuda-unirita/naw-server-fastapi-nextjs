# 05_テスト詳細設計

| No | 確認方法 | 対象 |
|---|---|---|
| 1 | `terraform fmt -recursive -check -diff`（`secuaigent-infra/`）と、環境（dev）の `init -backend=false` → `validate` | `secuaigent-infra/` |
| 2〜4・8 | 作業用ディレクトリに、変更前（`develop`）と変更後の `secuaigent-infra/` を置き、`AWS_PROFILE=oic` で backend をローカルに差し替えて `plan -out` → `terraform show -json`。アドレスで突き合わせ、増減と `values` の差分を出す。シークレットの値は、`sensitive_values` で機密扱いであることを確認する | 同左 |
| 5 | 組み立ての式と同じ文字列連結を、サンプル値（`root`・`secretpass`・`db.example`・`postgres`）で再現して、現行の接続文字列と比べる。乱数の出力が英数字のみであることは、`random_password` の `special = false` で担保する | コードの読解 |
| 6・7 | ECS モジュールのコードを読み、`environment` と `secrets` の内容を確認する。`valueFrom` は、移植元と同じ形式（`<ARN>:<キー>::`）であることを確認する | `secuaigent-infra/modules/ecs/main.tf` |
| 9 | `grep -rn "db_password\|secret_key\|TF_VAR_db_password\|TF_VAR_secret_key" secuaigent-infra .github`（`.terraform`・文書を除く） | 全体 |
| 10 | `.terraform.lock.hcl` に `hashicorp/random` があり、ハッシュに `h1:` と `zh:` が複数あることを確認する | `.terraform.lock.hcl` |
| 11 | `deploy-backend.yml` の `jq` の式を読み、サンプルの `describe-task-definition` 風の JSON（`secrets` を含む）に同じ式を適用して、`secrets` が残ることを確認する | `.github/workflows/deploy-backend.yml` |
| 12 | `bash -n` で構文を確認し、偽の `aws`・`terraform`・`jq` を PATH の先頭に置いて、3 通りを実行する | `secuaigent-infra/scripts/seed_via_bastion.sh` |
| 13 | `git diff` の追加行を目視。12 桁の数字・鍵の文字列・パスワードらしい値を検索する。確認は、文書の最後の更新のあとに行う | 変更ファイル全体 |

注意: `plan` は AWS に読み取りだけを行う。`apply` は実行しない。作業用ディレクトリの `terraform.tfvars` と `tfplan`（機密の値を含みうる）は、確認後に削除する。
