# 03_詳細設計

## 1. rds（`secuaigent-infra/modules/rds/`）

- `random_password.master`（`length = 32`、`special = false`）を足す。記号を含めないのは、接続文字列（URL）に埋め込んでも、エスケープが要らないようにするため
- `aws_db_instance.main` の `password` を `random_password.master.result` にする
- 入力 `db_password` を削除する
- 出力を足す: `master_password`（`random_password.master.result`、`sensitive = true`）。既存の出力（`address`・`username`・`db_name`）は変えない

## 2. secrets（新規。`secuaigent-infra/modules/secrets/`）

`main.tf`・`variables.tf`・`outputs.tf` の 3 ファイル（移植元と同じ構成）。

入力: `project_name`、`db_address`、`db_username`、`db_name`、`db_password`（`sensitive`）。

```hcl
resource "random_password" "secret_key" {
  length  = 64
  special = false
}

resource "aws_secretsmanager_secret" "backend" {
  name = "${var.project_name}/backend"
  // 開発用なので、削除待ちなし(destroy後に同じ名前で作り直せるようにする)
  recovery_window_in_days = 0
  tags = { Name = "${var.project_name}/backend" }
}

resource "aws_secretsmanager_secret_version" "backend" {
  secret_id = aws_secretsmanager_secret.backend.id
  secret_string = jsonencode({
    DATABASE_URL = "postgresql+asyncpg://${var.db_username}:${var.db_password}@${var.db_address}:5432/${var.db_name}"
    SECRET_KEY   = random_password.secret_key.result
    DB_PASSWORD  = var.db_password
  })
}
```

出力: `secret_arn`、`secret_name`。接続文字列の形式は、現行の `ecs` の `DATABASE_URL`（`postgresql+asyncpg://<ユーザー>:<パスワード>@<ホスト>:5432/<DB 名>`）と同じにする。

## 3. ecs（`secuaigent-infra/modules/ecs/`）

- 入力: `db_password`・`secret_key`・`rds_address`・`rds_username`・`rds_db_name` を削除し、`secret_arn`（string）を足す
- 2 つのタスク定義（`backend`・`backend_migrate`）のコンテナ定義: `environment` から `DATABASE_URL`・`SECRET_KEY` を削除し、次を足す

```hcl
secrets = [
  { name = "DATABASE_URL", valueFrom = "${var.secret_arn}:DATABASE_URL::" },
  { name = "SECRET_KEY",   valueFrom = "${var.secret_arn}:SECRET_KEY::" },
]
```

- 実行ロール `aws_iam_role.ecs_task_execution` に、インラインポリシーを足す（`secretsmanager:GetSecretValue`、`Resource = [var.secret_arn]`）。アプリのタスクロール `backend_task` には付けない
- 「`ignore_changes = [container_definitions]`」は変えない（CI が登録し直すため）

## 4. 環境（`secuaigent-infra/environments/dev/`）

- `variables.tf`: `db_password`・`secret_key` を削除する
- `main.tf`
  - `terraform` ブロックの `required_providers` に `random`（`hashicorp/random`、`~> 3.0`）を足す。`module "rds"` から `db_password` を削除する
  - `module "secrets"` を足す（`db_address = module.rds.address`、`db_username = module.rds.username`、`db_name = module.rds.db_name`、`db_password = module.rds.master_password`）
  - `module "ecs"` から `rds_*`・`db_password`・`secret_key` を削除し、`secret_arn = module.secrets.secret_arn` を足す
- `outputs.tf`: `backend_secret_name`（`module.secrets.secret_name`）を足す
- `terraform.tfvars.example`: `db_password`・`secret_key` の行を削除する
- `.terraform.lock.hcl`: `hashicorp/random` を足す（`terraform providers lock -platform=darwin_arm64 -platform=linux_amd64` で、ローカルと CI の両方のハッシュを入れる）

## 5. CI（`.github/workflows/deploy-infra.yml`）

`Terraform Plan`・`Terraform Apply` の `env` から、`TF_VAR_db_password`・`TF_VAR_secret_key` を削除する。ほかは変えない。`deploy-backend.yml` は変えない（`describe-task-definition` の結果を、そのまま登録し直すので、`secrets` が残る。`jq` の `del(...)` に `secrets` は含まれない）。

## 6. 踏み台のシード投入（`secuaigent-infra/scripts/seed_via_bastion.sh`）

- `DB_PASSWORD` を、環境変数から取る（なければ、Secrets Manager から取得する）。取得は、`terraform output -raw backend_secret_name` でシークレット名を取り、`aws secretsmanager get-secret-value --secret-id <名前> --query SecretString --output text | jq -r .DB_PASSWORD` とする。取得できなければ、原因を示して止まる
- 先頭のコメント（「DB_PASSWORD は呼び出し側から渡す」）を直す

## 7. 手順書・変数の例

- `secuaigent-infra/README.md`
  - 初回セットアップの GitHub Secret / Variable の登録から、`DB_PASSWORD`・`SECRET_KEY` を削除する
  - 「シークレット（Secrets Manager）」の節を足す: 中身（3 つのキー）、取得方法（`aws secretsmanager get-secret-value`）、値の変え方（再生成: `terraform apply -replace=...`、手動の変更はいずれ Terraform が戻すこと）、tfstate に値が残ること、アプリのタスクロールには読む権限がないこと、費用（単価未確認）
  - 踏み台のシード投入の説明（`DB_PASSWORD` を渡す記述）を直す
- `terraform.tfvars` の注意: 手元の `db_password`・`secret_key` は、使われなくなる
