# Secrets Manager を導入し、ECS の平文環境変数を Secrets に移す

## 概要

Issue #386（親: #380。#381〜#385 はマージ済み）。機密情報（DB パスワードを含む接続文字列、アプリの秘密鍵）を、ECS のタスク定義の平文の環境変数から、AWS Secrets Manager に移す。

## 説明

- 移植元 `modules/secrets` に合わせて、Secrets Manager にシークレットを作り、実行ロールに `GetSecretValue` を付ける
- ECS の `DATABASE_URL`・`SECRET_KEY`（DB パスワード込みの平文 environment。tfstate にも入る）を、`secrets` で注入する形に変える。アプリが個別の値を読むか、組み立てた値を渡すかは、アプリ側（`server/`）と合わせる（設定の読み込み部分の確認が要る）
- DB の master パスワードは `random_password` にする
- タスク定義の `ignore_changes` と CI のデプロイが共存するか確認する

## その他

- 確認した事実: アプリ（`server/app/core/config.py`）は、`DATABASE_URL`（接続文字列 1 本）と `SECRET_KEY` を環境変数で受け取る。CI（`deploy-backend.yml`）は、稼働中のタスク定義を `describe-task-definition` で取得し、イメージだけ差し替えて登録し直す（`secrets` の定義は、そのまま引き継がれる）
