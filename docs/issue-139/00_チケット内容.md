# #139 issue-139 backend mypy導入に向けた現状調査を行う

## 概要

backend の mypy 導入に向けて、現状の型チェックエラーを棚卸しし、段階導入の対象範囲と優先順位を整理する。

## 説明

`backend/pyproject.toml` には既に dev dependency として mypy と最小設定が存在するが、CI には組み込まれておらず、backend 全体を継続的に型チェックする運用にはなっていない。いきなり全体を CI 必須にすると既存エラーの量次第で作業が大きくなるため、まず現状把握を行う。

対応内容（想定）:

- `uv run mypy app tests` または候補範囲別の mypy 実行結果を取得する
- エラーをカテゴリ別に分類する
  - import / missing stubs
  - SQLModel / SQLAlchemy 型推論
  - Pydantic / FastAPI 型推論
  - Optional / None 安全性
  - test mock / AsyncMock 周辺
- すぐ直すべき型エラーと、設定で段階的に扱うべき型エラーを分ける
- 後続 Issue の対象範囲を決めるための調査結果を `docs/issue-*` に残す

## 受け入れ条件

- backend 全体または主要ディレクトリの mypy 実行結果が記録されている
- 型エラーの主なカテゴリと件数が整理されている
- 後続で修正する範囲と CI 組み込みまでの方針が明確になっている

## その他

- スコープ外: 大量の型エラー修正、CI への mypy 必須化、strict mode の全面適用
- 後続 Issue（連番の依存チェーン）
  - #140: mypy 設定整備
  - #141: エラー修正
  - #142: CI 組み込み
- 元チケット（NAW）参照なし
