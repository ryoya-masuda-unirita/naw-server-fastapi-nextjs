## カテゴリ分類

### 1. SQLModel / SQLAlchemy 型推論（構造的な問題・最多）

- 該当件数: 423件中ほぼ全件（`app/repositories` 全体）＋ `app/services` 7件（`user_service.py` 3件、`user_import_service.py` 2件を含む where 系）＋ `app/core/credit_quota.py` 3件
- 原因: SQLModel のモデルクラス属性は mypy 上で宣言した Python 型（`str` / `datetime` / `UUID` / `bool` / `date | None` など）としてしか認識されない。SQLModel には Django-stubs のような「モデル属性を `InstrumentedAttribute` として認識させる mypy プラグイン」が存在しないため、`Model.field == value` のような SQLAlchemy 的なカラム比較式や、`.where()` / `.join()` / `.in_()` / `.desc()` / `.asc()` / `.is_()` / `.label()` の呼び出しが、実行時には正しく動作するにもかかわらず mypy 上は「plain な Python 値に対する不正な操作」としてエラーになる
- 実測: `incompatible type "bool"` を含むエラーが234件（`.where()` / `.join()` の引数に `Model.field == value` のような bool 式を渡した際に発生）
- 代表例:
  - `app/repositories/group_user_repository.py:100`: `Argument 2 to "join" of "Select" has incompatible type "bool"`
  - `app/repositories/user_repository.py:70`: `"str" has no attribute "in_"`
  - `app/repositories/prompt_template_repository.py:82`: `"datetime" has no attribute "desc"`
  - `app/repositories/subscription_repository.py:35`: `Item "date" of "date | None" has no attribute "is_"`
  - `app/repositories/share_room_repository.py:25`: `No overload variant of "select" matches argument type "str"`
  - `app/repositories/file_repository.py:12`: `Dict entry 0 has incompatible type "str": "str | None"; expected "str": "InstrumentedAttribute[Any]"`
- 影響ファイル数: 37ファイル中35ファイル（`app/repositories/*.py` が34ファイル＋ `app/core/credit_quota.py`）
- 対応方針: リポジトリ層のクエリ構築パターン（SQLModel クラス属性を直接比較式に使う書き方）をそのままにする限り、根本解消は困難。以下のいずれかが必要になる見込み
  - a. per-module で該当エラーコードを無効化する mypy override（暫定措置。技術的負債として明示する）
  - b. リポジトリ層を SQLAlchemy 2.0 の `Mapped[]` 型宣言スタイルに寄せる、または `cast()` / `# type: ignore[code]` を個別に付与する（工数大、#141 以降で判断）
  - c. SQLModel/SQLAlchemy のバージョンアップやスタブ整備状況を継続ウォッチする
- 本 Issue のスコープでは修正を行わない（後続 #141 で対応要否を判断）

### 2. Optional / None 安全性（実バグ疑い・少数）

- 該当件数: 2件（`app/services` 内）
- 内容:
  - `app/services/index_service.py:594`: `Argument 1 to "find_by_id_and_tenant_id" of "RoomRepository" has incompatible type "str | None"; expected "str"` — `room_id` が `None` になり得る値をそのまま `str` 引数へ渡している。呼び出し元の値が本当に None になり得るなら実行時エラー（例外）につながる可能性がある
  - `app/services/message_service.py:1028`: `Incompatible types in assignment (expression has type "None", variable has type "MessageContentResponse")` — 変数の型注釈と実際の代入値が矛盾している
- 対応方針: 上記1のカテゴリとは異なり SQLModel 由来の構造的問題ではなく、コード側の Optional 扱いの見直しで解消できる可能性が高い。件数も少ないため #141（エラー修正）の最優先対象として提案する
