# 03_詳細設計

## 根拠（移植元 `~/Documents/unirita-develop-pj/secuaigent-ref/server`）

| 移植元 | 内容 |
|---|---|
| `api/UserController.java` `getUsers`（`GET /api/admin/users`） | `@RequestParam(required = false) String excludeGroupId` をそのまま `UserService.getUsers` に渡す。存在チェックなし |
| `service/UserService.java` `buildUserSpecification` | `excludeGroupId != null && !excludeGroupId.isBlank()` のとき、`GroupUser` のサブクエリ（`groupUser.user.id = root.id` かつ `groupUser.id.groupId = excludeGroupId`）に `NOT EXISTS` を掛ける。サブクエリにテナント条件はない |
| `service/UserService.java` `getUsers` | `includeUsage`・利用クレジット順の並べ替えの経路も同じ `buildUserSpecification` を使う |

存在しない・他テナントのグループ ID のときは、サブクエリに一致する所属行（このテナントのユーザーの行）がないため除外は起きず、200 で通常の一覧が返る。

## 実装対象ファイル

### `backend/app/services/user_service.py` `UserService.get_users`

- `# excludeGroupId はグループ機能実装時に対応する` のコメントを削除し、次を追加する

  ```python
  if exclude_group_id and exclude_group_id.strip():
      stmt = stmt.where(
          ~exists().where(
              GroupUser.user_id == User.id,
              GroupUser.group_id == exclude_group_id,
              GroupUser.tenant_id == tenant_id,
          )
      )
  ```

  - 件数（`count_stmt`）と並べ替え（利用クレジット順・通常）の両方が同じ `stmt` から作られるため、1 箇所で全経路に効く
  - 空白だけの値は、移植元の `isBlank` と同じく指定なしとして扱う（code-review #4）
  - サブクエリにはテナント条件を付ける（code-review #1）。移植元には無いが、`groups_users` は所属行のテナントとユーザーのテナントの一致を制約で保証しないため、他テナントのグループの所属行で自テナントのユーザーが消えないようにする。通常のデータでは結果は移植元と同じ。アシスタント・プロンプトテンプレートの除外とも揃う
- docstring の `exclude_group_id` の説明を更新する
- import に `sqlalchemy.exists` と `app.models.group.GroupUser` を追加する

既存の `get_users` はクエリを Service 内で組み立てており、条件の追加だけにとどめる（Repository への切り出しはこの Issue の範囲外）。
