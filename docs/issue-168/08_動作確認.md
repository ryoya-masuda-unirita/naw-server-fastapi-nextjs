# 08_動作確認

**ブラウザ・実機での確認は行わず、自動テスト（pytest）のみで代替した。** ローカルの Postgres / Redis / backend サーバーは他の作業と共有しているため起動・変更していない。テストはインメモリ SQLite と fakeredis で実行した。

## 確認環境

- ブランチ: `feature/issue-168`（`origin/develop` から作成。#167 の修正は含まないため、結合テストは `loginId` キーで送っている）
- `backend/` で `uv run pytest`（インメモリ SQLite + fakeredis）
- 環境変数は、メイン作業ツリーの `backend/.env` を worktree にコピーして読み込んだ（gitignore 対象のためコミットされない）
- 修正前のベースライン（`origin/develop`）: 779 passed

## 確認手順

1. 修正前の症状を再現する: `backend/app/core/password_policy.py` だけを `origin/develop` の状態に一時的に戻し、追加したテストを実行する
2. 修正後のコードに戻し、ポリシー検証の単体テストと、パスワード再設定 API の結合テストを実行する
3. 同じ検証処理を使う既存の単体テスト（認証サービス・ユーザーサービス）と、backend の全テストを実行して回帰がないことを確認する

- ブラウザ（frontend-angular `http://localhost:4201`）からのパスワード再設定・プロフィール更新の操作は実施していない（共有環境のサーバーを起動しない方針のため）
- frontend-angular はエラー時に `message` フィールドを表示するが、移植先 backend は `detail` で返すため、画面にはサーバーのメッセージが表示されない。全 API 共通の既存差分のため本 Issue のスコープ外
- frontend-angular の E2E テスト（テスト項目書の項番23〜38）の有効化はスコープ外
