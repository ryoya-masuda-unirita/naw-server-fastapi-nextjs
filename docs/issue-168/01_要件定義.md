# 01_要件定義

## 背景

テナントにはパスワードポリシーとして、最小文字数のほかに「大文字必須」「小文字必須」「数字必須」「記号必須（使用可能な記号の一覧つき）」を設定できる。しかし移植先では、ユーザーが新パスワードを設定するときに最小文字数しか検証しておらず、文字種のポリシーに反するパスワードを設定できてしまう。

移植元（Spring Boot）では、パスワード再設定時にテナントのポリシーに基づいて新パスワードを次の順に検証し、最初に満たさなかった項目のメッセージを入力エラー（400）として返している。

1. 未入力・空白のみでないこと
2. 最小文字数以上であること
3. 大文字必須の場合、大文字を含むこと
4. 小文字必須の場合、小文字を含むこと
5. 数字必須の場合、数字を含むこと
6. 記号必須の場合、使用可能な記号のいずれかを含むこと（使用可能な記号が未設定なら、記号要件を満たせないためエラー）

## 機能要件

1. パスワード再設定 API で、新パスワードを移植元と同じ順序・同じ条件でテナントのポリシーに照らして検証すること
2. ポリシー違反時は 400 とし、エラー詳細には移植元と同じ日本語メッセージを返すこと

   | 違反内容 | メッセージ |
   |---|---|
   | 未入力・空白のみ | 新パスワードの入力は必須です。 |
   | 最小文字数未満 | 新パスワードは{最小文字数}文字以上で入力してください。 |
   | 大文字なし | 新パスワードには大文字を含めてください。 |
   | 小文字なし | 新パスワードには小文字を含めてください。 |
   | 数字なし | 新パスワードには数字を含めてください。 |
   | 使用可能な記号が未設定 | 新パスワードの記号要件を満たせません。 |
   | 使用可能な記号なし | 新パスワードには次の記号のいずれかを含めてください: {使用可能な記号} |

3. 文字種の要件が無効な項目は検証しないこと（例: 大文字・小文字・記号が無効で数字のみ必須なら、数字だけのパスワードも許可）
4. 最小文字数と文字種の 16 通りの組み合わせのいずれでも、ポリシーを満たすパスワードは受け付け、満たさないパスワードは拒否すること

## 非機能要件

- DB マイグレーションは発生させない（ポリシー項目はテナントに既にある）
- 画面（frontend-angular / frontend）には手を入れない

## 影響（仕様として受け入れるもの）

- 新パスワードの検証処理は、ログインユーザー自身のプロフィール（パスワード）更新でも共用している。移植先ではこの処理で既に最小文字数を検証しているため、同じ処理を拡張し、プロフィール更新でも文字種ポリシーを検証するようにする。移植元のプロフィール更新はポリシー検証をしていないが、テナントのポリシーを確実に守らせるため、移植先の既存方針（同じ検証を共用する）を維持する
- 最小文字数違反のエラーメッセージが英語から移植元の日本語に変わる

## スコープ外

- エラーレスポンスの形式（移植先は `detail`、移植元は `message`）の統一。全 API 共通の差分のため本 Issue では扱わない
- 移植元にあるパスワード再設定の連続失敗ロックアウト（429）
- パスワード再設定リクエストのフィールド名不一致（Issue #167 で対応）
- frontend-angular の E2E テスト（項番23〜38）の有効化
