# 02_基本設計

## 変更対象

- 新パスワードのポリシー検証処理（共通ユーティリティ）
- ポリシー検証の単体テスト、パスワード再設定 API の結合テスト

## 画面 / API 変更概要

### POST /auth/password/reset

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 新パスワードの検証 | 最小文字数のみ | 空白のみ・最小文字数・大文字・小文字・数字・記号（テナントのポリシーに従う） |
| 違反時のステータス | 400 | 400（変更なし） |
| 違反時のエラー詳細 | 英語（最小文字数のみ） | 移植元と同じ日本語メッセージ |

検証の順序は移植元と同じで、最初に満たさなかった項目のメッセージを返す。既存の「旧パスワード照合（403）」→「ポリシー検証（400）」→「履歴重複チェック（400）」という処理の順番は変えない。

### PUT（プロフィール更新）でのパスワード変更

同じ検証処理を共用しているため、上記と同じ検証が適用される。

画面の変更はない。

## 影響範囲

- パスワード再設定 API
- ログインユーザー自身のプロフィール（パスワード）更新 API
- 管理者によるユーザー作成時の初期パスワード生成は、元々ポリシーに従って生成しているため影響しない

## 移植方針

- 移植元のパスワードポリシー検証（`PasswordPolicy.validate`）の判定順序・条件・メッセージをそのまま移植する
- 移植元は「結果オブジェクトを返し、呼び出し側で例外にする」構成だが、移植先は既存の検証関数と同じく「違反時に 400 の HTTP 例外を送出する」構成のまま拡張する（呼び出し側の変更が不要なため）
- 文字種の判定は移植元（Java の文字種判定）と同じく Unicode の文字カテゴリで判定する
