# #301 issue-301 顧客の社内（オンプレ）側の環境をDockerでまとめて立ち上げられるようにする

## 概要

顧客の社内（オンプレ）側の環境を、Docker で丸ごと立ち上げられるようにする。クラウド側（ルートの `docker-compose.yml` の backend など）と組み合わせ、SECURE アシスタントの経路をローカルで通しで動かして確かめられるようにする。

## 説明

### 立ち上げるもの（顧客の社内に置くもの）

- server-local（`server-local/`）
- Waha! エミュレーター（`waha-emulator/`。アダプタを含む）
- アダプタが使うベクトルDB（移植元が対応する PostgreSQL + pgvector。Graph RAG 用に AGE、ハイブリッド検索用に PGroonga が必要なら含める。移植元の `generative-ai-adapter/docker/` を参考にする）
- 顧客のファイルサーバーの代わり（同期で取り込む文書を置くディレクトリ。サンプル文書を数件入れておく）

### 要件

- 1 つの compose（置き場所は着手時に決める。例: ルートの `onprem/`）で上をまとめて起動・停止できる
- server-local と Waha! エミュレーターのストリームファイル用ディレクトリの共有、server-local → クラウド側 backend（ライブラリのスタブ作成）への接続先を設定済みにする
- クラウド側（ルートの compose の backend）とつないだときの設定（backend に登録する LOCAL_SERVER エンドポイントの URL・API キー、seed）を用意する
- 既存のローカルの環境（ルートの compose のコンテナ・ポート）と衝突しないポートにする
- README に、起動・停止のコマンドと、何が立ち上がるか（各サービス 1 行）、クラウド側とのつなぎ方を書く。長い説明は書かない
