# 04_テスト設計

## テスト方針

コードの変更はなく、Compose・イメージ・seed の追加だけのため、自動テストは追加しない。実際に Docker で起動して確かめる。既存の server-local・エミュレーターの自動テストは変更がないことの確認として流す。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | Compose の定義 | 社内側の Compose の設定を展開する | エラーなく展開でき、プロジェクト名・ポートが既存と異なる |
| 2 | 起動 | `.env` なしで起動する | 全サービスが起動し、healthcheck が healthy になる |
| 3 | ベクトルDB | 起動後に拡張とグラフを確かめる | vector・pgroonga・age の拡張と `embedding_graph` がある |
| 4 | ファイルサーバー | エミュレーターのコンテナから見る | サンプル文書が読める・書き込めない |
| 5 | SECURE のチャット | server-local に SECURE のチャットを送る | エミュレーター（echo）の回答が SSE で返る |
| 6 | ストリームファイルの共有 | 5 のあと | server-local が作ったファイルにエミュレーターが追記している |
| 7 | クラウド側とつなぐ | ルートの compose の backend を起動し、seed を流してログインし、ライブラリ作成付きのチャットを送る | backend のアクセスログに server-local からのスタブ作成のリクエストが届く |
| 8 | クラウド側の seed | backend の SECURE アシスタントの一覧 | 社内アシスタントの LOCAL_SERVER の URL・API キーが返る |
| 9 | 既存の環境 | 確認の前後 | 既存のコンテナ・ボリュームが変わらない |
| 10 | 片付け | 確認後 | 起動したコンテナ・ボリュームが残っていない |
| 11 | 既存テスト | server-local・エミュレーターの pytest | すべて成功（変更なし） |
