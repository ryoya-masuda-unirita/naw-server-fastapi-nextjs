# 01_要件定義

## 背景

SECURE アシスタントは、ブラウザから顧客の社内のサーバー（server-local）に直接質問を送り、server-local が Waha!（とアダプタ）で回答を作る。社内側の部品は server-local・Waha! エミュレーターとして個別に Docker で動かせるが、組み合わせるにはディレクトリの事前作成・接続先・認証キーの設定を手で揃える必要がある。アダプタが使うベクトルDB と、同期で取り込む文書の置き場（ファイルサーバー）はまだない。社内側をまとめて立ち上げ、クラウド側とつないで SECURE の経路を通しで確かめられるようにする。

## 機能要件

1. 1 つの Compose 定義で、社内側の次のものをまとめて起動・停止できる
   - server-local
   - Waha! エミュレーター（今は仮のチャットのみ。アダプタは後続 Issue で取り込む）
   - ベクトルDB（PostgreSQL + pgvector + PGroonga + Apache AGE。移植元のアダプタの検証環境と同じ構成）
   - ファイルサーバーの代わり（文書を置くディレクトリ。サンプル文書を数件入れる）
2. 起動しただけで次が設定済みになっている（`.env` を作らなくても動く）
   - server-local → エミュレーターの接続先と認証キー
   - server-local とエミュレーターのストリームファイル用ディレクトリの共有（事前のディレクトリ作成は不要）
   - server-local → クラウド側 backend の接続先（ルートの compose の backend をホストで公開しているポート）
3. 各サービスに healthcheck を付け、起動完了を `docker compose ps` で確かめられる
4. クラウド側（ルートの compose の backend）とつなぐための seed を用意する。backend に SECURE アシスタントと LOCAL_SERVER エンドポイント（server-local の URL と API キー）を登録し、既存の動作確認用ユーザーが使えるようにする
5. README に、起動・停止のコマンド、何が立ち上がるか（各サービス 1 行）、クラウド側とのつなぎ方だけを書く

## 非機能要件

- 既存のローカル環境（ルートの compose のコンテナ名・ポート・ボリューム、server-local・エミュレーター単体の compose）と衝突しない。別のプロジェクト名・別のポートにする
- 公開ポートは 127.0.0.1 に限る（既定の認証キー・DB パスワードで動かすため）
- docker-compose.yml のコメントは、各サービスが何を表すかの 1 行だけにする
- server-local・エミュレーターのコードと Dockerfile は変更せず、既存の Dockerfile をビルドして使う（エミュレーターは #298 が並行で変更中）

## スコープ外

- アダプタ（生成AI・検索・埋め込み）の取り込みと、ベクトルDB・ファイルサーバーを使うワークフロー（#298〜#300）。今回はベクトルDB とファイルサーバーを用意し、エミュレーターから見えるようにするだけ
- backend のライブラリのスタブ作成 API（`POST /api/libraries`）の移植。今は未移植で、server-local からの通信は届くがスタブは作られない
- React（`frontend/`）の SECURE チャット画面（未移植のため、ブラウザからの通しの確認はできない）
- 本番・顧客向けの配布物（今回はローカル検証用）
