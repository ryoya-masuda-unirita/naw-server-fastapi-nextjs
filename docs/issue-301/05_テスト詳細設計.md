# 05_テスト詳細設計

コマンドはリポジトリのルートから実行する。

| No | 手順 | 確かめること |
|---|---|---|
| 1 | `docker compose -f onprem/docker-compose.yml config` | 展開できる。`name: naw-onprem`、ポート 18090・18091・15432 |
| 2 | `docker compose -f onprem/docker-compose.yml up -d --build` → `docker compose -f onprem/docker-compose.yml ps` | 3 サービスが `healthy` |
| 3 | `docker compose -f onprem/docker-compose.yml exec vector-db psql -U onprem_vector -d onprem_vector -c "SELECT extname, extversion FROM pg_extension ..."` と `SELECT name FROM ag_catalog.ag_graph` | `vector`・`pgroonga`・`age`、`embedding_graph` |
| 4 | `exec waha-emulator ls /mnt/file-server` と `touch` | 3 件が見える。`touch` は Read-only file system で失敗 |
| 5 | `curl -N -H "X-SERVER-AUTH-KEY: onprem-local-key" -F 'textData={...}' http://localhost:18090/api/messages/content` | `message_stop`・`message_content`（回答は質問の echo） |
| 6 | `exec server-local ls -ln /app/data/stream-output` と `cat`、エミュレーター側でも同じファイルを `cat` | 両方から同じファイル。`completed` の行がある |
| 7 | ルートの compose を確認用 override（プロジェクト名 `naw-issue301-cloud`、コンテナ名・ポート 18001 などに変更）で起動 → `alembic upgrade head` → `seed.sql`・`onprem/cloud-seed.sql` を流す → server-local を `NAW_BASE_URL=http://host.docker.internal:18001` で再作成 → `POST /auth/login` で JWT を取得 → `createLibrary: true`・`accessToken`・`tenantId` 付きでチャットを送る | backend のログに `POST /api/libraries` が出る（スタブ作成 API は未移植のため 405 想定）。server-local のログに NAW API の失敗が出る |
| 8 | ログインした JWT で backend の `GET /api/messages`（アシスタント一覧を返す API）などを呼び、社内アシスタントの endpoints を見る | `LOCAL_SERVER`・`http://localhost:18090/`・`onprem-local-key` |
| 9 | 確認の前後で `docker ps -a`・`docker volume ls` | 既存のコンテナ・ボリュームに変化なし |
| 10 | `docker compose ... down -v`（社内側・確認用クラウド側）、確認用イメージの削除 | `naw-onprem`・`naw-issue301-cloud` のコンテナ・ボリュームがない |
| 11 | `cd server-local && uv run pytest`、`cd waha-emulator && uv run pytest` | すべて成功 |
