# 08_動作確認

**ブラウザ・実機での確認は行わず、Docker で実際に起動し、curl（ブラウザが送るのと同じリクエスト）で代替した。** React（`frontend/`）には SECURE のチャット（server-local へ直接送る処理）がまだなく、ログイン画面のテナント ID 入力欄も未移植のため、ブラウザからは通せない。コードの変更はないため自動テストは追加せず、既存の server-local・エミュレーターの pytest で変更がないことを確かめた。

## 確認環境

- macOS 27.2（Apple Silicon / arm64）、Docker 29.8.2（linux/arm64）、Docker Compose v5.5.0
- LLM はエミュレーターの `echo`（既定）
- `onprem/.env` は作らずに既定値で起動した
- 既存のコンテナ（`naw-fastapi-*`・`naw-postgres` は停止中、ほかのセッションの `naw-e2e-explorer-*` は起動中）には触らず、確認の前後でコンテナ一覧を比べた

## 確認手順

1. `cd server-local && uv run pytest -q`、`cd waha-emulator && uv run pytest -q`
2. `cd onprem && docker compose up -d --build`（ボリュームが空の状態から）→ `docker compose ps`
3. ベクトルDB の拡張とグラフ、初期化のログを見る
4. エミュレーターのコンテナからファイルサーバーのディレクトリを見る・書き込む
5. server-local の `POST /api/messages/content` に SECURE のチャットを送り、ストリームファイルを両方のコンテナから見る
6. クラウド側: ルートの `docker-compose.yml` を、既存と衝突しない確認用 override（プロジェクト名 `naw-issue301-cloud`、コンテナ名 `naw-issue301-cloud-*`、backend のポート 18001。コミットしない）で起動 → `alembic upgrade head` → `backend/seed.sql`・`onprem/cloud-seed.sql` を流す
7. user01 でログインし、ブラウザと同じ流れ（ルーム作成 → メッセージ作成 → `GET /api/messages?roomId=`）で社内アシスタントの送り先を取得する
8. server-local を `NAW_BASE_URL=http://host.docker.internal:18001`（確認用 backend のポート）で作り直し、`createLibrary: true`・`accessToken`・`tenantId` 付きのチャットを送る → backend のアクセスログを見る
9. 確認の前後でコンテナ一覧を比べ、`docker compose down -v --rmi local` で両方を片付ける
