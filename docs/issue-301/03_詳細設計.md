# 03_詳細設計

## ファイル構成（新設）

```
onprem/
├── docker-compose.yml        # 社内側をまとめて起動する（プロジェクト名 naw-onprem）
├── .env.example              # 既定値を変えるときだけ .env にコピーする
├── README.md
├── cloud-seed.sql            # クラウド側 backend に流す seed（backend/seed.sql の後）
├── vector-db/
│   ├── Dockerfile            # pgvector(pg16) + PGroonga + Apache AGE
│   └── init/01-init.sql      # 拡張と AGE のグラフを作る（初回起動時）

```

ルートの `README.md` の「Waha! エミュレーター」の節の後に、`onprem/` への案内を数行足す。

## onprem/docker-compose.yml

- トップレベルの `name: naw-onprem`。`container_name` は付けない（`naw-onprem-<サービス>-1` になり、ルートの compose の `naw-fastapi-*`、単体の compose の `naw-server-local`・`naw-waha-emulator` と衝突しない）
- コメントは各サービスの 1 行だけ

| サービス | ビルド | ポート | 主な環境変数 | ボリューム | healthcheck |
|---|---|---|---|---|---|
| server-local | `../server-local`（既存の Dockerfile） | `127.0.0.1:18090:8080` | `SECURITY_SERVER_AUTH_KEY=${SERVER_LOCAL_AUTH_KEY:-onprem-local-key}`、`WAHA_URL=http://waha-emulator:8080/`、`WAHA_AUTHKEY=${WAHA_AUTHKEY:-onprem-waha-key}`、`NAW_BASE_URL=${NAW_BASE_URL:-http://host.docker.internal:8001}`、`LOG_LEVEL`、`TZ` | `server-local-data:/app/data`、`stream-output:/app/data/stream-output` | `GET /api/hello`（python の urllib） |
| waha-emulator | `../waha-emulator`（既存の Dockerfile） | `127.0.0.1:18091:8080` | `WAHA_AUTHKEY`（同上）、`LLM_PROVIDER=${LLM_PROVIDER:-echo}`、`AZURE_OPENAI_*`（API バージョンを含む）、`LOG_LEVEL`、`TZ` | `stream-output:/app/data/stream-output`、`./file-server:/mnt/file-server:ro` | 8080 への TCP 接続（エミュレーターに稼働確認 API がないため） |
| vector-db | `./vector-db` | `127.0.0.1:15432:5432` | `POSTGRES_DB/USER=onprem_vector`、`POSTGRES_PASSWORD=onprem_vector_password` | `vector-db-data:/var/lib/postgresql/data`、`./vector-db/init:/docker-entrypoint-initdb.d:ro` | `pg_isready -h 127.0.0.1`（初期化中の一時サーバーは TCP を受け付けないため、初期化が終わるまで healthy にならない） |

- server-local は `depends_on: waha-emulator (service_healthy)`。エミュレーターは今はベクトルDB を使わないため、vector-db を待たない（vector-db のビルド・起動に失敗しても SECURE のチャットは動かせる）。アダプタを取り込む Issue で、必要なら依存を足す
- server-local に `extra_hosts: host.docker.internal:host-gateway`（Linux でホストの backend を呼ぶため。単体の compose と同じ）
- `restart` は付けない（ローカル検証用。`down` まで止まらない運用は不要）
- イメージ名は `naw-onprem-server-local` 等（Compose の既定）。単体の compose の `naw-server-local:latest`・`naw-waha-emulator:latest` を上書きしない
- server-local の `user:` は付けず、イメージの uid 1000 で動かす。名前付きボリュームは初回マウント時にイメージ側のディレクトリ（uid 1000 所有）の内容・所有者で初期化されるため書き込める
- ストリームファイルの `stream-output` ボリュームは server-local の `/app/data` ボリュームの中に重ねてマウントする。エミュレーターと同じパス（`/app/data/stream-output`）で見えるため、server-local の `STREAM_WAHA_OUTPUT_DIR` は設定しない

## onprem/vector-db/Dockerfile

移植元 `generative-ai-adapter/embedding-adapter/src/test/docker/graph-db/Dockerfile` と同じ内容（基底 `pgvector/pgvector:0.8.2-pg16-bookworm`、`postgresql-16-pgdg-pgroonga=4.0.6-1`、AGE `PG16/v1.6.0-rc0` をソースからビルド）。ビルドに使ったパッケージ（コンパイラ等）は移植元では残しているが、イメージを小さくするため最後に削除する。

## onprem/vector-db/init/01-init.sql

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pgroonga;
CREATE EXTENSION IF NOT EXISTS age;
ALTER DATABASE onprem_vector SET session_preload_libraries = 'age';
ALTER DATABASE onprem_vector SET search_path = ag_catalog, "$user", public;
LOAD 'age';
SET search_path = ag_catalog, "$user", public;
SELECT create_graph('embedding_graph') WHERE NOT EXISTS (...);
```

移植元の手動検証環境の `init/01-init.sql` に `pgroonga` を足したもの（統合テスト用の `01-readiness.sql` と同じ 3 拡張）。

## onprem/cloud-seed.sql

`backend/seed.sql` の `test-tenant`・動作確認用グループ（`20000000000040008000000000000001`、user01 が所属）を前提にする。ID は他の seed と衝突しないよう Issue 番号を含める。`ON CONFLICT DO NOTHING` で冪等にする。

| テーブル | 内容 |
|---|---|
| `assistants` | `10000000000040008000000000000301`、`SECURE`、「社内アシスタント（オンプレ）」、`include_history=true` |
| `tenant_endpoints` | `30000000000040008000000000000301`、`LOCAL_SERVER`、`http://localhost:18090/`、API キー `onprem-local-key`（compose の server-local の既定の認証キー） |
| `assistants_endpoints` | 上の 2 つ。`model=onprem-chat`（ブラウザが `textData.assistantId` に入れ、server-local が Waha! のサービス ID として execute に渡す。エミュレーターでは未登録のサービス ID は仮のチャットになる） |
| `groups_assistants` | 動作確認用グループに紐付ける |

## onprem/.env.example

`SERVER_LOCAL_AUTH_KEY`・`WAHA_AUTHKEY`・`NAW_BASE_URL`・`LLM_PROVIDER`・`AZURE_OPENAI_*`・`LOG_LEVEL` を、既定値とともにコメントアウトで並べる。`.env` は既存の `.gitignore`（`.env`）で管理外。

## README

`onprem/README.md` は次の 3 節だけ。

1. 起動・停止（`docker compose up -d --build` / `docker compose down`、データも消すなら `-v`）
2. 立ち上がるもの（サービス 1 行ずつ + ファイルサーバーのディレクトリ）
3. クラウド側とのつなぎ方（ルートの compose の backend を起動 → `seed.sql` と `cloud-seed.sql` を流す。ブラウザが使う URL・API キー、server-local がライブラリのスタブ作成で呼ぶ URL）

## 確認の方法（08 で実施）

- 既存の環境に触らないよう、ルートの compose は別のプロジェクト名・コンテナ名・ポートで起動する（確認用の override ファイルを scratchpad に置き、コミットしない）。override で backend のポートを変えるため、server-local の `NAW_BASE_URL` は確認時だけ `.env` 相当の環境変数で合わせる
