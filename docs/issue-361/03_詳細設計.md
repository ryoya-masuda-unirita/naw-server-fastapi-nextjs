# 03_詳細設計

## 実装対象ファイル

| ファイル | 内容 |
|---|---|
| `frontend/src/store/auth-store.ts` | `loginWithKey` の失敗時に、ユーザー情報・`AUTH_USER`・テナントIDを消さない（ログだけ出して `false` を返す） |
| `frontend/src/lib/initializers/login-key.ts` | 認証前に上書き前のテナントIDを控え、失敗したら戻す（なければ `clearTenantId`）。`onError` を `await` する（型は `void \| Promise<void>`） |
| `frontend/src/lib/initializers/login-key-error.ts`（新規） | `notifyLoginKeyError`。i18next の初期化を待ってから `AUTH.LOGIN_KEY.ERROR` のエラートーストを出す |
| `frontend/src/main.tsx` | `runLoginKeyInitializer` に `onError: () => notifyLoginKeyError(i18n, showErrorToast)` を渡す |

## 処理

1. 初期化処理が URL の `loginkey`・`tenantId` を読み、上書き前のテナントIDを控えてから `tenantId` を保存する
2. `loginWithKey` が失敗（401）したら `false`。ストアは何も消さない
3. 初期化処理が控えたテナントIDに戻し、`onError` でトーストを出す
4. 続くセッション確認 `GET /api/auth` は元のテナントIDで通り、ログイン中のユーザーに戻る

## 補足

`/auth/login-key` の 401 は、共通のエラー処理（`shouldInvalidateSession`）でセッション破棄の対象外（`/auth/` で始まるパス）。共通のエラートーストも出ない（ログインとして扱う）ため、トーストは `onError` の 1 つだけ。
