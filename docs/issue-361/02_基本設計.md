# 02_基本設計

## 変更対象

アプリ起動時のログインキー認証。

## 画面 / API 変更概要

画面の追加はなし。失敗時にエラートーストが出る。API は変更しない。

## 影響範囲

- ログインキーでの認証が失敗したときの、ユーザー情報・テナントIDの扱い
- 起動処理（ログインキー認証 → セッション確認）の順序

## 移植方針

- 移植元は失敗時にユーザーとテナントIDを消すが、直後のセッション確認がサブドメインからテナントを補ってログイン中のユーザーに戻る。このプロジェクトはサブドメインを使わない（#193・#195）ため、消さずに保つ。結果の挙動（ログイン中のユーザーのまま・アラートが出る）は移植元と同じになる
- URL の `tenantId` の上書きを担当する初期化処理が、失敗時に上書き前の値へ戻す
- トーストは移植元と同じく、翻訳の初期化を待ってから文言を引く
