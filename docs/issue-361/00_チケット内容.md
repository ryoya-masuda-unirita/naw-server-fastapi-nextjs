# ログインキーでの認証に失敗してもログイン中のセッションを保ちアラートを出す

## 概要

ログイン中に不正なログインキーの URL を開くと、`loginWithKey` の失敗時にテナント ID を消し、続く `GET /api/auth` が 400 になってログアウトされ、アラートも出ない。移植元はセッションを保ち、失敗のアラートを出す。

## 説明

対象の項番: 03-23（`frontend/src/store/auth-store.ts`・`frontend/src/main.tsx`。失敗時のトーストを渡していない点も）。テナント識別にサブドメインは使わない方針は変えない。

結合テスト項目書の E2E（#316、`e2e-spec/`）で見つかった、移植元との本当の差。原因・移植元の挙動・見立ては `docs/issue-316/ng-ログイン.md` の「原因 B」。
