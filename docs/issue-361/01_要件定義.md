# 01_要件定義

## 背景

ログイン中に不正なログインキー付きの URL を開くと、ログイン中のユーザーのままでいられず、ログイン画面に戻される。また、失敗を知らせるアラートも出ない。移植元は、ログイン中のユーザーのままサービスを使え、「不正なログインキーです」のアラートが出る。

## 機能要件

- ログインキーでの認証に失敗しても、ログイン中のセッション（ユーザー情報・テナントID）を壊さない
- URL の `tenantId` で一時的に上書きしたテナントIDは、失敗したら上書き前に戻す（上書き前がなければ消す）
- 失敗したら、翻訳 `AUTH.LOGIN_KEY.ERROR`（「不正なログインキーです」）のエラートーストを出す
- 未ログインで失敗した場合は、従来どおりログイン画面になる（03-22）

## 非機能要件

- アプリ起動直後でも、翻訳が読み込まれる前のキー文字列をトーストに出さない

## スコープ外

- サブドメインによるテナント識別（廃止した方針のまま）
- ログインキー成功時の挙動
