# 04_テスト設計

## テスト方針

自動テスト（API 経由の結合テスト・SQL 生成の単体テスト）で確認する。ローカルの DB・サーバーは共有環境のため使わない。テスト用 DB（SQLite）は列挙型を文字列で保持するため、PostgreSQL 固有の権限順は生成される SQL で確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 同値キーの昇降反転 | 更新日時が同じユーザーが複数いる状態で、更新日時順の昇順・降順を取得する | 降順の並びが昇順の完全な逆順になる |
| 2 | 権限順の昇降 | 管理者 1 名と一般ユーザー複数名で、権限順の昇順・降順を取得する | 昇順は管理者が先頭、降順は管理者が末尾で、並びが完全に反転する |
| 3 | 方向の大文字小文字 | 表示名順を大文字の降順指定で取得する | 降順で並ぶ |
| 4 | 権限順の SQL | 権限順のソート列を PostgreSQL 方言で SQL に変換する | 権限を文字列にキャストした式になる |
| 5 | 既存挙動の回帰 | 既存のユーザー一覧テスト一式を実行する | すべて成功する |
