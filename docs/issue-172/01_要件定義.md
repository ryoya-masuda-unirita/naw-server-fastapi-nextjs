# 01_要件定義

## 背景

- 管理コンソール「ユーザー管理」一覧で並べ替えを操作しても表示順が変わらない（または読み込みごとに不定になる）と報告された
- 調査の結果、Issue 起票時の原因記載（「ソートパラメータを受け取らず ORDER BY が無い」）は誤りだった。ユーザー一覧 API はすでに `sort` クエリパラメータ（`{キー},{asc|desc}`）を受け取り、ORDER BY を組み立てている（Issue #119 で実装済み）。並べ替え処理はリポジトリ層ではなくサービス層にあったため、見落とされたと考えられる
- 一方で、次の不具合があり、並べ替えを切り替えても表示順が変わらない・不定になる症状を説明できる
  1. ソートキーが同値の行（シード投入で同時刻になる更新日時、大半のユーザーが同じ「一般」の権限など）に対して並びを決めるキーが無い。同値グループ内の順序は DB 任せになり、昇順と降順を切り替えても反転しない。自動テストで、更新日時が同値のユーザー群では `updatedAt,asc` と `updatedAt,desc` の結果が完全に一致することを確認した
  2. 権限順の並びが移植元と逆になる。移植元は権限を文字列カラムで持つため「管理者 → 一般」の文字列順で並ぶが、こちらは PostgreSQL の列挙型で持っており、宣言順（一般 → 管理者）で並ぶ
  3. ソート方向の指定で大文字小文字を区別している（移植元は区別しない）
- フロントエンド（`frontend-angular`）は `sort={updatedAt|name|role|totalCredits},{asc|desc}` と `includeUsage=true` を送っており、移植元 Spring Boot の `GET /api/admin/users`（`Pageable` の `sort`）と一致している。フロントエンド側に問題は無い

## 機能要件

- 並べ替えキー（更新日時・ユーザー表示名・権限・利用クレジット）と方向（昇順・降順）の組み合わせで、一覧の並びが決定的に定まること
- 同じキーで昇順と降順を切り替えると、一覧の並びが完全に反転すること（同値の行を含む）
- 権限順は移植元と同じく文字列順（管理者 → 一般）を昇順とすること
- ソート方向は大文字小文字を区別せずに解釈すること
- 既存の挙動（キーのエイリアス、許可リスト外キーのフォールバック、利用クレジット順の副次ソート、`includeUsage` との組み合わせ検証）は変えないこと

## 非機能要件

- DB マイグレーションを追加しないこと
- 一覧取得のクエリ回数を増やさないこと

## スコープ外

- 他の一覧 API（テンプレート・チーム所属ユーザー等）の並べ替え（それぞれ別 Issue で対応する）
- フロントエンドの変更
- 複数キーのソート指定（`sort` パラメータの繰り返し指定）への対応（フロントエンドは単一キーしか送らないため）
