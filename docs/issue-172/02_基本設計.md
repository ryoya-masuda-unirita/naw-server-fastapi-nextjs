# 02_基本設計

## 変更対象

- バックエンドのユーザー管理サービス（ユーザー一覧取得の並び順組み立て）
- 対応する自動テスト

## 画面 / API 変更概要

- 対象 API: ユーザー一覧取得（管理者向け）
- リクエスト・レスポンスの形式は変更しない
- 並び順の変更点
  - すべての並べ替えで、最後のキーとしてユーザー ID を主キーと同じ方向で加える。同値の行も含めて並びが決まり、降順は昇順の完全な逆順になる
  - 権限順は列挙型を文字列に変換してから並べ、移植元と同じ文字列順にする
  - ソート方向は大文字小文字を区別せずに `desc` を降順、それ以外を昇順と解釈する

## 影響範囲

- ユーザー管理一覧画面の並び順（同値の行の並びが決定的になる。権限順の昇降が移植元と同じになる）
- 同じ API を使う画面（テナント設定の利用状況タブのユーザー選択、チームへのユーザー追加候補など）も、同値の行の並びが決定的になる。並びの主キーは変わらない
- チーム所属ユーザー一覧は別の処理のため影響しない

## 移植方針

- 移植元 Spring Boot は `Pageable` の `sort` に指定された User エンティティのプロパティでソートし、利用クレジット順のときだけ請求期間内クレジット合計のサブクエリ＋表示名昇順で並べる。これらのキーと方向の仕様は現行実装で移植済みのため維持する
- 移植元は同値の行の並びを決めていない（DB 任せ）。こちらで最終キーを加えても、移植元で起こりうる並びの一つに確定させるだけなので、移植元の API 仕様からは外れない
- 移植元の権限カラムは文字列型（`varchar(32)`）のため、文字列順で並べる挙動に合わせる
