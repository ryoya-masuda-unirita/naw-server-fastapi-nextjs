# 02_基本設計

## 変更対象

- 新規ドメイン: プラン（マスタ、全テナント共有）
- 新規ドメイン: サブスクリプション（テナント単位の契約情報）
- 新規ロジック: 請求サイクルの起算日算出（次回リセット日時・現在の請求期間開始日時の算出）
- 新規API: クレジット利用状況（本人用・テナント全体用）の2エンドポイント

## 画面 / API 変更概要

- `GET /api/credit-usage/me`: ログインユーザー本人の当該請求期間内クレジット利用合計・期間・次回リセット日時を返す
- `GET /api/credit-usage/workspace`: テナント全体の当該請求期間内クレジット利用合計・クレジット上限・期間・次回リセット日時を返す
- いずれもテナントに有効な契約が存在しない場合は空のレスポンスを返す（フィールドは全てnull相当、レスポンスボディに含めない）

## 影響範囲

- 新規テーブル追加（プラン・サブスクリプション）によるマイグレーション追加
- 既存のトークン利用集計ロジック（クレジット合計算出）を読み取り専用で再利用する
- 既存のテナント情報（従量課金クレジット上限）を読み取り専用で参照する
- 既存のルーター登録一覧に新規ルーターを追加する

## 移植方針

- 移植元のControllerとServiceの責務をそのまま踏襲しつつ、本リポジトリのrouter:service 1対1規約に合わせて実装する
- 移植元で複数機能から共用されているクレジット集計ロジックのうち、本Issueに必要な最小範囲（有効な請求期間の解決・請求期間内クレジット合計の取得）のみを移植する
- 請求サイクルの起算日算出ロジックは、他のサービスに依存しない純粋な計算ロジックとして独立したモジュールに実装する
- 既存のトークン利用量集計の仕組み・テナント情報取得の仕組みをそのまま流用し、重複した実装を作らない
