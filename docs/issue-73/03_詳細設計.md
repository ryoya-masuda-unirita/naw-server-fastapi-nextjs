# 03_詳細設計

## 新規テーブル

### `plans`（プランマスタ、全テナント共有・`tenant_id`なし）

| カラム | 型 | 制約 |
|---|---|---|
| id | varchar(32) | PK |
| name | varchar(255) | NOT NULL |
| max_users | int | NOT NULL |
| max_credits_per_month | bigint | NULL可（移植元DBはNOT NULLだが、Java側`resolveCreditLimit`がnullを許容して分岐しているため、将来の柔軟性を考慮しNULL許容とする） |

移植元: `~/Documents/naw-server/src/main/resources/liquibase/changelog/plans/changeset-001-init-table.xml`, `changeset-002-rename-max-credits-per-month.xml`

### `subscriptions`（テナントごとの契約）

| カラム | 型 | 制約 |
|---|---|---|
| id | varchar(32) | PK |
| tenant_id | varchar(32) | NOT NULL, FK→tenants.id ON DELETE CASCADE |
| plan_id | varchar(32) | NOT NULL, FK→plans.id ON DELETE RESTRICT |
| status | varchar(32)（Enum: ACTIVE, CANCELLED, EXPIRED, PENDING, TRIAL） | NOT NULL |
| start_date | date | NOT NULL |
| end_date | date | NULL可 |
| created_at | timestamptz | NOT NULL, server_default now() |
| updated_at | timestamptz | NOT NULL, server_default now(), onupdate now() |

インデックス: `tenant_id`（有効サブスクリプション検索用）

移植元: `~/Documents/naw-server/src/main/resources/liquibase/changelog/subscriptions/changeset-001〜003`

**RLSについて**: 移植元ではPostgreSQLのRLSポリシーを`subscriptions`に設定しているが、本リポジトリの既存実装（`token_usages`, `user_import_jobs`等）はPostgreSQL RLSポリシーを使わず、リポジトリ層でのクエリ条件（`tenant_id ==`絞り込み）によるテナント分離を採用している。既存実装との一貫性を優先し、本Issueでも同様にリポジトリ層での明示的な`tenant_id`絞り込みで対応する（RLSポリシーは追加しない）。

## 実装対象ファイル

### モデル

- `backend/app/models/plan.py`（新規）: `Plan` SQLModel
- `backend/app/models/subscription.py`（新規）: `SubscriptionStatus` Enum、`Subscription` SQLModel

### リポジトリ

- `backend/app/repositories/subscription_repository.py`（新規）:
  - `find_active_by_tenant_id_with_plan(tenant_id, today, session) -> Subscription | None`
    - `status == ACTIVE AND (end_date IS NULL OR end_date >= today)` を満たす行を`created_at DESC`で1件取得（`selectinload(Subscription.plan)`でN+1を避けEager Load）

### core（純粋ロジック）

- `backend/app/core/billing_cycle.py`（新規）: 移植元`SubscriptionBillingCycle`相当
  - `current_billing_reset_instant_utc(contract_start: date, now_utc: datetime) -> datetime | None`
  - `next_billing_reset_instant_utc(contract_start: date, now_utc: datetime) -> datetime | None`
  - 内部ヘルパー `_next_boundary_exclusive(period_start: date, base_day: int) -> date`
  - Java版の`LocalDate`/`YearMonth`をPythonの`datetime.date`+`calendar.monthrange`で書き直す

### サービス

- `backend/app/services/credit_usage_service.py`（新規、router:service 1対1）:
  - `resolve_active_billing_period(tenant_id, session) -> tuple[Subscription, datetime, datetime] | None`
    - 有効サブスクリプションがなければ`None`
    - あれば `(subscription, period_from, period_to)` を返す。`period_from = current_billing_reset_instant_utc(subscription.start_date, now)`, `period_to = now`
  - `get_my_credit_usage(tenant_id, current_user, session) -> MyCreditUsageResponse`
    - 有効請求期間がなければ全フィールドNoneの空レスポンス
    - あれば`TokenUsageRepository.summarize(tenant_id, period_from, period_to, user_id=current_user.id, session)`でtotalCredits算出、`next_billing_reset_instant_utc`でnextBillingResetAt算出
  - `get_workspace_credit_usage(tenant_id, session) -> WorkspaceCreditUsageResponse`
    - 有効請求期間がなければ全フィールドNoneの空レスポンス
    - あれば`TokenUsageRepository.summarize(tenant_id, period_from, period_to, user_id=None, session)`でテナント全体totalCredits算出
    - `creditLimit = plan.max_credits_per_month + tenant.max_usage_based_credits_per_month`（`plan.max_credits_per_month`がNoneならcreditLimitはNone）。テナント取得は既存`TenantRepository.find_by_id`を流用

### ルーター

- `backend/app/routers/credit_usage.py`（新規）:
  - `GET /api/credit-usage/me` → `Depends(get_verified_tenant_id)`, `Depends(get_current_user)`, `response_model=MyCreditUsageResponse`, `response_model_exclude_none=True`
  - `GET /api/credit-usage/workspace` → 同上、`response_model=WorkspaceCreditUsageResponse`

### スキーマ

  - `WorkspaceCreditUsageResponse`: 上記 + `creditLimit: int | None`
