# 08_動作確認

## 確認環境

**本Issueは全自動モードで対応しており、ブラウザ操作による動作確認は行っていない。自動テスト（pytest）の実行結果をもって動作確認の代替とする。**

- Python 3.14 / FastAPI（`uv run pytest`）
- テスト用DB: SQLite（インメモリ、`tests/integration/conftest.py`）

## 確認手順

```bash
cd backend
uv run pytest -q
uv run ruff check app/ tests/
```

## 確認結果

- `uv run pytest -q`: **502 passed**（新規追加分: 単体テスト6件`tests/unit/test_billing_cycle.py`、結合テスト8件`tests/integration/test_credit_usage.py`を含む。既存テストの回帰なし）
- `uv run ruff check app/ tests/`: **All checks passed!**
- `uv run mypy`: 新規追加ファイル（`subscription_repository.py`等）で、SQLModelの`Field`記述子を`mypy`が正しく認識できないことに起因する型エラーが検出されるが、これは既存の`user_repository.py`・`group_user_repository.py`等でも同一パターンで発生している既知の（新規実装固有ではない）問題であることを確認済み（`git stash`で未変更の`user_repository.py`単体を`mypy`にかけて再現を確認）。本Issueによる新規の型崩れではない。

### 結合テストで確認した主なシナリオ

- `GET /api/credit-usage/me`: 有効サブスクリプションありでの本人利用実績の合計取得、有効サブスクリプションなしでの空レスポンス（`{}`）、`X-Tenant-ID`未指定時のエラー、未認証時の401
- `GET /api/credit-usage/workspace`: 有効サブスクリプションありでのテナント全体利用実績の合計取得、`creditLimit`（`Plan.maxCreditsPerMonth + Tenant.maxUsageBasedCreditsPerMonth`）の算出、`Plan.maxCreditsPerMonth`がNULLの場合の`creditLimit`省略、有効サブスクリプションなしでの空レスポンス、`end_date`が過去のサブスクリプションが無効として扱われること

### 実PostgreSQL環境でのマイグレーション・シード確認

`docker compose up -d` でローカルPostgreSQLを起動し、以下を確認した。

```bash
cd backend
uv run alembic upgrade head
docker exec -i naw-fastapi-postgres psql -U root -d postgres < seed.sql
```

- `alembic upgrade head`: `018 -> 019`（`plans`・`subscriptions`テーブル作成）が正常に適用されることを確認
- `seed.sql`: `plans`に`plan-standard`、`subscriptions`に`test-tenant`向けの`ACTIVE`なサブスクリプション（`start_date`=当月1日）が冪等に登録されることを確認（`SELECT`で実データを確認済み）
