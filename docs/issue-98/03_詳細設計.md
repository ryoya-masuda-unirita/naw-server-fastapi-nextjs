# 03_詳細設計

## 実装対象ファイル

### `backend/app/core/llm_client.py`

- `ToolConfig` dataclass（frozen）を新規追加する。`core/` は `schemas/` に依存しない既存レイヤー規約を踏襲し、`schemas.message.ToolConfig`（Pydanticモデル）とは別に、呼び出しクライアントが必要とする最小限のフィールドだけを持つ軽量なdataclassとして定義する（`ChatMessage`と同じ設計方針）。
  - フィールド: `name: str`, `server_label: str | None`, `server_url: str | None`, `require_approval: str | None`, `authorization: str | None`, `headers: dict[str, str] | None`, `allowed_tools: list[str] | None`
- `AZURE_OPENAI_RESPONSES_API_VERSION` 定数を追加する（Responses APIに対応するプレビューAPIバージョン。Chat Completions用の `AZURE_OPENAI_API_VERSION` とは別定数にする理由をコメントに明記）。
- `_build_responses_tool(tool: ToolConfig) -> dict` 関数を追加する。移植元 `OpenAiLlmChatAdapter.toTool` / `buildMcpTool` 相当。
  - `name == "web_search"` → `{"type": "web_search"}`
  - `name == "mcp"` → `{"type": "mcp", "server_label": ..., "server_url": ..., ("authorization": ... if 指定), ("headers": ... if 指定), ("allowed_tools": ... if 指定), ("require_approval": ... if 指定)}`
  - それ以外 → `ValueError`（スキーマのバリデーションで通常到達しない防御的分岐）
- `AzureLlmChatClient.stream_chat` に `tools: list[ToolConfig] | None = None` 引数を追加する（デフォルト `None` で既存呼び出し元との後方互換を保つ）。
  - `tools` が `None` または空の場合: 既存のChat Completions API呼び出しをそのまま実行する（変更なし）。
  - `tools` が指定されている場合: 新設する `_stream_chat_responses_api` へ委譲し、Responses API（`client.responses.create(..., stream=True)`）を呼び出す。
    - `input`: `[{"role": m.role, "content": m.content} for m in messages]`
    - `tools`: `[_build_responses_tool(t) for t in tools]`
    - `max_output_tokens`: `max_tokens`（指定時のみ）
    - `temperature`: 呼び出し元から渡された値をそのまま設定
    - ストリーミングイベントをイテレートし、`event.type == "response.output_text.delta"` で `ChatStreamChunk(text_delta=event.delta)` を、`event.type == "response.completed"` で `event.response.usage` から `ChatStreamChunk(input_tokens=..., output_tokens=...)` をyieldする。

### `backend/app/schemas/llm.py`

- `LlmChatRequest` に `tools: list["ToolConfig"] | None = None` を追加する。`ToolConfig` は `schemas/message.py` の既存定義（issue-93で実装済み）を再利用し、`from app.schemas.message import ToolConfig` でインポートする。
- クラスdocstringから「tools（Function Calling）...は対象外」の記述を削除する。

### `backend/app/schemas/message.py`

- `MessageContentCreateRequest` に `tools: list[ToolConfig] | None = None` を追加する。
- クラスdocstringの「本Issueのスコープでは...tools...は対象外」から `tools` を削除する（他の既存スコープ外記述はissue-98の対象外のため変更しない）。

### `backend/app/services/llm_chat_service.py`

- `LlmChatService.stream_chat` 内、`AzureLlmChatClient.stream_chat` 呼び出しに `tools=_to_core_tool_configs(req.tools)` を追加する。
- `_to_core_tool_configs(tools: list[SchemaToolConfig] | None) -> list[CoreToolConfig] | None` をモジュールレベルのプライベート関数として追加し、`schemas.message.ToolConfig` → `core.llm_client.ToolConfig` へ変換する。
- モジュールdocstringから「tools（Function Calling）...は対象外」を削除する。

### `backend/app/services/message_service.py`

- `MessageService.stream_message_content` 内、`AzureLlmChatClient.stream_chat` 呼び出し（SAAS_CHAT・SAAS_RAG共通の1箇所）に `tools=_to_core_tool_configs(req.tools)` を追加する。
- `_to_core_tool_configs` を `llm_chat_service.py` と同内容でこのファイル内にも追加する（「serviceが別serviceを呼ばない」規約により複製する。既存の `_sse` / `_apply_additional_prompt` と同じ扱い）。
