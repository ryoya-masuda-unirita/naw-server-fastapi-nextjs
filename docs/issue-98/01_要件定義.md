# 01_要件定義

## 背景

- チャット送信API・メッセージ送信APIの両方で、tools（Function Calling: web_search / mcp）は issue-88・issue-93 の時点で意図的にスコープ外とされていた。
- 移植元（Spring Boot）実装を調査した結果、tools の実体は「独自のFunction Calling実装」ではなく、Azure OpenAI **Responses API** が提供する組み込みツール（built-in tools）の宣言をそのまま渡しているだけと判明した。
  - `web_search`: `{"type": "web_search"}` を渡すだけ。独自のBing検索APIコール等は一切実装していない。
  - `mcp`: MCPサーバーへの接続・プロトコル実装・tool一覧取得はすべてAzure OpenAI（OpenAI Responses API）側に委譲している。移植元は `server_label` / `server_url` / `authorization` / `headers` / `allowed_tools` / `require_approval` をそのままツール定義として渡すのみ。
  - ストリーミング中もtool呼び出しの中間イベント（tool呼び出し開始・実行結果等）をクライアントへ個別通知しておらず、最終テキストへ織り込まれた形でテキストデルタとして配信されるのみ。
- 一方、FastAPI側の現行実装（issue-88・issue-93で移植済み）は Python公式`openai`SDKの **Chat Completions API**（`chat.completions.create`）を使用している。Chat Completions APIには`web_search`/`mcp`のような「OpenAI側がサーバーサイドで実行を管理する組み込みツール」という概念自体が存在しないため、tools対応には Responses API 呼び出しへの切り替え（少なくとも tools 指定時のみの分岐追加）が前提となる。

## 機能要件

- チャット送信API（`/api/llm/chat`、`LlmChatRequest`）に `tools` を追加し、指定時は Responses API 経由で `web_search` / `mcp` ツールを有効にしてLLMを呼び出す。
- メッセージ送信API（`/api/messages/content`、`MessageContentCreateRequest`）に `tools` を追加し、指定時は同様に Responses API 経由でツールを有効にしてLLMを呼び出す。SAAS_CHAT・SAAS_RAGの両アシスタントタイプに適用する。
- `tools` 未指定・空リストの場合は、既存どおり Chat Completions API を使用する（既存の挙動・既存テストへの影響を避けるため）。
- `tools` の要素は `name`（`web_search` または `mcp`）、mcpの場合は `server_label` / `server_url` が必須、任意で `authorization` / `headers` / `allowed_tools` / `require_approval`（`never` または `always`）を指定できる。バリデーション内容は移植元・既存の `schemas/message.py` の `ToolConfig` を踏襲する（`ToolConfig` 自体は issue-93 で既に実装済みのため新規追加は不要）。
- `authorization` / `headers` は秘密情報のため、既存どおり永続化・レスポンス出力しない（受信のみ）。
- ストリーミング中のtool呼び出しに対する専用SSEイベントは追加しない。移植元同様、tool呼び出しは透過的に扱い、最終テキストのストリーミングデルタ・トークン使用量集計のみ既存イベント（`text_delta` / `message_stop` / `error` / `complete`）で扱う。

## 非機能要件

- `tools` 未指定時の既存の応答性能・挙動（Chat Completions APIでの呼び出し）に影響を与えないこと。
- Responses API呼び出し時も、既存同様にトークン使用量（入力・出力）をクレジット換算し永続化すること。

## スコープ外

- MCPサーバー自体への直接接続・MCPプロトコルのクライアント実装（Azure OpenAI側に委譲するため不要）。
- web_search の検索結果を独自にカスタマイズする機能（Azure OpenAI組み込みのweb_search機能をそのまま利用する）。
- ストリーミング中のtool呼び出し過程（検索中・MCP呼び出し中等）をクライアントへ個別のSSEイベントとして通知すること（移植元も対応していないため踏襲しない）。
- tool呼び出し履歴（呼び出したtool名・引数・実行結果）の永続化（移植元も対応していない）。
- メッセージ再生成時に前回送信の `tools`（`messages.tools`列。issue-93で実装済み）を自動的に読み込んで再適用する機能。移植元同様、`tools` はメッセージ送信APIのリクエストごとに都度指定する方式とする（クライアント側でUIに前回値を復元して再送する想定）。
