# 01_要件定義

## 背景

テナント管理者がワークスペース（テナント）の名前を変え、請求期間内のクレジット利用状況を見て、ローカルサーバー（Waha!）向けの API 接続先を管理する画面。`/admin/tenant` は `RequireTenantAdmin`（#277 で設定済み）。

## 機能要件

- ヘッダー: タイトルはテナント名、鉛筆アイコンで名称変更ダイアログ、タブ「利用状況」「API設定」。タブは `?tab=usage|api` で保持（未指定・不正値は `usage`）
- 利用状況タブ
  - 利用プラン情報: ドーナツ（請求期間内の利用合計 / 月間上限）、契約中のコース、請求期間（`from 〜 to`。UTC の日付）、請求期間内の利用状況
  - 今月の利用履歴: 利用者の絞り込み（全ユーザー + 500 件までのユーザー）、並べ替え（利用日時順・利用量。昇順・降順）、件数表示と上下のページ送り（1 ページ 5 件）、利用日時・利用量・利用者名の表
  - ワークスペース・ユーザーの利用制限パネルと上限編集ダイアログ（移植元でテンプレートがコメントアウトされており、画面には出ない。後述）
- API設定タブ
  - 「APIを追加」（作成ダイアログ: 表示名・接続先（Local Server 固定）・URL・API キー（「生成」で 32 文字の英数字、生成後は「コピー」））
  - 設定済み API の表（表示名・接続先・URL・API キー `*****`）。`LOCAL_SERVER` だけ「APIの設定を編集」「APIを削除」のメニュー、それ以外は無効の歯車
  - 編集ダイアログ（接続先は変更不可）、削除確認ダイアログ
  - 作成・更新・削除の成功・失敗はトースト（`TENANT.*`）
- 名称変更ダイアログ: 空（空白のみも）では保存できない。保存の成功・失敗はトースト

## 非機能要件

- 文言は既存の i18n 辞書のキーのみ（キーは足さない）。移植元が日本語をハードコードしている箇所（API 追加ダイアログ・上限編集ダイアログの一部）は移植元どおり
- 共通 UI（#278）・API パス/型（#279）を使い、共通ファイルの変更は最小限

## スコープ外

- backend の修正（応答の形の差は画面側で吸収、または docs に記載）
- `PATCH /api/admin/tenants/{id}/usage-limit` の backend 実装（#281 で「作らない」と判断済み）
