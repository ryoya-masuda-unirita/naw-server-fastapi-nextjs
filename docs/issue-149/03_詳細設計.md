## 詳細

### `backend/app/models/tenant_endpoint.py` / `backend/app/models/ai_model.py`

- `EndpointType`・`AIModelEndpointType`それぞれに`BEDROCK_CHAT = "BEDROCK_CHAT"`を追加する
- `tenant_endpoints.endpoint`には、Bedrock Mantleのエンドポイント（リージョンを含む、
  例: `https://bedrock-mantle.ap-northeast-1.api.aws/anthropic`）を登録する運用とする
- `tenant_endpoints.api_key`には、Bedrock API key（Bearerトークン）を登録する

### `backend/app/repositories/ai_model_repository.py`

- `find_by_name(name: str, session: AsyncSession) -> AIModel | None`を追加する
  （`endpoint_type`による絞り込みをせず、モデル名のみで検索する）
- 既存の`find_by_endpoint_type_and_name`は他の用途（現状は呼び出されていないが、
  将来同名モデルが複数プロバイダに存在する場合の明示的な絞り込み用）として残す

### `backend/app/core/llm_client.py`

`BedrockLlmChatClient`を新規追加する。

- `stream_chat(endpoint, api_key, model_id, messages, temperature, max_tokens, tools=None) -> AsyncIterator[ChatStreamChunk]`
  - `anthropic.AsyncAnthropic(base_url=endpoint, api_key=api_key)`を`async with`で生成する
    （Bedrock Mantleのbearerトークン方式は、SigV4署名を行う専用クライアントを使わず、
    標準の`Anthropic`クライアントに`base_url`とAPIキーを指定するだけで利用できる）
  - `messages`のうち`role == "system"`の発話は連結してAnthropic Messages APIの`system`
    パラメータへ変換し、残りの発話（user/assistant）のみを`messages`パラメータへ渡す
    （AnthropicのMessages APIはOpenAI系と異なり、システムプロンプトを`messages`配列に
    含めず別パラメータとして受け取るため）
  - `max_tokens`は必須パラメータのため、呼び出し元で`None`の場合は`ai_models.max_tokens`
    にフォールバックする（呼び出し元の`llm_chat_service.py`側で解決してから渡す）
  - `client.messages.stream(...)`の非同期コンテキストマネージャでストリーミングを開始し、
    `content_block_delta`イベント（`delta.type == "text_delta"`）からテキスト差分を、
    `message_start`イベントの`usage.input_tokens`、`message_delta`イベントの
    `usage.output_tokens`から利用量を取得して`ChatStreamChunk`に変換する
  - `tools`が指定された場合は`ValueError`を送出する（Bedrock Mantleはサーバーサイドの
    web_search/mcp組み込みツールに対応していないため。呼び出し元の`try/except`で
    SSEの`error`イベントに変換される既存の仕組みをそのまま使う）
  - `response_format`（構造化出力）のAzure相当パラメータは持たない
    （`llm_chat_service.py`側の汎用的なJSON出力指示の前置きのみで対応する）

### `backend/app/services/llm_chat_service.py`

- `AIModelRepository.find_by_endpoint_type_and_name(AIModelEndpointType.AZURE_OPENAI_CHAT, ...)`
  を`AIModelRepository.find_by_name(req.deployName, session)`に置き換える
- 取得した`ai_model.endpoint_type`に応じて、テナントエンドポイントの検索条件
  （`EndpointType.AZURE_OPENAI_CHAT`または`EndpointType.BEDROCK_CHAT`）と、呼び出す
  クライアント（`AzureLlmChatClient`または`BedrockLlmChatClient`）を分岐する
- `AIModelEndpointType.AZURE_OPENAI_CHAT`以外（今回は`BEDROCK_CHAT`）の場合、
  `tools`指定・`response_format`指定は非対応である旨を明確にする
  （Bedrock側は`tools`指定時に`BedrockLlmChatClient`が`ValueError`を送出する）
- `_persist_token_usage`の`endpoint_type=AIModelEndpointType.AZURE_OPENAI_CHAT.value`
  固定を、実際に呼び出した`ai_model.endpoint_type.value`を使うよう修正する

### `backend/seed.sql`

- 既存の`claude-3-5-sonnet`の`ai_models`行（`CLAUDE_CHAT`）とは別に、`BEDROCK_CHAT`の
  `ai_models`行（例: `anthropic.claude-sonnet-5`）と、対応する`tenant_endpoints`行
  （ダミーのBedrock Mantleエンドポイントとダミー API key）を追加する

## 移植元との対応整理

移植元（Spring Boot）にBedrock関連の実装は無いため対応表なし。既存の`AzureLlmChatClient`
との対比のみ記載する。

| Azure OpenAI | Bedrock |
|---|---|
| `AsyncAzureOpenAI`（openai公式SDK） | `AsyncAnthropic`（anthropic公式SDK） |
| `azure_endpoint` + `api_key` + `api_version` | `base_url` + `api_key`（api_versionは不要） |
| Chat Completions API / Responses API（tools用） | Messages API（1種類。toolsは非対応） |
