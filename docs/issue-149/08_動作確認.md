# 08_動作確認

## 確認環境

- `docker compose up -d postgres`でPostgreSQLをローカル起動（既存稼働中のコンテナを利用）
- `uv run alembic upgrade head`でマイグレーション適用（`023_add_bedrock_chat_endpoint_type`含む）
- `docker exec -i naw-fastapi-postgres psql -U root -d postgres < backend/seed.sql`でシードデータ投入
  （Bedrock用の`ai_models`・`tenant_endpoints`行を含む）
- `uv run uvicorn app.main:app --host 0.0.0.0 --port 8001`でbackendをローカル起動
- ユーザーが実際に発行したAWS Bedrock API key（Bearerトークン）・エンドポイント
  （`https://bedrock-mantle.ap-northeast-1.api.aws/anthropic`）を`tenant_endpoints`に設定
- 確認方法: ブラウザ（frontend-angular）ではなく、AIエージェントが`curl`でAPIを直接呼び出して確認した

## 確認手順・結果

### Step 1: ログインしてセッションを確立

`POST /auth/login`（`admin`/`admin@1234`、`X-Tenant-ID: test-tenant`）を実行。

✅ 200が返り、`session_id` Cookieが発行された（issue-147で実装済みの認証機構）

### Step 2: チャットAPIをBedrock経由で呼び出す

`POST /api/llm/chat`に`deployName: "anthropic.claude-haiku-4-5"`を指定して実行。

```
event: error
data: {"message": "Error code: 403 - {'type': 'error', 'request_id': '...', 'error': {'type': 'permission_error', 'message': 'anthropic.claude-haiku-4-5 is not available for this account. ...'}}"}
```

✅ ログイン・セッション認証・`BedrockLlmChatClient`への分岐・実際のBedrock Mantleエンドポイントへの
   HTTPS呼び出し・エラー時のSSE `error`イベントへの変換まで、パイプライン全体が正しく動作することを
   確認した
❌ 実際のテキスト応答の取得は未確認（AWSアカウント側でこのモデルへのアクセス許可が
   下りていないため、`permission_error`で終了した）

### 補足調査: モデルIDの形式

AWSコンソールのモデルカタログには`anthropic.claude-haiku-4-5-20251001-v1:0`という、日付・バージョン
付きの形式（従来の`InvokeModel`/`Converse` API用）が表示されていたが、これは`ai_models.name`
（`VARCHAR(32)`、40文字必要）に収まらずDB投入時にエラーになった。一方、Bedrock Mantle
（`/anthropic/v1/messages`）向けの短い形式`anthropic.claude-haiku-4-5`はAPI側に認識されており
（`permission_error`という具体的なエラーが返ったため、モデルID自体は不正扱いされていない）、
短い形式が正しいIDであると判断した。
