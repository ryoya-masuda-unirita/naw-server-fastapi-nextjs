## 3. API クライアント（`frontend/src/lib/api-client.ts`）

| 機能 | 実装 |
|---|---|
| メソッド | `get`・`post`・`put`・`patch`・`delete(path, { body })`。内部で `request(method, path, options)` に寄せる |
| オプション | `ApiRequestOptions`（`RequestInit` から `body`・`method`・`headers` を除いたもの + `params`・`headers`・`responseType`・`skipGlobalErrorToast`・`skipSessionInvalidation`）。独自キーは `toRequestInit` で取り除いて fetch に渡す |
| クエリ | `QueryParams = Record<string, 値 | 値[] | null | undefined>`。配列は `append` を繰り返す。`undefined`・`null` は送らない（移植元は `undefined` のみ除外。`null` を文字列 "null" で送る意味がないため除外を広げた） |
| ベース URL | 既存どおり。`/auth/` で始まるパスは `VITE_AUTH_API_URL`、それ以外は `VITE_API_URL`。`http(s)://` で始まる絶対 URL はベース URL を付けない |
| ヘッダー | JSON の本文があるときだけ `Content-Type: application/json`。`X-Tenant-ID` は既存どおり（絶対 URL にも付ける。移植元の authInterceptor が全リクエストに付けるのと同じ）。呼び出し側の `headers` が最後に上書きする |
| 本文 | `FormData`・`Blob`・`URLSearchParams`・`ArrayBuffer` はそのまま、それ以外は `JSON.stringify`。`null`・`undefined` は本文なし |
| 応答 | `responseType` が `text` → 文字列、`blob` → Blob、既定 `json` → 204・空の本文は `null`（Angular HttpClient と同じ） |
| credentials | 既定 `include`。オプションで上書きできる |
| エラー | `ApiError`（`status`・`body`・`method`・`path`、`message` は `HTTP {status}`）。fetch 自体の失敗は `status: 0`（呼び出し側の中断（`signal.aborted`）は元の例外のまま投げ、通知もしない）。投げる前に登録済みのハンドラー（`setApiErrorHandler`）へ `{ error, skipGlobalErrorToast, skipSessionInvalidation }` を渡す。絶対 URL は `skipSessionInvalidation: true` 扱い |
| SSE | `apiClient.stream(path, { method = 'POST', body, headers, credentials })` が `Response` を返す。エラー時は `ApiError` を投げるがハンドラーは呼ばない（移植元の fetch 直呼びはインターセプターを通らないため） |

## 4. エラー処理（`frontend/src/lib/api-error-handler.ts`・`frontend/src/hooks/use-api-error-interceptor.ts`）

- 移植元 `core/interceptors/error.interceptor.ts` の判定を純粋関数にした
  - `resolveErrorMessageKey(status)`: 403 → `COMMON.MESSAGES.ERROR.FORBIDDEN`、404 → `NOT_FOUND`、500 以上 → `SERVER_ERROR`、他 → `GENERAL`（4キーとも React の翻訳ファイルに既にある）
  - `shouldShowErrorToast`: `skipGlobalErrorToast`、ログイン（`path.includes('/auth/login')`。移植元と同じく `/auth/login-key` も含む）の 401/403、ログイン・パスワードリセットの 429 では出さない
  - `shouldInvalidateSession`: 401 かつ `skipSessionInvalidation` でなく、`/api/auth`（セッション確認）・`/auth/...`（api-client の `AUTH_API_PATH_PREFIX`）以外。移植元は `url.includes('/auth')`（移植元のセッション確認は `/auth`）で、結果としてセッション確認とログイン系を除外している。React はセッション確認が `/api/auth` なので両方を明示した
  - `createApiErrorHandler({ translate, showErrorToast?, onUnauthorized })`: 403・500 は移植元と同じく `console.error`
- `useApiErrorInterceptor({ showErrorToast? })`: `useNavigate`・認証ストアの `invalidateSession` を使ってハンドラーを登録し（翻訳は `useTranslation` だと翻訳ファイルの読み込みまで App が suspend して起動時のセッション確認が遅れるため、`@/lib/i18n` の `i18n.t` をエラー時に呼ぶ）、アンマウントで解除する。401 では `invalidateSession()` → `navigate(ROUTES.AUTH.LOGIN)`（移植元と同じく Router で遷移）
- トースト（移植元 `ToastService`）は #278 で移植されるため、現時点では `showErrorToast` を渡していない。#278 のマージ後に `main.tsx` の `useApiErrorInterceptor()` へ渡す（申し送り）

## 5. 認証ストア（`frontend/src/store/auth-store.ts`）

- `loginWithKey(loginKey)`: `POST /auth/login-key` `{ loginKey }`。成功でユーザーを保存して `true`、失敗で `console.error`・ユーザー・`AUTH_USER`・テナントIDを消して `false`（移植元 `AuthStore.loginWithKey` と同じ）
- `invalidateSession()`: ユーザー・`initPromise`・`AUTH_USER`・テナントIDを消す。移植元は sessionStorage を消すだけだが、React はストアの `user` が残るとログイン画面でも認証済み扱いになるため、ストアも空にする
- ログアウト2箇所の `POST /auth/logout` に `responseType: 'text'` を付けた（backend は `Logout successful.` を返す。移植元の auth-api.service も text で受けている）

## 6. ログインキー（`frontend/src/lib/initializers/login-key.ts`・`frontend/src/main.tsx`）

- `runLoginKeyInitializer({ loginWithKey, onError? })`: `loginkey` が無ければ何もしない。`tenantId` があれば `persistTenantId`。URL から `loginkey`・`tenantId` を消してから `loginWithKey` を呼び、失敗なら `onError`
- 移植元は認証後に URL を消すが、React の StrictMode（開発時）は effect を2回実行するため、先に消して2回目で再認証しないようにした
- さらに実行中の Promise を持ち、認証中に呼ばれた2回目は同じ Promise を待つ。2回目がすぐセッション確認（`GET /api/auth`）へ進むと、Cookie が無いまま未ログインで確定してしまうため（code-review #1）
- `main.tsx` の `App` で `useApiErrorInterceptor()` を呼び、`runLoginKeyInitializer` → `ensureInitialized` の順に実行する
- 失敗時のトースト（`AUTH.LOGIN_KEY.ERROR`）は、トーストと翻訳キー（#277 で移植される ja.json）がそろった後に `onError` へ渡す（申し送り）

## 7. 利用量（`frontend/src/hooks/use-credit-usage.ts`・`use-token-usage.ts`）

- `useCreditUsage()`: `requestId`（初期 0）を queryKey に含め、0 の間は `enabled: false`。`fetchUsage()` で +1 して `/api/credit-usage/me`・`/workspace` を並行取得（移植元と同じ）
- `useTokenUsage()`: 本日・今月の `{ from, to }` を `buildTokenUsageDateRange` で作り `/api/token-usages` に `params` で渡す。`to` は現在時刻のため、描画のたびに計算すると queryKey が変わり取り直し続ける。`useState` の初期化で1回だけ計算する（移植元も Service 生成時の1回）
