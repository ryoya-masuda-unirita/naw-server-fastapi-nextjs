# 02_基本設計

## 変更対象

| 区分 | 内容 |
|---|---|
| API パス定数 | 既存の認証系だけの定数を、移植元の全項目＋画面ごとの定数のパスに広げる |
| API の型 | 移植元の型ファイルを同じ構成で追加する |
| API クライアント | メソッド・クエリ・本文・応答の読み方・エラーを拡張する |
| エラー処理 | 移植元のエラー処理の判定を関数にし、画面の起動時に登録する |
| 認証ストア | ログインキーでのログインと、401 時のセッション破棄を追加する。ログアウトの応答をテキストで受ける |
| 起動処理 | ログインキーの処理とエラー処理の登録を、セッション確認の前に行う |
| 共通 util・hooks | 日付・入力チェック・フォームエラー・スクロール・デバウンス・タブのクエリ・利用量 |
| テスト用モック | 機能ごとのハンドラーを束ねる入口と、URL の書き方の補助を追加する。認証のハンドラーを新しい書き方に直す |
| 規約 | frontend の規約に API・型・MSW の置き方を追記する |

## 画面 / API 変更概要

- 画面の見た目・文言の変更はない
- 呼ぶ API の追加はない（ログインキーのログインは URL にキーがあるときだけ呼ぶ）
- ログアウトの応答（テキスト）を JSON として読もうとして失敗していたのを、テキストとして読むように直す（画面の振る舞いは変わらない）

## 影響範囲

- 既存の API クライアントの使い方（GET・POST、クエリ、テナントID、認証 API のベース URL）は互換を保つ。エラーの文言（`HTTP 状態コード`）も変えない。ログイン画面・パスワードリセット画面がこの文言で分岐しているため
- 変わる点
  - JSON の本文がないリクエスト（GET など）には JSON の Content-Type を付けない
  - 401 を受けると、セッション確認・ログイン系以外の API ではセッションを破棄してログイン画面へ戻る
- 共通ファイルのうち、起動処理と認証ストアに最小限の追加をする（#277 と重なる可能性がある）。ルート定義・サイドバー・CSS・翻訳ファイル・パッケージ定義は変更しない

## 移植方針

| 移植元（Angular） | 移植先（React） | 方針 |
|---|---|---|
| API パス定数 | 同名の定数 | キー名は同じ。移植元はインターセプターが `/api` を前置するため値に含まないが、React の API クライアントはパスをそのまま連結するため値に `/api` を含める（既存の React と同じ）。ログイン系だけは `/api` を付けない |
| 画面ごとの API パス定数 | 共通の定数の管理画面の区分 | 画面のエージェントが足さなくて済むようにまとめる |
| `src/types/` | `src/types/` | ファイル名・構成を同じにする（対応表どおり） |
| ApiClientService + インターセプター（ベース URL・認証ヘッダー） | fetch のラッパー | 移植元で HttpClient を直接使っていた理由（配列クエリ・blob・FormData・ヘッダー）をすべて API クライアントで扱えるようにする。移植元の「独自 URL 用メソッド」は、絶対 URL を渡したときの扱いで代える |
| エラーのインターセプター | 判定関数 + 起動時に登録する hook | Router・翻訳・トーストに依存するため API クライアントからは切り離し、hook から登録する。トースト部品は #278 で移植するため、表示の口だけ用意する |
| 起動時の初期化（ログインキー） | 起動処理から呼ぶ関数 | セッション確認より前に実行する |
| 利用量の Service（TanStack Query） | TanStack Query の hooks | 対応表どおり |
| 入力チェックの Service | 翻訳関数を引数で受け取る関数 | inject の代わりに引数で受け取る |
| フォームの Angular 依存（FormGroup・AbstractControl） | 同じ形の状態・判定関数を受け取る | React にはフォームライブラリがないため |
| シグナルのデバウンス | 値のデバウンス hook | React の state に合わせる |
| タブのクエリ（Router のクエリ） | React Router のクエリを使う hook | 判定部分は純粋関数のまま移す |
| HTTP インターセプターによるモック | MSW | 対応表どおり。機能ごとのファイルに分け、入口で束ねる |
