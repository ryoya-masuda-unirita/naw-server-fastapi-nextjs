## `FileRepository`のメソッド

```python
async def find_by_id_and_tenant_id(file_id, tenant_id, session) -> File | None
async def find_page(index_id, tenant_id, display_name, file_name, user_id, status, updated_at_from, updated_at_to, sort_col, sort_dir, page, size, session) -> tuple[list[File], int]
async def create(file: File, session) -> File
async def save(file: File, session) -> File
async def delete(file: File, session) -> None  # 物理削除
```

一覧検索は移植元`Specification`と同様、`displayName == fileName`（両方非空）の場合は`name`/`displayName`両方へのOR部分一致、それ以外は個別条件とする。

## `FileService`のメソッド

```python
async def list_files(index_id, tenant_id, query, session) -> PagedFileResponse
async def create_file(index_id, tenant_id, current_user, form, storage, session) -> FileResponse
async def get_file_for_download(index_id, file_id, tenant_id, session) -> tuple[File, bytes]  # (メタ, バイト列)
async def update_file(index_id, file_id, tenant_id, current_user, form, storage, session) -> FileResponse
async def delete_file(index_id, file_id, tenant_id, physical_delete, storage, session) -> None
```

- `create_file`/`delete_file`/`update_file`（file添付あり）は、まず`IndexRepository.find_by_id_and_tenant_id`でIndexを取得し、存在しなければ404、`type == LOCAL`なら400。
- `create_file`は`credit_quota.enforce_within_quota`を呼んだ後、`storage.upload(...)`→`FileRepository.create(...)`。ストレージアップロード後のDB保存で例外が出た場合は`storage.delete(storage_url)`でロールバックする（移植元の例外時Blob削除を踏襲）。
- `update_file`（file添付あり）は`enforce_within_quota`→旧ファイルの物理削除（ストレージ+DB）→`create_file`相当の処理。
- `delete_file`はストレージ実体を削除した上で、`physical_delete`に応じてDB物理削除/論理削除。
- `updatedBy`解決は一覧・詳細ともに`user_id`集合を`UserRepository.find_by_ids`で一括取得してマッピングする（N+1回避）。

## ルーター実装方針

- multipart受け取りは`Annotated[str | None, Form(...)]`等をルーター関数の引数に直接並べる（Pydanticモデルではなく、`user_imports.py`同様シンプルな形にする）。
- DI: `storage: FileStorage = Depends(get_file_storage)`
- ダウンロードは`fastapi.responses.Response`（`content=bytes, media_type="application/octet-stream", headers={"Content-Disposition": ...}`）で返す。

## マイグレーション

`021_add_files.py`で`files`テーブルを作成。`status`は`sa.SmallInteger`。外部キー: `tenant_id -> tenants.id`、`(user_id, tenant_id) -> users(id, tenant_id)`、`(index_id, tenant_id) -> indexes(id, tenant_id)`、`feedback_id -> message_feedbacks.id`、`(room_id, tenant_id) -> rooms(id, tenant_id)`。SQLiteテスト環境でも動くよう複合FKは`sa.ForeignKeyConstraint`で表現する。
