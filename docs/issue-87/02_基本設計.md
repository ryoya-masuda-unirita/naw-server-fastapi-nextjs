```

app/core/credit_quota.py       ← 請求期間解決・クレジット上限強制（credit_usage_serviceと共用）
```

`app/repositories/user_repository.py`に`find_by_ids`（UUID一覧→Userの一括取得）を追加し、一覧取得時の`updatedBy`解決のN+1を回避する。

## エンドポイント仕様

### GET /api/admin/indexes/{indexId}/files

- クエリ: `userId`（loginIdまたはUUID）, `updatedAtFrom`, `updatedAtTo`, `displayName`, `fileName`, `status`, `page`(0始まり,既定0), `size`(既定20), `sort`(既定`updatedAt,desc`)
- 200: `PagedFileResponse`
- 権限: `require_admin_or_group_admin`

### POST /api/admin/indexes/{indexId}/files

- multipart/form-data: `name`, `displayName`, `reference`, `splitLength`(本Issoueスコープでは未使用。互換のため受理のみ), `status`, `file`
- Indexが存在しない→404、`Index.type==LOCAL`→400、クレジット上限超過→429
- 200: `FileResponse`

### GET /api/admin/indexes/{indexId}/files/{id}

- 移植元同様、バイナリダウンロード。`Content-Type: application/octet-stream`、`Content-Disposition: attachment; filename="{displayName}"`
- ファイルが存在しない→404

### PATCH /api/admin/indexes/{indexId}/files/{id}

- multipart/form-data（POSTと同じ形式、全フィールド任意）
- `file`が未指定/空なら、`displayName`・`reference`・`status`のみ部分更新（`status=DELETED`指定は400）
- `file`指定時は、クレジット上限チェック→既存ファイルを物理削除→新規作成（移植元と同じ「削除して再作成」方式）

### DELETE /api/admin/indexes/{indexId}/files/{id}

- クエリ: `physicalDelete`(既定false)
- `physicalDelete=true`ならDB物理削除、falseなら`status=DELETED`論理削除。いずれもストレージ上の実体は削除する
- 204

## ファイルストレージ抽象化

```python
class FileStorage(Protocol):
    async def upload(self, tenant_id: str, file_id: str, filename: str, content: bytes) -> str: ...  # storage_urlを返す
    async def download(self, storage_url: str) -> bytes: ...
    async def delete(self, storage_url: str) -> None: ...
```

`LocalFileStorage`はローカルファイルシステム（設定`FILE_STORAGE_ROOT`、既定`./data/files`）に`{tenant_id}/{file_id}_{filename}`として保存し、`storage_url`には`file://`スキームの相対パスを格納する。将来のS3移行時は同インターフェースを実装するクラスを追加し、DIを差し替えるだけで済む設計とする。

## クレジット上限チェック

`app/core/credit_quota.py`に以下を新設し、`credit_usage_service.py`のプライベートメソッドをこちらに統合する（重複実装の回避）。

```python
async def resolve_active_billing_period(tenant_id, session) -> tuple[Subscription, Plan, datetime, datetime] | None
async def resolve_credit_limit(tenant_id, plan, session) -> int | None
async def enforce_within_quota(tenant_id, session) -> None  # 超過時 HTTPException(429)
```

`enforce_within_quota`は有効なサブスクリプションが存在しない場合はチェックをスキップする（移植元同様、上限が定義されていなければ制限しない）。

## モデル

`File`（`files`テーブル、移植元Liquibase最終形に準拠）:

```
id: str(36) PK
tenant_id: str(32) FK tenants.id CASCADE
name: str(255)
display_name: str(255) | None
reference: str(255) | None
status: FileStatus(IntEnum: ENABLE=0, DISABLE=1, DELETED=2)  # DB上はsmallint（ORDINAL踏襲）
user_id: uuid FK users.id CASCADE（users.idは単独UUID PKのため単一カラムFK。実装時にcomposite FKから修正）
index_id: str(32) FK (index_id, tenant_id) -> indexes(id, tenant_id) CASCADE
storage_url: str(2048) | None
feedback_id: str(32) | None FK message_feedbacks.id CASCADE
room_id: str(32) | None FK (room_id, tenant_id) -> rooms(id, tenant_id) CASCADE
created_at / updated_at: timestamptz
```

`file_parts`テーブルは本Issueでは未使用（埋め込み機能は#88）のためモデル化を見送り、#88着手時に追加する。
