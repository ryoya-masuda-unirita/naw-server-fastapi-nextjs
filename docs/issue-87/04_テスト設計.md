# 04_テスト設計

## 方針

- DB接続を要するため`tests/integration/`にルーターレベルのテストを配置する（既存`test_indexes.py`・`test_credit_usage.py`と同じ構成）。
- ファイルストレージは`LocalFileStorage`をテスト用一時ディレクトリ（`tmp_path`）に向けて使う。実際のS3/Azure等外部ストレージへは接続しない。
- クレジット上限超過（429）のテストは`test_credit_usage.py`のフィクスチャパターン（Tenant/Plan/Subscription/TokenUsage）を踏襲する。

## テストケース一覧

### 一覧取得

- 一覧を取得できること
- `displayName`/`fileName`部分一致で絞り込めること
- `status`で絞り込めること
- 存在しないインデックスでも空一覧を返す/404にはしない（移植元の`Specification`ベース検索はIndex存在チェックをしないため、その挙動を踏襲することをテストで明示する）

### アップロード

- ファイルをアップロードできること（ストレージに保存され、DBにメタデータが作成される）
- `Index`が存在しない場合404
- `Index.type == LOCAL`の場合400
- 当月クレジット上限超過時429

### ダウンロード

- アップロード済みファイルをダウンロードできること（バイト列一致、`Content-Disposition`ヘッダー確認）
- 存在しないファイルIDで404

### 更新

- メタデータのみ更新できること（`file`未添付）
- `status=DELETED`指定時400
- `file`添付時、既存ファイルが削除され新しいファイルに置き換わること
- `file`添付時、クレジット上限超過で429

### 削除

- 論理削除（`physicalDelete`省略/false）で`status=DELETED`になること
- 物理削除（`physicalDelete=true`）でレコードが消えること
- ストレージ上の実体も削除されること
