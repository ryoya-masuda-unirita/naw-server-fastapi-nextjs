# 02_基本設計

## 変更対象

- frontend のみ（`backend/` は変更しない）

## 画面 / API 変更概要

- 画面: サイドバー（`components/layouts/sidebar.tsx`）のチャットのセクション、`SidebarRouteButton` のピン・メニュー・バッジ、ルームの操作メニュー、各ダイアログ
- 利用する API（すべて #283 の `useRoomsStore` 経由。新しい API パスはない）: `GET /api/rooms`・`PATCH /api/rooms/:id`・`POST/DELETE /api/rooms/:id/pin`・`DELETE /api/rooms/:id`・`DELETE /api/rooms`（まとめて削除）・`PUT /api/rooms/pin`（一括ピン）

## 移植方針

| 移植元 | 移植先 |
|---|---|
| `sidebar.component`（chatSection・allSectionGroups・onSidebarScroll・openRoomMenu・onRenameRoom・onTogglePinRoom・openConfirmDeleteDialog・handleDeletedRooms） | `components/layouts/sidebar.tsx` |
| `sidebar-route-button`（hasPin・hasMenu・badge） | `components/layouts/sidebar/sidebar-route-button.tsx` |
| `chat-room-menu` / `chat-context-menu`（同じ表示制御を 2 つが持つ） | `sidebar/chat-room-menu.tsx` / `chat-context-menu.tsx` + 共通の `use-floating-menu.ts` |
| `chat-delete-dialog` / `chat-sort-dialog` | `sidebar/chat-delete-dialog.tsx` / `chat-sort-dialog.tsx` |
| `chat-rename-dialog`（サイドバー用の文言） | 既存 `features/chat/chat-rename-dialog.tsx` に title・cancelText・confirmText・confirmLoading を足す |
| `getRoomListTotalCount` | `lib/utils/room-list-mapper.ts` に追記 |
| `RoomsService` | #283 で移植済み（`store/rooms-store.ts`） |

## 意図的な差分・判断（根拠は移植元のコード）

1. **ルーム名は翻訳しない**。移植元はルーム名を `labelKey` に入れて翻訳パイプに通す。ルーム名は i18n キーではなく、`:`・`.` を含む名前が壊れる（i18next は `:` を名前空間区切りとして扱う）ため、roomId のある項目はそのまま出す。通常のルーム名では見た目は同じ
2. **チャットのセクションの開閉状態は持たない**。移植元の `chatSectionCollapsed` は切り替える手段が無く常に false
3. **`chat-context-menu` を開くボタン・`openSortDialog` の呼び出し元は移植元に無い**（`openChatMenu`・`openSortDialog` は定義だけで、テンプレートにも他のコードにも呼び出しが無い。確認: `grep -rn openChatMenu client/src/app`）。完璧なクローンとして部品と配線（メニュー → まとめて削除ダイアログ。並び替えダイアログの描画）は移すが、画面からは開けない。ユーザーが「開ける」ことを期待するなら別 Issue で開く口を決める
4. **保存・削除が失敗したときの扱い**: 移植元は `.then` だけで `catch` が無く、確認ダイアログのローディングが戻らない。React ではエラーをログに出し、ダイアログを開いたままローディングを戻す（エラートーストは api-client が出す）
5. **`PUT /api/rooms/pin` は失敗する**（移植元 server にも無い）。並び替えダイアログの「保存」は失敗してダイアログが開いたままになる。移植元と同じ
6. 並び替えダイアログのドラッグ: 移植元のテンプレートにも `cdkDrag` は無く、`cursor-grab` の見た目だけ。同じ
7. 一覧の取得は、まとめて削除・並び替えのダイアログでは TanStack Query（`gcTime: 0`）で行う。移植元は毎回 API を呼ぶので同じ挙動
8. `SidebarButton`（移植元で route が `#` の項目用）は移さない。React の `ADMIN_LAYOUT_CONFIG` にその項目が無く、`#` のアクション項目は `sidebar.tsx` のアクション項目の枠で描画済み

## 影響範囲

- `routes/chat/chat-room.tsx`: 一覧の暫定読み込みを削除
- サイドバーは全画面で描画されるため、マウント時に `GET /api/rooms` を呼ぶ。MSW の既定（`mocks/handlers/chat.ts`）は空の一覧を返すので既存テストは通る
