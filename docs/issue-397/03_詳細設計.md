# 03_詳細設計

## 変更対象ファイル

| ファイル | 変更内容 |
|---|---|
| `e2e-spec/playwright.config.ts` | `workers` の既定を 4 から 2 に下げる（定数 `DEFAULT_WORKERS`）。済み・未検証 |
| `e2e-spec/README.md` | `E2E_SPEC_WORKERS` の既定値の表記を 2 に直す。済み・未検証 |
| `client/src/test/setup.ts` | `configure({ asyncUtilTimeout: 5000 })`。済み・未検証 |
| `e2e-spec/tests/*.spec.ts` | 切り分けの結果、待ち時間の見直しが要る項目だけ直す（期待値は緩めない） |
| `server/` | 500 の原因が backend にあった場合だけ。直すか別チケットにするかはその時点で決める |

## 切り分けの手順

1. 変更前（並列 4）の設定で `npm run spec:all` を回し、NG の項目と症状（要素待ち・500・切断）を `09_集計結果.md` 相当の表にまとめる
2. 500 が出た項目（11-38・11-68）は、backend のコンテナのログで、例外の種類（DB の競合・接続の枯渇・タイムアウトなど）を確かめる
3. `library-list.test.tsx` の落ちた項目は、`vitest run` を全体で複数回回して再現する。再現しなければ、待ち上限の変更前後で比べる

## 判断基準

- 並列を 2 に下げて NG 0 になり、500 が負荷によるもの（接続の枯渇・応答遅延）なら、設定の変更で完了とする
- 並列を下げても同じ項目で 500 が出るなら、同時操作のバグとして backend を調べる
