# 04_テスト設計

## テスト方針

テスト用の偽物（例外を直接投げる）では実際の httpx の例外経路を通らないため、実際の Waha! クライアントに HTTP のモック（Waha! の応答を返す）を組み合わせて確認する。

- 単体: Waha! クライアントが返す例外のメッセージ（書式・authkey を含まないこと・元の例外を連鎖しないこと）
- 結合: アプリ全体を起動し、Waha! が 503 を返すときの API の応答・SSE・DB の回答・ログに authkey が出ないこと

修正前のコードで新しいテストが失敗することも確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | HTTP エラー（本文なし） | セッション開始で Waha! が 503 | `503 Service Unavailable: [no body]` の例外。authkey を含まず、元の例外を連鎖しない |
| 2 | HTTP エラー（本文あり） | ジョブ実行で Waha! が 500、本文に改行・制御文字 | `500 Internal Server Error: "…"`（改行は `<EOL>`、制御文字は `?`） |
| 3 | アップロードの HTTP エラー | アップロードで Waha! が 404 | `404 Not Found: [no body]` の例外 |
| 4 | 通信エラー | セッション開始で接続失敗 | クエリを除いた URL の `I/O error on GET request for "…": …` の例外。元の例外は表示しない |
| 5 | 学習ファイル登録の応答 | セッション開始で Waha! が 503 | 500、`message` が No.1 のメッセージ。応答・ログに authkey がない |
| 6 | 同期の質問 | セッション開始は成功、ジョブ実行で 503 | ERROR 状態の回答が No.1 のメッセージ。応答・DB・ログに authkey がない（セッション開始の httpx のリクエストログも出ない） |
| 7 | SSE の質問 | 同上 | error イベントの `message` と DB の回答が No.1 のメッセージ。応答・ログに authkey がない |
| 8 | 修正前の再現 | 修正前のコードで No.1〜7 | 失敗する |
| 9 | 回帰 | server-local のテスト全件・ruff | すべて成功 |
