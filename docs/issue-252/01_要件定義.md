# 01_要件定義

## 背景

server-local は Waha! のセッション開始で、認証キー（authkey）を URL のクエリに付けて送る（移植元と同じ）。HTTP クライアントの httpx は、HTTP エラー時の例外メッセージにクエリ付きの URL を含める。この文字列がそのまま API の応答、SSE の error イベント、DB の回答、ログに出ていた。さらに httpx は INFO レベルで全リクエストの URL をログに出すため、正常時も authkey がログに残っていた。

移植元（Spring Boot 3.2.3 / Spring Framework 6.1 の RestTemplate）は、HTTP エラーのメッセージを `{ステータスコード} {理由句}: {本文}` の形にし、URL を含めない。通信エラーのメッセージは URL を含むが、クエリを除いている。また、リクエストごとのログは出さない。

## 機能要件

1. Waha! が HTTP エラー（2xx 以外）を返したとき、メッセージを移植元と同じ書式にする
   - 本文なし: `503 Service Unavailable: [no body]`
   - 本文あり: `500 Internal Server Error: "本文"`（本文の改行は `<EOL>`、制御文字は `?` に置き換える）
2. Waha! と通信できないとき（接続失敗など）、メッセージを移植元と同じ書式にし、URL からクエリを除く
   - `I/O error on GET request for "http://…/WahaServer/servicerun/api/startsession": 原因`
3. 上記のメッセージを、移植元と同じく API の応答（500 の `message`）、同期・SSE の回答（DB の answer・error イベント）にそのまま使う
4. 元の httpx の例外（URL 付き）をログのトレースバックに出さない
5. httpx のリクエストログ（URL 付き）を出さない（移植元もリクエストごとのログは出さない）

## 非機能要件

- テスト用の偽物ではなく実際の Waha! クライアントを使い、HTTP のモックで Waha! の 503 を返して、応答・SSE・DB・ログに authkey が出ないことを自動テストで確認する
- 修正前のコードで、そのテストが失敗する（問題を再現できる）ことを確認する

## スコープ外

- NAW 本体の API クライアントのエラー（既に独自の例外に変換しており、URL に秘密情報を含まない）
- authkey をクエリ以外（ヘッダーなど）で送る変更（Waha! の API 仕様のため）
