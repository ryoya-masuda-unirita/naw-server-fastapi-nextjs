# 02_基本設計

## 変更対象

- Waha! の API クライアント（エラーの変換）
- 例外ハンドラー（httpx の例外を直接扱う処理の削除）
- アプリの起動処理（httpx のログレベル）
- テスト（Waha! クライアントの単体テスト、実際の例外経路を通す結合テスト）

## 画面 / API 変更概要

API のパス・パラメーター・ステータスコードは変えない。Waha! の失敗時に返すメッセージの文言だけが変わる。

| 場面 | 修正前のメッセージ | 修正後のメッセージ（移植元と同じ） |
|---|---|---|
| Waha! が 503（本文なし） | `Server error '503 Service Unavailable' for url 'http://…/startsession?authkey=…'` + httpx のヘルプ URL | `503 Service Unavailable: [no body]` |
| Waha! が 500（本文あり） | 同上の形式 | `500 Internal Server Error: "本文"` |
| Waha! に接続できない | `All connection attempts failed` など（httpx の文言） | `I/O error on GET request for "http://…/startsession": 原因` |

メッセージが使われる場所（修正前後で変わらない）:

- 学習ファイル・追加学習・同期など: 500 の `{"timestamp","message"}` の `message` とエラーログ
- 同期の質問（`/content/sync`）: ERROR 状態で保存する回答（answer）と応答
- SSE の質問: error イベントの `message`、ERROR 状態で保存する回答

### 移植元のメッセージの根拠

- HTTP エラー: Spring の `DefaultResponseErrorHandler` が `HttpServerErrorException` などを作るときのメッセージ。`{ステータス} {理由句}: ` に、本文がなければ `[no body]`、あれば `LogFormatUtils.formatValue`（引用符で囲み、改行を `<EOL>`、制御文字を `?` に置換）を付ける
- 通信エラー: `RestTemplate.doExecute` が `ResourceAccessException` を作るときのメッセージ。URL はクエリを除いて出す
- 移植元の `APIControllerAdvice` は `RestClientException` を 500 + `ErrorResponse(e.getMessage())` で返す。同期・SSE はサービス内で `e.getMessage()` を回答に入れる

### ログ

- httpx のロガーを WARNING にし、INFO の `HTTP Request: GET …?authkey=…` を出さない。`LOG_LEVEL` を DEBUG にしても出さない
- Waha! のエラーを変換するときは元の例外を連鎖させない。連鎖させるとサービスの `logger.exception` のトレースバックに元の例外（URL 付き）が出るため

## 影響範囲

- Waha! の失敗時にクライアント（ブラウザ・NAW 本体）が受け取るメッセージの文言（移植元と同じになる）
- httpx の例外を直接扱う例外ハンドラーは、Waha! の例外が届かなくなるため削除する（NAW 本体のクライアントも独自の例外に変換済みで、届く経路がない）
- サーバーログから、Waha! へのリクエストごとの行がなくなる

## 移植方針

- 移植元 `ServiceRunService` が使う RestTemplate のエラーメッセージに揃える。Spring Boot 3.2.3（Spring Framework 6.1）の書式を基準にする
- 理由句は Waha! の応答の理由句（なければ HTTP の標準の理由句）を使う
