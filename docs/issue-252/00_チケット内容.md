# #252 issue-252 server-localでWaha!のauthkeyが応答とログに出ないようにする

## 概要

`server-local/` で、Waha! の authkey が API の応答とログに出る。

- `app/clients/waha_client.py`: authkey をクエリに付けた URL で `raise_for_status()` しており、`httpx.HTTPStatusError` のメッセージに URL（authkey 込み）が入る
- `app/core/errors.py`: 例外の `str(exc)` をそのままログと応答の `message` に入れている
- SSE の場合も、例外の文字列が error イベントと DB の answer に入る（`message_content_stream_service.py`）
- `app/main.py` でログを INFO にしているため、httpx が `HTTP Request: GET ...?authkey=...` を毎回ログに出す

移植元（`service/ServiceRunService.java`）の RestTemplate の HTTP エラーのメッセージには URL が入らない。

## 説明

### 再現シナリオ

Waha! が 503 を返している間に学習ファイルを登録すると、500 の `message` に authkey が入って返る。

### 対応

- Waha! の HTTP エラーを、URL を含まない例外に変換する（応答・SSE・DB に出るメッセージは移植元に揃える）
- httpx のリクエストログに authkey が出ないようにする
- テストの `FakeWahaClient` が実際の `httpx.HTTPStatusError` の経路を通らないため、`httpx.MockTransport` 等で実際の例外経路を通すテストを追加する
