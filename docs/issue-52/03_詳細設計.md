# 03_詳細設計

## 集計クエリの設計

移植元の `MessageFeedbackRepository.findFeedbackUsers`（ネイティブSQL）をSQLAlchemy CoreのCTEで再現する。

```
stats CTE:
  SELECT
    u.id                                            AS user_id,
    u.login_id,
    u.name                                          AS display_name,
    COUNT(DISTINCT mf.id)                           AS feedback_message_count,
    COALESCE(MAX(mf.updated_at), u.updated_at)      AS latest_updated_at,
    COUNT(CASE WHEN r.rating = 'EXCELLENT' THEN 1 END) AS excellent,
    COUNT(CASE WHEN r.rating = 'VERY_GOOD'  THEN 1 END) AS very_good,
    COUNT(CASE WHEN r.rating = 'GOOD'       THEN 1 END) AS good,
    COUNT(CASE WHEN r.rating = 'AVERAGE'    THEN 1 END) AS average,
    COUNT(CASE WHEN r.rating = 'POOR'       THEN 1 END) AS poor
  FROM users u
  LEFT JOIN message_feedbacks mf ON u.id = mf.user_id AND mf.tenant_id = :tenant_id
  LEFT JOIN rooms r ON u.id = r.user_id AND r.tenant_id = :tenant_id
  WHERE u.tenant_id = :tenant_id
  GROUP BY u.id, u.login_id, u.name, u.updated_at
```

このうえで `responseStatus`（`feedback_message_count` の0/非0判定）・`satisfaction`（該当星の件数が1件以上か）で`stats`をフィルタし、`sortField`をマッピングしたカラムでソート、`page`/`size`でページングする。

**移植元の仕様をそのまま踏襲する注意点**: `message_feedbacks` と `rooms` はどちらも `users` からの独立した`LEFT JOIN`であり、両者を紐付ける結合条件がない。そのため、あるユーザーが複数件のメッセージフィードバックと複数件の評価済みルームを両方持つ場合、`GROUP BY` 前の行数はその直積（フィードバック件数 × ルーム件数）になり、`excellent`〜`poor`の件数が実際のルーム評価件数より過大にカウントされる。これは移植元のSQLと同一の挙動であり、本issueでは仕様として踏襲する（新たなバグ修正は行わない）。

## 実装対象ファイル

### スキーマ

- `backend/app/schemas/feedback.py`
  - `FeedbackUserListRequest`（クエリパラメータ用。`responseStatus`/`satisfaction`/`sortField`/`sortOrder`の許容値を`field_validator`で検証）
  - `FeedbackUserItemResponse`（`user: {id, userId, displayName}`, `isResponded`, `feedbackMessageCount`, `feedbackRoomCount: {excellent, veryGood, good, average, poor}`, `updatedAt`）
  - `PagedFeedbackUserResponse`（`content`/`totalElements`/`number`/`size`）

### リポジトリ

- `backend/app/repositories/message_feedback_repository.py`
  - `find_feedback_users`：上記CTEを組み立て、`responseStatus`/`satisfaction`でフィルタしたうえでソート・ページングした行一覧と総件数を返す（既存の`find_by_tenant_id_and_message_id`等と同じファイルに追加する）

### サービス

- `backend/app/services/feedback_service.py`（新規）
  - `get_feedback_users`：`sortField`の論理名→実カラム名マッピング（移植元`toEntitySortField()`相当）→リポジトリ呼び出し→レスポンス整形

### ルーター

- `backend/app/routers/feedback.py`（`prefix="/api/admin"`、`GET /feedbackUser`）
  - 認可は `require_admin_or_group_admin` を使用

### `main.py`

- `backend/app/main.py` に `feedback.router` を追加登録

## 移植元との差分（意図的な仕様変更）

- レスポンスの`{"feedbacks": Page<...>}`ラッパーを廃止し、`PagedFeedbackUserResponse`（`content`/`totalElements`/`number`/`size`）を直接返す
