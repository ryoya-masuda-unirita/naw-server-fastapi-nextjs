# 01_要件定義

## 背景

移植元（naw-server, Spring Boot）には、管理者がテナント内のユーザーごとのフィードバック状況（メッセージへの評価件数、ルームへの満足度評価件数）を一覧で確認できるダッシュボードAPIが存在する。
このリポジトリでは #48 でメッセージフィードバック（`message_feedbacks`）、#45 でルームの満足度評価（`rooms.rating`）をそれぞれ実装済みのため、これらを集計して一覧表示するAPIを追加する。

## 機能要件

- テナント内の全ユーザーについて、以下を1件ずつ一覧取得できる
  - ユーザー情報（ID・ログインID・表示名）
  - フィードバック済みメッセージ件数、および1件以上あるかどうか（応答済みフラグ）
  - そのユーザーが所有するルームの満足度評価（EXCELLENT/VERY_GOOD/GOOD/AVERAGE/POOR）別の件数
  - 直近の更新日時（フィードバックの最終更新日時。フィードバックがなければユーザー自身の更新日時）
- 応答有無（`responseStatus`: `has_response`/`no_response`）で絞り込める
- 満足度（`satisfaction`: `star1`〜`star5`。`star5`=EXCELLENT 〜 `star1`=POOR に1件以上該当するか）で絞り込める
- 指定項目（更新日時・表示名・フィードバック件数・満足度別件数）でソートできる
- ページング対応する

## 非機能要件

- 管理者（テナント管理者またはグループ管理者）のみアクセスできる（既存の `/api/admin/**` の認可方針に合わせる）
- 既存の移植済みAPI（アシスタントカテゴリ管理等）の方針に合わせたレスポンス形式・エラーハンドリングとする

## スコープ外

- `FeedbackController` の他2エンドポイント（`GET /api/admin/feedbackMessage`, `GET /api/admin/feedbackRoom`）は、`folderId` 絞り込みが未移植の `File`/インデックス機能に依存するため対象外とする
- `folderId` によるフォルダ（ナレッジ追加学習単位）絞り込みは、本issueの対象エンドポイントには存在しないため関係しない
