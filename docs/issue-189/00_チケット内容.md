# #189 issue-189 CI/CDパイプラインの構築とSQS/S3対応

## 概要

`develop`ブランチへの反映をトリガーに、frontend-angularのデプロイ・backendのデプロイ・Terraformのplan/applyを自動化するCI/CDパイプラインをGitHub Actionsで構築する。あわせて、Terraform化されたSQS/S3リソース（#186〜#188）がこのパイプライン経由で正しく反映されることを確認する。

（#161「CI/CDパイプラインにCI・Terraform・アプリ自動デプロイを組み込む」を本チケットに統合済み。#161はクローズ済み）

## 説明

- OIDC（GitHub Actions → IAMロール）でAWS認証する。アクセスキーは使わない
- frontend-angular: `develop`への変更時に`ng build` → S3 sync → CloudFrontキャッシュ無効化
- backend: `develop`への変更時にテスト・lint → Dockerビルド（ARM64明示） → ECR push → ECS force-new-deployment
- infra: `develop`への変更時にterraform plan → apply（Route53サブディレクトリは対象外）
- 追加スコープとしてTerraformのリモートバックエンド化（S3、`use_lockfile`によるS3ネイティブロック）を行う。CIからの自動applyにはstateの排他制御が必須のため。`dynamodb_table`によるロック方式はTerraform 1.11で非推奨化されているため使用しない
- OIDC用のIAMロール・IDプロバイダはTerraformでコード化する（`infra/`配下）。ただし`terraform apply`自体はこれまで通りユーザーが実施し、Claudeは提示・plan確認までとする
