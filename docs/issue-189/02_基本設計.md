# 02_基本設計

## 変更対象

- `.github/workflows/`に新規ワークフローを追加（frontend-angularデプロイ、backendデプロイ、infra plan/apply）
- `infra/`にOIDC用IAMロール・IDプロバイダ、Terraformリモートバックエンド用のS3バケット・DynamoDBテーブルを追加
- `infra/main.tf`の`backend`設定をローカルからリモート（S3）に変更

## 画面 / API 変更概要

- 画面・APIの変更は無し（CI/CDインフラのみ）

## 影響範囲

- `.github/workflows/`（新規ファイル追加のみ、既存の`backend-tests.yml`・`project-status-sync.yml`は変更しない）
- `infra/`（IAM・バックエンド設定の追加。既存リソースの動作には影響しない）
- GitHub側の設定（Secrets/Variablesの追加。既存のPR時テストの挙動には影響しない）

## 移植方針

- 参照実装（`~/Documents/naw-server/.github/workflows/deploy-dev-ecs.yml`）のOIDC認証・ECR push・ECS force-new-deploymentの実装パターンを踏襲する（`push-to-ecr.yml`はロールARN直書きの古い設計のため参照しない）
- モノレポ構成のため、参照実装には無いパスフィルタ（`paths:`）を追加し、変更されたディレクトリに応じたジョブのみ実行する（既存`backend-tests.yml`のパスフィルタ運用を踏襲）
- Dockerビルドは`docker buildx build --platform linux/arm64`で明示し、ECS（t4g、ARM64）と一致させる
- Terraformのリモートバックエンド化は、既存の`infra/s3.tf`等の命名規則に合わせた新規S3バケット・DynamoDBテーブルをTerraformでコード化した上で、`terraform init -migrate-state`でローカルstateを移行する（移行作業はユーザーが手動実施）
- OIDC用IAMロールの`assume_role_policy`は、GitHub Actions公式ドキュメントのパターンに準拠し、`sub`条件で対象リポジトリ（`ryoya-masuda-unirita/naw-server-fastapi-nextjs`）・対象ブランチ（`develop`）に限定する
