# 08_動作確認

## 確認環境

- `infra/` ディレクトリ、AWSプロファイル `naw-fastapi-issue158`（アカウントID: `035261964577`）
- 確認時点でdev環境のインフラはコスト削減のため`destroy`済み（#188の動作確認時と同じ状態）。`terraform.tfstate`のリソースは0件、Route53ホストゾーンも0件
- YAML構文チェック用にPython3の`yaml`モジュールを使用

## 確認手順

```bash
cd infra
terraform fmt -check -diff   # 差分検出 → terraform fmt で自動整形
terraform fmt -check -diff   # 再確認
terraform validate

# .github/workflows/*.yml のYAML構文チェック
python3 -c "
import yaml, glob
for f in glob.glob('.github/workflows/*.yml'):
    with open(f) as fp:
        yaml.safe_load(fp)
"

# main.tf の backend "s3" ブロックを一時的にコメントアウトし、
# ローカルバックエンドのままtfstate用バケット作成分のplanを確認(ニワトリ卵問題の回避)
terraform init -reconfigure
terraform plan \
  -target=aws_iam_openid_connect_provider.github \
  -target=aws_iam_role.github_actions \
  -target=aws_iam_role_policy.github_actions \
  -target=aws_iam_role_policy_attachment.github_actions_power_user \
  -target=aws_iam_role_policy_attachment.github_actions_iam_full_access \
  -target=aws_s3_bucket.tfstate \
  -target=aws_s3_bucket_public_access_block.tfstate \
  -target=aws_s3_bucket_versioning.tfstate

# backend "s3" ブロックを元に戻す
terraform fmt
```

## 確認結果

- `terraform fmt -check -diff`: 初回は`main.tf`・`tfstate_backend.tf`の2ファイルでインデント崩れを検出。`terraform fmt`で自動整形後、差分無しを確認
- `terraform validate`: `Success! The configuration is valid.`
- ワークフローYAML構文チェック: `.github/workflows/`配下の全6ファイル（`backend-tests.yml`, `project-status-sync.yml`, `deploy.yml`, `deploy-infra.yml`, `deploy-backend.yml`, `deploy-frontend-angular.yml`）でパースエラー無し
- `terraform plan`（`-target`指定）:
  - `main.tf`に`backend "s3"`ブロックを追加済みの状態のままplanを実行すると、S3バケットがまだ存在しないため`Backend initialization required`エラーとなり実行不可（設計通りの「ニワトリ卵問題」）。手順通り一時的にコメントアウトしてローカルバックエンドで確認した
  - dev環境が現在`destroy`済みのため、Route53ホストゾーン参照（`data.aws_route53_zone.main`）でエラーが発生し、plan全体は完了前に中断された（#188の動作確認時と同じ既知の制約）
  - ただし対象リソースはエラー発生前に評価され、以下がすべて`+ create`として計画に含まれていることを確認できた
    - `aws_iam_role.github_actions`（`name = "naw-fastapi-issue160-github-actions-role"`）
    - `aws_iam_role_policy_attachment.github_actions_power_user`（`PowerUserAccess`）
    - `aws_iam_role_policy_attachment.github_actions_iam_full_access`（`IAMFullAccess`）
    - `aws_s3_bucket.tfstate`（`bucket = "naw-fastapi-issue160-tfstate"`）
    - `aws_s3_bucket_public_access_block.tfstate`（4項目とも`true`）
    - `aws_s3_bucket_versioning.tfstate`（`status = "Enabled"`）
  - `aws_iam_role_policy.github_actions`（インラインポリシー）はRoute53エラーによる中断前の出力には現れなかったが、`terraform validate`で構文・参照エラーが無いことは確認済み
  - 確認後、`backend "s3"`ブロックはコメントアウトを解除して元に戻した
- `terraform apply`は本チケットのスコープ外のため未実施。ユーザーが別途、以下の順序で実施する
  1. `backend "s3"`ブロックをコメントアウトした状態で`terraform apply`し、tfstate用S3バケット等を作成
  2. `backend "s3"`ブロックを戻し、`terraform init -migrate-state`でstateをS3へ移行
  3. 以降の`apply`はOIDCロール経由（CI）またはローカルから、リモートバックエンド越しに実施
