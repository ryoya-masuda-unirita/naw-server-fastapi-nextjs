# 03_詳細設計

## 実装対象ファイル

### infra側（Terraformコード化。applyはユーザーが実施）

- `infra/tfstate_backend.tf`（新規）
  - `aws_s3_bucket.tfstate` : `${var.project_name}-tfstate`（バージョニング有効化、パブリックアクセスブロック）
  - `aws_dynamodb_table.tfstate_lock` : `${var.project_name}-tfstate-lock`（`LockID`をハッシュキーとするオンデマンド課金テーブル）
  - ※ このバケット・テーブル自体は「ローカルバックエンドでapply」した上で、その後`main.tf`の`backend`ブロックを追加して`terraform init -migrate-state`する、という順序が必要（ニワトリ卵問題のため）
- `infra/main.tf`（変更）
  - `terraform { backend "s3" { ... } }` を追加（bucket名・key・region・dynamodb_table名を指定）
- `infra/github_oidc.tf`（新規）
  - `aws_iam_openid_connect_provider.github` : `token.actions.githubusercontent.com`
  - `aws_iam_role.github_actions` : `assume_role_policy`で`sub`条件を`repo:ryoya-masuda-unirita/naw-server-fastapi-nextjs:ref:refs/heads/develop`に限定
  - `aws_iam_role_policy.github_actions` : ECR push（`ecr:GetAuthorizationToken`, `ecr:BatchCheckLayerAvailability`, `ecr:PutImage`, `ecr:InitiateLayerUpload`, `ecr:UploadLayerPart`, `ecr:CompleteLayerUpload`）、ECS操作（`ecs:DescribeTaskDefinition`, `ecs:RegisterTaskDefinition`, `ecs:UpdateService`, `ecs:DescribeServices`）、S3（frontendバケットへの`PutObject`/`DeleteObject`/`ListBucket`）、CloudFront（`cloudfront:CreateInvalidation`）、Terraform実行のための広めの権限（対象リソース種別のCRUD、`iam:PassRole`含む）

### `.github/workflows`側

- `.github/workflows/deploy-frontend-angular.yml`（新規）
  - トリガー: `push` to `develop`、`paths: ["frontend-angular/**"]`
  - `npm ci` → `npm run build` → `aws s3 sync dist/example/browser/ s3://<frontendバケット>/ --delete` → `aws cloudfront create-invalidation`
- `.github/workflows/deploy-backend.yml`（新規）
  - トリガー: `push` to `develop`、`paths: ["backend/**"]`
  - テスト・lint（既存`backend-tests.yml`のunit-tests/lint/mypyジョブと同等の内容を実行、もしくは`workflow_run`で既存ワークフローの成功を待つ）
  - `docker buildx build --platform linux/arm64` → ECR push（`latest`, commit SHA） → タスク定義のdescribe/register → `ecs update-service --force-new-deployment` → `wait services-stable`
- `.github/workflows/deploy-infra.yml`（新規）
  - トリガー: `push` to `develop`、`paths: ["infra/**", "!infra/route53/**"]`
  - `terraform fmt -check` → `terraform validate` → `terraform plan` → `terraform apply -auto-approve`

## 変更しないファイル

- `.github/workflows/backend-tests.yml`, `.github/workflows/project-status-sync.yml`：既存挙動を変更しない
- `infra/route53/`：スコープ外

## 実施内容

1. `infra/tfstate_backend.tf`を作成する（S3バケット・DynamoDBテーブル定義）
2. `infra/github_oidc.tf`を作成する（OIDCプロバイダ・IAMロール・ポリシー）
3. `infra/main.tf`にリモートバックエンド設定を追加する（コメントで移行手順を明記）
4. `.github/workflows/deploy-frontend-angular.yml`を作成する
5. `.github/workflows/deploy-backend.yml`を作成する
6. `.github/workflows/deploy-infra.yml`を作成する
7. `terraform fmt` / `terraform validate`でinfra側のコードを確認する
8. `terraform plan`（`-target`でOIDC/tfstate backend関連のみ）を実行し、意図した差分を確認する
9. GitHub Actionsのワークフロー構文チェック（`actionlint`があれば使用、無ければYAML構文のみ目視確認）
