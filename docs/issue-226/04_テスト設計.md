# 04_テスト設計

## テスト方針

API はテスト用の DB（インメモリ SQLite）と一時ディレクトリのストレージで実際に呼び出して確かめる。RAG の問い合わせ条件はデータベースの問い合わせを直接実行して確かめる（RAG 全体の流れは既存の単体テストで確認済みのため）。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 更新（状態） | 削除済みのファイルに状態「学習中」を指定して更新する | 400「削除済みのファイルは更新できません。」。状態は削除済みのまま |
| 2 | 更新（状態） | 削除済みのファイルに状態「停止中」を指定して更新する | 400。状態は削除済みのまま |
| 3 | 更新（表示名・参照先） | 削除済みのファイルの表示名・参照先を変更する | 400。表示名・参照先は変わらない |
| 4 | 更新（差し替え） | 削除済みのファイルを添付ファイルで差し替える | 400。ファイルは作り直されず、削除済みのまま残る |
| 5 | 更新（差し替え・name なし） | 削除済みのファイルを name なしの添付ファイルで差し替える | name の必須エラーより先に、削除済みの 400 になる |
| 6 | ダウンロード | 削除済みのファイルをダウンロードする | 400「削除済みのファイルはダウンロードできません。」 |
| 7 | RAG のファイル解決 | 学習中・停止中・削除済みのファイル ID をまとめて解決する | 学習中・停止中だけが返る |
| 8 | 回帰 | 既存のファイル API・メッセージのテスト | すべて成功 |
