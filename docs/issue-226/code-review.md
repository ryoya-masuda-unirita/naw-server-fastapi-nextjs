## 詳細

### 1. 削除と更新の同時実行（🟡 注意）→ 対応しない

移植元も楽観ロック・行ロックを持たず、NAW-1375 の文書（横展開「同時に届いた削除と更新」）で「同時実行の制御はこの修正の範囲外」としている。本 Issue も `01_要件定義.md` のスコープ外に同じく記載済み。同時実行制御はファイル以外のエンティティにも共通する設計判断のため、必要なら別 Issue で扱う。

### 2. ダウンロードで実体が無い場合の 500（🟡 注意）→ 対応済み

`FileService.get_file_for_download` で `storage.download` の `FileNotFoundError` を捕捉し、404「ファイルが存在しません。」（既存の 404 と同じ形式・文言）を返すようにした。削除済みの判定（400）をすり抜ける競合や、実体が手作業で消された場合も 500 にならない。テスト `test_download_file_without_stored_content_returns_404` を追加した。

### 3. 更新 API の `index_id` 照合（🟡 注意）→ 対応しない

変更前からある挙動で、本 Issue では `01_要件定義.md` のスコープ外とした。移植元は照合して 400「指定された学習先IDがファイルの学習先IDと一致しません。」を返すが、移植元のこの 400 は本文にメッセージが入らない既存バグ（NAW-1380）があり、エラー応答の形式は別途検討中のため、本 Issue では新たに決めない。

### 4. 差し替えのトランザクション（🟡 注意）→ 対応しない

変更前からある挙動で、本 Issue の対象（削除済みの扱い）とは別の問題。削除済みのファイルは今回の判定で差し替えの前に止まるため、本 Issue の変更で悪化はしない。

### 5. 差し替えでの重複取得（🔵 提案）→ 対応しない

差し替えは頻度が低く、削除処理（`delete_file`）を DELETE API と共有して挙動を揃えることを優先した。取得済みのエンティティを受け取る内部ヘルパーへの分割は、削除処理の責務をまたぐリファクタリングになるため見送る。

### 6. RAG の上位 K 件（🔵 提案）→ 対応しない

`02_基本設計.md` の案 A に移植元との差として記載済み。根本的にはベクトルストアへの登録・削除（論理削除時のチャンク削除）を移植した時点で解消する。K を多めに取って詰める暫定策は、移植元に無い検索件数の調整になり、検索コスト（クレジット）にも影響するため入れない。

### 7. 検証順の変化のテスト（🔵 提案）→ 対応済み

移植元 `updateFile` と同じく存在確認を先に行う順序が意図どおりであることを固定するため、`test_replace_missing_file_without_name_returns_404`（存在しない ID + 添付あり + name なし → 404）を追加した。
