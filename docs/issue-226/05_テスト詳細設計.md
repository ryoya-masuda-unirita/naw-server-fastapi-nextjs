# 05_テスト詳細設計

## `backend/tests/integration/test_files.py`

アップロード → `DELETE`（論理削除）で削除済みのファイルを作ってから操作する。

| No | クラス | テスト名 | 確認内容 |
|---|---|---|---|
| 1 | `TestUpdate` | `test_update_deleted_file_status_to_enable_returns_400` | `status=ENABLE` の PATCH が 400、`detail` が「削除済みのファイルは更新できません。」、`status=DELETED` で一覧すると状態が DELETED のまま |
| 2 | `TestUpdate` | `test_update_deleted_file_status_to_disable_returns_400` | `status=DISABLE` の PATCH が 400、状態が DELETED のまま |
| 3 | `TestUpdate` | `test_update_deleted_file_metadata_returns_400` | `displayName`・`reference` の PATCH が 400、一覧の表示名・参照先が変わらない |
| 4 | `TestUpdate` | `test_replace_deleted_file_returns_400` | 添付ファイル＋`name` の PATCH が 400、`status=DELETED` の一覧に元のファイル ID が 1 件だけ残り、学習中の一覧は 0 件 |
| 5 | `TestUpdate` | `test_replace_deleted_file_without_name_returns_deleted_error` | 添付ファイルのみ（`name` なし）の PATCH が 400 で、`detail` が削除済みのメッセージ |
| 6 | `TestDownload` | `test_download_deleted_file_returns_400` | GET が 400、`detail` が「削除済みのファイルはダウンロードできません。」 |
