# 01_要件定義

## 背景

学習データのファイルを削除（論理削除）すると、状態が「削除済み」になり、保存してあるファイルの実体も消える。#178 で一覧から削除済みを除いたが、ファイル ID を指定する操作と、チャットの RAG（検索結果を回答の文脈に使う処理）では削除済みかどうかを確かめていない。

- 更新: 削除済みのファイルの状態を「学習中」「停止中」に戻せる。表示名などの変更や差し替えも受け付けてしまう
- ダウンロード: 実体が消えているため、サーバー内部のエラー（500）になる
- RAG: 検索結果に削除済みのファイルの内容が含まれていると、そのまま回答の文脈と参照先に使ってしまう

移植元は、更新では削除済みを拒否し（NAW-1375）、RAG では論理削除時にベクトルストアからチャンクを消しているため削除済みのファイルが検索に出ない。

## 機能要件

1. 削除済みのファイルへの更新（状態・表示名・参照先の変更、添付ファイルでの差し替え）は、すべて 400「削除済みのファイルは更新できません。」で拒否し、何も変更しない（移植元 NAW-1375 と同じ）
   - 削除済みかどうかの確認は、ファイルの存在確認の直後、ほかの入力の検証より前に行う
2. 削除済みのファイルのダウンロードは、400「削除済みのファイルはダウンロードできません。」で拒否する（500 にしない）
3. RAG で検索結果を回答の文脈・参照先に使うとき、削除済みのファイルの内容は使わない（学習中・停止中のファイルの扱いは変えない）

## 非機能要件

- エラー応答の形式は既存の API と同じ（`detail` にメッセージを入れる）
- ステータスコードは既存の「status=DELETED は PATCH では指定できません」と同じ 400 を使う
- DB のマイグレーションは行わない

## スコープ外

- ファイルの登録・削除時にベクトルストアへチャンクを登録・削除する処理（コンテンツ分割・ベクトル登録は未移植で別 Issue のスコープ）
- 削除済みのファイルをもう一度削除したときの扱い（移植元もストレージ削除をもう一度呼ぶだけで、状態は戻らない）
- 停止中（DISABLE）のファイルを RAG から除くこと（移植元も除いていない）
- 更新 API での学習先 ID の不一致チェック、移植元で 400 の本文にメッセージが入らない既存バグ（NAW-1380）
- 削除と更新が同時に届いたときの同時実行制御
