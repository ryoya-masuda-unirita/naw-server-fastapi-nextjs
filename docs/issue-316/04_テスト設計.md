# 04_テスト設計

## テスト方針

土台自体のテストは、(1) 権限別ユーザーの確認、(2) 集計の確認、(3) 見本として書いた 03_ログイン 23 項目の実行、の 3 つで行う。実際に専用環境を起動して流す。ブラウザでの目視確認は行わない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 専用環境 | 1 コマンドで起動・テスト・破棄 | 画面と API が応答してテストが走り、終了後にコンテナ・ボリュームが残らない |
| 2 | 既存環境への影響 | 専用環境の起動中 | 既存のコンテナ・ポート・イメージ名に触れない |
| 3 | ローカル以外の拒否 | 実行先がローカル以外 | 起動・テストを拒否する |
| 4 | 権限別ユーザー | システム管理者・テナント管理者・一般ユーザー・グループ管理者 | API ログインで role が一致し、画面ログインでログイン後の画面に着く |
| 5 | テストデータ | テスト専用ユーザーの作成 | 初期パスワードが設定されてログインでき、テスト終了時に削除される |
| 6 | 項番の対応づけ | テスト名の先頭が `[カテゴリ-項番]` | 項番ごとに結果が集計される |
| 7 | 同じ項番に複数のテスト | OK と NG が混在 | NG になる |
| 8 | skip | 理由つきの `test.skip` | 「未実施（skip・理由あり）」に理由が出る |
| 9 | 未作成 | テストが書かれていない項番 | 「未実施（未作成）」として数える |
| 10 | 項目数 | 項目書の 20 カテゴリ | 合計 627 になる |
| 11 | 03_ログイン | 23 項目すべて | OK / NG が項番ごとに出る。NG は原因を確かめて記録する |
