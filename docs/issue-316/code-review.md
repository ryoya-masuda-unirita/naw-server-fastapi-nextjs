## 詳細

### 1. 並列実行で環境が衝突する（🔴 致命的）→ 対応済み

5 本のエージェントが並列にテストを書く前提なのに、プロジェクト名 `naw-e2e-spec`・ポート 55273/58100・イメージ名 `naw-e2e-spec-backend`・`test-results/` が固定だった。

- `E2E_SPEC_PROJECT` でプロジェクト名を変えられるようにし、backend のイメージ名はプロジェクト名から決める（`docker/compose.override.yml` は `E2E_SPEC_BACKEND_IMAGE` を受ける）。ポートは既存の `E2E_SPEC_FRONTEND_PORT`・`E2E_SPEC_BACKEND_PORT`
- Playwright の `outputDir` を `E2E_SPEC_REPORT_DIR` の下にして、同じディレクトリで同時に流しても trace が衝突しない
- 実際に、既定の環境と `E2E_SPEC_PROJECT=naw-e2e-spec-b`（ポート 55274/58101）の環境を**同時に**起動して `tests/00-foundation.spec.ts` を流し、どちらも `8 passed`、終了後にコンテナ 0 件を確認した（修正前は同時に流すと `ENOENT`（trace の衝突）で NG になった）
- 手順書（`e2e-spec/README.md`）に、同時に動かすときの環境変数を追記した

### 2. 起動に失敗したときに環境が残る（🟡 注意）→ 対応済み

`envUp` を `try` の外に置いていたため、`docker compose up` が途中で失敗すると破棄に進まなかった。`envUp` を `try ... finally` の中に入れた（`--keep-env` のときは残す）。

### 3. 書かれた項番の検出（🟡 注意）→ 対応しない

テストファイルの文字列を正規表現で走査するため、コメントに `[04-01]` と書くと「書かれた」と数える。影響は「未作成」と「未実行」の区別だけ（OK / NG の数は変わらない）。AST を解析するほどの価値はない。手順書で「テスト名の先頭に書く」としている。

### 4. 読み替えた項目（🟡 注意）→ 対応しない

サブドメインを使わない決定（#193・#195）と、Chrome 本体を使わない環境のため。読み替えの内容は `ng-ログイン.md` と `03_詳細設計.md` に書いた。

### 5. CI への組み込み（🔵 提案）→ 対応しない

Issue のスコープ外（`01_要件定義.md`）。専用環境の起動が要るテスト本体は CI に載せず、lint・型チェックだけを載せるのは後続で判断する。
