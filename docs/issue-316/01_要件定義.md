# 01_要件定義

## 背景

移植元の結合テスト項目書（20 カテゴリ・627 項目）は人が手で確かめたもので、移植した React + backend が同じに動くかを繰り返し確かめる手段がない。項目を自動テストにして、移植の完成度（NG の数）を数字で追えるようにしたい。

後で複数のエージェントがカテゴリごとに並列でテストを書くため、書き始める前に、衝突しない土台（置き場所・命名・共通部品・集計）を作る必要がある。

## 機能要件

1. 項目書の 1 項目 = 1 つの Playwright テストとして書ける新モジュールがある
2. 手元の既存環境（開発用コンテナ・デモ・探索ハーネスの環境）に触れない専用環境で、画面と backend を起動できる
   - 起動・テスト・破棄までを 1 コマンドで行える
   - 起動済みの環境に対してテストだけを流すこともできる
3. 共通部品がある
   - 権限別（システム管理者・テナント管理者・一般ユーザー・グループ管理者）のログイン
   - テストデータの準備と後片付けのための API ヘルパー
   - 画面ごとの Page Object の置き方
   - テスト名と項目書の項番の対応づけ（`[カテゴリ-項番] 小項目`）
4. 結果を項目書と同じ形で集計する
   - 項番ごとの OK / NG / 未実施（skip は理由つき）
   - カテゴリごとの 項目数・OK・NG・未実施 を Markdown と JSON に出す
   - 項目書の項目数と突き合わせ、テストが書かれていない項番は「未実施（未作成）」として数える
5. 見本として 03_ログイン（23 項目）をすべてテストにし、実際に実行した結果を記録する
   - NG は、移植元の挙動と React/backend の挙動のどちらが正しいかを移植元のコードと項目書の備考で確かめ、本当の差なら原因つきで記録する
6. 他のカテゴリを書く人向けの手順書がある

## 非機能要件

- 専用環境はローカルの URL にしか向けない（データを作成・削除するため）
- テストは並列に実行できる。互いのデータ（パスワード変更・ロック・削除）を壊さない
- lint と型チェックのコマンドがあり、通る
- 失敗を隠さない（再実行や期待値の緩和で OK にしない）

## スコープ外

- 04〜22 のカテゴリのテスト（別のエージェントが書く）
- NG の修正、および NG の Issue 起票（記録までを行う）
- `e2e-explorer/`（画面の巡回）の変更
- CI への組み込み
