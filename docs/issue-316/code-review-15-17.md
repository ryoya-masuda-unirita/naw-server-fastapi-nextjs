## 詳細

### 1. 「出ないこと」の確認が早すぎる（🔴 致命的）→ 対応済み

`search(...)` の直後に `rows` の `toHaveCount(0)` を評価すると、読み込み中の 0 行で通る。期間フィルターが壊れて出てはいけないデータが出ていても、結果が出る前にアサーションが通る（偽の OK）。17-12・13・14（seed のファイル10）と 16-07・08（seed の 2・8 日前のチャット）で、`toHaveCount(0)` の前に空状態の文言（「データがありません」「チャット履歴が見つかりません。」）が出るのを待つようにした。空状態の文言は結果が 0 件で確定してから出る（読み込み中はローディング表示）。

### 2. 追加の成否の決め方（🔴 致命的）→ 対応済み

`added.or(errorToast).first()` で先に見えた方に解決していたため、拒否のはずなのに遅れて追加された場合や、トーストが出てすぐ消える場合を見逃しうる。ファイル追加の API（`POST /api/admin/indexes/{id}/files`）の応答を待ち、ステータス（許可は 200・拒否は 429）、一覧に出たか、エラーのトーストが出たかを別々に確かめるようにした。

### 3. 後片付けの例外が失敗を覆い隠す（🟡 注意）→ 対応済み

プラン制限用のテナントの削除を、テスト本体の `finally` から fixture（`makeQuotaTenant`）に移した。fixture の後片付けの失敗は、テスト本体の失敗とは別のエラーとして報告される。テナントを消す SQL は、`tenants` を消すとほとんどの表が `ON DELETE CASCADE` で消える（スキーマで確認）ため、`password_histories`（カスケードなし）だけ先に消している。

### 4. 後片付けが途中で止まる（🟡 注意）→ 対応済み

`prefix`・`makeRoom`・`makeQuotaTenant` の後片付けを `runCleanup` にまとめた。1 つが失敗しても残りを実行し、最後に `AggregateError` でまとめて報告する。

### 5. seed のチャットの相対日数への依存（🟡 注意）→ 対応済み

16-08・16-09 の「含まれること」を、作ったばかりのチャットで確かめるようにした（16-07 と同じ）。seed の古いチャットは「含まれないこと」の確認だけに使う。環境が古くなるほど seed のチャットはより古くなるので、除外の確認は変わらない。

### 6. 管理者のパスワードの定数（🔵 提案）→ 対応済み

`QUOTA_ADMIN_LOGIN_ID`・`QUOTA_ADMIN_PASSWORD` を `USERS.tenantAdmin`（`src/users.ts`）から取るようにした。

### 7. カレンダーの日のボタン（🟡 注意）→ 対応しない

表示中の月以外の日（前月末・翌月初）は `<td>` だけでボタンではない（実際の画面の aria snapshot で確認）ため、日の名前のボタンは 1 つに決まる。タイムゾーンは、画面の日付がブラウザ（この PC と同じ）のタイムゾーンで、テストの `new Date()` も同じなので、ずれない。どちらも理由をコメントに書いた。

### 8. カテゴリ名の並びの比較（🟡 注意）→ 対応しない

カテゴリ管理タブは、並べ替えとページ分けを画面側（JavaScript の文字列の大小比較）で行う。移植元の `AssistantCategoryListStore.applyFilter`（`assistant-category-list.store.ts`）と React の `category-tab.tsx` の `applyFilter` は同じ比較で、DB の照合順序は関係しない。テストの期待も同じ比較（`sort()`）で作っている。理由をコメントに書いた。

### 9. seed のフォルダのファイル数（🔵 提案）→ 対応しない

seed のクラウドフォルダは、担当 3 カテゴリのどのテストも**読むだけ**（書き込む項目は、テストごとに作るフォルダで行う）。専用環境は実行ごとに作り直す前提で、seed の件数は項目書の確認用に意図して用意された値なので、固定のままにしている。

### 10. テナント ID の乱数（🔵 提案）→ 対応しない

`db-quota.ts` は fixture（`uniqueId`）を使えない同期の処理で、8 桁の乱数の衝突は実用上起きない。
