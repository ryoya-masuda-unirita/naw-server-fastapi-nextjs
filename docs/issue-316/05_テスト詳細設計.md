# 05_テスト詳細設計

## 実装対象のテストファイル

| ファイル | 内容 |
|---|---|
| `e2e-spec/tests/00-foundation.spec.ts` | 権限別 4 ユーザーの API ログイン（ID・role）と画面ログイン（04-4 の観点） |
| `e2e-spec/tests/03-login.spec.ts` | 03_ログイン 23 項目（`[03-01]`〜`[03-23]`） |

集計（観点 6〜10）は、実行して出力された `summary.md` / `summary.json` で確認する。観点 7・8 は、一時的なテストファイルを置いて実行し、確認後に削除した（コミットしない）。

## 03_ログインの各項目

| 項番 | 小項目 | 確認の方法 | 準備するデータ |
|---|---|---|---|
| 01 | ログイン画面表示 | `/auth/login` を開き、ユーザーID・パスワード欄とボタンが見える | なし |
| 02 | 正常ログイン | user01 でログイン。ダッシュボードに遷移し、サイドバーとメイン領域が見える | seed の一般ユーザー |
| 03 | ユーザーID未入力 | パスワードだけ入力して送信。「この項目は必須です」が 1 つ出る | なし |
| 04 | パスワード未入力 | ユーザーIDだけ入力して送信。同上 | なし |
| 05 | 両方未入力 | 空のまま送信。同じ文言が 2 つ出る | なし |
| 06 | 認証失敗（ID誤り） | 存在しないID。`POST /auth/login` が 403 と「Authentication failed」、画面に「ユーザIDかパスワードが間違っています」、ログイン画面に留まる | なし |
| 07 | 認証失敗（PW誤り） | 同上（誤ったパスワード） | テスト専用ユーザー |
| 08 | ログイン試行回数上限 | 誤ったパスワードで 6 回。上限の文言が出る。さらに正しいパスワードでも 429 | テスト専用ユーザー |
| 09 | パスワード表示切替 | 切替ボタンで `type` が password → text → password、値は変わらない | なし |
| 10 | 初回PW遷移 | 初期パスワードのままのユーザーでログイン。`/auth/password/reset` に遷移 | テスト専用ユーザー（`activate: false`） |
| 11 | 期限切れPW遷移 | seed の期限切れユーザーでログイン。`/auth/password/reset` に遷移 | seed の期限切れユーザー（読むだけ） |
| 12 | テナントURL必須確認 | テナント ID なしは送信されず、存在しないテナント ID は失敗、正しいテナント ID は成功 | なし |
| 13 | 認証後URL直アクセス | ログイン後に `/auth/login` を開くと認証後の画面に戻る | seed の一般ユーザー |
| 14 | 利用規約リンク表示 | フッターに利用規約・プライバシーポリシー・運営会社のリンク | なし |
| 15 | ユーザーID最小文字数 | 3 文字のIDでログインでき、認証 API の応答が成功 | テスト専用ユーザー（3 文字） |
| 16 | ユーザーID最大文字数 | 50 文字のIDで同上 | テスト専用ユーザー（50 文字） |
| 17 | ユーザーID文字数不足 | 2 文字のIDで送信。「3文字以上で入力してください」が出て、認証 API は呼ばれない | なし |
| 18 | パスワード最小文字数 | 12 文字（テナントの最小長）のパスワードでログインできる | テスト専用ユーザー |
| 19 | 正常ログイン Chrome | Chromium でログイン | seed の一般ユーザー |
| 20 | ログインキー（正常・セッションなし） | 発行したキーでダッシュボードを開く。ログイン画面を経由せず、そのユーザーでログイン | テスト専用ユーザー（キー発行） |
| 21 | ログインキー（正常・セッションあり） | user01 でログイン中に別ユーザーのキーで開く。そのユーザーに切り替わる | 同上 |
| 22 | ログインキー（異常・セッションなし） | 不正なキーで開く。ログイン画面に遷移 | なし |
| 23 | ログインキー（異常・セッションあり） | user01 でログイン中に不正なキーで開く。ログイン中のまま、アラートが出る（3 つの確認を soft にして全部の失敗を残す） | seed の一般ユーザー |
