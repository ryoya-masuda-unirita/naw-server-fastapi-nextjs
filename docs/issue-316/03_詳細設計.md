## 集計の判定

- テスト 1 件の結果: `outcome()` が `skipped` → SKIP（理由は `test.skip` の説明）、`unexpected` → NG（エラー全文。`expect.soft` の複数の失敗も残す）、それ以外（flaky を含む）→ OK
- 項番の結果: 同じ項番のテストが複数あれば、NG > SKIP > OK
- 結果がない項番: `tests/` に書かれていれば「未実行」、なければ「未作成」
- カテゴリの未実施 = SKIP + 未実行 + 未作成

## 画面のテナント ID

移植元はサブドメインでテナントを決めるが、このプロジェクトはログイン画面でテナント ID を入力する。`LoginPage.attemptLogin` は常にテナント ID を入力する。ログインキーのクエリには `tenantId` を付ける（`frontend/src/lib/initializers/login-key.ts` の仕様）。

## 03_ログインでの項目書との読み替え

- 03-12（テナント URL 必須）: テナント ID の入力に読み替える
- 03-19（Chrome）: Playwright の Chromium
- 03-08（試行回数上限）: 移植元は 6 回目の失敗で 429

## 注意（並列実行）

- ロック・パスワード変更・削除をするテストは `createUser` のテスト専用ユーザーを使い、seed のユーザーは変更しない
- seed の `expired-password-user` は読むだけ（ログインしても期限切れ状態は変わらない）
