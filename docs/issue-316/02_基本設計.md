# 02_基本設計

## 変更対象

- 新しいモジュール（Playwright・TypeScript）
- ドキュメント（本 Issue の docs）

既存の frontend・backend・e2e-explorer・ルートの compose ファイルは変更しない。

## 画面 / API 変更概要

画面・API の変更はない。テスト対象の画面・API を外から操作するだけである。

### 実行環境

- ルートのデモ用 compose（backend・frontend・PostgreSQL・Redis・LocalStack、デモデータ入り）を、別のプロジェクト名・別のポートで起動する
- 手元のデモ環境のイメージを付け替えないよう、イメージ名だけ専用にする上書き設定を重ねる
- デモの seed にないシステム管理者を、起動後に追加する
- 画面と backend が応答するまで待ってからテストに進む

### 共通部品

- 権限別のログインユーザーの定義（システム管理者・テナント管理者・一般ユーザー・グループ管理者）
- テストデータの準備用 API ヘルパー（ログイン、ユーザーの作成・初期パスワード設定・削除、ログイン中のユーザーの取得）
- fixture: 画面ログイン、管理者 API、テスト専用ユーザー（終了時に自動削除）、重ならない ID
- 画面ごとの Page Object（ログイン画面を見本にする）

### 項番との対応づけ

- テスト名の先頭に `[カテゴリ-項番]` を付ける（例: `[03-02] 正常ログイン`）
- 1 つの項番を複数のテストに分けてよい。集計は一番悪い結果を採る

### 結果の集計

- Playwright のレポーターで項番ごとの結果（OK / NG / skip と理由）を集める
- 項目書（Markdown）を読み込み、カテゴリごとの項目数と突き合わせる
- テストファイルに書かれている項番を調べ、書かれていない項番を「未作成」、書かれているが実行に含まれない項番を「未実行」と区別する
- 出力は、人が読む Markdown、機械が読む JSON（集計・項番ごとの結果）
- 別々に流した結果をまとめるコマンドを用意する（並列に書く担当の結果の統合用）

## 影響範囲

- 既存のコード・CI への影響はない
- ホストのポート 55273（画面）と 58100（backend）を使う。既存の環境（5173/8001、55173/58000）とは重ならない

## 移植方針

移植ではなく、移植結果の検証用の仕組みである。参考にした既存の仕組み:

- e2e-explorer: 専用環境の起動・破棄、ローカル以外を拒否する安全策、TypeScript の型除去実行、ESLint / tsconfig の設定
- 移植元の e2e-test: fixture でテスト用データを準備し、Page Object で画面を操作する構成
