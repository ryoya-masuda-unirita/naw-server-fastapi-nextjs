# 01_要件定義

## 背景

移植元（naw-server, Spring Boot）には、チャットのメッセージ（質問・回答のスレッド）を扱う API 群が存在する。
このリポジトリでは #45 でチャットルーム管理 API（ルームの作成・一覧・更新・削除・固定）を移植済みだが、
ルーム内のメッセージそのものを扱う API はまだ移植されていない。

メッセージ関連 API のうち、LLM（Azure OpenAI）へのチャット応答生成を伴う SSE ストリーミング API
（回答の生成・保存）は、LLM 連携基盤の移植とあわせて別issueで対応する。本issueでは、それ以外の
同期的な CRUD 系エンドポイントを先行して移植する。

## 機能要件

- メッセージ（質問スレッド）を新規作成できる。ルームIDを指定しない場合は新規ルームを同時に作成する
- 指定したルームのメッセージ一覧と、そのメッセージ群が参照するアシスタント情報を取得できる
- 指定したメッセージID群に対応するメッセージ内容（質問・回答・添付ファイル・参照ファイルパス）を取得できる
- メッセージを削除できる（子孫メッセージ・メッセージ内容も再帰的に削除する）
- メッセージ内容IDを指定してメッセージを削除できる（削除対象の解決方法が異なるだけで、削除処理はメッセージ削除と同じ）
- メッセージに対して良い/悪いの評価（フィードバック）を登録・更新できる（1メッセージにつき1件、既存があれば上書き）
- いずれの操作もテナント分離（RLS）を前提とし、自分が所有するルームのメッセージのみを操作対象とする

## 非機能要件

- 既存のルーム所有権チェック（ルームの `user_id` が自分であること）と同じ方式でアクセス制御する
- レスポンス形式・エラーハンドリングは既存の移植済みAPI（アシスタント管理・チャットルーム管理等）の方針に合わせる
- テナントをまたぐデータアクセスが発生しないよう、既存の RLS の仕組みをそのまま利用する

## スコープ外

- `POST /api/messages/content`（SSE ストリーミングによる LLM チャット応答生成・回答再生成・ライブラリ生成）は別issueで対応する
- LLM 連携（Azure OpenAI 呼び出し）、RAG 検索、トークン使用量記録は本issueでは扱わない
- 月次クレジット上限チェック（契約プラン・請求期間に基づく利用制限）は、移植元でプラン・請求期間・トークン使用量の各機能に依存しているが、
  それらの基盤（プラン管理・請求期間・トークン使用量記録）がこのリポジトリにまだ移植されていないため、本issueではチェックを実装しない
- ルームの共有機能（グループ共有・共有リンク経由のアクセス、テナント管理者による閲覧バイパス）は、共有機能自体が未移植のため本issueでは対象外とし、
  既存のルーム移植（#45）と同様にルーム所有者のみがアクセスできる方式とする
- 添付ファイル（メッセージ内容に紐づくファイル）は `POST /api/messages/content` 側で作成されるものであり、本issueでは作成経路を持たない。
  データモデル・取得APIのみ用意し、動作確認は手動で投入したデータに対して行う
