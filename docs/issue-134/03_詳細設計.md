# 03_詳細設計

## API（`docs/issue-279/api-backend-diff.md` と `backend/app/routers/rooms.py`・`schemas/room.py` を確認）

| API | 形 | 移植元との差と対応 |
|---|---|---|
| `GET /api/admin/histories` | `{ content, totalElements, number, size }` | ページング形は一致。`page` 0 始まり、`size` 1〜100（20 件で問題なし）、`orderBy` は `updatedAt`・`name`・`userName`（それ以外は updatedAt）、`reverse` |
| `createdAtFrom`・`createdAtTo` | ISO 8601（オフセット付き）のみ。To は排他 | #279 の `toDateTimeRange` が「開始日 0:00」「終了日の翌日 0:00」の UTC 日時にする。そのまま使用 |
| 行 | `name`・`userName` は null がある。`description` は無い | `name ?? ''`・`userName ?? ''` で吸収。`description` は backend が返さないため説明行は出ない（型は #279 のまま） |
| ユーザー絞り込み | `userId`（UUID） | 差なし |

## 状態

`useChatHistoryStore`: `filter`（pageSize 20・pageIndex 1・updatedAt desc）。条件を変えると 1 ページ目。画面を離れたら `reset()`。

## 移植元と変えた点（理由）

1. **画面を離れたら条件を捨てる**（`reset()`）。移植元は singleton ストアに条件が残るが、フィルター欄は初期値に戻るため見えない条件で絞り込まれる。#124・#136 と同じ判断
2. **フォーカスでの再取得をしない**（`refetchOnWindowFocus: false`）。移植元は開いたときと操作したときだけ読み込む
3. 一覧取得の失敗は空として扱う（移植元は `items: []`）。共通エラートーストは api-client が出す

## 移植元どおりにしたもの

- 検索はデバウンスなし（移植元の `SearchInput` もなし）
- 一覧ヘッダー右端のスペーサーのクラス `_w-9 _h-9`（移植元の誤記と思われるが、見た目を揃えるためそのまま）
- ユーザーの選択肢は最新 20 件の履歴からの近似。20 件に現れないユーザーは選べない（申し送り）
- 最終ページ外への補正はしない（移植元にもなく、この画面に削除操作がないため起きない）
