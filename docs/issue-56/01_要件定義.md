# 01_要件定義

## 背景

移植元（naw-server, Spring Boot）には、ユーザーがルームに満足度評価を登録するAPIと、管理者がルーム単位のフィードバックを一覧で確認できるAPIが存在する。
このリポジトリではルーム一覧・詳細・作成更新削除・固定は移植済みで、`rooms.rating` カラムも既にモデルに存在する。message feedback 周辺は #52, #54 で移植済みのため、次はルーム評価の登録と管理者一覧をまとめて実装する。

## 機能要件

### POST /api/rooms/{roomId}/feedback

- ログインユーザーが自分の所有するルームに満足度評価（`rating`）を登録できる
- `rating` は `EXCELLENT` / `VERY_GOOD` / `GOOD` / `AVERAGE` / `POOR` のいずれか
- 対象ルームが存在しない、または自分が所有していない場合はエラーとする
- 成功時は本文なしで返す（204）

### GET /api/admin/feedbackRoom

- テナント内の、`rating` が登録済みのルームをページング付きで一覧取得できる
- 各一覧項目に以下を含める
  - フィードバックID（ルームID）
  - テナントID
  - ユーザーID・ユーザー表示名
  - ルームID
  - ルーム情報（`id`, `name`, `defaultAssistantId`, `defaultAssistantName`, `rating`）
  - 評価（`rating`）
  - 作成日時・更新日時
- `assistantId`（`defaultAssistantId` 一致）で絞り込める
- `rating` で絞り込める
- 指定項目でソートできる
  - `updatedAt`
  - `chat`（ルーム名）
  - `name`（デフォルトアシスタントID）
  - `level`（評価）

## 非機能要件

- `POST /api/rooms/{roomId}/feedback` はログイン済みユーザーであれば誰でも呼べるが、対象ルームの所有者でない場合は権限エラーとする（移植元 `RoomAccessService.canWriteRoom` はオーナー判定のみのため、既存の `RoomService._get_owned_room_or_404` と同じ判定を再利用する）
- `GET /api/admin/feedbackRoom` は管理者（テナント管理者またはグループ管理者）のみアクセスできる（既存の `require_admin_or_group_admin` を使用）
- 本リポジトリ既存の一覧APIと同様、0始まりページングを採用する

## スコープ外

- `folderId` による絞り込み、およびレスポンスの `indexId`（ルームに紐づく追加学習フォルダ）
  - 移植元では `files` テーブルからルームに紐づくフォルダIDを導出しているが、FastAPI 側では `files` ドメインが未移植のため対象外とする
- `feedbackUser` / `feedbackMessage` の追加改修
