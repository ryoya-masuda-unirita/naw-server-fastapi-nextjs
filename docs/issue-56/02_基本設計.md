# 02_基本設計

## 変更対象

ルーム満足度フィードバックAPIを2本追加する（新規テーブルなし、`rooms.rating` は既存カラムを使用）。

## 画面 / API 変更概要

| メソッド | パス | 概要 |
|---|---|---|
| POST | `/api/rooms/{roomId}/feedback` | ルームへの満足度評価登録（ルーム所有者限定） |
| GET | `/api/admin/feedbackRoom` | ルームフィードバック一覧取得（ページング・ソート・絞り込み対応、管理者限定） |

`GET /api/admin/feedbackRoom` は既存の `feedbackMessage` と異なりローカルサーバー接続情報を含まないため、本リポジトリの一覧API標準形式である `PagedFeedbackRoomResponse` を直接返す方針とする（ラッパーなし）。

## 影響範囲

- 新規テーブルはなし。既存の `rooms` / `users` / `assistants` を読み取り・更新する
- 既存テーブルへの変更はない（`rooms.rating` は既存カラム）
- `router` は既存の `routers/rooms.py`（POST）と `routers/feedback.py`（GET admin）にそれぞれ追加する
- `service` は既存の `RoomService`（POST、update系と同じ責務）と `FeedbackService`（GET、既存 `get_feedback_messages` と同じ責務）にそれぞれメソッドを追加する
- `repository` は `RoomRepository` に一覧取得用クエリを追加する

## 移植方針

- POST 側の認可は既存の `RoomService._get_owned_room_or_404`（所有者のみ）を再利用する
- GET 側の認可は既存の `require_admin_or_group_admin` を使う
- `assistantId` / `rating` の絞り込みは、既存の repository パターンに合わせて SQLAlchemy の `select()` と条件追加で実装する
- `rating IS NOT NULL` を必須条件とする（未評価ルームは一覧に出さない）
- ユーザー表示名・アシスタント名は、一覧に含まれる `userId` / `assistantId` 群を集めて N+1 を避けて1クエリずつで解決する（既存 `getFeedbackRooms` の displayNames / assistantNames と同じ方針）
- `sortField` の論理名は以下の実カラムへマッピングする
  - `updatedAt` → `rooms.updated_at`
  - `chat` → `rooms.name`
  - `name` → `rooms.default_assistant_id`
  - `level` → `rooms.rating`
- ページングは既存の `page` / `size` クエリ（0始まり）に合わせる
- レスポンスの `folderId` 絞り込み・`indexId` は `01_要件定義.md` のスコープ外方針に従い実装しない
