# #402 issue-402 /api/llm/chat で、クライアントが message_stop の直後に接続を閉じるとトークン使用量が記録されない

## 概要

`/api/llm/chat` を、`message_stop` を読んだ直後に接続を閉じるクライアントで呼ぶと、`token_usages` に使用量が記録されない。SECURE の SecuAiGent ベンダー経由のチャットで、使用量・クレジットが記録されない。#102 の通しの確認で見つかった。

## 説明

- アダプタ（`generative-ai-core` の SecuAiGent ベンダー）は `message_stop` を読むと接続を閉じる。この経路では `message_stop`（入力 11・出力 7）は返るのに、`token_usages` に行ができない（2 回とも）。同じ呼び出しを最後まで読むと記録される
- 再現直後に `connection is closed`（`InterfaceError`）の 500 が 1 回出た。次のリクエストでは回復した
- 原因の見立て（Issue 起票時は未検証）: 切断でリクエストのタスクがキャンセルされ、`finally` 内の `await` による記録（新規セッションのコミット）が中断される
- 移植元: `LlmChatService.streamAndPersist` は別スレッドで動き、切断の影響を受けずに `persistTokenUsageInNewTransaction` を呼ぶ
- 修正案: 記録をキャンセルされないタスクで行う。メッセージ送信（`message_service`）の `finally` も同じ構造のため波及を確かめる。切断を再現するテストを足す
