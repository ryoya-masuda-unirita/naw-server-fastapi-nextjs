# 03_詳細設計

## 新規: `backend/app/core/shielded.py`

`run_shielded(coro)`: コルーチンを別タスク（`asyncio.ensure_future`）にして `asyncio.shield` で待つ。

- 呼び出し元がキャンセルされても、別タスクは最後まで動く。呼び出し元には `CancelledError` がそのまま伝わる
- 実行中のタスクをモジュール内の集合で保持し、完了時に外す（イベントループは弱参照しか持たないため、回収を防ぐ）
- 呼び出し元が受け取れなかった例外は、完了時のコールバックでログに残す

## 変更: `backend/app/services/llm_chat_service.py`

- `stream_chat` 内に `persist_after_stream(library_title, library_content, input_tokens, output_tokens)` を追加。ライブラリ保存とトークン使用量保存を、従来どおり個別に例外を捕捉してログに残す
- `event_stream()` の `finally` は、`await run_shielded(persist_after_stream(...))` だけにする

## 変更: `backend/app/services/message_service.py`

- `stream_message_content` 内に `persist_after_stream(content_status, answer_text, library_title, library_content, input_tokens, output_tokens)` を追加。回答・ライブラリ・トークン使用量の保存を、従来どおりの順序・例外処理で行い、`(content_response, persist_failed)` を返す
- `event_stream()` の `finally` は、`run_shielded` の結果で従来どおり `message_content` または `error` イベントを送る。切断でキャンセルされた場合は `CancelledError` が伝播し、送出処理は行われない（クライアントは既にいない）

## 変更しないもの

- `_persist_token_usage`・`_persist_message_content`・`_persist_library`（保存処理本体）
- SSE のイベント形式
