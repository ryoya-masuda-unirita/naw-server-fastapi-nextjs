# 01_要件定義

## 背景

SSE でストリーム配信する API は、配信が終わった後に、回答・ライブラリ・トークン使用量を新しい DB セッションで保存する。保存は、配信用ジェネレータの終了処理（`finally`）で行っている。

クライアントが接続を切ると、Web フレームワークは配信中のタスクをキャンセルする。キャンセルは終了処理の中の待機（`await`）にも及ぶため、保存の DB コミットが途中で中断される。実機（uvicorn）では、切断を検知するモードで配信されるため、この経路になる。

移植元は、配信と保存を別スレッドで動かすため、切断の影響を受けずに保存が完了する。SECURE のアダプタは `message_stop` を読むと接続を閉じるので、この API では毎回この状況になる。

## 機能要件

- クライアントが `message_stop` の直後（または配信の途中）に接続を閉じても、トークン使用量が記録されること（LLM チャット API）
- 同じく、メッセージ送信 API でも、回答（`message_content`）・ライブラリ・トークン使用量が記録されること
- 保存の失敗をログに残してストリームを正常に閉じる、既存の挙動は変えない
- 切断されていない通常の配信では、イベントの種類・順序・内容を変えない

## 非機能要件

- 保存処理が切断で中断されても、DB 接続が壊れた状態でプールに戻らないこと（切断後の `connection is closed` の 500 を出さない）
- 追加の依存ライブラリを入れない

## スコープ外

- 切断時に LLM への問い合わせ自体を止めるかどうか（現状どおり、配信が止まった時点でその先の読み取りは行わない）
- 移植元にない新しい永続化の仕組み（キュー・ジョブ基盤など）の導入
- ディレクトリ名変更（#399）に伴う変更
