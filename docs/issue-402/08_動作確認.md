# 08_動作確認

## 確認環境

- 全自動モードのため、動作確認は自動テストのみで代替した（実機のサーバー起動・実 DB・ブラウザでの確認はしていない）
- `server/.env` はどこにも無かったため、`server/.env.example` をコピーして使った（コミットしない）
- Python 3.14（`.venv`）、Starlette 1.3.1、uvicorn 0.49.0（HTTP の ASGI spec_version は 2.3）

## 確認手順

1. 切断を再現するテストを先に書き、修正前に実行した
2. `run_shielded` を入れて実行した
3. `run_shielded` の中身を一時的に `asyncio.shield` なしに戻し、新規テストが失敗することを確認し、元に戻した
4. `cd backend && uv run pytest` で全体を実行した。`uv run ruff check`・`ruff format --check`・`mypy app` も実行した

## 確認結果

- 修正前: 新規の 2 テストとも失敗した。LLM チャットはトークン使用量 0 件、メッセージ送信は回答の保存が 0 件（使用量も 0 件）。**原因の見立て（切断のキャンセルで `finally` 内の保存が中断される）のとおりだった**
- メッセージ送信の `finally` も同じ構造で、同じ不具合があった（Issue の見立てどおり）。この PR で一緒に直した
- 修正後: 新規テストが通る。`shield` を外すと再び失敗する（テストが不具合を検出できる）
- `uv run pytest` 全体: 1428 件すべて通過。`ruff`・`mypy` も問題なし
- 既存の切断テスト（`aclose()` で `GeneratorExit` を送るもの）は、キャンセルによる中断を再現しないため、この不具合を検出できていなかった

## 未確認事項

- **`connection is closed`（`InterfaceError`）の 500 が同じ原因か**: 実 PostgreSQL・asyncpg で確認していない。中断されたコミットの接続がプールに戻ったためと考えられ、保存が中断されなくなる本修正で出なくなる想定だが、未検証。SQLite 上のテストでは再現できない
- 実機（uvicorn + PostgreSQL）で、アダプタ（`message_stop` 直後に切断）を使った `token_usages` の記録確認
- 切断後に保存タスクが動き続ける間のシャットダウン時の扱い（保存は短時間のため、通常は問題にならない想定）
