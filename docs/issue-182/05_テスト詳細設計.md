`test_next_message_chains_to_previous_after_reloading_room` のシナリオ:

1. 本文ありのメッセージ A（`owned_message_content`）があるルームで、`POST /api/messages`（親 A）でメッセージ B を作成する
2. B に対して multipart で `POST /api/messages/content` を送信する（LLM はモック）
3. `GET /api/messages?roomId=` と `POST /api/messages/contents` で会話を読み直す
4. 読み直した結果を、frontend-angular の `buildVisibleThread` と同じ規則（親なしから辿り、各階層の最後の兄弟を選び、本文があるものだけを表示）で辿った末尾が B であること
5. その B を親として `POST /api/messages` でメッセージ C を作成し、DB 上の C の `parent_id` が B であること
