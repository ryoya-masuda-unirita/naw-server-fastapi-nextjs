# 既存ルームをURLから直接開いて新規メッセージを送信すると、直前の会話に続かず最初のメッセージの別バージョンとして扱われる

## 概要

チャットルームを `/chat/{roomId}` へ直接遷移（ページリロード）して新規メッセージを送信すると、送信メッセージの `parent_id` がルーム内の直前メッセージではなく、常にルームの**最初のメッセージ**に紐づいてしまう。

## 説明

### 再現手順

1. 既存メッセージが1件あるルームを `/chat/{roomId}` で開く
2. メッセージを送信する（AI回答が返る）
3. 一旦別ページに遷移し、同じルームへ再度 `/chat/{roomId}` で遷移する
4. 別のメッセージを送信する

### 期待結果

送信したメッセージの `parent_id` は、直前に送信されたメッセージ（会話の最新ノード）になり、会話が線形に続く。

### 実際の結果

`parent_id` が常にルーム内の最初のメッセージのままになり、新しく送信したメッセージは直前の会話への追加ではなく、最初のメッセージの「別バージョン（分岐）」として扱われてしまう。

### 確認したデータ例

テスト用ルーム `64000000000040008000000000000001` の `messages` テーブルで、複数回に分けて送信した10件中8件が、すべて同一の最初のメッセージID（`65000000000040008000000000000001`）を `parent_id` として持っていた。

同一ページセッション内で連続送信した場合は正しく前のメッセージへチェインされるため、ページリロードを挟んだ場合にのみ発生する。
