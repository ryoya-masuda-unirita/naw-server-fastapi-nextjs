# 04_テスト設計

## テスト方針

- メッセージ送信 API をクライアントと同じ `multipart/form-data` 形式で呼び出す結合テスト（インメモリ DB）で、本文が保存されることを確認する。
- Issue の再現シナリオ（送信 → 会話を読み直す → 次の送信）を API レベルで再現し、読み直した会話から求めた末尾メッセージが直前のメッセージになることを確認する。
- 入力定義の名前変換・正規化は単体テストで確認する。
- 既存の送信 API テストは新しい形式に置き換えて、従来の観点（404/403/422・再生成・添付ファイル保存）が維持されていることを確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 本体をファイル部で受け付ける | 本体を JSON のファイル部として送信 | 200、ストリームが完了し、質問・回答が保存される |
| 2 | 本体をフォーム値で受け付ける | 本体を通常のフォーム値として送信 | 200、質問・回答が保存される |
| 3 | 本体が JSON でない | 本体に JSON でない文字列 | 422 |
| 4 | 本体が JSON オブジェクトでない | 本体に JSON 配列 | 422 |
| 5 | 本体なし | 本体パートを送らない | 422 |
| 6 | 対象未指定 | 本体に messageId・messageContentId のどちらもない | 422 |
| 7 | 添付ファイル | 添付ファイルをファイル部で送信 | ファイル名・種別・内容が保存される |
| 8 | 過去添付ファイル件数 | 過去添付件数と履歴の件数合計が不一致 | 422 |
| 9 | ライブラリ生成フラグ | 本体に移植元名のライブラリ生成フラグ | ライブラリ生成モードとして扱われる |
| 10 | 出力フォーマット指定 | 本体に移植元名の出力フォーマット指定 | 指定が保持される |
| 11 | 会話履歴の発話種別 | 本体の履歴に移植元の大文字の発話種別 | 小文字の発話種別として扱われる |
| 12 | 不正な発話種別 | 列挙値以外の発話種別 | 入力エラー |
| 13 | 再現シナリオ | メッセージA（本文あり）の後にBを作成・送信し、会話を読み直す | Bの本文が取得でき、末尾がBになる。次のメッセージCの親にBを指定すると親がBで保存される |
| 14 | 既存観点の維持 | 存在しない/他人のメッセージ、回答再生成 | 404 / 403 / 既存回答の上書き（従来どおり） |
