# 08_動作確認

## 確認環境

- **ブラウザ・実機確認は行わず、自動テストのみで代替した**（全自動モード。ローカルの Postgres / Redis / backend サーバーは他の作業と共有のため起動・変更していない）
- `backend/` で `uv run pytest`（インメモリ SQLite + fakeredis、LLM 呼び出しはモック）
- `backend/.env` はメインの作業ツリーからコピーして使用（設定系テストの前提）

## 確認手順

1. 修正前のコードに対して、frontend-angular と同じ形式（`textData` を `application/json` のファイル部として送る `multipart/form-data`）でメッセージ送信 API を呼び、HTTP 422 になることを確認した（原因の裏付け）
2. 修正後、メッセージ送信 API の結合テスト・入力定義の単体テストを実行した
3. 再現シナリオのテスト（`test_next_message_chains_to_previous_after_reloading_room`）について、ルーターの変更だけを一時的に元に戻して実行し、修正前は失敗することを確認した
4. backend の全テストを実行した
