# 02_基本設計

## 変更対象

- メッセージ送信（アシスタント応答生成）API の入力の受け取り方
- メッセージ送信リクエストの入力定義（会話履歴の1発話、送信リクエスト本体）
- 添付ファイル入力定義の説明（受け取り方の変更に伴う記述の更新）
- 上記 API の自動テスト

## 画面 / API 変更概要

### メッセージ送信（アシスタント応答生成）API

| 項目 | 変更前 | 変更後（移植元と同じ） |
|---|---|---|
| Content-Type | `application/json` | `multipart/form-data` |
| 本体 | JSON ボディ全体 | `textData` パート（JSON） |
| 添付ファイル | JSON 内に Base64 文字列で `attachmentFiles` / `historyAttachmentFiles` | ファイルパート `attachmentFiles` / `historyAttachmentFiles`（複数可） |
| ライブラリ生成フラグ | `isCreateLibrary` | `createLibrary` |
| 出力フォーマット指定 | `responseFormat` | `response_format` |
| 会話履歴の発話種別 | `role`（`user` 等） | `type`（`USER` / `ASSISTANT` / `SYSTEM`） |

レスポンス（SSE ストリーム）・ステータスコードの体系は変更しない。

### 入力エラー

- `textData` パートが無い、JSON として解釈できない、JSON オブジェクトでない、または項目のバリデーションに失敗した場合は HTTP 422 を返す（従来と同じステータス）。

## 影響範囲

- 呼び出し元: `frontend-angular/` のチャット送信・編集再送信・回答再生成（移植元形式で送っているため、変更後に正しく受け付けられるようになる）
- `frontend/`（React）からはこの API は呼ばれていない
- サービス層以降（LLM 呼び出し・本文/添付/トークン使用量の保存）の処理内容は変わらない
- DB スキーマの変更なし

## 移植方針

- 移植元 `MessageController.createMessageContent` の `@RequestPart(name = "textData")`・`attachmentFiles`・`historyAttachmentFiles` に合わせる。
- `textData` の各フィールド名は移植元 `CreateMessageContentRequest`（`@JsonProperty`）に合わせる。
- 内部（サービス層）での属性名は既存のまま維持し、入力時の名前だけを移植元に合わせる。これによりサービス層の変更を不要にし、影響範囲を入力の受け取り部分に限定する。
- 会話履歴の発話種別は、移植元の列挙値（大文字）を受け取り、LLM 呼び出しで使う小文字の発話種別に正規化する。列挙値以外は入力エラーとする（移植元も列挙型への変換に失敗した場合はエラーになる）。
- 添付ファイルのファイル名・Content-Type はアップロードされたファイルのものを使う（移植元 `toFileDataList` 相当）。
