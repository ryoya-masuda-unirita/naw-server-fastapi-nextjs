# 02_基本設計

## 構成

```
ルートの docker-compose.yml
  postgres  vector-db  redis  localstack         （今のまま）
  migrate  ── postgres が healthy → alembic upgrade head → 終了
  seed     ── migrate が成功 → seed.sql・seed-demo.sql を流して終了
  backend  ── seed が成功 + redis・localstack が healthy（開発用イメージ・ソースのバインドマウントのまま）
  frontend ── backend が healthy（Vite の開発サーバー。client/Dockerfile.dev）
```

- `migrate` は、backend と同じイメージ・同じバインドマウントで動かす（マイグレーションのコードは、バインドマウントした `server/` にある）
- backend の起動は、seed の完了まで待つ（demo と同じ順）。一部だけ起動するとき（`up -d postgres redis`）は、これまでどおり

## 環境変数（`.env`）

| 変数 | 既定値 | 内容 |
|---|---|---|
| `FRONTEND_PORT` | 5173 | 画面のホストのポート |
| `BACKEND_PORT` | 8001 | backend のホストのポート（今の 8001 のまま） |
| `SECRET_KEY` | `dev-secret-not-for-production` | JWT などの署名鍵（ローカル用） |
| `COOKIE_SECURE` | false | ローカルは HTTP のため false |
| `COOKIE_SAME_SITE` | lax | |

- CORS の許可オリジンは、`http://localhost:${FRONTEND_PORT}` から作る（別の変数にしない）
- 画面が呼ぶ backend の URL（`VITE_API_URL`）も、`http://localhost:${BACKEND_PORT}` から作る
- DB・Redis・LocalStack の接続情報（コンテナ間の固定値）は、compose の中に書く。`.env` に出すのは、人が変えたい値だけ

## 設計の選び

| 項目 | 選び | 理由 |
|---|---|---|
| backend のイメージ | 開発用のまま | 今の使い方（ホットリロード）を壊さない。demo の本番用イメージはやめる |
| 既存のポート公開 | 変えない | 手元の開発を壊さない（0.0.0.0 のまま） |
| frontend のポート | `127.0.0.1` だけ | demo と同じ。画面は手元のブラウザだけが使う |
| e2e-spec の環境 | 自分用の compose | demo に重ねる上書きをやめ、demo のベースと上書きを合わせて 1 つにする。動作（本番用イメージ・静的配信・llm-mock）は変えない |
