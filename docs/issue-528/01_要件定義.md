# 01_要件定義

## 背景

画面を見るのに、ルートの compose と demo の compose を使い分ける必要があり、ポート（8001）も重なる。client は demo にしか入っていない。

## 機能要件

- ルートの compose に `migrate`・`seed`・`frontend` を足す。`docker compose up` だけで、マイグレーション・ログイン用データ・デモデータ・画面まで立ち上がり、http://localhost:5173 でログインできる（テナント `test-tenant`、`admin` / `admin@1234`）
- backend は、画面（別のポート）から呼べる設定（`SECRET_KEY`・CORS・Cookie）にする
- 環境変数は、ルートの `.env` で変えられるようにする。変えたい値は、ホストのポート（画面・backend）、`SECRET_KEY`、Cookie の設定。`.env.example` に例を置く。`.env` がなくても、既定値で動く
- 既存の `naw-fastapi-*` のコンテナ名・既存のポート（5433・5434・6380・4566・8001）・ボリュームは変えない
- `docker-compose.demo.yml` を削除し、README・コメントの参照を直す
- `e2e-spec/` は、`e2e-spec/docker/` に自分用の compose を持つ（demo に重ねる上書きをやめ、動作は変えない）

## 非機能要件

- 既存の開発の使い方（`docker compose up -d backend` など、必要なサービスだけの起動）が、そのまま動く
- マイグレーション・seed は、何度 `up` しても壊れない（冪等）。seed は `ON CONFLICT` で冪等
- `.env` は git に入れない（`.gitignore` 済み）。`.env.example` だけを入れる

## スコープ外

- `onprem/`・`e2e-explorer/` の compose
- backend を本番用イメージ（`Dockerfile`）にすること。開発用（`Dockerfile.dev`、ソースのバインドマウント）のまま
