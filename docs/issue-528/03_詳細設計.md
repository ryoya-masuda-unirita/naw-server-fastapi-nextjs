# 03_詳細設計

## ルートの `docker-compose.yml`

- `x-backend`（アンカー）: backend と migrate が共有する `build`（`./server`・`Dockerfile.dev`）・`volumes`（`./server:/app`・`naw_fastapi_backend_venv:/app/.venv`）・`environment`
- `environment` に足す: `SECRET_KEY`・`CORS_ALLOWED_ORIGINS`・`COOKIE_SECURE`・`COOKIE_SAME_SITE`（いずれも `${VAR:-既定値}`）
- `migrate`: `command: ["uv", "run", "--no-sync", "alembic", "upgrade", "head"]`、`depends_on: postgres: service_healthy`、`restart: "no"`
- `seed`: `postgres:18` イメージで `psql` が `seed.sql` → `seed-demo.sql` を流す。`depends_on: migrate: service_completed_successfully`。`container_name` は付けない（一時）
- `backend`: `depends_on` に `seed: service_completed_successfully` を足す。`ports` は `"${BACKEND_PORT:-8001}:8000"`（今の公開のまま）
- `frontend`: `build: ./client`（`Dockerfile.dev`）、`container_name: naw-fastapi-frontend`、`ports: "127.0.0.1:${FRONTEND_PORT:-5173}:5173"`、`VITE_API_URL: http://localhost:${BACKEND_PORT:-8001}`、healthcheck（demo と同じ）、`depends_on: backend: service_healthy`

## 確認の手順（08 に記録）

1. `docker compose config -q`
2. 別のプロジェクト名・ポート（`.env` を使わず環境変数で渡す）で、`docker compose up -d --build` → すべて起動、画面 5173 相当でログインできる（Playwright）
3. `up` を 2 回（冪等）、一部だけ起動（`up -d postgres redis`）
4. e2e-spec の環境が、新しい compose で起動する（`env:up` と数件のテスト）
5. 今動いている開発のコンテナ（`naw-fastapi-*`）には触れない
