## 詳細

### 1. 一括削除 API の同じ不具合（🟡 注意）→ 対応しない

本 Issue の対象は更新 API で、一括削除は `02_基本設計.md` の横展開でスコープ外と明記した。画面は応答のハイフンなしの ID を送るため、実際の利用では起きない。対応するかどうかはユーザーの判断に委ねる（新規 Issue は起票していない）。

### 2. ライブラリのタグ指定（🟡 注意）→ 対応しない

#1 と同じく本 Issue のスコープ外（`02_基本設計.md` の横展開で「未調査・スコープ外」としていた。指摘で同じ原因であることが分かった）。ライブラリ API 側の変更になるため、対応要否はユーザーに委ねる。

### 3. 正規化の共通化（🔵 提案）→ 対応しない

#1・#2 をまとめて直すときに効く設計で、本 Issue の範囲（更新 API）だけなら service 内の 1 か所で足りる。#1・#2 に対応する際にあわせて検討する。

### 4. UUID 解釈の重複（🔵 提案）→ 対応しない

#5 の修正で、タグ側は `uuid.UUID` による解釈ではなく 2 形式の正規表現に変わり、`_parse_library_id`（UUID を返す）とは処理が異なる。共通化するとライブラリ API 側の変更にもなるため見送る。

### 5. `uuid.UUID()` の許容範囲が広い（🟡 注意）→ 対応済み

受け付ける表記を、保存形式（ハイフンなし 32 桁）と UUID 標準形式（8-4-4-4-12、移植元の `UUID.fromString` が想定する形）の 2 つに正規表現で限定し、ハイフン除去・小文字化で保存形式に揃えるようにした。それ以外の表記は存在しない ID と同じ 404。同じタグを指す `urn:uuid:` 形式・波括弧形式が 404 になるテスト（`test_update_with_non_standard_id_format_returns_404`）を追加した。

### 6. 例外の連鎖（🔵 提案）→ 対応済み

#5 の修正で `try/except` 自体が無くなったため解消した。
