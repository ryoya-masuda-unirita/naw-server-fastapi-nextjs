## 実装内容

### `LibraryTagService._get_tag_or_404`

```python
_TAG_ID_PATTERN = re.compile(
    r"[0-9a-f]{32}|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}",
    re.IGNORECASE,
)

tag = None
if _TAG_ID_PATTERN.fullmatch(tag_id):
    tag = await LibraryTagRepository.find_by_id_and_tenant_id(
        tag_id.replace("-", "").lower(), tenant_id, session
    )
if not tag:
    raise HTTPException(status_code=404, detail="Library tag not found")
```

- 受け付けるのは、保存形式（ハイフンなし 32 桁）と、移植元の `UUID.fromString` が想定する標準形式（8-4-4-4-12）の 2 つだけ。大文字小文字は区別しない。保存値は `uuid4().hex`（小文字）で作っているため、ハイフン除去・小文字化で一致する
- 当初は `uuid.UUID(tag_id).hex` で揃えたが、`uuid.UUID` は `urn:uuid:`・波括弧・`0x` 接頭辞・`_` 区切りなども受け付け、1 つのタグを指す ID の表記が増えるため、code-review の指摘を受けて正規表現で 2 形式に限定した
- それ以外の形式は、存在しない ID と同じ 404・`Library tag not found` を返す（変更前の応答と同じ。ライブラリ API の `_parse_library_id` と同じ扱い）
- 呼び出し元は `update_library_tag` だけ

### `LibraryTagService.update_library_tag`

- `exists_by_tenant_id_and_name(..., exclude_id=tag_id)` を `exclude_id=tag.id` に変える。パスの値（ハイフン付き）のままだと保存値と一致せず、自分自身を重複とみなしてしまうため

## 移植元の根拠

- `server/src/main/java/com/example/naw/api/LibraryTagController.java` の `updateLibraryTag`（`@PathVariable String id` → `UUID.fromString(id)`）
- `server/src/main/java/com/example/naw/service/LibraryTagService.java` の `updateLibraryTag`（`findByIdAndTenantId(UUID, tenantId)`、見つからなければ `EntityNotFoundException` → 404）
