# 04_テスト設計

## テスト方針

更新 API をテスト用の DB（インメモリ SQLite）で実際に呼び出して確かめる。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | ハイフン付き | ハイフン付きの UUID 標準形式で ID を指定して更新する | 200。名前・説明が更新され、応答の ID はハイフンなし 32 桁 |
| 2 | 大文字 | ハイフン付きの大文字で ID を指定して更新する | 200。同じタグが更新される |
| 3 | 同名のまま更新 | ハイフン付きで指定し、名前を今と同じ名前にして更新する | 200（自分自身を重複とみなさない） |
| 4 | 重複 | ハイフン付きで指定し、別のタグと同じ名前にする | 400（既存と同じ） |
| 5 | 不正な形式 | UUID として解釈できない ID を指定する | 404（既存と同じ） |
| 6 | 他テナント | 他テナントのタグをハイフン付きで指定する | 404 |
| 7 | 回帰 | 既存のライブラリタグのテスト・全テスト | すべて成功 |
