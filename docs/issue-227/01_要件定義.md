# 01_要件定義

## 背景

ライブラリタグの ID は、データベースにハイフンなしの 32 桁の 16 進文字列で保存している。更新 API（管理者用）はパスで受け取った ID をそのまま保存値と比べるため、ハイフン付きの UUID 標準形式で指定すると、存在するタグでも「見つからない」（404）になる。

移植元は ID を UUID として読み取るため、ハイフン付きの形式で更新できる。ライブラリ一覧のタグ絞り込みは #173 でハイフン付き・なしの両方を受け付けるようにしており、更新 API も揃える。

## 機能要件

1. ライブラリタグの更新 API は、タグ ID をハイフン付き（UUID 標準形式）・ハイフンなし（32 桁）のどちらで指定しても、同じタグを更新できる
2. ハイフン付きで指定した場合も、名前の重複チェックで自分自身は重複とみなさない（同じ名前のまま更新しても 400 にならない）
3. UUID として解釈できない ID は、今と同じく 404（`Library tag not found`）にする

## 非機能要件

- エラー応答の形式・ステータスコードは変更しない（既存の 404・400 と `detail` のまま）
- DB のマイグレーションは行わない（保存形式は変えない）
- 応答の `id` はこれまでどおりハイフンなしの 32 桁

## スコープ外

- ライブラリタグの一括削除 API でのハイフン付き ID（横展開で同じ原因を確認したが、本 Issue の対象は更新 API のため。詳細は `02_基本設計.md`）
- 不正な形式の ID を移植元のように 400 にすること（ステータスコードの扱いは別途検討中のため、今の 404 を維持）
- 応答の `id` の形式を移植元（ハイフン付き）に合わせること
