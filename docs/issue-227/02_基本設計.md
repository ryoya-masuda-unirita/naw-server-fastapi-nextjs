# 02_基本設計

## 変更対象

- ライブラリタグ更新 API（管理者用、PATCH）

## 画面 / API 変更概要

| 指定した ID | 変更前 | 変更後 |
|---|---|---|
| ハイフンなし 32 桁（保存形式） | 更新できる | 更新できる（変更なし） |
| ハイフン付き UUID 標準形式 | 404 | 更新できる |
| 大文字を含む ID | 404 | 更新できる（UUID として同じ値のため） |
| UUID として解釈できない文字列 | 404 | 404（変更なし） |
| 存在しない UUID | 404 | 404（変更なし） |

画面の変更は無い（画面は応答のハイフンなしの ID をそのまま送るため、今も動いている）。

## 影響範囲

- ライブラリタグの更新 API のみ。一覧・作成・削除、ライブラリ本体の API は変更しない

## 移植方針

### 移植元の挙動

移植元の更新 API は、パスの ID を文字列で受け取り、UUID に変換してからタグを探す。UUID の標準の文字列変換はハイフン付きの形式を受け付けるため、ハイフン付きで更新できる（ハイフンなしは変換に失敗し 400）。

### このリポジトリの方針

#173（ライブラリ一覧のタグ絞り込み）と同じく、受け取った ID を UUID として解釈し、比べる前に保存形式（ハイフンなし 32 桁の小文字）に揃える。これにより、ハイフン付き・なしのどちらでも同じタグに当たる。

不正な形式の扱いは、移植元の 400 ではなく今の 404 を維持する。ステータスコードは別途検討中で本 Issue では新たに決めないことと、このリポジトリのライブラリ API がパスの ID を「UUID として解釈できなければ存在しない ID と同じく 404」と扱っており、それと揃えるため。

| 案 | 内容 | 判定 |
|---|---|---|
| A | パスの ID は文字列のまま受け、サービスで UUID として解釈して保存形式に揃える。解釈できなければ 404 | 採用。不正な形式の応答（404）が変わらず、ライブラリ API の扱いと同じ |
| B | パスの ID を UUID 型で受ける（#173 の一覧と同じ受け方） | 不採用。不正な形式がフレームワークの入力検証エラーになり、ステータスコードが 404 から変わる |

名前の重複チェックで自分自身を除く条件は、パスの値ではなく、取得したタグの ID（保存形式）で比べる。パスの値のままだと、ハイフン付きで指定したときに自分自身と重複して 400 になるため。

### 横展開

| 対象 | 結果 | 対応 |
|---|---|---|
| ライブラリタグの一括削除 API | 本文の ID 一覧を保存値とそのまま比べるため、ハイフン付きの ID は一致せず、エラーにならないまま削除されない（存在しない ID は無視する仕様のため 204）。コードから判断し、実行しての確認はしていない。移植元は UUID に変換して削除する | 本 Issue のスコープ外（更新 API が対象）。対応要否はユーザーに委ねる |
| ライブラリの作成・更新でのタグ指定 | 本 Issue では未調査 | スコープ外 |
