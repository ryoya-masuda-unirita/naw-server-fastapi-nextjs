# 04_テスト設計

## テスト方針

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 認証の groups | 所属グループがあるユーザーで POST `/auth/login`・GET `/api/auth` | `groups` が `{groupId, groupAdmin}` の並び（グループ ID 順）。所属が無ければ空配列 |
| 2 | 認証の null 項目 | パスワード再設定が必要なユーザーでログイン | `loginStatus` は `REQUIRES_PASSWORD_RESET`、`token`・`groups` が出ない |
| 3 | `loginStatus` | login-key・password/reset・GET `/api/auth` | `loginStatus` が出ない（POST `/auth/login` だけが出す） |
| 4 | ログインキーが null・空白 | POST `/auth/login-key` | 400 ではなく 401（検索しない） |
| 5 | キーの発行 | `issueLoginKey=true` で作成 | `loginKey` が英数字 32 文字、DB には `login_key_hash`（SHA-256）だけ。`Cache-Control: no-store` |
| 6 | キーの発行しない | `issueLoginKey` 省略で作成 | `loginKey` が null、`hasLoginKey` が false |
| 7 | 発行したキーでログイン | 作成の応答の `loginKey` で POST `/auth/login-key` | 200 |
| 8 | 廃止した `loginKey` | 作成・更新に `loginKey` の値を付ける | 400 と移植元の文言。null なら通る |
| 9 | 再発行・無効化 | 更新で REISSUE・REVOKE | REISSUE は新しいキーを返しハッシュを置換、REVOKE は `hasLoginKey` が false |
| 10 | キーの乱数 | `generate_login_key` を 20 回 | すべて英数字 32 文字で重複しない |
| 11 | CSV の廃止列 | `createLoginKey` 列があるCSV | ジョブが FAILED、移植元と同じメッセージ。列が無いCSVは既存ユーザーのキーを変えない |
| 12 | ユーザー一覧のページ | `size=1` で 2 件 | `number`・`numberOfElements`・`first`・`last`・`empty`、`page` が無い |
| 13 | shares | 作成・アクセス解決・削除 | `{data: ...}`、削除は 200 `{data: {id}}` |
| 14 | メッセージ一覧の assistants | エンドポイントがある・無い | `includeHistory`・`model`（無ければ null）。`endpoints[]` に `model` が無い |
| 15 | アシスタントの `label` | 管理者向け一覧と一般向け一覧 | 管理者向けだけ `label` に名前、一般向けは null。カテゴリの `updatedAt` は null |
| 16 | フィードバック | feedbackUser・feedbackRoom | `responded`・`isResponded`、`indexId`（最新ファイルのインデックス ID、無ければ null） |
| 17 | ファイルの `status` | 一覧・アップロード・更新 | `ENABLE`・`DISABLE`（文字列）、並べ替えは序数のまま |
| 18 | 回帰 | 全件 | 既存のテストがすべて通る |
