## 判断

- **`model` の順序**: 移植元は `assistant.getEndpoints().get(0).getModel()` で並びを決めていない。`endpoint_id` が最小の行を採る（既存の `find_chat_endpoint...` と同じ基準）
- **`isResponded` を残す**: 移植元 server は `responded`。React の型は移植元 client の複製で `isResponded` を読むため、両方を同じ値で返す（画面を移植するとき、`responded` に揃えて `isResponded` を削る）
- **既存の平文キーは捨てる**: 移植元 changeset-009（Q-03）と同じ。ハッシュに変換すると、平文のキーが一度でも漏れていた場合に漏れたキーが使い続けられる
- **`readOnly`（`isReadOnly` の重複項目）**: 移植元は `isReadOnly` と `readOnly` の両方を出すが、React の型は `isReadOnly` だけを読む。足さない
- **`loginStatus`**: React の `auth-store` は `REQUIRES_PASSWORD_RESET` かどうかだけを見る。login-key・reset で省略しても動く
- **ライブラリ**: スタブ作成・タイトル更新は #307 に任せる（`libraries.title` の NULL 化と `library_contents` の分離が前提で、同じテーブルを変えるため）
