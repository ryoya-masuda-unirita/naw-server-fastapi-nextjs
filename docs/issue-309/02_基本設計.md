# 02_基本設計

## 変更対象

認証・ユーザー・グループ・shares・メッセージ・アシスタント・フィードバック・ファイルの API の応答（と、ユーザー作成・更新・CSV 取り込みのリクエスト）。DB は `users` のログインキー列だけ。

## 画面 / API 変更概要

| API | 変更前 | 変更後（移植元と同じ） |
|---|---|---|
| POST `/auth/login` | `groups: []`、null も出力 | `groups: [{groupId, groupAdmin}]`、null は出さない |
| POST `/auth/login-key`・`/auth/password/reset`、GET `/api/auth` | `loginStatus: "SUCCESS"`、`groups: []` | `loginStatus` なし、`groups` は所属グループ |
| POST `/auth/login-key` の null・空白のキー | 400 | 401 |
| POST `/api/admin/users` | キーは `loginKey` を受け取って保存 | `issueLoginKey` でサーバーが発行（応答の `loginKey` に平文）、`loginKey` を付けると 400 |
| PATCH `/api/admin/users/{loginId}` | 同上 | `loginKeyAction`（KEEP・REISSUE・REVOKE）、`loginKey` を付けると 400 |
| POST `/api/admin/users/import` | `createLoginKey` 列でキーを作る | `createLoginKey` 列があると失敗（取り込みでキーを作らない・変えない） |
| GET `/api/admin/users` | `page` | `number`（＋ `numberOfElements`・`first`・`last`・`empty`） |
| POST `/api/shares`・GET `/api/shares/{id}/access` | 平らな応答 | `{data: ...}` |
| DELETE `/api/shares/{id}` | 204 | 200 `{data: {id}}` |
| GET `/api/messages` | `assistants[]` に `id`・`type`・`endpoints` | ＋ `includeHistory`・`model` |
| GET `/api/admin/assistants` | `endpoints[]` に `label` なし | `label`（テナントエンドポイント名） |
| GET `/api/assistants`・`/api/admin/assistants` | カテゴリに `updatedAt` なし | `updatedAt`（null） |
| GET `/api/admin/feedbackUser` | `isResponded` | ＋ `responded` |
| GET `/api/admin/feedbackRoom` | `indexId` なし | `indexId` |
| ファイルの応答（一覧・アップロード・更新） | `status` が整数（0・1・2） | `status` が `ENABLE`・`DISABLE`・`DELETED` |

画面は変更しない。

## 影響範囲

- React の型との整合: `hasLoginKey`・`groups[].groupId/groupAdmin`・`status`（文字列）・`number` は React の型に合う。`isResponded` は React の型が読む名前なので残した（移植元 server は `responded`。移植元 client も `isResponded` を読むが、実際の server の応答には無く undefined になる、移植元 client 側のバグ）
- `shares` の応答の包みは、移植元の画面と同じく `{data: ...}`。React の `share-api.type.ts` が受ける形に合う
- DB: `users.login_key`（平文）を `login_key_hash` に置き換える。ログインキーで入るリンクを配っているテナントは、移行後にキーを再発行する必要がある（移植元と同じ）

## 移植方針

- 移植元 `AuthController`・`AuthResponse`・`UserController`・`UserService`・`LoginKeyGenerator`・`LoginKeyHasher`・`CsvUserImportValidator`・`ShareController`・`GetMessagesResponse`・`AssistantGetResponse`・`FeedbackController`・各 Response に合わせる（詳細は `03_詳細設計.md`）
- 移植元 server に無い API・項目は作らない／足さない
- 移植元と違える点は `03_詳細設計.md` の「判断」に理由を書く
