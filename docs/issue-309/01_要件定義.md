# 01_要件定義

## 背景

React に移植した API の型（移植元 client の複製）と backend の応答に食い違いがある（`docs/issue-279/api-backend-diff.md`）。原因の一部は backend の移植遅れで、移植元 Spring Boot（`server/`）の方が新しい。移植元 `server/` の Response/Request を正として backend を揃え、画面が読む項目名と backend の応答を合わせる。React と移植元 client の型が移植元 server と違うところは、移植元 server に合わせ、client 側（React の画面）で吸収する。

## 機能要件

この PR で揃える項目（各項目は移植元の Controller・Response/Request で確かめた）。

1. 認証（POST `/auth/login`・`/auth/login-key`・`/auth/password/reset`、GET `/api/auth`）
   - `groups` は所属グループの `{groupId, groupAdmin}`（移植元 `AuthGroupResponse`）
   - null の項目は応答に出さない（移植元 `@JsonInclude(NON_NULL)`）。パスワード再設定が必要なときは `token`・`groups` も出ない
   - `loginStatus` は `/auth/login` だけが返す（login-key・password/reset・GET `/api/auth` は返さない）
   - `/auth/login-key` の `loginKey` が null・空白なら 400 ではなく 401
2. ログインキー
   - ユーザー作成は `issueLoginKey`（省略・null は false）、更新は `loginKeyAction`（KEEP・REISSUE・REVOKE。省略・null は KEEP）でサーバーが発行・再発行・無効化する
   - 発行したキーは作成・更新の応答の `loginKey` に一度だけ平文で入れ、DB には SHA-256 のハッシュだけを保存する（移植元 NAW-1342・NAW-1343）
   - 廃止した `loginKey` をリクエストに付けると 400（文言は移植元と同じ）。null は通る
   - CSV 取り込みの `createLoginKey` 列は廃止。列があるとジョブは失敗し、移植元と同じメッセージを記録する。取り込みでキーは作らず、既存ユーザーのキーも変えない
3. ユーザー一覧のページングは `number`（`page` ではない）。Spring の `Page` の `numberOfElements`・`first`・`last`・`empty` も返す
4. shares: 作成・アクセス解決の応答を `{data: ...}` で包み、削除は 204 ではなく 200 で `{data: {id}}`
5. メッセージ一覧（GET `/api/messages`）の `assistants[]` に `includeHistory` と `model`（最初に紐づくエンドポイントの model。SECURE でブラウザが Waha! のサービス ID として送る）を足す。`endpoints[]` には `model` を足さない（移植元に無い）
6. アシスタント: 管理者向け一覧の `endpoints[].label` にテナントエンドポイント名、`category`・`categories[]` に `updatedAt`（移植元は常に null）
7. フィードバック: ユーザー別集計に `responded`、ルーム評価に `indexId`（紐づく最新ファイルのインデックス ID）
8. ファイルの `status` は列挙名（`ENABLE`・`DISABLE`・`DELETED`）の文字列

## 非機能要件

- マイグレーションは 1 本だけ（`users.login_key` → `login_key_hash`。revision `issue309`、down_revision `023`）
- 既存のログインキー（平文）は移行時に捨てる（移植元 Q-03 と同じ。再発行が必要）
- 変更・追加した Python の関数・メソッド・クラスは NumPy 形式の日本語 docstring を付ける

## スコープ外

移植元 server に無い API（`docs/issue-279/api-backend-diff.md` の「2.」）は作らない。次は今回扱わず、PR 本文に残した。

- ライブラリのスタブ作成・タイトル更新・`GET /api/libraries/{id}` の形（#307 の `library_contents` 分離が前提）
- rooms の `rating`・`shareUrl`・`teamIds`・`pinned`、フィードバック送信の 200（移植元）と 204（backend）
- テナントの `deleted`、学習データの `uploadFileWahaServiceId` など、ファイルの `splitLength`（`files.split_length` の追加が要る）
- Spring の `Page` の全項目（ユーザー一覧以外）
