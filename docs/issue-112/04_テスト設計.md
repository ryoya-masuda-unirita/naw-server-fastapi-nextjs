# 04_テスト設計

## テスト方針

- Repository層の新規メソッド（IN句一括取得）はintegrationテストでDBに実際に接続して検証する
- Service層・Router層はグループ一覧取得APIのレスポンスに実データが含まれることをunitテストで検証する

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | Repository | 複数グループに紐づくアシスタントが存在する状態でグループID一覧をまとめて取得する | グループIDをキーとした(アシスタントID, アシスタント名)一覧が返る |
| 2 | Repository | アシスタントが紐づいていないグループが含まれる | 該当グループのキーには空リストが返る |
| 3 | Repository | 空のグループID一覧を渡す | 空辞書が返る |
| 4 | Repository | 複数グループに紐づくプロンプトテンプレートが存在する状態でグループID一覧をまとめて取得する | グループIDをキーとした(テンプレートID, テンプレート名)一覧が返る |
| 5 | Service/Router | グループにアシスタント・プロンプトテンプレートが紐づいている状態で `GET /api/groups` を呼ぶ | レスポンスの `assistants`/`assistantIds`/`promptTemplates`/`promptTemplateIds` に実データが含まれる |
| 6 | Service/Router | グループに何も紐づいていない状態で `GET /api/groups` を呼ぶ | レスポンスの該当フィールドが空リストになる |
| 7 | Service/Router | 複数グループを一覧取得したとき、各グループの紐付けが混在しないこと | グループAの結果にグループBのアシスタント/テンプレートが混入しない |
