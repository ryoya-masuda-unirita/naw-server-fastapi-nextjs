# 要件定義：ログインAPIのCORS未設定とセッションAPIのパス重複を修正

## 背景

issue-17（ログイン後の共通レイアウト実装）の動作確認中に、フロントエンド（`http://localhost:5173`）からバックエンド（`http://localhost:8000`）への実ログインがブラウザ上で一切成立しないことが判明した。原因は独立した既存バグ2件であり、いずれも本 Issue で修正する。

---

## 機能要件

### 1. CORS設定の追加

- `backend/app/main.py`（または `app/core` 配下の設定モジュール）に CORS 設定を追加し、フロントエンド開発サーバーからの API リクエストを許可する
- 許可オリジンは環境変数（`.env`）から読み込めるようにし、ハードコードしない
  - 開発環境: `http://localhost:5173`（React 開発サーバー）・`http://localhost:4201`（`frontend-angular` 開発サーバー。しばらくバックエンド優先で開発するため、動作確認は React 移植版ではなくこちらの Angular 版を使う）
- 許可メソッド・許可ヘッダーはログイン・セッション確認・認証付きAPI呼び出しに必要な範囲を許可する（`Authorization` ヘッダーを含む）
- Cookie ベースの認証情報（`credentials`）が必要な場合は許可設定に含める
- サブドメイン単位でのワイルドカード許可（例: `https://*.example.com`）にも対応できるよう、正規表現ベースの許可オリジン設定を追加する。ただし対象ドメインは本 Issue 時点で未確定のため、開発環境では未設定（空）のままとする

### 2. セッションAPIのパス重複解消

- `frontend/src/lib/constants/api-paths.ts` の `API_PATHS.AUTH.SESSION` を修正し、`api-client.ts` の `API_BASE_URL`（`${VITE_API_URL}/api`）と結合した際に、バックエンドの実エンドポイント（`GET /api/auth`）と一致するパスにする
- MSW モックハンドラー側は issue-15（#15）で既に修正済みのため、本 Issue では実体のパス定数のみを修正する

---

## 非機能要件

- 修正後、ブラウザ経由の実ログイン（フロントエンド開発サーバー → バックエンド開発サーバー）が成立すること
- ログイン後のページリロードでセッションが復元され、未認証状態に戻らないこと
- 既存の自動テスト（`pytest`／フロントエンドのテスト）に影響を与えないこと

---

## スコープ外

- CORS の本番/staging 環境向け許可オリジン・サブドメインワイルドカードの実際の値の設定（対象ドメイン未確定のため、確定後に別 Issue で対応）
- issue-17 の動作確認で判明した他の不具合（本 Issue の対象は CORS 未設定とセッション API パス重複の2件のみ）
