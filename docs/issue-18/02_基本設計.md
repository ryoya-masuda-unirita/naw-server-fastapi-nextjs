# 基本設計：ログインAPIのCORS未設定とセッションAPIのパス重複を修正

## 変更対象レイヤー

バックエンド（FastAPI）・フロントエンド（React）の両方。DB スキーマ変更なし（マイグレーション不要）。

---

## 変更概要

| 対象 | 変更内容 |
|---|---|
| バックエンド | `CORSMiddleware` を追加し、開発環境のフロントエンドオリジンからのリクエストを許可する |
| バックエンド | 許可オリジンを `.env` の環境変数から読み込む設定を追加する |
| フロントエンド | `API_PATHS.AUTH.SESSION` のパス定数を、`api-client.ts` の `API_BASE_URL` と結合した際にバックエンドの実エンドポイントと一致する値に修正する |

## 設計上の決定事項

### CORS許可オリジンの持ち方

Spring Boot 版（`~/Documents/naw-server`）は `CorsProperties`（`cors.allowed-origins`）で環境ごとに許可オリジンをリスト管理している。この方針を踏襲し、FastAPI 側も `.env` の `CORS_ALLOWED_ORIGINS`（カンマ区切り文字列 → `list[str]` にパース）を `Settings` に追加し、ハードコードしない。

開発環境の `.env` には `http://localhost:5173,http://localhost:4200` を設定する（React 開発サーバー・Angular 参照実装確認用）。

### サブドメインワイルドカード対応

Spring Boot 版の `cors.allowed-origins` はワイルドカードパターン（例: `https://*.example.com`）をサポートしているが、`starlette.CORSMiddleware` の `allow_origins` は完全一致のみで、ワイルドカードには `allow_origin_regex`（単一の正規表現文字列）を使う必要がある。

このため `CORS_ALLOWED_ORIGIN_REGEX` という別の環境変数を用意し、`Settings.cors_allowed_origin_regex: str | None` として読み込む。値が設定されていれば `CORSMiddleware(allow_origin_regex=...)` に渡す。

- 開発環境: 対象ドメインが未確定のため `CORS_ALLOWED_ORIGIN_REGEX` は空（未設定）のままとする
- 本番/staging 環境: CloudFront ドメイン等が確定した時点で、別 Issue で値を設定する（例: `https://.*\.example\.com$`）

### CORSMiddleware の許可設定

- `allow_origins`: `Settings.cors_allowed_origins`
- `allow_origin_regex`: `Settings.cors_allowed_origin_regex`（`None` の場合は指定しない）
- `allow_methods`: ログイン・ログアウト・セッション確認・各APIで使うメソッド一式（`GET`, `POST`, `PATCH`, `DELETE`）を許可
- `allow_headers`: `Authorization` を含む必要なヘッダーを許可
- `allow_credentials`: `True`（`frontend/src/lib/api-client.ts` が全リクエストで `credentials: 'include'` を指定しており、Cookie を利用する前提のため）
  - `allow_credentials: True` の場合 `allow_origins` に `"*"` は指定できない（ブラウザ仕様）。許可オリジンは具体的な値のリスト、または `allow_origin_regex` で指定する

### セッションAPIのパス修正

現状:

```
API_PATHS.AUTH.SESSION = '/api/auth'
API_BASE_URL = `${VITE_API_URL}/api`
→ 実際のリクエスト先: /api/api/auth（404）
```

修正後、バックエンドの実エンドポイント `GET /api/auth`（`backend/app/routers/auth.py` の `api_router`）と一致するよう、`API_PATHS.AUTH.SESSION` を `/auth`（他の `AUTH.LOGIN` 等と同じ相対パス形式）に修正する。

```
API_PATHS.AUTH.SESSION = '/auth'
→ 実際のリクエスト先: /api/auth（一致）
```

## 影響範囲

- 既存ルーター（`health.py`・`users.py`）: 変更なし
- 既存モデル: 変更なし
- DB マイグレーション: 不要
- 既存の自動テスト: `api-paths.ts` の値変更により、この定数を参照するフロントエンドのテスト（存在する場合）を確認・必要なら修正する
- 本番/staging 環境向けの許可オリジン設定は本 Issue のスコープ外（`01_要件定義.md` 参照）
