# ログインAPIのCORS未設定とセッションAPIのパス重複を修正

## 概要

issue-17（ログイン後の共通レイアウト実装）の動作確認中に、フロントエンドからバックエンドへの実ログインがブラウザ上で一切成立しないことが判明した既存バグ2件を修正する。

## 説明

### 1. CORS未設定

`backend/app/main.py` にCORSミドルウェア（`CORSMiddleware`）が設定されておらず、`http://localhost:5173`（フロントエンド開発サーバー）からのAPIリクエストがブラウザのCORSポリシーによって全てブロックされる。ログインAPI (`POST /api/auth/login`) を含む全てのAPI呼び出しが対象。

### 2. セッションAPIのパス重複

`frontend/src/lib/constants/api-paths.ts` の `API_PATHS.AUTH.SESSION` が `/api/auth` と定義されているが、`frontend/src/lib/api-client.ts` の `API_BASE_URL` が `${VITE_API_URL}/api` であるため、実際のリクエスト先が `http://localhost:8000/api/api/auth` と `/api` が重複してしまい、常に404になる。

ログイン成功後・ページ再読み込み時に呼ばれる `useAuthStore.ensureInitialized()` がこのセッションAPIに依存しているため、ログイン後にリロードするとセッションが復元できず未認証状態に戻ってしまう。

なお、issue-15（#15）の対応時にMSWモックハンドラー側の二重 `/api` は修正されていたが（コミット 49e0a34）、実体のパス定数 `API_PATHS.AUTH.SESSION` 側は修正されていなかった。
