# 05_テスト詳細設計

## 対象ファイルとテスト

| No | ファイル | テスト（英語名） | 内容 |
|---|---|---|---|
| 1〜5 | `server/tests/integration/test_assistants.py`（または `test_messages.py`） | `test_is_available_to_*` | 実 DB で、チームとアシスタントの割り当てを作り、`AssistantService.is_available_to` の結果を確かめる（No 1〜5 の各条件） |
| 6 | `server/tests/integration/test_assistants.py` | `test_is_available_to_matches_assistant_list` | 同じ状況で `get_assistants` の結果の ID の集合と、各アシスタントの `is_available_to` が一致する |
| 7・8・9 | `server/tests/integration/test_messages.py` | `test_create_message_with_unassigned_assistant_returns_403`・`..._with_other_group_assistant_returns_403`・`..._with_assigned_assistant_returns_201`・`..._with_unknown_assistant_returns_400` | API を呼び、応答コードと、403 のときメッセージが作られていないこと（件数が変わらない）を確かめる |
| 10・11・12 | `server/tests/integration/test_messages.py` | `test_stream_with_unassigned_assistant_returns_403`・`test_stream_with_multiple_groups_one_assigned_succeeds` | 回答生成を呼び、403 のとき LLM のクライアントが呼ばれないこと（パッチの呼び出し回数 0）を確かめる。SECURE のアシスタントでも同じ |
| 10 | `server/tests/unit/test_message_service.py` | `test_raises_403_when_assistant_not_available` | `is_available_to` を `False` にして、`stream_message_content` が 403 を送出し、アシスタントのエンドポイントの取得に進まないこと |
| 13 | 既存の統合テスト・単体テスト | — | `message_assistant` の準備に、所有者のチームへの割り当てを足す。単体テストは `is_available_to` を `True` にする |

## 方針

- 修正前のコードで、No 7・10 が失敗する（403 でなく成功・400 以外）ことを先に確かめる
- 「割り当てがある」と「割り当てがない」の両方を同じ構成で確かめ、判定の条件を逆にしたり、常に拒否したりする誤りでも、どれかが失敗するようにする
- テストのメソッド名は英語、意図は日本語の docstring で書く
- 実行は `server/` で `uv run pytest`。ruff（format・check）と mypy も通す
