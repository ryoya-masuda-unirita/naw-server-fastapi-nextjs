# 02_基本設計

## 変更対象

- メッセージ作成と回答の生成（ストリーム）の、アシスタントの確認処理
- アシスタントが「ユーザーの所属チームで使えるか」を返す判定（一覧と同じ条件を共通にする）
- 既存の、メッセージを作る・回答を生成するテスト

## 画面 / API 変更概要

- 画面の変更はない
- メッセージ作成 API と回答生成 API に、新しい失敗の応答（403）が加わる。他の入出力は変えない
- 判定の順序: ①アシスタントがテナントにあるか（なければ従来どおりのエラー）→ ②所属チームで使えるか（使えなければ 403）

## 影響範囲

- メッセージ作成と回答生成を呼ぶすべての利用者。チームに割り当てられていないアシスタントでの利用が、403 になる（意図した変更）
- 一覧 API の結果は変わらない。判定を共通にしても、一覧の条件は同じにする
- 既存のテストのうち、メッセージを作る・回答を生成するものは、アシスタントがチームに割り当たっていないと 403 になる。準備を足す

## 移植方針

- 移植元: 一覧と同じ関数で判定し、メッセージ作成・回答生成の 3 か所の確認を「存在確認 → 利用可否の確認」に置き換えた。拒否は 403（ルームの書き込み権限が無いときと同じ扱い）
- 移植先: 移植元の 3 か所のうち、メッセージ作成と回答生成の 2 か所に当たる。同じ順序（存在 → 利用可否）で判定する
- 判定は、一覧 API が使う「所属チーム → 割り当てられたアシスタント」の条件と共通にする。これで、一覧と食い違わない
- 403 の文言は、移植先の他の 403 に合わせて `Access Denied` とする（移植元は日本語の文言だが、移植先のエラーは英語で統一されている）
- 移植元のテストの観点（部分的な修正や誤った条件でも通らないテスト）を取り込む。具体的には、①チームに割り当てがあるときは通る ②割り当てがないと 403 ③他のチームに割り当てられているだけでも 403 ④複数チームのどれかに割り当てられていれば通る、を確かめる
