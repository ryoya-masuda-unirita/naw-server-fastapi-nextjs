# 08_動作確認

## 確認環境

- macOS、`feature/issue-446-NAW-1443`、`server/` で `uv run pytest`（統合テストはテスト用の PostgreSQL を使う）
- ブラウザでの確認は行っていない（画面の変更がなく、自動テストで API の応答を確かめた）

## 確認手順

1. 拒否のテストを先に足し、修正前のコードで失敗することを確かめる
2. 実装し、`tests/integration/test_messages.py` を実行する
3. 全体のテストと、ruff・mypy を実行する
4. `message_service.py` だけを `develop` の状態に戻し、拒否のテストが失敗することを再確認する

## 確認結果

### 修正前のコードでの失敗（手順 1）

- 拒否のテスト 4 件が失敗した（実装前）
  - `test_create_message_with_unassigned_assistant_returns_403`
  - `test_create_message_with_other_group_assistant_returns_403`
  - `test_stream_with_unassigned_assistant_returns_403_without_llm_call`
  - `test_stream_with_unassigned_secure_assistant_returns_403`
- そのほかの 50 件（`message_assistant` にチームへの割り当てを足したもの）は、修正前のコードでも通った

### 修正後（手順 2・3）

- `tests/integration/test_messages.py`: 54 passed
- 全体: 1483 passed
- `ruff format`・`ruff check`・`mypy`（236 ファイル）: 問題なし
- レビュー指摘への対応（判定をリポジトリの EXISTS に移した）のあとも、全体で 1483 passed

### 実装だけを戻した確認（手順 4）

- `message_service.py` だけを `develop` の版に戻し、`tests/integration/test_messages.py` を実行した。拒否のテスト 4 件が失敗し、50 件が通った（4 failed, 50 passed）
- 確認後、`message_service.py` を修正後の版に戻した。`test_messages.py` は 54 passed に戻った

### 一覧との一致

- `test_exists_available_to_user_matches_assistant_list`: 使えるアシスタントの集合と、一覧 API が返す集合が一致した（割り当て済み・未割り当て・他のチームにだけ割り当て済みの 3 つで確認）

## 未確認事項

- 画面（React）からの確認は行っていない。メッセージ作成・回答生成の画面は、チームに割り当てたアシスタントしか選べないため、通常の操作では 403 は出ない
- 実際の Azure OpenAI などの LLM との通しは行っていない（LLM はモックで、呼ばれないことを確かめた）
- 移植元の統合テスト（MessageIT）と同じ観点を取り込んだが、移植元のテストは実行していない
