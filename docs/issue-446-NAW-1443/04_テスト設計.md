# 04_テスト設計

## テスト方針

移植元のテストの観点（部分的な修正や誤った条件でも通らないこと）を取り込む。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 利用可否の判定 | 所属チームに割り当てられたアシスタント | 使える |
| 2 | 利用可否の判定 | どのチームにも割り当てられていないアシスタント | 使えない |
| 3 | 利用可否の判定 | 他のチームにだけ割り当てられている（自分は所属していない） | 使えない |
| 4 | 利用可否の判定 | 複数のチームに所属し、そのうち 1 つにだけ割り当てられている | 使える |
| 5 | 利用可否の判定 | 所属チームが 0 件 | 使えない |
| 6 | 一覧との一致 | 上の条件の各場合に、一覧 API が返すアシスタントの集合と、使えると判定される集合を比べる | 同じ |
| 7 | メッセージ作成 | 使えないアシスタントを指定する | 403。メッセージが作られない |
| 8 | メッセージ作成 | 使えるアシスタントを指定する | 従来どおり成功 |
| 9 | メッセージ作成 | テナントに存在しないアシスタントを指定する | 従来どおりのエラー（400） |
| 10 | 回答の生成 | メッセージのアシスタントが使えない | 403。回答が生成されず、LLM が呼ばれない |
| 11 | 回答の生成 | メッセージのアシスタントが使える | 従来どおり回答が返る |
| 12 | 回答の生成 | 種類が SECURE で、使えない | 403（種類の確認より先に拒否される） |
| 13 | 回帰 | 既存のテストをすべて実行する | メッセージ・アシスタント関係の既存テストが、割り当ての準備を足したうえで通る |
