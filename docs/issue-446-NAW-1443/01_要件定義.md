# 01_要件定義

## 背景

アシスタントは、チームに割り当てることで、そのチームの所属ユーザーが使える。一覧 API はこの割り当てで絞り込むが、メッセージの作成と回答の生成は絞り込まない。そのため、チームで使えないアシスタントの ID を送ると、回答が生成される。移植元は NAW-1443 でこれを塞いだ。移植先にも同じ穴がある。

## 機能要件

| No | 要件 |
|---|---|
| F1 | メッセージ作成で、指定されたアシスタントがログインユーザーの所属チームで使えないとき、403 を返し、メッセージを作らない |
| F2 | 回答の生成（ストリーム）で、メッセージのアシスタントがログインユーザーの所属チームで使えないとき、403 を返し、回答を生成しない |
| F3 | 「使える」の判定は、アシスタント一覧 API と同じ（所属チームに割り当てられたアシスタント）。一覧に出ないアシスタントは、必ず拒否される |
| F4 | 使えるアシスタントでは、従来どおり動く。テナントに存在しないアシスタントのエラーは、従来どおり |
| F5 | 403 の応答は、このプロジェクトの他の 403 と同じ形（`Access Denied`） |

## 非機能要件

- 既存のテストの結果が変わらない。成功する前提の既存テストは、アシスタントをチームに割り当てる準備を足す
- 判定のために増える DB の問い合わせは、一覧 API と同じ範囲に収める
- 追加・変更する関数に、日本語の NumPy 形式の docstring を書く
- テストのメソッド名は英語、意図は日本語の docstring

## スコープ外

- 存在しないアシスタントの応答コードを、移植元の 404 に合わせること（既存の差分）
- client の変更（NAW-1443 の client 側は再現しないため対象外）
- アシスタント一覧 API の仕様変更
- 管理者への例外扱い（移植元にもなく、管理者も同じ判定にする）
