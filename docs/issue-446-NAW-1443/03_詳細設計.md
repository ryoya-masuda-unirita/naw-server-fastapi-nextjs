## 変更の中身

### アシスタント側

```python
@staticmethod
async def _find_available_assistant_ids(
    tenant_id: str, user_id: UUID, session: AsyncSession
) -> list[str]:
    group_ids = await GroupUserRepository.find_belonging_group_ids(tenant_id, user_id, session)
    return await GroupAssistantRepository.find_assistant_ids_by_group_ids(group_ids, tenant_id, session)

@staticmethod
async def is_available_to(
    tenant_id: str, user_id: UUID, assistant_id: str, session: AsyncSession
) -> bool:
    return assistant_id in await AssistantService._find_available_assistant_ids(tenant_id, user_id, session)
```

- `get_assistants` は、`group_ids` と `assistant_ids` を自分で取る代わりに `_find_available_assistant_ids` を使う。一覧に出る条件と判定の条件が、同じ処理になる
- 使えるかどうかは、アシスタント ID の一覧に含まれるかで決める（所属チームが 0 件なら、空の一覧になり `False`）

### メッセージ側

- `create_message`: `find_by_id_and_tenant_id` が `None` なら従来どおり 400。続けて `is_available_to(tenant_id, current_user.id, req.assistantId, session)` が `False` なら 403（`detail="Access Denied"`）。ルームの解決・メッセージの作成より前に判定する
- `stream_message_content`: アシスタントが `None` なら従来どおり 400。続けて同じ判定を行い、`False` なら 403。`SECURE` かどうかの確認より前に判定する（チーム外のアシスタントは、種類によらず拒否する）
- 判定のために、ユーザーの所属チームの取得とチームのアシスタントの取得が 1 回ずつ増える（一覧 API と同じ問い合わせ）
