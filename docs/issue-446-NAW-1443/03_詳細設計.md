# 03_詳細設計

## 変更対象ファイル

| ファイル | 変更 |
|---|---|
| `server/app/repositories/group_assistant_repository.py` | `exists_available_to_user(assistant_id, user_id, tenant_id, session) -> bool` を追加する。ユーザーの所属グループのいずれかにアシスタントが割り当てられているかを、1 クエリ（EXISTS）で判定する |
| `server/app/services/message_service.py` | 内部の `_require_assistant_available` を追加し、`create_message`（アシスタントの存在確認の直後）と `stream_message_content`（同じく存在確認の直後、SECURE の確認より前）から呼ぶ。使えなければ `HTTPException(403, "Access Denied")` |
| `server/tests/unit/test_message_service.py` | 既存の回答生成のテストに、`exists_available_to_user` を `True` にするパッチ（自動適用）を足す。拒否のテストを追加する |
| `server/tests/integration/test_assistants.py` | `exists_available_to_user` の判定と、アシスタント一覧との一致のテストを追加する |
| `server/tests/integration/test_messages.py` | `message_assistant` の準備に、所有者・別ユーザーの所属チームへの割り当てを足す。割り当てなし・他のチームのみ・複数チームのうち 1 つのとき、メッセージ作成と回答生成が期待どおりになるテストを追加する |

## 変更の中身

### リポジトリ

```python
select(exists().where(
    GroupAssistant.assistant_id == assistant_id,
    GroupAssistant.tenant_id == tenant_id,
    GroupUser.group_id == GroupAssistant.group_id,
    GroupUser.tenant_id == tenant_id,
    GroupUser.user_id == user_id,
))
```

- 一覧 API（所属グループ → 割り当てられたアシスタント）と同じ条件を、1 つのアシスタントについて EXISTS で判定する。一覧との一致は、統合テストで確かめる
- 一覧の処理（`get_assistants`）は変えない

### サービス

- `create_message`: アシスタントがテナントに無ければ従来どおり 400。続けて `_require_assistant_available` が `False` なら 403。ルームの解決・メッセージの作成より前に判定する
- `stream_message_content`: アシスタントが無ければ従来どおり 400。続けて同じ判定を行う。`SECURE` かどうかの確認より前に判定する（チーム外のアシスタントは種類によらず拒否する）
- 判定は、`MessageService` がリポジトリを直接呼ぶ。プロジェクトの規約（`xxx_service.py` が別の `yyy_service.py` を呼ばない）に合わせるため、`AssistantService` には判定を置かない
- 判定で増える DB の問い合わせは 1 回（EXISTS）

## 設計の変更（レビューでの訂正）

- 初めは `AssistantService.is_available_to` を作り、`MessageService` から呼ぶ設計だった。サービス間の呼び出しを禁じる規約に反するため、また全アシスタント ID を取ってから含まれるかを調べる非効率を避けるため、リポジトリの EXISTS に変えた。`AssistantService` は変更しない

## 不要コードの確認

- `AssistantService` の変更は取り消した。孤立したコードはない
