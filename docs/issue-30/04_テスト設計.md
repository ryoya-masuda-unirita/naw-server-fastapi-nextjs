# 04_テスト設計

## テスト方針

- `GET /api/assistants`の既存テスト（issue-26）に加え、エンドポイント紐付けがある場合・複数エンドポイントがある場合・紐付けがない場合の挙動を重点的に確認する
- `label`がレスポンスに含まれないこと、`apiKey`が一切含まれないことを確認する

## テストケース一覧

### `GET /api/assistants`

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | アシスタントに1つのエンドポイントが紐づく | `endpoints`に`id`・`model`・`type`・`url`を含む1件が返る |
| 2 | アシスタントに2つのエンドポイントが紐づく | `endpoints`に2件返る |
| 3 | アシスタントにエンドポイントが紐づいていない | `endpoints`が空配列で返る（既存issue-26の挙動を維持） |
| 4 | レスポンスに`label`が含まれない | 全エンドポイントで確認 |
| 5 | レスポンスに`apiKey`が含まれない | 全エンドポイントで確認 |
| 6 | 複数アシスタントが異なるエンドポイントに紐づく | 各アシスタントに正しいエンドポイントのみが紐づく（取り違えがない） |

## 既存テストへの影響確認

- issue-26で追加した`test_assistants.py`の既存テスト（`endpoints == []`を検証しているもの）が回帰なく通ることを確認する
- 全体テスト（`pytest`）が回帰なく通ることを確認する
