# アシスタントとエンドポイントの紐付け（assistants_endpoints）の実装

## 概要

NAW-XXXX（複数チケットにまたがる機能）の一部移植。issue-26・issue-28で保留していた、アシスタントとテナントエンドポイント（AI接続先）の紐付けをFastAPIで実装する。

## 説明

### 背景

- issue-26でアシスタント一覧取得APIを実装したが、`endpoints`は常に空配列で返している
- issue-28でテナントエンドポイント（AI接続先）管理APIを実装したが、アシスタントとは未接続

移植元では`assistants_endpoints`中間テーブルがアシスタントとテナントエンドポイントを結び、`GET /api/assistants`のレスポンスに実際の接続情報（エンドポイントURL・タイプ・使用モデル）を含める。本チケットでこれを実装することで、アシスタント一覧APIが実用段階に到達する。

### やること（今回のスコープ）

- `assistants_endpoints`中間テーブル・モデルを新規作成する
  - `assistant_id`, `endpoint_id`, `tenant_id`, `model`（そのエンドポイント経由で使うAIモデル名）
  - 主キーは`(assistant_id, endpoint_id)`（`tenant_id`は含まない。移植元の最終スキーマに準拠）
- `GET /api/assistants`のレスポンスの`endpoints`項目を実データにする
  - 各エンドポイントは`id`（tenant_endpointのID）・`model`・`type`・`url`を含む
  - 移植元の`includeEndpointLabel=false`相当の挙動に合わせ、`label`（エンドポイント名）は含めない（一般ユーザー向け一覧のため）
- 動作確認用に、既存のシードデータ（アシスタント・エンドポイント）を紐付けるレコードを`seed.sql`に追加する

### スコープ外（後続チケット）

- 管理者向けのアシスタント⇔エンドポイント紐付けCRUD（現時点では`seed.sql`経由でのみデータ投入。API経由での追加・削除は別チケット）
- `assistant_categories`・`assistant_category_mappings`（カテゴリ機能）
- 管理者向けアシスタントCRUD（作成・更新・削除）
- `frontend`（React）側の対応（当面不問方針のため）
