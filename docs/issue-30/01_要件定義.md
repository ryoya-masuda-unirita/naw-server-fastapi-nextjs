# 01_要件定義

## 背景

issue-26で実装した`GET /api/assistants`は`endpoints`を常に空配列で返しており、issue-28で実装したテナントエンドポイント（AI接続先）管理APIともまだ接続されていない。移植元の`assistants_endpoints`中間テーブルを実装し、両者を結びつけることで、アシスタント一覧APIが実際の接続情報を返せるようにする。

## 機能要件

### データモデル

- `assistants_endpoints`テーブルを新規追加する
  - `assistant_id`：紐づくアシスタントID（`assistants.id`への外部キー）
  - `endpoint_id`：紐づくテナントエンドポイントID（`tenant_endpoints.id`への外部キー）
  - `tenant_id`：テナントID（`tenants.id`への外部キー。検索の絞り込み・RLS相当の用途）
  - `model`：そのエンドポイント経由で使用するAIモデル名（例: `gpt-4o`）
  - 主キーは`(assistant_id, endpoint_id)`（移植元の最終スキーマに準拠。`tenant_id`は主キーに含まない）
  - 1つのアシスタントが複数のエンドポイントに紐づくことができる（1対多）

### `GET /api/assistants`のレスポンス変更

- `endpoints`項目を、そのアシスタントに紐づく`assistants_endpoints`＋`tenant_endpoints`から構築した実データに置き換える
- 各エンドポイント項目の内容：
  - `id`：`tenant_endpoints.id`
  - `model`：`assistants_endpoints.model`
  - `type`：`tenant_endpoints.type`
  - `url`：`tenant_endpoints.endpoint`
- `label`（エンドポイント名）は含めない。移植元の`toEndpointResponse`は`includeEndpointLabel`フラグでlabelの有無を制御しており、一般ユーザー向け一覧（`getAssistantsByUserIdAndTenant`）では`false`（labelなし）で呼び出される仕様のため、これに合わせる
- `category`・`categories`は引き続き空/nullのまま（カテゴリ機能は別チケット）

## 非機能要件

- 既存の`backend/.claude/CLAUDE.md`のレイヤー構成に従う
- N+1を避けるため、複数アシスタント分のエンドポイント情報をバッチ取得する（issue-26のGroup紐づけ実装と同じ方針）
- 動作確認のため、`backend/seed.sql`に既存のシードアシスタント・シードエンドポイントを紐付けるレコードを追加する

## スコープ外

- 管理者向けのアシスタント⇔エンドポイント紐付けCRUD（追加・削除API）。今回はシードデータのみで動作確認する
- `assistant_categories`・`assistant_category_mappings`（カテゴリ機能）
- 管理者向けアシスタントCRUD（作成・更新・削除）
- `frontend`（React）側の対応（当面不問方針のため）
