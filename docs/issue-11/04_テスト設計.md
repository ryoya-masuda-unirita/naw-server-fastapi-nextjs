# 04_テスト設計

## テスト方針

- 新規追加する処理（リポジトリ、LIKEエスケープ、ソート許可リスト解決、パスワード発行共通処理、パスワード照合の非同期ラッパー）には専用の単体テストを追加する
- 既存のサービス層テストは、内部実装がリポジトリ経由に変わっても `session.execute` を介したクエリの呼び出し形が変わらない範囲では変更しない。挙動・アサーションが変わる箇所のみ更新する
- リポジトリの DB アクセスは `tests/integration/` に新規テストファイルとして追加する（CLAUDE.mdの「Model/Repositoryテストはintegration」方針に従う）
- ステータスコード差異・削除冪等設計の調査結果（`03_詳細設計.md` 7章）は実装変更を伴わないため新規テストは追加しない。既存テスト（`test_login_with_nonexistent_user` の401検証、`test_does_not_raise_when_user_not_found` の冪等検証等）が引き続き仕様を担保する
- LIKEエスケープの効果は、エスケープ関数単体の単体テストに加え、実際のDBでワイルドカード文字を含む検索が誤動作しないことを結合テストで検証する

## 既存テストへの影響

- `test_user_service.py` / `test_auth_service.py` の既存モックベーステストは、`UserRepository`/`TenantRepository` 抽出後も `session.execute` の呼び出し形（`select` → `execute` → `scalars().first()`）が変わらないため、原則として変更不要と見込む。実装後にテスト実行して確認する
- `create_user`/`update_user` のパスワード発行処理共通化に伴い、`PasswordHistoryRepository.save` のモック対象パスは変更しない（呼び出し元メソッド名が変わるのみ）
