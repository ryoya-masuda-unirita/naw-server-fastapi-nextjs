# #11 issue-11 ユーザー管理APIのリファクタ（code-review指摘の未対応分）

## 概要

Issue #9（ユーザー管理API CRUD・プロフィール実装）の `/code-review` で出た 🟡注意・🔵提案の指摘のうち、致命的指摘の修正を優先したため対応を見送った項目をまとめて対応する。

## 説明

`docs/issue-9/code-review.md` で「対応しない（リファクタIssueへ）」とした以下の項目に対応する。

### セキュリティ・正確性関連

- `backend/app/services/user_service.py` の `get_users` で `search_text` の LIKE ワイルドカード（`%`, `_`）がエスケープされていない
- `backend/app/services/user_service.py` の `get_users` で `sort` パラメータの列名にホワイトリストがなく、任意の属性名を `getattr` でモデル解決できてしまう
- `backend/app/services/auth_service.py` のリファクタで `login()` のエラーコードが履歴0件時 403→401 に変化している（意図的かフロントエンドと要確認）
- `backend/app/services/user_service.py` の `delete_user` が対象不在時に例外を出さず204を返す冪等設計の意図確認

### テスト

- `backend/tests/unit/test_auth_service.py` にリファクタ前にあったテストケース（パスワード履歴0件時のエラー、`PasswordHistoryRepository.save` 呼び出し確認）相当が欠落している

### コード品質

- `backend/app/schemas/user.py` の `UserResponse.from_user` に型ヒントがない（CLAUDE.md違反）
- `backend/app/services/user_service.py` の `_get_user`／`_get_tenant` パターンが `core/security.py`・`auth_service.py`・`user_service.py` に分散重複している（`UserRepository`/`TenantRepository` への抽出を検討）
- `backend/app/services/user_service.py` の `create_user`／`update_user` でパスワード生成・テナント取得・PasswordHistory保存のロジックが重複している
- `backend/app/services/user_service.py` の `get_users` で count クエリと本体クエリの直列実行、`reset_password` 系で Tenant の重複フェッチ、`PasswordHistoryRepository` 経由の bcrypt 検証がブロッキングになりうる点などの効率性改善
- `backend/app/services/user_service.py` の `get_users` で `excludeGroupId` パラメータを受理しつつ完全に無視している（グループ機能実装時に対応する設計だが、API契約上のリスクとして要検討）
