# 04_テスト設計

## テスト方針

- マーカー区切りロジック（`LibraryStreamRouter`）は、移植元のテストケース（1文字ずつ流す最悪ケース・マーカーがチャンク境界で分割されるケース・確定値取得・マーカー欠落時のフォールバック・コメント区間の振り分け）を移植し、単体テストで検証する。
- LLM Chat API・メッセージ送信APIの`createLibrary`対応は、既存のService単体テスト（Repositoryをモック）に、ライブラリ生成モードのケースを追加する形で検証する。
- DBへの実永続化（`system_prompt_templates`のシード投入・`libraries`テーブルへの保存）は、integrationテストで検証する。

## テストケース

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | マーカー区切り | タイトル・本文をまたぐ全文を1文字ずつ供給する | タイトル・本文が正しく振り分けられ、マーカー文字列が混入しないこと |
| 2 | マーカー区切り | `<<<TITLE>>>`がチャンク境界で分割される | タイトル・本文が正しく振り分けられること |
| 3 | 確定値取得 | 全文供給後 | `final_title`/`final_content`が正本を返すこと |
| 4 | フォールバック | マーカーが一切ない全文を供給する | `final_title`が空、`final_content`が全文になること |
| 5 | コメント区分 | `<<<COMMENT>>>`以降のテキストを供給する | コメント区分として振り分けられ、`final_content`に混入しないこと |
| 6 | コメント確定値 | `<<<COMMENT>>>`の有無 | `final_comment`が正本を返す・マーカーなしなら空文字を返すこと |
| 7 | LLM Chat API | `createLibrary=true`かつ`messageId`未指定 | 400エラーになること |
| 8 | LLM Chat API | `createLibrary=true`でストリーミング完了 | `library_title_delta`/`library_content_delta`イベントが配信され、`message_stop`後にライブラリが永続化されること |
| 9 | LLM Chat API | `createLibrary=true`でコメント区間が空 | デフォルト案内文が`text_delta`で配信されること |
| 10 | メッセージ送信API | `isCreateLibrary=true`でストリーミング完了 | `library_title_delta`/`library_content_delta`イベントが配信され、ライブラリが永続化されること |
| 11 | メッセージ送信API | `isCreateLibrary=true`かつタイトルが空 | ライブラリのタイトルが「ライブラリ」になること |
| 12 | メッセージ送信API | `isCreateLibrary=true`かつタイトルが255文字超 | 255文字に切り詰められて永続化されること |
| 13 | 固定システムプロンプト | `system_prompt_templates`テーブル | マイグレーション適用後、`type='LIBRARY'`の行が存在すること |
