# 08_動作確認

## 確認環境

- `naw-issue-loop`スキルによる全自動モード実行のため、ブラウザでの実操作確認は行わず、自動テスト（pytest）の実行結果のみで代替する。
- ローカルDB: `naw-fastapi-postgres`（Docker、`localhost:5433`）。

## 確認手順

1. `cd backend && uv run ruff check <変更・新規ファイル>` を実行し、Lintエラーがないことを確認。
2. `cd backend && uv run ruff format <変更・新規ファイル>` を実行し、フォーマットを揃える。
3. `cd backend && uv run alembic upgrade head` を実行し、`022_add_system_prompt_templates`マイグレーションが正常に適用されることを確認。
4. `docker exec -i naw-fastapi-postgres psql -U root -d postgres -c "SELECT type, length(content) FROM system_prompt_templates;"` で`LIBRARY`行のシード投入を確認。
5. `cd backend && uv run alembic downgrade -1 && uv run alembic upgrade head` でdowngrade/再upgradeが正常に動作することを確認。
6. `cd backend && uv run pytest -q` を実行し、新規追加分を含む全テストが通過することを確認。

## 確認結果

- `uv run ruff check` : 対象ファイルすべて `All checks passed!`。
- `uv run alembic upgrade head` : `021 -> 022` のマイグレーションが正常終了。
- シード投入確認:
  ```
    type   | length
  ---------+--------
   LIBRARY |   1662
  (1 row)
  ```
- `uv run alembic downgrade -1` → `uv run alembic upgrade head` : いずれも正常終了（エラーなし）。
- `uv run pytest -q` : **653 passed**（新規追加した`tests/unit/test_library_stream_router.py`（10件）、`tests/unit/test_llm_chat_service.py`のライブラリ生成モード追加分（2件）、`tests/unit/test_message_service.py`のライブラリ生成モード追加分（3件）、`tests/integration/test_system_prompt_templates.py`（2件）を含め、既存テストの回帰なし）。

## 未確認事項

- ブラウザ（`frontend-angular/`）を使った実際のUI操作での動作確認は、本Issueのスコープ（`naw-issue-loop`全自動モード）では行っていない。
- 実際のAzure OpenAIエンドポイントを使った、LLMが実際にマーカー形式（`<<<TITLE>>>`/`<<<CONTENT>>>`/`<<<COMMENT>>>`）で出力することの確認（プロンプトエンジニアリングの妥当性）は、モックによるユニットテストの範囲でのみ検証しており、実LLM呼び出しでは未検証。
