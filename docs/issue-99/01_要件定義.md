# 01_要件定義

## 背景

チャットのやりとりを後から読み返せるように md 形式でまとめた「ライブラリ」を、LLM に生成させる機能（`createLibrary`）が移植元（Spring Boot）に存在するが、issue-88（LLM Chat API 移植）・issue-93（Message送信API 移植）では意図的にスコープ外とされていた。issue-65 で Library 本体（CRUD・一覧・共有・タグ付け）は既に移植済みだが、生成機能自体が存在しないため、ユーザーはライブラリを新規作成できない状態にある。

移植元では、LLM Chat API（`/api/llm/chat`）・メッセージ送信API（`/api/messages/.../contents`相当）の両方から、リクエストに `createLibrary=true` を指定することでライブラリ生成モードに切り替えられる。生成中は通常のチャット応答の代わりに、タイトル・本文をそれぞれ専用の SSE イベントでストリーミング配信し、完了後に `libraries` テーブルへ永続化する。

## 機能要件

- LLM Chat API・メッセージ送信API の両方で、リクエストに `createLibrary`（メッセージ送信APIでは `isCreateLibrary`）フラグを指定できること。デフォルトは `false`（従来通りの通常チャット応答）。
- `createLibrary=true` の場合、LLM に対して「ライブラリ生成用の固定システムプロンプト」を追加指示したうえで、これまでの会話をまとめさせること。
- LLM の出力は、あらかじめ定めた区切りマーカーで「タイトル」「本文（md）」「補足コメント（省略可）」の3区間に区切られた単一のテキストとして生成させ、サーバ側でリアルタイムに区間判定してストリーミング配信すること。
  - タイトル区間: `library_title_delta` イベントで配信
  - 本文区間: `library_content_delta` イベントで配信
  - 補足コメント区間: 既存の `text_delta` イベントで配信（コメントが省略された場合は、生成完了後にデフォルトの案内文を `text_delta` として配信する）
- 区切りマーカーが、LLM から送られてくるチャンクの境界をまたいで分割されるケースを正しく扱えること（マーカーの一部だけが含まれるチャンクを誤って本文として配信しない）。
- ストリーミング完了後、確定したタイトル・本文を新規ライブラリとして永続化すること。
  - タイトルは 255 文字を超える場合は切り詰めること
  - タイトルが空の場合は「ライブラリ」をデフォルト値として使うこと
- `createLibrary=true` の場合、LLM Chat API では `messageId` の指定を必須とし、未指定の場合は 400 エラーとすること（生成したライブラリの紐付け先が必要なため）。
- メッセージ送信API では、送信元メッセージ（`req.messageId` で解決される既存メッセージ）にライブラリを紐付けること。
- ライブラリ生成用の固定システムプロンプトは、テナントに依存しないアプリケーション共通のマスタデータとして永続化し、実行時に参照できること。

## 非機能要件

- ライブラリの永続化は、ストリーミング応答を配信する非同期処理のライフサイクルとは独立した新規DBセッションで行うこと（既存の `_persist_token_usage`・`_persist_message_content` と同様の方針）。
- クライアント切断（`GeneratorExit`）時にも、可能な範囲で回答内容の永続化処理が中断されないこと（既存のメッセージ送信APIの堅牢性方針を踏襲する）。ただし、ライブラリ自体の永続化は、移植元同様ストリーミングが正常に完了した場合のみ行う。

## スコープ外

- Library 本体の CRUD・一覧・共有・タグ付け（issue-65 で対応済み）。
- `response_format` との相関バリデーション（`response_format` と `createLibrary` を同時指定できない、というルールが移植元に存在するが、`response_format` 自体が本バックエンドに未実装のため対象外とする）。
- ライブラリ本文中のグラフブロック（`chart:line`/`chart:bar`/`chart:pie`）のフロントエンド描画対応（本Issueはバックエンドのプロンプト・ストリーミング配信・永続化のみを対象とし、フロントエンドでの描画は対象外）。
- tools（Function Calling、#98）・添付ファイル（#97）と `createLibrary` の組み合わせ時の相互作用の網羅的な検証（両Issueは本Issue時点で未マージのため、`develop` ベースで独立して実装する）。
