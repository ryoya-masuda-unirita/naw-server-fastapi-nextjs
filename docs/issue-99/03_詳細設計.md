## 実装対象ファイル

### 新規作成

- `backend/app/core/library_stream_router.py`
  - `LibraryStreamRouter`クラス（マーカー区切りステートマシン。Python版では`feed(delta: str) -> list[tuple[str, str]]`・`flush() -> list[tuple[str, str]]`のインターフェースで、配信すべき`(区分, テキスト)`のリストを返す。区分は`"title"`/`"content"`/`"comment"`）
  - `final_title()`/`final_content()`/`final_comment()`: 蓄積した全文から正本を確定するメソッド（永続化用）
  - マーカー定数（`TITLE_MARKER`/`CONTENT_MARKER`/`COMMENT_MARKER`）
  - `LIBRARY_USER_INSTRUCTION_PREFIX`定数（ユーザー発話への前置テキスト）
- `backend/app/models/system_prompt_template.py`
  - `SystemPromptTemplate`モデル（`system_prompt_templates`テーブル。`type`（PK, str, max_length=64）・`content`（text）・`created_at`・`updated_at`。テナントに依存しない）
- `backend/app/repositories/system_prompt_template_repository.py`
  - `SystemPromptTemplateRepository.find_by_type(type_: str, session) -> SystemPromptTemplate | None`
- `backend/alembic/versions/022_add_system_prompt_templates.py`
  - `system_prompt_templates`テーブル作成 + `type='LIBRARY'`の固定プロンプトをシード投入（移植元Liquibase changesetの本文をそのまま踏襲）
- テスト
  - `backend/tests/unit/test_library_stream_router.py`（移植元`LibraryStreamRouterTest.java`のケースを移植）
  - `backend/tests/unit/test_system_prompt_template_repository.py`は追加しない（既存の`repositories`層は`integration/`でテストする方針に合わせ、`tests/integration/test_system_prompt_templates.py`を追加）

### 変更

- `backend/app/schemas/llm.py`
  - `LlmChatRequest`に`createLibrary: bool = False`を追加。docstringの「スコープ外」記載からライブラリ生成を除く。
- `backend/app/schemas/message.py`
  - `MessageContentCreateRequest`に`isCreateLibrary: bool = False`を追加。docstringの「スコープ外」記載からライブラリ生成を除く。
- `backend/app/services/llm_chat_service.py`
  - `stream_chat`: `createLibrary=True`かつ`messageId`未指定なら400。
  - 会話メッセージ構築時、`_apply_additional_prompt`適用後に、`createLibrary=True`なら`_apply_library_instruction_to_last_user_turn`（新規追加、末尾のuser発話へ`LIBRARY_USER_INSTRUCTION_PREFIX`を前置）を適用。
  - `createLibrary=True`の場合、`req.messages`内のrole="system"の発話をrole="user"へ降格（`_downgrade_system_turns_to_user`、新規追加）したうえで、`system_prompt_templates`から取得した`LIBRARY`プロンプトを新規のsystemメッセージとして先頭に追加。
  - ストリーミングループを`createLibrary`分岐に対応させ、`LibraryStreamRouter`経由でチャンクを`library_title_delta`/`library_content_delta`/`text_delta`（コメント）に振り分けて配信。
  - 完了後、`final_title()`（255文字に切り詰め、空なら"ライブラリ"）・`final_content()`を`LibraryRepository.save`で新規セッション永続化。`final_comment()`が空なら`「{title}」を作成しました`を`text_delta`で配信。
- `backend/app/services/message_service.py`
  - `stream_message_content`: `req.isCreateLibrary`が真の場合の処理を追加。`llm_chat_service.py`と同様のパターンで、`_apply_additional_prompt`適用後に`_apply_library_instruction_to_last_user_turn`を適用し、`historyMessages`内のrole="system"をrole="user"へ降格したうえでLIBRARYシステムプロンプトを先頭に追加。
  - ストリーミングループ・完了後の永続化は`llm_chat_service.py`と同様のロジック（`LibraryRepository.save`は新規セッションで実行）。
  - `_persist_message_content`へ渡す`answer`は、ライブラリ生成モードでは`final_comment()`（空ならデフォルト案内文）とする。

## 不明点・移植時の判断

- 移植元は`response_format`と`createLibrary`の相関バリデーションを持つが、本バックエンドには`response_format`自体が未実装のため対象外とする（`01_要件定義.md`のスコープ外に明記）。
- 移植元`LlmChatService`はメッセージ送信APIと異なりルーム所有権チェックを行わないが、既存の`stream_chat`実装は独自にルーム所有権チェックを追加済み（issue-88時点の判断）。本Issueはその既存方針を変更しない。
- Python版`LibraryStreamRouter`はコールバックではなく戻り値ベースのインターフェースとする（非同期ジェネレータからSSEバイト列を直接`yield`する既存コードの構造に合わせるため）。
