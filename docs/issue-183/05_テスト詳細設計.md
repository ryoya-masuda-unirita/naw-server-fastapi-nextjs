# 05_テスト詳細設計

## 共通ヘルパー

単体・結合テストそれぞれに `_sse_events(body: str) -> list[dict]` を追加する。frontend-angular の `parseSseDataLine` / `parseStreamEvent` と同じく、`data:` で始まる行だけを JSON として読み、`type` を持つものを返す。

## `backend/tests/unit/test_message_service.py`

| テスト（既存） | No | 変更内容 |
|---|---|---|
| 正常系の送信テスト（`event: text_delta` 等を確認しているもの） | 1〜4 | `_sse_events` で解釈し、`type` の並びが `text_delta, text_delta, message_stop, message_content` であること、`message_content.data.id` が保存したメッセージ内容IDであること、`event:` 行がないことを確認する |

| ライブラリ生成のテスト | 7 | `type` が `library_title_delta`・`library_content_delta`・`text_delta`・`message_stop` のイベントの `text` を確認する |
| 添付保存失敗時のテスト | 8 | `message_content.data.attachmentFiles == []` を確認する |

## `backend/tests/integration/test_messages.py`

| テスト | No | 内容 |
|---|---|---|
| 既存の送信・再生成・添付テスト | 1, 4, 6 | `event: complete` 等の確認を `_sse_events` による `type` の確認に置き換える |
| `test_edit_and_resend_streams_message_content_with_edited_question`（追加） | 9 | 下記シナリオ |

`test_edit_and_resend_streams_message_content_with_edited_question` のシナリオ（frontend-angular の `editMessage` と同じ API 呼び出し）:

1. 本文ありのメッセージ A（`owned_message_content`、質問「質問です」）がある
2. A と同じ親（なし）で `POST /api/messages` により新しいメッセージ A' を作成する
3. A' に対して編集後の質問文「編集後の質問」でメッセージ送信 API を呼ぶ（LLM はモック）
4. 応答のイベントを `_sse_events` で解釈し、最後が `message_content` で `data.messageId == A'`・`data.question == "編集後の質問"`・`data.status == "OK"` であること
5. `GET /api/messages?roomId=` で A と A' の `parentId` が同じ（兄弟＝バージョン分岐）であること
