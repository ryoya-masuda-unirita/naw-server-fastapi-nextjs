# 02_基本設計

## 変更対象

- メッセージ送信（アシスタント応答生成）API のストリーミング応答のイベント形式
- 上記 API の自動テスト（単体・結合）

## 画面 / API 変更概要

### メッセージ送信 API のストリーミング応答

| イベント | 変更前 | 変更後（移植元と同じ） |
|---|---|---|
| 回答の差分 | `event: text_delta` / `data: {"text": ...}` | `data: {"type": "text_delta", "text": ...}` |
| ライブラリ差分 | `event: library_title_delta` 等 / `data: {"text": ...}` | `data: {"type": "library_title_delta", "text": ...}` 等 |
| トークン数 | `event: message_stop` / `data: {"inputTokens", "outputTokens"}` | `data: {"type": "message_stop", "inputTokens", "outputTokens"}` |
| エラー | `event: error` / `data: {"message": ...}` | `data: {"type": "error", "message": ...}` |
| 最後のメッセージ内容 | `event: complete` / `data: {メッセージ内容}` | `data: {"type": "message_content", "data": {メッセージ内容}}` |

メッセージ内容の項目（`id`・`messageId`・`status`・`question`・`answer`・`context`・`attachmentFiles`・`referencePaths`・`isRated`）は移植元 `CreateMessageContentResponse` と同じで、変更しない。

## 影響範囲

- 呼び出し元: `frontend-angular/` のチャット送信・編集再送信・回答再生成（移植元形式のイベントを前提としているため、変更後に回答の表示・完了処理が正しく動く）
- `frontend/`（React）からはこの API は呼ばれていない
- LLM Chat API は別実装の SSE のため影響しない
- DB スキーマの変更なし

## 移植方針

- 移植元 `MessageService.streamAndPersist` と `response/sse` 配下のイベントクラス（`SseTextDeltaEvent`・`SseLibraryTitleDeltaEvent`・`SseLibraryContentDeltaEvent`・`SseMessageStopEvent`・`SseErrorEvent`・`SseCreateMessageContentResponseEvent`）に合わせる。
- 移植元は `SseEmitter.event().data(json)` でイベント名を付けずに送っているため、本ポートもイベント名の行を付けない。
- イベントの組み立ては既存の 1 か所（SSE 1 件を組み立てる関数）に集約されているため、その関数の出力形式と、最後のイベントの種別・入れ物だけを変える。
