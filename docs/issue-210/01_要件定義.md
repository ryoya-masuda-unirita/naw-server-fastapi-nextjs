# 01_要件定義

## 背景

- SECURE アシスタント（顧客環境のローカル LLM を使うアシスタント）では、ブラウザがクラウドの NAW 本体ではなく、顧客側に置かれた「ローカルサーバー（secuaigent-server-local）」へ直接メッセージを送り、ローカルサーバーが Waha! を呼んで回答を生成する。
- 移植元のローカルサーバーは Spring Boot（Java）+ H2 で作られ、Windows + Tomcat への配布を前提にしている。
- このリポジトリでは NAW 本体を FastAPI へ移植しているため、ローカルサーバーも Python（FastAPI）に揃え、Linux（Docker コンテナ）で動かせるようにする。
- このリポジトリの SECURE 対応（#102）では、移植後のローカルサーバーを呼ぶ前提のため、API の互換性を保つ必要がある。

## 機能要件

### 共通

- 移植元と同じ URL パス・HTTP メソッド・リクエスト形式（JSON / multipart のフィールド名）・レスポンス形式（JSON のフィールド名・ステータスコード）で応答する。
- 認証は移植元と同じく、リクエストヘッダー `X-SERVER-AUTH-KEY` が設定値と一致しない場合に 401 を返す。プリフライト（OPTIONS）と稼働確認 API は認証不要とする。
- CORS は移植元と同じく全オリジン・全ヘッダー・全メソッドを許可し、資格情報付きリクエストも許可する。
- アプリケーションのコンテキストパス（例: Tomcat の war 配置で付く `/secuaigent`）を設定で指定できる。未指定時はルート直下で応答する。
- 業務エラーは移植元と同じエラーレスポンス（`timestamp`（UNIX 秒）と `message`）を返す（400 / 404 / 500）。

### 稼働確認

- 稼働確認 API が固定文言「APIサーバは稼働中です。」を返す。

### メッセージ（SECURE アシスタントの質問・回答）

- 質問を受け付け、Waha! のジョブを実行して回答を生成し、Server-Sent Events（SSE）で NAW 互換のイベント（推論途中経過・ライブラリ生成途中経過・ライブラリ ID・回答本文・終了・メッセージ内容・エラー）を返す。
  - Waha! が書き出すストリームファイルを一定間隔で読み、推論途中経過・ライブラリ生成途中経過のイベントだけをブラウザへ中継する。
  - Waha! のジョブ結果が成功になったら、Waha! の出力ファイルから回答を確定し、回答・参照情報を保存したうえで、回答本文・終了・メッセージ内容のイベントを送って終了する。
  - ジョブ失敗・ストリームの error 終了・例外時は、メッセージ内容をエラー状態で保存し、エラーイベント（とメッセージ内容）を送って終了する。
  - ライブラリ作成指定時は、NAW 本体にライブラリのスタブを作成してライブラリ ID を通知し、生成されたライブラリ本文をローカルに保存し、タイトルを NAW 本体へ反映する。
  - 新規質問と回答再生成（既存メッセージ内容の ID 指定）の両方に対応する。
- 旧形式の同期 API（JSON で回答を返す）と、旧形式のストリーミング API（ストリームファイルの内容をそのまま中継し、メッセージ内容 ID・メッセージ ID をレスポンスヘッダーで返す）も移植元と同様に提供する（移植元で非推奨扱いだが、互換のため残す）。
- 複数のメッセージ ID を指定してメッセージ内容（質問・回答・参照・添付ファイル）を一括取得できる。
- メッセージ ID を指定してメッセージ内容を削除できる。

### ライブラリ本文

- ライブラリ ID を指定して、ローカルに保存したライブラリ本文を取得できる（存在しない場合は 404）。
- ライブラリ ID を指定して、ライブラリ本文を削除できる。

### 学習データ（インデックスのファイル）

- インデックスのファイル一覧を、表示名（部分一致）・ユーザー ID・状態・更新日の範囲で絞り込み、ページングして取得できる（Spring Data の Page 形式）。
- ファイルをアップロードし、Waha! の学習ジョブで登録できる。
- ファイルの表示名・参照先を更新できる。ファイルを添付した場合は、Waha! で旧データを削除してから再登録する。
- ファイルを削除できる（Waha! の削除ジョブを実行後、物理削除または論理削除）。
- Waha! の取得ジョブの結果（TSV）からファイル一覧を同期できる（未登録のものだけ追加）。
- フィードバック（または会話ルーム）の内容を追加学習として登録できる。
- ファイルのダウンロード API は、移植元が未実装（常に失敗）のため、同じく常にエラーを返す。

### 定期処理

- 1 時間ごとに、ストリームファイル出力先の古いファイル（既定 24 時間超）を削除する。

## 非機能要件

- 動作環境は Linux（Docker コンテナ）とする。イメージのビルド・起動手順を README に記載する。
- データは組み込み DB（ファイル 1 つ）に保存し、コンテナを作り直しても消えないよう永続ボリュームに置ける構成にする。
- テーブル構造の作成・変更はマイグレーションで管理し、起動時に自動適用する。
- 外部連携先（Waha!、NAW 本体）の URL・認証キー、ストリームの各種間隔・タイムアウト、DB の接続先は環境変数で切り替えられる。
- サーバー認証キーは必須設定とし、未設定のまま起動しない。
- 自動テストでは外部連携をすべてモックし、ネットワークや実 DB ファイルに依存しない。
- このリポジトリの既存プロジェクト（バックエンド）とは独立したプロジェクトとし、コードを共有しない。

## スコープ外

- Windows 向けの配布・起動スクリプト（2026-11-12 ユーザー判断）
- このリポジトリのバックエンド側の SECURE 対応（#102）
- H2 データベースの Web コンソール（組み込み DB を SQLite に置き換えるため提供しない）
- 移植元の既存 H2 データファイルからのデータ移行（新規配布前提）
