## DB（Alembic 初期リビジョン `0001`）

| テーブル | 列（型・制約） | 備考 |
|---|---|---|
| `message_contents` | `id` varchar(32) PK / `message_id` varchar(32) NOT NULL UNIQUE / `status` varchar(32) NOT NULL / `question` text NOT NULL / `answer` text NOT NULL / `context` text / `file_paths` text / `created_at`・`updated_at` timestamptz NOT NULL | index `message_contents_message_id_idx(message_id)`・`message_contents_created_at_idx(id, created_at)` |
| `message_content_files` | `id` varchar(32) PK / `message_content_id` varchar(32) NOT NULL FK→message_contents ON DELETE CASCADE / `name` varchar(256) NOT NULL / `type` varchar(128) NOT NULL / `data` blob NOT NULL / 日時 | 移植元の `data` は CLOB 定義だが Entity は `byte[]` のため blob |
| `files` | `id` varchar(36) PK / `tenant_id` varchar(32) / `name` varchar(255) / `display_name` / `reference` / `status` smallint NOT NULL（序数）/ `user_id` / `index_id` varchar(32) / `storage_url` varchar(2048) / `feedback_id`・`room_id` varchar(32) / 日時 | |
| `file_parts` | `id` varchar(36) PK / `tenant_id` / `file_id` varchar(255) FK→files ON DELETE CASCADE / 日時 | unique `uk_file_parts_id_file_id(id, file_id)` |
| `library_contents` | `library_id` varchar(36) PK / `content` text NOT NULL / 日時 | |

- 日時は UTC で保存し、JSON では Jackson の `Instant`（ISO-8601、`Z`、小数秒は 0/3/6 桁）で返す
- SQLite の外部キーは接続ごとに `PRAGMA foreign_keys=ON`、ファイル DB は `journal_mode=WAL`
- コンテナ起動時に `alembic upgrade head` を実行してから uvicorn を起動する（Liquibase の起動時適用に相当）

## 主要ロジック

### 認証ミドルウェア（`ServerAuthKeyFilter`）

- OPTIONS、`{CONTEXT_PATH}/api/hello` で始まるパスは素通し
- それ以外は `X-SERVER-AUTH-KEY` を `secrets.compare_digest` で比較し、不一致なら 401（Spring 既定形式 `{"timestamp","status":401,"error":"Unauthorized","path"}`）
- ミドルウェア順は CORS → 認証（401 にも CORS ヘッダーを付けるため。移植元は認証が先だが、ブラウザでエラー内容が読める方が有用なため）

### 例外ハンドラー（`APIControllerAdvice`）

| 例外 | ステータス | 本文 |
|---|---|---|
| `BadRequestError`（IllegalArgument 相当） | 400 | ErrorResponse |
| `EntityNotFoundError` | 404 | ErrorResponse |
| `ExternalServiceError`・`httpx.HTTPError`（RestClientException 相当） | 500 | ErrorResponse |
| `RequestValidationError`（必須ヘッダー・パラメーター欠落、型不一致） | 400 | Spring 既定形式 |
| Starlette の `HTTPException`（ルート不一致 404 等） | そのまま | Spring 既定形式 |
| その他の例外（IllegalState 相当） | 500 | Spring 既定形式 |

### Waha! クライアント（`ServiceRunService`）

- ベース URL: `{WAHA_URL}WahaServer/servicerun/api`
- `start_session` GET `/startsession?authkey=`、`end_session` GET `/endsession?sessionid=`
- `upload_file(filename, bytes, slot, session_id)` POST multipart `file` → `/upload/{slot}?sessionid=`
- `execute` / `execute_with_stream_file`（`streamfilepath`）/ `execute_learning`（`splitLength`・`filepath`）/ `execute_sync`（`start`・`end`）→ GET `/execute/{serviceId}?sessionid=...`
- `poll_result_once` → `SUCCESS*`=SUCCESS、`RUNNING`=RUNNING、それ以外 FAILURE
- `get_results` は初回取得前から間隔を空け、最大 10 回 RUNNING を許容。FAILURE は `ExternalServiceError("ジョブの実行に失敗しました。")`。上限超過時は例外を出さずに戻る（移植元どおり）
- `download_file(session_id, slot)` → GET `/download/{slot}?sessionid=` の本文文字列
- HTTP タイムアウトは移植元 RestTemplate と同じく無制限、4xx/5xx は `httpx.HTTPStatusError`

### NAW API クライアント

- `create_library_stub(message_id, access_token, tenant_id)` POST `{NAW_BASE_URL}/api/libraries` `{"messageId"}` → `data.id`（空・非文字列は例外）
- `update_library_title(library_id, title, ...)` PATCH `/api/libraries/{id}/title` `{"title"}`
- `Authorization: Bearer`、`X-Tenant-ID`（指定時のみ）。base-url・accessToken 未設定・HTTP 失敗は `NawApiError`

### メッセージ（同期・一覧・削除）

- `post_message_content`: 移植元 `MessageContentService.postMessageContent` を移植。Waha! 呼び出し中の例外は ERROR 状態で保存し、`endSession` は finally で必ず呼ぶ
- 履歴 JSON は `[{"role": "USER", "content": "..."}]`、添付は先頭 1 件のみ Waha! に送る（移植元どおり）
- 参照パスは `file_paths` 列にカンマ区切りで保存し、空なら `referencePaths: null`（移植元 `StringListConverter` の挙動）

### SSE（`MessageContentStreamService`）

```
POST /api/messages/content
  prepare_stream（同期・DB 確定）→ StreamRuntime 作成 → バックグラウンドタスク起動 → StreamingResponse(キュー読み出し)
バックグラウンド:
  job:   [createLibrary なら NAW スタブ作成 → library_id 送信] → startSession → textData/question/history/attachment アップロード
         → tail・result ポーリングタスク起動 → execute(streamfilepath)
  tail:  STREAM_TAIL_POLL_INTERVAL_MS ごとに tail_reader.read_new → 中継 → error 終端なら finalize_with_error → try_finalize
  result: STREAM_RESULT_POLL_INTERVAL_MS 後から同間隔で poll_result_once → FAILURE なら finalize_with_error、SUCCESS なら try_finalize
  try_finalize: SUCCESS 時のみ。残りを drain → outputfile をダウンロードして回答確定 → ライブラリ保存 → NAW モードなら text_delta / message_stop / message_content → 終了
```

- 終了判定は `finalized` フラグを await 前に同期的に立てて二重実行を防ぐ。自分以外のポーリングタスクはキャンセルする
- イベントは `data:{JSON}\n\n` 形式でキューへ。`client_connected` が False なら送らない。終了時は番兵を入れてレスポンスを閉じる
- レスポンス側は `STREAM_EMITTER_TIMEOUT_MS` で打ち切る。切断・タイムアウトでも DB 更新は続ける
- バックグラウンドタスクはサービスが参照を保持し（GC 防止）、アプリ終了時にキャンセルする
- NAW モードはストリームファイルの `reasoning_delta`・`library_title_delta`・`library_content_delta` のみ中継（ライブラリ系は本文・タイトルを蓄積）。旧形式は `data:` 行をそのまま中継
- textData: `{"streamfilepath","createLibrary","tools"(空なら省略),"accessToken"(null なら省略),"messageId"(null なら省略)}`

### ストリームファイル追従（`StreamFileTailReader`）

- バイトオフセットから追記分のみ読み、UTF-8 で連結したバッファから `\n\n` 区切りのイベントを取り出す
- 残りのバッファから改行で終わる `data:` 行を 1 イベントとして取り出し、それ以外の完結行は捨てる（移植元どおり）
- `type` が `completed` → COMPLETED、`error` → ERROR を終端とする

### 学習ファイル（`FileService`）

- 一覧: `tenant_id`・`index_id` 一致 + 任意条件（表示名の部分一致、ユーザー ID、状態、`updated_at` の範囲）。`updatedAtFrom/To` は `yyyy-MM-dd` をプロセスのローカルタイムゾーン（コンテナは `TZ`）の 0 時として解釈。`page < 0`・`size < 1` は 400
- Page 形式: `content / pageable{pageNumber,pageSize,sort,offset,paged,unpaged} / last / totalElements / totalPages / first / size / number / sort{empty,sorted,unsorted} / numberOfElements / empty`
- File の JSON: `id, tenantId, name, displayName, reference, status(名前), userId, indexId, storageUrl, feedbackId, roomId, createdAt, updatedAt, fileParts[{id, tenantId, fileId, createdAt, updatedAt}]`
- TSV の分割は Java の `String.split` 互換（末尾の空要素を落とす、区切りがなければ元文字列 1 要素）
- 同期: 列 0=フルパス、1=パート ID、2=ファイル ID。パスの `\` を `/` に置換し、ファイル名・親ディレクトリを取り出す（なければ「ファイル{ID 先頭 8 文字}」）。既存 ID（全テナント）は追加しない
- 削除: パート ID を改行区切りで `ids*.txt` としてアップロード → execute → get_results → 物理削除（パートは FK カスケード）または状態を DELETED
- 追加学習: `feedbackId`・`roomId` のどちらか一方のみ必須（違反は 400）。分割長 3000 固定、ファイル名・参照名は移植元の文言どおり
- ダウンロード: 常に 500（移植元が `RuntimeException` を投げるだけのため）

### 定期処理

- lifespan で 1 時間ごとのタスクを起動し、出力先直下の `*.txt` のうち最終更新から `STREAM_ORPHAN_CLEANUP_MAX_AGE_HOURS` 超のものを削除する
