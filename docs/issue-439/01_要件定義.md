# 01_要件定義

## 背景

SECURE アシスタントの RAG（社内文書を根拠にした回答）は、学習のときに文書をベクトルにして保存し、質問のときに質問をベクトルにして近い部分を探す。この 2 か所で、埋め込みモデルを呼ぶ。

#436 で、回答の生成は、社内側から Bedrock を直接呼べるようになった。しかし埋め込みは、Azure OpenAI などの 4 つのプロバイダしか呼べず、Bedrock だけでは RAG が通らない。Azure OpenAI を使わずに、Bedrock だけで RAG を通せるようにしたい。

移植元には Bedrock の埋め込みがなく、Python 版だけの拡張である。ただし、プロバイダごとの実行器の構成、設定の項目、失敗の分類は、移植元と既存の Python 版に揃える。

## 機能要件

| No | 要件 |
|---|---|
| F1 | 埋め込みアダプタが、文書のチャンクを、Bedrock の埋め込みモデルでベクトルにして、ベクトル DB に保存できる |
| F2 | 検索アダプタが、質問を、同じ Bedrock の埋め込みモデルでベクトルにして、ベクトル DB から近いチャンクを探せる |
| F3 | 接続先・API キー・モデル名は、既存のプロバイダと同じ設定の項目（URL・API_KEY・MODEL_NAME）で渡せる |
| F4 | 返ってきたベクトルの次元数が、ベクトル DB のテーブルの次元数と合うこと。合わないときは、保存や検索の前に、分かる失敗にする |
| F5 | ワークフロー定義で、埋め込み・検索の両方に Bedrock をベンダーとして登録できる。既存のベンダーの設定は、そのまま動く |
| F6 | 失敗（認証エラー・モデル不明・通信エラー・形式の不一致）は、既存のプロバイダと同じ分類の失敗として返り、API キーなどが出力に出ない |
| F7 | `onprem/` の手順だけで、Bedrock だけの RAG（学習 → 検索 → 回答）を通せる |

## 非機能要件

- 既存のプロバイダ（OpenAI・Azure・SecuAiGent・Echo）の挙動と、既存のテストの結果が変わらない
- 外部通信を行うテストは、モックで行い、本物の Bedrock には接続しない
- Bedrock の部品は、専用のファイルと、目印（`bedrock-ext`）をつけた数行だけにし、取り除いても既存のテストが通る（#436 と同じ）
- 追加・変更する関数・メソッド・クラスに、日本語の NumPy 形式の docstring を書く
- 埋め込みの呼び出しは、1 回の入力につき 1 回の通信とする

## スコープ外

- クラウド側 `server/` の埋め込みの Bedrock 対応
- 既存のベクトルの再計算・移行
- 本物の Bedrock への接続確認（API キーが要るため、手順を残してユーザーが行う）
- Cohere Embed など、Titan 以外のモデルの対応
- 回答の生成（#436 で対応済み）
