## 新規: `embedding/bedrock.py`

### 構成（上から、この順に書く）

| 順 | 要素 | 役割 |
|---|---|---|
| 1 | 定数 | `INVOKE_PATH_TEMPLATE = "/model/{model_id}/invoke"`、`EXPECTED_DIMENSIONS`（`vector.schema` の `EMBEDDING_DIMENSIONS` を使う） |
| 2 | 接続先の関数 `request_target(configuration)` | URL（`{URL}/model/{モデル ID（URL エンコード）}/invoke`）と、認証のヘッダー（`Authorization: Bearer {API キー}`・`content-type`）。**接続先ごとの違いはここだけ** |
| 3 | 形式の関数 | リクエスト本文の組み立て（`{"inputText": 文字列}`）、応答の解釈（`embedding` を取り出し、次元数を確かめる） |
| 4 | `BedrockCoreEmbeddingProvider` | `embed(request) -> CoreEmbeddingResult`（学習用。OpenAI・Azure の実行器と同じ形） |
| 5 | `embed_query(configuration, text) -> list[float]` | 質問用。`query_embedding.py` の `_EMBEDDERS` から呼ぶ関数 |

ファイルの冒頭の説明に、「移植元に対応する実装がない独自の拡張。移植元が対応したら置き換える」と書く。

### リクエストとレスポンス（AWS 公式ドキュメントの Titan G1 - Text）

- URL: `https://bedrock-runtime.<リージョン>.amazonaws.com/model/amazon.titan-embed-text-v1/invoke`
  - `URL`（設定）はホスト（`https://bedrock-runtime.ap-northeast-1.amazonaws.com`）、`MODEL_NAME` はモデル ID
- 本文: `{"inputText": "..."}`（G1 は `inputText` のみ。ほかのパラメータはない）
- 応答: `{"embedding": [float, ...], "inputTextTokenCount": int}`
- 認証: `Authorization: Bearer {Bedrock API キー}`（AWS の「Bedrock API キーを使う」の案内。Mantle と違い、2 種類のヘッダーは不要）

### 失敗と検証

- HTTP エラー: 学習用は `ProviderHttpError`（OpenAI 系と同じく、書式を整える）、質問用は `QueryEmbeddingError`（`embedding request failed: HTTP {status}`）
- 応答に `embedding` がない・配列でない: `TypeError`（学習用）/ `QueryEmbeddingError("embedding response is malformed")`（質問用）
- **次元数の検査:** ベクトルの長さが 1536 でなければ、保存・検索の前に、`DIMENSION_MISMATCH: embedding vector dimensions do not match ...` で失敗にする（SecuAiGent と同じ書式）。モデル ID を V2 などに変えたときに、DB のエラーではなく、原因が分かる失敗にするため
- ログ: `provider`・`model`・入力の文字数だけ。本文・キーは出さない

### 学習用と質問用で分ける理由

既存の構造が、学習用（`embedding/`、`CoreEmbeddingRequest`）と、質問用（`retrieval/query_embedding.py`、文字列を受けて `list[float]`）の 2 系統に分かれているため。OpenAI・Azure も、同じ重複を持っている。HTTP の送信と応答の解釈は、`bedrock.py` の中の共通の関数にまとめ、2 系統から呼ぶ。
