## 詳細

### 1. 429・5xx のリトライ（🔵 提案）→ 対応しない

OpenAI・Azure の埋め込みも、リトライしない作りで、Bedrock だけリトライを入れると、プロバイダごとの挙動がずれる。生成AIアダプタの README に、Spring AI・Azure SDK の自動リトライは再現していない、と既に書いてある。代わりに、`onprem/README.md` と `08_動作確認.md` に、「Bedrock の埋め込みは 1 分あたりの回数で制限され、大きな文書の学習で 429 が出ると、その学習は失敗になる。時間をおいて学習し直す」と書いた。実際に頻発するなら、リトライは、全プロバイダに共通の仕組みとして、別の Issue で入れる。

### 2. JSON でない応答・数値でない値（🔵 提案）→ 対応済み

200 でも JSON でない応答（プロキシの HTML など）と、数値でない値は、Python では `ValueError` で、質問用の既存の処理は、`ValueError` を設定の誤りとして扱う。Bedrock 側の不具合を、設定の誤りと取り違えないよう、どちらも `TypeError("embedding response is malformed")` にそろえた。

確認すると、失敗の要約には分類のコードが含まれないため、利用者に見える差は小さい。それでも、分類をそろえる意味はある。一方、例外を連鎖させると、要約が元の JSON エラーの文言（`Expecting value: ...`）に置き換わることが分かったので、連鎖を切った（`from None`）。テストを追加した（数値でない値 3 種・JSON でない応答・質問用の経路）。

### 3. NaN・無限大（🔵 提案）→ 対応済み

質問用は、後段で有限かを確かめるが、学習用は確かめず、そのまま保存されうる。`parse_vector` で、学習用・質問用に共通で弾くようにした（`TypeError("embedding vector contains non-finite value")`）。テストを追加した（NaN・無限大）。

### 4. 例のファイルが実機未確認（🔵 提案）→ 対応しない

実機の確認は、本物の Bedrock API キーが要り、私は行えない。マージ前の確認は、`08_動作確認.md` の「未確認事項」と、PR の本文に、4 点を書いて、あなたの確認に任せている。ただし、「利用者が、例を使って、未検証と気づけない」という指摘はもっともなので、`onprem/README.md` に「この例は、本物の Bedrock では、まだ確認していない」と明記した。JSON はコメントを書けないため、ファイルの中には書いていない。
