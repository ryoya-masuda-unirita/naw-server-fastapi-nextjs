# 04_テスト設計

## テスト方針

- 外部通信は、すべてモック（`respx` または既存の差し替え）で行う。本物の Bedrock には接続しない
- 既存のプロバイダと既存のテストは変えない。ベンダーの表を全件確かめているテストがあれば、実装で影響を確かめる
- 取り外したとき（専用ファイルと `bedrock-ext` の行を削除）に、既存のテストが通ることを確かめる

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 接続先 | URL（末尾 / あり・なし）とモデル ID | `…/model/{モデル ID}/invoke` になる。モデル ID の記号は URL エンコードされる |
| 2 | 認証 | リクエストのヘッダー | Bearer の API キーと content-type が付く。`x-api-key` は付かない |
| 3 | リクエスト本文 | 学習用・質問用 | `{"inputText": 文字列}` だけが送られる |
| 4 | 学習用の成功 | 1536 次元のベクトルが返る | 成功の結果になり、ベクトルが float32 に丸められて返る（既存の実行器と同じ） |
| 5 | 質問用の成功 | 同上 | 長さ 1536 の `list[float]` が返る |
| 6 | 次元数の不一致 | 1024 次元のベクトルが返る（V2 を指定した場合など） | `DIMENSION_MISMATCH` の失敗になる（学習用・質問用の両方） |
| 7 | 応答の形式不正 | `embedding` がない・配列でない・本文が JSON でない | 学習用は `TypeError`、質問用は `QueryEmbeddingError` |
| 8 | HTTP エラー | 401・403・429・500 | 学習用は `ProviderHttpError`、質問用は `QueryEmbeddingError`（`HTTP {status}`）。API キーが出力に出ない |
| 9 | 工場の登録（学習用） | プロバイダが Bedrock | 埋め込みの実行器が登録され、`CoreEmbeddingRequest` を実行できる |
| 10 | 質問の埋め込み | `embed_text` に Bedrock の設定 | `_EMBEDDERS` から Bedrock の関数が呼ばれ、ベクトルが返る |
| 11 | 埋め込みアダプタの検証 | `VENDOR` に `Bedrock` / `97` | 保存時チェックを通り、`SUPPORTED_VENDORS` で弾かれない |
| 12 | 検索アダプタの検証 | `VENDOR` に `97` | ベンダー名が `Bedrock` になる |
| 13 | 未知の ID の維持 | 既存のテストが使う「未知の ID」 | 従来どおり「未対応」で止まる（97 と重ならないこと） |
| 14 | ワークフロー定義 | 埋め込み・検索の定義に `VENDOR: Bedrock` と `${BEDROCK_API_KEY}` | 読み込めて、展開される |
| 15 | 通しのテスト（モック） | 学習（埋め込みアダプタ）→ 検索（検索アダプタ）を、モックの Bedrock で | 学習で保存したベクトルと、検索で作った質問のベクトルの次元が合う |
| 16 | 既存の回帰 | core・adapter・embedding・retrieval・waha-emulator の既存テスト | すべて通る |
| 17 | 静的チェック | ruff・mypy・docstring の検査 | 通る |
| 18 | 消せること | 専用ファイル・専用テスト・`bedrock-ext` の行を取り除く | 既存のテストがすべて通る（確認後、元に戻す） |
