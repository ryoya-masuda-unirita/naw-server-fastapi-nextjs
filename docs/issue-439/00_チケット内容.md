# #439 学習・検索のベクトル化で Bedrock の埋め込みモデルを使えるようにする

## 概要

学習（文書のベクトル化）と検索（質問のベクトル化）で、AWS Bedrock の埋め込みモデルを使えるようにする。#436 で回答の生成（チャット）は Bedrock で動くようになったが、Claude には埋め込みモデルがないため、RAG は Bedrock だけでは通らない。この Issue で、Azure OpenAI の埋め込みに頼らずに、`onprem/` で RAG を Bedrock だけで通せるようにする。

## 説明

### 背景・事実

- 埋め込みを実行できるプロバイダは OpenAI・Azure OpenAI・SecuAiGent・Echo の 4 つ。Bedrock の埋め込みは呼べない
- 移植元に Bedrock の埋め込みはない。移植ではなく、Python 版だけの拡張になる（#436 と同じ位置づけ）
- ベクトルの次元数は 1536 で固定されている（ベクトル DB のテーブルの列も 1536 次元）
- 埋め込みアダプタ・検索アダプタ・生成AIアダプタは、ベンダー ID の表を別々に持つ
- 今の回避策は、回答は Bedrock、埋め込みだけ Azure OpenAI

### 着手前の調査で分かったこと（AWS 公式ドキュメントと検索結果）

- **Mantle（#436 で使った入口）には、埋め込みの入口がない。** AWS のドキュメントが挙げる Mantle の API は、Responses・Chat Completions・Models・Anthropic Messages で、埋め込みはない。第三者のゲートウェイの文書にも「Mantle に埋め込みはない」とある。このため、埋め込みは別の入口（Bedrock Runtime の InvokeModel）を呼ぶ
- **認証:** Bedrock API キー（Bearer）は、Bedrock と Bedrock Runtime の操作に使える（AWS の「Bedrock API キーを使う」のページ）。そのキーの IAM に、`bedrock:InvokeModel` と `bedrock:CallWithBearerToken` が要る（後者は第三者の案内。公式での確認は未了）
- **Titan Text Embeddings V2**（`amazon.titan-embed-text-v2:0`）
  - リクエスト: `inputText`（必須）、`dimensions`（1024・512・256 から選ぶ。既定 1024）、`normalize`（既定 true）、`embeddingTypes`
  - レスポンス: `embedding`（float の配列）、`inputTextTokenCount`、`embeddingsByType`
  - 100 以上の言語に対応（日本語を含む。preview の扱いと書かれている）。**1536 次元は選べない**
- **Titan Embeddings G1 - Text**（`amazon.titan-embed-text-v1`）
  - リクエストは `inputText` だけ。推論パラメータなし。次元数は、AWS の公式ページ 2 つには書かれていなかった。AWS の別の資料と複数の記事は 1536 としている（日本語の AWS ページ 1 つだけが 1,024 と書いており、これは誤りと見ている）。英語に最適化されたモデル
  - 提供終了の記載は、確認したページにはなかった
- Cohere Embed が Bedrock にあるか、その次元数は、今回確認できなかった

### 対応

- Bedrock Runtime の InvokeModel で、Titan の埋め込みを呼ぶ実行器を、新しい専用ファイルとして追加する。#436 と同じく、後から消せる形にする
- 学習用の埋め込み（埋め込みアダプタ）と、質問用の埋め込み（検索アダプタ）の両方で使えるようにする
- 埋め込み・検索アダプタのベンダー ID の表に、Bedrock を足す
- `onprem/` に、学習・検索の例と手順を足す
- 実機の確認（Bedrock API キーが要る）は、手順を残してユーザーが行う

### 対象外

- クラウド側 `server/` の埋め込み（`AZURE_OPENAI_EMBEDDING` 相当）の Bedrock 対応
- 既存のベクトルの再計算・移行
- 次元数を設定にすること（下の「決めること 1」の案による）
