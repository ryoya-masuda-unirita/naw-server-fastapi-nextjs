# 03_詳細設計

## 実装対象ファイル

### `AGENTS.md`

- `.claude/CLAUDE.md` で既に整理されている frontend 移植向けの運用導線を、Codex 向けの `Skills / Commands` 節へ追加する。
- `naw-frontend-issue-workflow` / `naw-frontend-issue-batch` / `naw-frontend-issue-loop` / `naw-frontend-mentor` の呼び出し条件を明文化する。
- backend 優先方針と矛盾しないよう、frontend 系 Issue は優先順位確認を要すること、`frontend-port` ラベルで backend Issue と区別することを追記する。

### `frontend/AGENTS.md`

- 既存の簡易ガイドを、`frontend/.claude/CLAUDE.md` にある移植元デザイン資産、Angular → React 対応表、ディレクトリ構成、テスト命名補足、コーディング規約の粒度へ拡張する。
- Codex 実行時ルールとして完結させるため、`frontend/.claude/CLAUDE.md` を読まなくても移植時の判断ができる内容を優先して移植する。

### `.codex/skills/naw-frontend-issue-workflow/SKILL.md`（新規）

- `.claude/skills/naw-frontend-issue-workflow/SKILL.md` をベースに、Codex 向けの表現へ調整した frontend 移植 Issue の標準フローを追加する。
- 参照先は `.claude/...` ではなく `.codex/...` と `frontend/AGENTS.md` に置き換える。
- 調査方法は Claude 固有の agent 前提を排し、Codex が直接読む前提へ揃える。
- 起票手順には `frontend-port` ラベル付与、Issue タイトル付け直し、Project 追加確認を含める。

### `.codex/skills/naw-frontend-issue-batch/SKILL.md`（新規）

- backend 用 `naw-issue-batch` の Codex 文体に合わせ、frontend 移植候補を Issue 化するだけのフローを定義する。
- 候補検出条件に `frontend/src/`、`backend/app/routers/`、`gh issue list`、`gh pr list`、`frontend-port` ラベルを含める。
- 依存バックエンド API が未実装の候補を除外するルールを盛り込む。

### `.codex/skills/naw-frontend-issue-loop/SKILL.md`（新規）

- backend 用 `naw-issue-loop` の Codex 向け構造を踏襲しつつ、対象を `frontend-port` ラベル付き Todo Issue のみに限定する。
- 自動処理の開始時に `gh issue view ... --json title,body,labels` でラベル確認を必須化する。
- frontend の検証方法として `npm run test` / `npm run lint` / `npm run type-check` と、必要に応じた `npm run dev` ベースの画面確認方針を記載する。
- 補助スクリプト `scripts/next_todo_frontend_issue.sh` を参照する。

### `.codex/skills/naw-frontend-issue-loop/scripts/next_todo_frontend_issue.sh`（新規）

- `frontend-port` ラベル付き Open Issue のうち、Project Status が `Todo` の最小 Issue 番号を返す。
- `.claude` 側スクリプトのロジックを Codex 側へ移し、frontend loop の選定条件を単独で再利用できるようにする。

### `.codex/skills/naw-frontend-mentor/SKILL.md`（新規）

- `.claude/skills/naw-frontend-mentor/SKILL.md` をベースに、Codex 向けの伴走フローを追加する。
- 「AI は実装主体ではなく講師・レビュアー」「ユーザーが書いたコードをレビューする」「質問されたら具体例を出してよい」という役割差分を明文化する。
- frontend 標準 workflow との差分だけを整理し、通常実装フローと混同しないようにする。
