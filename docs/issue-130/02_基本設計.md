# 02_基本設計

## 変更対象

- ルートの運用ガイド
- frontend 配下の運用ガイド
- Codex 用 skill 一式
- frontend 移植 Issue のルール定義とその導線

## 画面 / API 変更概要

- 画面や API の利用者向け仕様変更は行わない。
- Codex が Issue 対応時に参照する運用文書と skill 構成を更新し、frontend 移植向けのフローを追加または明文化する。
- frontend 移植 Issue の識別ルール、着手条件、全自動処理条件、伴走支援条件を Codex 側にも持たせる。

## 影響範囲

- Codex が新規 Issue に着手する際の判断基準。
- frontend 移植関連の Issue 起票、ループ処理、伴走支援の呼び出し条件。
- AGENTS と skill の責務分担、および参照先の整合性。
- 既存の backend 優先方針との共存方法。

## 移植方針

- `.claude` 側の内容をそのまま機械的に複製するのではなく、Codex の tool 制約と既存の AGENTS / skill 構成に合わせて再配置する。
- backend 用 workflow と frontend 用 workflow は対になる構成を基本としつつ、Codex 側で未提供の仕組みに依存する記述は避け、必要なら Codex 向けの表現に置き換える。
- frontend 向けの運用知識は、日常的に参照するガイドへ要点を集約し、個別 skill では実行手順に集中させる。
- `frontend-port` ラベルのような識別ルールは、Issue 起票・選定・自動処理の各フローで一貫して使う前提で定義する。
- mentor 的なフローは、標準 workflow と目的が異なるため、追加する場合は実装主体と承認フローの違いが明確に分かるよう分離する。
