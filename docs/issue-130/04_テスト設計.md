# 04_テスト設計

## テスト方針

- 本 Issue は運用ドキュメントと skill 定義の更新が中心のため、主に静的確認で検証する。
- 追加した skill が既存の Codex 運用ルールと矛盾していないことを、参照パス・コマンド例・ラベル運用の観点で確認する。
- 補助スクリプトはシェル構文エラーがないことと、意図した `gh` クエリになっていることを確認する。
- frontend/AGENTS.md は、Codex 実行時に必要な移植ルールが読み切れる粒度になっているかを確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | ルート導線 | `AGENTS.md` を確認する | frontend 用 4 skill の呼び出し条件が追加されている |
| 2 | 優先方針整合 | `AGENTS.md` を確認する | backend 優先方針と frontend 着手前確認ルールが残っている |
| 3 | frontend ガイド | `frontend/AGENTS.md` を確認する | デザイン資産、Angular → React 対応表、規約が Codex 側へ反映されている |
| 4 | workflow skill | `naw-frontend-issue-workflow` を確認する | 起票手順、`frontend-port` ラベル、承認フロー、参照先が Codex 向けに定義されている |
| 5 | batch skill | `naw-frontend-issue-batch` を確認する | frontend 候補の検出条件と「Issue 起票のみ」の制約が定義されている |
| 6 | loop skill | `naw-frontend-issue-loop` を確認する | `frontend-port` ラベル付き Todo Issue のみ対象であることが定義されている |
| 7 | mentor skill | `naw-frontend-mentor` を確認する | AI が講師役であり、実装主体はユーザーであることが明記されている |
| 8 | loop スクリプト | `bash -n` と内容確認を行う | 構文エラーがなく、`frontend-port` ラベル付き Todo Issue の最小番号を返すロジックになっている |
| 9 | 参照整合 | `rg` で `.claude/skills/naw-frontend` と `.codex/skills/naw-frontend` を確認する | Codex 用ファイルから `.claude` 直参照が不要な箇所で残っていない |
| 10 | skill 一覧整合 | `.codex/skills` を確認する | 新規 frontend skill 群が backend 用 skill と並んで存在する |
