# 01_要件定義

## 背景

このリポジトリでは、Codex 用の運用ルールを `AGENTS.md` と `.codex/skills/` に集約する方針になっている。一方で、実運用上の更新は `.claude` 側で先行しており、特に frontend 移植に関する issue 対応フロー、ラベル運用、移植ガイドの詳細度に差が生じている。

その結果、同じ依頼でも `.claude` と Codex で参照すべき手順や判断基準が一致せず、Issue 起票や着手時の挙動に差が出るリスクがある。Codex 単独でも同等の運用判断ができる状態にそろえる必要がある。

## 機能要件

- Codex 側で参照すべき運用ルールだけを見れば、frontend 移植 Issue の起票、着手、全自動処理、伴走支援の各フローを判断できること。
- `.claude` にだけ存在する frontend 向け workflow 群の有無と役割差分を棚卸しし、Codex 側へ反映するか、反映しないならその理由を整理すること。
- frontend 移植 Issue をバックエンド Issue と区別するためのラベル運用と、関連する選定ルールを Codex 側にも定義すること。
- frontend 向けの移植ガイドについて、Codex 側の運用文書だけで必要な判断ができる粒度まで反映すること。
- Codex 用の AGENTS と skill 群の間で、参照先や呼び出し条件が矛盾しないこと。
- 既存の backend 優先方針や Issue 承認フローを壊さずに、今回の追加ルールを組み込めること。

## 非機能要件

- 既存の Codex 運用ルールとの整合性を保ち、同じルールが複数箇所で矛盾した表現にならないこと。
- `.claude` を実行時ルールの前提にせず、Codex 側の文書だけで完結する構成に近づけること。
- 追加する運用文書や skill は、用途が明確で、既存の backend 用 workflow と役割分担が判別しやすいこと。
- 今後 `.claude` 側に変更が入っても、Codex 側で追随対象を見つけやすい構成にすること。

## スコープ外

- `frontend/` や `backend/` の業務機能そのものの実装変更。
- `.claude` 側の既存 skill やドキュメントの改修。
- GitHub Issue / Projects の運用方針自体の全面見直し。
- frontend 移植 Issue を実際に新規作成・一括処理する運用テストの完遂までを必須とすること。
