# 管理一覧APIのページサイズ上限(le=100)がフロントのsize=1000要求と不整合で422になる

## 概要

frontend-angular の管理画面を開くと、複数の一覧APIが 422 Unprocessable Entity を返す。
backend が一覧APIの `size`（ページサイズ）を `le=100` に制限しているのに対し、
frontend-angular が「全件取得」目的で `size=1000` を送っているため。

## 説明

- 症状: `GET /api/admin/users?...&size=1000` 等が422（`size=10` 等 100以下なら200 OK）
- 影響API: `users` / `assistants` / `prompt-templates` / `indexes` の一覧
- 移植元(Spring Boot)には `spring.data.web.pageable.max-page-size` の設定が無く、
  デフォルト上限（2000）で `size=1000` が通っていた。FastAPI移植時に `le=100` を付けたのが
  frontend の前提と食い違った過剰制約
- 対処: backend側でページサイズ上限を移植元に合わせて緩和する（frontend-angular は
  動作確認用のため非改変方針）
