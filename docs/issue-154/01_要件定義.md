# 01_要件定義

## 背景

- backend の管理系一覧API（ユーザー・アシスタント・プロンプトテンプレート・インデックス）は
  ページサイズ `size` を `le=100`（上限100）に制限している
- frontend-angular は選択肢の全件取得などの目的で `size=1000` を送るため、上記APIが
  422 Unprocessable Entity を返し、一覧やセレクトボックスが表示されない
- 移植元(Spring Boot)にはページサイズ上限の明示設定が無く、デフォルト上限（2000）で
  `size=1000` が通っていた。FastAPI移植時に `le=100` を付けたことが原因

## 機能要件

- frontend-angular が送る `size=1000` の一覧リクエストが 422 にならず正常に処理されること
- 対象API: `/api/admin/users`・`/api/admin/assistants`・`/api/admin/prompt-templates`・
  `/api/admin/indexes`・`/api/admin/groups` の一覧取得
  （frontend-angular のコードを調査し、`size=1000` を送っている送信先をすべて洗い出した結果）
- ページサイズの下限（`ge`）は現状維持する

## 非機能要件

- 上限は完全な無制限にはせず、移植元のデフォルト上限（2000）以内の妥当な値に設定する
  （極端に大きな `size` によるメモリ負荷を避けるため）

## スコープ外

- frontend-angular 側の変更（動作確認用のため非改変方針）
- ページネーションのレスポンス形式・ソート仕様の変更
- 上記以外のAPIのページサイズ上限の見直し
  （`rooms`・`files`・`libraries`・`library_tags`・`groups` の一部エンドポイントには
  `le=100` が残るが、frontend-angular が `size=1000` を送っている実証がないため対象外とする）
