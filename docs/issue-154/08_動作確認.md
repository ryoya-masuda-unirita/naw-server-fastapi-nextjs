# 08_動作確認

## 確認環境

- `docker compose up -d` で PostgreSQL・Redis・backend・frontend-angular を起動
- DBは develop 相当（alembic=022）にマイグレーション適用済み、`seed.sql` 投入済み
  （テナント3件・ユーザー33件）
- 確認方法: AIエージェントが `curl` でAPIを直接呼び出して確認した

## 確認結果

### Step 1: 修正対象4エンドポイントで `size=1000` が200になること

修正前は全て 422 Unprocessable Entity だったリクエストを、認可済みセッションで実行した。

```
200  GET /api/admin/users?page=0&size=1000&searchText=&role=&sort=updatedAt,desc
200  GET /api/admin/assistants?page=0&size=1000&sort=name,desc
200  GET /api/admin/prompt-templates?page=0&size=1000&search=&sort=name,desc
200  GET /api/admin/indexes?size=1000
```

✅ 4エンドポイントすべてが 200 OK になり、422 が解消した

### Step 2: 上限超過（`size=1001`）は422のままであること

```
422  GET /api/admin/users?size=1001
```

✅ 上限が `1000` に正しく設定されており、超過分は引き続き422で弾かれる

### Step 3: groups API（code-reviewで検出した追加修正分）

frontend-angular が `size=1000` を送るにもかかわらず修正漏れだった `GET /api/admin/groups`
についても確認した。

```
200  GET /api/admin/groups?size=1000  （修正前は422）
422  GET /api/admin/groups?size=1001  （上限超過は引き続き422）
```

✅ groups API も 200 になり、上限超過は422のまま維持されている

### Step 4: frontend-angular のプロキシ経由でも疎通すること

frontend-angular（`localhost:4201`）のプロキシ経由で、実際にfrontendが送るのと同じ
リクエストを実行した。

```
200  GET localhost:4201/api/admin/users?page=0&size=1000&sort=updatedAt,desc
```

✅ frontend-angular が送る `size=1000` の一覧リクエストが正常に処理されるようになった

## 補足

動作確認の過程で、ローカルDBが空（テーブル0件）になっている事象が発生したため、
`alembic upgrade head`（022まで）と `seed.sql` を再投入してから確認を実施した。
本Issueの変更内容とは無関係のローカル環境事象。
