## 実行方式

- Node.js 22.18 以上（型除去で `.ts` を直接実行する）。`node src/cli.ts <コマンド>` を npm scripts から呼ぶ
- import は `.ts` の拡張子付きで書く（`allowImportingTsExtensions`）

## コマンド

| npm script | 内容 |
|---|---|
| `npm run explore:all` | `run`: 環境の起動 → 巡回（全担当範囲または `--shard`）→ まとめ → 環境の破棄（`--keep-env` で残す） |
| `npm run env:up` / `env:down` | 専用環境の起動（マイグレーション・seed・テナント作成まで）/ 破棄 |
| `npm run explore -- --shard <ID>` | 起動済みの環境に対して巡回（`--out` で出力先、`--workers`・`--seed`・`--max-depth`・`--max-actions`・`--max-minutes`） |
| `npm run merge -- --out <dir>` | 出力先の担当範囲ごとの結果を 1 つにまとめ直す |
| `npm run shards` | 担当範囲の一覧（ID・まとまり・権限・起点・範囲・テナント） |
| `npm run lint` / `typecheck` / `test` | ESLint / tsc / Playwright Test |

## 設定（explorer.config.json）

| キー | 内容 | 既定 |
|---|---|---|
| `target.baseUrl` | frontend の URL | `http://localhost:55173` |
| `target.apiUrl` | backend の URL（API の判定・遅さの対象） | `http://localhost:58000` |
| `target.loginPath` | ログイン画面のパス | `/auth/login` |
| `limits.maxDepth` / `maxActions` / `maxActionsPerState` / `maxMinutes` | 担当範囲ごとの上限 | 3 / 120 / 40 / 10 |
| `workers` | 並列数 | 4 |
| `seed` | 乱数の種 | 1 |
| `timing.settleQuietMs` / `settleTimeoutMs` / `navigationTimeoutMs` | 落ち着いたとみなす無通信時間・待つ上限 | 400 / 8000 / 15000 |
| `oracle.slowResponseMs` / `slowActionMs` | 遅いとみなすしきい値 | 3000 / 5000 |
| `oracle.axeImpacts` | 記録する axe の重大度 | `critical`・`serious` |
| `oracle.viewports` | 表示崩れを見る画面幅 | desktop 1280x800・mobile 375x812 |
| `oracle.expectedHttp` | 想定内とする 4xx（`method`・`path`・`status`・`pagePath`（応答を受けたときの画面のパス）・`onlyAfterAbnormalInput`） | 認証画面（`^/auth/`）での `GET /api/auth` の 401（ログアウト後の画面も含めるため、権限ではなく画面のパスで判定する）、異常値送信直後の 400・401・403・422・429 |
| `oracle.placeholderMarkers` | 画面の文字にこれが含まれたら未移植の仮画面として扱う | `未移植: ` |
| `oracle.ignoreConsole` | 無視するコンソールのメッセージ（正規表現） | `Failed to load resource`・`[API] Forbidden:` など 4xx の API ログ（HTTP の判定で拾うため。5xx は無視しない） |
| `crawl.inputKinds` | 入れる値の種類 | 全種類 |
| `crawl.defaultMaxLength` | maxlength がない欄の「最大」 | 255 |
| `crawl.dialogs` | ダイアログへの応答 | `accept` |
| `crawl.excludeSelectors` | 操作しない要素 | `[data-e2e-explorer-skip]` |
| `crawl.sharedRegions` / `sharedRegistryPerRole` | 共通領域・権限ごとに分けるか | `aside, header, nav, [role=navigation]` / false |
| `roles.<名前>` | `anonymous`（ログインなし）または `loginId`・`password`・`sourceTenantId`・`description` | anonymous / admin / user |
| `groups[]` | `id`・`description`・`startPath`・`include`（正規表現）・`roles` | 9 つ（02 を参照） |
| `environment.composeFile` / `projectName` | 専用環境 | `docker/compose.yml` / `naw-e2e-explorer` |

環境変数 `E2E_EXPLORER_BASE_URL`・`E2E_EXPLORER_API_URL` で対象 URL を上書きできる。設定ファイルの場所は `--config` で変えられる。

## 主な型（types.ts）

- `ActionDescriptor`: `{ kind: 'click' | 'fill-submit' | 'fill-enter' | 'select' | 'toggle', target: ElementRef, region?: string, values?: FieldValue[], inputKind?: string, label: string }`
- `ElementRef`: `{ signature: string, occurrence: number }`
- `Step`: 再現手順の 1 行（`description` と `action`）
- `Finding`: `{ kind, severity, title, location, message, fingerprint, shardId, role, steps, screenshot?, trace?, details }`
- `ShardReport`: 担当範囲の結果（統計・疑い・担当外・再生失敗）
- `MergedReport`: まとめた結果（`groups[]`: 同じ指紋の疑いと発生回数・担当範囲・権限）

## 巡回役（crawler.ts）

```
crawlShard(browser, config, shard, { outDir, registry, prepareContext? })
  context を作る（画面幅 desktop、ダイアログは設定どおり、trace を開始）
  prepareContext（テスト用の route など）
  権限がログインありなら auth.login（ログイン画面に入力 → sessionStorage を控え、以後の新しいタブに復元する init script を入れる）
  待ち行列 = [{ path: [], depth: 0 }]、訪問済み = {}
  while 待ち行列 and 上限内:
    node = 先頭
    page = replay(node.path)  // 新しいタブ → 起点 → 操作の再生
    root なら起点の読み込みを「観測する操作」として判定する
    key = 状態のキー; 訪問済みなら閉じて次へ
    状態の判定（真っ白・表示崩れ・axe）
    操作の候補 = 列挙 → 除外 → 種と key で並べ替え → 1 状態あたりの上限
    閉じる
    for 操作 in 候補:
      共通領域なら registry.claim(キー) に失敗したら飛ばす
      page = replay(node.path) → oracle.begin → 操作 → 落ち着くまで待つ → oracle.end
      担当外の URL なら記録して終わり。範囲内で深さが上限未満なら待ち行列へ
      疑いがあればスクリーンショット・trace を保存
  ShardReport を書き出す
```

- ログインした状態のはずが、起点を開いたらログイン画面だった（ログアウト操作の後など）ときは、ログインし直す。ログアウトのたびに要るため合計の回数には上限を付けず、ログインし直しても起点がログイン画面のままが 3 回続いたら止める
- ログイン直後はアプリが `window.location.href` で画面ごと遷移するため、sessionStorage は読み込みの完了を待ってから読む（遷移中に読むと評価の文脈が壊れて失敗する）
- 起点を開けなかったら、疑い 0 件と区別できるよう担当範囲ごとエラーで止める
- 操作が途中で失敗（要素が消えた・押せない）しても、それまでに起きた疑いは記録する（失敗の原因が 500 などのことがあるため）
- 担当範囲の開始時に、その担当範囲が前に取った共通の領域のキーを手放す（同じ出力先での流し直しのため）。操作に失敗した共通の領域のキーも手放す
- 出力先・コンテキストの作成の失敗も担当範囲のエラーとして記録する（並列実行の他のワーカーを止めないため）
- フォームの送信では、欄は 1 回の列挙で探し、送信の前に列挙し直してフォームと送信ボタンを探す（要素の番号は列挙ごとに振り直されるため）
- 時間の上限を過ぎても応答のない待ちで止まっている担当範囲は、さらに 60 秒でコンテキストを閉じて打ち切る（ウォッチドッグ）
- 操作の順番: 種と状態のキーから作った乱数で並べ替える
- trace は、タブごとに chunk を切り、新しい疑いが出たときだけ保存する

## 判定役（oracle.ts）

- `attach(page)` で通信・コンソール・例外のイベントを受け、`begin(observation)` 〜 `end()` の間に起きたものだけを疑いにする（再生中に起きたものは、前の操作の疑いとして既に記録済みのため）
- `end()` で真っ白・何も起きない・戻れない・遅い操作を判定し、疑いと操作後の要素の一覧を返す。要素の列挙は目印の属性を書き換えて DOM の変化に数えられるため、変化の数を読んでから列挙する
- 上限まで待っても通信が落ち着かなかった操作（定期的な問い合わせのある画面など）は、遅い操作の判定をしない
- 無通信の時間は操作の開始から数える（直前の通信からだと、操作の直後に起きる例外を待たずに終わるため）
- API の応答時間は `request` から `requestfinished` までを自分で測る（route で返した応答などは `request.timing()` に値が入らないため）
- `inspectState(page)` で表示崩れ（画面幅ごと）・axe・真っ白を判定する
- 指紋は `種類 | 場所 | 正規化したメッセージ`（UUID・数字・URL のクエリを除く）

## 調査済みの一覧（shared-registry.ts）

- `SharedRegistry(file)` の `claim(key, owner)`: 持ち主の印（token）を入れたディレクトリを一時名で作り `<file>.lock` へ付け替えて排他し、JSON を読んで未登録なら追記して true。`release(key, owner)`・`releaseOwner(owner)` で手放す
- 古い（30 秒）ロックは、自分だけの名前に付け替えてから古さを確かめて消す（新しいロックを誤って消さないため）。ロックを外すときは自分の印のロックだけを消す
- 呼んだワーカーごとに取れた数・飛ばした数を数える

## 並列（scheduler.ts）

- Chromium を 1 つ起動し、ワーカー数ぶんの非同期の処理が担当範囲の待ち行列から順に取って `crawlShard` を呼ぶ（担当範囲ごとに別のブラウザのコンテキスト）
- すべて終わったら report.merge でまとめる

## 専用環境（environment.ts / tenant-sql.ts / docker/compose.yml）

- compose のサービス: `postgres`（55432）・`redis`（56379）・`migrate`（backend のイメージで `alembic upgrade head`）・`seed`（postgres のイメージで `psql -f seed.sql`）・`backend`（58000）・`frontend`（55173）
- `env:up`: `docker compose -p naw-e2e-explorer -f docker/compose.yml up -d --build --wait backend frontend` → `docker compose exec -T postgres psql` に tenant-sql の SQL を流す
- `env:down`: `docker compose ... down -v --remove-orphans`
- tenant-sql: `CREATE TEMP TABLE ... AS SELECT * FROM tenants WHERE id = <元>` で写して ID・名前を変えて入れる。ユーザーは ID を `md5(テナント||ログインID)` から作り（毎回同じ）、パスワード履歴の最新 1 件を写す。すでにあれば何もしない

## レポート（report.ts）

- 担当範囲ごと: `<out>/shards/<ID>/shard-report.json` とスクリーンショット・trace
- まとめ: `<out>/report.json`・`report.md`・`report.html`
- 並びは重大度（高 → 低）→ 種類 → 場所
- HTML は外部の読み込みなしの 1 ファイル。文字はすべてエスケープする

## 仕分けのスキル

`.claude/skills/e2e-explorer-triage/SKILL.md`: レポートの読み方 → 疑いごとに再現・コードとの照合（frontend・backend・移植元）→ 判定（バグ / 仕様どおり / 未移植 / ハーネスの誤検知）→ Issue の文案（起票先は `--repo ryoya-masuda-unirita/naw-server-fastapi-nextjs`）→ 起票は人が判断。
