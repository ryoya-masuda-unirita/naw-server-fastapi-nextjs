# 08_動作確認

ブラウザ・実機（Waha!・実際の LLM）での確認は行わず、**自動テストと、Docker 上の echo プロバイダでの通しの確認だけ**で代替した。以下は実際に実行した出力。

## 確認環境

- macOS（Apple Silicon）、Python 3.12、uv 0.11、Docker（OrbStack 相当）
- 実際の LLM・Azure OpenAI には接続していない（OpenAI・Azure・SecuAiGent の HTTP はテストで `respx` によりモック）
- ブランチ: `feature/issue-298`

### 4. Docker で server-local → エミュレーター → アダプタ

`generative-ai-adapter/README.md` の手順どおり、エミュレーター（アダプタを含めてビルド）と server-local のコンテナを起動し、server-local の NAW 互換 SSE（`POST /api/messages/content`）を叩いた（ポートは 8091・8090 の代わりに 18091・18090、`WAHA_WORKFLOWS_FILE=/app/config/workflows.example.json`、`LLM_PROVIDER` は既定の echo）。

通常チャット（アシスタント ID `gpt-4o` = 既定の定義。履歴 2 件付き。質問は「こんにちは、通しの確認です」）の応答:

```
data:{"type":"reasoning_delta","text":"こんにちは、通し"}
data:{"type":"reasoning_delta","text":"の確認です"}
data:{"type":"text_delta","text":"こんにちは、通しの確認です"}
data:{"type":"message_stop","inputTokens":0,"outputTokens":0}
data:{"type":"message_content","data":{"id":"…","messageId":"m-1","status":"OK","question":"こんにちは、通しの確認です","answer":"こんにちは、通しの確認です","context":null,"attachmentFiles":[],"referencePaths":null,"isRated":false}}
```

アダプタが書いた途中経過（`reasoning_delta`）が server-local の SSE にそのまま届き、回答は出力ファイルから確定している。このときのエミュレーターのログ（部品の流れ。`generative-ai-adapter/README.md` に説明付きで載せている）:

サービス ID ごとの設定（`config/workflows.example.json`）の確認:

- `assistantId=echo-rag`（出力モード 1。RAG Context JSON を読む）: 回答が返り、`context` に `RAG_CONTEXT_BEGIN id=chunk-0003 source=travel-expense-policy … RAG_CONTEXT_END` の囲みが、`referencePaths` に `/docs/policies/travel-expense.md` が入った。ログは `write: route=rag` → `RAG Context JSON: allowRoot=True` → `executeLLMWithContext: messages=4, contexts=1` → `core rag: provider=Echo, messages=4, contexts=1` → `echo rag: contexts=1` → `core rag finished: answerPresent=True, answerChars=11, referenceIds=[1]` → `output written` の順
- `assistantId=echo-plain`（出力モード 2。本文だけを出力）: エミュレーターは回答の本文だけを書く。server-local は outputfile を JSON として読むため `RetrievalAnswer` の検証エラーで SSE がエラーになった。これは設定の意図どおり（server-local 向けではなく、エミュレーターの API を直接呼ぶ確認用）で、`generative-ai-adapter/README.md` に書いた

確認後、コンテナは `docker compose down` で停止し、確認用の `.env`・`data/` は削除した。
