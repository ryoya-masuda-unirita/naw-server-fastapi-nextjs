# 01_要件定義

## 背景

移植元のモノレポには、Waha!（ユニリタの ETL 製品）に組み込む生成AIアダプタがある。Waha! 本体はどちらのリポジトリにもなく、#274 で Waha! の代わりのエミュレーターを作ったが、そのワークフローは「質問を LLM に 1 回渡して回答を返す」仮のチャットだった。

SECURE アシスタントのチャットを移植元と同じ振る舞いで通しで動かすには、仮のチャットを、移植元の生成AIアダプタの移植に置き換える必要がある。生成AIアダプタは、共通の実行基盤（core）を呼ぶ構造になっており、core には他のアダプタ（埋め込み・検索）も使うプロバイダ・ネットワークの部分が含まれる。

## 機能要件

1. **移植の単位**: 移植元と同じ 4 つの分け方（core・生成AIアダプタ・埋め込みアダプタ・検索アダプタ）の Python パッケージをルートの専用ディレクトリに置く。今回は core のチャット・プロバイダ・ネットワークの部分と生成AIアダプタを移植し、埋め込み・検索は後続に回す
2. **通常チャット**: 出力モード 0（チャット用_回答）・2（回答）の経路。質問・システム・アシスタント・添付ファイル・会話履歴を列として受け取り、メッセージを組み立てて core に任せる。出力モード 2 は回答本文だけ、0 は `RetrievalAnswer` の JSON を出力ファイルに書く
3. **RAG 回答**: その他の出力モード（1）。旧来の入力（コンテキストのパス・本文）と、RAG コンテキスト JSON（契約 v1）の両方を受け取る。検索アダプタの出力が契約どおりであれば、同じ回答処理に渡せること。入力が足りないとき・回答が存在しないコンテキストを参照したときは、原因を示す文言を回答として出力し、LLM を呼ばない（または結果を捨てる）
4. **プロバイダ**: 移植元にあるもの（OpenAI・Azure OpenAI・SecuAiGent）が動く。Anthropic・VertexAI・GoogleAIStudio は移植元と同じ「未対応」の失敗を返す。SecuAiGent はクラウドの `/api/llm/chat` を呼び、ログイン（loginKey → JWT）、SSE の解析、推論・ライブラリ生成の途中経過の受け取りを行う
5. **textData と tools**: SecuAiGent の textData（JSON）の項目（accessToken・messageId・createLibrary・tools・deployName・temperature など）で資格情報・生成パラメータを上書きできる。tools はプロパティ・tools JSON・textData の順で解決し、通常チャットかつ SecuAiGent のときだけ許す。不正な textData・tools は固定の失敗として出力する
6. **途中経過**: 推論・ライブラリ生成の差分を、指定されたファイルに追記する（移植元と同じ書式）。ファイルは作らず、書き込みに失敗したら回答を書かない
7. **ネットワーク**: プロキシ（手動・システム）・SSL 検証の無効化・タイムアウトを、プロバイダの通信に適用する
8. **エミュレーターへの差し込み**: 仮のチャット用ワークフローを、移植したアダプタを呼ぶものに置き換える。サービス ID ごとにアダプタの設定（出力モード・プロパティ）を決められる。入力スロットと execute のパラメータは、本物の Waha! のジョブと同じ対応でアダプタの列・プロパティになる
9. **追跡**: チャット 1 回でどの部品がどの順に何を受け取り何を返したかを、INFO のログで追える。秘密情報（API キー・トークン・本文のパス）はログに出さない
10. **確認用**: キーなしで動く確認用のプロバイダを残す（質問をそのまま返す）

## 非機能要件

- 実際の LLM・外部サービスには接続しない自動テストで動作を確認する（HTTP はモック）
- 移植元の Java のテストのうち今回の範囲に当たるものを Python のテストとして移し、振る舞いを揃えた根拠にする
- Docker で、server-local → エミュレーター → アダプタを通して動く
- 既存の server-local・エミュレーターのテストが通り続ける
- 追加・変更するすべての関数・メソッド・クラスに NumPy 形式（日本語）の docstring を書く

## スコープ外

- 埋め込みアダプタ・検索アダプタの移植（RAG の検索結果は、入力の RAG コンテキスト JSON で代える）
- PDF・Word・Excel・PowerPoint のファイル前処理（テキスト・画像のみ。ほかは未対応の失敗）
- ログのファイル出力（環境変数で出力先を決める移植元の仕組み）、HTTP クライアントのテスト接続用の経路
- 本物の LLM への接続の確認
- 学習・学習データの同期・削除のワークフロー
