# 04_テスト設計

## テスト方針

- 実際の LLM・外部サービスには接続しない。プロバイダへの HTTP はモックし、送ったリクエスト（URL・ヘッダー・本文）と返した結果を確かめる
- 移植元の Java のテストのうち今回の範囲に当たるものを移し、同じ入力に同じ出力が返ることを根拠にする。Spring の内部を見るテストは、送信する HTTP リクエストを見るテストに置き換える
- 移植元のテストにない Python 版だけの部分（確認用プロバイダ・MIME 判定・ワークフローの設定とジョブの組み立て）は、新しくテストを書く
- server-local・エミュレーターの既存のテストが通り続けること。エミュレーターは server-local の実物の Waha! クライアント・SSE・同期 API から呼ぶ結合テストで、アダプタ経由でも同じ契約が守られることを確かめる

## 観点

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 失敗のサニタイズ | 認証情報・トークン・URL・キーを含む文言 | 秘密は伏せ字になり、空は `Runtime failure.` |
| 2 | chat・RAG ランタイム | プロバイダが例外・結果なし・成功 | 例外は失敗の結果になり、成功はそのまま返る |
| 3 | リクエストの正規化 | 空白・空・属性・ツール・コールバック | 移植元と同じ正規化。変更できない値は変更できない |
| 4 | ネットワーク設定 | プロキシ（なし・手動・システム）・SSL 無効・タイムアウトの範囲 | 範囲外は検証失敗。HTTP クライアントに設定が当たる |
| 5 | プロバイダ表 | 名前・別名・vendorId・未知 | 正しく引け、未知は失敗 |
| 6 | プロバイダの未対応 | Anthropic・VertexAI・GoogleAIStudio | 理由付きの未対応の失敗。tools があれば tools 用の失敗 |
| 7 | OpenAI・Azure の送信 | 通常 chat・画像・生成パラメータ・RAG | URL・認証ヘッダー・API バージョン・既定の temperature・メッセージ・応答形式が移植元どおり。RAG は回答と検証の 2 回 |
| 8 | RAG 回答の判定 | 参照 ID の表記・重複・範囲外・検証の真偽 | 条件を満たすときだけ回答あり。ほかは回答なし |
| 9 | SecuAiGent のリクエスト | 生成オプション・ライブラリ・tools・添付 | textData の項目・順序が移植元どおり。不正な承認設定は失敗 |
| 10 | SecuAiGent の SSE・ログイン | 各種イベント・途中で切断・HTTP エラー・不正な JSON | コールバックの呼び出し順、成功・失敗の分類（SSL・検証・タイムアウト・認証・ネットワーク）が移植元どおり。要約に秘密を出さない |
| 11 | SecuAiGent の textData 読み込み | 許可されないキー・型・範囲・重複・Bearer・tools | 不正はすべて固定メッセージの失敗。正しいものは読める |
| 12 | 前処理 | テキスト・画像・空・存在しない・未対応の形式・画像説明の失敗 | 移植元と同じコードの失敗。画像説明は説明文を本文にする |
| 13 | MIME 判定 | PNG・JPEG・GIF・WebP・PDF・ZIP/OOXML・拡張子・テキスト・バイナリ | 期待する MIME |
| 14 | 値オブジェクト・列挙 | 役割番号・RAG 入力不足・リクエストの組み立て・各列挙の値の変換 | 移植元どおり |
| 15 | プロパティの検証・設定 | URL・キー・出力先・プロキシ・数値・タイムアウト・空・null・必須不足・未対応のベンダー | 移植元のメッセージで失敗。任意の空は無視 |
| 16 | 列 → リクエスト | ユーザー・システム・アシスタント・ファイル・履歴・旧 RAG（パス・本文） | メッセージの順序（履歴が先頭）・画像説明の追記・入力不足の判定 |
| 17 | RAG Context JSON | 正常・上限・未知項目・graph の食い違い・path の形・印・パスの外・リンク | 正常は囲みに変換され、不正は固定の失敗で旧経路へ戻らない |
| 18 | textData・tools の解決 | textData の上書き・ライブラリ生成オフ・messageId・streamfilepath の優先・tools の優先順位・不正 | 移植元どおりに解決され、不正は provider を呼ぶ前に固定の失敗として出力 |
| 19 | 途中経過ファイル | 書式・順序・flush・開けない・再試行・期限・書き込み失敗・close の失敗 | 1 行ずつ追記。固定のコードで失敗。回答は書かれない |
| 20 | controller の出力 | 通常 chat・RAG・回答なし・参照 ID 範囲外・入力不足・tools の失敗・出力モード 2・画像説明 | 出力ファイルの内容（JSON の項目順・省略・本文だけ）が移植元どおり。例外メッセージは 512 文字まで |
| 21 | ワークフローの設定 | 名前 → ID・ベンダー名・環境変数・予約・未知・出力モード・既定・ファイルの読み込み | 不正は起動時のエラー。正しければ定義になる |
| 22 | ワークフローのジョブ | スロット → 列・プロパティ・許可ディレクトリ・質問なし・echo での通し・RAG・Azure の HTTP（モック）・失敗 | 期待する列・プロパティ・出力。アダプタの失敗は決まった接頭辞の失敗 |
| 23 | HTTP 経由・結合 | server-local の WahaClient・SSE（NAW 互換・旧形式）・同期 API・遅い LLM・LLM の失敗 | 回答が返る。途中経過が複数に分かれて届く。失敗は SSE のエラー |
| 24 | docstring | 追加・変更したすべての関数・メソッド・クラス | NumPy 形式で書かれている（静的検査で違反 0） |
