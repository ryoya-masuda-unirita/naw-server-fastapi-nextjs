# 01_要件定義

## 機能要件
- `github_repository` の既定値を、現在のリポジトリ名（`ryoya-masuda-unirita/secuaigent-fastapi-react`）にする
- CI（`deploy-infra.yml`）の Plan・Apply が、`github_repository`（実行中のリポジトリ名）と、`enable_github_actions_infra_role`（GitHub の Variable `ENABLE_GITHUB_ACTIONS_INFRA_ROLE`。未登録は false）を、Terraform に渡す。ローカルで infra 用ロールを作ったあとの CI の plan が、使用中のロールを削除しない
- `environments/dev/main.tf` に `required_version = ">= 1.10"`（`use_lockfile` の下限）を足し、bootstrap も揃える
- `terraform.tfvars.example` に、`enable_github_actions_infra_role`・`github_repository` を示す。README に、Variable の設定を書く

## 非機能要件
- `terraform fmt -check`・`terraform validate`（dev・bootstrap）が通る
- 既存のリソースを変えない（既定値の変更は、OIDC の信頼条件の文字列にだけ影響する）

## スコープ外
- 実際の `terraform apply`（AWS の資格情報が要る）。AWS 側のロールが、すでに旧名で作られているなら、apply で信頼条件が更新される（apply は、利用者が行う）
- 手元の `terraform.tfvars` の整理（git 管理外）
