# 01_要件定義

## 背景

アシスタントカテゴリの更新 API が、移植元（Spring Boot）と次の 2 点で違う（#281 の code-review で検出し申し送り）。

1. 説明を省略・空にして更新すると、backend は説明を空（null）で上書きする。移植元は空白でない値が来たときだけ説明を上書きし、それ以外は元の説明を残す
2. 同じテナントに同名のカテゴリがあると、backend は独自に事前チェックして 400 を返す。移植元は事前チェックをせず、DB の一意制約（テナント ID と名前の組）の違反になる

## 機能要件

### 更新 API

- 説明が空白でない文字列のときだけ説明を上書きする。省略・null・空文字・空白だけのときは元の説明を残す（移植元と同じ）
- 名前は従来どおり上書きする（入力チェックで空白だけの名前は 400 で弾かれるため、移植元の「空白でなければ上書き」の判定は常に真になる）
- 同名の事前チェックをやめ、DB の一意制約の違反は移植元と同じく 500 にする

### 作成 API

- 作成にも同じ同名の事前チェック（400）がある。移植元の作成処理にも事前チェックはなく、一意制約の違反で 500 になる。作成・更新で挙動をそろえるため、作成の事前チェックもあわせて外す（判断理由は 02 に記載）

## 非機能要件

- DB スキーマは変えない（一意制約は既にある）。マイグレーションは不要

## スコープ外

- 一意制約の違反時の応答本文の形（移植元は Spring Boot 既定のエラー本文、backend は FastAPI 既定の本文）。移植元のクライアントは状態コードで失敗を判定して汎用のエラー表示を出すだけで本文を読まないため、そろえない
- ライブラリタグ・ユーザーなど他の API の同名チェック
