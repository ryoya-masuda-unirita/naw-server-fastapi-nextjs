# 04_テスト設計

## テスト方針

正規化処理は単体テストで表記ごとの結果を確認し、各 API は結合テスト（インメモリ SQLite）で、応答と DB の状態（削除されたか・どの形式で付与されたか）を確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 正規化（1 件） | ハイフンなし 32 桁 | そのまま返る |
| 2 | 正規化（1 件） | ハイフン付き標準形式・大文字 | ハイフンなし 32 桁の小文字になる |
| 3 | 正規化（1 件） | `urn:uuid:` 形式・波括弧・桁不足・16 進以外・空文字 | 不正（`None`） |
| 4 | 正規化（一覧） | 表記の混在した一覧 | 順序を保って保存形式になる |
| 5 | 正規化（一覧） | 不正な形式を含む | 400・`Invalid UUID string: <値>` |
| 6 | 一括削除 | 保存形式の ID 2 件 | 204・2 件とも削除される |
| 7 | 一括削除 | ハイフン付きの ID | 204・削除される |
| 8 | 一括削除 | 大文字のハイフン付きの ID | 204・削除される |
| 9 | 一括削除 | 形式は正しいが存在しない ID を含む | 204・存在するものだけ削除される |
| 10 | 一括削除 | 他テナントのタグの ID（ハイフン付き） | 204・他テナントのタグは削除されない |
| 11 | 一括削除 | 不正な形式の ID を含む | 400・メッセージが `Invalid UUID string: <値>`・1 件も削除されない |
| 12 | 一括削除 | 非管理者 | 403（変更なし） |
| 13 | ライブラリ更新 | ハイフン付きのタグ ID | 200・タグが保存形式で付与される |
| 14 | ライブラリ更新 | 同じタグを保存形式と大文字のハイフン付きで指定 | 200・1 件だけ付与される |
| 15 | ライブラリ更新 | 形式は正しいが存在しないタグ ID | 400・`指定されたタグが存在しません` |
| 16 | ライブラリ更新 | 他テナントのタグ ID（ハイフン付き） | 400・`指定されたタグが存在しません` |
| 17 | ライブラリ更新 | 不正な形式のタグ ID | 400・`Invalid UUID string: <値>`・タイトル・タグは変わらない |
| 18 | ライブラリ更新 | 不正な形式のタグ ID を所有者以外が指定 | 403（所有者の確認が形式の確認より先） |
| 19 | 回帰 | ライブラリタグ更新 API（#227）の既存テスト | すべて通る |
| 20 | 回帰 | テスト全件・mypy・ruff | すべて通る |
