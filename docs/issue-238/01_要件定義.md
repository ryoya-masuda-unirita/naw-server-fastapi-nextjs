# 01_要件定義

## 背景

ライブラリタグの ID は、データベースにハイフンなしの 32 桁の 16 進文字列（小文字）で保存している。#227 でライブラリタグの更新 API は、ハイフン付きの UUID 標準形式でも同じタグに当たるようにした。しかし次の 2 か所は、受け取った ID を保存値とそのまま比べているため、ハイフン付きの ID が一致しない。

- ライブラリタグの一括削除 API: ハイフン付きの ID は一致せず、エラーにならないまま削除されない（応答は 204）
- ライブラリの更新 API のタグ指定: ハイフン付きの ID は「存在しないタグ」とみなされ 400 になる

移植元は、どちらも ID を UUID として読み取るため、ハイフン付きで動く。

## 機能要件

1. ライブラリタグの一括削除 API は、ID をハイフンなし 32 桁・ハイフン付き UUID 標準形式のどちらで指定しても、該当するタグを削除する。大文字小文字は区別しない
2. 一括削除 API で、UUID として解釈できない形式の ID が 1 件でも含まれる場合は、移植元と同じく 400 を返し、1 件も削除しない
3. 一括削除 API で、形式は正しいが存在しない ID（他テナントの ID を含む）は、これまでどおり無視する（204）
4. ライブラリの更新 API のタグ指定は、ハイフンなし 32 桁・ハイフン付き UUID 標準形式のどちらでも同じタグを付与できる。大文字小文字は区別しない。付与したタグは保存形式で保存する
5. ライブラリの更新 API で、同じタグを別の表記（ハイフンあり・なし、大文字・小文字）で重複して指定しても、1 件として扱う（移植元は UUID に変換してから重複を除く）
6. ライブラリの更新 API で、UUID として解釈できない形式のタグ ID は、移植元と同じく 400 を返す。形式は正しいが存在しないタグ ID は、これまでどおり 400（`指定されたタグが存在しません`）
7. ライブラリタグの更新 API（#227）の挙動は変えない（不正な形式は 404 のまま）

## 非機能要件

- 受け付ける ID の表記は #227 と同じく 2 形式（ハイフンなし 32 桁・UUID 標準形式 8-4-4-4-12）に限る。正規化の処理は 1 か所にまとめ、ライブラリタグ API とライブラリ API の両方から使う
- DB のマイグレーションは行わない（保存形式は変えない）
- エラー応答の形式は #228 で揃えた形（`timestamp`・`message`）のまま

## スコープ外

- ライブラリの作成でのタグ指定: 移植元のライブラリ作成 API はタグを受け取らず、このリポジトリのライブラリ作成（チャットの応答からの作成）もタグを受け取らないため、対象が無い
- ライブラリ一覧のタグ絞り込み: #173 で両形式を受け付けており、不正な形式は 400 になっている（変更しない。詳細は `02_基本設計.md` の横展開）
- ライブラリタグの更新 API で不正な形式を移植元のように 400 にすること（#227 で 404 を維持すると決めたため）
- 移植元が受け付ける、桁を詰めた表記（例: `1-2-3-4-5`）を受け付けること（#227 と同じく 2 形式に限る）
