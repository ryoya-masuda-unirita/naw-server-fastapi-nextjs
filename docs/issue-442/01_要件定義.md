# 01_要件定義

## 機能要件

1. `messages (tenant_id, room_id)` の索引を、マイグレーションで足すこと（一覧・外部キー `fk_messages_room_id` の探索。どちらも両方の列の等価条件）
2. `messages (parent_id)` の索引を、同じマイグレーションで足すこと（要判断。推奨は足す。理由は、削除の遅さの原因が `parent_id` で、`(tenant_id, room_id)` だけでは、削除は変わらないため）
3. ダウングレードで、両方の索引を消せること
4. 既存のデータ・挙動・API は変えないこと（索引の追加のみ）。モデルにも同じ索引を宣言すること

## 非機能要件

- 普通の `create_index`（既存・#433 と同じ。`CONCURRENTLY` は使わない）。作成の間、`messages` への書き込みが待たされる
- 費用: なし

## スコープ外

- `messages` 以外の、索引のない外部キー（`libraries.message_id`・`token_usages.message_id`・`message_files` など）。必要なら、別の Issue（今回、`libraries.message_id` などの削除への影響は未計測）
- 実環境への適用
