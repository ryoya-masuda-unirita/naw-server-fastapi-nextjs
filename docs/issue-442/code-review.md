## 詳細

### 1. 書き込みの待ち（対応しない）
`CONCURRENTLY` を使うかは、#433 と同じく、第 1 承認で「使わない（既存のマイグレーションに合わせる）」と決めている。作成の間の待ちと、利用が少ない時間帯に適用することを、docstring・PR に書いている。所要時間は未計測。

### 2. `assistant_id`（対応しない）
正しい指摘。`fk_messages_assistant_id` は `ON DELETE SET NULL` で、アシスタントの削除のたびに `messages` を `assistant_id` で探す。この PR は、計測した 2 つ（一覧の絞り込み・`parent_id` の削除）に絞っている。アシスタントの削除の頻度は、メッセージの削除より、ずっと低いと見ているが、確認していない。`08` に、未計測・スコープ外と明記した。

### 3. 一意性の確認（対応済み）
モデルの索引が、一意でないことも、テストで確かめるようにした。順序（`ASC`・`DESC`）は、どちらも既定のまま。

### 5. 書き込みの負荷（対応しない）
索引が増えると、INSERT・UPDATE が、索引の更新のぶん、わずかに遅くなる。`messages` は、1 回の質問で 1 行の INSERT で、索引は 3 本（主キーを含む）から 5 本になる。計測していないことは、PR に明記している。
