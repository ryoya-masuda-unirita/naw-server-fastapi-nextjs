# 01_要件定義

> **状態: BLOCKED（バックエンドのみでは対応できない）**
> 調査の結果、バックエンドはすでに移植元（Spring Boot）の API 仕様どおりの応答を返しており、不具合の原因はリポジトリ内の `frontend-angular/`（上流 `secuaigent/client` の古いコピー）側にある。上流 client では同じ不具合が NAW-1290 で修正済みのため、`frontend-angular/` の同期で解消する見込み。本 Issue ではバックエンドの変更を行わない。

## 背景

学習データファイルの一覧・編集画面で「リンク時の表示名」が常に空欄になり、編集モーダルで必須チェックに引っかかって保存できない。

## 調査結果

### 移植元（Spring Boot）の API 仕様

- `FileResponse` はファイルの内部名を `@JsonProperty("fileName")` で `fileName` として返す（`name` という項目は返さない）
- バックエンド（FastAPI）の `FileResponse` も `fileName` で返しており、移植元と一致している

### `frontend-angular/`（リポジトリ内のコピー）

- 一覧の変換処理が `row.name` を読み、編集フォームの「リンク時の表示名」を `file.name`（必須）で初期化している
- 移植元 API は `name` を返さないため、移植元に接続しても同じく空欄になる。つまりバックエンドの移植不備ではなく、画面側の不具合

### 上流 client（`secuaigent/client`、develop 最新）

- NAW-1290「管理者画面 学習データ、リンク時の表示名が表示・更新されない」（コミット `bb030f6b`、2026-08-17）で、この不具合が画面側で修正済み
  - 画面の項目から `name` を削除し、「リンク時の表示名」を `reference`（参照）として扱うよう変更
  - 編集フォームは `displayName`・`reference` で初期化し、どちらもバックエンドの `FileResponse` が返す項目
- リポジトリ内の `frontend-angular/` は NAW-1290 適用前のコピーのまま

## 対応方針（本 Issue の外で行う）

- `frontend-angular/` を上流 client と同期する（`frontend-angular-sync` skill）。同期後は「リンク時の表示名」に `reference` が表示され、編集も保存できる見込み
- 同期後の関連事項
  - 画面は編集（PATCH）の項目をクエリパラメータで送るため、#176（PR #209）のバックエンド修正が必要
  - 上流 client はファイル追加時に `name` を送らないため、追加は 400 になる（移植元でも `files.name` が NOT NULL のため失敗する。#176 の PR に記載）

## スコープ外（採用しなかった案）

- バックエンドの `FileResponse` に `name` を追加する、または `fileName` を `name` に変更する案は、移植元の API 仕様から外れるうえ、上流 client は「リンク時の表示名」に `name` を使わなくなっており（`reference` を使う）不要なため採用しない
- `frontend-angular/` の個別修正は、作業ルール（`frontend-angular/` は上流のコピーであり変更しない）により行わない
