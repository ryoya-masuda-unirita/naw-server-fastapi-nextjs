# 04_テスト設計

## テスト方針

本チケットは開発ツール・CI設定の追加であり、新規のpytestテストコードは追加しない。動作確認はローカルでの`pre-commit`実行結果とGitHub Actions上の実行結果を確認する形で行う。

## 確認ケース一覧

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | `ruff format --check .`・`ruff check .`を実行する | 指摘0件になる（クリーンアップ済みのため変化なし） |
| 2 | 既存の全pytestテストを実行する | 回帰なく全件成功する |
| 3 | `uv run pre-commit install`実行後、フォーマット崩れ・未使用importを含むファイルをステージしてコミットする | `pre-commit`フックが自動修正し、そのコミットが失敗する |
| 4 | ケース3の直後に`git add`し直して再度コミットする | 修正済みの内容でコミットが成功する |
| 5 | ケース4のコミットをpushする | `git ls-remote`で確認したリモートの内容が、修正済みの内容と一致する |
| 6 | 修正の必要がないクリーンな状態でコミットする | フックが何もせずコミットが成功する |
| 7 | `feature/issue-34`ブランチへのプッシュ後 | GitHub Actionsで既存の`lint`ジョブが成功する |

## 既存テストへの影響確認

- `pyproject.toml`・`.pre-commit-config.yaml`の追加はアプリケーションコードの動作に影響しないため、全体テスト（`pytest`）が回帰なく通ることを確認する
