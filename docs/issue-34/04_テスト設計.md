# 04_テスト設計

## テスト方針

本チケットは開発ツール・CI設定の追加であり、新規のpytestテストコードは追加しない。動作確認はローカルでのフック実行結果とGitHub Actions上の実行結果を確認する形で行う。

## 確認ケース一覧

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | クリーンアップ後、`ruff format --check .`・`ruff check .`を実行する | 指摘0件になる |
| 2 | クリーンアップ後、既存の全pytestテストを実行する | 回帰なく全件成功する |
| 3 | `git config core.hooksPath .githooks`設定後、フォーマット崩れ・未使用importを含む変更をコミットしてpushする | pre-pushフックが自動修正し、直前のコミットにamendされてからpushされる |
| 4 | 修正の必要がないクリーンな状態でpushする | フックが何もせずそのままpushされる |
| 5 | `feature/issue-34`ブランチへのプッシュ後 | GitHub Actionsで`lint`ジョブが成功する |

## 既存テストへの影響確認

- クリーンアップによるフォーマット変更はコードの動作に影響しないため、全体テスト（`pytest`）が回帰なく通ることを確認する
