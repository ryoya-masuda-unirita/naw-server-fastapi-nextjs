# Ruff（フォーマッター・リンター）のローカルpre-pushフック化とCI導入

## 概要

バックエンドのコード品質チェック（Ruffのフォーマッター・リンター）を、開発中は走らせず、`git push`時にローカルで自動適用し、GitHub Actionsでは検証のみ行う仕組みを導入する。

## 説明

### 背景・要件

- 開発中（保存のたび等）にはフォーマッター・リンターを走らせたくない（実装途中の「先にimportして後で使う」記述スタイルを妨げないため）
- `git push`時にのみ、ローカルで自動的に`ruff format`・`ruff check --fix`を適用したい
- 修正が入った場合、新しいコミットは作らず、直前のコミット（まだリモートに存在しないコミット）に`amend`してそのままpushを続行する
- GitHub Actions側では`--fix`なしで検証のみ行う（ローカルのフックを経由しないpush・過去のコミット等の取りこぼしを防ぐ多層防御）
- `pip`の`pre-commit`パッケージは使わない（新規依存を増やしたくないため）。`.githooks/`配下の自作シェルスクリプトで実現する
- 対象は**Ruffのみ**（フォーマッター機能・リンター機能とも）。`mypy`は今回のスコープ外

### 事前調査で判明したこと

現状のコードベースに対して`ruff format --check`・`ruff check`を実行したところ、以下が判明した。

- `ruff format --check`：38ファイルが未フォーマット
- `ruff check`：10件のエラー（`tests/unit/conftest.py`のE402×7件は`sys.path.insert()`を先に実行する意図的な構造によるもの、F401×2件は本当に未使用のimport、残り1件は要確認）

CIやフックを導入する前に、まず一度リポジトリ全体をクリーンな状態にしておく必要がある。

### やること

1. **既存コードのクリーンアップ**（本チケットの一部として実施）
   - `ruff format .`を実行し、フォーマット崩れを解消する
   - `ruff check --fix .`で自動修正可能な指摘を解消する
   - `tests/unit/conftest.py`のE402（意図的な`sys.path.insert`パターン）は、`pyproject.toml`の`[tool.ruff.lint.per-file-ignores]`でこのファイルのみE402を除外する
   - 自動修正できない残りの指摘は手動で修正する
2. **ローカルのpre-pushフック**
   - `.githooks/pre-push`を新規作成する（シェルスクリプト、`uv run ruff format` / `uv run ruff check --fix`を実行）
   - 修正によりファイルが変更された場合、`git add -A && git commit --amend --no-edit`で直前のコミットに畳み込んでからpushを続行する
   - 各開発者が最初に1回`git config core.hooksPath .githooks`を実行する必要がある旨を`backend/.claude/CLAUDE.md`または`README`に案内する
3. **GitHub Actions**
   - 既存の`.github/workflows/backend-tests.yml`と同様のパターンで、`ruff format --check`・`ruff check`（`--fix`なし）を実行するジョブを追加する（同じワークフローファイル内に追加するか、別ファイルにするかは設計時に判断する）

### 動作確認方法

- ローカルで意図的にフォーマット崩れ・未使用importを含むコミットを作成し、`git push`実行時にpre-pushフックが自動修正し、直前のコミットにamendされてpushされることを確認する
- GitHub Actions上で、`ruff format --check`・`ruff check`のジョブが成功することを確認する
- （参考動作確認）フックを経由せず`--no-verify`相当の状態で崩れたコードをpushした場合、CI側でエラーとして検出されることを確認する
