# Ruff（フォーマッター・リンター）のpre-commitフック化とCI導入

## 概要

バックエンドのコード品質チェック（Ruffのフォーマッター・リンター）を、コミット時にローカルで自動適用し、GitHub Actionsでは検証のみ行う仕組みを導入する。

## 説明

### 経緯（設計変更）

当初は「`git push`時にのみ自動適用し、修正が入った場合は直前のコミットに`amend`してそのままpushを継続する」という`.githooks/pre-push`の自作スクリプトで実装した。

しかし実機検証の結果、**Gitの`pre-push`フックは「pushする内容（SHA）」をフック実行前に確定してしまうため、フック内で`git commit --amend`しても、その修正後のコミットはpushされない**という致命的な設計上の欠陥が判明した（`git log`はamend後のコミットを示すが、実際にリモートに届くのはamend前の内容）。

この問題は「コミット時（pre-commit）に自動修正する」構成であれば、コミットオブジェクトが確定する前に修正が反映されるため発生しない。これはPython/FastAPIエコシステムにおける一般的なベストプラクティスでもあるため、方式を`pre-commit`フレームワーク（pip/uvでインストールする標準的なgitフック管理ツール）に変更する。

### 背景・要件

- 開発中（保存のたび等）にはフォーマッター・リンターを走らせたくない（実装途中の「先にimportして後で使う」記述スタイルを妨げないため）
- **コミット時**にローカルで自動的に`ruff format`・`ruff check --fix`を適用したい
- 自動修正が入った場合、標準的な`pre-commit`フレームワークの挙動（1回目のコミットは失敗させ、開発者が`git add`し直して再コミットする）を許容する
- GitHub Actions側では`--fix`なしで検証のみ行う（フックを未導入の開発者・`--no-verify`でのコミット等の取りこぼしを防ぐ多層防御。この部分は既存実装のまま変更しない）
- 対象は**Ruffのみ**（フォーマッター機能・リンター機能とも）。`mypy`は今回のスコープ外

### 事前調査で判明したこと（クリーンアップ実施済み）

現状のコードベースに対して`ruff format --check`・`ruff check`を実行したところ、以下が判明していた（このクリーンアップ自体は既に完了済みで、本ドキュメント再作成の対象外）。

- `ruff format --check`：38ファイルが未フォーマット → `ruff format .`で解消済み
- `ruff check`：10件のエラー → `tests/unit/conftest.py`のE402は`pyproject.toml`の`per-file-ignores`で除外、残りは`ruff check --fix`および手動修正で解消済み

### やること（再設計後）

1. ~~既存コードのクリーンアップ~~（実施済み。変更なし）
2. **`pre-commit`フレームワークの導入**
   - `backend/pyproject.toml`の`dev`依存グループに`pre-commit`を追加する
   - リポジトリ直下に`.pre-commit-config.yaml`を新規作成し、[`ruff-pre-commit`](https://github.com/astral-sh/ruff-pre-commit)の`ruff-format`・`ruff`（`--fix`付き）フックを、`backend/`配下のファイルのみに対して実行するよう設定する
   - 各開発者が最初に1回`pre-commit install`を実行する必要がある旨を`backend/.claude/CLAUDE.md`に案内する
3. **GitHub Actions**（変更なし）
   - 既存の`.github/workflows/backend-tests.yml`の`lint`ジョブ（`ruff format --check`・`ruff check`、`--fix`なし）をそのまま維持する
4. **旧実装の削除**
   - `.githooks/pre-push`を削除する
   - `backend/.claude/CLAUDE.md`の「Gitフックの初期設定」節を`pre-commit`向けの案内に書き換える

### 動作確認方法

- ローカルで意図的にフォーマット崩れ・未使用importを含むファイルをステージしてコミットし、`pre-commit`フックが自動修正・失敗させ、`git add`し直して再コミットすると成功することを確認する
- `git log`だけでなく`git ls-remote`でリモートの実態を確認し、pushされた内容が正しく修正済みであることを確認する（前回の見落としの再発防止）
- GitHub Actions上で、既存の`lint`ジョブが成功することを確認する
