# 02_基本設計

## 変更対象

- `backend/pyproject.toml`（`dev`依存グループに`pre-commit`を追加。`per-file-ignores`は変更なし）
- `.pre-commit-config.yaml`（新規、リポジトリ直下）
- `.githooks/pre-push`（削除）
- `.github/workflows/backend-tests.yml`（変更なし。既存の`lint`ジョブをそのまま維持）
- `backend/.claude/CLAUDE.md`（フックの初期設定手順を`pre-commit`向けに書き換え）

## pre-commitフックの処理フロー

1. `git commit`実行時に、`pre-commit`フレームワークが`.pre-commit-config.yaml`に定義されたフックを呼び出す
2. `ruff-format`フックが対象ファイル（`backend/`配下）に対して`ruff format`を実行する
3. `ruff`フックが対象ファイルに対して`ruff check --fix`を実行する
4. いずれかのフックがファイルを変更した場合、`pre-commit`はそのコミットを失敗させる（`pre-commit`フレームワークの標準動作）
5. 開発者は変更内容を確認し、`git add`でステージし直してから再度`git commit`する（2回目は変更がないため成功する）
6. `ruff check`が自動修正できないエラー（構文エラー等）を検出した場合も、フックは失敗しコミットが中断される

この方式では、フックが動くタイミングが「コミットオブジェクトが確定する前」であるため、`push`時に発生した「amendしても実際のpush内容に反映されない」問題は原理的に発生しない。

## 配布方式

- `.pre-commit-config.yaml`をリポジトリにコミットする
- 各開発者が最初に1回`pre-commit install`を実行することで、`.git/hooks/pre-commit`が`pre-commit`フレームワーク経由で呼び出されるようフックスクリプトが設置される
- `pre-commit`本体は`backend/pyproject.toml`の`dev`依存グループに追加し、`cd backend && uv sync`でインストールされる
- この手順を`backend/.claude/CLAUDE.md`の開発コマンド節に追記する

## `.pre-commit-config.yaml`の設計

- モノレポ構成のため、リポジトリ直下に配置しつつ、対象ファイルを`^backend/`に限定する（`files`パラメータ）
- `ruff-pre-commit`（Astral公式ミラー）を使用し、バージョンは`backend/pyproject.toml`の`ruff>=0.8.0`と大きく乖離しないものを指定する
- Ruffは対象ファイルから親ディレクトリを遡って`pyproject.toml`を自動的に探索するため、`backend/pyproject.toml`の`[tool.ruff]`設定がそのまま適用される

## GitHub Actions側の設計（変更なし）

既存の`lint`ジョブ（`uv run ruff format --check .`・`uv run ruff check .`、`--fix`なし）をそのまま維持する。`pre-commit`フックを経由しないコミット・pushを検出する多層防御としての役割は変わらない。

## 影響範囲

- 既存のフォーマット済みコードへの追加変更はない（クリーンアップは既に完了済み）
- `.githooks/pre-push`の削除により、`git config core.hooksPath .githooks`を設定している開発環境では、設定を`git config --unset core.hooksPath`で解除する必要がある（`backend/.claude/CLAUDE.md`に案内を追記する）
- `.github/workflows/backend-tests.yml`は変更しないため、既存の`unit-tests`・`integration-tests`・`lint`ジョブには影響しない
