# 02_基本設計

## 変更対象

- `backend/pyproject.toml`（`per-file-ignores`の追加）
- 既存コード（フォーマット・自動修正の適用）
- `.githooks/pre-push`（新規）
- `.github/workflows/backend-tests.yml`（Ruffジョブの追加）
- `backend/.claude/CLAUDE.md`（フックの初期設定手順の案内を追記）

## pre-pushフックの処理フロー

1. `git push`実行時にGitが`.githooks/pre-push`を呼び出す
2. スクリプト内で`backend`ディレクトリに移動し、`uv run ruff format .`・`uv run ruff check --fix .`を実行する
3. `git status --porcelain`等でワーキングツリーに変更があるか確認する
4. 変更があれば`git add -A`→`git commit --amend --no-edit`で直前のコミットに畳み込む
5. 変更がなければ・畳み込みが完了すれば、スクリプトは正常終了（exit 0）し、Gitが通常通りpushを続行する
6. `ruff check`が自動修正できないエラー（構文エラー等）を検出した場合は、スクリプトが非ゼロ終了し、pushを中断してユーザーに修正を促す

## 配布方式

- `.githooks/`ディレクトリをリポジトリにコミットする（Gitの`hooksPath`設定はデフォルトでは`.git/hooks`を見るため、そのままでは有効化されない）
- 各開発者が最初に1回`git config core.hooksPath .githooks`を実行することで、リポジトリ内の`.githooks/`が有効なフックディレクトリとして使われるようになる
- この手順を`backend/.claude/CLAUDE.md`の開発コマンド節に追記する

## GitHub Actions側の設計

- 既存の`.github/workflows/backend-tests.yml`に、独立したジョブとして`lint`（または`ruff`）を追加する（既存の`unit-tests`・`integration-tests`ジョブとは並列実行）
- トリガーは既存ワークフローと同じ`on.push`・`paths: ["backend/**", ...]`をそのまま使う
- ジョブ内容：`uv sync --locked`後、`uv run ruff format --check .`・`uv run ruff check .`を実行する（`--fix`は付けない。検証のみ）

## 既存コードのクリーンアップ方針

- `ruff format .`・`ruff check --fix .`をこの機会に一度適用し、以後の差分を小さく保つ
- `tests/unit/conftest.py`のE402（`sys.path.insert()`を先に実行する構造）は意図的なものであり、コード自体は変更せず、`pyproject.toml`に以下を追記して対応する

```toml
[tool.ruff.lint.per-file-ignores]
"tests/unit/conftest.py" = ["E402"]
```

## 影響範囲

- 既存の全ソースファイルにフォーマット差分が入る（クリーンアップの一環として想定通り）
- テストコード自体のロジックは変更しないため、既存テストは全件成功する想定
- `.github/workflows/backend-tests.yml`への追記のみで、既存の`unit-tests`・`integration-tests`ジョブには影響しない
