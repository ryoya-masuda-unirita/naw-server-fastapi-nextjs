# 01_要件定義

## 背景

バックエンドのコード品質（フォーマット・リンター）は、開発中に保存のたびチェックが走ると「先にimportして後で使う」実装スタイルが妨げられる（未使用importとして警告・自動削除されてしまう）ため、開発中は一切走らせたくない。

**コミット時**にのみローカルで自動適用し、GitHub Actions側では検証のみを行うことで、開発体験を損なわずにコード品質を担保する。

### 設計変更の経緯

当初`git push`時に自動修正する`.githooks/pre-push`の自作スクリプトで実装したが、実機検証により「Gitのpre-pushフックは、フック実行前に確定した内容をpushするため、フック内で`git commit --amend`しても修正後のコミットはpushされない」という致命的な欠陥が判明した。コミット時に自動修正すればこの問題自体が発生しないため、標準的な`pre-commit`フレームワークを採用する方式に変更する。

## 機能要件

### ローカル：pre-commitフック（`pre-commit`フレームワーク）

- リポジトリ直下に`.pre-commit-config.yaml`を新規作成する
- [`ruff-pre-commit`](https://github.com/astral-sh/ruff-pre-commit)（Astral公式）の`ruff-format`・`ruff --fix`フックを使用する
- 対象は`backend/`配下のPythonファイルのみに限定する
- `git commit`実行時に自動的にRuffのフォーマット・自動修正を実行する
- 修正によりファイルが変更された場合の挙動は、`pre-commit`フレームワークの標準動作に従う：
  - そのコミットは失敗する（変更後のファイルがワーキングツリーに反映されるが、ステージはされない）
  - 開発者が`git add`でステージし直し、再度`git commit`することで成功する
  - これは「自動でamendしてpush継続」ではなく「開発者が変更内容を確認したうえで再コミットする」標準的なフローであり、本チケットではこの挙動を許容する
- 各開発者は最初に1回`pre-commit install`を実行する必要がある（`backend/.claude/CLAUDE.md`に案内を追記する）
- `pre-commit`本体は`backend/pyproject.toml`の`dev`依存グループに追加し、`uv sync`でインストールされるようにする

### CI：GitHub Actions（変更なし）

- 既存の`.github/workflows/backend-tests.yml`の`lint`ジョブ（`ruff format --check`・`ruff check`、いずれも`--fix`なし・検証のみ）をそのまま維持する
- `pre-commit`フックを経由しないコミット（フック未導入の開発者、`--no-verify`でのコミット等）を確実に検出するための多層防御として位置づける

### 既存コードのクリーンアップ（実施済み・変更なし）

- `ruff format .`・`ruff check --fix .`は既に適用済み
- `tests/unit/conftest.py`のE402除外設定（`pyproject.toml`の`per-file-ignores`）も設定済み

## 非機能要件

- 対象は**Ruffのみ**（フォーマッター機能・リンター機能とも）。`mypy`は今回のスコープ外
- `pre-commit`（pip/uvパッケージ）を新規のdev依存として追加する（当初「新規依存を増やさない」という方針だったが、pre-pushフック方式が技術的に破綻したため、業界標準である`pre-commit`フレームワークの採用に方針転換する）
- 既存の`backend/.claude/CLAUDE.md`のPEP 8準拠方針と矛盾しない設定にする

## スコープ外

- `mypy`（型チェック）のフック化・CI化
- フロントエンド側のフォーマッター・リンター整備
- `pre-push`タイミングでの自動修正（技術的に実現不可能と判明したため、`pre-commit`タイミングに変更）
