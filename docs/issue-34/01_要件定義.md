# 01_要件定義

## 背景

バックエンドのコード品質（フォーマット・リンター）は現状チェックされておらず、開発者ごとにスタイルがばらつく可能性がある。一方で、開発中に保存のたびフォーマッター・リンターが走ると、「先にimportして後で使う」実装スタイルが妨げられる（未使用importとして警告・自動削除されてしまう）ため、開発中は一切走らせたくない。

`git push`のタイミングでのみローカルに自動適用し、GitHub Actions側では検証のみを行うことで、開発体験を損なわずにコード品質を担保する。

## 機能要件

### ローカル：pre-pushフック

- `.githooks/pre-push`（シェルスクリプト）を新規作成する
- `git push`実行時に自動的に`uv run ruff format`・`uv run ruff check --fix`を実行する
- 修正によりファイルが変更された場合：
  - 新しいコミットは作らない
  - `git add -A && git commit --amend --no-edit`で直前のコミットに畳み込む
  - そのままpushを続行する（ユーザーの追加操作は不要）
- 各開発者は最初に1回`git config core.hooksPath .githooks`を実行する必要がある（`backend/.claude/CLAUDE.md`に案内を追記する）

### CI：GitHub Actions

- `ruff format --check`・`ruff check`（いずれも`--fix`なし、検証のみ）を実行するジョブを追加する
- 既存の`.github/workflows/backend-tests.yml`と同様、`backend/**`の変更があった場合のみ実行する
- pre-pushフックを経由しないpush（フックを未設定の開発者、`--no-verify`でのpush等）を確実に検出するための多層防御として位置づける

### 既存コードのクリーンアップ（本チケットに含む）

- `ruff format .`で全体のフォーマットを揃える（現状38ファイルが未フォーマット）
- `ruff check --fix .`で自動修正可能な指摘（`tests/unit/test_auth_service.py`の未使用import`AsyncMock as AM`等）を解消する
- `tests/unit/conftest.py`のE402（`sys.path.insert()`を先に実行してからimportする意図的な構造）は、`pyproject.toml`の`[tool.ruff.lint.per-file-ignores]`でこのファイルのみE402を除外する

## 非機能要件

- 対象は**Ruffのみ**（フォーマッター機能・リンター機能とも）。`mypy`は今回のスコープ外
- 新規のPython依存パッケージは追加しない（`pip`の`pre-commit`パッケージは使わない）
- 既存の`backend/.claude/CLAUDE.md`のPEP 8準拠方針と矛盾しない設定にする

## スコープ外

- `mypy`（型チェック）のフック化・CI化
- フロントエンド側のフォーマッター・リンター整備
- コミット時（`pre-commit`）のフック（今回は`pre-push`のみ）
