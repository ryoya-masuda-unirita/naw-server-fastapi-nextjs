# 01_要件定義

## 背景

#491・#509 で、ルート README の古い記述と重複は直した。しかし、「正しい」ことと「読みやすい」ことは別で、ルート README は 218 行あり、最初に開いた人が、何をすればよいか分からない。

## 現状（`develop`、#509 のマージ後）の内訳

| 部分 | 行数 | 内容 |
|---|---|---|
| 概要 | 5 | リポジトリの説明と、SecuAiGent が何かの説明 |
| 目的別の入口 | 13 | 目的 → 読む場所の表 |
| 画面を見る（デモ環境） | 51 | ログイン情報、起動、画面一覧の表（9 行）、server-local の起動、オンプレとのつなぎ方、困ったとき |
| アシスタントの種類ごとの通信経路 | 30 | 図 2 枚、経路の説明（移植元のクラス名つき）、部品ごとの担当の表 |
| 社内（オンプレ）側と Waha! エミュレーター | 7 | 要約とリンク 3 つ |
| モノレポ構成 | 13 | ディレクトリの表（入口の表とリンク先が重なる） |
| ローカル疎通確認（frontend + backend） | 89 | 前提・初回セットアップ・起動・疎通確認・トラブルシュート |
| Codex 運用 | 3 | `AGENTS.md` への参照 |

`server/` と `client/` には README がない。通信経路と、ローカル疎通確認は、今は置き場所がルートしかない。

## 機能要件

| No | 要件 |
|---|---|
| F1 | ルート README は **80 行以内**。構成は、「これは何か（2〜3 行）」「まず動かす（3 ステップ）」「詳しくはここ（目的別のリンク）」の 3 つに、「Codex 運用」を末尾に残す |
| F2 | 「まず動かす」は、デモ環境の起動 → ブラウザで開く → ログイン、の 3 ステップ。停止の方法を 1〜2 行で添える |
| F3 | 「詳しくはここ」は、モノレポ構成の表と入口の表を 1 つにまとめる（ディレクトリ名・何か・リンクを 1 行で） |
| F4 | 通信経路（図 2 枚・経路の説明・部品ごとの担当）は、`docs/` の新しいファイルへ移し、ルートからリンクする |
| F5 | ローカル疎通確認は、`docs/` の新しいファイルへ移し、ルートからリンクする |
| F6 | デモ環境の詳細（画面一覧・server-local の起動・オンプレとのつなぎ方・困ったとき）は、`docs/` の新しいファイルへ移し、ルートからリンクする |
| F7 | 言葉をやさしくする。1 文を短くする。内部用語（SECURE・RAG・テナント・server-local・Waha! など）は、初出で 1 文で説明する。Issue 番号・経緯の注記・移植元のクラス名は、読む人に要るものだけ残す（移した先では、根拠として残してよい） |
| F8 | 残す手順（デモ環境の起動、ローカル疎通確認）は、**実際に実行して動くことを確かめる**。確かめた結果を `08_動作確認.md` に書く |
| F9 | 全 Markdown の相対リンクの先が実在する。移した内容が、移し先から読める |
| F10 | 「Codex 運用」の節は、本文を変えずに残す |

## 非機能要件

- ドキュメントだけを変える（コードは変えない）
- 移した内容の意味を変えない（言葉をやさしくする以外の中身の変更は、しない。古い・誤りと分かったものは、直して記録する）
- 稼働中の環境（`naw-onprem-*`・`naw-demo-477`・`naw-server*` など、複数が動いている）には触れない。実行して確かめるときは、別のプロジェクト名・別のポートで起動し、終わったら片付ける
- 実際の LLM（Bedrock など）にリクエストを送らない（#509 の反省。稼働中の `onprem` は Bedrock に接続している）

## スコープ外

- ルート以外の README（#510）
- コードの変更
- `docs/issue-*` の過去の記録の書き直し
- 通信経路の中身の正誤の検証（移植元のコードからの書き起こしで、そのまま移す）
