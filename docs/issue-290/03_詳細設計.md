# 03_詳細設計

## API（backend の実応答との差と画面での吸収）

`docs/issue-279/api-backend-diff.md` と `backend/app/routers/indexes.py`・`files.py`、`schemas/file.py`・`services/file_service.py` を確認した。backend は直さない。

| API | backend の形 | 移植元との差と画面での吸収 |
|---|---|---|
| `GET /api/admin/indexes/{id}` | `IndexResponse`（`tenantEndpoints[]`・`groupIds`） | 一覧と同じく `tenantEndpoints[].id` から `endpointIds` を作る（`indexRowToApiItem`） |
| `GET /api/admin/indexes/{id}/files` | `{ content, totalElements, number, size }`。行は `fileName`・`displayName`（null あり）・`reference`（null あり）・`userId`・`updatedBy`・`status`。`splitLength` は返らない | 移植元の型（`displayName`・`updatedBy`・`splitLength`）に対し、`displayName` が無ければ `fileName` を表示名にし、`updatedBy` が無ければ `userId` を使う（`fileRowToTrainingDataFile`）。`splitLength` が無いので行のチャンク分割は空になり、編集では既定の「中」から始まる（移植元は常に `splitLength` を受ける想定） |
| `POST /api/admin/indexes/{id}/files` | `file` は multipart、その他はクエリまたはフォーム。**`name` が必須**（無いと 400） | 移植元の画面は `name` を送らない。backend に合わせ、ファイルを付ける POST・PATCH で `name` にファイル名を付ける |
| `PATCH /api/admin/indexes/{id}/files/{fileId}` | ファイル無しはメタデータのみ。ファイル付きは旧ファイルを物理削除して作り直す（`name` 必須。新しい ID になる） | 同上。ファイル無しの PATCH は本文なし（移植元と同じ） |
| `DELETE .../files/{fileId}` | 204。`physicalDelete` 省略は論理削除 | 移植元と同じく 1 件ずつの DELETE を同時に送る（`bulk-delete` は使わない） |
| `POST .../indexes/{id}/sync` | 204。**SAAS 環境ではスタブ** | 移植元どおり呼ぶ |
| `POST .../files`（LOCAL のフォルダ） | `ensure_not_local` で 400 | ローカル接続のフォルダへの追加は backend が受けない。画面は移植元どおり操作できる（失敗は共通エラートーストで通知）。申し送り |
| ユーザー一覧（更新者の絞り込み・名前解決） | `GET /api/admin/users`（`size` 最大 1000） | 移植元と同じ 1000 件・名前の昇順。既存の `useAdminUsers` を使う |

## 移植元と変えた点

| 点 | 内容と理由 |
|---|---|
| ローカル／クラウドのビュー | 移植元は 2 コンポーネントでほぼ同一のコード。1 つにまとめ、案内・同期・ダウンロード・ダイアログ幅だけ `data.type` で切り替えた |
| 編集でファイルを選んだとき | 移植元は追加のときだけ選んだファイルを保持し、編集では表示（リンク名・プレビュー）だけ変えてファイルを送らない（前回の追加で選んだファイルが残っていれば、それが送られる）。意図とずれるため、編集でも選んだファイルを保持して送る。ダイアログを開くたびに保持を消す |
| 削除前の「戻る」 | 移植元の `Location.back()` は `navigate(-1)` |
| ファイル一覧の取得の順序 | 移植元はフォルダ → ユーザー → ファイルの順に直列。ここでは並列に取る（表示は同じ。更新者名はユーザーが届いた時点で置き換わる） |
| ファイルのプレビュー（`isPreviewOpen`・`onPreview`） | 移植元でも呼び出し元のボタンがコメントアウトされ開けない。移植していない。ダウンロードの「選択分をまとめて保存」（`onDownloadSelected`）も移植元のテンプレートにボタンがなく移していない |
| 一覧の取得失敗 | 移植元は失敗時に一覧を変えない。同じ（共通エラートースト） |

## 画面の挙動

### ヘッダー
- 見出しはフォルダ取得後はフォルダ名、取得前・取得失敗時は `LEARNING_DATA.DETAIL_TITLE`
- 編集メニュー: 「学習フォルダの設定を編集」「学習フォルダを削除」。フォルダ未取得のときは何もしない

### フォルダの編集ダイアログ
- 開くと全グループの取得 → 接続先の候補の取得（移植元 `initializeGroups` → `loadEndpointsForType`）。この間は読み込み表示
- ローカルは登録済みの接続先を選択。候補に無ければ先頭。クラウドは VDB・埋め込みモデルを登録済みのものから選び、無ければ先頭
- 保存ボタンは「読み込み中でない・接続先がある・送信中でない・名前がある・接続先が選ばれている」ときだけ押せる。押すと入力チェック（名前必須・255 文字、説明 1000 文字、ローカルの接続先必須）。保存後に詳細を読み直し、ダイアログを閉じる。失敗時は開いたまま
- サービス ID（取得・削除・学習）はローカルのみ、任意

### ファイル一覧
- 条件変更は 1 ページ目へ戻し、ページ送りは戻さない。「自分」は現在のユーザー ID に置き換える。期間は `toDateTimeRange` で UTC の日時に変える。学習設定 ON/OFF は `ENABLE`/`DISABLE`。並べ替えの更新者名順は `userId`
- 選択中の行は条件やページが変わっても残る（移植元と同じ）
- 追加ダイアログは、選んだファイルを先頭に挿入する（移植元の `FormArray.insert(index)`）。「全体に適用」は各行の `リンク先頭の文字 + 表示名` をリンク名にする
- 追加の「完了」は、1 件以上あり全行の入力が正しいときだけ押せる（移植元の `[disabled]`）。編集（スマートフォンの追加を含む）の「保存/完了」は、押すと入力チェックを出す
- 追加時の `status`（編集フォームのスイッチ）は、移植元の `uploadFile` が送らないため送られない（ファイル追加は常に backend の既定）

### 状態の更新
- 学習設定の切替・一覧上の名前変更は、先にキャッシュの行を書き換え、失敗したら元の行へ戻す。成功しても一覧は読み直さない
- 追加・削除・設定保存は、成功後に一覧を読み直す
- 同期は 3 秒待ってから POST し、フォルダ詳細とファイル一覧を読み直す。この間は画面全体が読み込み表示になり、一覧の選択状態は失われる（移植元と同じ）
- フォルダの削除は、確認後に待たずに前の画面へ戻る（移植元と同じ）

## 申し送り

- ローカル接続のフォルダでは、backend がファイル追加を 400 で拒否する。同期も SAAS ではスタブ
- ファイル行にチャンク分割（`splitLength`）が返らないため、編集ダイアログのチャンク分割は常に既定の「中」から始まる
- 説明の文字数上限は #135 と同じく、画面 1000 文字・backend 255 文字（フォルダ作成と同様）
