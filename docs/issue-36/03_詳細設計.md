# 03_詳細設計

## 新規作成ファイル

### モデル

- `backend/app/models/prompt_template.py`
  - `PromptTemplate`: `prompt_templates` テーブル。`id`（`varchar(32)` PK）・`tenant_id`（`tenants.id` FK, CASCADE）・`name`（`varchar(32)`）・`description`（`Text`, nullable）・`system_prompt`（`Text`, not null）・`updated_at`
  - `GroupPromptTemplate`: `groups_prompt_templates` テーブル。`group_id`・`prompt_template_id`・`tenant_id` の複合PK（`groups_assistants`/`GroupAssistant`と同じパターン）・`updated_at`
  - 参照: `~/Documents/naw-server` の `PromptTemplate.java`／`groups_prompt_templates` の Liquibase changeset

### スキーマ

- `backend/app/schemas/prompt_template.py`
  - `PromptTemplateCreateRequest`: `name: str`・`description: str | None`・`systemPrompt: str`・`groups: set[str] | None`（グループ**ID**集合。未指定/nullなら更新時は紐付け変更なし）
  - `PromptTemplateCreateResponse`: 作成・更新のレスポンス。`id`・`tenantId`・`name`・`description`・`systemPrompt`・`groups: set[str]`（グループ**ID**）。移植元 `PromptTemplateController` が作成・更新のレスポンスに `PromptTemplateCreateRequest` を流用し `groups` にID集合を詰めている挙動をそのまま踏襲する
  - `PromptTemplateResponse`: 一覧取得のレスポンス。`id`・`tenantId`・`name`・`description`・`systemPrompt`・`groups: set[str]`（グループ**名**集合）・`updatedAt`。移植元 `PromptTemplateResponse.java` 準拠（`groups` の意味が作成・更新レスポンスと異なる点は移植元の既存挙動であり、今回はそのまま踏襲する）
  - `PagedPromptTemplateResponse`: `content: list[PromptTemplateResponse]`・`totalElements: int`・`number: int`・`size: int`（`PagedGroupMemberResponse` と同じ形式。移植元がSpring Data `Page<T>` をそのままシリアライズしている形に合わせる）

### リポジトリ

- `backend/app/repositories/prompt_template_repository.py`
  - `find_by_id_and_tenant_id(id, tenant_id, session) -> PromptTemplate | None`
  - `find_page_by_group_ids(group_ids, tenant_id, search, page, size, session) -> tuple[list[PromptTemplate], int]`: 一般ユーザー向け。`groups_prompt_templates` を `EXISTS` 部分問い合わせで結合し重複排除する
  - `find_page_for_admin(tenant_id, search, group_filter, exclude_group_id, admin, admin_group_ids, page, size, session) -> tuple[list[PromptTemplate], int]`: 管理者向け。移植元 `PromptTemplateSpecification` の各条件（`hasTenantId`・`containsSearchText`・`matchesAdminScope`・`excludeGroupId`）を `where()` の動的組み立てで再現する
    - `group_filter` が `"__none__"`（移植元の `NO_GROUP_FILTER` 定数）の場合は、いずれのグループにも紐付いていないテンプレートのみを返す
    - `group_filter` が上記以外で指定されている場合は、そのグループ1件に紐付くテンプレートのみに絞り込む
    - `group_filter` 未指定時、`admin` が `True`（全体管理者）なら絞り込みなし、`False`（グループ管理者）なら `admin_group_ids` に紐付くテンプレートのみに絞り込む
    - `exclude_group_id` 指定時は、そのグループに紐付いていないテンプレートのみに絞り込む（複数条件はAND結合）
  - `save(prompt_template, session) -> PromptTemplate`（作成・更新共通）
  - `delete_by_id_and_tenant_id(id, tenant_id, session) -> None`

- `backend/app/repositories/group_prompt_template_repository.py`（`GroupAssistantRepository` と同じ位置づけ）
  - `find_template_ids_by_group_ids(group_ids, tenant_id, session) -> list[str]`
  - `find_groups_grouped_by_template_ids(template_ids, tenant_id, session) -> dict[str, list[tuple[str, str]]]`: テンプレートIDごとの `(group_id, group_name)` 一覧。一覧表示時のN+1回避のため`Group`とJOINして1クエリで取得する
  - `replace_groups_for_template(template_id, tenant_id, group_ids, session) -> None`: 対象テンプレートの既存紐付けを全削除してから指定グループ集合を再登録する（移植元がHibernateの`@ManyToMany`によるJOINテーブル自動同期で実現している処理を、明示的な中間テーブルモデルに対して手動で再現する）

- `backend/app/repositories/group_repository.py`（既存ファイルに追記）
  - `find_by_tenant_id_and_ids(tenant_id, ids, session) -> list[Group]`: 作成・更新時に指定グループID集合の実在チェック・取得に使用（移植元 `groupRepository.findByTenantIdAndIdIn` 相当。存在しないIDは無視する）

### サービス

- `backend/app/services/prompt_template_service.py`
  - `get_prompt_templates(tenant_id, current_user, search, page, size, session) -> PagedPromptTemplateResponse`: 一般ユーザー向け。`GroupUserRepository.find_belonging_group_ids` で所属グループを取得し、所属グループがなければ空ページを返す
  - `get_admin_prompt_templates(tenant_id, current_user, search, team, exclude_group_id, page, size, session) -> PagedPromptTemplateResponse`: `GroupService._is_tenant_admin` 相当の判定と `GroupUserRepository.find_admin_group_ids_for_user` を用いて管理者スコープを決定する
  - `create_prompt_template(tenant_id, req, session) -> PromptTemplateCreateResponse`
  - `update_prompt_template(template_id, tenant_id, req, session) -> PromptTemplateCreateResponse`（存在しない場合404）
  - `delete_prompt_template(template_id, tenant_id, session) -> None`
  - `_to_response(template, groups_by_id, session) -> PromptTemplateResponse` などレスポンス変換の内部ヘルパー

### ルーター

- `backend/app/routers/prompt_templates.py`
  - `prompt_template_router`（`prefix="/api/prompt-templates"`）: `GET ""`
  - `admin_prompt_template_router`（`prefix="/api/admin/prompt-templates"`）: `GET ""`・`POST ""`・`PATCH "/{template_id}"`・`DELETE "/{id}"`
  - 管理者向けエンドポイントは `require_admin` ではなく、グループ管理者も許可するため `get_current_user` を使い、サービス層で権限判定する（`GroupService`の管理者向けエンドポイントと同じ方針）
