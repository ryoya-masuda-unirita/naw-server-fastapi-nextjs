# 02_基本設計

## 変更対象

- 新規ドメイン: プロンプトテンプレート（本体）
- 新規中間テーブル: グループ⇔プロンプトテンプレートの紐付け（Groupは実装済みのため中間テーブルのみ新規）

## 画面 / API 変更概要

- プロンプトテンプレート一覧取得（一般ユーザー向け）
  - ログインユーザーの所属グループに紐づくテンプレートを、検索・ページネーション付きで返す
- プロンプトテンプレート一覧取得（管理者向け）
  - 検索・チームフィルタ・除外グループフィルタ・ページネーション付きで返す
  - 全体管理者は全件、グループ管理者は管理グループに紐づく分のみ参照可能
- プロンプトテンプレート作成
  - 名前・説明・システムプロンプト・グループ集合を受け取り新規作成する
- プロンプトテンプレート更新
  - 名前・説明・システムプロンプトを更新する。グループ集合は指定時のみ置き換える
- プロンプトテンプレート削除
  - テンプレートIDを指定して削除する

## 影響範囲

- 既存のGroup関連実装（一覧・詳細・所属ユーザー管理）には変更を加えない
- Group一覧レスポンスの`promptTemplates`/`promptTemplateIds`は今回は対象外とし、既存どおり固定で空リストを返す実装のまま維持する
- 既存の「グループとアシスタントの中間テーブル」実装パターン（テナントIDを含む複合主キー、更新日時カラムを持つ中間テーブルモデル）に倣った実装とする

## 移植方針

- 移植元のプロンプトテンプレートドメイン（本体エンティティ・リポジトリ・検索条件）を、既存のFastAPI実装のレイヤー構成（ルーティング／サービス／リポジトリ／モデル）に1:1で移植する
- 中間テーブルは、既存の「グループとアシスタントの中間テーブル」と同様のパターン（Entity化されていないテーブルも省略せずモデル化する方針）に倣い、明示的なモデルクラスとして定義する
- 管理者向け一覧の絞り込み条件（テナントID・検索文字列・グループフィルタ・除外グループフィルタの組み合わせ）は、既存の動的クエリ組み立ての方針を踏襲して実現する
- ページネーションレスポンスは既存の共通形式（content・totalElements・number・size）を踏襲する
- 移植元で「グループが見つからない場合は無視して作成する」「グループ集合がnullの場合は紐付けを変更しない」といった細かな挙動差分がある点は、詳細設計以降で実装に反映する
