# 01_要件定義

## 背景

issue-24（チーム管理API）実装時、GroupエンティティはAssistant・PromptTemplateとM2M関連を持つが、両ドメインが未実装だったためGroup単体のCRUD・ユーザー所属管理のみをスコープとし、PromptTemplateとの紐付けは別チケットとした。

Assistant関連は issue-26（一覧取得）・issue-28（テナントエンドポイント）・issue-30（紐付け）で完了済み。今回はもう一方のGroup関連ドメインであるPromptTemplateを移植する。

## 機能要件

- 一般ユーザー向け一覧取得
  - ログインユーザーが所属するグループに紐づくプロンプトテンプレートの一覧を、検索・ページネーション付きで取得できること
  - 所属グループがない場合は空の一覧を返すこと
- 管理者向け一覧取得
  - テナント内のプロンプトテンプレートを、検索・チームフィルタ（特定グループへの絞り込み）・除外グループフィルタ（特定グループに未紐付けのものだけを抽出）・ページネーション付きで取得できること
  - 全体管理者はテナント内の全プロンプトテンプレートを参照できること
  - グループ管理者は自分が管理するグループに紐づくプロンプトテンプレートのみを参照できること
- 作成
  - テンプレート名・説明・システムプロンプト・紐付けるグループ集合を指定して新規作成できること
  - 指定したグループが存在しない場合は該当グループを無視して作成できること（移植元の挙動を踏襲）
- 更新
  - 既存テンプレートの名前・説明・システムプロンプトを更新できること
  - グループ紐付けは指定された場合のみ置き換え、未指定の場合は既存の紐付けを維持すること
- 削除
  - テンプレートIDとテナントIDを指定して削除できること

## 非機能要件

- テナント分離: 既存実装と同様、クエリ条件に`tenant_id`を含めることで自テナント以外のプロンプトテンプレートにアクセスできないこと（本バックエンドはPostgreSQLのRLSではなくアプリケーション層での`tenant_id`絞り込みでテナント分離している）
- 権限制御: 管理者向けAPI（一覧・作成・更新・削除）は全体管理者またはグループ管理者のみ利用可能。一般ユーザー向け一覧取得は認証済みユーザーであれば誰でも利用可能
- ページネーションレスポンスは既存の共通形式を踏襲すること

## スコープ外

- Group側からのプロンプトテンプレート紐付け操作エンドポイント（グループ視点での追加・削除・一覧取得）。issue-30の`assistants_endpoints`と同様の位置づけで別チケットとする
- Group一覧レスポンスの`promptTemplates`/`promptTemplateIds`フィールドへの実データ配線。現状は固定で空リストを返す実装のままとし、対応は別チケットとする（`assistants`/`assistantIds`側も同様に未配線のまま）
- プロンプトテンプレートを利用したチャット時のライブラリ生成機能（Room/Message API未実装のためスコープ外）
