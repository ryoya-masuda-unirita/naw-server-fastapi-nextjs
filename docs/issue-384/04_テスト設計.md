# 04_テスト設計

## テスト方針

インフラと CI の構成変更なので、自動テストは追加しない。今回は、リソースの増減が想定どおりであることを、変更前後の `plan` の比較で確認する（#383 までのような「差分 0」にはならない）。AWS への `apply` は実行しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 構文・書式 | `fmt` と `validate` | エラーなし |
| 2 | リソースの増減 | 変更前（`develop`）と変更後の `plan` を、リソースのアドレスで比べる | 削除は想定の 7 リソースだけ（起動テンプレート、ASG、キャパシティプロバイダ、クラスタとの関連付け、インスタンスのロール・アタッチメント・プロファイル）。追加は 2 リソースだけ（EIP、NAT GW）。合計は 72 から 67 になる |
| 3 | 変わらないリソース | 上記以外のリソースの、確定している属性値を比べる | 差分があるのは、想定したリソースと属性だけ（VPC の CIDR と DNS、サブネットの CIDR、private のルートテーブル、ALB のターゲットタイプ、2 つのタスク定義、サービス）。RDS・キャッシュ・ECR・CloudFront・IAM のポリシーなどに差分がない |
| 4 | CIDR | 変更後の `plan` | VPC `10.10.0.0/16`、public `10.10.0.0/24`・`10.10.1.0/24`、private `10.10.10.0/24`・`10.10.11.0/24`。サブネットの名前・AZ は変わらない |
| 5 | NAT | `plan` | EIP と NAT GW が 1 つずつ。NAT は public サブネットにあり、private のルートテーブルの `0.0.0.0/0` が NAT を指す |
| 6 | タスク定義 | `plan` | 2 つとも `awsvpc`・`FARGATE`・CPU 512・メモリ 1024・`ARM64`・`LINUX`。コンテナ単位のメモリ指定なし。backend のポートは 8000 のみ |
| 7 | サービス | `plan` | Fargate、private サブネット、パブリック IP なし、ヘルスチェックの猶予 240 秒、ECS の SG。キャパシティプロバイダの指定なし。ALB に登録される |
| 8 | ALB | `plan` | ターゲットタイプ `ip`。ヘルスチェックのパスは `/health` のまま |
| 9 | 入力の整理 | `validate` | ecs の入力に public サブネットがなく、private サブネットがある。使われていない変数・出力がない |
| 10 | 命名 | `plan` のリソース名と、CI が組み立てる名前 | クラスタ・サービス・タスク定義・ECR は一致。キャパシティプロバイダの名前は、もうどこにもない |
| 11 | 検証 | `vpc_cidr` に不正な値 | `plan` が `Invalid value for variable` で失敗する |
| 12 | CI のマイグレーション | サービスのネットワーク設定の JSON を、サンプルで `run-task` の引数の形に渡す部分と、`null`・空・`None` のときの分岐を手元で再現する | 正しい JSON は通り、`null`・空・`None` は原因を示して止まる。YAML は読み込める |
| 13 | イメージの互換 | タスク定義の登録に使う `jq` の `del(...)` | `runtimePlatform` を消さない |
| 14 | 古い記述の残り | 検索 | `ECS_CAPACITY_PROVIDER`・キャパシティプロバイダ・`t4g`（イメージのビルドの説明以外）・EC2 起動タイプの記述が、README と CLAUDE.md とワークフローに残っていない |
| 15 | 秘密の混入 | 追加・変更したファイルを確認する | 認証情報・実のアカウント ID なし |
