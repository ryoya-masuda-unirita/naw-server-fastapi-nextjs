## 詳細

### 1. `vpc_cidr` の検証（🔵 提案）→ 対応済み

`cidrnetmask` の成否だけでは、`10.10.0.0/24`（サブネットが /32 になる）や `/25`（`cidrsubnet` が失敗する）を通してしまう。プレフィックス長を `/16`〜`/18`（サブネットが /24〜/26）に限り、ホストビットが立っている値（`10.10.0.5/16`）も弾くようにした。`plan` で、`10.10.0.0/16` は通り（67 リソース）、`/24`・`10.10.0.5/16`・`abc` はエラーメッセージつきで失敗することを確認した。

### 2. NAT GW が単一障害点（🔵 提案）→ 対応済み

設計どおり（移植元と同じ構成、固定費の抑制）なので構成は変えない。README に、NAT が 1 台のみで、そのAZ の障害時に、もう一方の AZ のタスクも外向きの通信ができなくなること、AZ ごとの NAT は別の機会に検討することを明記した。

### 3. コストの記述（🟡 注意）→ 対応済み

「月 4,000 円超」は、事前の調査で出た根拠のない概算を、そのまま書いたものだった。指摘では「実際はもっと高い」とされたが、その金額も確認できない。東京リージョンの単価を、公式の料金ページの検索で確認しようとしたが、リージョンの特定できる単価は得られなかった。そのため、**金額は書かない**ことにした。README には、課金の仕組み（NAT は存在する時間とデータ量、Fargate は vCPU とメモリの時間）、単価の確認方法（料金ページ、Pricing Calculator、Cost Explorer）、減らし方を書いた。`02_基本設計.md`・`08_動作確認.md`・PR 本文の同じ記述も直した。

### 4. サービスの取得失敗の診断（🔵 提案）→ 対応済み

`describe-services` の結果全体を取得し、`.services[0].networkConfiguration` が空のときは、`failures`（クラスタ名・サービス名の誤りなら `MISSING` が入る）を含めたメッセージで止まるようにした。偽の `aws` コマンドで、正常、サービス未存在（`failures: MISSING`）、起動失敗（`RESOURCE:ENI`）の 3 通りを実行して確認した。

### 5. `depends_on` の範囲（🔵 提案）→ 対応しない

必要なのは NAT のルートだけだが、モジュールをまたぐ個別リソースへの依存は書けない。モジュール全体を待たせると `apply` が少し直列になるが、害はない。ecs モジュールにデータソースがないため、`plan` の評価が遅れることもない。将来 network が ecs の出力に依存すると循環するので、その場合に見直すことを、`main.tf` のコメントに書いた。

### 6. `apply` していない（🔵 提案）→ 対応しない

`apply` は費用がかかるため、ユーザーの指示で実行しない。未確認の項目（NAT 経由のイメージ取得、ヘルスチェック、マイグレーションの実起動）は、`08_動作確認.md` と PR 本文に明記してある。実際に `apply` するときは、先に費用を見積もること。
