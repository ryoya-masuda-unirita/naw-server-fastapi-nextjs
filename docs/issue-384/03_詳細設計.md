# 03_詳細設計

## 1. network（`infra/modules/network/main.tf`・`variables.tf`）

- 入力に `vpc_cidr`（string、説明: `VPCのCIDR`）を足す。既定値は持たせない（環境側で持つ）
- `locals` に AZ の識別子 `az_suffixes = ["1a", "1c"]` を足す。サブネットは、現在と同じキー（`1a`・`1c`）の `for_each` を維持する（名前・SG・出力が、キーに依存しているため）

```hcl
resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  ...
}

# public: i = 0,1 → 10.10.0.0/24, 10.10.1.0/24
for_each = { for i, az in local.az_suffixes : az => cidrsubnet(var.vpc_cidr, 8, i) }
# private: i + 10 → 10.10.10.0/24, 10.10.11.0/24
for_each = { for i, az in local.az_suffixes : az => cidrsubnet(var.vpc_cidr, 8, i + 10) }
```

- NAT: `aws_eip.nat`（`domain = "vpc"`）と `aws_nat_gateway.main`（先頭の public サブネット `local.az_suffixes[0]`、`depends_on = [aws_internet_gateway.main]`）を足す。Name タグは `${var.project_name}-nat-eip`・`${var.project_name}-nat`
- `aws_route_table.private` に `route { cidr_block = "0.0.0.0/0", nat_gateway_id = aws_nat_gateway.main.id }` を足し、「localルートのみ」のコメントを直す
- 出力は変えない（`private_subnet_ids`・`public_subnet_ids`・`public_subnet_ids_by_key` ほか）
- セキュリティグループは変えない（ECS の入力 8000 は ALB から、RDS・キャッシュは ECS から、のまま）

## 2. alb（`infra/modules/alb/main.tf`）

- ターゲットグループの `target_type` を `"ip"` にし、コメント（「EC2起動タイプ+bridgeモード…」）を直す。ヘルスチェック・リスナーは変えない

## 3. ecs（`infra/modules/ecs/main.tf`・`variables.tf`）

削除するリソースとデータソース（7 リソース + 1 データソース）:
`aws_launch_template.ecs`、`data.aws_ssm_parameter.ecs_ami`、`aws_autoscaling_group.ecs`、`aws_ecs_capacity_provider.main`、`aws_ecs_cluster_capacity_providers.main`、`aws_iam_role.ecs_instance`、`aws_iam_role_policy_attachment.ecs_instance`、`aws_iam_instance_profile.ecs`

タスク定義（`backend`・`backend_migrate` の 2 つとも）:

```hcl
network_mode             = "awsvpc"
requires_compatibilities = ["FARGATE"]
cpu                      = var.cpu
memory                   = var.memory
runtime_platform {
  cpu_architecture        = "ARM64"   # イメージはARM64向けにビルドしているため
  operating_system_family = "LINUX"
}
```

- コンテナ定義から、コンテナ単位の `memory = 128` を削除する。`backend` の `portMappings` から `hostPort` を削除し、`containerPort = 8000` のみにする（awsvpc ではホストポートを持たない）。`backend_migrate` に `portMappings` はない
- ほかのコンテナ設定（環境変数、ログ、`lifecycle { ignore_changes = [container_definitions] }`）は変えない。コメントの「EC2モード」を直す

サービス `aws_ecs_service.backend`:

```hcl
launch_type = "FARGATE"
health_check_grace_period_seconds = var.health_check_grace_period_seconds

network_configuration {
  subnets          = var.private_subnet_ids
  security_groups  = [var.ecs_sg_id]
  assign_public_ip = false
}
```

- 削除: `deployment_minimum_healthy_percent`・`deployment_maximum_percent`（既定のローリング更新にする）、`capacity_provider_strategy`
- 維持: `desired_count = 1`、`load_balancer`、`lifecycle { ignore_changes = [task_definition] }`

変数:
- 削除: `public_subnet_ids`
- 追加: `private_subnet_ids`（list(string)）、`cpu`（number、既定 512）、`memory`（number、既定 1024）、`health_check_grace_period_seconds`（number、既定 240）。既定値は、移植元の変数の既定値と同じ

## 4. 環境（`infra/environments/dev`）

- `variables.tf`: `vpc_cidr`（string、既定 `"10.10.0.0/16"`）を足す。`validation { condition = can(cidrnetmask(var.vpc_cidr)) }` で、CIDR の形式を検査する
- `main.tf`: `module "network"` に `vpc_cidr = var.vpc_cidr`、`module "ecs"` の `public_subnet_ids` を `private_subnet_ids = module.network.private_subnet_ids` に置き換える
- `module "ecs"` に `depends_on = [module.network]` を足す。サービスの作成前に、NAT のルートが整っている必要があるため（Fargate のタスクは、イメージの取得とログ送信に NAT を使う）。ecs モジュールにはデータソースが残らないので、plan の評価が apply まで遅れることはない

## 5. CI（`.github/workflows/deploy-backend.yml`）

- `Resolve resource names` から `ECS_CAPACITY_PROVIDER` の出力を削除する
- `Run DB migration task` を次の形にする

```bash
NETWORK_CONFIG=$(aws ecs describe-services --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE} \
  --query 'services[0].networkConfiguration' --output json)
if [ -z "${NETWORK_CONFIG}" ] || [ "${NETWORK_CONFIG}" = "null" ]; then
  echo "::error::サービス ${ECS_SERVICE} のネットワーク設定を取得できません。サービスが存在することを確認してください。"
  exit 1
fi
MIGRATION_TASK_ARN=$(aws ecs run-task \
  --cluster ${ECS_CLUSTER} \
  --task-definition <登録したマイグレーションのタスク定義> \
  --launch-type FARGATE \
  --network-configuration "${NETWORK_CONFIG}" \
  --count 1 \
  --query 'tasks[0].taskArn' --output text)
```

- 起動に失敗して `tasks` が空のとき、`taskArn` が `None` になり、後続が分かりにくく失敗する。`None` なら、`failures` の内容を出して止める
- 「単一 EC2 上でもポート競合しない」というコメントを、Fargate の説明に直す
- タスク定義の登録に使う `jq` の `del(...)` は変えない（`runtimePlatform` を消さない。消すと ARM64 の指定が失われる）
