# 03_詳細設計

## 1. リポジトリ（`server/app/repositories/message_repository.py`）

`MessageRepository.find_by_tenant_id_and_room_id_with_feedback` を変更する。

- `func` を `sqlalchemy` からインポートする
- メッセージごとの「内容の作成日時」を、相関サブクエリで求める。結合はしない（`message_contents.message_id` に DB 上の一意制約がなく、結合するとメッセージの行が重複しうるため）

```python
content_created_at = (
    select(func.min(MessageContent.created_at))
    .where(
        MessageContent.message_id == Message.id,
        MessageContent.tenant_id == tenant_id,
    )
    .correlate(Message)
    .scalar_subquery()
)
stmt = (
    select(Message, MessageFeedback)
    .outerjoin(MessageFeedback, ...)            # 既存のまま
    .where(Message.tenant_id == tenant_id, Message.room_id == room_id)
    .order_by(content_created_at.asc().nulls_last(), Message.id.asc())
)
```

- 内容が複数あるメッセージは、最も古い作成日時（`min`）で並べる（通常は 1 メッセージに 1 内容。その場合は、移植元と同じ結果）
- `nulls_last()` で、内容のないメッセージを末尾にする。SQLite と PostgreSQL で、NULL の既定の扱いが違うため、明示する
- docstring（NumPy 形式、日本語）に、並び順と、その理由（編集・再生成で分かれた版の「最新」を、配列の末尾から一貫して選べるようにするため）、サブクエリにした理由を書く
- 戻り値の型・引数・フィードバックの結合・アクセス制御（呼び出し側の `require_viewable_room`）は変えない

## 2. サービス・ルーター・スキーマ

変更なし。`MessageService.get_messages` は、返ってきた順にそのままレスポンスを組み立てるので、並び順が API の返す順になる。
