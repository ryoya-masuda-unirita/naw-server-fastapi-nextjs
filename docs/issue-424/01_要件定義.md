# 01_要件定義

## 背景

- ルームのメッセージは、編集・再生成によって、同じ親から枝分かれする（同じ質問の、新旧の版が並ぶ）。画面（チャット）や追加学習は、配列の末尾から「最新の版」を選ぶ
- 現在の一覧取得には、並び順の指定がなく、データベースの返す順に依存する。同じ新旧 2 件でも、逆順で返るだけで、「最新の版」の選択が変わる（移植元で確認された不具合）
- `messages`（メッセージ）には、作成日時の列がない。やり取りの新旧は、回答の本文を持つ `message_contents`（メッセージ内容）の作成日時で決まる。移植元は、これで並べている

## 機能要件

1. ルームのメッセージ一覧を、メッセージ内容の作成日時の昇順（古い順）で返すこと
2. メッセージ内容が、まだ作られていないメッセージは、一覧の末尾に置くこと
3. 作成日時が同じ（または内容がない）メッセージは、メッセージ ID の昇順で並べ、呼び出しのたびに同じ順序になること
4. 1 つのメッセージが、一覧に複数回現れないこと（メッセージ内容の行が、データ上は複数ありえても、メッセージの行は増えない）
5. 返す項目（メッセージ・フィードバック・評価など）と、アクセス制御（テナント・ルームの閲覧権限）は、変えないこと
6. 並び順を確かめるテストを足すこと（作成日時が前後するメッセージ、内容がないメッセージ、同順位）

## 非機能要件

- 追加のクエリを増やさないこと（現在は、メッセージとフィードバックを 1 クエリで取得している。その 1 クエリの中で並べる）
- 並び順が、SQLite（テスト）と PostgreSQL（本番）の両方で、同じになること（「内容がないものは末尾」を、DB の既定の NULL の扱いに任せず、明示する）
- `ruff`・`mypy`・既存のテストが通ること
- 費用: なし（コードの変更のみ。AWS・インフラに触れない）

## スコープ外

- `client/` 側の追加学習の変更（#425）
- 一覧の返す項目の追加、ページングの追加
- ほかの一覧の並び順（#427）
- メッセージ内容の作成日時の更新の仕組みの変更
