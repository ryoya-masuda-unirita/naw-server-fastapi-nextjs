# 04_テスト設計

## テスト方針

API を通した統合テスト（SQLite のインメモリ）で、並び順を確かめる。PostgreSQL（本番）向けの SQL は、SQLAlchemy でコンパイルして、並びの指定が正しいことを確認する（実際の PostgreSQL では実行しない）。先にテストを書き、実装前に失敗することを確認する（移植元も、修正前で落ち、修正後に通ることを確かめている）。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 並び順（基本） | 挿入順と、内容の作成日時の順が違う 3 件 | 内容の作成日時の古い順に返る |
| 2 | 内容なし | 内容のないメッセージ（ID が最小） | 末尾に返る |
| 3 | 同順位 | 作成日時が同じ 3 件、内容のない 2 件（挿入順は ID の逆） | ID の昇順で返る。内容のないものは、その後ろ |
| 4 | 重複しない | 内容が複数あるメッセージ | 1 回だけ返り、最も古い作成日時で並ぶ |
| 5 | 既存の挙動 | 既存の `TestGetMessages`（6 件）と、メッセージ関連の既存テスト | すべて通る（返す項目・権限・404・403 は不変） |
| 6 | 実装前の失敗 | No.1〜4 を、実装前に実行 | 4 件とも失敗する（テストが並びを検証できている） |
| 7 | SQL | PostgreSQL・SQLite 向けにコンパイル | `ORDER BY (サブクエリ) ASC NULLS LAST, messages.id ASC` |
| 8 | 品質 | `ruff`（整形・検査）、`mypy` | エラーなし |
| 9 | 全体 | サーバーのテスト全体 | 既存の失敗を増やさない |
