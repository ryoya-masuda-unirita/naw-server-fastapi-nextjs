# Pythonの全プロジェクトにdocstringを付けruffで強制する

> この docs は Issue #311 のうち **`server-local/` の分**（1 本目の PR）を記録したもの。`waha-emulator/`・`generative-ai-adapter/`・`backend/` の分は、後続の PR で同じディレクトリに追記する。

## 概要

Python の各プロジェクトに docstring の無い関数・メソッド・クラスが大量にある（2026-11-13 時点で backend: 関数 160・メソッド 13・クラス約 290、server-local: 関数 77・メソッド 39・クラス 30、waha-emulator: 関数 15・メソッド 17・クラス 11）。**NumPy 形式**・日本語（Parameters/Returns/Raises）の docstring を全プロジェクトで付け、ruff の pydocstyle（D ルール、`convention = "numpy"`）で CI と pre-commit で強制する。

## 説明

### 進め方（衝突を避けるため、プロジェクトごとに別 PR）

1. `server-local/`（今すぐ）
2. `waha-emulator/`・`generative-ai-adapter/`（#298 のマージ後）
3. `backend/`（#307・#308・#309 のマージ後）

### 要件

- 対象: すべての関数・メソッド・クラス（private も含む）。モジュール・パッケージの docstring（D100・D104）は任意
- テスト関数は日本語 1 行の docstring
- ruff の設定で D101・D102・D103・D105・D106・D107・D417（と、google 規約で必要なもの）を有効にし、違反 0 にする。CI（backend-tests.yml など）と pre-commit で落ちるようにする
- docstring は中身に合った説明を書く（関数名を言い換えただけの文は不可）。挙動は変えない

### 形式の変更（2026-11-13 ユーザー指示）

- docstring は **NumPy 形式**にする（これまでの backend の規約は Google 形式だった）。既存の Google 形式（`Args:` 等）も NumPy 形式に書き換える
- `backend/.claude/CLAUDE.md` の「docstring」の規約と例も NumPy 形式に書き換える
