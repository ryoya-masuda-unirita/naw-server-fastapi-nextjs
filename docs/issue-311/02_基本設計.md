# 02_基本設計

## server-local の分（1 本目の PR）

### 変更対象

- server-local のアプリ本体（設定・DB・例外・ミドルウェア・外部 API クライアント・ルーター・スキーマ・モデル・リポジトリ・サービス・起動処理）とマイグレーションの docstring
- server-local のテスト（テスト関数・fixture・ヘルパー・フェイク）の docstring
- server-local の ruff の設定（pydocstyle のルールと規約）
- server-local 用の CI ワークフローの新設

### 画面 / API 変更概要

- 画面の変更なし。API の応答・挙動の変更なし
- FastAPI はルート関数と Pydantic モデルの docstring を OpenAPI（`/docs`・`/openapi.json`）の説明文に使うため、OpenAPI の説明文は増える。応答の形やステータスは変わらないため許容する

### 影響範囲

- 実行時の挙動: なし（docstring を除いた構文木が作業前と一致することで確認する）
- 開発フロー: server-local で docstring の無い public な関数・メソッド・クラス・`__init__`、または引数の説明が漏れた docstring を書くと、pre-commit と CI で落ちるようになる
- CI: server-local を変更した PR・push で新しいワークフロー（テスト・ruff）が走る

### 移植方針

- 移植元（Spring Boot の secuaigent-server-local）の挙動には関わらない。docstring では、移植元に合わせている実装はその旨を書く
- ruff の設定は、既定のルールを残したまま D ルールを足す（既定ルールを置き換えない）
- NumPy 規約は D107・D417 を既定で外すため、ルールを明示して有効にする
- private（先頭が `_`）の関数・クラスやテスト関数は ruff の D ルールでは検出されないため、規約として同じく書き、AST による自前の検査で漏れが無いことを確かめる
- CI はバックエンドのワークフローの書き方（uv・Python 3.12・ロックファイルの検証・paths 指定）に揃える

## waha-emulator の分（2 本目の PR）

### 変更対象

- `waha-emulator/pyproject.toml`: `[tool.ruff.lint]` に `extend-select`、`[tool.ruff.lint.pydocstyle]` に `convention = "numpy"` を追加（server-local と同じ設定）
- `waha-emulator/tests/test_registry.py`・`test_sessions.py`・`test_retrieval_workflow.py`: docstring の無いテスト用のフェイククラス・メソッド・ヘルパー・ネストした関数 11 件に docstring を付ける
- `.github/workflows/generative-ai-adapter-tests.yml`: `emulator` ジョブの `ruff check` に、D ルールも検査される旨のコメントを足す（動作は変えない）

### 影響範囲

- 実行時の挙動・API の応答: なし（docstring のみ）
- 開発フロー: waha-emulator で docstring の無い public な関数・クラス・メソッド・`__init__`、または引数の説明が漏れた docstring を書くと、pre-commit（ルートの設定が `waha-emulator/` を対象に含む）と CI で落ちる
- CI のワークフローは既存の `emulator` ジョブが `ruff check .` を実行するため、新設は不要
