# 01_要件定義

## server-local の分（1 本目の PR）

### 背景

- server-local には docstring の無い関数・メソッド・クラスが多く、あっても引数・戻り値・例外の節が無いものが多い。作業前の検査では、docstring なし 237 件（private・テスト・ネストした関数を含む）、引数の節の漏れ 51 件、戻り値の節の漏れ 48 件、例外の節の漏れ 11 件、複数行のテスト docstring 2 件があった
- ruff の pydocstyle を有効にした場合の違反は 162 件（public 関数 84・public メソッド 39・public クラス 30・`__init__` 9）
- server-local には CI のワークフローが無く、ruff・テストは pre-commit と手元での実行に頼っている

### 機能要件

1. server-local のすべての関数・メソッド・クラス（private・ネストした関数・`__init__`・テスト・fixture・テスト用のフェイクを含む）に docstring を付ける
2. 形式は NumPy 形式・日本語。1 行目は要約。引数・戻り値・例外があれば `Parameters`・`Returns`（ジェネレーターは `Yields`）・`Raises` の節を書く（節名の下に下線）
3. 説明はコードを読んだうえで、何をするか・なぜそうしているか（移植元に合わせている点、設計上の理由など）が分かる内容にする。名前の言い換えだけは不可
4. テスト関数は日本語 1 行（既存の書き方に揃え「〜こと」で終える）。複数行だったものは 1 行にまとめ、落とした補足は本体のコメントに移して情報を失わない
5. ruff の pydocstyle を NumPy 規約で有効にし、D101・D102・D103・D105・D106・D107・D417 の違反を 0 にする
6. pre-commit（ルートの設定）で docstring の漏れがあるとコミットが落ちることを確かめる
7. server-local 用の CI（テストと ruff）を追加し、PR と push で docstring の漏れが落ちるようにする

### 非機能要件

- コードの挙動を変えない（docstring 以外の変更をしない）
- テスト全件・ruff の検査・フォーマットの検査を通す

### スコープ外

- `waha-emulator/`・`generative-ai-adapter/`・`backend/` の docstring と ruff 設定（後続の PR）
- backend の規約文書の docstring の項を NumPy 形式に書き換えること（backend の PR で行う）
- モジュール・パッケージの docstring（任意のため有効にしない）
- mypy の CI への追加（server-local には既存の型エラーがあるため入れない）

## waha-emulator の分（2 本目の PR）

### 背景

- Issue 起票時（2026-11-13）の件数は waha-emulator で関数 15・メソッド 17・クラス 11 だったが、#298〜#300 の実装で NumPy 形式の docstring が付いたため、作業前の AST 検査（private・ネストした関数・テストを含む）では 333 件中 **docstring なしは 11 件**（すべて `tests/` の private なフェイククラスと、そのメソッド・ネストした関数）だった
- Google 形式（`Args:` など）の docstring は無かった
- `waha-emulator/pyproject.toml` の ruff は既定のルールのみで、D ルールは未設定だった。D ルールを有効にしても違反は 0 件（未記載の 11 件はすべて private か private クラスの中のため、ruff では検出されない）
- CI は `generative-ai-adapter-tests.yml` の `emulator` ジョブが既に pytest・`ruff format --check`・`ruff check`・mypy を実行している

### 機能要件

1. waha-emulator のすべての関数・メソッド・クラス（private・ネストした関数・テストを含む）に NumPy 形式・日本語の docstring があること
2. ruff に pydocstyle（`convention = "numpy"`）と D101・D102・D103・D105・D106・D107・D417 を有効にし、違反 0 にする
3. CI（既存の `emulator` ジョブの `ruff check`）で docstring の漏れが落ちること
4. コードの挙動を変えない

### スコープ外

- `generative-ai-adapter/`（#298〜#300 で対応済み）、`backend/`（後続の PR）
