# 03_詳細設計

## server-local の分（1 本目の PR）

### ruff の設定（`server-local/pyproject.toml`）

```toml
[tool.ruff.lint]
extend-select = ["D101", "D102", "D103", "D105", "D106", "D107", "D417"]

[tool.ruff.lint.pydocstyle]
convention = "numpy"
```

- `select` ではなく `extend-select` にして、既定のルール（E4・E7・E9・F）を残す
- `convention = "numpy"` は D107・D417 を既定で外すが、`extend-select` で明示すれば有効になることを確かめた（`__init__` に docstring が無い関数で D107、Parameters 節に引数が 1 つ足りない関数で D417 が出た）
- D100・D104（モジュール・パッケージ）は Issue で任意とされているため有効にしない
- 「google 規約で必要なもの」は、形式を NumPy に変えたため対象外。NumPy 規約の他のルール（要約の句読点など）は `extend-select` に含めない。日本語の要約は「。」で終わり、英語の句読点を前提とする D400 などと合わないため

### docstring の書き方

```python
def find_user(login_id: str, tenant_id: str) -> User | None:
    """ログインIDとテナントIDでユーザーを探す。

    Parameters
    ----------
    login_id : str
        ログインID。
    tenant_id : str
        テナントID。

    Returns
    -------
    User | None
        見つかったユーザー。いなければ None。
    """
```

- `self`・`cls` は Parameters に書かない。`*args`・`**kwargs` は `*args : 型` と書く
- `__init__` は自身の docstring に Parameters を書く（D107・D417 が `__init__` の docstring を見るため）
- dataclass・SQLModel・Pydantic のクラスは用途と、必要に応じて `Attributes` 節を書く
- ルーター関数は `Depends` で受け取る引数も Parameters に書き、サービスから伝わって HTTP エラーになる例外はステータスと一緒に Raises に書く
- 戻り値が `None` の関数は Returns を書かない。ジェネレーター・fixture の `yield` は `Yields` 節に書く
- テスト関数は 1 行。`test_indexes_request_values.py::test_upload_existing_file_without_user_id` と `test_message_request_and_finalize.py::test_concurrent_finalize_runs_once` は複数行だったため 1 行にまとめ、補足は関数本体の先頭のコメントに移した

### CI（`.github/workflows/server-local-tests.yml`）

- トリガー: `server-local/**` とワークフロー自身を変更した PR・push
- ジョブ `tests`: `uv sync --locked` → `uv run pytest -q`。テストは SQLite を一時ディレクトリに作り、外部サービスはフェイクに差し替え、設定もテスト内で組み立てるため、`.env` の準備や DB サービスは不要
- ジョブ `lint`: `uv run ruff format --check .` → `uv run ruff check .`（D ルールもここで検査される）
- mypy は入れない。server-local の依存に mypy が無く、実行すると既存の型エラーが 28 件出る（2026-11-13 時点、`uv run --with mypy mypy app tests`）

### pre-commit

- ルートの `.pre-commit-config.yaml` の ruff フックは `server-local/` を対象に含み、ruff はファイルごとに一番近い `pyproject.toml` の設定を読むため、設定ファイルの変更は不要
- docstring の無い public 関数・クラス・メソッドを置いたファイルで、フック（ruff v0.15.20）が D103・D101・D102 で落ちることを確かめた

### 判断したこと

- OpenAPI の説明文が増える点は、応答が変わらないため許容した（02 参照）
- 既存の docstring に Google 形式の節（`Args:` など）は無かった。節の無い既存の docstring は説明文を活かして NumPy 形式の節を追記した。短すぎる既存の説明（「@PreUpdate 相当。」など）は中身が分かるように書き直した
