# 04_テスト設計

## server-local の分（1 本目の PR）

### テスト方針

docstring の追加だけで挙動は変えないため、新しいテストケースは追加しない。挙動が変わっていないこと・docstring の漏れが無いこと・漏れを仕組みで検出できることを、次の検査で確かめる。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 挙動が変わっていない | 既存のテストを全件実行する | 全件成功する |
| 2 | 挙動が変わっていない | 変更したすべてのファイルで、docstring を除いた構文木を作業前と比べる | すべて一致する |
| 3 | docstring の漏れが無い（ruff の対象） | NumPy 規約で D101・D102・D103・D105・D106・D107・D417 を検査する | 違反 0 |
| 4 | docstring の漏れが無い（ruff の対象外） | private・ネストした関数・テストを含むすべての関数・クラスについて、docstring の有無と、引数・戻り値・明示的に送出する例外に対応する節の有無、Google 形式の節の残り、テストの docstring が 1 行かを検査する | 漏れ 0 |
| 5 | 形式・リンター | フォーマットとリンターの検査を実行する | すべて通る |
| 6 | pre-commit で強制される | docstring の無い public 関数・クラス・メソッドを置いたファイルにフックを当てる | フックが失敗する |
| 7 | pre-commit で通る | 変更したすべてのファイルにフックを当てる | すべて通る |
| 8 | CI で強制される | PR で新しいワークフローが走る | テストと ruff のジョブが成功する |
