# 08_動作確認

## 確認環境

- 自動テスト: Vitest（`client/`）、ESLint、TypeScript
- E2E: `e2e-spec` の専用 Docker 環境（`npm run spec:all -- -- tests/18-feedback.spec.ts`。backend・frontend・PostgreSQL・Redis・LocalStack。今のこのブランチの `client/`・`server/` でビルド。server には #475 の変更が入っている）
- 確認日: 2026-11-25

## 確認手順

1. 選択肢のテスト（`feedback-list.test.tsx`）を、実装を退避した状態で実行し、余分な選択肢が出て失敗することを確かめた。実装後は成功した
2. `npm run test`・`npm run lint`・`npm run type-check` を実行した
3. E2E の `18-feedback` を専用環境で実行した。比較のため、変更のない `origin/develop`（a85b9ad）でも、失敗した 15 項目すべて（2 回に分けて）を実行した

## 確認結果

### 自動テスト

- 追加した 2 件（回答精度評価・チャット満足度の並べ替えの選択肢）は、実装前に選択肢の差で失敗し、実装後に成功した
- `npm run test`: 142 ファイル・1453 件すべて成功
- `npm run lint`・`npm run type-check`: 問題なし
- `e2e-spec` の `npm run lint`・`npm run typecheck`: 問題なし

### E2E（18_フィードバック管理 52 項目）

結果: 27 成功・15 失敗・10 skip。

- 並べ替えの項目は成功した: 18-08（精度・アシスタント名）、18-09、18-12、18-13、18-14、18-26〜18-29（満足度の並べ替え。アシスタント名・満足度順を含む）、18-32、18-33
- 18-10・18-11・18-30・18-31 は、画面から選択肢が外れたため、理由つきで skip（意図どおり）
- 失敗の 15 件（18-03〜06、15、20、22〜25、34、47〜49、52）は、フィルターのドロップダウンを操作する項目で、いずれも 60 秒のタイムアウト。今回の変更とは関係がない。変更のない `origin/develop` で 15 件すべてを実行し、15 件すべて同じく失敗した
- 失敗の原因: #471 のアクセシビリティ修正で、検索付きセレクトのトリガーが `<input role="combobox" aria-haspopup="listbox">` になった。E2E の `filter()`（`:not(input)` で入力欄を除く locator）が本物のトリガーを除き、フィルターの番号がずれる（18-03 では精度のドロップダウンが開くことをスクリーンショットで確認）。対応は #498
