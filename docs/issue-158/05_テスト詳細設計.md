# 05_テスト詳細設計

`04_テスト設計.md`の各Noに対応する具体的な確認コマンド・手順。

## No.1 ネットワーク到達性

```bash
curl -i http://<ECSホストのパブリックIP>:8000/api/health   # 実際のヘルスチェックパスはbackend実装を確認
```

期待結果: `HTTP/1.1 200 OK`

## No.2 RDS疎通（マイグレーション・シード投入）

```bash
ssh -i bastion-key.pem -L 5433:<RDSエンドポイント>:5432 ec2-user@<踏み台パブリックIP>
# 別ターミナルで
cd backend
DATABASE_URL=postgresql+asyncpg://root:***@localhost:5433/postgres uv run alembic upgrade head
docker exec -i naw-fastapi-postgres psql ... # ではなく、踏み台トンネル経由でpsqlから直接investigate
psql "postgresql://root:***@localhost:5433/postgres" -f backend/seed.sql
```

期待結果: マイグレーションが最新まで適用され、seed.sqlのINSERTがエラーなく完了する

## No.3 RDS遮断確認

```bash
psql "postgresql://root:***@<RDSエンドポイント>:5432/postgres" -c "select 1"
```

実行元: ローカルPC（踏み台を経由しない）
期待結果: 接続がタイムアウトする、または拒否される

## No.4 踏み台経由の接続確認

pgAdmin4で以下のSSHトンネル設定を行い接続する。

- SSH Tunnel: Host=踏み台パブリックIP、Username=ec2-user、Private Key=bastion-key.pem
- DB Host: RDSエンドポイント（トンネル経由）

期待結果: 接続でき、`users`テーブル等にseed投入したレコードが見える

## No.5 ElastiCache疎通

```bash
docker logs <backendコンテナ相当のECSタスクログ>   # CloudWatch Logsで確認
```

期待結果: Redis接続エラー（`ConnectionRefusedError`等）が出ていない

## No.6 ALB HTTPS疎通

```bash
curl -i https://<ip>.sslip.io/api/health
openssl s_client -connect <ip>.sslip.io:443 -servername <ip>.sslip.io </dev/null | openssl x509 -noout -dates
```

期待結果: 200が返り、証明書の有効期限が現在時刻を含んでいる（自己署名でないことも確認）

## No.7 同一オリジンAPIリバースプロキシ経由のCookie認証

1. ブラウザでCloudFrontのURLを開く
2. ログイン操作を行う（`frontend-angular`は相対パス`/api`・`/auth`でリクエストするため、ログインリクエスト先はCloudFrontと同一オリジンの`/auth/...`になる。CloudFront側で`/auth/*`をALBへ転送する設定がされていること）
3. ブラウザの開発者ツール（Network/Application）で以下を確認する
   - ログインレスポンスの`Set-Cookie`ヘッダーに`SameSite=Lax; Secure`が含まれる
   - 以降のAPIリクエスト（`/api/...`）で同Cookieが送信され、認証済み扱いになっている
   - リロード後もログイン状態が維持されている

期待結果: 上記すべてが成立する（Issue #147のセッションCookie認証がCloudFront経由のリバースプロキシ構成で正しく機能する）
