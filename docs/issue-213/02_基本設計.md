# 02_基本設計

## 変更対象

| 区分 | 変更内容 |
|---|---|
| Angular 版フロント | ディレクトリごと削除 |
| CI/CD | フロントのデプロイジョブを React 版のビルド・配信に置き換える。変更検知の対象も React 版のディレクトリに変える |
| React 版フロント（ビルド設定） | 本番ビルド時の API ベース URL を空（相対パス）にする設定を追加する。API クライアントが相対パスのベース URL でも URL を組み立てられるようにする |
| インフラ（CDN） | SPA の画面パスと backend の認証 API のパスが重なる箇所で、画面の直接表示・再読み込みが壊れないよう、エラー応答の扱いを 1 件追加する |
| ローカル開発（コンテナ定義） | Angular 版の起動定義と専用ボリュームを削除する |
| backend | CORS 許可オリジンの例・テストの例示値・コメントから Angular 版前提を外す（動作は変えない） |
| ドキュメント・AI 設定 | 同期スキルを削除し、各設定・README の記述を React 版前提に書き換える |

## 画面 / API 変更概要

- API の仕様変更はない
- 画面の変更はない。React 版の API 呼び出し先の決め方だけを変える
  - ローカル開発（開発サーバー）: これまでどおり環境変数の API URL（絶対 URL）を使う
  - 本番ビルド（dev 環境配信用）: API URL を空にし、配信元と同じオリジンの相対パス（`/api/...`・`/auth/...`）で呼ぶ。CDN が `/api/*`・`/auth/*` を backend に転送する既存の構成をそのまま使う

### 画面パスと API パスの重なり

- React 版のログイン画面・パスワードリセット画面は `/auth/...` 配下にある（移植元 Angular と同じ）。CDN は `/auth/*` を backend に転送するため、これらの画面を直接開くと backend に届く
- `/auth/login` は backend のログイン API（POST のみ）と同じパスで、画面として GET すると backend は 405 を返す。React 版はログアウト時・パスワードリセット遷移時にページ全体を読み込み直すため、この状態ではログアウト後に画面が表示されない
- パスだけでは画面と API を振り分けられないので、CDN のエラー応答設定に「405 のときは SPA の index.html を 200 で返す」を追加する。既存の 403/404 と同じ仕組みで、ブラウザの画面遷移だけでなく API の 405 も index.html に置き換わるが、dev 環境限定で既存の 403/404 と同じ扱いになるため許容する

## 影響範囲

- dev 環境のフロント配信が Angular 版から React 版に変わる。React 版は移植済み画面（ログイン・パスワードリセット・ダッシュボード）しかないため、dev 環境で使える画面は減る
- React 版のログイン画面にはテナントID入力欄がない（ログイン後にセッション取得 API のレスポンスからテナントIDを得る作りだが、そのセッション取得 API もテナントIDヘッダ必須で、レスポンスにテナントIDもないため成り立たない）。backend のログイン API はテナントIDヘッダを必須にしているため、入力欄を移植するまでは dev 環境でもローカルでも React 版からログインできない（本 Issue のスコープ外。PR・動作確認に明記する）
- backend の動作は変わらない（CORS 許可オリジンは環境変数で決まり、dev 環境は CDN のドメインだけを許可している）
- Angular 版を前提にしていた E2E テスト（Playwright）は削除され、ブラウザ経由の自動テストはなくなる

## 移植方針

- 移植元からの機能移植はない
- Angular 版のデプロイで考慮していた「本家の本番 API ドメインをビルドに含めない」は、React 版では本番ビルド用の環境設定ファイルで API URL を空にすることで満たす
