## 2. CI/CD

## 3. React 版（API ベース URL）

### `frontend/.env.production`（新規）

```
VITE_API_URL=
```

- Vite は `vite build`（mode=production）で `.env` → `.env.production` の順に読み、後者が優先される。git 管理の `frontend/.env`（`http://localhost:8000`）がビルドに入らないよう空で上書きする
- コメントで理由（CloudFront が `/api/*`・`/auth/*` を backend へ転送するため相対パスで呼ぶ）を書く

### `frontend/src/lib/api-client.ts`

- 現状 `get` が `new URL(\`${API_BASE_URL}${path}\`)` を使っており、ベース URL が空だと `TypeError: Invalid URL` になる。`post` は `fetch` に文字列を渡しており、ブラウザでは相対パスで動くが Node（テスト）では動かない
- `buildUrl(path, params?)` を追加し、`new URL(\`${API_BASE_URL}${path}\`, window.location.origin)` で URL を組み立てる。ベース URL が絶対 URL のときは第 2 引数は無視されるため、ローカル開発の挙動は変わらない
- `API_BASE_URL` は `import.meta.env.VITE_API_URL ?? ''` とし、未定義でも `undefined/api/...` にならないようにする

## 4. インフラ（`infra/cloudfront.tf`）

- `custom_error_response { error_code = 405, response_code = 200, response_page_path = "/index.html" }` を追加
- 理由: React の `/auth/login` は backend の `POST /auth/login` と同じパスで、CloudFront の `/auth/*` ビヘイビアで ALB に転送される。`GET /auth/login` は FastAPI が 405 を返すため、ログアウト時（`window.location.href = '/auth/login'`）や再読み込みで画面が出ない。`/auth/pw-reset` は backend が 404 を返し、既存の 404 → index.html で表示される
- `error_caching_min_ttl` は既存の 403/404 と同じく既定値（10 秒）のままにする
