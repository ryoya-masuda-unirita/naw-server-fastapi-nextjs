# 04_テスト設計

## テスト方針

- React 版の API 呼び出し先の決め方は単体テストで確認する
- 本番ビルドの成果物に、開発者のローカル URL や本家のドメインが含まれないことをビルド結果で確認する
- backend は動作を変えないため、既存の全テスト・型チェック・lint が通ることで確認する
- インフラ定義は書式チェック・構文検証で確認する（実環境への反映はマージ後）
- Angular 版前提の記述が過去の作業記録以外に残っていないことを検索で確認する

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | API ベース URL（相対） | API URL が空のとき GET（クエリ付き）を呼ぶ | 配信元オリジン + パス + クエリに送信される |
| 2 | API ベース URL（相対） | API URL が空のとき POST を呼ぶ | 配信元オリジン + パスに送信される |
| 3 | API ベース URL（絶対） | API URL が絶対 URL のとき GET を呼ぶ | その URL + パスに送信される（従来どおり） |
| 4 | 既存画面 | React 版の既存単体テスト一式 | すべて成功 |
| 5 | 本番ビルド | React 版を本番ビルドする | 成功し、成果物にローカル URL が含まれない |
| 6 | 静的解析 | React 版の lint・型チェック | エラーなし |
| 7 | backend 回帰 | backend の全テスト・型チェック・lint | すべて成功 |
| 8 | インフラ定義 | 書式チェック・構文検証 | 差分・エラーなし |
| 9 | 参照の残存 | 過去の作業記録以外で Angular 版のディレクトリ名・4201 を検索 | ヒットしない |
