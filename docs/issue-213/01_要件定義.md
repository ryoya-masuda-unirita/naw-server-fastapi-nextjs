# 01_要件定義

## 背景

- Angular 版フロント（上流 `secuaigent/client` のコピー）は、React 移植が終わるまでの backend 動作確認用としてリポジトリに置いていた
- 2026-11-12 のユーザー判断で不要になったため削除する。dev 環境のフロント配信も React 版に切り替える
- Angular 版は同期のたびに上流で上書きされ、サブドメイン廃止（#193）の差分が巻き戻るなどの手間もあった

## 機能要件

1. Angular 版フロントのソース一式（E2E テストを含む）をリポジトリから削除する
2. dev 環境の自動デプロイ（develop への push）で、React 版フロントをビルドし、これまでと同じ静的ファイル置き場・配信（CDN）に載せる
   - API は配信元と同じオリジンの相対パスで呼ぶ。本家（上流）の本番ドメインや開発者のローカル URL をビルドに含めない
   - React 版の画面パス（ログイン画面等）を直接開いた・再読み込みしたときも画面が表示されること
3. ローカル開発用のコンテナ定義から Angular 版の起動定義を削除する
4. backend の CORS 許可オリジンの例から Angular 版の開発サーバー（ポート 4201）を外し、React 版の開発サーバーのオリジンだけを残す
5. AI エージェント向けの設定・スキル・README から Angular 版前提の記述を外す
   - 同期スキル（Claude 用・Codex 用）を削除する
   - backend の動作確認（ブラウザ操作）は「自動テスト、または React 版の移植済み画面で行う」に変える
   - テナント識別方式（サブドメイン廃止）の説明は、React 版にも同じ方針（ログイン画面でテナントIDを入力 → テナントIDヘッダで送信）が必要であること、React 版の現状を正確に書く
6. 過去の作業記録（`docs/`）は変更しない

## 非機能要件

- backend の既存テスト・型チェック・lint がすべて通ること
- React 版のビルド・単体テスト・lint・型チェックが通ること
- インフラ変更は最小限にし、PR に明記する

## スコープ外

- React 版の未移植画面の実装（ログイン画面のテナントID入力欄を含む）
- React 版の E2E テスト作成
- 配信設定の既存の挙動のうち、本 Issue と無関係なもの（API の 403/404 応答の扱い等）の見直し
- dev 環境への実デプロイ確認（CI の認証が develop ブランチにしか許可されていないため、マージ後に確認する）
