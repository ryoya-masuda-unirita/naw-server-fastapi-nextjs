## 未確認事項

- **dev 環境への実デプロイ（S3 配信・CloudFront 反映・`terraform apply`）**: CI の OIDC が `develop` ブランチにしか許可されていないため、マージ後の `Deploy` ワークフローで確認する。マージで `infra/**` と `frontend/**` の両方が変わるため、infra ジョブ（CloudFront の 405 設定）→ frontend ジョブ（React の配信）の順に実行される想定
- **CloudFront 経由の画面表示**: `/`・`/dashboard`（S3 の 404 → index.html）、`/auth/login` の直接表示・ログアウト後の遷移（backend の 405 → index.html）、`/auth/pw-reset`（backend の 404 → index.html）は、マージ後にブラウザで確認が必要
- **React からのログイン**: ログイン画面にテナントID入力欄がなく、backend の `POST /auth/login` は `X-Tenant-ID` 必須のため、React からはローカルでも dev 環境でもログインできない（スコープ外。入力欄の移植は別 Issue で対応が必要）。dev 環境は切り替え後、ログインが必要な画面を使えなくなる
- **フォントの配信**: 上記のビルド警告のとおり `@fontsource` のフォントは `/assets/files/*.woff` を実行時に参照するが、`dist/` には含まれない。CloudFront では 404 → index.html になり、フォントは代替フォントで表示される見込み（既存の問題。本 Issue では対応しない）
- **CloudFront のエラー応答置き換えの副作用**: 既存の 403/404 に加えて 405 も index.html（200）に置き換わるため、`/api/*`・`/auth/*` の 403/404/405 応答は、dev 環境ではブラウザに HTML（200）として届く。403/404 は既存の挙動、405 は今回追加分
