# 05_テスト詳細設計

## 対象ファイル

`backend/tests/integration/test_assistants.py`（`TestDeleteAssistant` クラス）

## テストケース詳細

### test_delete_assistant_keeps_messages_and_sets_assistant_id_null

- **区分**: integration（実DB接続、FK制約の実挙動を検証）
- **前提データ**:
  - `tenant`・`member_user`・`assistant`（削除対象）フィクスチャを使用
  - `other_assistant`: テスト内で新規作成する、削除対象とは別のアシスタント
  - `room`: `default_assistant_id=other_assistant.id` で作成（削除対象アシスタントをRESTRICT対象にしないため）
  - `message`: `room_id=room.id`, `assistant_id=assistant.id`（削除対象）で作成
- **操作**: `DELETE /api/admin/assistants/{assistant.id}` を管理者権限で呼び出す
- **期待結果**:
  - HTTPステータス: `204 No Content`
  - `session.refresh(message)` 後、`message.assistant_id is None`
- **検証の意図**: `backend/alembic/versions/012_add_messages.py` の `fk_messages_assistant_id`（`ondelete="SET NULL"`）と `app/models/message.py` の `assistant_id: str | None` 定義が、実際のDB挙動として機能していることを担保する。将来、誤って `ondelete` をCASCADEに変更してしまった場合などにこのテストが失敗し検知できる。
