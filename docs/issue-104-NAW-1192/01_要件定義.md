# 01_要件定義

## 背景

naw-server（Spring Boot）側のコミット `2027e2cbab6283f7fb95e2724645a5f102519f48`（NAW-1192）は、以下の不具合を修正している。

- 修正前: `messages.assistant_id` が `NOT NULL` かつ、DB上のFK制約が実質CASCADE相当の挙動になっており、アシスタントを削除すると、そのアシスタントを使った既存チャット（Message）が根こそぎ削除されてしまう。
- 修正後:
  - `messages.assistant_id` を nullable に変更し、FK制約を `ON DELETE SET NULL` で再作成（アシスタント削除時はメッセージを残したまま `assistant_id` のみ `NULL` にする）
  - `rooms.default_assistant_id` のFK制約を `ON DELETE RESTRICT` で再作成（デフォルトアシスタントとして参照中のルームがある場合は削除自体を拒否する）
  - `AssistantService.delete()` で `DataIntegrityViolationException` を捕捉し、`AssistantInUseException` → HTTP 409 Conflict に変換する

Issue #104 起票時点では、FastAPI側 `backend/app/models/message.py` にこの修正が未反映と認識されていた（`docs/調査結果/20260711.md` 4章 項目9）。

## 着手時の調査結果（重要）

Issue着手にあたり `backend/app/models/message.py`・`backend/app/models/room.py`・対応するAlembicマイグレーション（`011_add_rooms_and_room_pins.py`・`012_add_messages.py`）・`backend/app/services/assistant_service.py` を確認したところ、**起票時の認識と異なり、FastAPI側は既に本修正相当のFK制約・例外ハンドリングを実装済み**であることが判明した。

- `Message.assistant_id`（`app/models/message.py`）: `str | None`（nullable）、`sa.ForeignKey("assistants.id", ondelete="SET NULL")` で定義済み
- `alembic/versions/012_add_messages.py`: `fk_messages_assistant_id` を `ondelete="SET NULL"` で作成済み
- `Room.default_assistant_id`（`app/models/room.py`）: `sa.ForeignKey("assistants.id", ondelete="RESTRICT")` で定義済み（`NOT NULL`）
- `alembic/versions/011_add_rooms_and_room_pins.py`: `fk_rooms_default_assistant_id` を `ondelete="RESTRICT"` で作成済み
- `AssistantService.delete_assistant()`（`app/services/assistant_service.py`）: `IntegrityError` を捕捉し `HTTPException(400, ...)` に変換する実装が既に存在（Issue #42 で実装済み）

これらは、Room機能移植（Issue #45・#48）の時点で、アシスタントを参照する `messages.assistant_id` を最初から nullable + `SET NULL` として設計していたために、naw-server側の元々のバグ（CASCADE削除でチャットが消える）がFastAPI側にはそもそも存在しなかったことによる。

一方で、以下の2点は naw-server の修正後の挙動と一致していない。

1. **回帰テストの欠如**: 「アシスタント削除時にメッセージが消えず `assistant_id` が `NULL` になる」ことを直接検証する自動テストが存在しない（`rooms.default_assistant_id` によるRESTRICT/400のテストは `tests/integration/test_assistants.py::TestDeleteAssistant` に既存）。
2. **ステータスコードの差異**: naw-server は使用中エラーを **409 Conflict**（`AssistantInUseException`）で返すが、FastAPI側は既存実装で **400 Bad Request** を返す。

## 機能要件

- アシスタントを削除した際、そのアシスタントを使用しているメッセージ（`messages`）は削除されず、`assistant_id` が `NULL` になることを保証する（既存実装の確認 + 回帰テストによる担保）
- デフォルトアシスタントとして参照中のルームがある場合はアシスタント削除自体が失敗すること（既存実装・既存テストで担保済み。本Issueでは変更しない）

## 非機能要件

- 既存のAPIレスポンス仕様（ステータスコード・メッセージ文言）に対する後方互換性を壊さない

## スコープ外

- **ステータスコードを400→409に変更すること**: `docs/調査結果/20260711.md` 5章に「issue-42：ルーム視点でのアシスタント参照・デフォルトアシスタント削除時の409判定 → 未起票」と明記されている通り、この差異は本Issue（#104）が対象とするNAW-1192のFK制約変更とは別の、未起票の独立したスコープとして整理されている。Issue #104本文の「スコープ（想定）」にも400→409変更は含まれていないため、本Issueでは対応しない。対応が必要な場合は別Issueとして起票する。
- room（チャット本体）ドメイン自体の新規実装（既に実装済みのため対象外）
