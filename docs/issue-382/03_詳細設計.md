# 03_詳細設計

## 1. ディレクトリ構成（変更後）

```
infra/
├── bootstrap/                 # #381。変更しない
├── route53/                   # #383 で削除。変更しない
├── scripts/seed_via_bastion.sh
├── environments/dev/
│   ├── main.tf                # terraform（backend・required_providers）、provider、モジュール呼び出し
│   ├── variables.tf           # 現行の variables.tf をそのまま移す
│   ├── outputs.tf             # 現行の outputs.tf（モジュールの出力を参照する形）
│   ├── terraform.tfvars.example
│   └── .terraform.lock.hcl
└── modules/
    ├── network/ rds/ elasticache/ ecr/ alb/ ecs/ github-actions/ bastion/ user-import/
    └── frontend/              # functions/（spa_fallback.js・strip_backend_prefix.js・functions.test.mjs）を含む
```

各モジュールは `main.tf`・`variables.tf`・`outputs.tf` の 3 ファイル（移植元と同じ）。`backend.hcl`（実体・git 管理外）の置き場所は `infra/environments/dev/`。

## 2. リソースの移し先（元のファイル → モジュール）

| 元 | 移し先 | リソース |
|---|---|---|
| `network.tf`・`security_groups.tf` | `modules/network` | VPC、サブネット（public / private）、IGW、ルートテーブルとその関連付け、セキュリティグループ 5 種（bastion・alb・ecs・rds・elasticache）とそのルール |
| `rds.tf` | `modules/rds` | サブネットグループ、DB インスタンス |
| `elasticache.tf` | `modules/elasticache` | サブネットグループ、レプリケーショングループ |
| `ecr.tf` | `modules/ecr` | リポジトリ |
| `alb.tf` | `modules/alb` | ALB、ターゲットグループ、HTTP リスナー |
| `ecs.tf`・`iam.tf` | `modules/ecs` | クラスタ、起動テンプレート、SSM パラメータ（AMI）、ASG、キャパシティプロバイダ、ログ 2 つ、タスク定義 2 つ、サービス、IAM ロール（実行・インスタンス・タスク）とポリシー、インスタンスプロファイル |
| `cloudfront.tf`・`s3.tf` | `modules/frontend` | S3 バケット、public block、OAC、バケットポリシー、ディストリビューション、CloudFront Function 2 本 |
| `github_oidc.tf` | `modules/github-actions` | OIDC プロバイダ、ロール、ポリシー・アタッチメント |
| `bastion.tf` | `modules/bastion` | AMI のデータソース、インスタンス |
| `s3_user_import.tf`・`sqs.tf` | `modules/user-import` | バケット、public block、キュー、DLQ |

リソースの種類・名前（ラベル）・属性は変えない。変えるのは、別のモジュールのリソースを参照している箇所を変数に置き換えることだけ。

## 3. モジュールの入出力（モジュールをまたぐ参照の置き換え）

共通の入力として `project_name` を全モジュールに、`region` を ecs に渡す。

| モジュール | 入力（元の参照） | 出力 |
|---|---|---|
| network | `allowed_ssh_cidrs`・`allowed_admin_cidrs` | `vpc_id`、`public_subnet_ids`、`private_subnet_ids`、`public_subnet_ids_by_key`（bastion が `values(...)[0]` を使うため、元と同じ順序で選べるようにする）、`alb_sg_id`・`ecs_sg_id`・`rds_sg_id`・`elasticache_sg_id`・`bastion_sg_id` |
| rds | `private_subnet_ids`、`rds_sg_id`、`db_password` | `endpoint`、`address`、`username`、`db_name`（ecs の接続文字列に使う項目） |
| elasticache | `private_subnet_ids`、`elasticache_sg_id` | `primary_endpoint_address` |
| ecr | なし | `repository_url` |
| alb | `vpc_id`、`public_subnet_ids`、`alb_sg_id` | `dns_name`、`target_group_arn`（`depends_on` でリスナーに依存させ、元の `depends_on = [aws_lb_listener.http]` と同じ順序を保つ） |
| frontend | `alb_dns_name` | `bucket_arn`、`bucket_name`、`distribution_id`、`distribution_arn`、`domain_name` |
| user-import | なし | `bucket_name`、`bucket_arn`、`queue_url`、`queue_arn` |
| ecs | `public_subnet_ids`、`ecs_sg_id`、`ecr_repository_url`、`rds_*`（上記）、`db_password`、`secret_key`、`redis_endpoint`、`cloudfront_domain_name`、`user_import_bucket_name`・`user_import_bucket_arn`・`user_import_queue_url`・`user_import_queue_arn`、`target_group_arn`、`region` | `execution_role_arn`、`task_role_arn`、`cluster_name`、`service_name` |
| github-actions | `ecs_task_execution_role_arn`、`backend_task_role_arn`、`frontend_bucket_arn`、`cloudfront_distribution_arn`、`tfstate_bucket_name` | `role_arn` |
| bastion | `public_subnet_id`、`bastion_sg_id`、`key_pair_name` | `public_ip` |

依存の向き: network → rds / elasticache / alb / bastion、alb → frontend → ecs、user-import・ecr・rds・elasticache → ecs、ecs・frontend → github-actions。循環はない。

## 4. 環境（dev）

- `main.tf` に、現行の `terraform { ... backend "s3" { ... } }` と provider を移す。`backend` の `key` は `dev/terraform.tfstate` にする（移植元と同じ。新アカウントなので影響なし）
- 各モジュールを `source = "../../modules/<名前>"` で呼び出し、入力を上の表のとおり渡す
- `variables.tf` は現行をそのまま移す（名前・型・既定値・説明を変えない）
- `outputs.tf` は、現行と同じ名前の出力を、モジュールの出力から作る（`cloudfront_domain_name`、`cloudfront_distribution_id`、`frontend_bucket_name`、`github_actions_role_arn`、`alb_dns_name`、`rds_endpoint`、`ecr_repository_url`、`bastion_public_ip`、`user_import_bucket_name`、`user_import_queue_url`）
- `terraform.tfvars.example` は現行をそのまま移す
- 現行の `infra/*.tf`・`.terraform.lock.hcl`・`terraform.tfvars.example` は、移した後に削除する（`git mv` で履歴を残す）

## 5. 配信用の関数

- `cloudfront_functions/` を `modules/frontend/functions/` に `git mv` する
- `file("${path.module}/cloudfront_functions/...")` を `file("${path.module}/functions/...")` に直す
- `functions.test.mjs` の先頭コメントの実行方法（`cd infra && node --test cloudfront_functions/...`）を、新しいパスに直す

## 6. CI・スクリプト・手順書

- `deploy-infra.yml`: `working-directory` を `infra/environments/dev` にする。関数のテストは `node --test ../../modules/frontend/functions/functions.test.mjs`
- `seed_via_bastion.sh`: `terraform output` を実行するディレクトリを `infra/environments/dev` にする（`INFRA_DIR` はスクリプトの置き場所の親のまま、出力の取得先だけを `ENV_DIR` として分ける）。先頭コメントも直す
- `deploy.yml`: 変更なし（`infra/**` の判定は変わらない）
- `.pre-commit-config.yaml`: `files: ^infra/` のままで変更なし（fmt は配下すべてに効く）
- `infra/README.md`: ディレクトリ構成の図、構築手順（`cd infra/environments/dev`）、`backend.hcl` の出力先（`../environments/dev/backend.hcl`）、`terraform.tfvars` の場所、`terraform output` を使う `gh` コマンド（`-chdir`）を直す
- `infra/bootstrap/main.tf` の先頭コメントの `../backend.hcl` を `../environments/dev/backend.hcl` に直す
- `infra/backend.hcl.example` は `infra/environments/dev/` に移す
