### backend/app/services/auth_service.py の修正（移植漏れの修正）

E2Eテストケース設計中に、`03_ログイン.md`項番11（期限切れPW遷移）に対応するbackendロジックが存在しないことが判明した。

- frontend側（`pw-reset.component.ts`）は`reason: 'EXPIRED'`のケースを既に想定・テスト済みだった
- backend側（`AuthService.login`）は`user.is_required_password_reset`のみを見て常に`reason="INITIAL"`を返し、`password_histories.expired_at`（パスワード有効期限、`tenant.pw_validity_period_days`から計算される。既に存在するカラム）を一切参照していなかった

移植元Spring Boot（`~/Documents/secuaigent/server`）の`PasswordResetService.evaluate()`を確認したところ、以下の仕様であることが判明した。

- `latest.expired_at`が現在時刻より過去なら`EXPIRED`
- そうでなく`user.is_required_password_reset`が`true`なら`INITIAL`
- **両方に該当する場合は`EXPIRED`が優先される**
- `pw_validity_period_days`のデフォルトは90日（テナント設定）

この仕様通り`AuthService.login`に判定分岐を追加した。

```python
# 移植元のPasswordResetService.evaluateと同じ優先順位で判定する。
# EXPIRED（有効期限切れ）はINITIAL（初回ログイン）より優先される。
if latest.expired_at is not None and latest.expired_at < datetime.now(timezone.utc):
    return AuthResponse(
        id=user.login_id,
        name=user.name,
        role=user.role.value,
        groups=[],
        loginStatus="REQUIRES_PASSWORD_RESET",
        reason="EXPIRED",
    )

if user.is_required_password_reset:
    return AuthResponse(
        ...
        reason="INITIAL",
    )
```

既存テストで`get_latest`のモックに`expired_at`を明示していなかったため、`MagicMock`の自動属性（`None`でも実DateTimeでもない）と`datetime`の比較で型エラーになる問題があり、既存テスト2件に`expired_at=None`を明示する修正も行った。加えて、EXPIRED判定用テスト・EXPIREDとINITIALの優先順位を検証するテストを追加した（`tests/unit/test_auth_service.py`）。

`pytest tests/unit`（262件）・`mypy`・`ruff`とも成功を確認済み。実環境（`docker compose`起動中のbackend）でも`curl`でEXPIRED/INITIAL両方のレスポンスを確認済み。

### backend/seed.sql への追加

`ON CONFLICT DO NOTHING`で既存データに影響を与えない形で、以下2ユーザーを追加した（実装・投入・API確認済み）。

- `first-login-user`（password: `firstlogin@1234`）：`is_required_password_reset=true`（項番10対応）
- `expired-password-user`（password: `expired@1234`）：`password_histories.expired_at`を`now() - interval '1 day'`にして有効期限切れを再現（項番11対応）
