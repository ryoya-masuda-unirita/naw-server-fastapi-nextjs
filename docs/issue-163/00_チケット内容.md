# 結合テスト項目書のE2E自動化基盤を構築する（Playwright）

## 概要

`25DA61_結合テスト項目書_md/` に格納された旧システム（Spring Boot + Angular）の手動結合テスト項目書（全20カテゴリ、616〜627項目）を、ローカル環境で全自動実行できるE2Eテストとして整備する基盤を作る。

## 説明

### 背景

現状これらのテスト項目はすべて手動実施を前提としたExcel由来のもので、自動化されていない。ローカル環境（`frontend-angular` http://localhost:4201 + `backend` http://localhost:8001）で繰り返し実行できるE2Eテストとして自動化したい。

### スコープ（本Issue）

**本Issueはテスト自動化の"基盤構築"のみを対象とする。616項目全ての自動化（各カテゴリのテストケース実装）は対象外とし、カテゴリ単位で後続Issueに分割する。**

- Playwrightの導入（`frontend-angular/`配下、または独立した`e2e/`ディレクトリ）
- ローカル環境（docker-compose PostgreSQL + backend + frontend-angular）を対象にした実行構成
- 認証（ログイン）を伴うテストのための共通セットアップ（ログイン処理のfixture化、テナント付きURLでのアクセス等）
- テストデータ（`seed.sql`）との整合、または専用のE2E用シードデータ方針の検討
- 1カテゴリ（`03_ログイン.md`）を試験実装し、全自動実行できることを確認する
- 実行コマンド・レポート出力（失敗時のスクリーンショット等）の整備
- `docs/issue-163/` にテスト自動化の設計方針をまとめる

### スコープ外（後続Issueで対応）

- `04_ログアウト.md`〜`22_Waha!生成AI検索.md`の各カテゴリの網羅的なテストケース実装
- CI（GitHub Actions）への組み込み（Issue #161のCI/CDパイプラインと連携する可能性はあるが、まずはローカルでの全自動実行を優先する）
