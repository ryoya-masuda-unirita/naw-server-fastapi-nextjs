# 01_要件定義

## 背景

- `GET /api/admin/feedbackUser`（回答数一覧タブ）は `feedbacks` ラッパーを持たず
  `{content, totalElements, number, size}` を直接返している
- frontendは `data.feedbacks.totalPages` を参照するため、`feedbacks` が無いと
  TypeErrorで画面がクラッシュする
- 移植元 Spring Boot は `feedbackUser`・`feedbackMessage`・`feedbackRoom` の3APIすべてを
  `feedbacks` でラップして返しており、`feedbackUser` だけが移植時に漏れている
- feedback系3APIとも `totalPages`・`numberOfElements` を返しておらず、ページ送りが機能しない
  （frontendの型定義には存在するがbackendが返していないフィールド。frontendのコードを
  調査した結果、実際に参照されているのはこの2つのみで、`sort`・`pageable`・`first`・`last`・
  `empty` は型定義にあるが未使用と確認済み）

## 機能要件

- `GET /api/admin/feedbackUser` のレスポンスを `{feedbacks: {...}}` でラップし、
  `feedbackMessage`・`feedbackRoom` と同じ構造にする
- feedback系3API（feedbackUser / feedbackMessage / feedbackRoom）のページング部分に
  `totalPages`・`numberOfElements` を追加する
  - `totalPages`: 既存の `PagedUserResponse` と同じ計算式（`ceil(totalElements / size)`、
    `size <= 0` の場合は `0`）を踏襲する
  - `numberOfElements`: そのページに含まれる実際の件数（`len(content)`）
- 「回答数一覧」タブがクラッシュせずに表示され、3タブすべてページ送りが正しく動作すること

## 非機能要件

- 既存の `feedbackMessage`・`feedbackRoom` のレスポンス形式（`feedbacks`ラッパー・
  `assistantIdToServerMap`等）に対する破壊的変更は行わない（フィールド追加のみ）

## スコープ外

- frontend-angular 側の変更（動作確認用のため非改変方針）
- `sort`・`pageable`・`first`・`last`・`empty`（frontend型定義にあるが未使用）の追加
- feedback系以外のAPIのページングレスポンス形式の見直し
