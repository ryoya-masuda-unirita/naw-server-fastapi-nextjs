# 08_動作確認

## 確認環境

- macOS、Docker 29.8.2（OrbStack）。ブランチ `feature/issue-483`（`develop` の 0a421c7 から作成）
- 手元で `onprem/` の環境（server-local 18090、エミュレーター 18091、ベクトル DB 15432）が稼働中だったため、触れないよう、**別のプロジェクト名（`naw-onprem-483`）と別のポート**（server-local 58090、エミュレーター 58091、ベクトル DB 55432）で確認した。ポートだけを上書きする compose を一時ファイルに置いて、`onprem/docker-compose.yml` と重ねた。確認後は `down -v` で削除し、既存の環境が稼働し続けていることを確かめた
- 学習の確認では、`WAHA_WORKFLOWS_FILE=/app/config/workflows.example.json` を、環境変数で直接渡した（`onprem/.env` は作っていない）

## 未確認事項

- 既定のポート（18090・18091）での実行。手元の `onprem/` が使用中のため、別ポートで確認した。ポート番号以外は同じ定義
- `docker compose up -d --build server-local` が、エミュレーターが起動していない状態から、`depends_on` で一緒に起動すること（compose の定義上はそうなる。今回は、エミュレーターを先に起動してから server-local を起動した）
- `client` の手動の通しテスト（`npx vitest run --config vitest.e2e-local.config.ts`）。README の手順を書き換えたが、実行していない
- `onprem/.env` に `WAHA_WORKFLOWS_FILE` を書いて渡す経路（環境変数での直接指定では確認した）
- `SOURCE_ALLOWED_DIR` を足す前の動き（足す前は `filepath` だけの学習が失敗するはずだが、今回は再現していない。エミュレーターの自動テストに、未設定のときの失敗を確かめるものがある）
- 本物の Bedrock での動作（この Issue の範囲外）
