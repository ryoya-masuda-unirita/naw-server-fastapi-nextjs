# 04_テスト設計

## テスト方針

構成と手順書の変更なので、自動テストは増やさない。既存の自動テストが変わらず通ることと、整理後の構成を実際に起動して確かめることを中心にする。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 既存テストへの影響 | エミュレーター・server-local の自動テストを実行する | 作業前と同じ件数が通る |
| 2 | compose の定義 | まとめて起動する側の compose の定義を検証する | エラーなく展開できる |
| 3 | 参照の取り残し | 削除した compose と、削除した環境変数（`WAHA_EMULATOR_*`）を、手順書・設定で検索する | `docs/issue-*` の過去の記録以外に、残っていない |
| 4 | まとめて起動 | まとめて起動する側の compose で、全サービスを起動する | すべて healthy になる |
| 5 | エミュレーターだけの起動 | サービス名を指定して、エミュレーターだけを起動する | エミュレーターだけが起動し、server-local とベクトル DB は起動しない。セッションの開始に成功する |
| 6 | チャットの通し | server-local に、履歴つきの質問を送る | 回答が返り、途中経過が届く |
| 7 | 学習の通し | server-local にファイルをアップロードして学習し、一覧・削除まで行う | 登録、一覧、削除が成功する |
| 8 | ファイルサーバーの許可ディレクトリ | エミュレーターのコンテナの中で、許可ディレクトリの設定と、ファイルサーバーのマウントを確認する | 許可ディレクトリが設定され、サンプル文書が読める |
| 9 | 設定ファイルの例 | `/app/config` の例（`workflows.example.json`）を指定して起動し、質問する | 例のサービス ID（`echo-rag` など）が動く |
| 10 | ホストで動かす手順 | 書き換えた README の「両方ともホストで動かす」を、手順どおり実行する | 動く（変更前と同じ） |
| 11 | 書き換えた手順 | 書き換えた README の Docker の手順を、上から順にそのまま実行する | 手順どおりに動く |
