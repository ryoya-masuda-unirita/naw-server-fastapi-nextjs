# #483 waha-emulator と onprem の docker compose の重複を整理する

## 概要

`waha-emulator/docker-compose.yml`（エミュレーター単体）と `onprem/docker-compose.yml`（社内側の環境をまとめて起動）の 2 つがあり、起動対象と設定の渡し方が重なっている。役割を整理して、compose を 1 つに寄せるか、分けたまま重複を減らす。

## 説明

### 現状（調査して確認した事実）

| 項目 | `waha-emulator/docker-compose.yml`（単体。#274・#298） | `onprem/docker-compose.yml`（#301） |
|---|---|---|
| 起動するもの | `waha-emulator` だけ | `server-local`・`waha-emulator`・`vector-db` |
| ストリームファイルの共有 | ホストのディレクトリを bind mount（`secuaigent-server-local/data/stream-output`）。server-local は別の compose、またはホストで動かす | named volume `stream-output` を server-local とエミュレーターが共有。ホストの server-local とは共有できない |
| `.env` | 必須（`WAHA_AUTHKEY`） | なくても動く（既定値つき） |
| ポート | 8091（`WAHA_EMULATOR_PORT`） | 18090・18091・15432（127.0.0.1 のみ） |
| コンテナ名 | `naw-waha-emulator`（固定） | 付けない（`naw-onprem-<サービス>-1`） |
| 実行ユーザー | `WAHA_EMULATOR_UID` / `GID`（既定 1000） | 指定なし |
| `SOURCE_ALLOWED_DIR` | 渡す | **渡さない**（`./file-server` を `/mnt/file-server` にマウントしているが、`filepath` による学習の許可ディレクトリが設定されない） |
| `EXECUTE_WAIT_FOR_COMPLETION`・`WAHA_EMULATOR_CONFIG_DIR` | 渡す | 渡さない（設定は `./config` を `/app/onprem-config` にマウント） |
| `AZURE_OPENAI_API_VERSION`・Bedrock の設定 | なし | あり |

- どちらも同じ `waha-emulator/Dockerfile` からビルドする（ビルドコンテキストはリポジトリのルート）
- エミュレーターの環境変数（`WAHA_AUTHKEY`・`LLM_PROVIDER`・`AZURE_OPENAI_*`・`WAHA_WORKFLOWS_FILE`・`LOG_LEVEL`・`TZ`）が 2 か所に定義されていて、片方だけ直し忘れるおそれがある
- 単体の compose を残した理由、またはやめる判断の記録は見つかっていない

### 単体の compose を参照している箇所

- `waha-emulator/README.md`: 「両方とも Docker で動かす」の手順
- `generative-ai-adapter/README.md`: 「Docker で server-local → エミュレーター → アダプタを通して確かめる」の手順（`docker logs naw-waha-emulator` を含む）
- ルートの `README.md`（`cd waha-emulator && cp .env.example .env && docker compose up -d --build`）
- `waha-emulator/.env.example`
- `client/src/features/chat/README.md`: 手動の通しテストの手順に、`onprem/docker-compose.yml` の `build: ../waha-emulator` では build できない、という記述がある（現在の `onprem/docker-compose.yml` はビルドコンテキストがルートに直っているため、記述が古い可能性がある）
