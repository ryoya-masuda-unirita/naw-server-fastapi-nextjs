## 設計上の判断

- **コンテナ名**: 単体側の `container_name: naw-waha-emulator` は、まとめて起動する側にはない（名前は `naw-onprem-waha-emulator-1`）。ログは `docker compose -f onprem/docker-compose.yml logs waha-emulator` で見る手順にする。`container_name` は足さない（#301 で、ルートの compose と衝突しないよう付けない設計にしている）
- **`SOURCE_ALLOWED_DIR`**: マウント先が固定（`/mnt/file-server`）なので、環境変数を設定せずに固定値で渡す。未設定のままだと、`filepath` だけで学習する経路（`file` スロットが空）が失敗する。server-local はファイルをアップロードして学習するため、通常の登録には影響しないと見ている（動作確認で確かめる）
- **`/app/config` のマウント**: `onprem/config` は `/app/onprem-config` にマウントされている（Bedrock の例）。`waha-emulator/config` は別のディレクトリなので、衝突しない
- **ポート**: 手順書の `8091` は、まとめて起動する側の `18091`（エミュレーター）・`18090`（server-local）に直す。server-local 単体の compose の既定ポート 8090 は変えない（顧客向けの本体なので）
- **実行ユーザー**: 単体側の `WAHA_EMULATOR_UID`・`GID` は、ホストのディレクトリを共有するための設定だった。named volume を使う側では不要なので持ち込まない
