# 03_詳細設計

## リネーム

`git mv` で次の4つを移動する。

- `backend/` → `server/`
- `frontend/` → `client/`
- `infra/` → `secuaigent-infra/`
- `server-local/` → `secuaigent-server-local/`

## 参照の置き換えルール

ディレクトリのパスを指す参照だけを置き換える。同じ文字列でも別の意味のものは置き換えない。

### 置き換える

- `backend/…`・`frontend/…`・`infra/…`・`server-local/…` の形のパス（`./`・`../` が前に付く形を含む）
- `working-directory: backend` や `cd backend` のように、スラッシュなしでディレクトリを指すもの
- `.claude/settings.json` に書かれたローカルの絶対パス

置き換えは、直前が英数字・`/`・`.`・`-` でないものに限る（perl の否定先読みで判定する）。これで次の2つも守れる。

- `/backend/auth/*` のような URL パスは、直前が `/` なので対象外
- `secuaigent-infra/`・`secuaigent-server-local/` のように移植元を指す名前は、直前が `-` なので対象外（二重に置き換わらない）

### 置き換えない

- URL パス `/backend/auth/*` と、それを扱う CloudFront Function（`strip_backend_prefix.js`・テスト）
- ECR・ECS・タスク定義の名前（`${PROJECT_NAME}-backend`、`backend_migrate` など）
- Terraform の module 名と、その配下のパス（`infra/modules/frontend/` の `frontend` は module 名。先頭の `infra/` だけ変える）
- `docs/issue-*`（過去の記録）
- 移植元を指す記述（`secuaigent-ref/server`、`secuaigent/client`）

### 手で直す

- `CLAUDE.md`・`AGENTS.md`・`.cursorrules`・README・skill の中で、移植元と移植先の両方が `server/`・`client/` になって区別がつかなくなる箇所。「移植元」「移植先」を明記して書き直す
- `.gitignore`・`.pre-commit-config.yaml`・workflow の `paths`
- docker compose の `build.context`・ボリュームのパス、Dockerfile の `COPY`
- スラッシュなしの参照（`working-directory`・`cd`・`context`・`-C` など）は、置き換えの後に、残りを grep で洗い出して1件ずつ確認する

## 手順

1. 未コミット変更が混ざらないよう、リネームと置き換えのファイルだけを `git add` する
2. ディレクトリごとに `git mv` → 置き換え → 残りの grep → 手で修正、の順で進める
3. 4つとも終わってから、全体の `git grep`（`docs/` 除く）で旧名を確認する
