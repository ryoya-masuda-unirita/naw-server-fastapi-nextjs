# 04_テスト設計

## テスト方針

動作は変わらないので、新しいテストは書かない。既存のテストと CI が、名前を変えた後も通ることで確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 名前の変更 | 4つのディレクトリをリネームした後 | 新しい名前だけが存在し、旧名は存在しない |
| 2 | 参照の残り | 旧名で全体を検索する（`docs/` 除く） | ディレクトリを指す参照が残っていない |
| 3 | 別物の保護 | URL パス・ECR/ECS の名前・module 名 | 変更されていない |
| 4 | backend のテスト | server で既存のテストを実行 | 全件成功 |
| 5 | frontend のテスト | client で既存のテストを実行 | 全件成功 |
| 6 | 他モジュールのテスト | server-local・waha-emulator・generative-ai-adapter のテスト | 全件成功 |
| 7 | Terraform | secuaigent-infra で fmt と validate、plan | 差分なし |
| 8 | CI | PR の全ジョブ | 全件成功 |
| 9 | ローカル起動 | docker compose で起動する | 全サービスが起動し、ログインできる |
