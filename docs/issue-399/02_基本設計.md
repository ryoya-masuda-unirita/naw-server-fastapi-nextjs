# 02_基本設計

## 変更対象

| 今 | 変更後 |
|---|---|
| `backend/` | `server/` |
| `frontend/` | `client/` |
| `infra/` | `secuaigent-infra/` |
| `server-local/` | `secuaigent-server-local/` |

## 画面 / API 変更概要

なし。画面・API・DB・インフラの実リソースは変わらない。

## 影響範囲

旧名を参照している箇所を、次の種類ごとに洗い出して直す。

- CI/CD: GitHub Actions の workflow（`paths`・`working-directory`・デプロイ手順）、`.pre-commit-config.yaml`
- コンテナ: docker compose、Dockerfile、onprem 配布物、`e2e-spec`・`e2e-explorer` の docker 定義
- インフラ: Terraform、infra 配下のスクリプト、CloudFront の関数
- 他モジュール: `waha-emulator`・`generative-ai-adapter`・`server-local` が、別ディレクトリをパスで参照している箇所
- ドキュメント・AI 向け設定: `CLAUDE.md`、`AGENTS.md`、`.cursorrules`、README、`.claude/`（agents・skills・memory）、`.codex/skills/`
- その他: `.gitignore`、`.vscode/settings.json`

同じ文字列が別の意味で出る箇所（`frontend` というモジュール名・S3 の名前・Terraform の module 名など）は、ディレクトリのパスを指すものだけを置き換える。

## 移植方針

- `git mv` でリネームし、履歴を保つ
- 置き換えは一括置換にせず、ディレクトリを1つずつ、参照の種類ごとに確認しながら行う
- 完了確認は、旧名での `git grep`（`docs/` 除く）が空であること、CI 全ジョブの成功、docker compose でのローカル起動とテスト実行で行う
- Terraform はディレクトリ名を変えるだけで、state のキーとリソース名は変えない。`plan` で差分が出ないことを確認する
