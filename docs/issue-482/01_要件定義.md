# 01_要件定義

## 背景

埋め込みアダプタは、学習データのファイルからテキストを取り出して、分割・埋め込み・保存する。移植元は、専用プロセッサ（PDF・Word・PowerPoint・Excel・画像）が読まない形式を、Apache Tika で取り出す。移植先は、テキスト系の MIME だけを自前で読むため、旧形式の Office・RTF・EPUB・HWP などは取り出せない。

## 機能要件

| No | 要件 |
|---|---|
| F1 | `waha-emulator` のコンテナに、JRE と Tika 3.1.0 のサーバーの jar を入れる。jar はビルドのときに取得し、固定した SHA-512 で検証する（実行時のダウンロードはしない） |
| F2 | 設定 `TIKA_SERVER_JAR` があるとき、必要になったときに（遅延起動）、同じコンテナの中で `127.0.0.1` に jar を子プロセスとして起動し、応答するまで待つ。すでに応答する Tika があれば、起動せずにそれを使う |
| F3 | 設定 `TIKA_URL` があるときは、そのサーバーを使う（子プロセスは起動しない） |
| F4 | どちらの設定もなければ、Tika を使わず、今のテキスト系の取り出しのままにする（既存の環境の動きは変わらない。**ただし、RTF・EPUB は MIME 判定を足すため `UNSUPPORTED_MIME` になる。意図した変更。03 を参照**） |
| F5 | Tika を使うときの対象を、移植元に合わせる。画像、`.pdf`・`.docx`・`.pptx`・`.xlsx`、MIME が `application/octet-stream` のものを除く、すべてのファイル |
| F6 | 取り出しは `PUT /tika`（`Accept: text/plain`、`Content-Type` に判定済みの MIME、`Content-Disposition` にファイル名）で行い、本文を前後の空白を除いて返す |
| F7 | 移植元の設定（OCR なし、埋め込み画像は読み飛ばす、`tika-config.xml` の Parser の一覧）を、Tika サーバーの設定ファイルで再現する。子の JVM のヒープ上限も設定で渡す（既定 256MB）。再現できない部分は、差として README に書く |
| F8 | 失敗は、core の前処理の失敗の結果で返す。ファイルの問題（解析できない・未対応の形式）と、Tika 側の障害（起動できない・応答しない・メモリ不足など）を区別する。ファイルの中身は、メッセージ・ログに出さない |
| F9 | 子プロセスが落ちたら、次の呼び出しで起動し直す。アダプタ（エミュレーター）の終了時に、子プロセスを止める |
| F10 | `onprem/` で、`.doc`・`.xls` などを登録して、本文が取り出されることを実機で確かめる |

## 非機能要件

- Tika を使わない環境（設定なし）で、既存のテストの結果が変わらない。ただし、RTF・EPUB の MIME 判定を足すため、この 2 つだけは `UNSUPPORTED_MIME` になる（下の 03 を参照。実機の確認で分かった）
- core の前処理は同期のため、Tika のクライアントも同期にする
- Tika への HTTP は、テストではモックの通信で行う。実機の確認は、実際のコンテナで行う
- 追加する関数に、日本語の NumPy 形式の docstring を書く。テストのメソッド名は英語、意図は日本語の docstring

## スコープ外

- 本物の Waha! への Tika の導入
- `secuaigent-server-local/` の変更（Waha! にファイルを渡すだけで、テキスト抽出はしない）
- PDF・Word・PowerPoint・Excel の専用プロセッサの置き換え（Tika は残りの形式の受け皿）
- 画像説明、PDF の代替抽出
