# ローカル側の埋め込みアダプタのファイルの取り出しを、Apache Tika（コンテナの中で起動）に対応させる

## 概要

`generative-ai-adapter/`（埋め込みアダプタが使う core のファイル前処理）で、移植元と同じ Apache Tika を使えるようにする。Tika を使うのは、移植元の `TextCoreMediaProcessor` と同じ範囲（専用プロセッサが読まない形式。`.doc`・`.xls`・`.ppt`・RTF・HTML・EPUB・HWP など）。

## 説明

- 移植元（Java）は、Tika をアダプタのプロセスの中でライブラリとして呼ぶ。Python からは直接呼べないため、`waha-emulator` のコンテナに JRE と Tika 3.1.0 のサーバー（jar）を入れ、同じコンテナの中で子プロセスとして起動し、`127.0.0.1` で HTTP 接続して呼ぶ。クラウド側 `server/` の #469 と同じ方式
- 現状の core は、テキスト系の MIME だけを自前でデコードして読む。旧形式の Office や RTF などは読めない
- 本物の Waha! には Tika を入れない（移植元の Java 版アダプタが、すでに組み込んでいる）。Python 版のアダプタが動くのは `waha-emulator` だけ
