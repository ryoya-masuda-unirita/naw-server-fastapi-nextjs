# 04_テスト設計

## 方針

- Tika への HTTP は、偽の通信（モック）で行う。子プロセスの起動も偽にする。実機の確認は、実際のコンテナで行う（08）
- 設定がない環境で、既存のテストの結果が変わらないことを確かめる

## 観点

| 区分 | 観点 |
|---|---|
| 設定 | 何もなければ無効。`TIKA_URL` だけ・`TIKA_SERVER_JAR` だけで有効。既定値。不正な値（ポート・ヒープ・時間）はエラー |
| 抽出 | 判定済みの MIME・ファイル名（日本語を含む）・本文を、正しいヘッダで送る。応答の本文を返す |
| 失敗の区別 | 415 → 未対応、422 など 4xx → 破損、5xx → Tika の障害、接続できない → Tika の障害 |
| 起動 | 必要になるまで起動しない。起動を待つ。同時の呼び出しで 1 回だけ起動する。すでに応答する Tika は借りる。借りた先が落ちたら次は起動する。落ちたら次の呼び出しで起動し直す。時間内に起動しなければ失敗。`TIKA_URL` のときは起動しない |
| 終了 | 起動したものを止める。止まらなければ kill する。設定ファイルを消す |
| 設定ファイル | ヒープの指定と、OCR の除外が入っている |
| プロセッサの対象 | Tika が使えるとき: 画像・`.pdf`・`.docx`・`.pptx`・`.xlsx`・octet-stream は対象外、`.doc`・`.xls`・`.ppt`・RTF・HTML・CSV などは対象。使えないとき: 従来どおり |
| プロセッサの処理 | Tika で取り出した本文の空白を除く。空なら失敗。Tika の失敗が、前処理の失敗の結果になる（コードと、ファイルの中身を出さないこと） |
| エミュレーター | 終了時に Tika を止める |

## 実機の確認（08）

実際のコンテナで、`.doc`・`.xls`・`.ppt`・RTF・HTML を登録して本文が取り出されること、壊れたファイルが失敗になること、設定なしの環境が従来どおりであること。
