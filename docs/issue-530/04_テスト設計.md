# 04_テスト設計（PR 1）

## 方針

- 版 1 の既存のテスト（`test_studio_*`・`test_servicerun_api` など）が、変更なしで通る（共存の確認）
- 版 2 を、検証・テンプレート・エンジン・サービス・API・実行（execute）の観点で確かめる。偽の生成AI（スクリプトされたプロバイダ）で、2 回目のプロンプトに、1 回目の回答が入ることを確かめる

## 観点

### 検証（`parse_flow`）
- 例 1（推敲）の定義を読める
- `version`・`id`・`name`・`serviceIds`・ノード数の上限・ノードの種類・ID の形・重複を、それぞれ弾く
- `start` が 0 個・2 個、`end` が 0 個を弾く
- 各ノードの `config`（必須の項目、型、長さ、不明なキー、`outputType` の値、`inheritContext` の型）を弾く
- 線: 存在しないノード、`start` への線、`end` からの線、2 本目の出る線、輪、到達できないノード、行き止まりを弾く
- 変数: `question`・`history`・上流の `ノードID.text` は通り、下流のノード・存在しないノード・`.text` 以外・自分自身の参照を弾く。空白入り（`{{ draft.text }}`）も通る

### テンプレート（`render`）
- 変数を埋める、同じ変数を複数回、変数がない文字列はそのまま、`{{` が閉じていない文字列はそのまま

### エンジン
- 例 1: 2 回の生成AI が呼ばれ、2 回目のプロンプトに 1 回目の回答が入り、最終回答は 2 回目の回答（`answer`）
- `outputType` が 2 のノードの本文が、変数に入る。0 のノードは JSON の `answer`
- `template` ノードの出力が、後ろのプロンプトで使える
- `end` の出力が、`{{llm.text}}` 1 つだけなら、そのノードの出力（生）をそのまま返す。複数・文字が混ざる場合は、`answer` にした JSON を返す
- `inheritContext`: false のとき、会話履歴・添付ファイルを渡さない。true のとき渡す。textData は渡す
- 失敗: 生成AI が失敗したら、ノード名つきの理由

### サービス・API・実行
- 版 2 の作成・取得・更新・削除・検証、重複（409）、不正（400）。取得で、`config.properties` の API キーが伏せられ、伏せ字のまま更新しても、保存済みの値が残る
- 保存した版 2 のサービス ID で execute し、`SUCCESS` と回答が返る。版 1 と版 2 が、同じ保存先に共存する
- 画面: 版 2 を開こうとしたら、非対応の表示が出る
