# 01_要件定義

## 背景

今のワークフローは、「開始 →（検索 →）生成AI → 終了」の鎖に固定で、次のことができない。

- 生成AI を 2 回以上使い、前の回答を、次の生成AI のプロンプトに入れる
- 生成AI の判定の結果で、道を分ける
- 生成AI に渡すプロンプトを、画面で決める（今は、質問をそのまま渡す）

## 達成したいこと（受け入れの例）

### 例 1: 推敲

`開始 → 生成AI①（プロンプト: 「{{question}}」に回答して）→ 生成AI②（プロンプト: 「次の下書きの、誤りと冗長さを直して: {{draft.text}}」）→ 終了（出力: {{polish.text}}）`

- 質問を送ると、生成AI が 2 回呼ばれ、2 回目のプロンプトに、1 回目の回答が入る
- 最終回答は、2 回目の回答になる

### 例 3: 根拠チェック付きの RAG

`開始 → 検索 → 生成AI（根拠つきで回答）→ 生成AI（判定: 「回答が、次の文書に書いてあれば OK、なければ NG とだけ答えて」）→ 条件分岐（判定に「OK」を含むか）→ はい: 終了（出力: 回答）／いいえ: 終了（出力: 「根拠となる文書が見つからず、お答えできません」）`

- 判定が OK なら、回答（と引用元）が返る。NG なら、固定の文が返る
- 判定の生成AI に、検索で得た引用資料の本文が、プロンプトで渡る

## 機能要件

### ノードの種類

| ノード | 役割 | 出力する変数 |
|---|---|---|
| 開始 | 届いた入力を持つ | `question`（質問）、`history`（会話履歴。あれば） |
| 生成AI | プロンプト（テンプレート）を埋めて、生成AI を 1 回呼ぶ。接続（プロパティ）は今と同じ。検索ノードの出力を、引用資料に使うこともできる | `text`（回答） |
| 検索 | 質問で検索する（今ある） | `contexts`（引用資料のリスト）、`contexts_text`（本文を連結した文字列） |
| 条件分岐 | 変数を、条件（含む・等しい・空）で調べ、はい／いいえの 2 つの線に分ける | なし |
| テンプレート | 文字列を、変数を埋めて作る（固定の文にも使う） | `text` |
| 終了 | 出力する文字列（テンプレート）を決める。複数置ける（到達した終了が、回答になる） | なし |

### 変数

- ノードの出力は、`{{ノードID.変数名}}` で、あとのノードのプロンプト・条件・終了の出力に埋め込める（開始の変数は `{{question}}` のように、ノード ID を省略できる）
- 存在しない変数を参照したときは、保存の時点で、どのノードのどこかを示して弾く

### つなぎ方

- 鎖の固定をやめ、開始から終了までの、分岐のある有向グラフを組める（合流は、いずれかの終了に到達する形だけ。並列の枝分かれは、スコープ外）
- 条件分岐は、「はい」「いいえ」の 2 つの出口を持つ。1 つの出口から出る線は 1 本
- 輪（ループ）は作れない。開始から到達できないノード、終了に到達できない行き止まりは、保存の時点で弾く

### 実行

- 開始から線をたどり、実行するノードの順に、ノードを 1 つずつ動かす。分岐で選ばれなかった側のノードは、実行しない
- 回答は、今と同じ形（`answer`・`references` など）の JSON で返す。検索ノードを使った生成AI の引用元は、`references` に入る
- ノードが失敗したら、そこで止め、どのノードの失敗かが分かる理由を返す（今と同じ）
- 途中経過（推論の差分）は、今と同じ形でストリームファイルに書く（最後に実行した生成AI の分）

### 保存形式

- 版 2 にする。今の版 1（鎖）の保存データは、読み込めて、そのまま動く（保存し直すと版 2 になる）
- 版 2 でも、`position`・`name` など、今の項目は、そのまま

### 画面

- パレットから、生成AI・検索・条件分岐・テンプレート・終了を、足せる（開始は 1 つで固定）。ノードを削除できる
- 線を自由に引ける。条件分岐の出口（はい／いいえ）を、見分けられる
- ノードを選ぶと、種類ごとの設定を、右で編集できる（生成AI: プロンプト・接続、条件分岐: 変数・条件・値、テンプレート: 文字列、終了: 出力）
- 使える変数を、一覧で見られ、プロンプトの入力欄に挿入できる
- 何も開いていないとき、使い方の案内（3 ステップ）を出す

## 非機能要件

- servicerun API は変えない。今の `workflows.json` と、今の版 1 の保存データが、そのまま動く（巻き戻し: タグ `waha-emulator-before-studio`、PR 単位で revert できる）
- 生成AI の呼び方（アダプターの呼び出し・プロパティの検証・秘密の伏せ字）は、今のものを使い回す
- ループがなく、ノードの数に上限（例: 50）を置き、1 回の実行が、無限に続かない

## スコープ外

- 試し実行（別の Issue。ユーザーが実装）。この Issue のエンジンは、試し実行が、ノードごとの入出力を取れる形にしておく
- 並列の枝分かれ、ループ、エージェント（ツール呼び出し）、学習・削除・同期のノード、ストリームの途中経過の詳細
