## 版 2 の保存形式

```json
{
  "version": 2, "id": "polish", "name": "推敲", "serviceIds": ["polish"],
  "nodes": [
    {"id": "start", "type": "start", "name": "開始", "position": {"x": 0, "y": 0}},
    {"id": "draft", "type": "llm", "name": "下書き", "position": {"x": 280, "y": 0},
     "config": {"prompt": "{{question}} に回答してください", "outputType": 2, "properties": {"VENDOR": "Echo", "URL": "http://echo.invalid", "API_KEY": "echo", "MODEL_NAME": "echo"}}},
    {"id": "polish", "type": "llm", "name": "推敲", "position": {"x": 560, "y": 0},
     "config": {"prompt": "次の下書きの誤りと冗長さを直してください:\n{{draft.text}}", "properties": {"...": "..."}}},
    {"id": "end", "type": "end", "name": "終了", "position": {"x": 840, "y": 0},
     "config": {"output": "{{polish.text}}"}}
  ],
  "edges": [{"source": "start", "target": "draft"}, {"source": "draft", "target": "polish"}, {"source": "polish", "target": "end"}]
}
```

| ノード | `config` |
|---|---|
| `start` | なし |
| `llm` | `prompt`（必須。1〜20000 文字）、`properties`（接続。版 1 と同じ規則）、`outputType`（0 か 2。省略は 0）、`inheritContext`（真偽。省略は false。true のとき、会話履歴と添付ファイルを、この生成AI にも渡す） |
| `template` | `text`（必須。1〜20000 文字） |
| `end` | `output`（必須。1〜20000 文字） |

- 線: `source`・`target`。PR 2 で、条件分岐のために `sourceHandle` を足す（PR 1 では、書けない）
- 保存の項目の不明なキーは弾く（版 1 と同じ）

## 検証（`parse_flow`・`compile_flow`）

| 規則 | エラー |
|---|---|
| `version` が 2 | 未対応の version |
| `id`・`name`・`serviceIds` は、版 1 と同じ規則 | 同じ文言 |
| ノードの ID は、英数字・`-`・`_` の 1〜64 文字で、重複しない。種類が 4 つのどれか。ノードは 50 個まで | ノードが不正 |
| `start` は 1 つ、`end` は 1 つ以上 | ノードの数が不正 |
| 各ノードの `config` の項目・型・長さ | どのノードのどの項目か |
| 線の端が、存在するノード。`start` に入る線・`end` から出る線がない。ノードから出る線は 1 本まで | 線が不正 |
| 輪がない。すべてのノードが `start` から到達できる。`end` 以外のノードは、必ず出る線を持つ（行き止まりがない） | つなぎ方が不正 |
| テンプレート（`prompt`・`text`・`output`）の `{{...}}` の参照が、`question`・`history`、または、**そのノードより前に実行される** `llm`・`template` ノードの `ノードID.text` | どのノードのどの参照か |
| `llm` の `properties` が、アダプターの検証を通る（`${環境変数}` も展開） | ノード名つき（版 1 と同じ） |

## 実行（`FlowWorkflow.run`）

1. 変数の置き場（辞書）に `question`・`history` を入れる（`history` がなければ空文字）
2. `start` から、出る線をたどり、ノードを順に動かす（ノードの総数が上限）
3. `llm`: `prompt` を埋め、質問のスロットを、その文字列に差し替えた `WorkflowRequest`（`inheritContext` が false のとき、会話履歴・添付ファイルのスロットは外す。textData は残す）を作り、今の `GenerativeAiWorkflow`（出力モードは `outputType`）を 1 回動かす。出力が、モード 0 なら JSON の `answer`、モード 2 なら本文を、`ノードID.text` に入れる。出力の文字列（生）は、ノード ID ごとに覚える
4. `template`: `text` を埋め、`ノードID.text` に入れる
5. `end`: `output` を埋める。`output` が、`{{ノードID.text}}` 1 つだけで、そのノードが `llm` なら、そのノードの出力（生）をそのまま返す（今の版 1 の回答と同じ形・同じ引用元になる）。それ以外は、`{"answer": 埋めた文字列, "filepaths": [], "references": [], "imageExplanations": []}` を返す
6. 失敗（`WorkflowError`）は、止めて、`ノード「名前」: 理由` で返す

## `StudioService`・管理 API

- `version` が 1 なら今の処理、2 なら `parse_flow`・`compile_flow`。ほかは、未対応の version（400）
- ワークフローの重複・サービス ID の重複・保存・登録・伏せ字の引き継ぎは、版 1 と同じ
- 管理 API のパス・応答は変えない（本文が版 2 でも、受け取れる）

## 注意

- 生成AI ノードのたびに、ジョブのディレクトリを作り直す（今の `GenerativeAiWorkflow` の動き）。ノード間の受け渡しは、文字列の変数だけ（ファイルは渡さない）
