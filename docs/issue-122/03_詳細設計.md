# 03_詳細設計

## 状態

- Zustand `useGroupListStore`: `filter`（`pageSize 5`・`pageIndex 1`・`sortField 'updatedAt'`・`sortOrder 'desc'`）。`updateFilter` は 1 ページ目へ戻す（移植元 `GroupListStore` と同じ）
- 画面を離れたら `reset`（#124 と同じ。残すと検索欄が空に戻っても前回の条件が効く）
- 検索の `query` は空文字なら未指定にする（移植元 `event.query || undefined`）

## 一覧の表示用データ

- `toViewModel`（移植元と同じ）: 管理者・所属ユーザーは一覧の名前が空でなければそれを使い、空なら ID を対応表で引く。アシスタント・テンプレートは常に ID（なければ名前の配列）を対応表で引く
- 対応表にない ID は移植元では ID のまま。backend は ID と同じ並びの名前も返すため、その名前を使う（後述の差 2）
- 名前が足りない（4 つのうち 1 つでも空の）チームは、グループ内の一覧（ユーザー・アシスタント・テンプレート）で補う。補完に失敗したらそのまま表示

## 判断と理由（移植元との差）

1. 作成後の一覧: 移植元は先頭にローカルで足す（件数 +1。1 ページ 6 件になり得る）。React は TanStack Query で再取得し、並び・ページ境界は常にサーバーの結果になる（#124 と同じ判断）。テンプレート管理のグループ選択肢（`['admin-groups']`）も無効化する
2. 名前の対応表にない ID: 上記のとおり backend の名前の配列で補う（移植元は ID のまま）
3. グループ内の一覧の `size`: 移植元は 1000。backend は 100 までしか受けず超えると 422 になるため 100 にした。100 件を超えるチームは補完が途中までになる（backend は直さない。後続候補）
4. 対応表・補完のエラートースト: 移植元は共通のエラートーストが出うるが、失敗しても ID のまま表示する設計のため `skipGlobalErrorToast` で出さない。特に `GET /api/admin/users` は backend ではテナント管理者専用で、グループ管理者だと 403 になり、毎回トーストが出てしまう
5. 補完の対象: 移植元は最初の読み込み後に 1 回だけ補う。React は表示したページごとに補う（ページ送り・検索後も名前が揃う）。結果は query にキャッシュされる
6. ローディング: 移植元は `mat-spinner`（40px）。`CircularLoading` で代替。対応表の取得が終わるまでもスピナーを出す（移植元は対応表を読み終えてから一覧を読み込むため、その間カードが出ない）
7. 「閲覧・編集」ボタン: 移植元は `app-button` に `routerLink`。`Button` に `link` がないため `useNavigate` で遷移（`ROUTES.APP.ADMIN_GROUP_DETAIL_TAB(id, 'users')`）
8. `AddGroupDialogComponent`（`add-group-dialog`）: 移植元で使われていない（ダイアログは `group-form` を使う）ため移植しない。`group-form` はフォームがチーム名 1 つだけ（管理者・ユーザー等の選択はコメントアウト済み）で、`GroupAddDialog` に取り込んだ
9. ダイアログの `maxHeight: '90vh'`・`showDivider`: 共通 `Dialog` に対応する prop がない（#124 と同じ）。幅は `min(100%, 800px)`
10. 名前の入力: 移植元どおり `required` は空文字だけを弾き、空白のみは通って trim 後に空で送られる（backend が拒否しなければそのまま作られる）。確認ボタンは入力が誤りでも無効にしない（押すと誤りを表示する）

## backend の応答との突き合わせ（`docs/issue-279/api-backend-diff.md`）

- `GET /api/admin/groups` は `{ data, total, page, size }`。型と一致。行は `users`・`adminUserIds`・`adminUserNames`・`userNames`・`assistants`・`assistantIds`・`promptTemplates`・`promptTemplateIds`・`updatedAt` を返し、移植元の型と一致
- `POST /api/admin/groups` は `GroupDetailResponse`。画面は結果を使わず再取得するので差は影響しない
- `GET /api/admin/users` は `PagedUserResponse`（`content` の `id`・`name`）。ページ番号は `page`（`number` ではない）だが、画面は `content` だけ読む
- グループ内の一覧の行は `userId`・`name`・`displayName`（null あり）・`groupAdmin`。表示名は `displayName ?? name`
