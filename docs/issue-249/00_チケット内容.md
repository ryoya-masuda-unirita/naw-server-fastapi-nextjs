# #249 issue-249 Bedrockのアシスタント送信・maxTokens切り詰め・tools検証を直す

## 概要

#149（PR #199）で追加した Bedrock（Claude）対応に、次の問題がある。

1. アシスタントに `BEDROCK_CHAT` のエンドポイントを登録できる（`assistant_service.py` の `_is_chat_type` は種別名が `CHAT` で終わるかで判定する）が、メッセージ送信側（`message_service.py` / `assistant_endpoint_repository.find_chat_endpoint`）は `AZURE_OPENAI_CHAT` 固定のため、送信すると 400 `No chat endpoint found for this assistant` になる。`docs/issue-149/01_要件定義.md` は既存のチャット API からも呼べる想定だった
2. リクエストの `maxTokens` を、モデルの上限（`ai_models.max_tokens`）で切り詰めていない。移植元は `OpenAiLlmChatAdapter` で `min(reqMax, model.getMaxTokens())` にする。Bedrock で上限を超える値を送ると、応答開始後に SSE の `error` になる（Azure 側も同じく切り詰めていない）
3. Bedrock で `tools` を指定したときのエラーが、ストリーミング開始後に SSE の `error` として返り、トークン使用量 0 の行も記録される。開始前に 400 で拒否する方がよい

## 説明

- 1 は、メッセージ送信でも Bedrock を使えるようにするか、登録時に拒否するかを設計で決める（#149 の要件どおり使えるようにするのが第一候補）
- 2 は、移植元と同じく切り詰める（Azure・Bedrock の両方）
- 3 は、ストリーミング開始前に検証する
