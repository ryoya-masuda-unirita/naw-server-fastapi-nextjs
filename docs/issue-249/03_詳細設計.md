# 03_詳細設計

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `backend/app/models/ai_model.py` | チャット用の対応表 `CHAT_TENANT_ENDPOINT_TYPES`（AI モデル種別 → テナントエンドポイント種別）と逆引き `CHAT_AI_MODEL_ENDPOINT_TYPES` を追加 |
| `backend/app/core/llm_client.py` | `cap_max_tokens` を追加。`BedrockLlmChatClient.validate_request` を追加し、`stream_chat` の `max_tokens` を必須の `int` に変更（`max_tokens_fallback` を削除） |
| `backend/app/repositories/assistant_endpoint_repository.py` | `find_chat_endpoint` の条件を `TenantEndpoint.type.in_(CHAT_AI_MODEL_ENDPOINT_TYPES)` に変更 |
| `backend/app/services/llm_chat_service.py` | 対応表を `models` のものに置き換え。Bedrock の事前検証（400）、`cap_max_tokens` による切り詰め |
| `backend/app/services/message_service.py` | AI モデル検索の種別をエンドポイント種別から引く。Bedrock の事前検証（400）、Bedrock 分岐、トークン使用量の `endpoint_type` を実際の種別に |

## 詳細

### `models/ai_model.py`

```python
CHAT_TENANT_ENDPOINT_TYPES: dict[AIModelEndpointType, EndpointType] = {
    AIModelEndpointType.AZURE_OPENAI_CHAT: EndpointType.AZURE_OPENAI_CHAT,
    AIModelEndpointType.BEDROCK_CHAT: EndpointType.BEDROCK_CHAT,
}
CHAT_AI_MODEL_ENDPOINT_TYPES: dict[EndpointType, AIModelEndpointType] = {
    tenant_type: model_type for model_type, tenant_type in CHAT_TENANT_ENDPOINT_TYPES.items()
}
```

- `services/llm_chat_service.py` の `_CHAT_TENANT_ENDPOINT_TYPES` をここへ移し、メッセージ送信・
  リポジトリと共有する（サービス同士は呼び合わない規約のため、共通の置き場として `models` を使う）

### `core/llm_client.py`

- `cap_max_tokens(requested: int | None, model_max_tokens: int) -> int | None`
  - `requested` が `None` なら `None`、それ以外は `min(requested, model_max_tokens)`
  - 移植元 `OpenAiLlmChatAdapter.buildParams` の `Math.min(reqMax, cap)` に対応
- `BedrockLlmChatClient.validate_request(tools: list[ToolConfig] | None) -> None`
  - `tools` が空でなければ `ValueError`（文言は従来の `stream_chat` 内の文言）
- `BedrockLlmChatClient.stream_chat(..., max_tokens: int, tools=None)`
  - 冒頭で `validate_request(tools)` を呼ぶ（防御的）
  - `max_tokens_fallback` を削除。上限の決定は呼び出し側で行う

### `repositories/assistant_endpoint_repository.py`

- `find_chat_endpoint` の `TenantEndpoint.type == EndpointType.AZURE_OPENAI_CHAT` を
  `TenantEndpoint.type.in_(CHAT_AI_MODEL_ENDPOINT_TYPES.keys())` に変更
- 並び順は「Azure OpenAI を優先（`case`）→ `endpoint_id` 昇順」の先頭 1 件を採用する。Azure・Bedrock の両方を
  紐づけたアシスタントで、従来の送信先（Azure）を変えないため（code-review #2）

### `services/llm_chat_service.py`

- AI モデル・エンドポイント解決と messageId の存在確認・所有者確認の後に、`ai_model.endpoint_type == BEDROCK_CHAT` なら
  `BedrockLlmChatClient.validate_request(tools)` を呼び、`ValueError` を 400 に変換する（404/403 を優先する。code-review #3）
- `max_tokens = cap_max_tokens(req.maxTokens, ai_model.max_tokens)`
  - Azure: そのまま渡す（未指定は `None` のまま）
  - Bedrock: `max_tokens if max_tokens is not None else model_max_tokens` を渡す

### `services/message_service.py`

- `find_chat_endpoint` の結果の `tenant_endpoint.type` から `CHAT_AI_MODEL_ENDPOINT_TYPES` で AI モデル種別を引き、
  `AIModelRepository.find_by_endpoint_type_and_name` で検索する
- AI モデル解決の直後（RAG コンテキスト構築より前）に、Bedrock なら `validate_request(tools)` を呼び、
  `ValueError` を 400 に変換する
- `event_stream` 内で、Azure は従来どおり `AzureLlmChatClient.stream_chat(..., 0.0, None, tools, response_format)`、
  Bedrock は `BedrockLlmChatClient.stream_chat(..., 0.0, ai_model.max_tokens)` を呼ぶ
  （応答形式は JSON 出力指示の前置で対応。LLM チャット API と同じ）
- `_persist_token_usage` に `endpoint_type` 引数を追加し、固定の `AZURE_OPENAI_CHAT` をやめる
