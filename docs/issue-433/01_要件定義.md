# 01_要件定義

## 機能要件

1. `message_contents (message_id)` の索引を、Alembic のマイグレーションで足すこと
   - 列は `message_id` だけにする。外部キーの CASCADE の探索（`WHERE message_id = ?`）と、結合・`IN` の絞り込みのすべてに効く。`tenant_id` を先頭にすると、CASCADE の探索に効かない。`message_id` はほぼ一意なので、`tenant_id` を足しても絞り込みは変わらない
2. ダウングレードで、索引を消せること
3. 既存のデータ・挙動・API は変えないこと（索引の追加のみ）
4. （要判断）`messages (tenant_id, room_id)` の索引も、同じマイグレーションで足すか

## 非機能要件

- 本番のデータが大きい場合、`CREATE INDEX` は、書き込みを止める（ロックを取る）。`CONCURRENTLY` にするかを決める（Alembic では、トランザクション外で実行する必要がある）。このプロジェクトの既存のマイグレーションが、`CONCURRENTLY` を使っているかを確認する
- 費用: なし

## スコープ外

- 移植元にある索引の移植（これは、移植元にない独自の改善）
- 実環境への適用（Deploy は旧環境向けで、動かない見込み）
- ほかのテーブルの索引（`message_files`・`token_usages` など。必要なら別の Issue）
