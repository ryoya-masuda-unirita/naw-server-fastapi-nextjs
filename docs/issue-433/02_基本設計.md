# 02_基本設計

## 変更対象

1. **マイグレーション（新規）**: `server/alembic/versions/issue433_add_message_contents_message_id_index.py`。`revision = "issue433"`、`down_revision = "issue309"`。`upgrade` で `message_contents_message_id_idx` を作り、`downgrade` で消す
2. **モデル**: `MessageContent` の `__table_args__` に、同名の `Index` を足す（モデルとマイグレーションを一致させる。ずれると、`alembic check` や自動生成で差分が出る）
3. **テスト**: マイグレーションを PostgreSQL で上げ下げして、索引が作られ・消えることを確認する（自動テストは SQLite なので、PostgreSQL では手動確認）。モデルの索引が、SQLite のテストで作られても壊れないことは、既存のテストで確認する

## 画面 / API 変更概要

なし。

## 影響範囲

- 書き込み（`message_contents` の INSERT・UPDATE）が、索引の更新のぶん、わずかに遅くなる
- ディスク: 450,000 件で 14 MB
- 本番の適用時、`CREATE INDEX` の間、`message_contents` への書き込みが待たされる（件数が大きい場合）
