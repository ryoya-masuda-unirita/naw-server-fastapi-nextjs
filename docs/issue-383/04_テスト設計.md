# 04_テスト設計

## テスト方針

インフラと CI の設定変更なので、自動テストは追加しない。タグ以外のリソース設定が変わっていないことを、再構成前後の `plan` の比較で確認する。AWS への `apply` は実行しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 構文・書式 | `fmt` と `validate` | エラーなし |
| 2 | リソース数 | 変更前後の `plan` の追加数 | 変更前と同じ数（`route53` の削除はメインの構成に影響しない） |
| 3 | タグ以外の設定 | 変更前後の `plan` の、確定している属性値を比べる（リソース名はプロジェクト名の既定値が変わるため、名前の差を除く） | 差分は、リソース名に含まれるプロジェクト名、`tags`・`tags_all`、CloudFront 向けプレフィックスリスト ID の参照のみ |
| 4 | 実際に付くタグ | 変更前後の `tags_all`（`Project` を含む）を比べる | これまで `Project` が付いていたリソースは同じキーと値。これまでタグのなかったリソースには `Project` だけが増える（`Project` の値は新しいプロジェクト名） |
| 5 | プレフィックスリスト | `plan` の ALB のセキュリティグループのルール | 元と同じ ID（`pl-58a04531`）が入る |
| 6 | 信頼条件 | 信頼ポリシーの `sub` の値 | 変数の既定値から組み立てた値が、元の直書きと同じ文字列になる |
| 7 | プロジェクト名の直書き | 検索 | `issue160`・`issue158` が、設計書以外のどこにも残っていない |
| 8 | route53 の残り | 検索 | `infra/route53`・`!infra/route53` の参照が、README の注記以外に残っていない |
| 9 | インフラの CI | 変数が空・形式が不正のとき | 原因を示して失敗する。正しい値では通る（検査の正規表現を bash で試す） |
| 10 | backend の CI | 同上。名前の組み立て | 元の直書きと同じ形（`<名>-cluster` ほか）になる |
| 11 | 名前の整合 | backend のデプロイが組み立てる名前と、インフラが作る名前 | 5 つとも一致する（`plan` の名前と突き合わせる） |
| 12 | 秘密の混入 | 追加・変更したファイルを確認する | 認証情報・アカウント ID の実値なし |
