## 詳細

### 1. S3 のバケット名の衝突（🟡 注意）→ 対応済み

`${var.project_name}-frontend` が `naw-fastapi-frontend` のような汎用的な名前になり、他アカウントが同名のバケットを持っていれば、`apply` が `BucketAlreadyExists` で失敗する。`plan` の比較は何も作らないので、検出できなかった。フロントエンド用とユーザー取込用のバケット名に、`aws_caller_identity` のアカウント ID を含めた（bootstrap の state 用バケットと同じ方式）。バケット名は、出力と変数を経由してしか参照されておらず、CI は `terraform output` から取った値を使うので、ほかへの影響はない。`plan` で 72 リソースのまま、名前が `naw-fastapi-frontend-<アカウント ID>` になることを確認した。

### 2. 検査の正規表現（🔵 提案）→ 対応済み

`^[a-z0-9][a-z0-9-]{1,28}[a-z0-9]$` にして、ハイフンで始まる・終わる名前を弾く（長さは 3〜30 文字のまま）。2 つのワークフローを同じ式にそろえた。さらに、同じ形式を Terraform の変数 `project_name` の `validation` にも入れ、ローカルで `apply` する場合にも、不正な名前を早く止める。`-bad-` を渡すと `plan` が `Invalid value for variable` で失敗することを確認した。

### 3. 文書中のアカウント ID（🔵 提案）→ 対応済み

`docs/issue-383/08_動作確認.md` と、#382 で同じ記述を入れた `docs/issue-382/08_動作確認.md` から、実のアカウント ID を削除した（「ユニリタとは別の AWS アカウント」と書く）。最初の確認で「12 桁の数字なし」としたのは誤りで、`08` を書いた後に再確認していなかった。Git の履歴には、旧コミットに ID が残る（公開リポジトリでないこと、アカウント ID 自体は認証情報ではないことから、履歴の書き換えはしない）。

### 4. 旧名の既存環境への適用（🔵 提案）→ 対応済み

コードでの防止（`precondition`）は、新アカウント専用という前提と、旧環境の `tfvars` の有無に依存して判定が難しいため入れない。代わりに `infra/README.md` の冒頭の注意に、既定値を変えたため旧名で作った既存の環境に適用するとほぼ全リソースの作り直しになることを明記した。
