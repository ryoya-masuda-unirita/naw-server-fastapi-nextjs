# 02_基本設計

## 変更対象レイヤー

- `models`（`TenantEndpoint`の新規テーブル定義）
- `schemas`（リクエスト・レスポンススキーマ）
- `repositories`（`tenant_endpoints`テーブルへのDBアクセス）
- `services`（LOCAL_SERVER限定バリデーション・CRUDロジック）
- `routers`（`GET/POST/PATCH/DELETE /api/admin/tenants/{tenantId}/endpoints`系エンドポイント）

## データモデル概要

### tenant_endpoints テーブル

- `id`：UUID hex 32文字、主キー
- `tenant_id`：所属テナント
- `type`：Enum（`LOCAL_SERVER`, `VDB`, `AZURE_OPENAI_CHAT`, `CLAUDE_CHAT`, `GEMINI_CHAT`, `OPENAI_CHAT`, `OPENAI_WEB_SEARCH_CHAT`, `AZURE_OPENAI_EMBEDDING`）
- `endpoint_name`：エンドポイント名（表示用）
- `endpoint`：接続先URL
- `api_key`：APIキー（平文保存、レスポンスには含めない）

## API変更概要

### 一覧・タイプ別取得（全タイプ対象）

- `GET /api/admin/tenants/{tenantId}/endpoints`：テナント内の全エンドポイント一覧
- `GET /api/admin/tenants/endpoints/{type}`：指定タイプのエンドポイント一覧

いずれもテナント管理者専用。パスの`tenantId`と認証済みユーザーのテナントIDが一致することを検証する（一致しなければ403）。

### 作成・更新・削除（LOCAL_SERVER限定）

- `POST /api/admin/tenants/{tenantId}/endpoints`：`type`が`LOCAL_SERVER`でなければ400
- `PATCH /api/admin/tenants/{tenantId}/endpoints/{endpointId}`：対象の現在の`type`、および更新後の`type`（指定時）がいずれも`LOCAL_SERVER`でなければ400
- `DELETE /api/admin/tenants/{tenantId}/endpoints/{id}`：対象の`type`が`LOCAL_SERVER`でなければ400

これは移植元の`assertLocalServerOnly`をそのまま踏襲する仕様であり、クラウドAIプロバイダー（Azure OpenAI等）の接続情報は本APIでは作成・更新・削除できない。

## 権限判定の実装方針

既存の`require_admin`（テナント管理者専用）を全エンドポイントに適用する。加えて、パスパラメータの`tenant_id`が認証済みユーザーの所属テナントと一致するかを検証する小さな依存関数（またはサービス層での検証）を追加する（移植元の`ensureTenantMatchesContext`相当）。既存の`get_verified_tenant_id`はヘッダーとJWTの一致を検証する仕組みのため、そのまま流用しつつパス値との突合を追加する形にする。

## レスポンス形式

```json
{
  "id": "string",
  "tenantId": "string",
  "type": "LOCAL_SERVER",
  "endpointName": "string",
  "endpoint": "https://..."
}
```

`apiKey`はレスポンスに含めない。

## 影響範囲

- 新規テーブル追加のためAlembicマイグレーションが必要
- 既存の認証・ユーザー・グループ・アシスタント管理コードへの変更はなし（新規ファイル追加のみ）
- `frontend-angular`のコード変更は不要（本チケットでは接続確認まで行わない想定。UI操作確認は`frontend-angular`の管理画面があれば実施する）
- `frontend`（React）は対象外
