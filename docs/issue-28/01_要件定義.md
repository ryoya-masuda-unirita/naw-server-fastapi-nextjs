# 01_要件定義

## 背景

issue-26でアシスタント一覧取得APIを実装したが、`endpoints`は常に空配列で返している。移植元では、アシスタントは`TenantEndpoint`（テナントごとのAI接続先）と`assistants_endpoints`中間テーブルを介して紐づく。本チケットでは、まず`tenant_endpoints`本体のCRUD・参照APIのみを実装し、アシスタントとの紐付けは別チケットとする。

移植元の`TenantService`を調査した結果、**作成・更新・削除は`type`が`LOCAL_SERVER`のエンドポイントに限定**されており、それ以外のタイプ（`AZURE_OPENAI_CHAT`・`CLAUDE_CHAT`・`GEMINI_CHAT`・`OPENAI_CHAT`・`OPENAI_WEB_SEARCH_CHAT`・`AZURE_OPENAI_EMBEDDING`・`VDB`）はこのAPI経由では作成・更新・削除できない（`assertLocalServerOnly`により`IllegalArgumentException`）ことが判明した。これらクラウドAIプロバイダーの接続情報は、本APIとは別の手段（運用者による直接投入等）で管理される想定と考えられる。参照系（一覧取得）は全タイプが対象。

## 機能要件

### エンドポイント

- `GET /api/admin/tenants/{tenantId}/endpoints`：テナント内の全エンドポイント一覧取得（全タイプ対象）。テナント管理者専用
- `POST /api/admin/tenants/{tenantId}/endpoints`：エンドポイント作成。**`type`が`LOCAL_SERVER`以外の場合は400エラー**。テナント管理者専用
- `PATCH /api/admin/tenants/{tenantId}/endpoints/{endpointId}`：エンドポイント更新。**対象エンドポイントの現在の`type`、および更新後の`type`（指定された場合）がいずれも`LOCAL_SERVER`でなければ400エラー**。テナント管理者専用
- `DELETE /api/admin/tenants/{tenantId}/endpoints/{id}`：エンドポイント削除。**対象エンドポイントの`type`が`LOCAL_SERVER`以外の場合は400エラー**。テナント管理者専用
- `GET /api/admin/tenants/endpoints/{type}`：指定タイプのエンドポイント一覧取得（全タイプ対象、アシスタント作成・編集画面のモデル選択肢用途）。テナント管理者専用

### 権限モデル

- 全エンドポイントともテナント管理者専用（`require_admin`を使用）
- パスパラメータの`tenantId`が、認証済みユーザーのテナントIDと一致することを確認する（移植元の`ensureTenantMatchesContext`相当。既存の`get_verified_tenant_id`依存関数の仕組みを踏襲する）

### バリデーション

- `type`・`endpointName`・`endpoint`・`apiKey`は作成時必須（移植元の`@NotBlank`相当）
- `endpoint`はURL形式であることを検証する（移植元の`@URL`相当。Pydanticの`HttpUrl`等での検証を検討する）
- 更新時、`apiKey`が指定されなかった場合は既存の値を保持する（移植元の`if (apiKey != null) endPointExist.setApiKey(apiKey)`相当）

### レスポンス

- レスポンスに`apiKey`を一切含めない（移植元の`@JsonProperty(access = WRITE_ONLY)`相当）
- フィールド：`id`, `tenantId`, `type`, `endpointName`, `endpoint`

## 非機能要件

- APIキーはDBに平文で保存する（移植元と同じ方針。アプリ側の暗号化は行わない。ユーザー承認済み）
- 既存の`backend/.claude/CLAUDE.md`のレイヤー構成に従う
- エンドポイントIDは既存パターンと同様、UUID（ハイフンなし32文字hex）で生成する

## スコープ外

- `assistants_endpoints`中間テーブル・アシスタントとの紐付け（別チケット）
- `GET /tenants/endpoints/local/{endpointId}`（ローカルサーバー種別向けの個別参照。用途を精査してから対応要否を判断）
- `GET /admin/tenants/resources/{resourceId}/cost`（Azureコスト管理、ビリング機能未実装のためスコープ外）
- APIキーのアプリ側暗号化
- 管理者向けアシスタントCRUD（別チケット）
- `frontend`（React）側の対応（当面不問方針のため）
