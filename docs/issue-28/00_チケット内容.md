# テナントエンドポイント（AI接続先）管理APIの実装

## 概要

NAW-XXXX（複数チケットにまたがる機能）の一部移植。issue-26で保留していたテナントエンドポイント（AI接続先）管理APIをFastAPIで実装する。

## 説明

### 背景

issue-26でアシスタント一覧取得APIを実装したが、`endpoints`は常に空配列で返している。移植元では、アシスタントは`TenantEndpoint`（テナントごとのAI接続先：Azure OpenAI/Claude/Gemini等のURL・APIキー・モデル種別）と`assistants_endpoints`中間テーブルを介して紐づき、実際のチャット機能に必要な接続情報を保持する。

本チケットでは、まず`tenant_endpoints`本体のCRUD（管理者向け）のみを実装する。アシスタントとの紐付け（`assistants_endpoints`）は別チケットとする。

### APIキーの取り扱い

移植元は`TenantEndpoint.apiKey`を平文でDB保存し、`@JsonProperty(access = WRITE_ONLY)`によりAPIレスポンスには一切含めない設計（保護はRLS＋レスポンス除外のみ、アプリ側の暗号化なし）。本チケットでも同じ方針を踏襲する（暗号化は別チケットで検討）。

### やること（今回のスコープ）

- `tenant_endpoints`テーブル・モデルを新規作成する
  - `id`, `tenant_id`, `type`（Enum: `LOCAL_SERVER`, `VDB`, `AZURE_OPENAI_CHAT`, `CLAUDE_CHAT`, `GEMINI_CHAT`, `OPENAI_CHAT`, `OPENAI_WEB_SEARCH_CHAT`, `AZURE_OPENAI_EMBEDDING`）, `endpoint_name`, `endpoint`（URL）, `api_key`
- `GET /api/admin/tenants/{tenantId}/endpoints`：エンドポイント一覧取得（テナント管理者専用）
- `POST /api/admin/tenants/{tenantId}/endpoints`：作成（テナント管理者専用）
- `PATCH /api/admin/tenants/{tenantId}/endpoints/{endpointId}`：更新（テナント管理者専用）
- `DELETE /api/admin/tenants/{tenantId}/endpoints/{id}`：削除（テナント管理者専用）
- `GET /api/admin/tenants/endpoints/{type}`：タイプ別エンドポイント一覧取得（アシスタント作成・編集画面のモデル選択肢用）
- レスポンスに`apiKey`を一切含めない（移植元と同じ`WRITE_ONLY`相当の設計）

### スコープ外（後続チケット）

- `assistants_endpoints`中間テーブル・アシスタントとの紐付け（`GET /api/assistants`のendpoints項目を実データにする対応）
- `GET /tenants/endpoints/local/{endpointId}`（ローカルサーバー種別向けの個別参照。用途を精査してから対応要否を判断）
- `GET /admin/tenants/resources/{resourceId}/cost`（Azureコスト管理、ビリング機能未実装のためスコープ外）
- APIキーのアプリ側暗号化（今回は移植元と同じ平文保存＋レスポンス除外のみ）
- 管理者向けアシスタントCRUD（別チケット）
