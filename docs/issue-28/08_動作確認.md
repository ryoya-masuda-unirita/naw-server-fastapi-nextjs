- `docker compose up -d`（postgres起動済み、追加操作なし）
- `cd backend && .venv/bin/python -m alembic upgrade head` でマイグレーション適用
- `cd backend && .venv/bin/python -m uvicorn app.main:app --port 8001` でバックエンドを起動
- 確認はcurlを用いてClaude Codeが実施（本チケットはAPIのみのスコープのため、フロントエンド確認は行わない）

## マイグレーションの冪等性確認

```
$ alembic upgrade head
$ alembic downgrade 004 && alembic upgrade head
$ alembic downgrade 004 && alembic upgrade head
REVERSIBILITY OK
```

`upgrade→downgrade→upgrade`を2往復実行し、`endpointtype`のPostgresネイティブEnum型が重複エラーなく再作成されることを確認した（issue-26のcode-review指摘を踏まえ、最初から`users`テーブルと同じ形式で実装済み）。

## API直叩きでの確認

### LOCAL_SERVERエンドポイントの作成

```
$ curl -X POST /api/admin/tenants/test-tenant/endpoints -d '{"type":"LOCAL_SERVER","endpointName":"ローカルサーバー","endpoint":"http://localhost:9000","apiKey":"my-secret-key"}'
{"id":"...","tenantId":"test-tenant","type":"LOCAL_SERVER","endpointName":"ローカルサーバー","endpoint":"http://localhost:9000"}
```

✅ レスポンスに`apiKey`が含まれないことを確認

### LOCAL_SERVER以外のタイプでの作成拒否

```
$ curl -X POST /api/admin/tenants/test-tenant/endpoints -d '{"type":"AZURE_OPENAI_CHAT", ...}'
HTTP/1.1 400 Bad Request
```

✅ `assertLocalServerOnly`相当の制約が機能することを確認

### 一覧取得・更新・タイプ別取得・削除

```
$ curl /api/admin/tenants/test-tenant/endpoints
[{"id":"...","type":"LOCAL_SERVER", ...}]  ← apiKeyなし

$ curl -X PATCH /api/admin/tenants/test-tenant/endpoints/{id} -d '{"endpointName":"改名済み"}'
{"id":"...","endpointName":"改名済み", ...}  ← apiKeyを指定しなくても成功

$ curl /api/admin/tenants/endpoints/LOCAL_SERVER
[{"id":"...","type":"LOCAL_SERVER", ...}]

$ curl -X DELETE /api/admin/tenants/test-tenant/endpoints/{id}
HTTP/1.1 204 No Content
```

すべて期待通りの結果を確認した。
