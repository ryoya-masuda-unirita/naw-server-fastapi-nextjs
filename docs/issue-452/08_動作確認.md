# 08_動作確認

## 確認環境

- macOS、`feature/issue-452`
- `waha-emulator/` と `generative-ai-adapter/` の `uv run pytest`（アダプタはモック）
- オンプレ（`onprem/` の docker compose）: waha-emulator を再ビルドして、ひな形入りの例の設定（`workflows.bedrock.example.json`）で起動。ベクトル DB は実物（pgvector）、埋め込みは実際の Bedrock（Titan）

## 確認手順

1. 先にテストを足し、修正前のコードで失敗することを確かめる
2. 実装し、テストと ruff を実行する
3. オンプレで、waha-emulator の API に直接、`kb-learn-hr` と `kb-learn-expense` で別の文書を学習する
4. ベクトル DB のテーブルと、質問時のアクセス先を確かめる

## 確認結果

### テスト

- 修正前のコードで、追加したテスト 23 件が失敗した
- 修正後: `waha-emulator` 201 passed、`generative-ai-adapter` 1431 passed, 3 skipped。ruff（format・check）も問題なし

### オンプレの実機（実際のベクトル DB・Bedrock）

- `kb-learn-hr` に `情報セキュリティ方針.txt`、`kb-learn-expense` に `経費精算の手順.md` を学習 → どちらも `SUCCESS`
- 保存先のテーブルが自動で作られた（設定の書き足しと再起動なし）

| テーブル | 中身（先頭） | 行数 |
|---|---|---|
| `docs`（従来） | 情報セキュリティ方針（以前の学習） | 1 |
| `docs_hr`（新規） | 情報セキュリティ方針 | 1 |
| `docs_expense`（新規） | 経費精算の手順 | 1 |

- 質問時にアクセスが増えたテーブル（`pg_stat_user_tables` の読み取り回数の差）

| 質問したアシスタントのサービス ID | アクセスが増えたテーブル |
|---|---|
| `bedrock-rag-hr` | `docs_hr` だけ |
| `bedrock-rag-expense` | `docs_expense` だけ |
| `bedrock-rag`（従来） | `docs` だけ |

- 不正な接尾辞（大文字・記号など）は、API で 400 になる（自動テストで確認）

## 未確認事項

- **RAG の回答の生成（Bedrock）が、回答を却下する**（#452 の範囲外の別件）: 検索はできている（`contexts=1`）が、回答の段階で `rag answer rejected: provider=Bedrock` になり、定型文「提供された情報からは答えが分かりませんでした」が返る。`rag-answer` の呼び出し 1 回のあと、検証（`rag-validation`）の呼び出しがなく、Claude の回答が RAG の形式として読み取れなかった可能性がある（#436 の `08_動作確認.md` で、RAG の回答は未確認だった部分）。このため、フォルダごとに「回答が文書の内容に基づく」ところまでは、確認できていない。分離そのものは、検索先のテーブルで確認した
- 画面（クラウド側）から、フォルダ・アシスタントを作っての通しの確認は、まだ行っていない
- 接尾辞のそろえ間違いは、システムが検知しない（README に注意を書いた）
