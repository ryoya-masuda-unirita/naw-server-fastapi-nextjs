# 04_テスト設計

## テスト方針

外部通信（Bedrock）はモックまたはテスト用の定義で行い、本物には接続しない。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | ひな形の読み込み | `kb-learn-*` と `{name}` を持つ定義を読む | 読める。前の部分が `kb-learn-` のひな形として登録される |
| 2 | ひな形の誤り | `{name}` がないひな形 / 前の部分が空（`*` だけ）/ 構造の誤り | 読み込みで分かる失敗になる |
| 3 | 接尾辞の反映 | `kb-learn-hr` を解決する | 保存先が `docs_hr` のワークフローになる |
| 4 | 分離 | `kb-learn-hr` と `kb-learn-expense` を解決する | 別の保存先（`docs_hr`・`docs_expense`）になり、混ざらない |
| 5 | 4 つの組 | 同じ接尾辞で学習・取得・削除・質問を解決する | 4 つとも同じ保存先を指す |
| 6 | 優先順位 | 個別に書いたサービス ID と、ひな形に当てはまるものが重なる | 個別のものが優先される |
| 7 | 当てはまらない | ひな形にない名前 / 前の部分だけで接尾辞が空（`kb-learn-`）| 従来どおり（学習・同期の判別 → 既定） |
| 8 | 接尾辞の検証 | 大文字・記号・空白・`;`・長すぎる名前を接尾辞にする | 400 で失敗し、保存先を作らない（SQL 注入の入力も拒否） |
| 9 | 使い回し | 同じサービス ID を 2 回解決する | 同じワークフローが返る |
| 10 | 最長一致 | 前の部分が重なる 2 つのひな形 | 長いほうが選ばれる |
| 11 | フォルダごとの分離（設定 → レジストリ） | 学習・取得・削除・質問の 4 つのひな形を書き、接尾辞が `hr` と `expense` のサービス ID を解決する | 同じ接尾辞の 4 つは同じ保存先（`docs_hr`）を指し、違う接尾辞は別の保存先（`docs_expense`）を指す |
| 11b | フォルダごとの分離（実際のベクトル DB） | オンプレで、`hr` と `expense` に別の文書を学習し、それぞれの質問用で質問する（自動テストにはせず、`08_動作確認.md` で確かめる） | 保存先のテーブルが自動で作られ、質問のとき、自分の接尾辞のテーブルだけが検索される |
| 12 | 回帰 | 既存のテストをすべて実行する | ひな形を使わない既存の設定の結果が変わらない |
