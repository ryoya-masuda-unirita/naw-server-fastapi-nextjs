# 01_要件定義

## 背景

オンプレ検証環境（`onprem/`）は、本物の Waha! の代わりに waha-emulator を動かす。学習・取得・削除・質問は、それぞれサービス ID で呼ばれ、保存先と検索先はサービス ID の設定で決まる。今は、設定ファイルにサービス ID を 1 つずつ書く作りで、フォルダごとに保存先を分けるには、フォルダを作るたびに設定を書き足して再起動する必要がある。

移植元の製品も、フォルダごとの保存先は、Waha! 側のジョブ設定（サービス ID）で決まる。エミュレーターは、そのジョブを、名前の規則で自動的に用意できるようにする。

## 機能要件

| No | 要件 |
|---|---|
| F1 | 設定ファイルに、サービス ID の「ひな形」を書ける。ひな形のサービス ID は、前の部分が決まった名前に、任意の接尾辞が続く形（例: 前の部分が `kb-learn-` で、接尾辞が `hr`） |
| F2 | ひな形の設定の中で、接尾辞を入れる場所（例: 保存先のテーブル名）を書ける。接尾辞が `hr` のサービス ID では、その場所が `hr` になる |
| F3 | 学習・取得・削除・質問のサービス ID に、同じ接尾辞を付けると、同じ保存先を指す。違う接尾辞の保存先とは、混ざらない |
| F4 | 保存先は、最初の学習のときに自動で作られる（既存の挙動）。設定ファイルの書き足しと、エミュレーターの再起動は要らない |
| F5 | 設定ファイルに個別に書いたサービス ID（ひな形でない）は、従来どおり、ひな形より優先する。登録のないサービス ID は、従来どおり既定になる |
| F6 | 接尾辞は、テーブル名として安全な文字（英小文字・数字・アンダースコア）の決まった長さに限る。不正なときは、保存先を作らず、分かる失敗にする |
| F7 | 例の設定（Bedrock）と README に、ひな形と、フォルダごとに分ける手順を書く |

## 非機能要件

- 既存の設定（ひな形を使わない設定）の挙動と、既存のテストの結果が変わらない
- 追加・変更する関数・メソッド・クラスに、日本語の NumPy 形式の docstring を書く
- テストのメソッド名は英語、意図は日本語の docstring
- 外部通信を行うテストは、モックまたはテスト用の接続で行い、本物の Bedrock には接続しない
- 接尾辞から作るテーブル名は、SQL に埋め込まれるため、検証済みの文字だけにして、注入を防ぐ

## スコープ外

- server-local がフォルダの ID を Waha! へ渡す変更（本物の Waha! の仕様を変える提案になるため）
- 画面でのアシスタントとフォルダの結びつけ（移植元でも、セキュアのアシスタントは学習先フォルダを選ばない）
- 既存の `docs` の中のデータの移行
- 本物の Waha! での確認
