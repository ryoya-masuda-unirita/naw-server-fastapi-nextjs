## 詳細

### 1. ワークフローの覚えすぎ（🟡 注意）→ 対応済み

接尾辞は 1〜40 文字の英小文字・数字・`_` なら何通りでも有効で、変えながら呼ばれるたびにワークフローを作って残していた。覚えておく数に上限（256）を設け、超えたら古いものから捨てる。捨てても、次に呼ばれたときに作り直すだけなので、動作は変わらない。上限を確かめるテスト（`test_template_workflow_cache_is_bounded`）を足した。

### 2. ハイフンなどが使えない（🔵 提案）→ 対応済み

接尾辞は保存先のテーブル名（SQL）になるため、制限は意図したもの（ハイフンは引用符なしのテーブル名に使えず、大文字は小文字に変わって `HR` と `hr` が同じ保存先になる）。接尾辞が不正なときに 400 になる点は、設計（`03_詳細設計.md`）のとおり。「server-local のバグに見える」という懸念は、README に、使えない文字と、`hr-dept` でなく `hr_dept` にする例を明記して解消した。エラーメッセージにも使える文字を書いてある。

### 3. `*` の確認の重複（🔵 提案）→ 対応済み

`_is_template_key`（末尾に 1 つだけ `*` があるか）にまとめ、`_template` 側の重複した確認を消した。

### 4. 接尾辞のそろえ間違い（🔵 提案）→ 対応しない

学習・取得・削除・質問のサービス ID は、別々のリクエストで呼ばれ、サーバー側に「同じフォルダのもの」という情報がない。読み込み時や起動時には、そろえ間違いを検知できない。README に、そろえ間違いを検知できないことと、症状（空の保存先を探して「分かりません」と答える）を書いてある。画面でフォルダとアシスタントを結びつける機能は、移植元の仕様にもなく、スコープ外（`01_要件定義.md`）。
