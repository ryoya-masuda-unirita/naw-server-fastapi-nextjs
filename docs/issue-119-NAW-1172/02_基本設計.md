# 02_基本設計

## 変更対象

- `app/routers/users.py`（`GET /api/admin/users`）
- `app/routers/groups.py`（`GET /api/admin/groups/{group_id}/users`）
- `app/services/user_service.py`
- `app/services/group_service.py`
- `app/repositories/token_usage_repository.py`
- `app/repositories/group_user_repository.py`
- `app/schemas/user.py`
- `app/core/credit_quota.py`（billing period 解決ロジックの拡張）

## 画面 / API 変更概要

- `GET /api/admin/users` に `includeUsage`（真偽値、デフォルトfalse）クエリパラメータを追加
- `GET /api/admin/groups/{group_id}/users` に同様の `includeUsage` パラメータを追加
- 両APIで `sort=totalCredits` を許可し、`includeUsage=true` の場合のみ有効とする
- レスポンス（`UserResponse`・既存の `GroupMemberUserResponse`）に `totalCredits`（`int | None`）を含める。`None` の場合はレスポンスから省略する

## 影響範囲

- ユーザー一覧・グループメンバー一覧の呼び出し元（管理画面フロントエンド）。`includeUsage` 未指定時は既存の挙動と完全互換（`totalCredits` は付与されない）
- `GroupMemberUserResponse` は既にスキーマに `totalCredits` フィールドを持つが常に `None` 固定だったため、実際に値が入るようになる
- `UserResponse` に新規フィールド `totalCredits` を追加する。既存の `UserCreateResponse`・`UserUpdateResponse`・プロフィール取得系エンドポイントは `total_credits` を渡さないため引き続き `None`（`GET /api/admin/users` 以外のレスポンスへの影響はなし。`GET /api/admin/users` のみ `response_model_exclude_none=True` を追加）

## 移植方針

- 請求期間（billing period）解決は、既に移植済みの `app/core/credit_quota.resolve_active_billing_period` をそのまま流用する（移植元 `BillingPeriodService.resolveActiveBillingContext` 相当）
- `sort=totalCredits` のバリデーション（`includeUsage=false` の場合400）は、移植元 `UserBillingUsageService.validateTotalCreditsSort` 相当として `app/core/credit_quota.py` に関数を追加する
  - `UserService`・`GroupService` の双方から呼ぶ必要があるが、`xxx_service.py` が別の `yyy_service.py` を呼ぶ構造は禁止のため、共通ロジックは `core/` に置く（既存の `enforce_within_quota` 等と同じ配置方針）
- ユーザー単位のクレジット合計集計（移植元 `TokenUsageRepository.sumTotalCreditsByUserIdsInPeriod` 相当）は `app/repositories/token_usage_repository.py` に `sum_total_credits_by_user_ids` を新設し、IN句で1クエリ一括取得する（N+1回避）
- `sort=totalCredits` のDBソート（移植元 `Specification` によるサブクエリソート相当）は、`app/core/credit_quota.py` に `total_credits_correlated_subquery` として汎用的な相関サブクエリ生成関数を切り出し、`UserService.get_users` と `GroupUserRepository.find_page_by_group` の双方から利用する
- `UserBillingUsageService` そのものに対応する単一のサービスクラスは作らず、上記の通り「バリデーション」「サブクエリ生成」「一括集計」の3つの関数・メソッドに分解して配置する（Pythonの関数ベースのユーティリティ配置方針に合わせるため。詳細は `03_詳細設計.md` に記載）
