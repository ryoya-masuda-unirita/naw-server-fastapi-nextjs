# 01_要件定義

## 背景

管理者がユーザー管理画面・チーム管理画面でユーザー一覧を閲覧する際、各ユーザーのクレジット利用量を確認しながら、利用量の多い順・少ない順に並び替えたいという要望がある。移植元（Spring Boot）では NAW-1172 として、`includeUsage` パラメータの追加と `sort=totalCredits` ソートが既に実装済みであり、これを FastAPI 側に移植する。

前提として NAW-1125（クレジット利用状況ダッシュボード）が既に移植済みであり、テナントの有効な請求期間（billing period）を解決するロジックがバックエンドに存在する。本チケットはこのロジックを流用し、ユーザー単位の集計に拡張する。

## 機能要件

- ユーザー一覧API（`GET /api/admin/users`）・グループメンバー一覧API（`GET /api/admin/groups/{id}/users`）に `includeUsage`（真偽値、デフォルトfalse）パラメータを追加する
- `includeUsage=true` の場合、有効な請求期間内の各ユーザーのクレジット利用量合計（`totalCredits`）をレスポンスの各要素に付与する
- 有効な請求期間が存在しない（有効なサブスクリプション契約がない等）場合は `totalCredits` を含めない（レスポンスから省略する）
- `sort=totalCredits` を指定した場合、`totalCredits` の降順・昇順でソートする
  - `includeUsage=false` の状態で `sort=totalCredits` を指定した場合は 400 エラーを返す
  - `includeUsage=true` かつ有効な請求期間が存在しない場合、`sort=totalCredits` は無効化され、既定のソート（作成日時等）にフォールバックする
- `totalCredits` が同値の場合は名前順で安定的にソートする

## 非機能要件

- ユーザー一覧・グループメンバー一覧のページ内クレジット集計は、ユーザーごとに個別クエリを発行せず、1回のクエリで一括取得する（N+1回避）
- `sort=totalCredits` によるソート自体もDBクエリ側（SQLの `ORDER BY`）で行い、アプリケーション側での全件ソートは行わない
- 既存の billing period 解決ロジック（`app/core/credit_quota.py`）を再利用する

## スコープ外

- フロントエンド（`frontend/` React移植）対応（`secuaigent-client` 側は型・モックが既に対応済みだが、本チケットはバックエンドのみ）
- `GET /api/users`（一般ユーザー向けプロフィール取得等）への `includeUsage` 対応（移植元も対象は管理者向け一覧APIのみ）
