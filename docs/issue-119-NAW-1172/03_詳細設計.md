# 03_詳細設計

## `app/core/credit_quota.py`

- `TOTAL_CREDITS_SORT_PROPERTY = "totalCredits"` 定数を追加
- `is_sort_by_total_credits(sort: str) -> bool`: `sort.split(",")[0] == TOTAL_CREDITS_SORT_PROPERTY` を判定
- `validate_total_credits_sort(sort: str, include_usage: bool) -> None`: `sort=totalCredits` かつ `include_usage=False` の場合 `HTTPException(400, "sort=totalCredits requires includeUsage=true")`
- `total_credits_correlated_subquery(tenant_id, from_, to, user_id_column) -> Any`: `TokenUsage` を `user_id_column` に相関させ、`input_credits+output_credits+embedding_credits` の `COALESCE(SUM(...), 0)` を返すスカラーサブクエリ。`ORDER BY` にそのまま利用する

## `app/repositories/token_usage_repository.py`

- `sum_total_credits_by_user_ids(tenant_id, from_, to, user_ids, session) -> dict[UUID, int]` を追加
  - `user_ids` が空なら即 `{}` を返しクエリを発行しない
  - `TokenUsage.user_id IN (:user_ids)` で絞り込み `GROUP BY user_id` で集計（1クエリ、N+1回避）

## `app/schemas/user.py`

- `UserResponse` に `totalCredits: int | None = None` を追加
- `UserResponse.from_user(user, total_credits: int | None = None)` にパラメータ追加（デフォルトNoneのため既存呼び出し元は変更不要）

## `app/routers/users.py`

- `GET /api/admin/users` に `includeUsage: bool = Query(False)` を追加
- `response_model_exclude_none=True` を追加（`totalCredits=None` の場合にレスポンスから省略するため）
- `UserService.get_users(..., include_usage=includeUsage)` として呼び出す

## `app/services/user_service.py`

- `get_users` のシグネチャ末尾にキーワード専用引数 `include_usage: bool = False` を追加（既存の位置引数呼び出しとの後方互換性を保つ）
- 冒頭で `validate_total_credits_sort(sort, include_usage)` を呼ぶ
- `include_usage=True` の場合のみ `resolve_active_billing_period(tenant_id, session)` を呼び、`period: tuple[datetime, datetime] | None` を得る
- `sort_col_name == "totalCredits"` かつ `period is not None` の場合、`total_credits_correlated_subquery` を用いてDBクエリで `ORDER BY` する（副次ソートに `User.name.asc()` を付与）。それ以外は既存の `_resolve_sort_column` にフォールバック
  - `period is None`（有効な請求期間なし）の場合は `sort=totalCredits` が指定されていても `_resolve_sort_column("totalCredits")` が許可リスト外のため `User.created_at` にフォールバックする。これは移植元と完全一致ではないが、Java側の「JPQLソートに未知のプロパティを渡した場合の挙動」が不明瞭なため、無効なDBソートで例外になることを避ける安全側の設計判断とした
- ページ取得後、`include_usage and period is not None` の場合のみ `TokenUsageRepository.sum_total_credits_by_user_ids` で一括取得し `UserResponse.from_user(u, totals.get(u.id, 0))` を構築。`include_usage=True` かつ `period is None` の場合は `totalCredits=None`。`include_usage=False` の場合は従来通り `UserResponse.from_user(u)`

## `app/repositories/group_user_repository.py`

- `find_page_by_group` にキーワード専用引数 `billing_period: tuple[datetime, datetime] | None = None` を追加
- `sort_col_name == "totalCredits"` かつ `billing_period is not None` の場合、`total_credits_correlated_subquery(tenant_id, period_from, period_to, GroupUser.user_id)` でDBソート（副次ソートに `User.name.asc()`）。それ以外は既存の `role`/`updatedAt`/`name` 分岐にフォールバック

## `app/services/group_service.py`

- `list_group_users` にキーワード専用引数 `include_usage: bool = False` を追加
- `user_service.py` と同様に `validate_total_credits_sort` → `resolve_active_billing_period` → `find_page_by_group(..., billing_period=period)` → `sum_total_credits_by_user_ids` の一括集計、の流れで実装
- `GroupMemberUserResponse` 生成時に `totalCredits=totals.get(u.id, 0) if include_usage and period is not None else None` を設定（既存フィールドを利用、`response_model_exclude_none=True` は既に付与済みのため追加変更不要）

## `app/routers/groups.py`

- `GET /api/admin/groups/{group_id}/users` に `includeUsage: bool = Query(False)` を追加し `GroupService.list_group_users(..., include_usage=includeUsage)` として呼び出す

## 移植元との差分メモ

- 移植元は `UserBillingUsageService` という単一クラスに集約しているが、Python版はレイヤー規約（service間呼び出し禁止）に従い、`core/credit_quota.py`（バリデーション・サブクエリ生成）・`repositories/token_usage_repository.py`（一括集計）に分割配置した
- 移植元の `UserListItem` レコード（`User`+`Long totalCredits`のペア）に相当する中間型は導入せず、`UserResponse.from_user(user, total_credits)` に直接値を渡す形で簡略化した（Pythonでは中間DTOを都度作らずレスポンス構築時に直接渡す方が自然なため）
