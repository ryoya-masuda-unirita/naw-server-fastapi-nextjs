### 失敗した6件について

以下6件は本Issue着手前から`develop`ブランチに存在する既知の事前失敗であり、本Issueの変更に起因しないことを確認済み。

```
tests/integration/test_credit_usage.py::TestCreditUsageRouter::TestGetMyCreditUsage::test_get_my_credit_usage_with_active_subscription
tests/integration/test_credit_usage.py::TestCreditUsageRouter::TestGetWorkspaceCreditUsage::test_get_workspace_credit_usage_with_active_subscription
tests/integration/test_credit_usage.py::TestCreditUsageRouter::TestGetWorkspaceCreditUsage::test_get_workspace_credit_usage_expired_subscription_is_treated_as_inactive
tests/integration/test_files.py::TestFilesRouter::TestUpload::test_quota_exceeded_returns_429
tests/integration/test_files.py::TestFilesRouter::TestUpdate::test_update_with_file_quota_exceeded_returns_429
tests/integration/test_tenants.py::TestTenantsRouter::TestPatchAdminTenant::test_patch_returns_400_when_usage_exceeds_new_limit
```

`git stash` して変更前のコードで `pytest tests/integration/test_credit_usage.py` を実行しても同一の3件（`test_get_my_credit_usage_with_active_subscription`・`test_get_workspace_credit_usage_with_active_subscription`・`test_get_workspace_credit_usage_expired_subscription_is_treated_as_inactive`）が失敗することを確認済み。原因は `Subscription.start_date = date.today()`（ローカルタイムゾーン基準）を使うテストフィクスチャと、`app/core/billing_cycle.py` のUTC基準の請求期間解決ロジックとの境界日ズレによるもので、本Issueと直接関連する領域だが、本Issueで新規に発生した問題ではなく、`app/core/billing_cycle.py` 自体の修正は本Issueのスコープ外と判断した。自チームで追加したテスト（`tests/integration/test_users.py`・`tests/integration/test_groups.py`）では、この既知の問題を回避するため `start_date` に十分なマージン（2日以上）を持たせている。
