# 05_テスト詳細設計

## テスト対象ファイル

- `backend/tests/integration/test_library_tags.py`

## fixture方針

`tests/integration/test_assistant_categories.py` と同様の構成を踏襲する。

- `tenant` / `other_tenant`: テスト用テナント
- `admin_user` / `member_user`: 管理者・一般ユーザー
- `tag` / `second_tag`: 検証用ライブラリタグ（同一テナント内で2件、重複名チェック用）
- `other_tenant_tag`: 他テナントのライブラリタグ
- `admin_headers` / `member_headers`: 認証ヘッダー

## テストクラス構成

```python
class TestListLibraryTags:
    """GET /api/libraries/tags"""
    # 一般ユーザーで自テナント分のみ名前順に返ること
    # 0件の場合空リストが返ること

class TestListLibraryTagsAdmin:
    """GET /api/admin/library-tags"""
    # ページング・検索付きで取得できること
    # searchでワイルドカード文字(%, _)を含む名前も文字通り検索されること
    # 非管理者は403になること

class TestCreateLibraryTag:
    """POST /api/admin/library-tags"""
    # 正しいリクエストで作成できること
    # 名前が空白のみだと422になること
    # 同名タグが既に存在する場合400になること
    # 非管理者は403になること

class TestUpdateLibraryTag:
    """PATCH /api/admin/library-tags/{id}"""
    # name/descriptionを更新できること
    # 未指定項目は現状維持されること
    # 存在しないIDだと404になること
    # 他テナントのIDだと404になること
    # 非管理者は403になること

class TestDeleteLibraryTags:
    """DELETE /api/admin/library-tags"""
    # 指定したIDが削除され204が返ること
    # 存在しないIDを含んでも204が返り、存在するものだけ削除されること
    # 非管理者は403になること
```

## モックデータ

`tag`: name="契約書", description="契約書関連のライブラリ"
`second_tag`: name="規程", description="規程関連のライブラリ"（重複名チェック用の別名）
`other_tenant_tag`: name="他テナントタグ"
