# 02_基本設計

## 変更対象

- 新規テーブル `library_tags`
- 新規 router / service / repository / model / schema 一式

## 画面 / API 変更概要

| メソッド | パス | 権限 | 概要 |
|---|---|---|---|
| GET | `/api/libraries/tags` | 認証ユーザー | テナント内タグを名前順に全件取得 |
| GET | `/api/admin/library-tags` | 管理者 | ページング・検索付き一覧取得 |
| POST | `/api/admin/library-tags` | 管理者 | 新規作成 |
| PATCH | `/api/admin/library-tags/{id}` | 管理者 | 更新（未指定項目は現状維持） |
| DELETE | `/api/admin/library-tags` | 管理者 | 一括削除（body指定） |

## 影響範囲

- 新規追加のみで既存機能への影響はない
- `app/main.py` にルーター登録を追加

## 移植方針

- レイヤー構成・命名は既存の `assistant_categories` 実装を踏襲する
- ページング一覧は既存の `PagedResponse` 形式ではなく、Spring版が `Page<T>` をそのまま返す構造（`content`/`totalElements`/`number`/`size`）に合わせる
- 移植元の検索（LIKE + ワイルドカードエスケープ）はSQLAlchemyの `ilike` + エスケープ処理で再現する
- 移植元の更新処理（空文字列・nullは更新しない）はAPI側で「未指定（None）の場合のみ現状維持」に合わせる
