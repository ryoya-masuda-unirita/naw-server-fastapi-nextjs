# 03 詳細設計

## API とのやり取り

| 操作 | 送るもの（移植元どおり） |
|---|---|
| 一覧 | `GET /api/admin/users?page=(pageIndex-1)&size&searchText=(trim。なければ空文字)&role=(ADMIN/SYSTEM/USER。なければ空文字)&sort=(field,order)&includeUsage=true` |
| 作成 | `POST`。`{ loginId(trim), name(trim), role(大文字), issueLoginKey?: true }` |
| 更新 | `PATCH /api/admin/users/{encodeURIComponent(loginId)}`。`{ name, resetPassword?: true, loginKeyAction?(KEEP は送らない), role? }` |
| 削除 | `DELETE /api/admin/users/{loginId}` を選択件数ぶん並行。1 件でも失敗したら全体を失敗扱い（再取得もしない） |

作成・更新・削除は `skipGlobalErrorToast: true`（画面で個別にトーストを出すため。移植元 `SKIP_GLOBAL_ERROR_TOAST`）。

## backend との差（`docs/issue-279/api-backend-diff.md` の行と、#309 の範囲）

| 項目 | 現在の backend | 移植元 server | この PR の対応 |
|---|---|---|---|
| ページ番号 | `page` | `number` | 画面側で吸収（`number ?? page`）。#309 で `number` になれば `page` の読み取りは不要 |
| ログインキー | 行・作成・更新の応答に `loginKey`（保存値そのもの）。`hasLoginKey` なし | `hasLoginKey` だけ。`loginKey` は発行・再発行したときだけ平文 | 一覧の設定状況は `hasLoginKey ?? (loginKey の有無)` で吸収。値は画面に出さない。**保存値を返す問題自体は #309（セキュリティ）の範囲** |
| 更新のキー操作 | `loginKey`・`resetPassword` を受ける | `loginKeyAction`（KEEP/REISSUE/REVOKE） | 画面は移植元どおり `loginKeyAction` を送る。backend が受けるのは #309。それまでキーの再発行・削除は効かない |
| 作成のキー発行 | `loginKey` を受ける | `issueLoginKey` | 同上（`issueLoginKey` を送る。#309 の範囲） |
| `displayName`・`accountType`・`email`・`updatedAt` | なし | あり | 画面は `name`・`'none'`・`''`・現在時刻で補う（移植元の normalize と同じ） |

注意: 現在の backend は更新の応答にも保存済みの `loginKey` を入れるため、更新のたびに「ログインキー」の表示ダイアログが出てしまう。#309 で応答が移植元どおりになれば出なくなる（画面側のロジックは移植元どおり `loginKey` があれば表示）。

## 移植元と変えた点（判断と理由）

| 点 | 内容 | 理由 |
|---|---|---|
| 読み込み中の表示 | `CircularLoading` を出す | 移植元は `<app-svg-icon name="loading">` だが、`loading` は SvgIcon の辞書にない（移植元でも描画されない）。空白のままだと読み込み中か分からない |
| `user-list-tenant.helpers`・`UserListAuthService` | 移植しない | サブドメイン前提のテナント補修。認証とヘッダーは api-client・ガードに任せる（ルート CLAUDE.md） |
| `openMenuId`・`toggleMenu`・`closeMenu` | 移植しない | 移植元でも未使用（メニューは `app-context-menu` が持つ） |
| 削除ダイアログの `class: 'm-w-[calc(100vw-32px)]'` | 移植しない | Tailwind に存在しないクラス（タイポ）で、効いていない |
| 追加・編集の「入力欄のフォーカス」 | ダイアログを閉じたら待機中の処理を取り消す | 移植元は `document.querySelector` で探すが、React では閉じた後に別の入力欄へ当たりうるため（テストで実際に起きた） |
| ラベルの `for` | 検索欄のみ `data-testid` | 共通部品（`SearchInput`・`Select`）が `id` を受けない |
| パスワードのコピーボタン | `data-testid` を足した | テスト用（移植元はキーのボタンだけ持つ） |

## 移植元のまま残した挙動

- 表示名・ユーザーIDの必須チェックは空文字だけ（空白だけは通り、trim 後に API が弾いて `CREATE_FAILED`）。Angular の `Validators.required` と同じ。
- 検索は 1 文字ごとに取り直す（debounce なし）。
- 一覧の取得失敗は空の一覧（共通のエラートーストは api-client 側）。

## 共通ファイルへの変更

- `src/mocks/handlers/index.ts`（`adminUsersHandlers` を追加）。ほかの共通ファイル（`routes/index.tsx`・`index.css`・`i18n`・`package.json`・`api-paths.ts` など）は触っていない。
