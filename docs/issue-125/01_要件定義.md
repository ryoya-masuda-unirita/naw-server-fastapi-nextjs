# 01 要件定義

## 機能要件（移植元のとおり）

1. 一覧: 表示名・ユーザーID・権限・請求期間内クレジット（桁区切り）・ログインキーの設定状況（アイコンのみ。値は出さない）。PC は表、モバイルは項目名付きの縦並び。
2. 絞り込み・並べ替え: 検索（部分一致）、権限フィルター（全て・管理者・一般）、並べ替え（更新日時・名前・権限・利用クレジット、昇順・降順）。条件を変えたら 1 ページ目に戻り、選択を外す。既定は名前の昇順・10 件。
3. ページング: 上は前後ボタンと件数表示、下は前後ボタン。
4. 選択と削除: 行・全選択のチェック。選択中は作成ボタンが「選択を解除」「削除」に替わる。行メニューの「削除」は 1 件。削除は確認ダイアログを経て並行して DELETE する。
5. 追加ダイアログ: 表示名・ユーザーID（必須・100 文字以内）、ログインキーを発行する、権限（一般・管理者）。作成後は条件を既定に戻し、トーストと、初期パスワード（とキー）の 1 回限りの表示ダイアログを出す。
6. 編集ダイアログ: 表示名、ユーザーID（変更不可）、ログインキーの操作（変更しない・再発行/発行・削除）、権限、パスワードをリセットする。保存したときだけ API を呼ぶ。初期パスワードまたはキーが返ったら表示ダイアログを出す。SYSTEM の行は「一般」で開き、管理者に変えたときだけ権限を送る。
7. 表示ダイアログ: 背景クリック・Esc で閉じない。コピーボタン（3 秒間「コピーしました」）。閉じたら平文を状態から消す。
8. 失敗時: 作成・更新・削除の失敗は共通のエラートーストを出さず、画面のトースト（`*_FAILED`）を出し、ダイアログは閉じない。

## 非機能・制約

- 文言は既存の i18n 辞書のキーのみ（キーを足さない）。
- テナント識別にサブドメインを使わない（`user-list-tenant.helpers`・`UserListAuthService` の hostname 補修は移植しない。`X-Tenant-ID` は api-client が付ける）。
