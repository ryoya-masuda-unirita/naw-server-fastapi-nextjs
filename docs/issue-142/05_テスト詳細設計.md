# 05_テスト詳細設計

## 実行コマンド（ローカル）

```bash
cd backend

# mypy: CIに組み込む対象コマンドと同一のものをローカルで実行
uv run mypy app tests

# pytest: 既存テストへの非回帰を確認
uv run pytest tests/unit -q

# ruff: 既存のフォーマット・リンターチェックへの非回帰を確認
uv run ruff format --check .
uv run ruff check .
```

## 対象ファイル

- `.github/workflows/backend-tests.yml`（変更対象。ワークフロー定義ファイルのためユニットテストの対象にはならない。GitHub Actions上での実行結果で検証する）
- `backend/pyproject.toml`・`backend/tests/unit/test_azure_cost_client.py`・`backend/app/services/index_service.py`・`backend/app/services/message_service.py`（前提反映分。Issue #140/#141 で既にレビュー済みのため、新規テストケースは追加しない）

## 確認手順（CI）

1. `feature/issue-142` ブランチから `develop` 向けの PR を作成する
2. `gh pr checks <PR番号>` または GitHub Actions の実行結果画面で、`unit-tests`・`lint`・`mypy` の各ジョブが実行され、成功していることを確認する
3. `integration-tests` ジョブは `develop` へのマージ時のみ実行される設定（`if: github.ref == 'refs/heads/develop'`）のため、PR時点では `skipped` 表示になることを確認する（既存仕様通りであり、本Issueによる変化ではない）

## 期待結果

- `uv run mypy app tests`: `Success: no issues found in 195 source files`
- `uv run pytest tests/unit -q`: 全件成功（Issue #141完了時点と同数）
- `uv run ruff format --check .`・`uv run ruff check .`: 両方成功
- CI: PR上で `unit-tests`・`lint`・`mypy` の3ジョブが成功、`integration-tests` は `skipped`
