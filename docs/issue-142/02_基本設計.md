# 02_基本設計

## 変更対象

- `.github/workflows/backend-tests.yml`（mypy を実行する新規ジョブを追加）

## 画面 / API 変更概要

該当なし（CIワークフローの変更のみで、画面・APIの変更は行わない）。

## 影響範囲

- backend の CI 実行結果（PR画面・Actionsタブに表示されるチェック一覧に `mypy` ジョブが新たに追加される）
- 既存の `unit-tests`（単体テスト）・`integration-tests`（結合テスト）・`lint`（Ruff）ジョブの実行内容・結果には影響しない（独立ジョブとして追加するため）
- 実行時のアプリケーション動作（API レスポンス、DB アクセス等）には一切影響しない

## 移植方針

本Issueは移植作業ではなく、backend自体のCI設定整備。既存の `lint` ジョブと同じ構成（`actions/checkout` → `setup-uv` → `setup-python` → `uv sync --locked` → 実行コマンド）を踏襲し、`mypy` という新規ジョブを追加する。

- 実行コマンドは Issue #139〜#141 で標準化した `uv run mypy app tests` をそのまま使う（`backend/pyproject.toml` の `[tool.mypy]` に `files = ["app", "tests"]` を設定済みのため、引数を省略しても同じ対象になるが、ローカル運用のコマンドと明示的に揃えるため `app tests` を明記する）
- `.env` の準備は mypy 実行に不要（実行時の環境変数読み込みではなく静的解析のため）なので、`lint` ジョブと同様に省略する
- 既存の `on.pull_request`/`on.push` の `paths`（`backend/**`、`.github/workflows/backend-tests.yml`）をそのまま利用し、mypyジョブ専用のトリガー変更は行わない
