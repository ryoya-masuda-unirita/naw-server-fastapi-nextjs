# 01_要件定義

## 背景

Issue #139〜#141 により、backend の mypy 設定は段階導入向けに整備済みで、`uv run mypy app tests` はエラー0件（195 source files）になっている。Ruff と pytest は既に CI（`.github/workflows/backend-tests.yml`）に組み込まれているが、mypy はまだ CI に組み込まれておらず、ローカルでの実行漏れがあると型の回帰に気付けない状態にある。

## 機能要件

- `.github/workflows/backend-tests.yml` に mypy を実行するジョブを追加する
- 実行コマンドは、これまでの Issue（#139〜#141）で標準化した `uv run mypy app tests` に合わせる
- 既存の `lint`（Ruff）ジョブ・`unit-tests`（pytest）ジョブとは独立したジョブとして追加し、失敗原因が種類ごとに区別できるようにする
- mypy ジョブは PR 作成・更新時、および `backend/**` もしくは本ワークフロー自身への push 時に実行されるようにする（既存の `on.pull_request`/`on.push` の `paths` 条件をそのまま利用する）

## 非機能要件

- 既存の Ruff / 単体テスト・結合テストの CI ジョブに影響を与えない（並列実行される独立ジョブとして追加する）
- CI 実行時間を大きく悪化させない（依存インストールは既存ジョブと同様に `uv sync --locked` + キャッシュを利用する）

## スコープ外

- backend 全体 strict mode の強制
- 未対応範囲（`app.repositories.*` 等、`[[tool.mypy.overrides]]` で `ignore_errors = true` にしているモジュール）の型エラー一括修正
- mypy 設定自体（`[tool.mypy]` の対象範囲・除外設定）の変更（#140 で整備済み。本Issueでは変更しない）
