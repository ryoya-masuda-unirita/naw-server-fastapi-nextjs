# 03_詳細設計

## 標準実行コマンド（CI・ローカル共通）

```bash
cd backend
uv run mypy app tests
```

## 追加するジョブ（`.github/workflows/backend-tests.yml`）

既存の `lint` ジョブの直後に、以下の `mypy` ジョブを追加する。

```yaml
  mypy:
    name: mypyチェック
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: backend
    steps:
      - uses: actions/checkout@v4

      - name: uvをインストール
        uses: astral-sh/setup-uv@v8.3.0
        with:
          enable-cache: true

      - name: Pythonをセットアップ
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: 依存関係をインストール
        run: uv sync --locked

      - name: mypyを実行
        run: uv run mypy app tests
```

- `lint` ジョブと同様、`.env` 準備ステップは含めない（mypy は静的解析のみで実行時の環境変数を読まないため）
- `on.pull_request`/`on.push` の `paths` フィルタは既存のワークフロー全体設定をそのまま利用する（ジョブ単位でのトリガー変更はしない）

## 前提: develop未マージのIssue #139〜#141 相当の変更を作業ブランチへ反映

`develop` には Issue #139（PR #143）・#140（PR #144）・#141（PR #145）がまだマージされていない。本Issueの作業ブランチ（`feature/issue-142`）は `develop` から作成したため、mypy設定・エラー修正が反映されていない状態だった。

このままではCIにmypyを組み込んでも、除外設定前の435件のエラーで確実に失敗し、CI組み込み自体の検証ができない。そのため、Issue #141 の作業ブランチ（`feature/issue-141`、PR #145）から以下の2コミットを `cherry-pick` して先行反映した。

| コミット | 内容 |

| `1dfcde2`（`#141 issue-141 mypy設定をdevelop未マージのIssue#140相当に先行反映`） | `backend/pyproject.toml` の `[tool.mypy]` 整備（PR #144 と同内容）、`tests/unit/test_azure_cost_client.py` の不要な `# type: ignore` 削除 |
