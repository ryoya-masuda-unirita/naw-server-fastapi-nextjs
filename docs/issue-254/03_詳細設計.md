# 03_詳細設計

## 変更ファイル

### `backend/app/services/message_service.py`

`stream_message_content` 内の `event_stream()` の `finally` 節のみ変更する。

- 局所変数 `persist_failed = False` を追加する
- `_persist_message_content` の `except ValueError` を `except Exception` に広げ、`persist_failed = True` を立てる（`content_response = None` は従来どおり）
- `_persist_library` を `try/except Exception` で囲み、失敗時は `logger.exception("ライブラリの永続化に失敗しました")` と `persist_failed = True`
- `_persist_token_usage` を `try/except Exception` で囲み、失敗時は `logger.exception("トークン使用量の永続化に失敗しました")` と `persist_failed = True`。回答の保存が失敗してもトークン使用量の保存は実行する
- message_content を送る条件を `stream_finished and content_response is not None and not persist_failed` にする
- それ以外で `stream_finished` の場合は、従来どおり `sse_event("error", {"message": _PERSIST_ERROR_MESSAGE})`（「エラーが発生しました。」）を送る
- クライアント切断（`GeneratorExit`）時は `stream_finished` が False のため yield しない。保存の例外はすべて捕捉されるため、終了処理で例外が送出されない

`except Exception` では `GeneratorExit`・`CancelledError`（`BaseException` のサブクラス）は捕捉しないため、切断・キャンセルの伝播は妨げない。

### `backend/app/services/llm_chat_service.py`

`stream_chat` 内の `event_stream()` の `finally` 節のみ変更する。

- `_persist_library` を `try/except Exception` で囲み、`logger.exception("ライブラリの永続化に失敗しました")`
- `_persist_token_usage` を `try/except Exception` で囲み、`logger.exception("トークン使用量の永続化に失敗しました")`
- error イベントは送らない（移植元 `LlmChatService.streamAndPersist` は `emitter.complete()` 後に保存するため）

### 移植元の根拠

- `server/src/main/java/com/example/naw/service/MessageService.java` `streamAndPersist`: 内側の catch（LLM 失敗）→ ERROR で保存・`sendSseError`・最終応答。成功時は `persistLibrary` → `persistMessageContent`（トークン使用量も同一トランザクション）→ `sendSseMessageStop` → `sendSseFinalResponse`。これらの例外は一番外側の `catch (Exception e)` で `sendSseError` → `emitter.complete()`
- `server/src/main/java/com/example/naw/service/LlmChatService.java` `streamAndPersist`: `sendMessageStop` → `emitter.complete()`（失敗時は `sendError` → `complete()`）、その後 `finally` で `persistTokenUsageInNewTransaction`
