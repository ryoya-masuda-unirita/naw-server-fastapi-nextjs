# 01_要件定義

> **状態: BLOCKED（方針判断待ち）**
> バックエンドを移植元に合わせる方針ではこの不一致を解消できないため、実装に進んでいない。下記「判断が必要な点」をユーザーに確認する。

## 背景

テンプレート名の上限が画面（100文字）と DB（32文字）で食い違っており、33〜100文字の名前を入れると画面のチェックは通るのに保存で失敗する。

## 調査結果（移植元・移植先の現状）

| 対象 | テンプレート名の上限 | 根拠 |
|---|---|---|
| 移植元 server（Spring Boot） | 32文字 | Liquibase `prompt_templates/changeset-001-init-table.xml` の `name varchar(32)`、エンティティ `PromptTemplate.name` の `@Column(length = 32)`。以降の changeset でカラム長の変更はない |
| 移植元 server のリクエスト検証 | なし | `PromptTemplateCreateRequest` に `@Size` 等の検証がない。33文字以上は DB への保存時にエラーとなる。例外ハンドラ（`APIControllerAdvice`）に DB 制約違反の扱いがないため、500 で返る |
| 移植元 client（上流 `secuaigent/client`） | 100文字 | `template-list.component.ts` のフォーム定義 `Validators.maxLength(100)` |
| 移植先 backend（FastAPI） | 32文字 | モデル `name` が `max_length=32`、マイグレーション `007_add_prompt_templates` も32文字。リクエストスキーマに検証はなく、移植元と同じ状態 |
| 移植先 frontend-angular | 100文字 | 上流 client のコピーで、上流と同じ |

**不一致は移植元（上流）そのものにある。** 移植先のバックエンドは、カラム長・検証の有無とも移植元と一致している。上流のコミット履歴にも、この不一致を直した変更はない（2026-11-12 時点）。

## 判断が必要な点

共通方針は「フロントとバックエンドの不一致は、バックエンドを移植元 Spring Boot の API 仕様に合わせて直す。`frontend-angular/` は変更しない」。この方針のもとでは次のとおりで、バックエンドだけでは Issue の症状（100文字まで入力できるのに保存できない）を解消できない。

1. 移植元のカラム長は32文字で、バックエンドはすでにそれに合っている。移植元に合わせて直す箇所がない。
2. 本来の修正はフロントエンドの上限を32文字にすることだが、`frontend-angular/` は上流 client のコピーで、同期のたびに上書きされる。修正は上流 client 側で行う必要がある。
3. バックエンドの上限を100文字に広げると症状は消える。ただし移植元のカラム長（32文字）と食い違い、マイグレーションも必要になる。移植元を根拠にする方針に反する。

選択肢:

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A（推奨） | 上流 client（`secuaigent/client`）でテンプレート名の上限を32文字にしてもらう。その後 `frontend-angular` を同期する | 移植元の DB 仕様に合う。移植先バックエンドの変更は不要 | 上流チームへの依頼が必要。このリポジトリだけでは完結しない |
| B | 移植先バックエンドのカラムを100文字に広げる（マイグレーション追加） | このリポジトリだけで症状が消える | 移植元と DB 仕様が食い違う。今後の移植・データ移行で差分の管理が要る |
| C | バックエンドのリクエスト検証に32文字上限を追加し、500 ではなく 400/422 で返す | 原因が分かるエラーになる | 画面は100文字まで入力でき、保存に失敗する症状は残る（Issue は閉じられない）。移植元は 500 のため挙動も変わる |

## スコープ外

- `frontend-angular/`・`frontend/` の変更（共通方針により変更しない）
