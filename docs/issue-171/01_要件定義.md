# 01_要件定義

> **方針: 案 C（ユーザー決定）**
> 一度 BLOCKED として Issue に選択肢を提示した。ユーザーが案 C（バックエンドのリクエスト検証に、DB カラムと同じ32文字の上限を入れる）に決めた。DB・マイグレーションは変更しない。`frontend-angular/` はリポジトリから削除する方針となったため、フロント側の対応は行わない。

## 背景

テンプレート名の上限が画面（100文字）と DB（32文字）で食い違っており、33〜100文字の名前を入れると画面のチェックは通るのに保存で失敗する。保存時の失敗は DB の制約違反で、利用者には原因の分からない 500 エラーとして返る。

## 調査結果（移植元・移植先の現状）

| 対象 | テンプレート名の上限 | 根拠 |
|---|---|---|
| 移植元 server（Spring Boot） | 32文字 | Liquibase `prompt_templates/changeset-001-init-table.xml` の `name varchar(32)`、エンティティ `PromptTemplate.name` の `@Column(length = 32)`。以降の changeset でカラム長の変更はない |
| 移植元 server のリクエスト検証 | なし | `PromptTemplateCreateRequest` に `@Size` 等の検証がない。33文字以上は DB への保存時にエラーとなる。例外ハンドラ（`APIControllerAdvice`）に DB 制約違反の扱いがないため、500 で返る |
| 移植元 client（上流 `secuaigent/client`） | 100文字 | `template-list.component.ts` のフォーム定義 `Validators.maxLength(100)` |
| 移植先 backend（FastAPI） | 32文字 | モデル `name` が `max_length=32`、マイグレーション `007_add_prompt_templates` も32文字。リクエストスキーマに検証はなく、移植元と同じ状態 |
| 移植先 frontend-angular | 100文字 | 上流 client のコピー（削除予定） |

不一致は移植元（上流）そのものにある。上流のコミット履歴にも、この不一致を直した変更はない（2026-11-12 時点）。

## 検討した選択肢

| 案 | 内容 | 採否 |
|---|---|---|
| A | 上流 client でテンプレート名の上限を32文字にしてもらう | 不採用（このリポジトリだけでは完結しない。frontend-angular は削除方針） |
| B | バックエンドのカラムを100文字に広げる（マイグレーション追加） | 不採用（移植元の DB 仕様と食い違う） |
| C | バックエンドのリクエスト検証に32文字上限を追加し、500 ではなく 422 で返す | **採用** |

## 機能要件

1. テンプレート作成 API・テンプレート更新 API は、テンプレート名が32文字を超えるリクエストを、DB に保存する前に 422 で拒否すること。
2. 32文字ちょうどのテンプレート名は、作成・更新とも従来どおり受け付けること。
3. 文字数は文字単位で数えること（DB の `varchar(32)` と同じく、日本語などのマルチバイト文字も1文字として数える）。
4. 拒否したときは、テンプレートの作成・更新を行わないこと（既存テンプレートの内容は変わらない）。
5. 上限値は DB カラムの長さと同じ値を使い、両者がずれないようにすること。

## 非機能要件

- DB スキーマは変更しない（マイグレーションなし）。
- エラー応答の形式は、他の API の入力検証エラーと同じ（FastAPI 標準の 422）とする。

## 移植元との差分

- 移植元はリクエスト検証がなく、33文字以上は 500 になる。移植先は保存前に 422 で返す。原因の分かるエラーにするための意図的な差分。

## スコープ外

- `frontend-angular/`・`frontend/` の変更（frontend-angular は削除方針、frontend は当面不問）。
- テンプレート名以外の項目（説明・システムプロンプト）の上限。DB はいずれも上限のない型で、本 Issue の不一致に関係しない。
- DB カラム長の変更。
