# 02_基本設計

## 変更対象

- バックエンド: テンプレート作成・更新 API のリクエスト定義
- バックエンド: テンプレートのデータ定義（上限値の共有のみ。DB スキーマは変えない）

## 画面 / API 変更概要

| API | 変更内容 |
|---|---|
| テンプレート作成（管理者向け） | テンプレート名が32文字を超えると 422 を返す |
| テンプレート更新（管理者向け） | テンプレート名が32文字を超えると 422 を返す |

| テンプレート名 | 変更前 | 変更後 |
|---|---|---|
| 32文字以下 | 作成・更新できる | 変更なし |
| 33文字以上 | DB の制約違反で 500（PostgreSQL） | 保存前に 422 |

422 の応答は FastAPI 標準の入力検証エラーと同じ形式（`detail` に、項目の位置・エラー種別・メッセージの一覧）。

## 影響範囲

- テンプレート作成・更新を呼ぶ画面: 33文字以上の名前で保存すると、500 ではなく 422 が返る。画面側はどちらもエラーとして扱う（作成失敗のトーストが出る）ため、操作上の違いはない。
- テンプレート一覧などの参照 API: 変更なし。
- DB: 変更なし。

## 移植方針

- 上限値は移植元の DB カラム長（32文字）を根拠にする。
- 移植元にはリクエスト検証がないが、移植先では保存前に検証して 422 を返す（ユーザー決定の案 C）。他の移植済み API（アシスタント名など）でも、DB カラム長に合わせた入力検証を入れている。
- 上限値はデータ定義に定数として置き、リクエスト定義から同じ定数を参照する。DB カラム長と検証の上限がずれないようにするため。
