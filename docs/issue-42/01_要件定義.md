# 01_要件定義

## 背景

issue-26で一般ユーザー向けの一覧取得（`GET /api/assistants`）のみ実装されたが、Assistant自体の作成・更新・削除、および管理者向けの一覧取得・絞り込みは未実装のまま残っていた。issue-40でAssistantCategory本体のCRUDが完了し、依存関係（Group・TenantEndpoint・AssistantCategory）がすべて揃ったため、本チケットでAssistant管理者向けCRUD一式を移植する。

移植元`AssistantController`調査の結果、以下が判明した。

- `assistant_category_mappings`（Assistant↔AssistantCategoryのM2M、PKは`assistant_id`+`category_id`。`tenant_id`列はあるがPK外）が未実装
- `ai_models`（AIモデルマスタ）が未実装
- 管理者向け一覧取得（`GET /api/admin/assistants`）は、テナント管理者だけでなく「グループ管理者」も呼び出せる。グループ管理者（`isGroupAdmin && !isAdmin`）の場合は、自身が管理者権限を持つグループに所属するアシスタントのみに絞り込まれる
- 削除は、そのアシスタントがルームのデフォルトアシスタントとして参照されている場合にDB制約違反（409）となるが、room（チャット本体）ドメインは本プロジェクトで未移植のため、本チケットでは物理的にこの制約は発生しない（後続のroom移植時に再検討）

## 機能要件

### 作成・更新・削除

- テナント管理者がアシスタントを作成・更新・削除できる
- 作成時の項目: `type`（SECURE/SAAS_CHAT/SAAS_RAG、必須）、`endpoints`（テナントエンドポイントIDとモデルの組、1件以上必須）、`indexId`（任意）、`groups`（所属グループID、任意）、`name`（必須・非空白・32文字以内）、`description`（任意・1000文字以内）、`includeHistory`（真偽値）、`iconColor`（任意。未指定時はランダムなHEXカラーをサーバー側で生成）、`categoryIds`（任意）
- 更新時は部分更新。`name`・`description`は未送信/nullなら変更しない、送信時は同じバリデーションを適用する。`type`・`endpoints`はSpring側の現行実装同様、更新のたびに必須（空配列不可）とする
- `categoryIds`・`groups`は「未送信/null」と「空配列」を区別しない。どちらの場合も送信されたリストで完全に置き換える（空配列なら全解除）
- `indexId`は空文字が送られた場合は`null`として保存する（SAAS_RAG→SAAS_CHAT/SECURE切替時の解除操作に対応）
- エンドポイント種別のバリデーション:
  - `SECURE`: 全エンドポイントが`LOCAL_SERVER`であること
  - `SAAS_CHAT`: 全エンドポイントがチャット系（`isChatType()`、種別名が`CHAT`で終わるもの）であること
  - `SAAS_RAG`: 全エンドポイントがチャット系であり、かつちょうど1件であること
- 削除は、対象が自テナントに属さない場合404、それ以外は削除する（room未移植のため409判定は本チケットのスコープ外）

### 管理者向け一覧取得

- `GET /api/admin/assistants`: ページネーション・検索（名前・説明の部分一致）・種別/カテゴリ/グループでの絞り込みに対応する
  - `categoryId=NONE`はカテゴリ未設定のアシスタントに絞り込む、`groupId=NONE`は未所属のアシスタントに絞り込む（移植元の予約値）
  - `excludeGroupId`指定時は、そのグループに所属**していない**アシスタントに絞り込む（グループへのアシスタント追加モーダル用）
  - 呼び出し元がテナント管理者でなく、かつ自身がいずれかのグループの管理者（グループ管理者）であり、`excludeGroupId`未指定の場合は、自身が管理するグループに所属するアシスタントのみに絞り込む
  - 上記以外（管理者権限もグループ管理者権限もない一般ユーザー）はアクセス不可
- `GET /api/admin/assistants/endpoints/{type}`: アシスタント種別（SECURE/SAAS_CHAT/SAAS_RAG）に応じて選択可能なテナントエンドポイント一覧を返す（作成・編集画面のエンドポイント選択用）
- `GET /api/admin/assistants/AIModels`: AIモデル一覧を返す（`ai_models`テーブルの新規移植を含む）

## 非機能要件

- 既存の管理者向けエンドポイントと同様、RLS（テナント分離）により他テナントのアシスタントを参照・操作できないようにする
- 一覧取得・エンドポイント紐付け解決においてN+1問題を発生させない（`assistants_endpoints`・`groups_assistants`・`assistant_category_mappings`はいずれもIN句/JOINで一括取得する）
- カテゴリ・グループ・エンドポイントの差分更新は、削除対象・追加対象を洗い出した上でバルク処理する（1件ずつのループ処理にしない）

## スコープ外

- 一般ユーザー向け一覧取得（`GET /api/assistants`）: issue-26で対応済み
- `assistants_endpoints`紐付け自体: issue-30で対応済み（本チケットは作成・更新時の差し替えロジックのみ扱う）
- room（チャット本体）からのアシスタント参照・デフォルトアシスタント削除時の409判定: room未移植のため後続チケット
- フロントエンド対応（本チケットはバックエンドのみ）
