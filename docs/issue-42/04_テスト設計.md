# 04_テスト設計

## 方針

既存ドメイン（AssistantCategory・PromptTemplate）と同様の構成に揃える。

| 種別 | ディレクトリ | 対象 |
|---|---|---|
| Router テスト | `unit/` | 6エンドポイントの正常系・異常系（`ASGITransport`、DB不要） |
| Service テスト | `unit/` | バリデーション・エンドポイント種別チェック・権限分岐・ソートマッピングをRepositoryモックで検証 |
| Model/Repository テスト | `integration/` | 実DBでの制約（PK・FK・CASCADE）、`find_page`の絞り込み・ソート、`replace_*`の差分更新を検証 |

## テスト観点

### 作成・更新・削除

- 作成: 正常作成、`iconColor`未指定時のランダム色生成、`indexId`空文字→null変換、必須項目欠如で422、名前空白で422
- 更新: 部分更新（name/description未送信で変更なし）、`categoryIds`/`groups`の空配列で全解除、`type`/`endpoints`省略で422（移植元同様必須）、404（他テナントのID）
- 削除: 正常削除、404（他テナントのID）
- エンドポイント種別バリデーション: `SECURE`+非LOCAL_SERVERで400、`SAAS_CHAT`+embedding系で400、`SAAS_RAG`+2件以上または非chat系で400

### 一覧取得

- ページネーション・ソート（デフォルト・`type`エイリアス・`category`名前ソート）
- 検索（name/description部分一致）
- `categoryId`（通常値・`NONE`）、`groupId`（通常値・`NONE`）、`excludeGroupId`の絞り込み
- グループ管理者（テナント管理者でない）が自分の管理グループのみに絞り込まれること
- テナント管理者は全件取得できること
- 管理者権限もグループ管理者権限もない一般ユーザーは403

### エンドポイント一覧・AIモデル一覧

- `SECURE`→`LOCAL_SERVER`のみ返る
- `SAAS_CHAT`/`SAAS_RAG`→チャット系エンドポイントのみ返る
- AIモデル一覧が全件返る

### N+1回避（Repositoryテスト）

- 複数アシスタント一覧取得時、カテゴリ・グループ・エンドポイントの取得クエリがそれぞれ1回であること（既存`GroupPromptTemplateRepository`同様の集約ロジックの単体検証）

### 権限

- テナント管理者: 全エンドポイント許可
- グループ管理者（テナント管理者でない）: 全エンドポイント許可（一覧のみ絞り込みあり）
- 一般ユーザー: 全エンドポイント403

### 既存機能への影響

- 一般ユーザー向け`GET /api/assistants`のレスポンスに、紐付けたカテゴリが実データとして返ること（既存テストの期待値更新）
