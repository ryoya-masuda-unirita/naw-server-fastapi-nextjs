# 08_動作確認

## 確認環境

- ローカルDB: `docker compose`起動済みの`naw-fastapi-postgres`（PostgreSQL、ポート5433）
- マイグレーション: `uv run alembic upgrade head`（008→010、`ai_models`・`assistant_category_mappings`テーブル作成）を実行
- サーバー: `uv run uvicorn app.main:app --port 8001`
- シードデータ: `backend/seed.sql`に、既存アシスタントとカテゴリの紐付け・AIモデル2件（`gpt-4o`・`claude-3-5-sonnet`）を追加し投入
- 認証: `create_access_token("admin", "test-tenant")`（テナント管理者）・`create_access_token("user01", "test-tenant")`（一般ユーザー）で発行したJWTを`Authorization: Bearer`ヘッダーに付与してcurlで直接呼び出し（issue-40と同じ方式）

## テスト実行結果

- `uv run pytest -q`: 242 passed（新規追加分を含む。既存219件は非破壊）
- `uv run ruff check .`: All checks passed
- `uv run ruff format .`: 実行し整形（`app/services/assistant_service.py`・`tests/integration/test_assistants.py`を整形）
- `uv run mypy app/`: 既存から37件増加（89→126件）。いずれも本プロジェクト全体に既存する`sa.Column`型付け起因の既知の誤検知パターンと同種で、CIも`ruff`のみを実行しmypyはゲートしていないため許容する
