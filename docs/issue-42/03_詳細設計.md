## 権限設計

移植元の`AdminAuthorizationFilter`は、`/api/admin/**`配下を「テナント管理者（ADMIN/SYSTEM） **または** いずれかのグループの管理者（グループ管理者）」に許可している。`AssistantController`は個々のメソッドで追加の`assertTenantAdmin()`呼び出しをしていない（Groupの作成/更新/削除は追加でテナント管理者必須にしているのと対照的）。そのため、**作成・更新・削除・一覧・エンドポイント一覧・AIモデル一覧のいずれも、グループ管理者であればテナント管理者でなくても呼び出せる**（グループ管理者に対する追加の絞り込みは一覧取得のみ）。

`app/core/security.py`に新規依存関数を追加する。

```python
async def require_admin_or_group_admin(
    x_tenant_id: str = Depends(get_verified_tenant_id),
    current_user: User = Depends(get_current_user),
    session: AsyncSession = Depends(get_session),
) -> User:
    """テナント管理者、またはいずれかのグループの管理者であることを検証する。

    移植元 AdminAuthorizationFilter（/api/admin/** への一律フィルタ）相当。
    """
    if current_user.role in (UserRole.ADMIN, UserRole.SYSTEM):
        return current_user
    admin_group_ids = await GroupUserRepository.find_admin_group_ids_for_user(
        x_tenant_id, current_user.id, session
    )
    if not admin_group_ids:
        raise HTTPException(status_code=403, detail="Access Denied")
    return current_user
```

6エンドポイントすべてこの依存関数を使う。一覧取得のみ、サービス層内部でさらに「グループ管理者かつテナント管理者でない場合は自分の管理グループに絞り込む」処理を行う。

既存`AssistantService`に以下を追加する（別serviceを呼ばないルールに従い、Group/AssistantCategory関連repositoryは直接使う）。

- `create_assistant(tenant_id, req, session) -> AssistantGetResponse`

  - `_validate_endpoint_types`でエンドポイント種別を検証（400）
  - Assistant保存 → エンドポイント・グループ・カテゴリを新規INSERT
- `update_assistant(assistant_id, tenant_id, req, session) -> AssistantGetResponse`
  - 404: 対象が存在しない
  - `name`/`description`: 送信時のみ上書き（Noneなら変更なし）
  - `categoryIds`/`groups`: 常に置き換え（`replace_*`系リポジトリメソッドで全削除→追加）
  - `endpoints`: 常に置き換え
- `delete_assistant(assistant_id, tenant_id, session) -> None`
  - 404: 対象が存在しない
  - room未移植のため409判定は行わない（コメントで明記）
- `list_admin_assistants(tenant_id, current_user, page, size, sort, search, type, category_id, group_id, exclude_group_id, session) -> PagedAssistantResponse`
  - `current_user`がテナント管理者でなく、`exclude_group_id`未指定の場合のみ`allowed_group_ids`（自分が管理者のグループID一覧）を算出し絞り込む
  - ソートキーのマッピング: `serverType`/`server`/`type`→DBの`type`列、`category`→カテゴリ名、それ以外（`name`）→そのまま。許可されないキーは`updatedAt`にフォールバックする
- `get_assistant_endpoints(assistant_type, tenant_id, session) -> list[AssistantEndpointResponse]`
  - `SECURE`→`LOCAL_SERVER`のみ、`SAAS_CHAT`/`SAAS_RAG`→チャット系エンドポイント全種別
- `get_ai_models(session) -> list[AIModelResponse]`
- 内部ヘルパー`_validate_endpoint_types(assistant_type, endpoints, tenant_id, session)`
  - `SECURE`: 全エンドポイントが`LOCAL_SERVER`でなければ400
  - `SAAS_CHAT`: 全エンドポイントがチャット系でなければ400
  - `SAAS_RAG`: 全エンドポイントがチャット系かつ1件でなければ400
- 一覧取得のレスポンス組み立ては、対象アシスタントID一覧に対して`assistants_endpoints`・`groups_assistants`・`assistant_category_mappings`をそれぞれ1回のIN句/JOINで取得しPython側で集約する（N+1回避）
