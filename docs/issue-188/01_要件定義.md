# 01_要件定義

## 背景

- ユーザーインポート機能の非同期化（#186）でSQS/S3を利用する設計となったが、これまではLocalStackによるローカル代替のみで、実際のAWS環境には対応するリソースが存在しない
- 当初は#187としてAWSマネジメントコンソールでの手動構築を予定していたが、恒久的な構成管理は本リポジトリの方針（ECS/RDS/ECR等と同様にTerraformで管理）に合わせるため、マネジメントコンソールでの手動構築は行わず、直接Terraformでコード化する
- dev/staging環境の再現性・変更履歴の追跡性を確保する

## 機能要件

- SQS標準キュー（ユーザーインポートジョブ用メインキュー）をTerraformで定義する
- デッドレターキュー（DLQ）をTerraformで定義し、メインキューと再配信ポリシー（最大受信回数到達時にDLQへ転送）で紐付ける
- S3バケット（ユーザーインポート用CSVの一時保存先）をTerraformで定義する。パブリックアクセスは許可しない
- ECS上で動くbackendアプリケーションが、SQSキューへのメッセージ送受信・削除、S3バケットへのオブジェクト操作を行えるよう、IAMロール・ポリシーをTerraformで定義し、ECSタスクロールとして付与する
- `terraform plan` を実行し、意図した差分のみが出ることを確認する（`terraform apply` は本チケットのスコープ外、ユーザーが別途実施する）

## 非機能要件

- 既存の`infra/`配下のリソース命名規則・タグ付け規約に合わせる
- SQSのVisibility Timeout・DLQへの最大受信回数は、参照実装（Spring Boot版 `application.yml` に記載の想定値）に準拠する
- IAM権限は必要最小限（対象のキュー・バケットに限定したリソースベースのスコープ）とする

## スコープ外

- `terraform apply` によるAWS実リソースの作成・変更（ユーザーが実施）
- CI/CDパイプラインへのTerraform組み込み（#189で対応）
- backend側のSQS/S3連携実装そのもの（#186で対応済み）
- 環境ごとのTerraform workspace分割など、既存の単一環境構成からの大きな構成変更（現状の`infra/`の構成に合わせる）
