# 02_基本設計

## 変更対象

- `infra/` 配下に新規Terraformリソース定義を追加(SQSキュー、DLQ、S3バケット、ECSタスクロール用IAM)
- 既存のECSタスク定義に、新規IAMロールの割り当てと環境変数(バケット名・キューURL)の追加

## 画面 / API 変更概要

- 画面・APIの変更は無し(インフラ定義のみ)

## 影響範囲

- `infra/` ディレクトリ(新規リソース追加のみで、既存のフロントエンド配信用S3・ECS実行ロール等の既存定義は変更しない)
- backendのECSタスク定義(タスクロールの新規付与、環境変数追加)
- 既存の`terraform.tfstate`に新規リソースが追加される(`terraform plan`で確認、`apply`はユーザーが実施)

## 移植方針

- 参照実装(Spring Boot版 `application.yml` の `aws.sqs` / `aws.s3` セクション、`SqsConfig.java`)に記載の想定値(Visibility Timeout、DLQ最大受信回数、バケット/キュー名の命名パターン)をTerraform変数のデフォルト値として踏襲する
- backend側の`.env.example`(`AWS_S3_BUCKET_NAME` / `AWS_SQS_QUEUE_URL`)と整合する名前になるよう、Terraformの出力値(`outputs.tf`)にバケット名・キューURLを追加する
- 既存の`infra/`の命名規則(`${var.project_name}-リソース種別`)・タグ付け(`Name`/`Project`)に合わせて新規リソースを定義する
- IAMは既存の`ecs_task_execution`ロール(ECR pull/CloudWatch Logs用)とは別に、新規`ecs_task`ロールを作成し、ECSタスク定義の`task_role_arn`として割り当てる(実行時権限と起動時権限を分離する既存のAWSベストプラクティスに合わせる)
