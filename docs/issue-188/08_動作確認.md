# 08_動作確認

## 確認環境

- `infra/` ディレクトリ、AWSプロファイル `naw-fastapi-issue158`（アカウントID: `035261964577`）
- 確認時点でdev環境のインフラはコスト削減のため`destroy`済み（ユーザーが意図的に全リソース削除した状態）。`terraform.tfstate`のリソースは0件

## 確認手順

```bash
cd infra
terraform fmt -check -diff
terraform validate
terraform plan \
  -target=aws_sqs_queue.user_import \
  -target=aws_sqs_queue.user_import_dlq \
  -target=aws_s3_bucket.user_import \
  -target=aws_s3_bucket_public_access_block.user_import \
  -target=aws_iam_role.backend_task \
  -target=aws_iam_role_policy.backend_task_sqs_s3 \
  -target=aws_ecs_task_definition.backend
```

`terraform plan`を`-target`で絞ったのは、`infra/main.tf`の`data "aws_route53_zone" "main"`が既存インフラ側の未整備状態（ホストゾーン0件）によりエラーとなり、`-target`無しではplan自体が実行できなかったため。

## 確認結果

- `terraform fmt -check -diff`: 差分あり（タグの`=`揃え・末尾空白除去のみ）。`terraform fmt`で自動整形し反映済み
- `terraform validate`: `Success! The configuration is valid.`
- `terraform plan`（`-target`指定）: `Plan: 19 to add, 0 to change, 0 to destroy`
  - dev環境が現在`destroy`済みのため、VPC/RDS/ECR等の既存リソースも含めて「新規作成」としてplanに現れた（想定通り。本来は既存インフラがある状態でSQS/S3/IAM関連の6リソースのみが追加される見込み）
  - 今回追加したリソースは全て意図通り`+ create`として計画に含まれている
    - `aws_sqs_queue.user_import`（`visibility_timeout_seconds = 300`、`redrive_policy`でDLQ紐付け）
    - `aws_sqs_queue.user_import_dlq`
    - `aws_s3_bucket.user_import`（`bucket = "naw-fastapi-issue160-user-import-jobs"`）
    - `aws_s3_bucket_public_access_block.user_import`（4項目とも`true`）
    - `aws_iam_role.backend_task`
    - `aws_iam_role_policy.backend_task_sqs_s3`（SQS/S3ともワイルドカード無しで対象リソースに限定）
  - `aws_ecs_task_definition.backend`にも意図通り`task_role_arn`・環境変数2件（`AWS_S3_BUCKET_NAME`, `AWS_SQS_QUEUE_URL`）が反映されている
  - 既存リソース（RDS、ALB、CloudFront等）への意図しない変更・削除は無し（`0 to change, 0 to destroy`）
- `terraform apply`は本チケットのスコープ外のため未実施。ユーザーが別途実施する
