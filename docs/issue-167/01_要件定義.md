# 01_要件定義

## 背景

パスワード再設定 API のリクエストボディで、画面が送るログインIDのキー名（`username`）と API が受け付けるキー名（`loginId`）が一致しておらず、パスワード再設定が常に入力エラー（422）で失敗している。

移植元（Spring Boot）の API 仕様を確認した結果、パスワード再設定リクエストのログインIDは正式名 `loginId` に加えて、別名 `username` でも受け付ける仕様になっている（API ドキュメントにも「ログインID (username も許容)」と明記されている）。移植先 API はこの別名受け付けを移植しておらず、仕様差分になっている。

## 機能要件

1. パスワード再設定 API は、ログインIDをキー名 `loginId` と `username` のどちらで受け取っても処理できること（移植元と同じ仕様）
2. `username` で受け取った場合も、`loginId` で受け取った場合と同じ業務処理（旧パスワード照合・ポリシー検証・履歴チェック・パスワード更新・セッション発行）に到達すること
3. ログインIDがどちらのキーでも送られなかった場合は、従来どおり入力エラー（422）とすること
4. 既存の `loginId` を使うクライアントの挙動は変えないこと

## 非機能要件

- 画面（frontend-angular / frontend）には手を入れない。frontend-angular は上流のコピーで同期のたびに上書きされるため、backend を移植元 API 仕様に合わせる形で解消する
- DB マイグレーションは発生させない

## スコープ外

- 移植元の `@NotBlank`（空文字・空白のみの入力を 400 とする）入力チェックの移植。本 Issue はフィールド名不一致の解消に限定する
- 移植元にある連続失敗時のロックアウト（429）の移植
- パスワード複雑性ポリシー（大文字/小文字/数字/記号）の検証（Issue #168 で別途対応）
- frontend-angular の E2E テスト（`test.skip` 中）の有効化
