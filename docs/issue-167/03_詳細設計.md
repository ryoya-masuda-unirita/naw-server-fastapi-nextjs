# 03_詳細設計

## 変更対象ファイル

| ファイル | 変更内容 |
|---|---|
| `backend/app/schemas/auth.py` | `PasswordResetRequest.loginId` に `Field(validation_alias=AliasChoices("loginId", "username"))` を付与し、入力時に `loginId` / `username` の両方を受け付ける |
| `backend/tests/integration/test_auth.py` | `username` キーでのパスワード再設定成功・旧パスワード誤り（403）、ログインID未指定（422）のテストを追加 |
| `backend/tests/unit/test_auth_schemas.py`（新規） | `PasswordResetRequest` のキー名受け付け（`loginId` / `username` / 両方指定時は `loginId` 優先 / 両方なしで ValidationError）の単体テスト |

## 移植元の根拠

- `secuaigent/server/src/main/java/com/example/naw/request/PasswordResetRequest.java`
  ```java
  @NotBlank(message = "ログインIDの入力は必須です。") @JsonAlias("username")
  @Schema(description = "ログインID (username も許容)", requiredMode = Schema.RequiredMode.REQUIRED)
  private String loginId;
  ```
- `secuaigent/server/src/main/java/com/example/naw/api/AuthController.java` の `POST /auth/password/reset` は `@Valid @RequestBody PasswordResetRequest` をそのまま `PasswordResetService.resetPassword` に渡す

## 実装詳細

```python
from pydantic import AliasChoices, BaseModel, Field


class PasswordResetRequest(BaseModel):
    """パスワードリセットリクエスト"""

    # 移植元は @JsonAlias("username") で username も受け付ける。
    # frontend-angular は username で送信するため、両方を許容する。
    loginId: str = Field(validation_alias=AliasChoices("loginId", "username"))
    oldPassword: str
    newPassword: str
```

- `validation_alias` は入力（バリデーション）時のみ有効で、属性名 `loginId` は変わらないため、`backend/app/routers/auth.py` の `request.loginId` 参照はそのまま使える
- `AliasChoices` は先頭から順に探すため、両方指定時は `loginId` が優先される

## エラー時の挙動

| ケース | レスポンス |
|---|---|
| `loginId` / `username` どちらもなし | 422 |
| ユーザーなし・旧パスワード誤り | 403（既存のサービス処理） |
| ポリシー違反・履歴重複 | 400（既存のサービス処理） |
