# 02_基本設計

## 変更対象

- 認証系のリクエストスキーマ（パスワード再設定リクエスト）
- 認証 API の結合テスト・スキーマの単体テスト

## 画面 / API 変更概要

### POST /auth/password/reset

| 項目 | 変更前 | 変更後 |
|---|---|---|
| ログインIDのキー名 | `loginId` のみ | `loginId` または `username`（移植元の別名受け付けと同じ） |
| 両方とも未指定 | 422 | 422（変更なし） |
| レスポンス | 変更なし | 変更なし |

両方のキーが同時に送られた場合は `loginId` を優先する。

画面の変更はない。

## 影響範囲

- パスワード再設定 API のみ。処理側はスキーマのログインID属性を参照しており、属性名は変えないため影響しない
- 他の認証 API（ログイン・ログインキー認証・トークン取得）は影響しない

## 移植方針

- 移植元のリクエストクラスは、正式名 `loginId` に別名 `username` を付けて両方を受け付けている。移植先でも属性名は `loginId` のまま、入力時の別名として `username` を許容する
- frontend は変更せず、backend 側を移植元仕様に合わせる
