# 03_詳細設計

## 実装対象ファイル

- `backend/.env.example`
- `backend/app/core/config.py`
- `backend/app/core/llm_client.py`

## テスト対象ファイル

- `backend/tests/unit/test_config.py`
- `backend/tests/unit/test_llm_client.py`

## 設定設計

`backend/app/core/config.py` に `AzureOpenAISettings` を追加する。既存の `CorsSettings` や `LlmCreditSettings` と同様、アプリ全体の `Settings` とは分離する。

追加する設定値:

| 設定項目 | 環境変数 | デフォルト | 用途 |
|---|---|---|---|
| `api_version` | `AZURE_OPENAI_API_VERSION` | `2024-10-21` | Chat Completions / Embeddings API |
| `responses_api_version` | `AZURE_OPENAI_RESPONSES_API_VERSION` | `2025-04-01-preview` | tools 指定時の Responses API |

`get_azure_openai_settings()` を `lru_cache` 付きで追加する。環境変数が未指定でもデフォルトで動くため、`app.main` import 時の必須設定は増えない。

`backend/.env.example` には、追加する環境変数をデフォルト値付きで追記する。API version は秘密値ではないため、サンプルに記載して運用時の設定漏れを防ぐ。

## LLMクライアント設計

`backend/app/core/llm_client.py` では、固定定数を設定クラスのデフォルト値として移動し、Azure client 生成時に `get_azure_openai_settings()` から API version を取得する。

利用箇所:

- Chat Completions API: `settings.api_version`
- Embeddings API: `settings.api_version`
- Responses API: `settings.responses_api_version`

endpoint / api_key / deploy_name は引き続き呼び出し元から受け取る。これはテナントごとの接続情報が DB 管理されているため。

## テスト設計

`backend/tests/unit/test_config.py` に `AzureOpenAISettings` のテストを追加する。

- 未指定時に現行値と同じデフォルトを返すこと
- 環境変数相当の値で上書きできること

`backend/tests/unit/test_llm_client.py` に Azure client 生成引数のテストを追加する。

- Chat Completions API で `api_version` が設定値になること
- Responses API で `api_version` が Responses 用設定値になること
- Embeddings API で `api_version` が設定値になること

## 互換性

環境変数を設定しない場合は現行の API version と同じ値を使う。既存の LLM API、SSE、トークン使用量計算、テナントエンドポイント管理の挙動は変更しない。
