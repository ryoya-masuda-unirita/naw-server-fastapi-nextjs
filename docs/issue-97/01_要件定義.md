# 01_要件定義

## 背景

- issue-88（`POST /api/llm/chat`, `POST /api/llm/embedding`）・issue-93（`POST /api/messages/content`）の両方で、添付ファイル対応は意図的にスコープ外とされていた。
- 移植元（Spring Boot）では、`multipart/form-data`でJSON部＋添付ファイル部を受け取り、画像ファイルはLLM呼び出し時にマルチモーダルの画像パートとして埋め込み、非画像ファイル（PDF等）はApache Tikaでテキスト抽出してプロンプトに埋め込んでいる。
- `historyAttachmentFiles`（過去ターンの添付ファイル）は、移植元では件数バリデーションのためだけに存在し、実際のLLM呼び出しには一切使われない（過去ターンは常にテキストのみで送信される設計）。

## 機能要件

- `POST /api/llm/chat`のリクエストに`attachmentFiles`（今回の呼び出しに対する添付ファイル一覧）を追加できること。
- `POST /api/messages/content`のリクエストに`attachmentFiles`（今回のユーザー発話に対する添付ファイル一覧）・`historyAttachmentFiles`（過去ターンの添付ファイル一覧、件数検証のみに使用）を追加できること。
- `attachmentFiles`は、ファイル名・content-type（`type`）・ファイル本体（Base64エンコード）を持つこと。
- 添付ファイルのうち画像ファイル（content-typeが`image/`で始まるもの）は、Azure OpenAI Chat Completions APIへのリクエストでマルチモーダルの画像パート（Base64データURL）として、最後のユーザー発話に埋め込まれること。
- `POST /api/messages/content`では、送信した`attachmentFiles`を`message_files`テーブルに永続化し、`GET`系API（`get_message_contents`等、既存実装）で取得できること。
- `historyAttachmentFiles`の件数が、`historyMessages`各ターンの`attachmentsCount`合計と一致しない場合はリクエストエラー（422）とすること（移植元`CreateMessageContentViewModel.isHistoryAttachmentCountCorrect`相当）。

## 非機能要件

- 既存のSSEストリーミング応答・トークン使用量永続化・クレジット上限チェックの挙動を変更しないこと。
- 添付ファイルが存在しない場合、LLM呼び出しのリクエスト形式（`content`が文字列のまま）を変更しないこと（既存の単体テストへの影響を避けるため）。

## スコープ外（移植元との差分・今回対応しない事項）

- **リクエスト形式の変更**: 移植元は`multipart/form-data`だが、本ポートでは他の既存エンドポイント（`LlmChatRequest`・`MessageContentCreateRequest`とも純粋なJSONボディ）との一貫性を優先し、`attachmentFiles`/`historyAttachmentFiles`もJSONボディ内でBase64エンコードして受け取る形式とする。`multipart/form-data`への変更は行わない。
- **非画像ファイルのテキスト抽出（Apache Tika相当）**: 移植元は非画像ファイル（PDF等）をTikaでテキスト抽出しプロンプトに埋め込むが、本ポートのPythonバックエンドには同等のテキスト抽出ライブラリが未導入。本Issueでは非画像ファイルのテキスト抽出は対象外とし、非画像ファイルは「テキスト抽出未対応の添付ファイルが存在する」旨のみをプロンプトに付記する（ファイル自体は`POST /api/messages/content`では永続化する）。
- **`POST /api/llm/chat`のターンごとのファイル名紐付け（移植元`attachments`フィールド）**: 移植元は各会話ターンにファイル名の配列を持たせ、ファイル名で突き合わせて対象ターンを判定する。本ポートでは複雑さ低減のため、`attachmentFiles`は常に最後のユーザー発話（`additionalPrompt`適用後）に対して一括で適用する。複数ターンへの個別紐付けは対象外とする。
- **`historyAttachmentFiles`の内容送信**: 移植元と同じく、過去ターンの添付ファイル内容はLLMへ再送しない（件数検証のみ）。
- **`POST /api/llm/embedding`**: 添付ファイルは対象外（移植元でも埋め込みAPIに添付ファイルは存在しない）。
- **`POST /api/messages/content`でのRAG/tools/ライブラリ生成・response_format・メッセージ再生成**: issue-93で既にスコープ外とされており、本Issueでも対象外のまま。
