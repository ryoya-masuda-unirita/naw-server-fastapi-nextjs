# 03_詳細設計

## 新規ファイル

### `backend/app/schemas/attachment.py`

```python
class AttachmentFile(BaseModel):
    name: str = Field(min_length=1, max_length=255)
    type: str = Field(min_length=1, max_length=128)
    data: bytes
```

- `LlmChatRequest`・`MessageContentCreateRequest`の双方から共通で参照する、添付ファイル1件のリクエストスキーマ。
- `data`は`bytes`型として宣言し、Pydantic v2の標準動作（JSON入力時はBase64文字列を自動デコード）に任せる。

### `backend/app/core/attachment_media.py`

- `IMAGE_CONTENT_TYPE_PREFIX = "image/"`
- `build_user_content(text: str, files: list[AttachmentFile]) -> str | list[dict[str, object]]`
  - `files`が空なら`text`をそのまま返す（既存の`str`ベースの挙動を維持）。
  - 画像ファイル（`type`が`image/`始まり）は`{"type": "image_url", "image_url": {"url": f"data:{type};base64,{base64データ}"}}`パートに変換する。
  - 非画像ファイルはテキスト抽出せず、`text`の末尾に「添付ファイル名は画像以外のためテキスト抽出未対応」の注記を付記する。
  - 戻り値は`[{"type": "text", "text": 本文}, 画像パート...]`のリスト形式（OpenAI Chat Completions APIのマルチモーダル`content`形式）。

## 変更対象ファイル

### `backend/app/core/llm_client.py`

- `ChatMessage.content`の型を`str`から`str | list[dict[str, object]]`に変更する。
- `AzureLlmChatClient.stream_chat`の`create_kwargs`組み立て（`{"role": ..., "content": ...}`）はそのまま変更不要（`content`が文字列でもリストでもAzure OpenAI SDKにそのまま渡せる）。

### `backend/app/schemas/llm.py`

- `LlmChatRequest`に`attachmentFiles: list[AttachmentFile] = []`を追加。
- docstringから「添付ファイル」をスコープ外の記述から除外する。

### `backend/app/schemas/message.py`

- `MessageContentHistoryTurn`に`attachmentsCount: int = Field(default=0, ge=0)`を追加。
- `MessageContentCreateRequest`に`attachmentFiles: list[AttachmentFile] = []`・`historyAttachmentFiles: list[AttachmentFile] = []`を追加。
- `MessageContentCreateRequest`に`@model_validator(mode="after")`で、`len(historyAttachmentFiles) == sum(turn.attachmentsCount for turn in historyMessages)`を検証するバリデータ（`_validate_history_attachment_count`）を追加し、不一致なら`ValueError`（422）とする。
- docstringから「添付ファイル」をスコープ外の記述から除外する。

### `backend/app/services/llm_chat_service.py`

- `_apply_attachment_files(messages: list[ChatMessage], files: list[AttachmentFile]) -> list[ChatMessage]`をstaticmethodとして追加（`_apply_additional_prompt`と同様、末尾から遡って最後の"user"発話を書き換える）。
- `stream_chat`内、`_apply_additional_prompt`適用後に`_apply_attachment_files(chat_messages, req.attachmentFiles)`を適用する。
- モジュールdocstringから「添付ファイル」をスコープ外の記述から除外する。

### `backend/app/services/message_service.py`

- モジュールレベル関数`_apply_attachment_files`（`_apply_additional_prompt`と同じファイル内、同様のロジック）を追加。
- `stream_message_content`内、`_apply_additional_prompt`適用後に`_apply_attachment_files(chat_messages, req.attachmentFiles)`を適用する。
- `event_stream`のクロージャ変数として`attachment_files = req.attachmentFiles`を捕捉し、`_persist_message_content`へ渡す。
- `_persist_message_content`に`attachment_files: list[AttachmentFile]`引数を追加。`MessageContent`保存後、`attachment_files`が空でなければ`MessageContentRepository.save_attachment_files`で`MessageFile`をまとめて保存し、レスポンスの`attachmentFiles`に反映する（現状は空リスト固定）。
- `stream_message_content`のdocstringから「添付ファイル」をスコープ外の記述から除外する。

### `backend/app/repositories/message_content_repository.py`

- `save_attachment_files(files: list[MessageFile], session: AsyncSession) -> list[MessageFile]`を追加。各`MessageFile`を`session.add`した後、1回の`commit`でまとめて保存する（`session.add`をループで呼ぶのはINSERTが1回にまとめられるため許容パターン、`backend/.claude/CLAUDE.md`のN+1回避ルールに準拠）。

## データ設計

- `message_files`テーブル・`MessageFile`モデルは変更不要（既存のまま`name`/`type`/`data`/`message_id`を利用）。
- マイグレーション追加は不要。
