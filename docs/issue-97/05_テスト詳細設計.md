# 05_テスト詳細設計

## 対象テストファイル

- `backend/tests/unit/test_attachment_media.py`（新規）: `build_user_content`の純粋関数テスト（04の1〜4）
- `backend/tests/unit/test_llm.py`（新規、または既存スキーマテストファイルがあれば追加）: `AttachmentFile`・`LlmChatRequest`のBase64デコード確認（04の5）
- `backend/tests/unit/test_message_service.py`（既存に追加）: `MessageContentCreateRequest`のhistoryAttachmentFiles検証（04の6, 7）、`_apply_attachment_files`（04の11, 12）、`stream_message_content`の添付ファイルあり/なしケース（04の13, 14）
- `backend/tests/unit/test_llm_chat_service.py`（既存に追加）: `_apply_attachment_files`（04の8, 9）、`stream_chat`の添付ファイルありケース（04の10）
- `backend/tests/unit/test_message_content_repository.py`または`backend/tests/integration/test_messages.py`（既存のリポジトリ/統合テストの並びに合わせて追加）: `save_attachment_files`（04の15）

## モック方針

- `LlmChatService`・`MessageService`のテストは既存パターン（`AzureLlmChatClient.stream_chat`をモックし、呼び出し引数の`messages`を検証する）を踏襲する。
- `mock_stream_chat.call_args`または`mock_stream_chat.await_args`から実際に渡された`messages`（`list[ChatMessage]`）を取得し、最後のuser発話の`content`がlist形式でimage_urlパートを含むことをアサートする。
- `MessageContentRepository.save_attachment_files`は`message_service`側テストでモックし、呼び出し引数の`MessageFile`一覧を検証する。
