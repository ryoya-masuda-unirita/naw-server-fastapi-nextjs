# 02_基本設計

## 変更対象

- `POST /api/llm/chat`（`LlmChatRequest`, `LlmChatService.stream_chat`）
- `POST /api/messages/content`（`MessageContentCreateRequest`, `MessageService.stream_message_content`）
- LLM呼び出し共通基盤（`ChatMessage`, Azure OpenAI呼び出しクライアント）
- 添付ファイルの永続化（`message_files`テーブルへの保存、既存の取得系実装はそのまま利用）

## API変更概要

- `LlmChatRequest`に`attachmentFiles`（添付ファイル一覧）を追加する。
- `MessageContentCreateRequest`に`attachmentFiles`（今回分）・`historyAttachmentFiles`（履歴分、件数検証のみ）を追加し、`historyMessages`の各ターンに`attachmentsCount`を追加する。
- 添付ファイル1件の形式は、ファイル名・content-type・Base64エンコードされたファイル本体を持つ共通のリクエストスキーマとする（新規/既存の他エンドポイントに影響しない専用スキーマとして追加）。
- レスポンス形式（`MessageContentResponse.attachmentFiles`）は既存のまま変更しない。今回のPOSTで送信した添付ファイルが、保存後にこの`attachmentFiles`へ反映されるようになる（従来は空リスト固定だった）。

## 影響範囲

- `backend/app/schemas/llm.py`, `backend/app/schemas/message.py`（リクエストスキーマ追加）
- `backend/app/schemas/attachment.py`（新規、共通の添付ファイルリクエストスキーマ）
- `backend/app/core/llm_client.py`（`ChatMessage.content`の型をマルチモーダル対応に拡張）
- `backend/app/core/attachment_media.py`（新規、添付ファイル→LLM入力コンテンツ変換の純粋関数）
- `backend/app/services/llm_chat_service.py`（添付ファイルを最後のユーザー発話に適用）
- `backend/app/services/message_service.py`（添付ファイルを最後のユーザー発話に適用、永続化）
- `backend/app/repositories/message_content_repository.py`（添付ファイル保存メソッドの追加）
- 既存の`message_files`テーブル・`MessageFile`モデル・添付ファイル取得系実装（`find_attachment_files_grouped_by_content_ids`）はそのまま利用し、変更不要。

## 移植方針

- 「serviceが別serviceを呼ばない」規約を維持するため、`_apply_additional_prompt`と同様に「最後のユーザー発話を探して書き換える」ロジック（`_apply_attachment_files`）は`llm_chat_service.py`・`message_service.py`の双方に複製する。ただし、添付ファイルからLLM入力コンテンツを組み立てる純粋関数（`build_user_content`）は、外部インフラ層である`core/attachment_media.py`に1つだけ置き、両方のserviceから呼び出す（`core/`はserviceから参照してよいため規約に抵触しない）。
- `ChatMessage.content`の型を`str`から`str | list[dict[str, object]]`に拡張する。添付ファイルがない場合は従来通り`str`のままとし、既存の単体テスト（`ChatMessage(role=..., content="...")`との等価比較）に影響しないようにする。
- 画像ファイルはAzure OpenAI Chat Completions APIの`image_url`パート（Base64データURL）としてそのまま埋め込む。非画像ファイルはテキスト抽出を行わず、ファイル名を付記するのみに留める（`01_要件定義.md`のスコープ外を参照）。
- `POST /api/messages/content`の添付ファイル永続化は、既存の`_persist_message_content`（新規セッションでの永続化）に相乗りさせ、`MessageContent`保存後に`MessageFile`を保存する。`POST /api/llm/chat`は元々`MessageContent`を作成しない設計のため、添付ファイルの永続化も行わない（LLM呼び出し時の一時的な利用のみ）。
