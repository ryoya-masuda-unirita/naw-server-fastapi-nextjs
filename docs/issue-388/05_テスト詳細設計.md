# 05_テスト詳細設計

| No | 確認方法 | 対象 |
|---|---|---|
| 1 | `terraform fmt -recursive -check -diff` と、環境（dev）の `init -backend=false` → `validate` | `secuaigent-infra/` |
| 2・3・6〜8 | 作業用ディレクトリに、変更前（`develop`）と変更後の `secuaigent-infra/` を置き、`AWS_PROFILE=oic` で backend をローカルに差し替えて `plan -out` → `terraform show -json`。アドレスで突き合わせ、増減と `values` の差分を出す。インラインポリシーと信頼条件の JSON は、`plan` で確定していれば、中身を比べる（確定しない場合は、コードを読む） | 同左 |
| 4・5 | `aws iam simulate-custom-policy`（読み取りのみ）。ポリシーは、`plan` から取り出した（確定していなければ、モジュールの式と同じ内容を JSON に書き起こす）デプロイ用のインラインポリシー。許可すべき操作と、拒否すべき操作を、一覧にして実行し、`EvalDecision` を表にする。リソースの ARN は、ダミーのアカウント ID（`111111111111`）で組み立てる。ダミーを使うので、実際のアカウントには影響しない | `AWS_PROFILE=oic` |
| 9 | `python3` で YAML を読み込む。検査の `bash` を、`AWS_INFRA_ROLE_ARN` が空・非空で実行する | `.github/workflows/deploy-infra.yml` |
| 10 | `grep -rn "github_actions_role_arn\|github_actions_infra_role_arn" secuaigent-infra .github` | 全体 |
| 11 | README を読み、記述を確認する | `secuaigent-infra/README.md` |
| 12 | `git diff` の追加行を目視。12 桁の数字・鍵の文字列を検索し、ヒットした場合は内容を確認する。確認は、文書の最後の更新のあとに行う | 変更ファイル全体 |

注意: `plan` とシミュレーターは、AWS に読み取りだけを行う。`apply` は実行しない。作業用ディレクトリの `terraform.tfvars` と `tfplan` は、確認後に削除する。
