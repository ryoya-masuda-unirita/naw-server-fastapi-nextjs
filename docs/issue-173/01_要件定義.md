# 01_要件定義

## 背景

ライブラリ一覧取得APIでタグによる絞り込みを指定すると、PostgreSQL上で「文字列型の列」と「UUID型の値」を比較するSQLが発行され、HTTP 500になる。管理画面のライブラリ一覧でタグフィルターが使えない。

移植元（Spring Boot）ではタグIDの列・パラメータともにUUID型で統一されているため問題にならないが、本リポジトリではタグIDを32桁hex文字列（ハイフンなし）の文字列型で移植しており、パラメータ（UUID）との間に型の不一致が生じている。

## 機能要件

- ライブラリ一覧取得でタグIDを1件以上指定したとき、指定タグのいずれかが付与されたライブラリのみが返ること（HTTP 200）
- タグIDはハイフン付きUUID形式・ハイフンなし32桁hex形式のどちらで指定しても同じ結果になること（タグ一覧APIはハイフンなし形式を返すため、画面からはハイフンなし形式で送られる）
- タグIDとしてUUIDとして解釈できない値を指定した場合は、これまでどおりリクエスト不正としてエラーを返すこと（移植元がUUID型でパラメータを受けるのと同じ扱い）
- 他の絞り込み条件（タイトル・作成者・除外作成者）やページング・ソートとの組み合わせ動作は変えないこと

## 非機能要件

- DBスキーマ（列の型）は変更しない（マイグレーションを発生させない）
- 自動テストはインメモリSQLiteで動くため、PostgreSQLの型不一致そのものは再現できない。PostgreSQL（asyncpg）向けにSQLを組み立てたときにタグIDが文字列として渡ることを、自動テストで検証する

## スコープ外

- タグID列をUUID型へ変更する（移植元に合わせる）スキーマ変更
- フロントエンド（`frontend-angular/`・`frontend/`）の変更、および Issue #166 で skip されたE2Eテストの有効化
- バリデーションエラー時のHTTPステータスを移植元（400）に揃えること（プロジェクト共通の扱いのため）
