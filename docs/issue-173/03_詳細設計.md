# 03_詳細設計

## 変更対象ファイル

| ファイル | 変更内容 |
|---|---|
| `backend/app/repositories/library_repository.py` | `LibraryRepository.find_page` のタグ絞り込み条件で、`tag_ids`（`list[uuid.UUID]`）を `[tag_id.hex for tag_id in tag_ids]` に変換してから `LibraryTagMapping.library_tag_id.in_()` に渡す。変換理由（列が `String(32)` でhex保存、UUIDのまま渡すとバインド型が `Uuid` と推論されasyncpgで `varchar = uuid` になる）をコメントで残す |
| `backend/tests/integration/test_library_repository.py`（新規） | 実DBセッションで `find_page` を実行して発行された文を捕捉し、asyncpg方言でのバインドパラメータの型・値を検証するRepositoryテスト（規約上、Repositoryテストは `integration/` に置く） |
| `backend/tests/integration/test_libraries.py` | ハイフン付きUUID形式での絞り込み・指定タグ以外のライブラリの除外・不正値の拒否を確認する結合テストを追加 |

- `app/routers/libraries.py` の `tagIds: list[uuid.UUID] | None` は移植元 `@RequestParam List<UUID> tagIds` と同じ型のため変更しない
- `app/services/library_service.py` は `tag_ids` をそのままリポジトリに渡すだけのため変更しない
- `app/models/library.py` の `LibraryTagMapping.library_tag_id: str`（`String(32)`）は `library_tags.id`（`String(32)`、`uuid4().hex`）への外部キーとして正しい型のため変更しない

## 原因の確認（コンパイル結果）

修正前の `LibraryTagMapping.library_tag_id.in_([uuid.UUID(...)])` を各方言でコンパイルした結果:

| 方言 | バインド型 | bind processor | 実際に送られる値 |
|---|---|---|---|
| `postgresql+asyncpg` | `Uuid`（`CHAR(32)` と表示） | なし | `uuid.UUID` オブジェクト → asyncpg が uuid 型で送信し `varchar = uuid` エラー |
| `sqlite` | `Uuid` | `Uuid.bind_processor`（hex文字列化） | `"94878ab1eb9f..."`（hex） → 保存値と一致してしまう |

## 修正後の期待

`in_()` に `str` のリストを渡すことで、バインド型は列の型（`String`）になり、どの方言でも `str`（ハイフンなし32桁hex）がそのまま送られる。
