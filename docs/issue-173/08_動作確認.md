**ブラウザ・実機確認は行わず、自動テスト（pytest、インメモリSQLite + fakeredis）のみで代替した。** ローカルのPostgreSQL/backendサーバーは他作業と共有しているため起動・使用していない。

## 確認環境

- macOS（darwin）、Python 3.14.6、pytest 9.1.1
- `backend/` で `uv sync` 後に `uv run pytest` を実行
- 作業用 git worktree には `backend/.env`（gitignore対象）がないため、メインの作業ツリーからコピーして実行した
- DB: インメモリSQLite（`tests/integration/conftest.py`）

## 確認手順

1. 修正前のコードについて、SQLAlchemy が asyncpg / SQLite 方言でタグIDをどうバインドするかを確認する
2. 修正前のコードに対して、新規Repositoryテスト（asyncpg方言でのバインド型・値の検証）が失敗することを確認する
3. 修正後に、ライブラリ一覧関連のテストを実行する
4. バックエンド全テストを実行する

## 確認結果

### 1. 原因の確認（修正前コードの asyncpg / SQLite 方言でのコンパイル結果）

`LibraryTagMapping.library_tag_id.in_([uuid.uuid4()])` を各方言でコンパイルした結果（スクラッチスクリプトで確認）:

```
PGDialect_asyncpg SELECT library_tag_mappings.library_id  FROM library_tag_mappings  WHERE library_tag_mappings.library_tag_id IN (__[POSTCOMPILE_library_tag_id_1])
 params: {'library_tag_id_1': ('list', [UUID('94878ab1-eb9f-4248-af7e-ff9f556e7677')])}
 bind type: CHAR(32) processor: None
SQLiteDialect_pysqlite SELECT library_tag_mappings.library_id  FROM library_tag_mappings  WHERE library_tag_mappings.library_tag_id IN (__[POSTCOMPILE_library_tag_id_1])
 params: {'library_tag_id_1': ('list', [UUID('94878ab1-eb9f-4248-af7e-ff9f556e7677')])}
 bind type: CHAR(32) processor: <function Uuid.bind_processor.<locals>.process at 0x105897320>
```

- バインド型は `Uuid`（汎用表示で `CHAR(32)`）と推論されている
- asyncpg では bind processor がなく `UUID` オブジェクトのまま送られる → `varchar = uuid` エラーの原因
- SQLite では `Uuid.bind_processor` がhex文字列に変換するため、既存テストは成功していた
