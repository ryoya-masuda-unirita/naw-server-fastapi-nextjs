# ライブラリ一覧をタグで絞り込むとサーバーエラー(500)になる

## 概要

`GET /api/libraries` に `tagIds` パラメータを指定してタグ絞り込みを行うと、SQLの型不一致によりHTTP 500エラーが発生する。

- GitHub Issue: https://github.com/ryoya-masuda-unirita/naw-server-fastapi-nextjs/issues/173

## 説明

### 原因（起票時の見立て）

- `app/models/library.py` の `LibraryTagMapping.library_tag_id` が `str` 型で定義されている
- `app/repositories/library_repository.py` の `get_libraries`（122〜124行目付近）で `LibraryTagMapping.library_tag_id.in_(tag_ids)` に `list[uuid.UUID]` を渡している
- 結果として `library_tag_mappings.library_tag_id IN ($uuid, ...)` というSQLになり、varcharカラムとUUID値の比較で `operator does not exist: character varying = uuid` が発生する

```
sqlalchemy.exc.ProgrammingError: (sqlalchemy.dialects.postgresql.asyncpg.ProgrammingError) <class 'asyncpg.exceptions.UndefinedFunctionError'>: operator does not exist: character varying = uuid
HINT:  No operator matches the given name and argument types. You might need to add explicit type casts.
```

### 発見経緯

Issue #166（E2Eテスト自動化）の09_ライブラリカテゴリ実装中、タグフィルター機能のE2Eテスト（`frontend-angular/e2e/library.spec.ts`）作成時に発見。管理画面でタグを選択して絞り込むと一覧が「エラーが発生しました」等の状態になる。

### 対応方針案（起票時）

`LibraryTagMapping.library_tag_id` を `uuid.UUID` 型に修正するか、リポジトリ側で `str(tag_id)` にキャストして比較する。他のマイグレーション済みカラムとの型整合も含めて確認要。

## その他

### 本Issueでは対応しない（Issue #166 側の扱い）

Issue #166はE2Eテスト自動化基盤の整備が目的のため、本バグの修正はこのIssueのスコープ外とする。該当のE2Eテストケースは `test.skip` としてこのIssueへの参照コメントを残す。
