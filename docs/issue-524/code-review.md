## 詳細

### 1. 作り直すと 502（🔴 致命的）→ 対応済み

`proxy_pass` に固定のホスト名を書くと、nginx は起動時に 1 度だけ名前を引く。`docker compose up -d --build waha-emulator` のたびに画面の再起動が要ってしまう。

Docker の内蔵 DNS（`resolver 127.0.0.11 valid=10s`）と、変数での中継先（`set $upstream ...; proxy_pass $upstream;`）に変え、使うたびに名前を引くようにした。変数の `proxy_pass` では URI がそのまま渡されることを、実機（`/admin/workflows` が通る）で確かめた。ダミーのコンテナで元の IP を塞いでエミュレーターの IP を変え（`.2` → `.5`）、画面を動かしたまま `/admin` が 200 を返すことを確認した。

### 2. 別サイトからの書き込み（🔴 致命的）→ 対応済み

指摘のとおり、`127.0.0.1` だけへの公開は、ホストのブラウザの別のページからのリクエストを防がない。ただし、指摘の例の DELETE は、`no-cors` では送れず（プリフライトが失敗する）、POST も、本文の形が JSON でないと拒否されるため、実害は限られる。それでも安価に塞げるため、nginx の `/admin/` で `Origin` を確認するようにした。

- Origin がない（`curl`・同じ出どころの GET）か、`http://<Host>` と一致するものだけを通し、それ以外は 403
- 実機で、別の Origin の GET・POST・DELETE が 403、同じ Origin が通る（画面からの保存も通る）ことを確認した

認証そのものは足していない（検証用の道具で、ホストの `127.0.0.1` だけに公開する方針）。`curl` のように、Origin を付けないリクエストは通る。

### 3. CI の対象外（🔵 提案）→ 対応済み

`emulator-ui` ジョブに、イメージのビルドと `nginx -t` を足した。中継先を起動時に引かない設計（1）のため、仮の値で通る。

`08_動作確認.md`・`code-review.md` を書いた。
