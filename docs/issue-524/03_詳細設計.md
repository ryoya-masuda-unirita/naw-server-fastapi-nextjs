# 03_詳細設計

## 新規ファイル

| ファイル | 内容 |
|---|---|
| `waha-emulator/ui/Dockerfile` | 2 段。`node` で `npm ci` → `npm run build`、`nginx` で `dist` を配信 |
| `waha-emulator/ui/nginx.conf.template` | `listen 80`。`/admin/` を `${WAHA_UPSTREAM}` へ中継。それ以外は `try_files $uri /index.html` |
| `waha-emulator/ui/.dockerignore` | `node_modules`・`dist` を除く |

- nginx の公式イメージは、`/etc/nginx/templates/*.template` の `${変数}` を、環境変数で置き換えて `conf.d` に書く。置き換えるのは、コンテナの環境変数にある名前だけなので、nginx の `$uri` などはそのまま残る
- ビルドコンテキストは `waha-emulator/ui`（compose の `build: ../waha-emulator/ui`）

## 変更するファイル

| ファイル | 変更 |
|---|---|
| `onprem/docker-compose.yml` | `waha-emulator-ui` を足す（ポート `127.0.0.1:18092:80`、`WAHA_UPSTREAM: http://waha-emulator:8080`、`depends_on: waha-emulator: service_healthy`、healthcheck）。`waha-emulator` に `WAHA_STUDIO_DIR: /app/data/workflows` と名前つきボリューム `waha-workflows:/app/data/workflows` を足す。`volumes:` に `waha-workflows` |

| `onprem/README.md` | 立ち上がるものの表に画面を足し、開き方と、サービス ID を server-local から呼ぶ流れを書く |
| `waha-emulator/README.md` | 画面の節に compose での開き方を足す |
| `.github/workflows/...` | 変更なし（画面のイメージの CI ビルドは、スコープ外） |

## nginx の設定（概念）

- `/admin/` の中継: URL をそのまま渡す（`proxy_pass` に URI を付けない）。本文が大きくならないため、バッファの特別な設定はしない
- 画面のファイルは、`index.html` を毎回確認させ（キャッシュしない）、ハッシュ付きの `assets/` は長くキャッシュしてよい
- `/admin/` 以外の `/WahaServer/` などは、中継しない（`try_files` で画面のトップが返るだけ）

## 確認の手順（08 に記録する）

1. `docker compose build waha-emulator waha-emulator-ui` が通る
2. `docker compose up -d --build server-local waha-emulator-ui` で、画面・エミュレーター・server-local が healthy になる
3. `http://127.0.0.1:18092/` が画面を返し、`/admin/workflows` が JSON を返す。`/WahaServer/...` は中継されない
4. 画面（Playwright）でワークフローを作って保存し、サービス ID を server-local の API で呼んで回答が返る
5. `docker compose down` → `up` で、保存したワークフローが残る。`down -v` で消える
