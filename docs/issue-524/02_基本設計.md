# 02_基本設計

## 構成

```
ブラウザ ──▶ 127.0.0.1:18092 ──▶ waha-emulator-ui（静的配信 + /admin の中継）
                                   │  /admin だけ
                                   ▼
                              waha-emulator（保存先をボリュームに）◀── server-local（servicerun）
```

- 画面のサービス（`waha-emulator-ui`）: 画面をビルドして、Web サーバーで配信する。`/admin/` へのリクエストを、エミュレーターへ中継する（開発サーバーのプロキシと同じ役割）。それ以外のパスは、画面のファイルを返す（画面の中のパスは 1 つなので、見つからないパスも、画面のトップを返す）
- エミュレーター: 保存先を、コンテナの中のディレクトリに設定し、そこを名前つきボリュームにする。実行ユーザーが書き込める持ち主にしておく
- 起動順: 画面は、エミュレーターが healthy になってから起動する。画面の healthy は、トップページが返ることで判定する
- ホストのポート: 画面は `127.0.0.1:18092`（server-local 18090・エミュレーター 18091・vector-db 15432 に続く番号）

## 設計の選び

| 項目 | 選び | 理由 |
|---|---|---|
| 配信 | ビルド済みの静的ファイル + nginx | 開発サーバー（Vite）は、CPU とメモリを多く使う（e2e でも、静的配信に変えて下がった）。コンテナで動かすなら静的配信が軽い |
| 中継先の指定 | 環境変数（エミュレーターのアドレス） | compose のサービス名に依存する値を、イメージに焼かない |
| 公開範囲 | ホストの `127.0.0.1` のみ | 認証がない管理用 API に、中継経由で外から触れないようにする |
| ボリューム | 名前つき | 既存の server-local・ベクトルDB と同じ扱い。`down` では残り、`down -v` で消える |

## 失敗の扱い

- エミュレーターが起動していない間は、画面を起動しない（依存の healthy）
- 画面から管理用 API が失敗したときは、画面側が「エミュレーターに接続できません」と出す（#522 のとおり）

## 確認したい点

1. 画面のポートは 18092
2. 保存したワークフローは、名前つきボリュームに残し、`down -v` で消える
