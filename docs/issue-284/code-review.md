## 詳細

### 1. 既定アシスタントが反映されない（🟡）→ 対応済み

`/chat/:roomId` を直接開く・再読み込みすると、ルーム一覧（#285 未移植の間は `AdminChatRoomPage` が読む）が遅れて届く。初回は `defaultAssistantId` が null のため一覧の既定が選ばれ、そのルームでは固定されていた。移植元ではサイドバーが先に一覧を読み込むので起きない。

初期アシスタントを決めたときのルームの既定 ID を覚え、あとから変わったら選び直すようにした。利用者が自分で選んだあと（`isUserSelected`）は上書きしない。テスト `ルームの既定アシスタントが後から分かったら選び直し…` を追加。

### 2. ルーム作成の失敗で本文が消える（🟡）→ 対応しない

移植元も `chat-input` が `send` を出した直後に入力欄を空にし、`ChatWindow.handleSend`（非同期）の失敗は待たない。完璧なクローンのため同じ挙動にした（エラートーストは api-client が出す）。直すなら移植元の改善提案として別途。

### 3. 一覧にないルームが新規チャット扱い（🟡）→ 対応しない

移植元も `activeRoom` はルーム一覧（`allRooms`）から引く。一覧が空のときは `AdminChatRoomPage` が読み込む。2 ページ目以降のルームや、一覧に載る前の新規ルームは移植元と同じ挙動で、サイドバー（#285）が一覧を保つ前提。#285 で確認する。

### 4. body の overflow（🟡）→ 対応済み

effect を「ビューワーを開いている間だけ」触るようにした（閉じているときは何もしない）。

### 5. 前の会話が一瞬見える（🟡）→ 対応済み

`useEffect` を `useLayoutEffect` にして、描画の前に空にする。

### 6. ドラッグ中の後始末（🟡）→ 対応済み

後始末の関数を ref に持ち、アンマウント時に呼ぶ。テスト `ドラッグ中にパネルが消えても…` を追加。

### 7. 預かったメッセージの残り（🔵）→ 対応しない

預かる直後に必ずそのルームの画面へ移動し、画面が取り出す。取り出されないのは移動が失敗したときだけで、そのときも鍵がルーム ID なので別のルームへ漏れず、再読み込みで消える（移植元の `history.state` と同等）。期限は付けない。

### 8. ChatClaude（🔵）→ 対応しない

Issue の対象（`chat-claude`）に明記されているため移した。移植元でも `isClaude` は常に false。

### 9. 名前変更の失敗（🔵）→ 対応しない

移植元も `dialogRef.afterClosed` で閉じてから `renameRoom` を呼び、失敗を待たない。失敗時のトーストは api-client の共通処理が出す。
