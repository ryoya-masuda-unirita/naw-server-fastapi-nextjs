# 03_詳細設計

## 構成

```
routes/chat/chat-new.tsx        ChatNewPage        … startNewChat → ChatWindow（roomId なし）
routes/chat/chat-room.tsx       AdminChatRoomPage  … setActiveRoomId → 預かったメッセージを送る / 読み込む → ChatWindow + ChatDataPanel
components/features/chat/
  chat-window.tsx               ヘッダー・一覧・入力欄・名前変更ダイアログ・モバイルのビューワー。送信・各操作を store へつなぐ
  chat-header / chat-message-list / chat-message-item / chat-message-footer / chat-message-logo
  chat-input / chat-claude / chat-alert / chat-error / chat-reasoning-display
  chat-rename-dialog / chat-new-room-dialog / new-chat-dialog（サイドバー）
  chat-data-panel / chat-file-preview / message-error-section / message-reference
```

## 送信（ChatWindow.handleSend）

- `roomId` がある: `messages store.sendMessage(content, files, activeRoomId, [], options)`
- `roomId` がない（新規チャット）: `useChatActions().createNewRoom(assistantId ?? 'default')` → `activeRoomId` を設定 → `setPendingMessage(roomId, …)` → `/chat/:roomId` へ移動。移動先が `takePendingMessage` で取り出して送る。作成に失敗したら（トーストは api-client が出す）送らない

## AdminChatRoomPage

- `roomId` が変わるたびに 1 回だけ（`handledRoomId` の ref で、StrictMode の二重実行を防ぐ）: `setActiveRoomId` → 預かりがあれば送信（読み込まない）、なければ `loadMessagesForRoom(roomId, true)`
- 読み込み中（`isLoading`）は `.chat-main` にローディングだけを出す（移植元と同じ。ウィンドウは作り直される）

## 送信中にルームを切り替えたとき（#283 の申し送り）

移植元と同じく送信は止めない。切り替え先のメッセージ読み込み（`loadSequence`）でメッセージ一覧が入れ替わるため、送信中だったメッセージの更新は画面に反映されない（`patchMessages` は ID で当てるので、存在しなければ何も起きない）。サーバー側の処理は完了し、元のルームを開き直せば結果が見える。`isGenerating` は送信完了で必ず戻る。止める・切り替えを禁止する処理は移植元にもないので入れない

## ChatInput

- 状態は `useChatInputControls`（初期アシスタントはルームごとに 1 回、`resolveInitialAssistant`）
- `canSend` = 「@」で始まらない かつ（本文あり または 添付あり）
- 送信後: 本文・添付を空に、ライブラリ作成を解除（Web 検索は維持）、textarea の高さを戻す
- `isClaude` は移植元でも常に false（`ChatClaude` は表示されない）
- `chat-input.component.scss` の `.chat-input-textarea` は `index.css` に同じ定義があるため、CSS は足さない。`.chat-multi-panel`・`.assistant-menu`・`.dl-trigger--chat` は＋メニュー・アシスタント選択（#286・#287）の担当

## 移植元と同じにした「不自然な」点

- `ChatError` のクラス `w-fulll`（タイプミス）・メッセージ項目の添付ファイルチップが削除ボタンを出す（`showRemoveBtn` の既定が true）は、見た目を揃えるためそのままにした。`ChatMessageList` の `retry` 出力はメッセージ項目から呼ばれない（フッターに再試行ボタンがない）ので持たない
- `ChatNewRoomDialog` は、開くヘッダーのボタンが移植元でコメントアウトされていて到達できない。部品とテストだけ移した
- `chat-message-list-skeleton` は移植元でもどこからも使われていないので移していない（Issue の対象にもない）
