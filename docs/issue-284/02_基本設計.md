# 02_基本設計

## 変更対象

- frontend のみ（`backend/` は変更しない）

## 画面 / API 変更概要

- 画面: `routes/chat/chat-new.tsx`（`ChatNewPage`）・`routes/chat/chat-room.tsx`（`AdminChatRoomPage`）の仮ファイルを本物に置き換える。サイドバーの `components/features/chat/new-chat-dialog.tsx` も本物にする
- 利用する API: `GET /api/assistants`・`GET/POST/PATCH /api/rooms`・`/api/messages` 系（#283 の store 経由）。新しい API の呼び出しはない

## 移植方針

| 移植元 | 移植先 |
|---|---|
| `ChatService`（表示中のルーム） | `store/chat-store.ts`（`activeRoomId`・`selectRoom`・`setActiveRoomId`・`startNewChat`・`useActiveRoom`） |
| `ChatNewComponent` / `AdminChatRoomComponent` | `routes/chat/chat-new.tsx` / `chat-room.tsx` |
| `chat-window` ほか `chat-*` | `components/features/chat/chat-*.tsx`（同名） |
| `chat-input` の signal 群 | `hooks/use-chat-input-controls.ts` |
| `router.navigate(..., { state: { pendingMessage } })` | `lib/chat/pending-message.ts` |
| `core/utils` の `room-name`・`resolve-initial-assistant`・`file.helpers` | `lib/utils/room-name.ts`（追記）・`resolve-initial-assistant.ts`・`file-preview.ts` |
| `MatDialog` + `DialogComponent` | 共通 UI の `Dialog`（#278） |

### 別 Issue への口（空の領域）

`ChatInput` の `renderMention`・`renderToolbar`・`renderAddMenu`・`renderAttachments`・`renderDropzone`・`onDropFiles`・`onTextareaKeyDown`、`ChatWindow` の `inputSlots`・`onShareClick`・`onLikeClick`・`renderViewer`、`ChatDataPanel` の `renderSummary`。未指定なら移植元と同じ位置に空の要素だけが残る（「未移植」表示は出さない）。一覧は `features/chat/README.md`。

### 意図的な差分

1. 最初のメッセージの受け渡しは、履歴の state ではなくモジュール内の Map（`pending-message.ts`）にする。ルーム ID を鍵にして 1 回だけ取り出せるので、StrictMode の effect 二重実行でも二重送信にならない。再読み込みで消えるのは移植元と同じ
2. ヘッダーのルーム名はルーム一覧から引く。移植元はサイドバーが一覧を読み込むが、#285 が未移植の間は `AdminChatRoomPage` が、一覧が空なら読み込む（#285 でサイドバーが読み込むようになれば不要になる）
3. 添付ファイルの状態（`ChatService.attachedFiles`）・共有ルームの文脈（`sharedRoomContext`）は持たない。使う画面（#287・#288）が足す。送信時の `attachedFiles` は常に空配列
4. 「ライブラリ生成中は右のビューワーを出す」条件（`ViewerService.isLibraryStreaming`）は、ビューワー（#288）が足す。今は「回答が 1 つ以上」だけ
