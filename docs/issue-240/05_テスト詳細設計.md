# 05_テスト詳細設計

## CloudFront Function（`infra/cloudfront_functions/functions.test.mjs`）

実行: `cd infra && node --test cloudfront_functions/functions.test.mjs`

関数ファイルを `node:vm` の `runInNewContext` で評価し、トップレベルの `handler` を取り出して `event`（`{ request: { method, uri, querystring, headers } }`）を渡す。

| No | テスト | 入力 uri | 期待 uri |
|---|---|---|---|
| 1-1 | spa_fallback: 画面パスは index.html | `/`、`/dashboard`、`/auth`、`/auth/login`、`/auth/pw-reset`、`/dashboard/`（末尾 `/`） | `/index.html` |
| 2-1 | spa_fallback: 静的ファイルは書き換えない | `/index.html`、`/assets/index-abc123.js`、`/assets/index-abc123.css`、`/i18n/ja.json`、`/favicon.ico`、`/assets/fonts/noto/sans.woff2` | 入力と同じ |
| 3-1 | spa_fallback: クエリ文字列は変えない | `/dashboard`（querystring `page=1`） | `/index.html`、querystring は同じ |
| 4-1 | strip_backend_prefix: プレフィックスを外す | `/backend/auth/login`、`/backend/auth/login-key`、`/backend/auth/logout`、`/backend/auth/password/reset` | `/auth/login`、`/auth/login-key`、`/auth/logout`、`/auth/password/reset` |
| 5-1 | strip_backend_prefix: uri 以外は変えない | `POST /backend/auth/login`（ヘッダー・querystring 付き） | method・headers・querystring が同じ |
| 6-1 | strip_backend_prefix: 対象外は書き換えない | `/backendx/auth/login`、`/api/auth`、`/auth/login` | 入力と同じ |

## フロント（`frontend/src/lib/api-client.test.ts`）

既存の `loadApiClient` を、認証 API のベース URL（`VITE_AUTH_API_URL`）も指定できるように拡張する（未指定なら stub しない）。

| No | テスト | 設定 | 期待結果 |
|---|---|---|---|
| 7-1 | 認証 API のベース URL が指定されていれば、認証 API の POST がそのベース URL 付きで配信元と同じオリジンに送られること | `VITE_API_URL=''`、`VITE_AUTH_API_URL='/backend'`、`POST /auth/login` | `${origin}/backend/auth/login` |
| 8-1 | 認証 API のベース URL が指定されていても、`/api/` の API にはプレフィックスが付かないこと | 同上、`GET /api/auth` | `${origin}/api/auth` |
| 9-1 | 認証 API のベース URL が未指定なら、認証 API も API のベース URL に送られること | `VITE_API_URL='http://localhost:8000'`、`POST /auth/login` | `http://localhost:8000/auth/login` |

既存テスト（ベース URL が空・絶対 URL の GET/POST）は変更しない（`VITE_AUTH_API_URL` 未指定のケースとして引き続き有効）。
