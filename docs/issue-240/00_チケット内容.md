# #240 issue-240 dev環境のCloudFrontがAPIの403/404/405をindex.htmlに置き換えないようにする

## 概要

dev の CloudFront（`infra/cloudfront.tf`）は、SPA のルーティングのために `custom_error_response` で 403/404/405 を `/index.html`（200）に置き換えている。`custom_error_response` はディストリビューション全体に効くため、ALB に転送した API（`/api/*`・`/auth/*`）が返す 403/404/405 も HTML（200）に置き換わる。

- フロントは API の 403/404 をエラーとして扱えず、HTML を JSON として読もうとする
- 405 は、React のログイン画面 `/auth/login` が backend のログイン API と同じパスで、画面として GET すると backend が 405 を返すために #223 で追加した

## 説明

- SPA のフォールバックを S3 のビヘイビアだけに効かせ、API の応答はそのまま返す（CloudFront Functions で S3 側のパスを `/index.html` に書き換える、など）
- `/auth/login` を画面として GET したときに React の画面を返す方法を決める（`Accept: text/html` の GET だけ S3 に回す、など）
- 方式は設計で決める

## その他
