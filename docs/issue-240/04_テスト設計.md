# 04_テスト設計

## テスト方針

- AWS には接続しない。CloudFront の設定は Terraform のフォーマット・構文検証で確認する
- CloudFront Function のロジック（パスの書き換え）は、関数のコードをそのまま Node.js で評価して単体テストする
- フロントの API クライアントは Vitest + MSW で、実際にリクエストされた URL を検証する
- フロント全体のテスト・lint・型チェック・ビルドを通す

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | SPA フォールバック | 画面パス（`/`、`/dashboard`、`/auth/login`、`/auth/pw-reset`、`/auth`、末尾 `/` 付き） | `/index.html` に書き換わる |
| 2 | SPA フォールバック | 静的ファイル（JS・CSS・JSON・ico、深い階層の拡張子付き） | 書き換わらない |
| 3 | SPA フォールバック | クエリ文字列付きの画面パス | パスだけ `/index.html` になり、クエリ文字列は変わらない |
| 4 | プレフィックス除去 | `/backend/auth/login` など認証 API のパス | `/auth/login` など、プレフィックスを外したパスになる |
| 5 | プレフィックス除去 | メソッド・ヘッダー・クエリ文字列 | 変わらない |
| 6 | プレフィックス除去 | `/backend` で始まらない（`/backendx/...` を含む） | 書き換わらない |
| 7 | API クライアント | 認証 API のベース URL が指定されている（本番ビルド相当） | 認証 API（`/auth/` 始まり）はそのベース URL 付きで、配信元と同じオリジンに送られる |
| 8 | API クライアント | 認証 API のベース URL が指定されている | `/api/` 始まりの API（セッション取得を含む）にはプレフィックスが付かない |
| 9 | API クライアント | 認証 API のベース URL が未指定（ローカル開発） | 認証 API も他の API と同じベース URL に送られる |
| 10 | 既存機能 | フロントの既存テスト全件 | すべて成功する |
| 11 | Terraform | フォーマット検証・構文検証 | エラーがない |
| 12 | フロントの品質 | lint・型チェック・ビルド | エラーがない |
