# 02 基本設計

## 方針

規模が大きい（約 5,200 か所）ため、機械的に付けられるものはスクリプトで付け、残りを手で直す。

1. AST で fixture の戻り値の型を推論し（`return Tenant(...)` や `t = Tenant(...); return t` など）、fixture の引数名から型を引いて付ける
2. テスト関数の戻り値には `-> None` を付ける
3. `@patch` 由来の `mock_*` 引数は `MagicMock`、`@pytest.mark.parametrize` の引数は値のリテラルから型を推論する
4. 推論できなかったもの（ジェネレータ fixture、補助関数、ネストした関数）は手で付ける
5. 型を付けたことで、これまで検査されなかったテスト本体が mypy の検査対象になる。型で表せない箇所は `# type: ignore[コード]` を付ける
6. docstring の抜けは、ファイル単位で分担して付ける

## type: ignore の方針（計 193 行）

| 種類 | 理由 |
|---|---|
| `session=None`（`arg-type`） | サービス層の単体テストで、DB を使わないため `None` を渡している。挙動を変えないため `cast` や別の値には変えない |
| `.where(Model.col == x)`（`arg-type`） | SQLModel のモデル属性は mypy 上は宣言した Python 型としてしか認識されない既知の限界（`pyproject.toml` の既存の注記・docs/issue-139 参照） |
| `sessionmaker(..., class_=AsyncSession)`（`call-overload`） | SQLAlchemy の型スタブのオーバーロードが `AsyncSession` を受けない |
| `session.get()` の直後の属性参照（`union-attr`）、`dict` の添字（`index`）など | テスト本体を書き換えない（assert を足さない）ため |

## 挙動を変えない確認

docstring・型注釈・追加した import を除いた構文木が、`origin/develop` と全ファイルで一致することを確かめる（server-local の PR #315、backend の PR #352 と同じ方法）。
