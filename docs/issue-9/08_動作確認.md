# 動作確認：ユーザー管理 API（CRUD・プロフィール）

## 環境

- PostgreSQL: Docker（`naw-fastapi-postgres`、既に起動済みを確認）
- マイグレーション: `alembic upgrade head` 実行済み
- サーバー: `uvicorn app.main:app --reload --port 8001`（8000番は別プロセスが使用中だったため8001番で起動）
- 動作確認用データ: テナント `verify-tenant`、ADMINユーザー `admin-verify` を直接DBに投入して使用

## Step 1: サーバー起動・ルーティング登録確認

`/openapi.json` で6エンドポイントが登録されていることを確認。

```
/health
/auth/login
/auth/logout
/auth/password/reset
/api/auth
/api/admin/users
/api/admin/users/{user_id}
/api/users/profile
```

✅ 6エンドポイント全て登録されていることを確認

## Step 2: ログイン（admin-verify）

```
POST /auth/login
{"username":"admin-verify","password":"AdminPass1!"}
→ 200 OK, token 取得
```

✅ ログイン成功、JWTトークン取得

## Step 3: GET /api/admin/users（一覧取得）

```
$ curl -X GET http://localhost:8001/api/admin/users -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant"
→ HTTP 200
{"content":[{"id":"2fed5e5d-...","loginId":"admin-verify","name":"動作確認管理者","role":"ADMIN","loginKey":null,"isRequiredPasswordReset":false}],"totalElements":1,"totalPages":1,"page":0,"size":20}
```

✅ ユーザー一覧を取得できることを確認

## Step 4: POST /api/admin/users（ユーザー作成）

```
$ curl -X POST http://localhost:8001/api/admin/users -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant" -d '{"loginId":"newuser01","name":"新規ユーザー","role":"USER"}'
→ HTTP 200
{"id":"47455abe-...","loginId":"newuser01","name":"新規ユーザー","role":"USER","loginKey":null,"isRequiredPasswordReset":true,"initialPassword":"vtPoF4%C","passwordExpiredAt":"2026-09-28T03:31:48.135927Z"}
```

✅ ユーザーを作成でき、initialPassword・passwordExpiredAt が返ることを確認

## Step 5: テナント分離バイパスの修正確認（code-review 致命的指摘1番）

JWT は `verify-tenant` のままで、`X-Tenant-ID` ヘッダーに別テナントを指定。

```
$ curl -X GET http://localhost:8001/api/admin/users -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: other-tenant"
→ HTTP 403
{"detail":"Tenant mismatch"}
```

✅ JWT と異なる X-Tenant-ID を指定すると 403 になることを確認（修正前は他テナントのデータが取得できてしまっていた）

## Step 6: PATCH /api/admin/users/{user_id}（ユーザー更新）

```
$ curl -X PATCH http://localhost:8001/api/admin/users/newuser01 -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant" -d '{"name":"更新後ユーザー名"}'
→ HTTP 200
{"id":"47455abe-...","loginId":"newuser01","name":"更新後ユーザー名","role":"USER","loginKey":null,"isRequiredPasswordReset":true,"initialPassword":null,"passwordExpiredAt":null}
```

✅ name を更新できることを確認

```
$ curl -X PATCH http://localhost:8001/api/admin/users/newuser01 -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant" -d '{"resetPassword":true}'
→ HTTP 200
{"id":"47455abe-...","loginId":"newuser01",...,"initialPassword":"g9^e9hNl","passwordExpiredAt":"2026-09-28T03:32:03.692272Z"}
```

✅ resetPassword=true で initialPassword が再発行されることを確認

## Step 7: パスワードリセット後のログイン

```
$ curl -X POST http://localhost:8001/auth/login -H "X-Tenant-ID: verify-tenant" -d '{"username":"newuser01","password":"g9^e9hNl"}'（→login）
$ curl -X POST http://localhost:8001/auth/password/reset -d '{"loginId":"newuser01","oldPassword":"g9^e9hNl","newPassword":"NewUserPass1!"}'
→ 200 OK, token 取得
```

✅ 発行された initialPassword でログインし、新パスワードに変更できることを確認

## Step 8: GET /api/users/profile（プロフィール取得）

```
$ curl -X GET http://localhost:8001/api/users/profile -H "Authorization: Bearer $USER_TOKEN" -H "X-Tenant-ID: verify-tenant"
→ HTTP 200
{"id":"47455abe-...","loginId":"newuser01","name":"更新後ユーザー名","role":"USER","loginKey":null,"isRequiredPasswordReset":false}
```

✅ 認証ユーザーが自分のプロフィールを取得できることを確認

## Step 9: PATCH /api/users/profile（パスワード変更）と ポリシー検証修正確認（code-review 致命的指摘2番）

```
$ curl -X PATCH http://localhost:8001/api/users/profile -H "Authorization: Bearer $USER_TOKEN" -d '{"password":"AnotherPass2!"}'
→ HTTP 200
```

✅ パスワードを変更できることを確認

```
$ curl -X PATCH http://localhost:8001/api/users/profile -H "Authorization: Bearer $USER_TOKEN" -d '{"password":"short"}'
→ HTTP 400
{"detail":"Password must be at least 8 characters"}
```

✅ ポリシー違反（最小長未満）のパスワードが拒否されることを確認（修正前はチェックされずそのまま保存されていた）

## Step 10: 一般ユーザーの認可チェック

```
$ curl -X GET http://localhost:8001/api/admin/users -H "Authorization: Bearer $USER_TOKEN" -H "X-Tenant-ID: verify-tenant"
→ HTTP 403
{"detail":"Access Denied"}
```

✅ 一般ユーザー（USERロール）が管理者APIにアクセスすると403になることを確認

## Step 11: DELETE /api/admin/users/{user_id}（ユーザー削除）

```
$ curl -X DELETE http://localhost:8001/api/admin/users/newuser01 -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant"
→ HTTP 204
```

✅ ユーザーを削除できることを確認

```
$ curl -X GET http://localhost:8001/api/admin/users -H "Authorization: Bearer $TOKEN" -H "X-Tenant-ID: verify-tenant"
→ {"content":[{"id":"2fed5e5d-...","loginId":"admin-verify",...}],"totalElements":1,...}
```

✅ 削除後、一覧から newuser01 が消えていることを確認
