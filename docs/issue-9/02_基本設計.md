# 基本設計：ユーザー管理 API（CRUD・プロフィール）

## 変更対象レイヤー

バックエンド（FastAPI）のみ。DB スキーマ変更なし（マイグレーション不要）。

---

## API 変更概要

| エンドポイント | メソッド | 説明 | 認証 | ロール要件 |
|---|---|---|---|---|
| `/api/admin/users` | GET | ユーザー一覧取得（ページング・検索） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users` | POST | ユーザー作成（初期パスワード自動生成） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users/{userId}` | PATCH | ユーザー更新（名前・ロール・パスワードリセット） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users/{userId}` | DELETE | ユーザー削除 | JWT 必須 | ADMIN または SYSTEM |
| `/api/users/profile` | GET | 自分のプロフィール取得 | JWT 必須 | なし（認証済みであればよい） |
| `/api/users/profile` | PATCH | プロフィール更新（パスワード変更） | JWT 必須 | なし（認証済みであればよい） |

## 設計上の決定事項

### URLパスパラメータ `{userId}` = `users.login_id`

Spring Boot 版と同様に `userId` は `users.id`（UUID）ではなく `users.login_id`（文字列）。
ルーターのパス変数名は `user_id` とする（Python 慣例）。

### ページング方式

Spring Boot の `Pageable` に相当するクエリパラメータを以下のように実装する。

| クエリパラメータ | 型 | デフォルト | 説明 |
|---|---|---|---|
| `page` | int | 0 | 0 始まりのページ番号 |
| `size` | int | 20 | 1 ページあたりの件数 |
| `sort` | str | `created_at,desc` | ソートカラムと順序（例: `name,asc`） |

SQLAlchemy の `offset = page * size` で実装する。
レスポンスは Spring Boot の `Page<T>` に相当する以下の構造にする。

```json
{
  "content": [...],
  "totalElements": 100,
  "totalPages": 5,
  "page": 0,
  "size": 20
}
```

### ADMINロールチェック

`security.py` に `require_admin` 関数を追加し、`get_current_user` で取得したユーザーのロールを確認する。
`ADMIN` または `SYSTEM` であればアクセスを許可する。

```python
async def require_admin(current_user: User = Depends(get_current_user)) -> User:
    if current_user.role not in (UserRole.ADMIN, UserRole.SYSTEM):
        raise HTTPException(status_code=403, detail="Access Denied")
    return current_user
```

### パスワード自動生成

Spring Boot の `PasswordGenerator.generate(tenant)` 相当を `password_service.py` に追加する。
テナントの以下フィールドを参照してポリシーに準拠したランダムパスワードを生成する。

- `pw_policy_min_length`
- `pw_policy_use_uppercase`
- `pw_policy_use_lowercase`
- `pw_policy_use_digits`
- `pw_policy_use_symbols` + `pw_policy_valid_symbols`
- `pw_validity_period_days`（`passwordExpiredAt` 計算に使用）

### `excludeGroupId` パラメータ

パラメータとして受け付けるが、グループ機能が未実装のため今回は無視する（フィルタなし）。
コメントで「グループ機能実装時に対応する」と明記する。
