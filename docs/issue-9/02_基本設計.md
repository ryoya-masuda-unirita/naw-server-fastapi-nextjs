# 基本設計：ユーザー管理 API（CRUD・プロフィール）

## 変更対象レイヤー

バックエンド（FastAPI）のみ。DB スキーマ変更なし（マイグレーション不要）。

---

## API 変更概要

| エンドポイント | メソッド | 説明 | 認証 | ロール要件 |
|---|---|---|---|---|
| `/api/admin/users` | GET | ユーザー一覧取得（ページング・検索） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users` | POST | ユーザー作成（初期パスワード自動生成） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users/{userId}` | PATCH | ユーザー更新（名前・ロール・パスワードリセット） | JWT 必須 | ADMIN または SYSTEM |
| `/api/admin/users/{userId}` | DELETE | ユーザー削除 | JWT 必須 | ADMIN または SYSTEM |
| `/api/users/profile` | GET | 自分のプロフィール取得 | JWT 必須 | なし |
| `/api/users/profile` | PATCH | プロフィール更新（パスワード変更） | JWT 必須 | なし |

## アーキテクチャ

### レイヤー構成

```
routers/users.py
    └── services/user_service.py          ← ビジネスロジック（1対1対応）
            ├── repositories/password_history_repository.py  ← auth_service と共有
            └── （Tenant・User を直接 session で取得）
```

### routers/services 1対1対応の維持

既存の `auth_service.py` と同様に、`user_service.py` は `routers/users.py` 専用のサービスとする。
複数のサービスから使う DB 操作は `repositories/` に置く（`PasswordHistoryRepository` がその例）。

## 設計上の決定事項

### URLパスパラメータ `{userId}` = `users.login_id`

Spring Boot 版と同様に `userId` は `users.id`（UUID）ではなく `users.login_id`（文字列）。
ルーターのパス変数名は `user_id` とする（Python 慣例）。

### ページング方式

Spring Boot の `Pageable` に相当するクエリパラメータを以下のように実装する。

| クエリパラメータ | 型 | デフォルト | 説明 |
|---|---|---|---|
| `page` | int | 0 | 0 始まりのページ番号 |
| `size` | int | 20 | 1 ページあたりの件数 |
| `sort` | str | `created_at,desc` | ソートカラムと順序（例: `name,asc`） |

SQLAlchemy の `offset = page * size` で実装する。
レスポンスは Spring Boot の `Page<T>` に相当する以下の構造にする。

```json
{
  "content": [...],
  "totalElements": 100,
  "totalPages": 5,
  "page": 0,
  "size": 20
}
```

### ADMIN ロールチェック

`security.py` に `require_admin` 依存関数を追加する。
`get_current_user` で取得したユーザーのロールが `ADMIN` または `SYSTEM` であればアクセスを許可する。

### パスワード自動生成

Spring Boot の `PasswordGenerator.generate(tenant)` 相当を `user_service.py` 内に実装する。
テナントの以下フィールドを参照してポリシーに準拠したランダムパスワードを生成し、`PasswordHistoryRepository.save` で保存する。

- `pw_policy_min_length` / `pw_policy_use_uppercase` / `pw_policy_use_lowercase`
- `pw_policy_use_digits` / `pw_policy_use_symbols` / `pw_policy_valid_symbols`
- `pw_validity_period_days`（`passwordExpiredAt` の計算に使用）

### `excludeGroupId` パラメータ

クエリパラメータとして受け付けるが、グループ機能が未実装のため今回は無視する。
