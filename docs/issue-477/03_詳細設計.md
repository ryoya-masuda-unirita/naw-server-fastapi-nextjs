## `ComboboxMulti` の変更

### props

`scrollChipsWhenOpen?: boolean`（既定 `false`）を足す。説明: 一覧を開いている間、選んだチップの欄の高さに上限を付けて中でスクロールさせる（大量に選ぶ欄で使う）。

### 導出値

`chipsScrollable = isOpen && scrollChipsWhenOpen`

### チップ欄の描画

`className={cx('combobox-chips-row', chipsScrollable && 'max-h-24 overflow-y-auto')}`

### `+N` の判定（`recalcChipOverflow`）

`firstTop` を最初に 1 度だけ測る方式をやめ、`wrapped = (el) => el.offsetTop > chips[0].offsetTop` を、判定のたびに評価する。チップの判定と、バッジが折り返したかの判定（`while` の条件）の両方に使う。理由は、チップを隠して欄が 1 行になると、上下中央に寄って `offsetTop` が変わるため。

### 開くときの復元

`recalcChipOverflow` の先頭にある、チップの `hidden` を外し、`+N` を消し、入力欄の `hidden` を外す部分を、`restoreChips()` に切り出す（`recalcChipOverflow` の先頭からも呼ぶ）。`open()` が、状態を更新する前に `restoreChips()` を呼ぶ。理由は、`open()` の時点では、再描画前で `latest.current.isOpen` がまだ `false` のため、`recalcChipOverflow` をそのまま呼ぶと、また隠してしまうから。入力欄の復元は、続くフォーカス（`queueMicrotask`）より前に済む。

### 開いている間のスクロールと一覧の付け直し

`chipsScrollable` が真の間、`effectiveValue`（選択中の値）が変わるたびに、描画後に次を行う。
1. `chipsRowRef.current.scrollTop = scrollHeight`（入力欄が見えるように末尾へ）
2. モバイルでなければ、`latest.current.positionList()`（欄が高くなったら、一覧を欄の下端に付け直す）

`useEffect` で行う（依存は `effectiveValue`・`chipsScrollable`）。`positionList` は `latest` から呼ぶ。

## 所属ユーザー追加のダイアログ

```tsx
<ComboboxMulti
  id="group-add-users"
  name="group-add-users"
  value={addSelection}
  onCommit={setAddSelection}
  options={addOptions}
  placeholder={t('GROUPS.MEMBERS_PLACEHOLDER')}
  searchHint={t('GROUPS.MEMBERS_SEARCH_HINT')}
  emptyMessage={t('COMMON.EMPTY_RESULT')}
  testidPrefix="admin-groups-add-user-select"
  panelSize="full"
  scrollChipsWhenOpen
/>
```

`addOptions`（ダイアログを開くときに 1 回取得）と、`addSelection`、`handleAddSubmit` は変えない。絞り込みは部品の中で行うため、入力しても候補を取り直さない。

## 使用する CSS・Tailwind

- `max-h-24`・`overflow-y-auto`: Tailwind の標準クラス（`index.css` の `@theme` に依存しない）
- `padding-right`: `index.css` の既存の変数 `--spacing` を使う
