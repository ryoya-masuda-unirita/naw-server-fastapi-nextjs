# 05_テスト詳細設計

## `combobox-multi.test.tsx`（共通部品）

jsdom の `offsetTop` を、チップの並びの模擬で差し込む。`HTMLElement.prototype` の `offsetTop` を、チップ欄（`[data-cmulti-chips]`）の子要素に限って、次の規則で返す（その他の要素は 0）。

- 見えている（`hidden` でない）チップ・バッジを、1 行に `PER_LINE` 個ずつ並べる。行の番号 × 行の高さが `offsetTop`
- **見えているものが 1 行に収まるとき、全体が上下中央に寄って、`offsetTop` に一律の差（中央寄せ分）が足される**（移植元の不具合を再現する条件。修正前の実装なら、2 つ目以降が `firstTop` と違うため、すべて `+N` になる）
- `clientWidth` は、チップ欄で 0 でない値を返す

| No | 対応 | テスト名（案） | 内容 |
|---|---|---|---|
| 12 | `+N` | 一覧を開いて［決定］で閉じると、もう一度 1 行に入るだけのチップを出し、残りを +N で出す | 7 つ選んで 1 行 3 個の模擬。閉じたあと、見えるチップが 3 つで、バッジが `+4` |
| 13 | `+N` | バッジが折り返すときは、収まるまで末尾のチップを隠す | バッジが入る余地がない模擬。見えるチップが 1 つ減り、バッジの数が 1 増える |
| 14 | 開き直し | `+N` になった後に開き直すと、すべてのチップと入力欄を出し、+N を消し、名前で絞り込める | 閉じて `+N` と入力欄の `hidden` を確かめる → 開く。`hidden` のチップがなく、バッジがなく、入力欄が `hidden` でないこと。名前を入力して候補が絞り込まれること。**修正前のコードでは失敗する**ことを、実装の前に確かめる |
| 15 | 高さ上限 | 指定すると、開いている間だけ欄の高さに上限を付ける | `max-h-24`・`overflow-y-auto` が、開くと付き、閉じると外れる |
| 16 | 高さ上限 | 指定しなければ、開いても上限を付けない | 付かない |
| 17 | スクロール | 指定すると、候補を選ぶたびに欄を末尾までスクロールする | `scrollHeight` を差し込み、選ぶたびに `scrollTop` がその値になる |
| 18 | 付け直し | 指定すると、欄が高くなったら、一覧を欄の下端に付け直す | トリガーの `getBoundingClientRect` の `bottom` を、変数で差し替えられるようにし、選んだ後に、一覧の `top` が新しい `bottom` になる |
| 19 | 付け直さない | 指定しなければ、選んでも一覧の位置を付け直さない | 同じ操作で、一覧の `top` が変わらない |

## `group-detail.test.tsx`（所属ユーザー追加）

既存の `mockApis`（候補の取得と、追加の送信を記録する）を使う。ユーザーの名前は、既存のものに加え、絞り込み用に、名前の違うユーザーを足す。

- 既存「ユーザーを追加すると、…送信すること」: `getByText('GROUPS.MEMBERS_PLACEHOLDER')` の操作を、`getByTestId('admin-groups-add-user-select-trigger')` に直す。候補は `findByRole('option', { name })`（または `-option` の testid）、確定は `admin-groups-add-user-select-confirm-button`
- 新規（No.1〜9）: 入力は、検索欄（`combobox` の role）に `userEvent.type`。候補の数は `-option` の testid の数で確かめる。取り直しは、`log.optionParams` の長さが 1 のままであること
