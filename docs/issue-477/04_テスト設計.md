# 04_テスト設計

## テスト方針

Vitest + React Testing Library。jsdom はレイアウトを計算せず `offsetTop` が常に 0 になるため、`+N` の判定は、チップの並びを模した `offsetTop`・`clientWidth` を差し込んで確かめる。画面の見た目は、実画面でも確かめる（08）。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 所属ユーザー追加: 絞り込み | ダイアログを開き、一覧を開いて名前の一部を入力する | 名前に一致するユーザーだけが候補に残る |
| 2 | 所属ユーザー追加: ID だけ一致 | ユーザー ID にだけ含まれる文字を入力する | 候補に出ない |
| 3 | 所属ユーザー追加: 入力を消す | 入力した文字を消す | 未所属のユーザーが全員戻る |
| 4 | 所属ユーザー追加: 取り直さない | 入力して絞り込む | 候補の取得は、ダイアログを開いたときの 1 回のまま |
| 5 | 所属ユーザー追加: 一致なし | 誰にも一致しない文字を入力する | 「表示するデータがありません」（`COMMON.EMPTY_RESULT`）が出る |
| 6 | 所属ユーザー追加: 補足文 | 一覧を開く | 検索欄の下に `GROUPS.MEMBERS_SEARCH_HINT` が出る |
| 7 | 所属ユーザー追加: 追加 | 絞り込みを変えながら選んで確定し、［追加］を押す | 選んだユーザーが全員、追加の送信に入る |
| 8 | 所属ユーザー追加: すべて選択 | 絞り込んでいる間に「すべて選択」を押す | 表示中のユーザーだけが選ばれ、先に選んだ選択は残る |
| 9 | 所属ユーザー追加: すべて解除 | 絞り込んでいる間に「すべて解除」を押す | 表示中のユーザーだけが外れ、表示していない選択は残る |
| 10 | 所属ユーザー追加: 識別子 | 追加ダイアログの部品 | `admin-groups-add-user-select-trigger`・`-option`・`-confirm-button` で操作できる |
| 11 | 所属ユーザー追加: 欄の高さ | 一覧を開く | チップ欄に高さ上限のクラスが付く。閉じると外れる |
| 12 | `+N`: 1 行に入るだけ出す | 1 行に 3 つ入る幅で、7 つ選んだ状態にして、一覧を開いて［決定］で閉じる | 3 つのチップと `+4` が出る（2 つ目以降をすべて `+N` に数えない） |
| 13 | `+N`: バッジの折り返し | バッジが折り返す幅 | 収まるまで末尾のチップを 1 つずつ隠す |
| 14 | 開き直し | `+N` になった後に、もう一度開く | すべてのチップと入力欄が出て、`+N` が消え、名前で絞り込める |
| 15 | 高さ上限: 指定あり | `scrollChipsWhenOpen` を指定して開く | 開いている間だけ高さ上限のクラスが付く |
| 16 | 高さ上限: 指定なし | 指定せずに開く | 付かない |
| 17 | 末尾へスクロール | 指定ありで、候補を選ぶ | そのたびに欄が末尾までスクロールする |
| 18 | 一覧の付け直し | 指定ありで、候補を選んで欄の下端が下がる | 一覧の位置が、新しい下端に付け直される |
| 19 | 付け直さない | 指定なしで、同じ操作をする | 一覧の位置は変わらない |
| 20 | 既存の利用箇所 | 既存の `ComboboxMulti`・各画面のテスト | 変わらず通る |
