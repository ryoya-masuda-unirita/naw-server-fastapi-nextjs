## 詳細

### 1. 右の余白が全体に効く（🔵 提案）→ 対応しない

意図した変更。移植元（NAW-1452 の 2 つ目のコミット）も、同じ `.combobox-chips-row` の `padding-right` を共通の CSS に入れている。理由は、`+N` の判定を直すと、最後のチップが右端の区切り線と［▼］に重なるため。Issue の本文にも「チップ欄の右 padding を `spacing*12` にして ▼ と重ねない」とある。所属ユーザー追加だけに限る要件ではない（限るのは高さ上限と一覧の付け直しだけ）。

影響の確認として、アシスタントの新規作成ダイアログのコンボボックス（15 件を全選択）を実画面で確かめた。閉じた状態が 4 件と `+11`（4 + 11 = 15）で、最後の要素が区切り線に重ならない（`08_動作確認.md`）。テンプレート、チャットの共有・ライブラリ保存の実画面は未確認（自動テストは通る）。

### 2. 選択が変わるたびに末尾へスクロールする（🔵 提案）→ 対応しない

指摘のとおり、`scrollChipsWhenOpen` が有効なとき、選択の変更のたびに末尾へスクロールし、一覧を付け直す。ただし、移植元の `afterRenderEffect`（選択中の値が変わるたびに、末尾へスクロールして、一覧を付け直す）と、同じ依存・同じ動き。入力欄は欄の末尾に並ぶため、末尾へ寄せるのは「入力欄が見えるようにする」という目的と合っている。

開いた直後の `positionList` の呼び出しも、移植元と同じ。実画面（デスクトップ・モバイル）で、一覧が欄の下端に付くことを確かめた。ちらつきは、静止画では判別できないため確認していない。途中のチップを消したときの動きに不満が出たら、「選択が増えたときだけ末尾へ」に絞る改善を、移植元と合わせて別に検討する。

### 3. 閉じるときのちらつき（🔵 提案）→ 対応しない

閉じるときに `+N` を再計算する処理（`useEffect` のマイクロタスク）は、今回の変更より前からある。今回足したのは、開くときの復元（`restoreChips()`）だけで、閉じる経路は変えていない。この Issue の範囲外。
