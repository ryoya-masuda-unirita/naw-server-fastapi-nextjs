# 02_基本設計

## 変更対象

- メッセージ送信リクエストのスキーマ（入力検証）
- メッセージ送信 API の単体テスト・結合テスト

## 画面 / API 変更概要

メッセージ送信 API（multipart/form-data）の入力検証だけを変更する。レスポンス形式・エンドポイントは変えない。

| 入力 | 変更前 | 変更後（移植元と同じ） |
|---|---|---|
| 履歴添付ファイルの件数と履歴の添付件数合計の不一致 | 400 | 受け付ける（200） |
| 質問本文が空文字 | 400 | 受け付ける（200） |
| 質問本文の項目がない | 400 | 400（変更なし） |

## 影響範囲

- メッセージ送信（新規生成・質問再生成・回答再生成）の入力検証
- 履歴添付ファイルの受け取り自体は残す（移植元の API も受け取るパートとして定義している）。受け取った履歴添付ファイルは従来どおり LLM には送らない
- サービス層の処理は変更しない。空文字の本文は既存の処理でそのまま LLM 送信・保存される

## 移植方針

- 移植元で実行時に評価されている制約（本文の null 不可）だけを移植先にも残し、評価されていない制約（履歴添付件数の一致）は持ち込まない
- 件数チェックを外したことで不要になった検証処理は削除する
