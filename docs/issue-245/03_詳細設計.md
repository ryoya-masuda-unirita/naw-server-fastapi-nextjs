# 03_詳細設計

## 移植元の根拠

| ファイル（`secuaigent-ref/server/src/main/java/com/example/naw/` 配下） | 内容 |
|---|---|
| `request/CreateMessageContentRequest.java` | `userInput`・`historyMessages` に制約なし（`@JsonProperty` のみ） |
| `api/MessageController.java` | `@RequestPart("textData") @Valid CreateMessageContentRequest`、`@RequestPart(required=false) historyAttachmentFiles` を受け取り、`new CreateMessageContentViewModel(...)` を組み立てて `messageService.resolveStreamContext(vm)` を呼ぶ |
| `viewmodel/CreateMessageContentViewModel.java` | `@NotNull String userInput`（jakarta）、`isHistoryAttachmentCountCorrect()` に `javax.validation.constraints.AssertTrue` |
| `service/MessageService.java` | クラスに `@Validated`、`resolveStreamContext(@Valid CreateMessageContentViewModel vm)` でメソッドバリデーション |
| `infrastructure/APIControllerAdvice.java` | `jakarta.validation.ConstraintViolationException` を 400 にする |
| `pom.xml` | バリデーションは `spring-boot-starter-validation`（Hibernate Validator、jakarta）のみ |
| `service/PromptUserSpecService.java` | `createUserMessage` は `UserMessage.builder().text(userInput).media(...)`。空文字でもそのまま送る |

Hibernate Validator（jakarta）は `javax.validation` の注釈を認識しないため、`@AssertTrue` は評価されない。`@NotNull userInput` は評価されるため、`userInput` が null のときだけ 400 になる。

## 変更ファイル

### `backend/app/schemas/message.py`

- `MessageContentCreateRequest.userInput` を `Field(min_length=1)` から必須の `str`（長さの制約なし）に変更する
  - 項目なし・`null` は Pydantic の必須チェックで 400 のまま（移植元 `@NotNull` 相当）
  - 空文字を許す理由（移植元は `@NotNull` だけ、添付だけの送信がある）をコメントに書く
- `MessageContentCreateRequest._validate_history_attachment_count` を削除する
  - `historyAttachmentFiles` フィールドと `parse_message_content_create_form` の `historyAttachmentFiles` パートは残す（移植元 `MessageController.createMessageContent` も受け取る。移植元同様 LLM には送らない）
  - 件数チェックを移植しない理由をフィールドのコメントに書く
- `MessageContentHistoryTurn.attachmentsCount` は件数チェック以外で使わなくなるが、移植元 `HistoryMessageContent.attachmentsCount` に対応するリクエスト項目（移植元のクライアントが送る）のため残す

### サービス層（変更なし）

`app/services/message_service.py` は変更しない。空文字の `userInput` は次のとおり処理される。

- `ChatMessage(role="user", content="")` を最後のユーザー発話として組み立てる
- 添付ファイルがあれば `build_user_content("", files)` で `[{"type": "text", "text": ""}, {"type": "image_url", ...}]` になる（移植元も空文字の本文と画像を送る）
- 新規生成時は `question_text = req.userInput`（空文字）で `MessageContent.question` に保存される
