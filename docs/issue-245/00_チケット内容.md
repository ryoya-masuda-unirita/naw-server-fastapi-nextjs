# #245 issue-245 メッセージ送信で履歴の添付件数チェックを外し本文の空文字を許可する

## 概要

メッセージ送信 API（multipart、#207 で移植）で、`historyAttachmentFiles` の件数が `historyMessages[].attachmentsCount` の合計と合わないと 400 を返す（`backend/app/schemas/message.py` の `_validate_history_attachment_count`）。移植元ではこのチェックは実行時に効いていない。あわせて `userInput` が `min_length=1` になっているが、移植元は空文字を許す。

## 説明

- 移植元 `viewmodel/CreateMessageContentViewModel.java` の `@AssertTrue` は `javax.validation` の import で、実行時のバリデータ（jakarta）は評価しない
- 移植元のクライアントは `attachmentsCount` を送るが、`historyAttachmentFiles` は送らない（`messages.service.ts` に定義があるだけで呼び出し元がない）
- そのため、画像を添付して送信したあと同じルームで次を送ると、backend だけ 400 になる（React はチャット履歴の送信を未移植のため、今は画面からは起きない）
- `userInput` は移植元では `@NotNull` だけで空文字を許し、クライアントは本文が空でも添付があれば送信できる

### 対応

- 履歴の添付件数チェックを外す（件数が合わなくても 200）。既存のテスト（`tests/integration/test_messages.py` の 400 を固定しているもの）を書き換える
- `userInput` の空文字を、移植元と同じく許可する（必須なのは項目があることだけ）
