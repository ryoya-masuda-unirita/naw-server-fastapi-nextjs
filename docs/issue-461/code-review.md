## 詳細

### 1. 初回の保存の競合（🔴 重要）→ 対応済み

実機（pgvector）で、新しいテナントに、8 件を同時に保存して確かめた。修正前の `CREATE ... IF NOT EXISTS` を、ロックなしで同時に流すと、競合しうる。作成を、トランザクションの中で、`pg_advisory_xact_lock(hashtext(表名))` を取ってから行う形に直した。修正後、同時の 8 件が、失敗なしで、8 行すべて保存された。テスト（`test_creation_runs_in_transaction_with_advisory_lock`）を足した。

### 2. 索引名（🔵 提案）→ 対応済み

表名は最長 54 文字で、接尾辞を付けると 63 文字を超える。索引名を、表名のハッシュから作る短い名前（`idx_<12 文字>_fileid`・`..._embedding`）に変えた。実機で、長いテナント ID（200 文字）の表名 54 文字、索引名 23・26 文字を確認した。

### 3. 次元数の不一致（🔵 提案）→ 対応済み

`Embedding dimension mismatch` の別のメッセージで 400 を返し、原因を、ログに出す。接続の失敗とは区別される。

### 4. URL のパスワードと `sslmode`（🔵 提案）→ 対応済み

URL にパスワードを書いた接続先は、拒否する（パスワードは `api_key` 欄だけ）。`?sslmode=require` などは、`asyncpg` の `ssl` に渡す。未対応の値は拒否する。指定がなければ、asyncpg の既定（`prefer`）。

### 5. 接続とプール（🔵 提案）→ 一部対応済み

保存のたびの作成の SQL は、表がすでにあれば（`to_regclass`）省くようにした。接続プールは、Azure のクライアントも、呼び出しごとにクライアントを作る形で、揃っており、負荷の見積もりなしに入れるのは早いため、今回は見送る（`08_動作確認.md` の未確認事項に、規模での確認を書いた）。

### 6・7. import と無関係の変更（対応不要）

`ruff check` は通っている。`.vscode/settings.json` と画像は、コミットしていない（コミットは、特定のパスだけを指定している）。
