# 08_動作確認

## 確認環境

- macOS、`feature/issue-461`
- テストは `server/` の `uv run pytest`（`asyncpg` の接続はモック）
- 実機: ルートの docker compose に足した pgvector（`pgvector/pgvector:pg17`、`vector-db`）。クラウドの backend のコンテナから、実装したクライアントを呼んだ

## 確認手順

1. テストを足し、pgvector の切り替えのテストが、切り替えを外した版で失敗することを確かめる
2. 実装し、テスト・ruff・mypy を実行する
3. compose で `vector-db` を起動し、`ensure_table` → `add_rows` → `similarity_search` → `delete_by_file_id` を通しで実行する

## 確認結果

### テスト

- RAG の検索の切り替え（pgvector のとき pgvector を呼ぶ）を外すと、切り替えのテスト 1 件が失敗し（`1 failed, 1 passed`）、戻すと 2 passed
- 追加したテスト: クライアントと補助関数 31 件（接続先の判定・表名・接続の引数・パスワード入り URL の拒否・`sslmode`・リテラル・検索・表なし・失敗・保存・表の作成のロック・索引名の長さ・削除）、切り替え 2 件
- `ruff format`・`ruff check`・`mypy`（243 ファイル）が問題なし。全体の結果は、`server/` で **1544 passed**（`/code-review` の指摘に対応したあと）

### 実機（実際の pgvector）

`test-tenant` と `other-tenant` で、backend のコンテナからクライアントを呼んだ。

| 確認 | 結果 |
|---|---|
| 表名 | `docs_test_tenant_0183bfca`・`docs_other_tenant_9b506114`（テナントごとに別） |
| 表がないときの検索 | 0 件 |
| 保存 | 表・索引が自動で作られ、3 行（file-A 1 行、file-B 2 行）と、別のテナントの 1 行が入った |
| 近い順の検索 | `vec(0)` で検索 → file-A が先頭、`vec(1)` で検索 → file-B の 2 行が先頭、file-A が最後（距離の順） |
| テナントの分離 | 他のテナントの文書（file-X）が、検索に出ない |
| ファイル単位の削除 | file-B を削除 → 2 行。削除後の検索には file-A だけが出る |
| 不正なパスワード | 400（`Failed to connect to vector database`）。ログには例外の種類（`InvalidPasswordError`）だけで、パスワードは出ない |

### `/code-review` の指摘のあとの再確認（実機）

- 新しいテナントに、**8 件を同時に**保存 → 失敗なし、8 行すべて保存された（アドバイザリロック）
- 200 文字のテナント ID でも保存でき、表名 54 文字、索引名 23・26 文字（63 文字以内）
- 次元数が違うクエリ → `Embedding dimension mismatch`（接続の失敗とは区別される）
