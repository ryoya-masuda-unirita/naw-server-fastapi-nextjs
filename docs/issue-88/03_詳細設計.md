# 03_詳細設計

## 新規依存

- `backend/pyproject.toml`: `openai`（Python公式OpenAI SDK。`AsyncAzureOpenAI`でAzure OpenAI Chat Completions API・Embeddings APIの両方を呼び出す）を追加する

## 新規ファイル

### `backend/app/schemas/llm.py`

- `LlmChatTurn`: `role: str`, `content: str`（いずれも必須）
- `LlmChatRequest`: `deployName: str`（必須）, `messageId: str | None`, `additionalPrompt: str | None`, `temperature: float = 0.0`（0.0〜1.0）, `maxTokens: int | None`, `messages: list[LlmChatTurn]`（1件以上必須）
- `LlmEmbeddingRequest`: `deployName: str`（必須）, `input: str`（必須, 空白のみ拒否）, `dimensions: int | None`（1〜32767）
- `LlmEmbeddingResponse`: `embedding: list[float]`

### `backend/app/core/llm_client.py`

Azure OpenAI SDK呼び出しを閉じ込めるクライアント（`core/`配置。移植元の複数SDK系統をPython公式`openai`SDKに統一する）。

- `ChatStreamChunk`（dataclass）: `text_delta: str | None`, `input_tokens: int | None`, `output_tokens: int | None`（最終チャンクのみ`usage`から設定）
- `AzureLlmChatClient.stream_chat(endpoint, api_key, deploy_name, messages, temperature, max_tokens) -> AsyncIterator[ChatStreamChunk]`: `AsyncAzureOpenAI(...).chat.completions.create(stream=True, stream_options={"include_usage": True}, ...)`を呼び出し、テキスト差分・最終利用量チャンクを`ChatStreamChunk`に変換して yield する
- `EmbeddingResult`（dataclass）: `embedding: list[float]`, `tokens: int`
- `AzureLlmEmbeddingClient.create_embedding(endpoint, api_key, deploy_name, input_text, dimensions) -> EmbeddingResult`: `AsyncAzureOpenAI(...).embeddings.create(...)`を呼び出す

### `backend/app/core/credit_quota.py`

- `enforce_within_quota(tenant_id, session) -> None`: 移植元`TenantMonthlyCreditQuotaService.enforceWithinQuota`相当。`llm_chat_service.py`・`llm_embedding_service.py`の両方から呼ぶDBクエリを伴う共通チェックのため、「serviceが別serviceを呼ばない」規約に抵触しないよう`core/`に置く（`app/services/tenant_service.py`の`_assert_new_max_usage_based_credits_not_below_current_usage`と判定式は同一だが目的が異なるため独立実装とする）
- テナント未存在／有効なサブスクリプションなし／プランのクレジット枠未設定／請求サイクル起算日が算出できない、のいずれかに該当する場合はチェックをスキップする
- 上限以上の場合`HTTPException(429, detail="今月のクレジット利用量の上限に達しているため、チャットが送信できません")`を送出する（移植元`CreditQuotaExceededException`のメッセージ・ステータスコード(`TOO_MANY_REQUESTS`)を踏襲）

### `backend/app/services/llm_chat_service.py`

- `LlmChatService.stream_chat(tenant_id, current_user, req, session) -> StreamingResponse`
  1. `enforce_within_quota`でクレジット上限チェック
  2. `AIModelRepository.find_by_endpoint_type_and_name(AZURE_OPENAI_CHAT, req.deployName, session)`でAIModel解決。存在しなければ400
  3. `TenantEndpointRepository.find_by_tenant_id_and_type(tenant_id, AZURE_OPENAI_CHAT, session)`でエンドポイント一覧取得、`id`最小のものを採用（複数存在する場合、移植元同様に先頭を使う）。存在しなければ400
  4. `req.messageId`指定時は`MessageRepository.find_by_tenant_id_and_id`で解決し、`require_owned_room`でルーム所有権を検証（存在しない場合404、所有者でない場合403）
  5. `additionalPrompt`指定時は、最後のメッセージ本文の前に追記する（移植元と同様の単純結合）
  6. 上記で解決した`endpoint`・`api_key`・`deploy_name`・`messages`・`temperature`・`max_tokens`をクロージャに閉じ込めた非同期ジェネレータ`_sse_event_stream(...)`を作り、`StreamingResponse(media_type="text/event-stream")`として返す
- `_sse_event_stream(...)`（モジュール内部関数）
  - `AzureLlmChatClient.stream_chat`から受け取った`text_delta`ごとに`event: text_delta\ndata: {"text": ...}\n\n`をyield
  - ストリーム完了後、`event: message_stop\ndata: {"inputTokens": ..., "outputTokens": ...}\n\n`をyield
  - 例外発生時は`event: error\ndata: {"message": ...}\n\n`をyieldして終了する（例外を再送出しない。SSEは一度開始すると通常のHTTPステータスでエラーを返せないため）
  - 完了時（正常・異常問わず）、新規セッション（`get_session_maker()`）を用いて`TokenUsage`を1件保存する。入力/出力トークンからクレジットを計算する式は既存`TokenUsageRepository`・`AIModel.token_weight`を踏襲する

### `backend/app/services/llm_embedding_service.py`

- `LlmEmbeddingService.create_embedding(tenant_id, current_user, req, session) -> LlmEmbeddingResponse`
  1. `enforce_within_quota`でクレジット上限チェック
  2. `AIModelRepository.find_by_endpoint_type_and_name(AZURE_OPENAI_EMBEDDING, req.deployName, session)`でAIModel解決。存在しなければ400
  3. `TenantEndpointRepository.find_by_tenant_id_and_type(tenant_id, AZURE_OPENAI_EMBEDDING, session)`でエンドポイント解決。存在しなければ400
  4. `AzureLlmEmbeddingClient.create_embedding(...)`を呼び出す
  5. `TokenUsage`を1件保存する（`embedding_tokens`・`embedding_credits`のみ設定）
  6. `LlmEmbeddingResponse(embedding=...)`を返す

### `backend/app/routers/llm.py`

- `POST /api/llm/chat` → `LlmChatService.stream_chat`
- `POST /api/llm/embedding` → `LlmEmbeddingService.create_embedding`
- 両エンドポイントとも`get_verified_tenant_id`・`get_current_user`・`get_session`に依存する（既存ルーターと同じパターン）

## クレジット計算式

移植元`TokenUsage.creditsFromTokens`・`TokenUsage.embeddingCredits`相当の計算はFastAPI側に存在しないため、本Issueで`app/models/token_usage.py`または`app/core/`に計算関数を新規追加する。計算式は以下（移植元Java版を踏襲）。

- `input_credits = ceil(input_tokens * token_weight / tokens_per_credit * input_credit_weight)`
- `output_credits = ceil(output_tokens * token_weight / tokens_per_credit)`
- `embedding_credits = ceil(embedding_tokens * token_weight / tokens_per_credit)`

移植元の`tokensPerCredit`・`inputCreditWeight`定数は環境設定値のため、`app/core/config.py`に`LlmCreditSettings`（`AzureCostSettings`と同様の独立設定クラス）として追加する。デフォルト値は移植元の設定ファイル（`application.yml`）を確認し、値が見つからない場合は`tokens_per_credit=1000`, `input_credit_weight=1.0`を仮値とし、`06_タスクリスト.md`に要確認事項として明記する。
