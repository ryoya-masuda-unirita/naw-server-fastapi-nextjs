# 04_テスト設計

## テスト方針

- Azure OpenAI SDKへの実際のネットワーク呼び出しは行わず、`AzureLlmChatClient`・`AzureLlmEmbeddingClient`（またはその内部で使う`AsyncAzureOpenAI`）をモックする
- チャットのSSEストリーミングは、`httpx`の`AsyncClient`でエンドポイントを叩き、レスポンスボディに含まれるSSEイベント文字列を検証することで代替する（ブラウザでのEventSource動作確認は行わない）
- クレジット上限チェック・モデル/エンドポイント解決・トークン使用量永続化はサービス層の単体テストで検証する（Repositoryをモック）

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | クレジット上限チェック | 当月利用量が上限未満 | チェックを通過する |
| 2 | クレジット上限チェック | 当月利用量が上限以上 | 429エラーになる |
| 3 | クレジット上限チェック | 有効なサブスクリプションが存在しない | チェックをスキップして通過する |
| 4 | チャット: モデル解決 | 指定したdeployNameのAIModelが存在しない | 400エラーになる |
| 5 | チャット: エンドポイント解決 | テナントにAzure OpenAI Chatエンドポイントが存在しない | 400エラーになる |
| 6 | チャット: messageId指定 | 指定したメッセージが別ユーザーのルームに属する | 403エラーになる |
| 7 | チャット: ストリーミング | 正常系 | `text_delta`イベントが本文分割で送出され、最後に`message_stop`イベントが送出される |
| 8 | チャット: ストリーミング | Azure呼び出し中に例外発生 | `error`イベントが送出され、例外がクライアントに伝播しない |
| 9 | チャット: 永続化 | ストリーミング完了後 | 入力/出力トークン数に応じたTokenUsageが1件保存される |
| 10 | 埋め込み: 正常系 | 有効なdeployName・inputを指定 | ベクトルが返却され、embeddingTokensに応じたTokenUsageが1件保存される |
| 11 | 埋め込み: モデル解決 | 指定したdeployNameのAIModelが存在しない | 400エラーになる |
| 12 | クレジット計算 | input/output/embeddingトークン数を指定 | 移植元と同じ計算式でクレジットが算出される |
