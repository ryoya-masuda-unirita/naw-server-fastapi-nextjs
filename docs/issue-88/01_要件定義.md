# 01_要件定義

## 背景

FastAPI移植先には、チャット画面から実際にAIモデルを呼び出す手段がまだ存在しない。Room/Message関連のドメイン（質問スレッドの作成・一覧取得・削除・フィードバック）はすでに移植済みだが、それらに対して実際にLLMへ問い合わせて回答を生成する仕組みが欠けている。本Issueでは、移植元(Spring Boot)の`LlmController`が提供するチャット・埋め込みAPIをFastAPI側に移植する。

## 機能要件

### チャット（ストリーミング応答）

- テナントに紐づくAzure OpenAIエンドポイント・APIキー・デプロイ名を用いて、Azure OpenAI Chatモデルを呼び出す
- 会話履歴（ロール・本文の配列）とデプロイ名を必須パラメータとして受け取り、応答をSSE（Server-Sent Events）でストリーミング返却する
- 呼び出し前に、テナントの当月クレジット利用量が契約プランの上限に達していないかを検証し、達している場合は呼び出しを拒否する
- ストリーミング完了後、消費したトークン数・クレジット数を利用量記録として永続化する
- 追加のシステムプロンプト（`additionalPrompt`）、生成パラメータ（`temperature`・`maxTokens`）を指定できる
- 既存の質問スレッド（`messageId`）を指定した場合、その所属ルームの所有者本人であることを検証する

### 埋め込み

- テナントに紐づくAzure OpenAI Embeddingsモデルを呼び出し、入力テキストのベクトル表現を取得する
- 呼び出し前にチャットと同様のクレジット上限チェックを行う
- 呼び出し後、消費したトークン数・クレジット数を利用量記録として永続化する

## 非機能要件

- Azure OpenAI SDKへの実際のネットワーク呼び出しは、自動テストではすべてモック化する
- SSEストリーミングの検証は、自動テストで可能な範囲（イベント形式・完了時の永続化呼び出し等）に限定する
- ブラウザでの動作確認は行わず、自動テストの実行結果で代替する

## スコープ外

移植元は「基本チャット」→「Web検索/MCP tools対応」→「ライブラリ生成（createLibrary）」→「response_format（レスポンス形式指定）」の順に段階的に機能が積まれており、一括移植は実装・レビューの両面で規模が大きすぎる。本Issueでは以下を明示的にスコープ外とし、後続Issueで対応する。

- チャットへの添付ファイル（画像等）指定・処理
- tools（`web_search` / `mcp`）を用いたFunction Calling
- ライブラリ生成モード（`createLibrary`）
- response_format（JSON出力形式指定）
- `reasoning_effort` / `verbosity` 等、上記機能に付随する詳細パラメータ

これらのパラメータを含むリクエストは、本Issueの実装では受け付けない（スキーマに含めない）。
