# 05_テスト詳細設計

## 対象テストファイル

- `backend/tests/unit/test_credit_quota.py`: `enforce_within_quota`の単体テスト（`TenantRepository`・`SubscriptionRepository`・`TokenUsageRepository`をモック）
- `backend/tests/unit/test_llm_client.py`: `AzureLlmChatClient.stream_chat`・`AzureLlmEmbeddingClient.create_embedding`の単体テスト（`AsyncAzureOpenAI`をモックし、SDKレスポンスから`ChatStreamChunk`/`EmbeddingResult`への変換を検証）
- `backend/tests/unit/test_llm_chat_service.py`: `LlmChatService.stream_chat`の単体テスト（Repository・`AzureLlmChatClient`・`enforce_within_quota`をモック。`StreamingResponse`の`body_iterator`を実際に消費してSSEイベント文字列を検証する）
- `backend/tests/unit/test_llm_embedding_service.py`: `LlmEmbeddingService.create_embedding`の単体テスト（Repository・`AzureLlmEmbeddingClient`をモック）
- `backend/tests/unit/test_token_usage_credit_calc.py`: クレジット計算関数の単体テスト

## 対象実装ファイル

`03_詳細設計.md`に記載の新規ファイル一式・`ai_model_repository.py`・`pyproject.toml`・`main.py`。

## テストデータ方針

- テナント・ユーザー・AIModel・TenantEndpoint・Plan・Subscriptionは、いずれもDBに接続しないユニットテストのため、Pythonオブジェクトとして`SimpleNamespace`または実際のSQLModelインスタンス（DB未保存）を組み立てて使う
- Azure SDKのレスポンスは`unittest.mock.MagicMock`/`AsyncMock`で、`chat.completions.create`のストリーミングチャンク列・`embeddings.create`のレスポンス構造を模したオブジェクトを用意する
