# 01_要件定義

## 背景

ローカル用サーバーの学習データの更新者はログイン ID しか持たない。クライアントが更新者名を引くには、現状の部分一致の `searchText` だとログイン ID ごとに呼ぶ必要があり、部分一致で別の人も当たる。全ユーザー取得はユーザー数に比例して遅くなる。そのため、表示するページ分のログイン ID を完全一致で 1 回で引けるようにする。

## 機能要件

- ユーザー一覧 API が、ログイン ID の完全一致で絞り込む任意のクエリ `loginIds` を受け取れる。
- `loginIds` は同じキーを繰り返して複数指定できる。指定したログイン ID のいずれかに完全一致するユーザーだけが返る。
- 空・未指定の場合は絞り込まない（既存の呼び出し元の振る舞いは変わらない）。
- 他の条件（検索文字列・ロール・除外グループ）や並べ替え、利用量の付与と併用できる。`totalCredits` ソートと併用しても絞り込みが効く。
- 件数（`totalElements`）にも絞り込みが反映される。
- テナント分離と、SYSTEM ロールを一覧に出さない既存の挙動は、`loginIds` を指定しても変わらない（他テナント・SYSTEM のログイン ID を指定しても返らない）。

## 非機能要件

- 指定する値の数に関わらず、追加のクエリを発行しない（絞り込みは 1 回の検索条件として扱う）。

## スコープ外

- フロントエンドの学習データ更新者名の引き当て。
- コンマ区切り指定の解釈（クライアントは同じキーの繰り返しで送る）。
