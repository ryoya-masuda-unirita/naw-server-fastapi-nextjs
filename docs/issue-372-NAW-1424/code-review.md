## 詳細

### 1. 空文字のログイン ID（🔵 提案）→ 対応しない

移植元も、指定された値をそのまま IN 条件に渡しており（null・空リストのときだけ無効）、空文字 1 件のときは同じく 0 件になる。移植元と挙動を揃えるため変更しない。

### 2. 要素数の上限（🔵 提案）→ 対応しない

移植元にも上限はなく、利用側は 1 ページ分（`size` は最大 1000）のログイン ID を渡す想定。スコープ外のため変更しない。

## 🔴 致命的

なし。条件はテナント・SYSTEM 除外の条件に AND で足されるため、他テナント・SYSTEM のユーザーは返らない（結合テストで確認済み）。件数用クエリ・利用クレジット順の分岐は同じ検索条件を使うため併用できる（結合テストで確認済み）。
