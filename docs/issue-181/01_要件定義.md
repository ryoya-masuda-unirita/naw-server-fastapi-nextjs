# 01_要件定義

## 背景

- チーム詳細の所属ユーザー一覧で、ユーザー表示名順の昇順・降順を切り替えても先頭行が変わらないと報告された
- フロントエンド（`frontend-angular`）は `sort={updatedAt|name|role},{asc|desc}` と `includeUsage=true` を送っており、移植元 Spring Boot の所属ユーザー一覧 API（`Pageable` の `sort`）と一致している。フロントエンドでの並べ替え直しも無い。原因はバックエンドにある
- バックエンドはすでに `sort` を受け取り ORDER BY を組み立てているが、移植元と比べて次の差分・不具合がある
  1. ソートキーが同値の行（同名ユーザー、シード投入で同時刻になる追加日時、大半が「一般」の権限など）に対して並びを決めるキーが無い。同値グループ内の順序は DB 任せになり、昇順と降順を切り替えても反転しない。自動テストで、追加日時が同値の所属ユーザー群では昇順と降順の結果が完全に一致することを確認した
  2. ユーザー表示名順は、移植元では大文字小文字を区別しない（`lower(user.name)`）が、こちらは区別して並べている
  3. ソート方向の指定で大文字小文字を区別している（移植元は区別しない）
- 共有のローカル DB は使えないため、報告環境の所属ユーザーのデータで「表示名順の先頭行が変わらない」ことを直接再現することはできていない。上記 1 は、昇順・降順を切り替えても順序が変わらないという報告どおりの症状を起こす。そのため、上記の差分をすべて移植元に合わせて直す

## 機能要件

- 並べ替えキー（追加日時・ユーザー表示名・権限・利用クレジット）と方向（昇順・降順）の組み合わせで、一覧の並びが決定的に定まること
- 同じキーで昇順と降順を切り替えると、一覧の並びが完全に反転すること（同値の行を含む）
  - ただし利用クレジット順は、移植元（`orderByTotalCreditsForGroupUser`）に合わせてクレジットが同じ行は方向に関係なく表示名の昇順で並べる
- ユーザー表示名順は大文字小文字を区別せずに並べること
- ソート方向は大文字小文字を区別せずに解釈すること
- 既存の挙動（キーの読み替え、利用クレジット順と `includeUsage` の組み合わせ検証）は変えないこと

## 非機能要件

- DB マイグレーションを追加しないこと
- 一覧取得のクエリ回数を増やさないこと

## スコープ外

- 所属ユーザー一覧から SYSTEM 権限のユーザーを外す処理（移植元の `excludeSystemUsers` 相当）。並べ替えとは別の差分のため、本 Issue では扱わない
- 他の一覧 API（ユーザー管理一覧は #172、テンプレート一覧は #170）
- フロントエンドの変更（E2E テストの `test.skip` 解除を含む）
