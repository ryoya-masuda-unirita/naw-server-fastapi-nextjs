# 05_テスト詳細設計

## 対象ファイル

`backend/tests/integration/test_libraries.py`

## fixture方針

`tests/integration/test_library_tags.py`のfixtureパターン（tenant/other_tenant/admin_user/member_user/_headers）を踏襲しつつ、Library固有のfixtureを追加する。

- `tenant`, `other_tenant`: テスト用テナント
- `owner_user`: ルーム所有者（ライブラリ作成者になることが多い）
- `other_user`: 別ユーザー（グループ経由アクセスの検証、権限なしの検証に使う）
- `group`: 所属グループ。`other_user`を所属させる。
- `room`: `owner_user`が所有するルーム
- `message`: `room`に紐づくメッセージ
- `library`: `owner_user`が作成し`message`に紐づくライブラリ
- `library_tag`: 付与用のライブラリタグ
- `share_library`: `library`を`group`に共有する`ShareLibrary`レコード（一部テストのみ使用）

## テストクラス構成

- `TestListLibraries`（GET /api/libraries）: 04の No.1〜11 に対応
- `TestListLibrariesByRoom`（GET /api/libraries/{roomId}/list）: No.12〜15
- `TestGetLibrary`（GET /api/libraries/{libraryId}）: No.16〜19
- `TestUpdateLibrary`（PUT /api/libraries/{libraryId}）: No.20〜26
- `TestDeleteLibrary`（DELETE /api/libraries/{libraryId}）: No.27〜29
- テナント分離（No.30）は`TestGetLibrary`内に追加

## 主要なアサーション例

```python
async def test_list_libraries_shared_via_group(
    self, client, member_headers, shared_library, group_member_headers
):
    """所属グループに共有されたライブラリが一覧に含まれること"""
    async with client as c:
        response = await c.get("/api/libraries", headers=group_member_headers)

    assert response.status_code == 200
    body = response.json()["data"]
    assert shared_library.id in [item["id"] for item in body["content"]]
```

各テストメソッド名は英語（`test_xxx`）、意図は日本語docstringで記載する（プロジェクト規約）。
