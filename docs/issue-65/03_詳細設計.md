# 03_詳細設計

## マイグレーション

`backend/alembic/versions/015_add_libraries.py`

- `libraries`: id(uuid, pk, server_default gen_random_uuid()) / tenant_id(varchar32, fk tenants.id cascade) / message_id(varchar32, fk messages.id cascade) / user_id(uuid, fk users.id cascade) / title(varchar255, not null) / content(text, nullable) / created_at / updated_at
- `share_libraries`: id(uuid, pk) / tenant_id(fk tenants.id cascade) / library_id(uuid, fk libraries.id cascade) / group_id(varchar32, fk groups.id cascade) / created_at / unique(library_id, group_id)
- `library_tag_mappings`: id(uuid, pk) / tenant_id(fk tenants.id cascade) / library_id(uuid, fk libraries.id cascade) / library_tag_id(uuid, fk library_tags.id cascade) / created_at / unique(library_id, library_tag_id)

## モデル

`backend/app/models/library.py`

- `Library(SQLModel, table=True)`: `__tablename__ = "libraries"`。id: uuid.UUID（`sa.UUID` + `server_default=gen_random_uuid()`、Group/Room等と違いUUID型である点に注意）。tenant_id/message_id: str(32) with FK。user_id: uuid.UUID with FK(users.id)。title: str(255)。content: str | None（`sa.Text`）。created_at/updated_at。
- `ShareLibrary(SQLModel, table=True)`: `__tablename__ = "share_libraries"`。id: uuid.UUID。tenant_id/group_id: str(32) with FK。library_id: uuid.UUID with FK(libraries.id)。created_at。UniqueConstraint(library_id, group_id)。
- `LibraryTagMapping(SQLModel, table=True)`: `__tablename__ = "library_tag_mappings"`。id: uuid.UUID。tenant_id: str(32) with FK。library_id: uuid.UUID with FK(libraries.id)。library_tag_id: uuid.UUID with FK(library_tags.id)。created_at。UniqueConstraint(library_id, library_tag_id)。

既存の`LibraryTag`（`app/models/library_tag.py`）・`Group`・`Room`・`User`・`Message`はそのまま流用する。

## core/room_access.py 拡張

既存の`require_owned_room`はそのまま維持。新規に以下を追加する。

- `async def can_view_room(tenant_id, current_user, room, session) -> bool`: room所有者 or `current_user.role == UserRole.ADMIN` or 共有グループ経由（`ShareRoomRepository.find_group_ids_by_room_id` と `GroupUserRepository.find_belonging_group_ids` の積集合が非空）。
- `async def require_viewable_room(tenant_id, current_user, room_id, session) -> Room`: ルームが存在しなければ404、`can_view_room`がFalseなら403。ルームを返す。

## リポジトリ

- `backend/app/repositories/library_repository.py`: `find_by_id_and_tenant_id` / `find_page`（絞り込み条件・ソートを引数で受け取り動的に`where()`組み立て） / `find_by_room_id_and_tenant_id`（メッセージ経由でルーム紐づきライブラリ取得、created_at昇順） / `save` / `delete`

- `backend/app/repositories/library_tag_mapping_repository.py`: `find_tags_grouped_by_library_ids`（IN句2段階） / `replace_tags_for_library`（一括DELETE + add）
- `backend/app/repositories/share_room_repository.py` に `find_group_ids_by_room_id(room_id, tenant_id, session)` を追加（既存の`find_group_ids_by_share_id`とは別に、room_idで直接引けるメソッドを追加。`ShareRoom`モデルは`room_id`列を保持済みのため追加クエリのみで対応可能）

## スキーマ

`backend/app/schemas/library.py`

## サービス

`backend/app/services/library_service.py`（`LibraryService`）

- `get_libraries(tenant_id, current_user, page, size, title, created_by, exclude_created_by, tag_ids, sort_by, sort_dir, session)`: `isVisibleToUser`相当の絞り込み（`user_id == current_user.id` or 共有先グループに所属）+ 各種絞り込み。取得後、対象ライブラリID一覧でタグ・共有グループをIN句一括取得しレスポンスに合成。
- `get_library_list(tenant_id, current_user, room_id, session)`: `require_viewable_room`でルーム閲覧権限を検証後、ルーム紐づきライブラリ一覧を返す。
- `get_library(tenant_id, current_user, library_id, session)`: ライブラリ取得（404）。`message_id`から`Message`を引き`room_id`を取得。ルームが存在し`can_view_room`がTrueなら返す。それ以外は「所有者 or 共有先グループ所属」を満たすか判定し、満たさなければ404。
- `update_library(tenant_id, current_user, library_id, req, session)`: ライブラリ取得（404）→ 紐づく`message_id`から`room_id`解決（取得不可なら404）→ `require_owned_room`で所有者検証（403）→ name更新 → グループ・タグ完全置換（存在しないID指定時は400）。
- `delete_library(tenant_id, current_user, library_id, session)`: 同様の404/403検証後、削除（CASCADEで中間テーブルも連動削除）。

## ルーター

`backend/app/routers/libraries.py`（`library_router = APIRouter(prefix="/api/libraries", tags=["libraries"])`）

- `GET ""` → `get_libraries`
- `GET "/{room_id}/list"` → `get_library_list`
- `GET "/{library_id}"` → `get_library`
- `PUT "/{library_id}"` → `update_library`
- `DELETE "/{library_id}"` → `delete_library`（204）

`app/main.py`に`library_router`を登録する。ルーティングの優先順位上、`/{room_id}/list`と`/{library_id}`はパスパターンが競合しないためFastAPIのルート登録順に依存しない（`/list`サフィックスの有無で区別される）。
