# 04_テスト設計

## テスト方針

Router層をASGITransport経由で叩く形式のテスト（既存の`tests/integration/test_library_tags.py`等と同じ構成）を`tests/integration/test_libraries.py`に作成する。DBはインメモリSQLiteを使用する既存のconftestパターンに従う。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 一覧取得 | 自身作成のライブラリのみ存在 | 自身のライブラリが返る |
| 2 | 一覧取得 | 所属グループに共有されたライブラリが存在 | 共有先ライブラリも返る |
| 3 | 一覧取得 | 他人が作成し自分に共有されていないライブラリが存在 | 返らない |
| 4 | 一覧取得 | title絞り込み指定 | 部分一致するもののみ返る |
| 5 | 一覧取得 | title に % や _ を含む | ワイルドカードとして扱われず文字通り検索される |
| 6 | 一覧取得 | createdBy指定 | 指定loginIdが作成したもののみ返る |
| 7 | 一覧取得 | excludeCreatedBy指定 | 指定loginId以外が作成したもののみ返る |
| 8 | 一覧取得 | tagIds指定 | 指定タグが付与されたもののみ返る |
| 9 | 一覧取得 | ページング（page, size） | 指定ページ・件数で返り、totalElementsが正しい |
| 10 | 一覧取得 | sortBy=title | タイトル順で返る |
| 11 | 一覧取得 | 不正なsortBy/sortDir | エラーにならずデフォルト（updatedAt/desc）でフォールバックする |
| 12 | ルーム紐づき一覧 | 自身が所有するルーム | 紐づくライブラリがcreated_at昇順で返る |
| 13 | ルーム紐づき一覧 | 共有グループ経由でアクセス可能なルーム | 一覧が返る |
| 14 | ルーム紐づき一覧 | アクセス権のないルーム | 403になる |
| 15 | ルーム紐づき一覧 | 存在しないルームID | 404になる |
| 16 | コンテンツ取得 | ルーム所有者本人 | title・contentが返る |
| 17 | コンテンツ取得 | ライブラリの共有先グループのメンバー（ルームへのアクセス権はない） | title・contentが返る |
| 18 | コンテンツ取得 | どちらの条件も満たさない | 404になる |
| 19 | コンテンツ取得 | 存在しないlibraryId | 404になる |
| 20 | 更新 | ルーム所有者本人が名前・グループ・タグを更新 | 更新され、idが返る |
| 21 | 更新 | groups/tagsを空配列で指定 | 既存の共有・タグが全解除される |
| 22 | 更新 | 存在しないグループIDを指定 | 400になる |
| 23 | 更新 | 存在しないタグIDを指定 | 400になる |
| 24 | 更新 | ルーム所有者でない（共有グループメンバー含む） | 403になる |
| 25 | 更新 | 存在しないlibraryId | 404になる |
| 26 | 更新 | name空白のみ | 422になる |
| 27 | 削除 | ルーム所有者本人 | 204が返り、共有・タグ紐づけも連動削除される |
| 28 | 削除 | ルーム所有者でない | 403になる |
| 29 | 削除 | 存在しないlibraryId | 404になる |
| 30 | テナント分離 | 他テナントのlibraryIdを指定 | 404になる |
