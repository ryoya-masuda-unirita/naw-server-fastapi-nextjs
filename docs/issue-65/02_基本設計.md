# 02_基本設計

## 変更対象

- 新規テーブル: `libraries`（ライブラリ本体）・`share_libraries`（ライブラリ⇄共有先グループ中間テーブル）・`library_tag_mappings`（ライブラリ⇄タグ中間テーブル）
- 新規モデル・リポジトリ・サービス・ルーター一式（Library関連）
- 既存の `core/room_access.py` へ、ルーム閲覧権限（所有者・テナント管理者・共有グループ経由）の判定ロジックを追加

## 画面 / API 変更概要

- `GET /api/libraries`: 汎用一覧。ページング・絞り込み・ソートに対応。
- `GET /api/libraries/{roomId}/list`: ルーム紐づき一覧（id・titleのみ）。
- `GET /api/libraries/{libraryId}`: Markdownコンテンツ取得。
- `PUT /api/libraries/{libraryId}`: 名前・共有グループ・タグの更新（完全置換）。
- `DELETE /api/libraries/{libraryId}`: 削除。

## 影響範囲

- 既存の `library_tags`・`groups`・`rooms`・`users`・`messages` テーブルへの参照が発生するが、これらのテーブル自体には変更を加えない。
- `core/room_access.py` に関数を追加するが、既存の `require_owned_room` の挙動・シグネチャは変更しない（後方互換）。

## 移植方針

- Spring Boot側の`RoomAccessService.canAccessRoom`（所有者 or テナント管理者 or 共有グループ経由）に相当する判定は、FastAPI側に未実装のため`core/room_access.py`に新規関数として追加する。`canWriteRoom`はグループを考慮せず所有者のみの判定であり、これは既存の`require_owned_room`とロジックが一致するためそのまま流用する。
- `LibrarySpecification`（動的Specification）はSQLAlchemyの`where()`の動的組み立てで代替する。
- `title`・`createdBy`・`excludeCreatedBy`・`tagIds`のいずれも未指定時はその条件を追加しない（Spring側がSpecificationをnullにして無視するのと同じ挙動）。
- `sortBy`・`sortDir`は不正な値でも422にせず、Spring同様デフォルトへ寛容にフォールバックする。
- ページ一覧のタグ・共有グループはIN句2段階で取得し、Python側でdictに集約してN+1を回避する（既存の`group_prompt_template_repository.py`のパターンを踏襲）。
- 更新時の完全置換（共有グループ・タグ）は、一括DELETE文 + `session.add()`ループ（`insertmanyvalues`で1回のINSERTにバッチ化される）で実装する。
