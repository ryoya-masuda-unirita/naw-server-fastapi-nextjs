# 02_基本設計

## 変更対象

ログイン画面。

## 画面 / API 変更概要

画面のみ。API は変更しない。入力に誤りがあるときは認証 API を呼ばない。

## 影響範囲

- ログイン画面の入力欄・送信の挙動
- パスワード再設定画面（#362）でも使えるよう、入力チェックは共通の関数に切り出す

## 移植方針

- 移植元 `login.component.ts` のバリデーション（required・minLength(3)・maxLength(50)、パスワードは required・maxLength(PASSWORD_MAX_LENGTH)・passwordAscii）と、`resolveControlError` のエラー順（必須 → 最小 → 最大 → 半角）に合わせる
- Angular の `Validators.required` は空文字だけを未入力とするため、同じ判定にする（空白のみは必須エラーにしない）。テナントID は React 独自で、従来どおり前後の空白を除いた値で判定する
- 判断: 移植元のログインエラーはユーザーID欄の下に出るが、本 Issue の範囲外のため既存の上部の帯のままにする
