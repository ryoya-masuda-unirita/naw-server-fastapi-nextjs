# 01_要件定義

## 背景

E2E（#316）で、ログイン画面が移植元と違い、未入力・文字数不足のときに画面へ何も出さず、入力の誤りが利用者に伝わらないことが分かった。

## 機能要件

- 送信時に全欄を検証し、誤りのある欄の下に文言を出す。誤りがあれば認証 API を呼ばない
- ユーザーID: 必須（「この項目は必須です」）、3 文字以上（「3文字以上で入力してください」）、50 文字以下
- パスワード: 必須、64 文字以下、半角英数字記号のみ。入力欄は全角を取り除き 64 文字で切る
- テナントID（React 独自の欄）: 未入力なら必須エラーを出す
- ブラウザ標準の吹き出しは出さない
- エラーは移植元と同じく、触れた欄（blur・送信済み）にだけ出し、入力を直せば消える

## 非機能要件

- 文言は既存の i18n キー（`VALIDATION.*`）を使う。辞書は変えない

## スコープ外

- ログイン成功・失敗時のトースト（移植元の `AUTH.LOGIN.SUCCESS` など）
- ログインキー認証（#361）、パスワード再設定画面（#362）
