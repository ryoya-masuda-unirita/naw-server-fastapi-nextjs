# 02_基本設計

## 変更対象

- `backend/seed.sql`（追記のみ。既存の記述は変更しない）

## 画面 / API変更概要

- 画面・APIの仕様変更は無い。投入するデータ量・多様性が増えるのみ

## 影響範囲

- ローカル開発環境での動作確認時に見えるデータ量・データの多様性
- 既存Issue対応で参照している固定IDのデータには影響しない
  （既存記述は変更せず、新規データを追記する方針のため）

## 移植方針

- 移植元（Spring Boot / naw-server）の実データそのものを移行するのではなく、
  「テナント数・ユーザー数・グループ数などの規模感」「グループ・アシスタント・
  プロンプトテンプレートの紐付けパターン」のみを参考にしてゼロから新規データを作成する
- 既存のseed.sqlの書き方（`INSERT ... SELECT ... WHERE NOT EXISTS`または
  `INSERT ... ON CONFLICT DO NOTHING`による冪等な投入、固定IDの使用）を踏襲する
- 追加するテナント・ユーザー等の名称・内容は、実在の顧客名・個人名を想起させない、
  一般的なダミー名（例: 部署名・役職名のパターンを模した架空の名称）にする
