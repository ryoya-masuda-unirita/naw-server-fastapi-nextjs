# 08_動作確認

## 確認環境

- 既存稼働中の`naw-fastapi-postgres`・`naw-fastapi-backend`コンテナを使用
- 確認方法: AIエージェントが`docker exec psql`・`curl`で確認した

## 確認結果

### Step 1: 冪等性の確認

`seed.sql`全体を複数回実行し、2回目以降はすべて`INSERT 0 0`（追加分なし）になることを確認した。

✅ 冪等に再実行できることを確認した

### Step 2: データ件数の確認

追加した2テナント（`tenant-demo-a`・`tenant-demo-b`）分のデータ件数をSQLで集計した。

```
groups            :  8 (4件 × 2テナント)
assistants        : 12 (6件 × 2テナント)
prompt_templates  : 12 (6件 × 2テナント)
rooms             : 24 (12件 × 2テナント)
messages          : 24 (12件 × 2テナント)
message_feedbacks : 12 (6件 × 2テナント)
tenant_endpoints  :  2 (1件 × 2テナント)
groups_users      : 30 (15件 × 2テナント)
groups_assistants : 12 (6件 × 2テナント)
subscriptions     :  2 (1件 × 2テナント)
```

✅ `03_詳細設計.md`記載の想定件数と一致した

### Step 3: ログイン確認

`tenant-demo-a-user01`（`tenant-demo-a`の管理者ユーザー）で`admin@1234`によりログインを実行。

```
{"id":"tenant-demo-a-user01","name":"デモユーザー01","role":"ADMIN","loginStatus":"SUCCESS",...}
```

✅ ログインに成功した

途中、既存`admin`ユーザーのbcryptハッシュが`admin@1234`で検証が通らない誤った値であることが
判明したため（`bcrypt.checkpw`で直接検証し確認）、正しい値に修正した上で再検証している。

### Step 4: グループ一覧APIの確認

ログイン後のセッションでグループ一覧APIを呼び出したところ、4件のグループが返った。

✅ 想定件数のグループが取得できた

### Step 5: クレジット利用状況ダッシュボードAPIの確認

```
{"totalCredits":0,"creditLimit":50000,"periodFrom":"2026-07-01T00:00:00Z",
 "periodTo":"...","nextBillingResetAt":"2026-08-01T00:00:00Z"}
```

✅ サブスクリプション・プランに基づく請求期間・クレジット上限が正しく返った

### Step 6: 既存データへの影響確認

`test-tenant`関連のテーブル・データ件数を確認し、既存記述の変更がないことをコードレビュー
（`git diff`）で確認した（`backend/seed.sql`は追記のみで、既存部分の変更は
adminユーザーのハッシュ修正1箇所のみ）。

✅ 既存データへの影響がないことを確認した
