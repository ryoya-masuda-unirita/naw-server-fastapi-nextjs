# 01_要件定義

## 背景

- `backend/seed.sql`は各Issue対応のたびに、そのIssueで必要な最小限のデータを追記する形で
  育ってきており、テナント数・ユーザー数・アシスタント数・グループ数などが実運用の規模感と
  比べて非常に少ない
- 一覧表示・ページネーション・複数テナント/複数ユーザーが絡む機能（フィードバック一覧、
  クレジット利用状況、グループ管理等）の動作確認を行う際、データ件数が少なすぎて
  UI上の見え方（一覧のスクロール、ページング、空状態と一覧表示の切り替わり等）を
  十分に確認できない
- dev/staging RDS（Spring Boot版）の実データを直接移行することはできない
  （スキーマ管理方式・テーブル構造が異なるため。Issue #150関連の調査で確認済み）が、
  「テナント数・ユーザー数・グループ数などの規模感」「グループ・アシスタント・
  プロンプトテンプレートの紐付けパターン」は参考にできる

## 機能要件

- 複数テナント（2〜3件程度）を用意し、テナント間のデータが混在しないことを確認できるようにする
- テナントごとに複数ユーザー（管理者・一般ユーザーを含め数十件程度）を用意する
- 複数グループを用意し、グループへのユーザー・アシスタント・プロンプトテンプレートの
  紐付けを、1グループに複数件・1ユーザーが複数グループに所属する等、実運用相当の
  多重度で用意する
- アシスタント・プロンプトテンプレートを、役割やカテゴリの異なる複数種類用意する
- ルーム・メッセージ・メッセージフィードバックを、一覧系画面の動作確認に十分な件数
  （現状より一桁多い程度）用意する
- 既存Issue対応で参照されている固定ID（例: `test-tenant`、
  `00000000-0000-4000-8000-000000000001`等）は変更せず、追加分は新しいIDで積み増す

## 非機能要件

- 既存の`ON CONFLICT DO NOTHING`による冪等な投入方針を維持し、既存データを壊さない
- `docker exec -i naw-fastapi-postgres psql -U root -d postgres < backend/seed.sql`の
  実行時間が極端に長くならない範囲に収める

## スコープ外

- Spring Boot側の実データそのものの移行・コピー
- パフォーマンステスト用の大量データ（数千件規模）投入
- フロントエンド（React `frontend/`）向けのseedデータ整備
