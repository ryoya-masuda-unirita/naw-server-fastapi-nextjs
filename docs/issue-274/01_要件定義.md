# 01_要件定義

## 背景

- SECURE アシスタントでは、ブラウザ → server-local → Waha! → アダプタ → LLM の順に処理が流れる。Waha! はユニリタの ETL 製品で、移植元・このリポジトリのどちらにも本体がない
- そのため、server-local を通しで動かして確かめる手段がない。Waha! と同じ HTTP API を持つ代わりのサービス（エミュレーター）を作り、server-local からチャットが通しで動く状態にする
- 本 Issue は土台。アダプタ（生成AI・検索・埋め込み）は後続の Issue で 1 つずつ移植して差し込むため、ワークフローを差し替えられる作りにしておく

## 機能要件

### API（server-local の Waha! クライアントが使うものだけ）

| No | 機能 | 要件 |
|---|---|---|
| F1 | セッション開始 | 認証キーが設定値と一致すればセッション ID をテキストで返す。一致しなければ HTTP エラー |
| F2 | セッション終了 | セッションと、保持しているスロットのファイルを破棄する。実行中のジョブがあれば止める |
| F3 | ファイルのアップロード | 入力スロット（`file`・`question`・`attachmentfile`・`history`・`textdata`）に multipart の `file` を保存する。同じスロットへの再アップロードは上書き |
| F4 | ジョブの実行 | サービス ID とパラメータからワークフローを選んで実行する。チャットでは `streamfilepath` に途中経過を書く |
| F5 | 結果の取得 | 実行中は `RUNNING`、成功は `SUCCESS`、失敗は `FAILURE` で始まる理由付きのテキストを返す |
| F6 | 出力のダウンロード | ワークフローが書いた `outputfile` の中身をテキストで返す |

- 存在しないセッション ID は HTTP エラーにする
- パス・パラメータ名・応答は server-local の Waha! クライアントと同じにする

### ワークフロー

| No | 機能 | 要件 |
|---|---|---|
| W1 | ワークフローの選択 | サービス ID ごとにワークフローを登録できる。登録がなければパラメータで学習・同期を見分け、それ以外は既定（仮のチャット）にする |
| W2 | 仮のチャット | 質問（と履歴）を LLM に 1 回渡し、回答を `{"answer", "filepaths", "references"}` の JSON で出力する。LLM の応答の差分を途中経過としてストリームファイルに書く |
| W3 | 未対応 | 学習・削除・同期とライブラリ生成は「未対応」の理由で失敗にする |

### LLM の接続先

| No | 機能 | 要件 |
|---|---|---|
| L1 | 確認用（echo） | キーなしで動き、質問をそのまま回答として返す。既定 |
| L2 | Azure OpenAI | エンドポイント・API キー・デプロイ名・API バージョンを環境変数で設定し、chat completions をストリーミングで呼ぶ |

- 接続先は環境変数で選ぶ。Azure OpenAI を選んで必要な値が足りなければ、起動時にエラーにする

## 非機能要件

- server-local のコードは変更しない。server-local がそのまま受け付ける応答・ストリームファイルの形式にする
- Docker（Linux）でビルド・起動できる。server-local と同じく root 以外のユーザーで動かす
- 認証キーを応答・ログに出さない（server-local の #252 と同じ考え方）
- ストリームファイルの書き込み先を、設定したディレクトリの中だけに制限できるようにする（任意のファイルに追記されないように）
- テスト・ruff check / format・mypy を通す

## スコープ外

- アダプタ（生成AI・検索・埋め込み）の移植と差し込み
- ワークフローの定義（サービス ID・アダプタ・設定の組み合わせ）の仕様
- 学習データの登録・削除・同期、ライブラリ生成（`createLibrary`）、ツール（web 検索・MCP）、添付ファイルの LLM への受け渡し
- セッションの永続化（再起動でセッションは消える）・複数プロセスでの共有
- ブラウザからの通しの確認（React に SECURE アシスタントのチャット画面がまだなく、ログインもできないため。08 を参照）
