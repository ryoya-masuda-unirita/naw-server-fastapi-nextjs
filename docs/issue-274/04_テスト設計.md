# 04_テスト設計

## テスト方針

- エミュレーター単体（API・ワークフロー・LLM の接続先・ストリームファイル・設定）を pytest で確かめる。Azure OpenAI は SDK のクライアントを偽物に差し替え、実際には呼ばない
- server-local の Waha! クライアントと SSE のアプリを、ASGI 経由でエミュレーターにつないで、チャットの往復とストリームファイル経由の途中経過を確かめる（server-local のコードは変更せず、エミュレーター側のテストから読み込む）
- execute の同期・非同期の両方で server-local が動くこと、非同期では同期 API が失敗しうること（02 の根拠）をテストで示す
- Docker（Linux）でビルド・起動し、HTTP で `startsession` が返ること、server-local のコンテナと組み合わせてチャットが通ることを確かめる
- ruff check / format、mypy を通す

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | セッション開始 | 正しい認証キー | セッション ID が返る |
| 2 | セッション開始 | 誤った認証キー | 401。本文に認証キーが含まれない |
| 3 | セッション終了 | 開始したセッション | `OK`。以降そのセッションは 404 |
| 4 | セッション終了 | ジョブ実行中 | ジョブが止まる |
| 5 | 存在しないセッション | 各 API | 404 |
| 6 | アップロード | 入力スロット | `OK`。同じスロットは上書き |
| 7 | アップロード | 出力スロット・未知のスロット | 400 |
| 8 | 実行前の結果 | execute 前 | `RUNNING` |
| 9 | チャット | 質問のみ（同期） | execute が `SUCCESS` を返し、outputfile が `answer`・`filepaths`・`references` の JSON |
| 10 | チャット | 実行中 | `RUNNING` |
| 11 | チャット | 非同期 | execute がすぐ `OK`、その後 `SUCCESS` |
| 12 | チャット | 実行中に再度 execute | 409 |
| 13 | チャット | 質問なし（削除サービスと同じ呼び方） | `FAILURE` で始まり、未対応の理由 |
| 14 | 学習・同期 | `splitLength`・`filepath` / `start`・`end` 付き | `FAILURE`（未対応） |
| 15 | ライブラリ生成 | `textdata` の `createLibrary` が true | `FAILURE`（未対応） |
| 16 | 履歴 | 履歴あり | 役割を小文字にして、質問の前に LLM へ渡る。役割なしは渡さない |
| 17 | 履歴 | JSON でない | `FAILURE` |
| 18 | LLM の失敗 | LLM が例外 | `FAILURE`。ストリームに `error` |
| 19 | ストリームファイル | 存在するファイル | 差分ごとに `text_delta`、最後に `completed` が 1 行形式で追記される |
| 20 | ストリームファイル | 存在しないファイル | 作られず、ジョブが `FAILURE` |
| 21 | ストリームファイル | 許可ディレクトリの外 | ジョブが `FAILURE` |
| 22 | ワークフローの選択 | サービス ID の登録あり | 登録したものが使われる（学習のパラメータより優先） |
| 23 | echo | 質問 | 数文字ずつ差分が返り、つなぐと質問と同じ |
| 24 | Azure OpenAI | 偽の SDK | デプロイ名・メッセージを渡してストリーミングで呼び、差分だけを返す |
| 25 | 設定 | `azure_openai` で必須値が足りない | 起動時（設定の検証）にエラー |
| 26 | 設定 | 認証キーが空 | エラー |
| 27 | server-local 往復 | WahaClient で startsession → upload → execute → result → download → endsession | 回答が得られ、セッションが破棄される |
| 28 | server-local 往復 | WahaClient で学習を実行 | 結果待ちで失敗（例外） |
| 29 | server-local SSE | NAW_COMPATIBLE（同期・非同期） | `text_delta`（回答）→ `message_stop` → `message_content`（status OK）。ストリームファイルに途中経過と `completed` が残る |
| 30 | server-local SSE | LEGACY_PASSTHROUGH | ストリームファイルの `text_delta` が複数回に分かれて中継され、つなぐと回答になる。最後に `completed` |
| 31 | server-local 同期 API | 同期・非同期 | 回答が返る |
| 32 | server-local 同期 API | 非同期で、LLM が結果待ちの上限より遅い | 失敗する（同期なら成功する） |
| 33 | server-local SSE | LLM が失敗 | `error` イベントで終わる |
| 34 | Docker | ビルド・起動 | `startsession` がセッション ID を返す |
| 35 | Docker | server-local のコンテナと組み合わせる | `/api/messages/content` で回答が返る |
