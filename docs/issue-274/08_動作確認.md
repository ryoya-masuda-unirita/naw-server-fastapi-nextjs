# 08_動作確認

**ブラウザ・実機での確認は行わず、自動テストと Docker（コマンド）での確認で代替した。** React（`frontend/`）には SECURE アシスタントのチャット（server-local へ直接送る処理）がまだなく、ログイン画面のテナント ID 入力欄も未移植でログインできないため、「ブラウザ → server-local → エミュレーター → LLM → 回答の表示」をブラウザで通すことはできない。代わりに、server-local のアプリ（ブラウザが呼ぶ `POST /api/messages/content`）を HTTP で呼び、SSE の応答を確かめた。

## 確認環境

- macOS（Apple Silicon）、Python 3.12.13、uv 0.11.21
- Docker 29.8.2（linux/aarch64）。イメージは `python:3.12-slim` ベース（linux/arm64）
- LLM は `echo`（Azure OpenAI は SDK を偽物に差し替えたテストのみ。実際の Azure OpenAI には接続していない）

## 確認手順

1. `cd waha-emulator && uv sync && uv run pytest -v`（エミュレーター単体と、server-local の `WahaClient`・アプリから呼ぶ結合テスト）
2. `uv run ruff check .`・`uv run ruff format --check .`・`uv run mypy`。pre-commit と同じ版の ruff（`uvx ruff@0.15.20`）でも確認
3. `docker build` → `docker run -e WAHA_AUTHKEY=docker-key -p 18091:8080` → `curl` で `startsession`
4. `waha-emulator/docker-compose.yml` と `server-local/docker-compose.yml` で両方を起動し（ポート 18091 / 18090、ストリームファイルのディレクトリを共有、server-local の `WAHA_URL=http://host.docker.internal:18091/`）、`curl` で server-local の `POST /api/messages/content`・`/content/stream` を呼ぶ
5. ホストで `uv run uvicorn waha_emulator.main:app_factory --factory --port 18092 --no-access-log` を起動し、`startsession` を呼ぶ
