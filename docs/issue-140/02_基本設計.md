# 02_基本設計

## 変更対象

- `backend/pyproject.toml` の `[tool.mypy]` セクション
- `warn_unused_ignores` を有効化した結果、不要と判明した `# type: ignore` コメント（テストコード）

## 画面 / API 変更概要

該当なし（mypy の設定整備のみで、画面・API の変更は行わない）。

## 影響範囲

- backend の型チェック運用（開発者がローカルで `uv run mypy app tests` を実行した際の出力範囲）
- 既存の実行時動作（API レスポンス、DB アクセス等）には一切影響しない
- CI には現時点で組み込まれていないため、CI の挙動に影響しない（#142 のスコープ）

## 移植方針

本Issueは移植作業ではなく、backend自体の型チェック運用整備。Issue #139（PR #143、未マージ）の調査結果を踏まえ、以下の方針で `[tool.mypy]` を整備する。

- **対象範囲の明示**: `files = ["app", "tests"]` を追加し、引数なしの `uv run mypy` でも `uv run mypy app tests` と同じ対象になるようにする
- **初期導入で除外するモジュール**: `docs/issue-139/03_詳細設計.md` の分類に基づき、SQLModel/SQLAlchemy の型推論に起因する構造的エラー（`Model.field == value` のような比較式を `.where()`/`.join()`/`.in_()` 等に渡す書き方が mypy 上は型エラーになる問題）が集中する以下のモジュールを `ignore_errors = true` で除外する
  - `app.repositories.*`（423件）
  - `app.services.user_service`（3件）
  - `app.services.user_import_service`（2件、2箇所×2エラーで実質4件相当だが調査時点の数え方に合わせる）
  - `app.core.credit_quota`（3件）
  - 除外理由はコメントで `pyproject.toml` 上に明記し、解消方針の判断は #141 に委ねる
- **残す2件のエラー**: `app/services/index_service.py:594` と `app/services/message_service.py:1028` は上記の構造的問題とは異なり、コード側のOptional/None扱いに起因する実バグ疑いのため、除外せず可視化したまま残す（#141 で対応要否を判断してもらう）
- **警告設定**: `warn_unused_ignores = true`（不要な `# type: ignore` の検出）、`warn_redundant_casts = true`（不要な `cast()` の検出）を追加する
  - 追加した結果、`tests/unit/test_azure_cost_client.py` に既に不要になっていた `# type: ignore[arg-type]` が1件検出されたため、本Issueの中で削除する
- **missing imports の扱い**: 現状 `uv run mypy app tests` では `import-untyped` / `import-not-found` 系のエラーは0件（`types-passlib` 等、必要なスタブは dev dependency に含まれている）。プロジェクト全体を緩める `ignore_missing_imports = true` は設定しない。将来スタブのないライブラリを追加する場合は、`[[tool.mypy.overrides]]` でモジュール単位・理由付きで `ignore_missing_imports = true` を追加する方針を docs に残す（`03_詳細設計.md` に記載）
- **標準実行コマンド**: `cd backend && uv run mypy app tests` を標準コマンドとして `03_詳細設計.md` に記録する
