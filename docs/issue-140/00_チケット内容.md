# backend mypy設定を段階導入向けに整備する

## 概要

backend の mypy 設定を段階導入しやすい形に整備する。

## 説明

現状の `backend/pyproject.toml` には `plugins = ["pydantic.mypy"]` のみがあり、対象範囲、除外範囲、警告レベル、missing imports の扱いなどが明確ではない。安定して運用するには、最初に通す範囲を決め、エラーを増やさない設定へ整える必要がある。

対応内容（想定）:

- mypy の対象範囲を明示する
- 初期導入で扱わない範囲があれば理由付きで除外設定する
- `warn_unused_ignores` など、運用に有効な警告設定を検討する
- 外部ライブラリの missing stubs / missing imports の扱いを整理する
- `uv run mypy ...` の標準実行コマンドを docs に残す

受け入れ条件:

- `backend/pyproject.toml` の mypy 設定方針が明確になっている
- 決めた対象範囲で mypy が実行できる
- 除外や ignore を入れる場合は理由が docs に記録されている

スコープ外:

- backend 全体の型エラー完全解消
- CI 必須化
- strict mode の全面適用
