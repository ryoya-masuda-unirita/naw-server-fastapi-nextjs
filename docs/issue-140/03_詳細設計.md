## 変更後の `[tool.mypy]`

```toml
[tool.mypy]
# 標準実行コマンド: `cd backend && uv run mypy app tests`
# `files` も明示しておくことで、引数なしの `uv run mypy` でも同じ対象範囲になる。
files = ["app", "tests"]
python_version = "3.12"
plugins = ["pydantic.mypy"]
# ignore（無視）を付けたが実際にはエラーが出ていない箇所を検出する。
# 型エラーが解消された後に不要な ignore が残るのを防ぐための運用設定。
warn_unused_ignores = true
# 不要な cast() を検出する。
warn_redundant_casts = true

# --- 初期導入時点では対象外にするモジュール ---
# 理由: docs/issue-139/03_詳細設計.md で調査済みの通り、SQLModel のモデル属性は
# mypy 上では宣言した Python 型（str/datetime/UUID/bool 等）としてしか認識されず、
# `Model.field == value` のような SQLAlchemy 的な比較式を `.where()` / `.join()` /
# `.in_()` / `.desc()` / `.asc()` / `.is_()` に渡す書き方が、実行時には正しく動作する
# にもかかわらず mypy 上は型エラーになる（SQLModel に InstrumentedAttribute を認識
# させる mypy プラグインが存在しないための構造的な限界）。
# リポジトリ層のクエリ構築パターンを変えない限り根本解消できないため、初期導入では
# 該当モジュールを除外し、無理に `# type: ignore` を大量に付けない方針とする。
# 除外の要否・解消方針は #141（エラー修正）で改めて判断する。
[[tool.mypy.overrides]]
module = [
    "app.repositories.*",
    "app.services.user_service",
    "app.services.user_import_service",
    "app.core.credit_quota",
]
ignore_errors = true
```

## 除外モジュールの根拠（`docs/issue-139/03_詳細設計.md` の集計に基づく）

| モジュール | 除外前エラー数 | 内容 |
|---|---|---|
| `app.repositories.*`（34ファイル） | 423 | SQLModel/SQLAlchemy 型推論の構造的問題（`arg-type`/`attr-defined`/`union-attr`/`call-overload`/`assignment`/`dict-item`/`operator`） |
| `app.services.user_service` | 3 | 同上（`where()` への bool 式渡し） |
| `app.services.user_import_service` | 2箇所（4エラー） | 同上（`where()` への bool 式渡し・`.in_()` 呼び出し） |
| `app.core.credit_quota` | 3 | 同上（`where()` への bool 式渡し） |

除外後に mypy 上へ残るのは以下の2件のみ（`docs/issue-139/03_詳細設計.md` で「実バグ疑い」に分類されたもの）。

| ファイル:行 | 内容 |
|---|---|
| `app/services/index_service.py:594` | `room_id`（`str \| None`）を `str` 引数へそのまま渡している |
| `app/services/message_service.py:1028` | `None` を `MessageContentResponse` 型変数へ代入している |

この2件は本Issueのスコープ外（backend全体の型エラー完全解消は対象外）のため修正しないが、除外対象にせず可視化したまま残すことで、#141 が最優先で対応要否を判断できる状態にする。

## missing imports / missing stubs の扱い方針

- 現状 `uv run mypy app tests` では `import-untyped` / `import-not-found` 系のエラーは検出されていない（`types-passlib` 等、必要な型スタブは既に `dependency-groups.dev` に含まれている）
- 方針: プロジェクト全体を緩める `ignore_missing_imports = true`（グローバル設定）は使わない
- 将来、型スタブを持たない外部ライブラリを追加してエラーが出た場合は、以下のようにモジュール単位・理由付きで `[[tool.mypy.overrides]]` を追加する

```toml
# 例: some_untyped_lib に型スタブが存在しないため、モジュール単位で無視する
[[tool.mypy.overrides]]
module = "some_untyped_lib.*"
ignore_missing_imports = true
```

## `warn_unused_ignores` 導入に伴う既存コードの修正

```python
)
```
