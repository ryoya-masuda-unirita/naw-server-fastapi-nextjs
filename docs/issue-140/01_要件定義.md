# 01_要件定義

## 背景

Issue #139 の現状調査（PR #143、未マージ）により、`uv run mypy app tests` は435件のエラー（37ファイル）を検出し、その大半（423件）が `app/repositories` に集中していること、原因はほぼ全てが SQLModel/SQLAlchemy の型推論に起因する構造的な問題であることが判明した。あわせて `app/services` 配下に Optional/None 安全性に関する実バグ疑いが2件見つかっている。

このまま mypy を運用しようとすると、構造的エラーに埋もれて実バグ疑いのエラーに気付けない、対象範囲・除外範囲・警告方針が定まっていないため個々人が場当たり的に `# type: ignore` を付けてしまう、といった問題が起きる。段階導入に耐えられる設定へ整備する必要がある。

## 機能要件

- `backend/pyproject.toml` の `[tool.mypy]` に、対象範囲（`files`）を明示する
- SQLModel/SQLAlchemy の型推論に起因する構造的エラーが集中するモジュールを、理由をコメントで明記した上で初期導入の対象から除外する
  - 除外は「エラーを消すための一時しのぎ」ではなく、後続 Issue（#141）で解消方針を判断するまでの暫定措置であることをコメント・docsの両方に明記する
- `warn_unused_ignores`（不要な `# type: ignore` の検出）など、運用に有効な mypy 設定を追加する
- 外部ライブラリの missing stubs / missing imports の扱い方針を整理し、docsに記録する（現状は import 関連エラーが0件のため、設定変更が必要かどうかも含めて調査する）
- `uv run mypy app tests` を標準実行コマンドとして docs に残す

## 非機能要件

- 既存のテスト（`pytest tests/unit`）に影響を与えないこと
- 除外設定はモジュール単位のオーバーライド（`[[tool.mypy.overrides]]`）で行い、範囲を最小限にすること（プロジェクト全体を緩めるような設定はしない）

## スコープ外

- backend 全体の型エラー完全解消（Issue #139 で見つかった実バグ疑い2件の修正を含む。対応要否の判断・修正は #141 で行う）
- CI への mypy 組み込み（#142 で対応）
- strict mode の全面適用
