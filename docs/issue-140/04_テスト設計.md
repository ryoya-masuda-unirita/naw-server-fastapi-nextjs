# 04_テスト設計

## テスト方針

本Issueは mypy 設定変更が中心のため、以下の2種類で確認する。

- `uv run mypy app tests` の実行結果が設計通りになっていること（対象範囲・除外設定・残るエラー件数）
- 既存の自動テスト（`pytest tests/unit`）に回帰がないこと（設定変更・`# type: ignore` 削除がテストの実行結果に影響しないことの確認）

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | mypy 対象範囲 | `uv run mypy app tests` を実行する | 195 source files がチェックされる（変更前と同じ対象規模） |
| 2 | 除外設定の効果 | `app/repositories`・`app/services/user_service.py`・`app/services/user_import_service.py`・`app/core/credit_quota.py` に起因する SQLModel 構造的エラーが表示されないこと | 除外前 435件 → 除外後 2件まで減少する |
| 3 | 実バグ疑いの可視化 | `app/services/index_service.py:594` と `app/services/message_service.py:1028` のエラーが除外されず残ること | mypy 出力にこの2件のエラーが表示される |
| 4 | `warn_unused_ignores` の効果 | 既存コードに不要な `# type: ignore` がないか確認する | `tests/unit/test_azure_cost_client.py` の不要な ignore が検出され、削除後に警告が消える |
| 5 | 既存テストの非回帰 | `uv run pytest tests/unit -q` を実行する | 変更前と同じ件数（249件）が全件成功する |
