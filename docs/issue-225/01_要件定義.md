# 01_要件定義

## 背景

- 移植元（Spring Boot）では、一覧 API の並べ替え指定を Spring Data の Pageable がまとめて解釈している。こちらは API ごとに文字列を手で分解しており、次の差がある
  - 方向（`asc` / `desc`）の大文字小文字を区別する API と、区別しない API が混在している。`DESC` を指定すると昇順になる API がある
  - 並べ替え指定を複数並べる書き方（例: `sort=name,asc&sort=updatedAt,desc`）に対応していない
  - 同じ値の行の並びを決める最終キーがない API がある。そのためページをまたいで行が重複・欠落しうる。昇順と降順を切り替えても、同値の行の並びが反転しない
- ユーザー一覧で、権限の絞り込みに未知の値を指定するとサーバー内部エラー（500）になる。移植元は 400 を返す
- 移植元は、チーム所属ユーザー一覧から SYSTEM 権限（外部連携用の内部ユーザー）を除外している。こちらは除外せずに表示してしまう

## 機能要件

### 1. 並べ替え指定の解釈を共通化する

- 移植元（Spring Data の Pageable）と同じ規則で並べ替え指定を解釈する共通処理を用意する。移植元で Pageable の並べ替えを受けている一覧 API に適用する。規則は次のとおり
  - 1 つの指定は「キー」または「キー,方向」の形式。「キー1,キー2,方向」のように、複数のキーに同じ方向を付けられる
  - 方向は `asc` / `desc` を大文字小文字を区別せずに解釈する。省略時は昇順
  - 最後の要素を方向として解釈できない場合は、すべての要素をキーとして昇順で扱う
  - 並べ替え指定は複数並べられる。指定した順に優先する
  - 空の要素と前後の空白は無視する
  - 末尾の `ignorecase` は読み飛ばす。方向・キーと取り違えないようにするため。大文字小文字の扱いは、各 API の列の定義に従う
  - 解釈した結果、キーが 1 つもない場合（空文字の指定など）は、その API の既定の並び順にする
- 各 API の既定の並び順・受け付けるキーは変えない
- 未知のキーは読み飛ばす（移植元と同じ）。既知のキーが 1 つもない場合は、従来どおり先頭の指定の方向で既定の列に読み替える。これで単一指定のときの従来の挙動を保つ
- 並べ替えの最後に、行を一意に決めるキー（ID）を加える
  - 方向は先頭の並べ替えキーと同じにする。これで降順が昇順の完全な逆順になる。#172・#181 で決めた規則に揃える
  - ただし、#170（管理者向けテンプレート一覧）・#175（学習データファイル一覧）で入れた「常に ID 昇順」は維持する。既存の挙動を変えないため
- 利用クレジット順（`totalCredits`）は、移植元と同様に、指定のいずれかに含まれていれば利用クレジット順として扱う。`includeUsage` を必須とする検証も同様

### 2. ユーザー一覧の不正な権限指定を 400 にする

- 権限の絞り込みに `USER` / `ADMIN` / `SYSTEM` 以外を指定した場合は 400 を返す（移植元も 400）
- 大文字小文字は区別する（移植元と同じ。`admin` は不正値）
- 空文字・空白のみの指定は、絞り込みなしとして扱う（移植元と同じ）
- エラー応答の形式は既存 API と同じ形にする（学習データファイル一覧で不正なステータスを指定したときなど）

### 3. チーム所属ユーザー一覧から SYSTEM 権限のユーザーを除外する

- チーム所属ユーザー一覧の検索結果と総件数から、SYSTEM 権限のユーザーを除外する（移植元と同じ）

## 非機能要件

- 一覧取得のクエリ回数を増やさない（並べ替えは SQL の並び順指定で行う）
- 既存の自動テストがすべて通ること

## スコープ外

- 移植元で Pageable の並べ替えを受けていない一覧 API。ルーム一覧、フィードバック系、ライブラリ一覧、トークン使用量一覧などは、独自のパラメータで並べ替えを受けている
- 並べ替え指定を受けていない一覧 API（ライブラリタグ一覧など）に、新たにキーを受け付けさせること
- `ignorecase` による、大文字小文字を区別しない並べ替え。指定は読み飛ばすだけにする（フロントエンドは送らない）
- 既知のキーが 1 つもない場合に、移植元と同じくエラー・並べ替えなしにすること。既存の挙動を変えないため、従来どおり既定の列に読み替える
- 表示名・インデックス名などを、大文字小文字を区別せずに並べ替えること（チーム所属ユーザー一覧以外）
- チーム所属ユーザー一覧の権限の絞り込みの差分。移植元は大文字小文字を区別せず、未知の値では 0 件を返すが、Issue の指摘対象外のため扱わない（PR で触れる）
- エラー応答の形式・バリデーションエラーのステータスコードの統一（別途検討中）
