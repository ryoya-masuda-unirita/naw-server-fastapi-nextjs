# 04_テスト設計

## テスト方針

- 並べ替え指定の解釈は、共通処理の単体テストで Spring Data の規則を網羅する
- 各一覧 API は、結合テスト（テスト用のインメモリ DB）で「大文字の方向」「同値の行の並びが昇順・降順で反転する」「複数指定」を代表して確認する
- 既存の並べ替えテスト（#170・#172・#175・#181）がそのまま通ることで、既定の並び順・受け付けるキーが変わっていないことを確認する
- ブラウザ・実機での確認は行わず、自動テストで代替する

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 解釈: 基本 | 「キー,方向」を 1 つ指定 | キーと方向に分かれる |
| 2 | 解釈: 方向の大文字小文字 | `DESC` / `Asc` | 降順 / 昇順 |
| 3 | 解釈: 方向の省略 | キーだけ | 昇順 |
| 4 | 解釈: 複数キー＋方向 | 「キー1,キー2,方向」 | 両キーにその方向 |
| 5 | 解釈: 方向として解釈できない末尾 | 「キー,foo」 | 両方キー・昇順 |
| 6 | 解釈: 複数指定 | 2 つの指定 | 指定順に並ぶ |
| 7 | 解釈: 空・空白 | 空文字、空要素、前後の空白、方向のみ | 空要素を無視し、キーが残らなければ空 |
| 8 | 既定値 | キーが残らない指定 | API の既定の並び順 |
| 9 | 並び順の組み立て | 既知・未知のキー | 対応する列 / 読み替え先の列で並ぶ |
| 10 | 最終キー | 先頭が降順 | 最終キーも降順（固定昇順の指定時は昇順） |
| 11 | 利用クレジット順の判定 | 複数指定のいずれかに利用クレジット | 利用クレジット順と判定する |
| 12 | アシスタント一覧 | 同名・大文字の方向・別名キー | 同値が反転、`DESC` で降順、別名で種別順 |
| 13 | チーム一覧（管理者・全件） | 同名・大文字の方向 | 同値が反転、`DESC` で降順 |
| 14 | チーム所属アシスタント一覧 | 同じ追加日時・大文字の方向 | 同値が反転、`DESC` で降順 |
| 15 | チーム所属テンプレート一覧 | 同じ追加日時・大文字の方向 | 同値が反転、`DESC` で降順 |
| 16 | インデックス一覧 | 同名・大文字の方向 | 同値が反転、`DESC` で降順 |
| 17 | 複数指定 | 第 1 キーが同値で第 2 キーが異なる | 第 2 キーで並ぶ |
| 18 | 空の指定 | `sort=` | 既定の並び順 |
| 19 | 一般向けテンプレート一覧 | 同じ更新日時 | ID の降順で並ぶ |
| 20 | ユーザー一覧: 不正な権限 | 未知の値 / 小文字 | 400、既存の 400 と同じ形式 |
| 21 | ユーザー一覧: 空白の権限 | 空白のみ | 絞り込みなしで 200 |
| 22 | チーム所属ユーザー一覧: SYSTEM 除外 | SYSTEM 権限のユーザーが所属 | 一覧・総件数に含まれない |
| 23 | 既存挙動の維持 | 既存の並べ替えテスト | すべて通る |
