# 一覧APIの並べ替え・絞り込みを移植元に揃える（ソート解析の共通化・不正roleで500・チーム所属一覧のSYSTEM除外）

## 概要

#172・#181 の調査で判明した一覧 API の残課題をまとめて直す。

## 説明

1. ユーザー一覧・チーム所属一覧以外の一覧 API にも、同じ値の行の並びを決める第2キーがない・ソート指定（`sort={キー},{asc|desc}`）の解析が API ごとにばらばら、という問題が残っている。Spring の Pageable 相当の共通ユーティリティにまとめ、各一覧 API に適用する。
2. ユーザー一覧で `role=foo` など不正な値を指定すると 500 になる（移植元の挙動に合わせて 400 等にする）。
3. 移植元はチーム所属ユーザー一覧から SYSTEM 権限のユーザーを除外しているが、こちらは除外していない。

## その他

- 参考: #170（テンプレート一覧の sort 対応、PR #205）、#172（ユーザー一覧、PR #206）、#175（学習データファイル一覧、PR #204）、#181（チーム所属一覧、PR #212）
- 既存 API の挙動（既定の並び順、受け付けるキー）は変えない
- エラー応答の形式（`detail` / `message`）やバリデーションエラーのステータスコード（422 / 400）は別途検討中のため、本 Issue では新たに決めず既存 API と同じ形にする
