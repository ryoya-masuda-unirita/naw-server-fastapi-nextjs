# 01_要件定義

## 背景

Spring Boot版(naw-server)には、管理者がテナント内のLLMトークン消費量を確認するためのAPIが存在する。FastAPI版(backend/)には同等機能が未移植であり、管理ダッシュボードでトークン消費量を確認できない状態にある。

## 機能要件

- 管理者（テナント管理者、またはいずれかのグループの管理者）が、指定した期間（`from`〜`to`）のトークン消費量一覧をページングで取得できる。
- 一覧は `userId` を指定して特定ユーザーの消費量に絞り込める。
- 一覧は `createdAt` または `totalTokens` を軸に昇順・降順を指定して並び替えできる。
- 管理者が、指定した期間のトークン消費量サマリ（トークン数・クレジット数の合計）を取得できる。サマリも `userId` で絞り込める。
- 期間指定は必須。`from <= to` であること、期間が31日以内であることをバリデーションする。
- `userId` を指定した場合、そのユーザーがテナント内に実在することを確認し、存在しなければ404を返す。
- テナント分離を行い、他テナントのデータが含まれないこと。

## 非機能要件

- 一覧・サマリともに集計はDBクエリで行い、N+1問題を発生させないこと。
- レスポンスのフィールド名・構造は移植元Spring Boot版と同一（キャメルケース、`contents`/`totalCount`/`hasNext`等）とし、既存フロントエンドとの互換性を維持する。

## スコープ外

- `token_usages` テーブルへのデータ投入処理（チャット送信・RAG・埋め込み機能側でのINSERT）は別Issueのスコープであり、本Issueでは対応しない。
- PostgreSQLのRLS（Row Level Security）は、移植先FastAPI全体で未導入のため、本Issueでも導入しない（既存テーブル群同様、アプリケーション側の`tenant_id`フィルタで分離する）。
- フロントエンド（React/Angular）側の画面実装は対象外。
