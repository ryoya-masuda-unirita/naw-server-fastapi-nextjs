# 03_詳細設計

## 実装対象ファイル

### モデル

`backend/app/models/token_usage.py`

```python
class TokenUsage(SQLModel, table=True):
    __tablename__ = "token_usages"

    id: str  # PK, max_length=32
    tenant_id: str  # FK -> tenants.id, ON DELETE CASCADE
    user_id: uuid.UUID | None  # FK制約なし（移植元同様、参照整合性はDB制約で強制しない）
    room_id: str | None
    message_id: str | None  # FK -> messages.id, ON DELETE SET NULL
    endpoint_type: str | None
    model: str
    input_tokens: int  # default 0
    output_tokens: int  # default 0
    input_credits: int  # bigint, default 0
    output_credits: int  # bigint, default 0
    embedding_tokens: int  # default 0
    embedding_credits: int  # bigint, default 0
    total_tokens: int  # DB生成列 GENERATED ALWAYS AS (input_tokens+output_tokens+embedding_tokens) STORED
    created_at: datetime  # timestamptz, server_default now()
```

- インデックス: `idx_token_usages_tenant_id`, `idx_token_usages_user_id`, `idx_token_usages_tenant_id_created_at`（複合）

### Migration

### スキーマ

`backend/app/schemas/token_usage.py`

- `TokenUsageListRequest`（Query paramsから組み立てる想定のため実体は router 側の関数引数 + バリデーション関数、またはBaseModelで表現）
  - `from_`（エイリアス`from`）, `to`, `user_id`（エイリアス`userId`）, `page`, `size`, `order_by`（エイリアス`orderBy`）, `reverse`
  - `@field_validator`で `from <= to`、期間31日以内、`orderBy`が`createdAt`|`totalTokens`のいずれかをチェック
- `TokenUsageSummaryRequest`
  - `from_`, `to`, `user_id`
  - 同様に `from <= to`・31日以内をチェック
- `TokenUsageItemResponse`
  - `id, userId, messageId, model, inputTokens, outputTokens, embeddingTokens, totalTokens, inputCredits, outputCredits, embeddingCredits, totalCredits, createdAt`
  - `totalCredits`は`from_token_usage()`ファクトリメソッド内で計算
- `TokenUsageListResponse`
  - `contents: list[TokenUsageItemResponse], totalCount: int, hasNext: bool`
- `TokenUsageSummaryResponse`
  - `inputTokens, outputTokens, embeddingTokens, totalTokens, inputCredits, outputCredits, embeddingCredits, totalCredits`

### リポジトリ

`backend/app/repositories/token_usage_repository.py`

- `find_page(tenant_id, from_, to, user_id, page, size, order_by, reverse, session) -> tuple[list[TokenUsage], int]`
  - `created_at`が`[from_, to]`区間、`user_id`指定時は絞り込み
  - `order_by`でホワイトリスト解決（`created_at`|`total_tokens`カラム）、`reverse`でasc/desc
  - `offset(page*size).limit(size)` + `count()`で総件数取得
- `summarize(tenant_id, from_, to, user_id, session) -> TokenUsageSummary`（DTO: input/output/embedding tokensとcreditsの合計を1クエリで集計。`func.sum`を使用しN+1を避ける）

### サービス

`backend/app/services/token_usage_service.py`

- `TokenUsageService.list_token_usages(...)`: `user_id`指定時は`UserRepository.find_by_id_and_tenant_id`で存在確認（存在しなければ404）。リポジトリから一覧取得し`TokenUsageListResponse`を構築（`hasNext = (page+1)*size < total_count`）。
- `TokenUsageService.get_summary(...)`: 同様にuser_id存在確認後、リポジトリのsummarize結果から`TokenUsageSummaryResponse`を構築。

### ルーター

`backend/app/routers/token_usage.py`

- `admin_router = APIRouter(prefix="/api/admin/token-usages", tags=["admin-token-usages"])`
- `GET ""`: 一覧
- `GET "/summary"`: サマリ
- 両方 `Depends(require_admin_or_group_admin)` + `Depends(get_verified_tenant_id)`
