# 01_要件定義

## 背景

#284 でチャット画面の中核を移した。入力欄の添付、ヘッダーの共有・評価、サイドバーのチャット検索は、口だけ用意して中身が空（または仮ダイアログ）になっている。これを移植元と同じ見た目・操作で埋める。

## 機能要件

1. 添付（`chat-input` + `shared/components/file*`）
   - 画像・PDF・Office・テキスト系だけを受け付ける（`CHAT_ATTACHMENT_ACCEPT`・`isAllowedChatAttachment`）。許可外のファイルは黙って捨てる
   - 追加の手段: 入力欄へのドロップ（＋メニューの「画像またはファイルを添付」は #286 が、ドロップ領域の input を開く）
   - 添付チップ列: 画像はサムネイル（`FileImageChip`）、それ以外は `FileChip`。×で外せる
   - 送信すると添付は空になる（#284 の `ChatInput` が行う）
2. 評価（`chat-rating-dialog`・`chat-message-footer`）
   - ヘッダーの「評価」でダイアログを開く。★5〜★1 のラジオ。ルームに評価があれば初期選択にする
   - 送信で `POST /api/rooms/{roomId}/feedback`。送信中は確認ボタンがローディング。成功したら閉じる。失敗したら開いたまま
   - メッセージ単位の評価（フッターの 👍👎）は #284 で移植済み。`useChatActions().rateMessage` につながっていることを確認する
3. 検索（`chat-search-modal`）
   - サイドバーの「チャットを検索」で開くダイアログ。入力を 300ms デバウンスし、`GET /api/rooms?name=&page=&size=20` で検索
   - 結果は日付・ルーム名・最終メッセージ。クリックでそのルームへ移動（ダイアログを閉じる）。0 件は「表示するデータがありません」。ページ送りあり
4. 共有（`chat-share-dialog`・`shares.service`・`teams.service`）
   - ヘッダーの「共有」でダイアログを開く。共有先チーム（`GET /api/groups`）を複数選択。選ばないと「共有」を押せない
   - 共有で `POST /api/shares`（`{data}` 包み）。成功してもダイアログは閉じず、共有リンクのコピー・共有解除が出る
   - 共有解除は確認ダイアログを経て `DELETE /api/shares/{shareId}`。成功で共有ダイアログも閉じる。失敗でも閉じる
   - 読み取り専用（共有ルームを開いた側）はチーム選択を無効にし、共有ボタンを出さない
   - `resolveShareAccess`（`GET /api/shares/{shareId}/access`）も移す（共有閲覧画面は #288）
5. 状態
   - chat-store に添付（`ChatService.attachedFiles`）と共有ルームの文脈（`sharedRoomContext`・`openSharedRoom`）を足す

## 非機能要件

- 見た目・文言は移植元のクラス・i18n キーをそのまま使う
- 他の Issue が触る `chat-window.tsx`・`chat-input.tsx` への変更は最小限にする

## スコープ外

- ＋メニュー本体・アシスタント選択・テンプレート・メンション（#286）。この Issue はドロップ領域の `input[type=file]` までを用意する
- 共有閲覧画面（`/chat/share/:shareId`）・ビューワー（#288）
