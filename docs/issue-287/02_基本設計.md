# 02_基本設計

## 変更対象

- frontend のみ（`backend/` は変更しない）

## 画面 / API 変更概要

- 画面: 入力欄の添付、ヘッダーの評価・共有ダイアログ、サイドバーのチャット検索ダイアログ（`chat-search-modal.tsx` の仮ファイルを本物にする）
- 利用する API: `POST /api/rooms/{roomId}/feedback`、`GET /api/rooms`（検索）、`GET /api/groups`、`POST /api/shares`、`DELETE /api/shares/{shareId}`、`GET /api/shares/{shareId}/access`。いずれも backend 実装済み

### 既存ファイルの変更（最小限）

- `chat-window.tsx`: `useChatRoomDialogs` を呼び、ヘッダーの `onShareClick`・`onLikeClick` の既定にする。入力欄の `inputSlots` の既定に `chatAttachmentSlots` を足す（ページが渡した値が優先）。ダイアログを描画する。`ChatInput` は変更しない
- `chat-store.ts`: 添付と共有ルームの文脈を追記
- `components/shared/dialog.tsx`: `autoFocus` を足した（共有ダイアログは移植元が `autoFocus: false`。既定の自動フォーカスだと先頭の ComboboxMulti が勝手に開く）。既定は従来どおり
- `README.md`（`features/chat`）: 口の担当を更新

### 意図的な差分

1. 添付ファイルの `<input type="file">` は、移植元と同じくドロップ領域（`renderDropzone`）の中に置く。＋メニューの項目からは `id="chat-file-upload"` の input を `click()` する（移植元は `viewChild`）。画面に入力欄は 1 つだけなので衝突しない
2. 検索は、入力が続いたときに遅れて届いた前の検索の応答で結果を上書きしないよう、連番で古い応答を捨てる（移植元にはない）。失敗したら結果を空にして `console.error` に出す（api-client の共通エラートーストが出る）
3. `SharesService.shareId`（共有ダイアログが書くだけで読まれない signal）は持たない
4. 共有ダイアログのチーム選択は、ルームが変わったときに「描画中の状態調整」で入れ直す（移植元の `effect`）
