# 04_テスト設計

## テスト方針

- `models`・`repositories`・`services`・`routers`を新規追加するため、Router層は`tests/integration/`（実DB接続）で一括して検証する
- Group紐づけによるフィルタリング・重複排除・未所属時の空配列返却を重点的に確認する

## テストケース一覧

### `GET /api/assistants`

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | ユーザーが所属するGroupに紐づくアシスタントが1件 | そのアシスタントが1件返る |
| 2 | ユーザーがどのGroupにも所属していない | 空配列が返る |
| 3 | ユーザーが2つのGroupに所属し、両方に同じアシスタントが紐づく | 重複排除され1件のみ返る |
| 4 | ユーザーが所属しないGroupに紐づくアシスタントが存在する | そのアシスタントは含まれない |
| 5 | レスポンス形式 | `endpoints=[]`・`category=null`・`categories=[]`であること |
| 6 | 未認証 | 401 |

## 既存テストへの影響確認

- 既存の認証・ユーザー管理・グループ管理テストへの影響はない（新規ファイル追加のみ）
- 全体テスト（`pytest`）が回帰なく通ることを確認する
