# 01_要件定義

## 背景

issue-20の動作確認で `GET /api/assistants` が404であることを確認していた。issue-24でチーム（Group）管理APIを実装したことで、Group紐づけによるアシスタント一覧のフィルタリングが可能になった。

移植元のAssistantドメインを調査した結果、以下の依存関係があることが判明した。

- `assistants`（本体）
- `groups_assistants`（Group⇔Assistant紐付け中間テーブル）
- `assistants_endpoints`・`tenant_endpoints`（AI接続先情報。APIキー等の機微情報を扱う別ドメイン）
- `assistant_categories`・`assistant_category_mappings`（カテゴリ機能）
- `ai_models`（管理者向けAIモデル選択肢取得専用）

このうち `assistants_endpoints`・`tenant_endpoints`・カテゴリ関連は独立した別ドメインであり、特に `tenant_endpoints` はAPIキー等の機微情報を扱うため別チケットとして慎重に設計する。`ai_models` は一覧APIのレスポンス生成に一切関与しないことを移植元コードで確認済みのため対象外とする。

`frontend-angular`のチャット機能側の実装（`AssistantsService`・`parseAssistantsListResponse`）を確認した結果、レスポンスが生の配列であること、`category`/`categories`/`endpoints`が欠損していても安全にフォールバックする実装になっていることを確認した。最小スコープでの実装がそのまま利用可能である。

## 機能要件

- `GET /api/assistants`：ログインユーザーが所属するGroupに紐づくアシスタント一覧を取得する
  - 認証必須（`get_current_user`）。ロール不問（一般ユーザーも利用可能）
  - ユーザーが所属するGroup（`groups_users`）に紐づくGroup（`groups_assistants`経由）のAssistantのみを対象とする
  - 同一Assistantが複数のGroup経由で見える場合も重複排除する
  - レスポンスは配列（ページネーションなし。移植元も配列を直接返す仕様）
  - `endpoints`は常に空配列、`category`はnull、`categories`は空配列で返す（今回のスコープでは接続先・カテゴリ情報を持たないため）

## 非機能要件

- 既存の`backend/.claude/CLAUDE.md`のレイヤー構成（routers/services/repositories/models）に従う
- AssistantIDは既存のGroup同様、UUID（ハイフンなし32文字hex）で生成する（今回のスコープでは作成APIは実装しないため、シードデータ投入時のみ使用）
- 動作確認のため、`backend/seed.sql`にアシスタント・グループ紐付けのシードデータを追加する

## スコープ外

- `assistants_endpoints`・`tenant_endpoints`（AI接続先・APIキー管理。別チケットで設計する）
- `assistant_categories`・`assistant_category_mappings`（カテゴリ機能）
- `ai_models`（管理者向けAIモデル一覧取得）
- 管理者向けアシスタントCRUD（作成・更新・削除）
- `frontend`（React）側の対応（当面不問方針のため）
