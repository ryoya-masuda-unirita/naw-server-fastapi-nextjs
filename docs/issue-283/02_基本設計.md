# 02_基本設計

## 変更対象

- frontend のみ（`backend/` は変更しない）
- 部品は `frontend/.claude/CLAUDE.md` のディレクトリ構成に置く。使い方は `frontend/src/features/chat/README.md`（ユーザー指定の場所。このディレクトリには README だけを置く）

## 画面 / API 変更概要

- 画面の追加・変更なし
- 利用する API: `GET /api/messages`・`POST /api/messages`・`POST /api/messages/contents`・`POST /api/messages/content`（SSE）・`DELETE /api/messages/{id}`・`POST /api/messages/{id}/feedback`、`/api/rooms` 系、`GET /api/assistants`、`GET /api/auth`（SECURE のトークン）
- 追加ライブラリ: marked・echarts・mermaid（移植元の版）、DOMPurify（移植元にない。下記）

## 影響範囲

- `components/shared/README.md` に MarkdownView の使い方を追記
- api-client に `omitTenantId` オプションを追加（既存の挙動は変えない）
- 既存の画面・ルート・i18n・CSS への変更なし（`.chart-block`・`.chat-message-bubble`・`.viewer-markdown` は `index.css` に移植済み）

## 移植方針

| 移植元 | 移植先 | 方針 |
|---|---|---|
| `<markdown>`（ngx-markdown）| `MarkdownView` + `markdown-render.ts` | marked の既定設定で描画し、`trimIndentation` と mermaid の `<div class="mermaid">` への差し替えまで ngx-markdown 21.3.0 の実装に揃える |
| `ChartBlockDirective`・`chart-block.helpers`・`echarts.setup` | `chart-blocks.ts`・`lib/utils/chart-block.ts`・`echarts-setup.ts` | ロジック・オプション値をそのまま移植。directive の `ready` 購読は、本文（HTML）が変わったときの effect に置き換え |
| `parseSseChunk` | `lib/utils/sse-parser.ts` | そのまま |
| `MessageContentStreamService` | `lib/chat/message-content-stream.ts` | `fetch` 直呼びを `apiClient.stream` に置き換え（`target` で接続先を切り替え） |
| `MessageService`・`RoomsService` | `store/messages-store.ts`・`store/rooms-store.ts`（Zustand） | 状態と操作を 1 つにまとめる（移植元が signal + service のため）。query cache が要る部分は `hooks/use-chat-actions.ts` |
| `MessageContentsApiService`・`features/chat/utils/*`・`core/utils/*` | `lib/chat/*`・`lib/utils/*` | そのまま移植 |
| `AssistantsService` | `hooks/use-assistants.ts` | `useQuery`（query key `['assistants']`） |

### 意図的な差分

1. HTML を DOMPurify で無害化する（移植元は `disableSanitizer` で素通し）。AI の回答や参照した文書に HTML が混ざったとき、React の innerHTML 経由で `<img onerror>` が動くのを防ぐため。`class` は残るのでチャート・mermaid の判定に影響しない
2. mermaid のコードは HTML エスケープして `<div class="mermaid">` に入れる（移植元は無加工）。mermaid は innerHTML をエンティティ復号して読むため図は同じで、`<` を含む図が DOM として壊れないようにするため
3. mermaid は必要になったときに動的 import する（移植元は `angular.json` の `scripts` で全画面の初期読み込み）。初期バンドルを増やさないため
4. SECURE のローカルへのストリームは `X-Tenant-ID` を付けない（api-client の `omitTenantId`）。移植元の `fetch` 直呼びが付けていないため
5. モック応答（`enableMock`）は移植しない
6. messages・rooms の状態は TanStack Query ではなく Zustand に置く。ページ読み込み・並び替え・楽観的更新・ストリーミング中の逐次更新を重ねるため
