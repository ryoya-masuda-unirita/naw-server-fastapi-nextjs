# 03_詳細設計

## 追加ライブラリ（`frontend/package.json`）

| パッケージ | 版 | 理由 |
|---|---|---|
| `marked` | 18.0.4 | 移植元と同じ版（ngx-markdown の peer）。Markdown → HTML |
| `echarts` | 6.1.0 | 移植元と同じ版。チャート描画 |
| `mermaid` | 11.16.0 | 移植元と同じ版。図の描画 |
| `dompurify` | 3.4.17 | 移植元にはない。HTML の無害化（02 の意図的な差分 1）。型は同梱 |

既存の依存の版の指定方法（`^` なしの固定）に合わせた。

## ファイル

### 描画

- `components/shared/markdown-render.ts`
  - `trimIndentation(markdown)`: ngx-markdown 21.3.0 の `trimIndentation` と同じ
  - `renderMarkdownToHtml(markdown, { mermaid })`: `new Marked()`（既定）と、`code` を差し替えた `Marked`（mermaid 用。`lang === 'mermaid'` だけ `<div class="mermaid">` にし、他は `false` で既定に戻す）を使い分け、`DOMPurify.sanitize`
- `components/shared/chart-blocks.ts`: `renderChartBlocks(host)`（`code[class*="language-chart:"]` → `.chart-block` の div + `echarts.init(..., { renderer: 'svg' })` + `ResizeObserver`）、`disposeChartBlocks`
- `components/shared/markdown-view.tsx`: `MarkdownView({ data, className, mermaid = true, chartBlocks = true })`。`html` を `dangerouslySetInnerHTML` で入れ、`html` が変わるたびの effect で mermaid（動的 import → `initialize({ startOnLoad: false, securityLevel: 'strict' })` → `run({ nodes })`）とチャート（`requestAnimationFrame` で 1 回に集約）を描く。cleanup でキャンセル・破棄
- `lib/utils/chart-block.ts`・`lib/utils/echarts-setup.ts`: 移植元のロジックのまま（マジックナンバーは定数化）

### SSE

- `lib/utils/sse-parser.ts`: `parseSseDataLine`・`parseSseChunk`
- `lib/chat/message-content-stream.ts`
  - `streamMessageContent(formData, localMessageId, handlers, target = { kind: 'naw' })`
  - naw: `apiClient.stream(API_PATHS.MESSAGES.CONTENT, { body, headers: { Accept } })`
  - local: `apiClient.stream(contentUrl, { body, headers: { Accept, 'X-Server-Auth-Key' }, credentials: 'omit', omitTenantId: true })`
  - `reader.read()` → `TextDecoder(stream: true)` → `parseSseChunk`。最後に残った行は `\n` を足して読む。`message_content` が無ければ `Error`
  - イベントの値の検証（`text` が文字列か等）・`message_content` の欠けた項目の既定値は移植元と同じ
- `lib/api-client.ts`: `ApiRequestOptions.omitTenantId`（true なら `X-Tenant-ID` を付けない）。fetch に渡さない独自オプションの一覧に追加

### messages・rooms

- `lib/chat/message-thread.ts`・`message-history.ts`・`message-content-endpoint.ts`: 移植元 `features/chat/utils/*` を import の書き換えだけで移植
- `lib/chat/message-contents-api.ts`: `fetchMessageContents(listData)`（移植元 `MessageContentsApiService.fetchContents`）。ローカルは絶対 URL への `apiClient.post`（`X-Server-Auth-Key`）
- `lib/chat/local-content-token.ts`: `getAccessTokenForLocalContent()`（`GET /api/auth` の `token`。無ければ `Error`）
- `lib/chat/library-stream-bridge.ts`: ビューワー（#288）への窓口。`setLibraryStreamBridge` / `getLibraryStreamBridge`
- `lib/chat/assistants-api-mapper.ts`・`hooks/use-assistants.ts`・`lib/constants/assistant-type.ts`・`lib/utils/{reasoning-text,room-name,share-url,room-list-mapper}.ts`: 移植元から移植
- `store/messages-store.ts`: 状態は `messages`・`messageRecords`・`assistants`・`activeVersionIndex`・`isLoading`・`isGenerating`・`loadError`・`assistantCatalog`。操作は移植元 `MessageService` の公開メソッドと同名。派生値は `useVisibleMessages()`・`useVersionInfoByMessageId()`
  - 移植元で 3 か所に重複していた「ライブラリ生成のストリーム管理」は `createLibraryStreamSession` にまとめた（開始・途中失敗・終了の順序は同じ）
  - 移植元の `HttpErrorResponse` の 403 判定は `ApiError.status === 403`
  - トーストは `useToastStore.getState().warning(i18next.t(キー))`。キーは移植元の `CHAT.MESSAGES.*`（辞書は移植済み）
  - ルーム名の自動変更は `useRoomsStore` の `allRooms`・`renameRoom` を使う。失敗しても送信は続ける（移植元は握り潰し。React では警告をログに出す）
- `store/rooms-store.ts`: 移植元 `RoomsService` の状態（`allRooms`・`searchResults`・各 `is*` フラグ・`allRoomsHasMore`）と操作。`lastSavedRoomOrder`・`currentRoomsPage` は state に持つ。`selectPinnedRooms`
- `hooks/use-chat-actions.ts`: `useChatActions()` が `useAssistants` の結果を `setAssistantCatalog` で渡し、`createNewRoom`（アシスタント名）・`rateMessage`（`['feedback', 'accuracy'|'users']` を無効化）・`submitRoomFeedback`（`['feedback', 'accuracy'|'satisfaction'|'users']` を再取得）を提供

## 判断した点

- 移植元の `rateMessage` は評価後に query を無効化するが、store は QueryClient を持てない（`main.tsx` のローカル変数）。`main.tsx` を触らず、hook で包む方式にした
- ngx-markdown の `trimIndentation` は先頭行より深いインデントの行も削る癖があるが、移植元の挙動のまま揃える
