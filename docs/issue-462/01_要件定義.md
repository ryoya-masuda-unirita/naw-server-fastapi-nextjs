# 01_要件定義

## 背景

クラウドの RAG は、学習先フォルダに登録された文書のベクトルを検索する。ベクトルを作る処理（登録）が `server/` にないため、画面からクラウドのフォルダに追加しても、質問で見つからない。

## 機能要件

| No | 要件 |
|---|---|
| F1 | ファイル登録で、ファイルからテキストを取り出し、分割長（100〜10000、既定 1000）で分割し、各部分の埋め込みを作り、ベクトルストアに保存する |
| F2 | 分割は、移植元の `ContentSplitter` と同じ（文の区切り `。.!?！？` で分け、分割長を超える文は強制的に分割する） |
| F3 | 埋め込みの接続先（Azure／Bedrock）と、ベクトルの保存先（pgvector）は、RAG の検索と同じ選び方にする。検索で見つかる場所に保存する |
| F4 | 埋め込みで消費したトークンを、`TokenUsage` に記録する（既存の RAG の埋め込みと同じ計算） |
| F5 | 登録に失敗したとき、保存したベクトルとストレージの実体を消し、ファイルの記録を残さない |
| F6 | 差し替え（ファイルを添付した更新）で、古いベクトルを消し、新しいファイルのベクトルを保存する。メタデータだけの更新は、ベクトルに触れない |
| F7 | 削除（論理・物理）で、そのファイルのベクトルを消す |
| F8 | `splitLength` が範囲外・数値でないときは、400 にする（移植元と同じメッセージ） |
| F9 | 取り出せるファイル形式は、テキスト系（UTF-8 のテキスト・Markdown・CSV・JSON・XML・HTML など）。それ以外は、分かるメッセージで 400 にする |
| F10 | ベクトルストアが pgvector でない（Azure AI Search など）接続先、または埋め込み・ベクトル DB の接続先が未設定のフォルダは、従来どおり、ファイルの記録だけを作る（ベクトル化はしない。警告をログに出す） |

## 非機能要件

- 既存のテスト（ファイル登録・更新・削除）の結果が変わらない
- 追加する関数に、日本語の NumPy 形式の docstring を書く。テストのメソッド名は英語、意図は日本語の docstring
- 外部通信は、テストではモックにする

## スコープ外

- PDF・Word・Excel など、テキスト系以外の形式の取り出し（Tika 相当）。別の Issue
- `FilePart` の記録とマイグレーション（ベクトルは `fileid` で削除するため不要）。`files.split_length` の記録（差し替えで分割長を省略したら、既定 1000）
- Azure AI Search への書き込み
- 追加学習（`additionalLearning`）・一括同期（`sync`）
- 画面（`client/`）の変更
