# 02_基本設計

## 変更対象

- ファイル登録の処理（ストレージへの保存のあと、DB に記録する前に、ベクトル化を行う）
- ファイルの差し替え・削除の処理
- テキストの取り出し・分割・分割長の検証（新規の部品）
- ベクトル化と、ベクトルの削除をまとめる部品（新規）

## 流れ（登録）

1. 分割長を検証する（`splitLength` の指定があれば）
2. ストレージにファイルを保存する
3. ベクトル化できる設定か確かめる（フォルダの埋め込み接続先と、テナントの VDB 接続先が、pgvector で、そろっているか）。そろっていなければ、4 をとばして DB に記録する（従来どおり）
4. テキストを取り出し → 分割 → 各部分の埋め込み → pgvector に保存 → トークンを記録
5. ファイルの記録を DB に保存する
6. 途中で失敗したら、保存したベクトルとストレージの実体を消して、エラーにする

## 差し替え・削除

- 差し替え: 既存の仕組み（古いファイルを物理削除 → 新規作成）の中で、削除でベクトルが消え、作成でベクトルが入る
- 削除: ストレージの実体を消すのと同じ流れで、そのファイルのベクトルを消す

## 影響範囲

- ベクトル化できる設定（pgvector の VDB 接続先と、埋め込み接続先）のフォルダだけ、動作が変わる。それ以外は、従来どおり
- 埋め込みのトークンが、クレジットに数えられる（上限は、月のクレジットの確認で、登録の前に確かめている既存の仕組み）

## 移植方針

- 分割は、移植元の `ContentSplitter` を、そのまま移す
- 分割長の検証と、エラーのメッセージは、移植元に合わせる
- Tika の代わりは、テキスト系だけを対象にした簡易な取り出し。対応していない形式は、黙って空にせず、分かるメッセージで拒否する
