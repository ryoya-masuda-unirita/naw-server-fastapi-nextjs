# 08_動作確認

## 確認環境

- macOS、`feature/issue-462`
- テストは `server/` の `uv run pytest`（結合テストは実際の PostgreSQL。Bedrock・pgvector のクライアントは差し替え）
- 実機: ローカルの docker compose（クラウド側の backend・PostgreSQL、pgvector の `vector-db`）と、本物の Bedrock（Titan の埋め込み、Claude の回答）

## 確認手順

1. テストを足し、組み込みを外した状態で、結合テストが失敗することを確かめる
2. 実装し、テスト・ruff・mypy を実行する
3. ローカルの DB のクラウドのフォルダ「クラウド」を、pgvector の VDB と、Bedrock の埋め込みの接続先に差し替える（キーはオンプレのコンテナの環境変数から、画面・ログに出さずに渡した）
4. API（画面と同じ経路）で、`就業規則_抜粋.md` を登録し、クラウドのアシスタントで質問する

## 確認結果

### テスト

- 組み込み（`file_service.py`・`file_creation.py`）を `develop` の状態に戻すと、結合テスト 15 件（`/code-review` の前の時点）のうち 11 件が失敗し（`11 failed, 4 passed`）、戻すと 15 passed
- 実装後（`/code-review` の指摘に対応したあと）: `server/` 全体で **1594 passed**。`ruff format`・`ruff check`・`mypy`（246 ファイル）が問題なし
- 追加したテスト: 分割・分割長の検証・取り出し 31 件（移植元 `ContentSplitter` の動き、Java の分割と同じ末尾の空の捨て方）、登録・失敗・従来どおり・差し替え（失敗時に古いファイルが残ること）・削除（ベクトルの削除の失敗で止まらないこと）・分割数の上限・空白だけの文章・想定外の失敗の API 19 件

### 実機（本物の Bedrock・pgvector）

| 確認 | 結果 |

| 登録（`splitLength=300`） | `ENABLE` のファイルが作られた |

## 気づいたこと

- 移植元の `ContentSplitter` は、`.` も文の区切りとして扱うため、Markdown の番号（`2.`）で文が切れ、部分に `2。` のような断片が混ざる（実機で確認）。移植元と同じ動きなので、そのまま移した（分割の仕様の見直しは、別件）
- Claude の回答には、文書にない一般論の補足（例: 緊急の事情がある場合）が付くことがある。RAG のプロンプトの調整は、別件

## 未確認事項

- 差し替え・削除の、実際の pgvector での通し（結合テストで、呼び出しの引数と、失敗時の挙動を確認した）
- 登録が途中で失敗したとき、消費済みの埋め込みのトークンが、`TokenUsage` に記録されないこと（並列化・バッチ化とあわせて、別件）
