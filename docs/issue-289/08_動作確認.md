## 2. ブラウザ → server-local → エミュレーター（Echo）の通し

### 起動

`onprem/README.md` の手順で `server-local` と `waha-emulator` を起動した（プロジェクト名 `naw-onprem-289`。既存のコンテナとは別）。vector-db は使わないため起動していない。`onprem/docker-compose.yml` の `waha-emulator` は `build: ../waha-emulator` でビルドコンテキストが合わず build に失敗した（`/waha-emulator/waha_emulator: not found`）ため、build context をリポジトリのルートにする上書きの compose を一時ファイル（スクラッチ）で用意した。

```
$ docker compose -p naw-onprem-289 -f onprem/docker-compose.yml -f <上書き> up -d --build server-local waha-emulator
NAME                             SERVICE         STATUS                    PORTS
naw-onprem-289-server-local-1    server-local    Up 15 seconds (healthy)   127.0.0.1:18090->8080/tcp
naw-onprem-289-waha-emulator-1   waha-emulator   Up 20 seconds (healthy)   127.0.0.1:18091->8080/tcp
```

### preflight（curl。Origin は React の開発サーバー）

```
$ curl -si -X OPTIONS http://localhost:18090/api/messages/content -H 'Origin: http://localhost:5173' \
    -H 'Access-Control-Request-Method: POST' -H 'Access-Control-Request-Headers: x-server-auth-key,accept'
HTTP/1.1 200 OK
access-control-allow-credentials: true
access-control-allow-origin: http://localhost:5173
access-control-allow-headers: x-server-auth-key,accept
```

`/api/libraries/x/content`（GET、`x-server-auth-key,x-tenant-id`）でも同様に許可された。

### 通しのテスト（`frontend/e2e-local/local-server.e2e.ts`）

実際の `useMessagesStore.sendMessage` / `loadMessagesForRoom`（→ `GET /api/auth` のトークン取得 → `streamMessageContent` の `target: local`）を、実物の server-local（Echo プロバイダー）に対して実行した。NAW 側（メッセージ作成・`GET /api/auth`・メッセージ一覧）だけ MSW。

```
$ npx vitest run --config vitest.e2e-local.config.ts --reporter=verbose
```

- 1 回目の実行は、固定の messageId を使ったため 2 回目の実行で server-local の `UNIQUE constraint failed: message_content...`（500）になった。テストが実行ごとの messageId を使うよう直した（server-local の不具合ではない。同じ messageId の再送は移植元でも同様に一意制約違反）
- 認証キー違いは server-local のログに `Unauthorized: Invalid Server Auth Key` が出て 401
