## 確認結果（結合）

| # | 確認事項 | 結果 | 根拠 |
|---|---|---|---|
| 1 | `GET /api/auth` が `token` を返すか | 返す（#309 後）。`AuthResponse.token` は `create_access_token(login_id, tenant_id)` の値で、`response_model_exclude_none=True` のため `None` のときだけ省く | `backend/app/routers/auth.py` の `get_auth`、`backend/app/schemas/auth.py`。通しのテストでは MSW で用意した（backend は起動していない） |
| 2 | server-local の CORS が `X-Server-Auth-Key` を許すか | 許す。`allow_origin_regex=".*"`・`allow_credentials=True`・`allow_headers=["*"]`（Starlette はリクエストされたヘッダーをそのまま許可する）。認証・サイズ超過・想定外のエラーにも CORS ヘッダーが付く | `server-local/app/main.py`。実物に対する preflight で `access-control-allow-headers: x-server-auth-key,x-tenant-id,accept` を確認（08） |
| 3 | `apiKey`・`model` | `apiKey` は SECURE の LOCAL_SERVER のときだけ返し、それ以外は空文字。移植元 `GetMessagesViewModel` と同じ。`model` は最初に紐づくエンドポイントの model（`AssistantResponse.model`）。ライブラリ詳細の `assistant` も同じ規則 | `backend/app/services/message_service.py`・`library_service.py`、移植元 `GetMessagesViewModel.java`・`LibraryGetResponse.java` |

backend・server-local の差分は見つからなかったため、Issue 起票・修正 PR はない。

## 意図的な差分・申し送り

1. `resolveAssistantModel`（#283）は endpoint の model が空白のとき assistant 直下の model に落とす（`||`）。移植元は `endpoint?.model?.trim() ?? assistant.model?.trim()` で、空文字は落とさない。backend は `model` が空文字のエンドポイントを返さない前提で実害がなく、#283 の判断を変えない
2. `apiClient.get` は絶対 URL でも `X-Tenant-ID` を付ける（移植元の `authInterceptor` と同じ）。server-local の CORS は全ヘッダーを許すので問題ない。送信（SSE）は移植元の `fetch` 直呼びに合わせて付けない（#283）
3. `onprem/docker-compose.yml` の `waha-emulator` は `build: ../waha-emulator` だが、Dockerfile はリポジトリのルートをコンテキストにする前提（`COPY generative-ai-adapter/...`）で、そのままでは build できない。本 Issue の範囲外なので触らず、確認時は上書きの compose で build context をルートにした（08）
