# 01_要件定義

## 背景

SECURE アシスタントは、質問・回答の本文を NAW ではなくテナントの server-local に置く。#283 で送信先の切り替え・トークン取得・本文取得を `store/messages-store.ts` と `lib/chat/*` に移したが、実物の server-local との結合は未確認で、ライブラリ本文の取得（`library-content-api.service.ts`）は未移植だった。

## 機能要件

1. 移植元の SECURE 経路との突き合わせ（`message-content-endpoint.resolver.ts`、`prepareSecureStreamContext`、`LibraryContentApiService`、`ViewerService.loadContent`）を行い、足りない部分を移す
   - ライブラリ本文の取得 `fetchLibraryBody` / `fetchLibraryContent`（SECURE は `GET {destination}/api/libraries/{id}/content` を `X-Server-Auth-Key` 付きで、それ以外は NAW `GET /api/libraries/{id}/content`）
   - `buildLocalLibraryContentUrl`（resolver）
2. 結合の確認
   - (1) backend `GET /api/auth` が `token` を返すか
   - (2) server-local の CORS が `X-Server-Auth-Key`（と `X-Tenant-ID`）を許すか
   - (3) メッセージ一覧の `assistants[].endpoints[]` の `apiKey`・`model`
3. ブラウザ（送信処理）→ server-local → エミュレーター（Echo）の通しを実物で確かめる

## 非機能要件

- `chat-window.tsx` は触らない（#287・#288 が並行で触る）
- 共通ファイルは触らない

## スコープ外

- ビューワー本体（#288）。ライブラリを開く処理は #288 が `fetchLibraryContent` を呼ぶ
- backend・server-local の修正（確認の結果、不要だった）
