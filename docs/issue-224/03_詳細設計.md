# 03_詳細設計

## 実装対象ファイル

### 新規: `backend/app/core/sse.py`（SSE イベント組み立ての共通化）

```python
def sse_event(event_type: str, payload: dict[str, object]) -> bytes:
    data = {**payload, "type": event_type}
    return f"data: {json.dumps(data, ensure_ascii=False)}\n\n".encode()
```

- `message_service.py` の `_sse`（#183）をそのまま移す。汎用チャット・送信 API の両 service から使うため、「service が別 service を呼ばない」規約に抵触しない `core/` に置く。
- `message_service.py`・`llm_chat_service.py` の `_sse` は削除し、本関数に置き換える。

### 新規: `backend/app/schemas/multipart_form.py`（`textData` パート解釈の共通化）

```python
async def parse_text_data_form[ModelT: BaseModel](
    model: type[ModelT],
    text_data: UploadFile | str,
    file_parts: dict[str, list[UploadFile] | None],
) -> ModelT:
```

- `schemas/message.py` の `parse_message_content_create_form` の中身（`_TEXT_DATA_ADAPTER`・`_to_request_validation_error`・`_to_attachment_payload`・`_DEFAULT_ATTACHMENT_CONTENT_TYPE`）を移し、検証先のモデルとファイルパート（項目名 → アップロードファイル一覧）を引数で受け取る形にする。
- `textData` を JSON オブジェクトとして読み、`file_parts` の各ファイルを `AttachmentFile` の入力形式（Base64）に変換して合わせ、`model.model_validate` する。`ValidationError` は `loc=("body", "textData", ...)` の `RequestValidationError`（422）へ変換する（#182 と同じ）。
- `parse_message_content_create_form` は本関数を呼ぶだけにする（挙動は変えない）。

### `backend/app/schemas/llm.py`

- `LlmChatTurn` に `attachments: list[str]` を追加する（既定は空。`validation_alias=AliasChoices("attachments", "attatchments")`。移植元 `@JsonAlias("attatchments")` 相当）。
- `LlmChatRequest`
  - `model_config = ConfigDict(populate_by_name=True)`
  - `responseFormat` に `validation_alias="response_format"` を付ける（移植元 `@JsonProperty("response_format")`）。属性名での生成も許可する（service・既存テストは属性名を使うため。`MessageContentCreateRequest` と同じ）。
  - `attachmentFiles` は multipart の `attachmentFiles` パートから詰める。
  - `@field_validator("attachmentFiles")` でファイル名の重複を拒否する（`ValueError("添付ファイルのリストに同名のファイルが含まれています")`。移植元 `@UniqueFileNames` の文言）。
  - `reasoning_effort`・`verbosity` は項目を定義しない（Pydantic の既定で無視される。`01_要件定義.md` のスコープ外参照）。
- 新規 `parse_llm_chat_form(textData: Annotated[UploadFile | str, Form()], attachmentFiles: Annotated[list[UploadFile] | None, File()] = None) -> LlmChatRequest`
  - `parse_text_data_form(LlmChatRequest, textData, {"attachmentFiles": attachmentFiles})` を返す。

### `backend/app/routers/llm.py`

- `chat` の `req` を `Depends(parse_llm_chat_form)` に変更する。認証前に添付ファイルの読み込み・検証が走らないよう、認証の依存より後に置く（送信 API と同じ）。

### `backend/app/services/llm_chat_service.py`

- `_sse` を削除し、`sse_event` に置き換える（種別名・項目は従来どおり）。
- `_apply_attachment_files` を、ターン単位の紐付けに置き換える。

```python
@staticmethod
def _apply_attachment_files(
    messages: list[ChatMessage],
    turns: list[LlmChatTurn],
    files: list[AttachmentFile],
) -> list[ChatMessage]:
```

- `messages` は `turns` から 1 対 1 で作った会話履歴（追加プロンプト・ライブラリ用指示・system 発話の降格を適用済み）。`zip(..., strict=True)` で対応付ける。
- `files` からファイル名の索引を作る（空のファイルは除外、同名は先勝ち。移植元 `indexAttachmentFiles`）。
- 元の発話（`turns`）の `role` が `user`（大文字小文字を区別しない）で `attachments` がある場合だけ、名前で索引を引いて `build_user_content` で添付する。ライブラリ生成で system から user に降格した発話には添付しない（移植元は system 発話を添付なしの user 発話に変換するため）。
- 索引にない名前があれば `HTTPException(400, "messages 内の添付ファイル名に一致するファイルがありません: {name}")`（移植元と同じ文言）。
- モジュール docstring の「添付ファイル」の記述を更新する。

### `backend/app/services/message_service.py`

- `_sse` を削除し、`sse_event` に置き換える。挙動は変えない。

### `backend/app/schemas/attachment.py`

- docstring の「`LlmChatRequest` は JSON ボディ内で Base64 エンコードして受け取る」を、両 API とも multipart で受け取る記述に更新する。
