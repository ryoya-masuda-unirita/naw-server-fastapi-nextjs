# 汎用チャットAPI（/api/llm/chat）のリクエスト形式とSSE形式を移植元に揃える

## 概要

`POST /api/llm/chat` のリクエスト形式・SSE 応答形式が、移植元 Spring Boot（`LlmController`）と異なる。移植元の Request/Response・SSE イベント形式に合わせる。

## 説明

#183 の調査で判明。`POST /api/llm/chat` のリクエスト形式・SSE 応答形式が移植元 Spring Boot（`LlmController`）と異なる。移植元の Request/Response・SSE イベント形式（#183 で送信 API に適用した `data: {"type": ...}` 形式と同様か確認）に合わせる。#149 で追加した Bedrock 経路も含めて動作を保つこと。

## その他

- 関連: #182（送信 API のリクエストを multipart 化）、#183（送信 API の SSE を `data: {"type": ...}` 形式化、PR #220）、#149（Bedrock 対応）
- エラー応答の形式（`detail` / `message`）やバリデーションエラーのステータスコード（422 / 400）は別途検討中のため、本 Issue では変えない
