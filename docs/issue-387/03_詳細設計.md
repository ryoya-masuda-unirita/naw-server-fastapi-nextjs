# 03_詳細設計

対象ファイルは `secuaigent-infra/modules/frontend/main.tf` の1つ。

## 1. ディストリビューション（`aws_cloudfront_distribution.main`）

- `is_ipv6_enabled = true` を追加する
- 3つのビヘイビアそれぞれに `compress = true` を追加する
  - `default_cache_behavior`（S3）
  - `ordered_cache_behavior`（`/api/*`）
  - `ordered_cache_behavior`（`/backend/auth/*`）
- `/api/*` の `forwarded_values.headers` を、`["*"]` から次に変える

  ```hcl
  headers = ["Authorization", "Origin", "Accept", "Content-Type", "X-Tenant-ID"]
  ```

  - `Host` を含めない理由と `X-Tenant-ID` を含める理由を、コメントに書く
  - `/backend/auth/*` の `headers = ["*"]` は変えない（スコープ外）
- 5xx のキャッシュをやめる。移植元と同じ `dynamic "custom_error_response"` を、`restrictions` の前に追加する

  ```hcl
  dynamic "custom_error_response" {
    for_each = [500, 502, 503, 504]
    content {
      error_code            = custom_error_response.value
      error_caching_min_ttl = 0
    }
  }
  ```

  - `response_code`・`response_page_path` は書かない（エラー応答の中身を置き換えない）
  - 既存のコメント（`custom_error_response` は全体に効くので使わない、という #240 の記述）と矛盾しないよう、「中身は置き換えず、キャッシュ時間だけを変える」旨を書き足す

## 2. S3 バケット（`aws_s3_bucket.frontend`）

次の2つを、バケットの定義の近くに追加する。

```hcl
resource "aws_s3_bucket_versioning" "frontend" {
  bucket = aws_s3_bucket.frontend.id

  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "frontend" {
  bucket = aws_s3_bucket.frontend.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}
```

- 既存のバケット（`force_destroy = true`）は変えない。バージョニングを付けても、`terraform destroy` は旧版ごと削除できる
