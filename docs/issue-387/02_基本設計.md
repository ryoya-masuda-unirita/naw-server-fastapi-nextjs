# 02_基本設計

## 変更対象

- CloudFront ディストリビューション（画面・`/api/*`・`/backend/auth/*` の3つのビヘイビア）
- フロントエンド用 S3 バケット（バージョニングと暗号化の追加）

## 画面 / API 変更概要

画面・API の仕様は変わらない。配信の設定だけが変わる。

| 項目 | 今 | 変更後 |
|---|---|---|
| 圧縮 | なし | 3つのビヘイビアすべてで有効 |
| IPv6 | 無効 | 有効 |
| `/api/*` の転送ヘッダ | 全部 | `Authorization`・`Origin`・`Accept`・`Content-Type`・`X-Tenant-ID` |
| 5xx（500・502・503・504） | CloudFront の既定のキャッシュ | キャッシュしない |
| S3 のバージョニング | なし | 有効 |
| S3 の暗号化 | なし | AES256 |

## 影響範囲

- **テナント識別**: server は `X-Tenant-ID` ヘッダ（必須）でテナントを識別している。限定リストに含め忘れると、`/api/*` のすべてのリクエストが 400 になる。移植元のリストをそのまま写さない
- **`Host`**: server は `Host` を読まず、ALB にもホスト条件がない。転送をやめても影響しない
- **Cookie・クエリ文字列**: 今のとおり転送する（ヘッダとは別の設定）
- **5xx のキャッシュ設定**: エラー応答の中身は置き換えない（`/api/*` の ALB の 5xx 応答もそのまま返る）。SPA フォールバックは CloudFront Function で行っているので、404・403 の書き換えには影響しない
- **S3 のバージョニング**: 以後、デプロイで上書き・削除したファイルの旧版が残り続ける（容量が増える）。今はデプロイが `--delete` で同期するため、旧版の掃除が必要なら別途ライフサイクルを検討する
- **既存リソース**: ディストリビューションと S3 バケットは更新（in-place）で済む。バージョニングと暗号化は別リソースとして追加される

## 移植方針

- 移植元（`modules/frontend`）の該当箇所に合わせる。ただし、サブドメイン関連（エイリアス・ACM・Route53）は持ち込まない
- 移植元との違い（意図的）:
  - 転送ヘッダに `X-Tenant-ID` を足し、`Host` を外す（上記のとおり、テナント識別の方式が違うため）
  - CloudFront → ALB は HTTP のまま（今の構成を維持）
  - `/backend/auth/*` は移植元にない、この移植先独自のビヘイビア。ヘッダの見直しはスコープ外
- 確認は `terraform fmt`・`validate` と、plan の差分（変更が in-place のみで、作り直し・削除がないこと）で行う
