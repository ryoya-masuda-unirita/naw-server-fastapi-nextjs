# 01_要件定義

## 背景

親 Issue #380 で、インフラの構成・設定を移植元に揃えている。CloudFront と、フロントエンド用 S3 バケットには、次の差がある。

- 圧縮と IPv6 が有効になっていない
- `/api/*` は、全ヘッダを ALB へ転送している（移植元は限定リスト）
- 5xx のエラー応答が、CloudFront の既定で一定時間キャッシュされる。S3 の一時的な 503 が、その間すべての閲覧者に返り、画面のチャンク読み込み失敗時の自動リロードでも回復できない（NAW-1338）
- フロントエンド用 S3 バケットに、バージョニングと暗号化がない

## 機能要件

1. 画面（S3）と `/api/*` のビヘイビアで、応答の圧縮を有効にする。`/backend/auth/*` は、応答が小さい JSON で効果が薄く、全ヘッダ転送との組み合わせの確認もしていないため、対象外にする
2. ディストリビューションで IPv6 を有効にする
3. `/api/*` の転送ヘッダを、必要なものだけの限定リストにする
   - テナント識別に使うヘッダ（`X-Tenant-ID`）は必ず転送する。サブドメインを廃止しているため、このヘッダが唯一のテナント識別の手段になる
   - 移植元はテナントをサブドメイン（`Host`）で識別するために `Host` を転送しているが、この移植先では不要なので転送しない
4. 500・502・503・504 のエラー応答を、キャッシュしない（最小 TTL を 0 にする）。エラー応答の中身は置き換えない
5. フロントエンド用 S3 バケットで、バージョニングを有効にし、AES256 で暗号化する

## 非機能要件

- 既存の挙動を壊さない。維持するもの:
  - 画面パスの SPA フォールバック（CloudFront Function）
  - `/backend/auth/*` の転送と、`/backend` の除去
  - CloudFront のデフォルト証明書と、デフォルトドメインでの配信
  - 固定オリジンの CORS
- 既存リソースの作り直し（破壊的な変更）を起こさない。S3 バケットとディストリビューションは、同じものを更新する
- 親 Issue の方針どおり、`terraform apply` は人が実行する。PR では plan の差分を確認する
- ストリーミング（SSE）や、ログイン後のセッション Cookie が、変更前と同じように動く

## スコープ外

- エイリアス・ACM 証明書（サブドメイン関連）
- `/backend/auth/*` のヘッダ転送の見直し（Issue の対象は `/api/*` のみ。今は全ヘッダを転送している）
- Secrets Manager（#386）、GitHub Actions ロールの権限（#388）など、親 Issue の他の子 Issue
- 価格クラス（`PriceClass_100`）の変更
