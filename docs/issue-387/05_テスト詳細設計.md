# 05_テスト詳細設計

| No | コマンド・操作 | 合格条件 |
|---|---|---|
| 1 | `terraform fmt -check -recursive secuaigent-infra` | 差分なし |
| 2 | `cd secuaigent-infra/environments/dev && terraform init -backend=false && terraform validate` | `Success!` |
| 3 | 変更前（`develop`）と変更後で、ローカルの空の state に対して `terraform plan -refresh=false` を取り、リソースの一覧を比べる | 追加は `aws_s3_bucket_versioning.frontend` と `aws_s3_bucket_server_side_encryption_configuration.frontend` の2つだけ。ほかのリソースの増減がない |
| 4 | plan の出力で、ディストリビューションの差分を見る | `is_ipv6_enabled`・`compress`・`custom_error_response`・転送ヘッダの変更だけ |
| 5 | `git diff` で `/api/*` の `headers` を読む | `X-Tenant-ID` がある。`Host` がない |
| 6 | `git diff` を読む | `spa_fallback`・`strip_backend_prefix`・`viewer_certificate`・`price_class` に差分がない |
| 7 | `node --test secuaigent-infra/modules/frontend/functions/functions.test.mjs` | 6件成功 |
| 8 | （デプロイ後、人が実施）ログインし、画面を開く。ブラウザの開発者ツールで、画面の応答に `content-encoding` が付くこと、`/api/*` が 200 を返すことを見る | ログインでき、API が通る |

3 の plan は、実環境の state がないため、ローカルの空の state で取る（#399 と同じ方法）。実環境の plan（in-place のみ）は、state にアクセスできる人が確認する。
