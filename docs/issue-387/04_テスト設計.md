# 04_テスト設計

## テスト方針

Terraform の設定変更なので、新しい自動テストは書かない。静的検証と、plan の差分で確認する。CloudFront の挙動は、デプロイ後に確認する（デプロイは人が実行する）。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 書式 | 設定を変えた後 | 書式の検査が通る |
| 2 | 構文・整合 | 設定を変えた後 | 検証が通る |
| 3 | 変更の種類 | 既存の状態に対して plan する | ディストリビューションは更新のみ。作り直し・削除がない |
| 4 | S3 | 同上 | バージョニングと暗号化が追加され、バケット自体は変わらない |
| 5 | 転送ヘッダ | `/api/*` の設定を読む | テナント識別のヘッダが含まれ、`Host` が含まれない |
| 6 | 維持するもの | 差分を読む | SPA フォールバック・`/backend/auth/*`・デフォルト証明書・価格クラスが変わっていない |
| 7 | CloudFront Function のテスト | 既存のテストを実行 | 全件成功（関数は変えていない） |
| 8 | 実環境の挙動 | デプロイ後（人が実施） | ログインと API 呼び出しが通る。画面が圧縮されて配信される |
