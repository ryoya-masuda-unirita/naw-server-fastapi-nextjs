# 01_要件定義

## 背景

請求期間・クレジット上限の判定は、移植元（Spring Boot）と同じく UTC の日付で行っている。一方、結合テストはサブスクリプションの契約開始日・終了日を実行環境のローカル日付で作っているため、ローカル日付と UTC の日付が異なる時間帯（日本時間 0:00〜9:00 など）にテストを実行すると、契約開始日が UTC の「明日」になり、有効なサブスクリプションがないものとして扱われてテストが失敗する。

修正前に UTC+14 のタイムゾーンで実行し、Issue に記載の 6 件が失敗することを再現した（`08_動作確認.md` 参照）。

## 機能要件

| No | 要件 |
|---|---|
| 1 | 結合テストが作るサブスクリプションの契約開始日・終了日を、アプリと同じ UTC の日付を基準にする |
| 2 | 対象は、クレジット利用量・ファイル・テナント・ユーザー・グループの結合テストで、ローカル日付を使っている全箇所とする |
| 3 | ユーザー・グループの結合テストにある、時差のずれを避けるための回避策（開始日を 2 日前にずらす）は、ずれの原因がなくなるため取り除き、他のテストと同じく「UTC の今日」を開始日にする |
| 4 | 実行環境のタイムゾーンによらず（UTC+14・UTC の両方で）全テストが通る |

## 非機能要件

- アプリ（本番コード）の挙動は変えない
- テストの検証内容（期待値）は変えない

## スコープ外

- アプリ側の日付の扱い: grep で確認した結果、ローカル日付（今日の日付の取得・タイムゾーンなしの現在時刻・DB の現在日付関数）は使っておらず、すべて UTC 基準でそろっているため変更しない（詳細は `02_基本設計.md`）
- 結合テストの共通 fixture にある、パスワード作成日時の UTC 現在時刻の取得（非推奨 API を使っている）。値は UTC の日時でありローカル日付との混在ではないため、本 Issue では変更しない
