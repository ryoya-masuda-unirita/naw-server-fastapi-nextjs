# #266 issue-266 日本時間の深夜に結合テストが失敗する日付の扱いを直す

## 概要

結合テストの一部が、日本時間の 0:00〜9:00（UTC と日付が違う時間帯）に手元で実行すると失敗する。CI（UTC）では通る。

失敗するテスト（2026-11-13 00:03 JST に確認）:

- `tests/integration/test_credit_usage.py` の 3 件
- `tests/integration/test_files.py` のクォータ超過 2 件
- `tests/integration/test_tenants.py` の使用量超過 1 件

## 説明

### 原因

テストはサブスクリプションの `start_date` を `date.today()`（ローカルの日付 = JST）で作るが、アプリ（`app/core/credit_quota.py`）は `datetime.now(timezone.utc).date()` で有効なサブスクリプションを探す。JST の 0:00〜9:00 はテストの開始日が UTC の「明日」になり、有効なサブスクリプションとして扱われない。

### 対応

テストの `date.today()` を、アプリと同じ UTC の日付（`datetime.now(timezone.utc).date()`）にそろえる。`test_users.py`・`test_groups.py` の同様の箇所も含める。`TZ` を UTC+14 などにして失敗→修正後成功を確かめる。

## その他

### 依頼時の補足

- 共通のヘルパーにするかは既存の conftest の作りに合わせて判断する
- アプリ側に同じ問題（ローカル日付と UTC の混在）がないかも grep で確認し、あれば docs に記録する（直すかは範囲を見て判断、大きければ報告だけ）
- 修正前に `TZ=Pacific/Kiritimati`（UTC+14。いつ実行しても UTC と日付がずれる）で失敗を再現し、修正後に `TZ=Pacific/Kiritimati` と `TZ=UTC` の両方で全件通ることを 08 に記録する
- 全自動モードで対応する（第1承認・第2承認は省略）
