# 04_テスト設計

## 方針

- 画面は、**ロジック（`editor/model.ts`・`api/client.ts`）を中心に厚く**、部品（一覧・プロパティ・ヘッダー）は振る舞いで確かめる
- キャンバス（React Flow）は、jsdom で描画の細部を確かめるのが難しいため、**実ブラウザでの動作確認（08）**で補う
- エミュレーター側（候補のエンドポイント）は、Python のテスト

## 観点

### エミュレーター（Python）

- 候補が、生成AI・検索ごとに返り、秘密の名前に印が付く
- エミュレーターが決める名前が入らない
- 候補に出る名前は、検証で未知のプロパティとして弾かれない

### モデル（`editor/model.ts`）

- サーバーの形 → キャンバス → サーバーの形で、内容が変わらない（位置・名前・プロパティ・出力モード）
- 新規の定義が、サーバーの規則（鎖）に合う
- 線の規則: 正しい線は引ける。逆向き・出る線が 2 本・入る線が 2 本・鎖の順に反する・自分自身への線を、理由つきで拒否する
- ノードの追加: 検索は 1 つまで。開始・終了・生成AI は足せない。ID が重ならない
- 未保存の判定: 変更なし → false。位置・名前・プロパティ・線・サービス ID の変更 → true

### API クライアント（`api/client.ts`）

- 各呼び出しの URL・メソッド・本文
- 400・404・409 で、サーバーの `detail` を持つ `ApiError`
- 通信の失敗で、「エミュレーターに接続できません」の `ApiError`（`status = 0`）
- 204（削除）で本文なし

### 部品

- 一覧: 名前・サービス ID の表示、選択、新規作成、削除（確認）
- プロパティ: 候補から追加、候補にない名前の拒否、秘密の値は隠す、`********` の表示、値の変更、削除、検索があるときの出力モードの無効化
- ヘッダー: 名前・サービス ID の編集（追加・削除）、検証・保存の押下、結果（成功・エラー）の表示、保存中の無効化
- アプリ: 一覧 → 開く → 名前を変える → 保存で、更新の API が呼ばれる（API を差し替えた結合）
