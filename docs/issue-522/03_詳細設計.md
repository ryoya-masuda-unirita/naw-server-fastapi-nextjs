# 03_詳細設計

## エミュレーター側（追加）

| ファイル | 内容 |
|---|---|
| `waha-emulator/waha_emulator/studio/catalog.py` | `property_catalog()`: 生成AI・検索のプロパティ名の候補（`{name, secret}`）。エミュレーターが決める名前（`OUTPUT_DIR` など）は入れない |
| `waha-emulator/waha_emulator/studio/service.py` | `is_secret_name(name)` を公開（候補の `secret` と、応答の伏せ字で同じ判定を使う） |

応答の例: `{"generativeAi": [{"name": "API_KEY", "secret": true}, ...], "retrieval": [...]}`

## 画面（`waha-emulator/ui/`）

独立した npm プロジェクト。`client/` と同じ版（React 19・Vite・Tailwind 4・Vitest・TypeScript 6）に揃える。

```
ui/
  package.json  tsconfig.json  vite.config.ts  vitest.config.ts
  eslint.config.js  postcss.config.js  index.html
  src/
    main.tsx  index.css  App.tsx
    api/types.ts      サーバーとやり取りする JSON の型
    api/client.ts     管理用 API の呼び出し（ApiError）
    editor/model.ts   サーバーの形 ⇔ キャンバスの形の変換、線の規則、新規の定義、未保存の判定
    editor/useEditor.ts  編集中の状態（開く・変更・検証・保存・削除）
    components/Header.tsx          名前・サービス ID・検証・保存・結果表示
    components/WorkflowList.tsx    左の一覧・新規作成・削除
    components/Canvas.tsx          React Flow のキャンバス・パレット

```

### `api/types.ts`

- `GraphData`（サーバーの保存形式 版 1）: `version`・`id`・`name`・`serviceIds`・`nodes`・`edges`
- `GraphNodeData`: `id`・`type`（`start`・`retrieval`・`generative-ai`・`end`）・`name?`・`position`・`properties?`・`outputType?`
- `WorkflowSummary`、`PropertyCatalog`（`generativeAi`・`retrieval`: `{name, secret}[]`）

### `api/client.ts`

- `ApiError(status, message)`: サーバーの `detail`（400・404・409）か、通信の失敗（`status = 0`、「エミュレーターに接続できません」）
- `listWorkflows`・`getWorkflow`・`createWorkflow`・`updateWorkflow`・`deleteWorkflow`・`validateWorkflow`・`getPropertyCatalog`
- 接続先は同じオリジンの `/admin/...`（開発サーバーのプロキシが中継）

### `editor/model.ts`

| 関数 | 内容 |
|---|---|
| `toFlow(graph)` | `GraphData` → React Flow のノード・線（`data` に種類・名前・プロパティ・出力モード）|
| `fromFlow(base, nodes, edges)` | キャンバスの状態 → `GraphData`（`id`・`name`・`serviceIds` などは `base` から）|
| `newGraph(id, name, serviceIds)` | 開始 → 生成AI（echo）→ 終了の最小の定義 |
| `canConnect(nodes, edges, connection)` | 線を引いてよいか。引けないときは理由を返す |
| `canAddNode(nodes, type)` | ノードを足してよいか（検索は 1 つまで、開始・終了・生成AI は足せない）|
| `addNode(nodes, type)` | 新しいノード（ID は重ならない値、位置は右端の次）|
| `isDirty(saved, current)` | 開いたときの定義との違いがあるか（`position` の変化も含む）|

線の規則: 開始から出る・終了へ入る・1 つのノードから出る線は 1 本・入る線は 1 本・鎖（開始 →（検索 →）生成AI → 終了）の順序に合う向き。理由の文言は、サーバーの文言に合わせる。

### `editor/useEditor.ts`

- 状態: `graph`（保存済み）・`nodes`・`edges`・`name`・`serviceIds`・`selectedId`・`status`（`idle`・`validating`・`saving`）・`message`（成功・エラー）
- 操作: `open(id)`・`create(...)`・`remove(id)`・`validate()`・`save()`・ノード・線の変更・`isDirty`
- 保存済みの伏せ字（`********`）は、そのまま保持して送り返す（サーバーが引き継ぐ）

### 画面のふるまい

- 一覧: 開くときに、未保存の変更があれば確認（`window.confirm`）。新規作成は、名前・ID・サービス ID を入れるダイアログ
- キャンバス: React Flow の `onConnect` の前に `canConnect` で確かめ、不可なら理由を上部に出す。Delete キーで、選んだノード（開始・終了・生成AI を除く）・線を消す
- プロパティ: 名前の入力欄（候補の `datalist` つき）。候補にない名前は追加できない。`secret` の名前は `type="password"` で、値が `********` のときは、プレースホルダーで「保存済みの値を使います」と出し、入力されたときだけ置き換える
- 生成AI の出力モード: 検索ノードがあるときは無効（RAG 固定）
- 保存: 検証 → 作成（未保存の新規）または更新。成功は、上部に出す。サーバーの理由は、そのまま出す
- `beforeunload`: 未保存のとき、ブラウザの確認

### 開発サーバー

- `vite.config.ts`: `/admin` を `WAHA_URL`（既定 `http://localhost:8091`）へ中継する
- `npm run dev`（5174 番。`client/` の 5173 と重ならない）、`npm test`、`npm run type-check`、`npm run lint`、`npm run build`
