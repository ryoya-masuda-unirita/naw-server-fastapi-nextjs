# 02_基本設計

## 全体像

```
ブラウザ（画面。開発サーバーで動く）
   │  /admin/workflows ...        ← 開発サーバーのプロキシ
   ▼
waha-emulator（管理用 API。#521）
   ＋ プロパティ名の候補を返すエンドポイント（この Issue で追加）
```

- 画面は、エミュレーターの管理用 API だけを呼ぶ。servicerun（server-local が呼ぶ経路）は呼ばない
- 画面とエミュレーターは別のプロセス。画面の配信・デプロイは対象外

## 画面の構成

```
┌───────────────────────────────────────────────────────────────┐
│ 名前 [        ]  サービス ID [ a ][ b ][+]    [検証] [保存]     │
├─────────┬───────────────────────────────────┬─────────────────┤
│ ワークフ │                                   │ プロパティ        │
│ ロー一覧 │        キャンバス                  │ （選んだノード）   │
│          │   [開始] → [検索] → [生成AI] → [終了] │                 │
│ [+新規]  │   （点のグリッド・拡大縮小）          │ 名前 / 出力モード  │
│          │                                   │ プロパティ一覧     │
│          │  [＋検索] [＋生成AI]（パレット）      │                 │
└─────────┴───────────────────────────────────┴─────────────────┘
```

- 左: 本家 Designer のツリーに当たる一覧（最初の版は、フォルダ階層を持たない平らな一覧）
- 中央: キャンバス。点のグリッド・ミニマップ・拡大縮小。ノードは種類ごとにアイコン・色を変える（入力: 開始、処理: 検索・生成AI、出力: 終了）
- 右: 選んだノードのプロパティ。何も選んでいないときは、ワークフローの説明

## 画面の状態

| 状態 | 内容 |
|---|---|
| 一覧 | サーバーの一覧。作成・削除のあとで取り直す |
| 編集中の定義 | 開いたワークフロー（ノード・線・名前・サービス ID）。画面の中で変更し、保存で送る |
| 未保存 | 開いたときの定義と、編集中の定義の違いがあるか |
| 選択 | 選んでいるノード |
| 検証・保存の結果 | 成功、または、サーバーの理由（400・409） |

- 伏せた値は、「保存済みの値」として覚え、入れ直されない限り、そのまま送り返す（サーバーが引き継ぐ）
- サーバーの保存形式（版 1）と、画面の編集用の形（キャンバスの部品が使う形）の変換を、1 か所に集める

## 線の規則（画面側）

- サーバーの規則（開始 →（検索 →）生成AI → 終了の 1 本の鎖）と同じ内容を、画面でも、線を引く瞬間に確かめる
  - 開始・終了の向きの誤り、1 つのノードから複数の線、1 つのノードへ複数の線、鎖の外れを拒否する
- 最終的な判断はサーバー（検証・保存）に任せる。画面の確認は、引いたときにすぐ分かるための補助

## プロパティ名の候補

- アダプターが持つプロパティ名（生成AI・検索）を、サーバーから取る。画面は、その候補から選ばせる
- 候補のエンドポイントは、読み取り専用で、サービス ID・ワークフローとは独立
- 値の入力は文字。プルダウン（ベンダー名など）は、この版では持たない

## 技術の選び

| 項目 | 選び | 理由 |
|---|---|---|
| ビルド・実行 | Vite + React + TypeScript | 既存の `client/` と同じ系統で、`npm run dev` だけで動く |
| キャンバス | React Flow（`@xyflow/react`） | ノード・線・拡大縮小・ミニマップ・グリッドが揃っていて、Dify も同じ系統 |
| スタイル | Tailwind CSS | `client/` と同じ。検証用の道具のため、部品ライブラリは入れない |
| テスト | Vitest + Testing Library | `client/` と同じ |
| 置き場所 | `waha-emulator/ui/`（独立した npm プロジェクト） | エミュレーターの一部だが、Python と分けて管理する |

## 失敗の扱い

| 場面 | 扱い |
|---|---|
| 検証・保存が 400 | サーバーの理由を、画面の上部（保存の近く）に出す。編集中の内容は残す |
| サービス ID の重複（409） | 同上 |
| 通信の失敗 | 「エミュレーターに接続できません」と出す。編集中の内容は残す |
| 未保存のまま移動・閉じる | 確認を出す |
