# 01_要件定義

## 背景

- 第 1 弾（#521）で、ワークフローを保存・管理する API と、サービス ID での実行ができた。ワークフローを組むには、今は JSON を手で書く必要がある
- Dify のように、ノードと線で対話的に組める画面にしたい。本物の Waha! Transformer の Designer も、データと処理を矢印でつなぐ画面
- 利用者は、SecuAiGent の動作確認をする開発者 1 人。認証・多人数の同時編集は考えない

## 機能要件

### ワークフローの一覧

- 保存したワークフローを一覧で見られる（名前・サービス ID）
- 新規作成できる。名前とサービス ID を入れると、開始 → 生成AI → 終了の最小の鎖でできる
- 削除できる（確認を出す）
- 選ぶと、キャンバスに開く

### キャンバス

- 開始・検索・生成AI・終了のノードを、キャンバスに表示する。位置は、保存された位置を使う
- ノードを追加できる（検索・生成AI。開始・終了は 1 つずつで、削除できない）。検索は 1 つまで、生成AI は 1 つで、削除できない
- ノードを動かせる。動かした位置は保存される
- ノードの出力から、別のノードの入力へ線を引ける。線を選んで消せる
- 線のつなぎ方の規則（開始 →（検索 →）生成AI → 終了の 1 本の鎖）に反する線は、引いた時点で拒否して、理由を出す
- 点のグリッドの背景、拡大・縮小、全体表示ができる

### プロパティの編集

- ノードを選ぶと、右のパネルで編集できる
  - 共通: 名前
  - 生成AI: 出力モード（0: チャット用_回答、2: 回答の本文だけ。検索があるときは固定の RAG で、選べない）
  - 検索・生成AI: プロパティ（名前と値の一覧）
- プロパティの名前は、アダプターが持つ名前の候補から選べる（候補にない名前は、入れられない）。値は文字で入れる。`${環境変数}` の参照を書ける
- 伏せた値（`********`）の項目は、「保存済みの値を使う」と分かる表示にする。値を入れ直すと、その値で更新される
- 秘密を入れる項目（API キー・パスワード）は、入力中の文字を隠す

### ワークフローの名前・サービス ID

- 名前とサービス ID（1 つ以上）を、画面上部で編集できる

### 検証と保存

- 保存の前に、サーバーで検証し、不正なときは、理由（どのノード・項目か）を画面に出す
- 保存できる。サービス ID の重複（409）も、理由を画面に出す
- 未保存の変更があるときは、分かる表示にする。他のワークフローへ移る・閉じるときに、確認を出す

### 管理用 API の追加

- アダプターのプロパティ名の候補（検索ノード用・生成AI ノード用）を返す、読み取り用のエンドポイントを足す

## 非機能要件

- `npm run dev` だけで動く。サーバー（エミュレーター）への接続は、開発サーバーの中継（プロキシ）で行い、エミュレーター側に CORS の設定を足さない
- 既存の `client/`（製品の画面）と、依存・設定を共有しない（独立したプロジェクト）
- 日本語の表示。デザインは、検証用の道具として見やすいことを優先する
- キーボードで、主な操作（保存・ノードの削除）ができる
- 型検査・lint・テストが通る。画面の主要な振る舞いにテストがある

## スコープ外

- 試し実行（質問を送って回答を見る）・実行ログの表示
- 学習・削除・同期のノード、エージェント、条件分岐などの追加ノード
- 元に戻す・やり直し、複数ワークフローの同時編集
- デプロイ、認証、エミュレーターからの画面の配信
