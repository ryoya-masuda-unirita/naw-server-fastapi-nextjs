# 02_基本設計

## 変更対象

- アシスタントカテゴリの業務処理（見つからない場合のエラー文言）
- アシスタントカテゴリの単体テスト・結合テスト

## 画面 / API 変更概要

| API | 変更前 | 変更後 |
|---|---|---|
| `GET /api/admin/assistant-categories/{id}`（`options` を含む） | 404 `Assistant category not found` | 404 `AssistantCategory not found with id:{id}` |
| `PATCH /api/admin/assistant-categories/{id}` | 404 `Assistant category not found` | 404 `AssistantCategory not found with id: {id}` |
| `DELETE /api/admin/assistant-categories/{id}` | 404 `Assistant category not found` | 404 `AssistantCategory not found with id:{id}` |

ステータスコード・成功時の応答・認可は変えない。

## 影響範囲

- 移植先の React はこの文言を表示に使っていない（移植元 client も同様）。文言の変更による画面への影響は無い

## 移植方針

- `/options` を専用の API として新設しない。移植元に無く、client からも呼ばれないため、移植元と同じ挙動（単体取得の 404）にそろえるのが「移植元どおり」になる
- backend の id は文字列（varchar(32)）なので、`options` を渡しても型エラー（500）にはならず、移植元と同じく「見つからない」になる。これを結合テストで固定する
