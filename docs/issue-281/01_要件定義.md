# 01_要件定義

## 背景

フロントエンドの棚卸し（移植元 client の API パス定義から作成）で、backend に無い API として 4 件が挙がった。移植元 server（Spring Boot、2026-11-12 時点の develop）と client を突き合わせた結果は次のとおり。

| 対象 | 移植元 server | 移植元 client の実コードからの呼び出し | 結論 |
|---|---|---|---|
| `GET /api/tags`・`/api/tags/{id}` | 無い（全ブランチの履歴にも無い） | 無い。パス定義はモックからだけ参照される。チャットのタグ一覧（tags.service）は実装済みの `GET /api/libraries/tags` を呼ぶ | 移植しない |
| 一般ユーザー用 `GET /api/token-usages` | 無い（全ブランチの履歴にも無い）。管理者用 `/api/admin/token-usages`・`/summary` のみ | 無い。サービス（token-usage.service）は定義されているが、どの画面・サービスからも使われていない | 移植しない |
| `PATCH /api/admin/tenants/{id}/usage-limit` | 無い（全ブランチの履歴にも無い）。テナントのテーブルにも月間上限・アラート割合などの列が無い | 有る。テナント管理の利用量タブが呼ぶ。移植元の本番（モック無効）では server に無いため失敗し、失敗のトーストが出る | 移植元に根拠が無いため、このチケットでは実装しない。どう扱うかは判断を仰ぐ |
| `GET /api/admin/assistant-categories/options` | 専用の API は無い。`GET /api/admin/assistant-categories/{id}`（id は文字列）に入り、id=`options` のカテゴリが無いため 404 `AssistantCategory not found with id:options` を返す | 無い。取得関数は定義されているが呼び出し元が無い | 移植元と同じく `/{id}` に入り 404 を返すことを確かめる。応答本文の文言を移植元に揃える |

## 機能要件

1. `GET /api/admin/assistant-categories/options` は、移植元と同じく単体取得として扱い、404 と本文の `message` に `AssistantCategory not found with id:options` を返す
2. アシスタントカテゴリの単体取得・更新・削除で対象が見つからない場合の 404 の文言を移植元に揃える
   - 単体取得・削除: `AssistantCategory not found with id:{id}`
   - 更新: `AssistantCategory not found with id: {id}`（移植元は更新だけコロンの後に空白が入る）

## 非機能要件

- 認可（テナント管理者のみ）・ステータスコードは変えない
- マイグレーションは追加しない

## スコープ外

- `GET /api/tags`・`/api/tags/{id}`、一般ユーザー用 `GET /api/token-usages`: 移植元 server に存在せず、client の実コードからも呼ばれないため実装しない
- `PATCH /api/admin/tenants/{id}/usage-limit`: 移植元 server に API もデータの置き場所も無い。作るには API とテナントの列（月間・日次のクレジット上限、ユーザー数上限、アラート割合）を新たに設計する必要があり、移植の範囲を超える。扱いは判断待ちとし、Issue に記録する
