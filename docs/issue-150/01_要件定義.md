# 01_要件定義

## 背景

- 現状、ローカル開発ではPostgreSQL・Redisのみdocker-composeで起動し、backend（FastAPI）と
  frontend-angular（動作確認用フロントエンド）はそれぞれホストで個別に起動する運用になっている
- 起動手順が複数箇所に分かれており、環境構築時の手間や手順の把握コストが大きい
- frontend-angularの開発サーバーは、`/api`・`/auth`宛のリクエストをbackendへ転送するプロキシ
  機能を持っており、現状は転送先をホスト上のbackend（`http://localhost:8001`）に固定している。
  frontend-angularをコンテナ化した場合、この転送先をコンテナ間通信用のアドレスに切り替えられる
  必要がある

## 機能要件

- ルートのdocker-composeに、backend・frontend-angularのサービスを追加する
- `docker compose up`一発で、PostgreSQL・Redis・backend・frontend-angularが立ち上がり、
  ブラウザから動作確認できる状態にする
- backend・frontend-angularともに、ソースコードの変更が起動中のコンテナへ即座に反映される
  （ホットリロード）構成にする
- frontend-angularのプロキシ転送先を、コンテナ環境かどうかで切り替え可能にする
  （ホストで直接起動する既存の運用は変更しない）
- backend・frontend-angular間、backend・PostgreSQL/Redis間の接続は、コンテナ同士のネットワーク
  経由で行う

## 非機能要件

- 既存のホスト直接起動の開発フロー（`uvicorn --reload`、`npm start` / `npm run start:local`）は
  そのまま使えるようにする（今回追加するdocker-compose起動は選択肢の追加であり、既存フローの
  廃止ではない）
- コンテナ起動後の初回セットアップ（依存パッケージインストール等）にかかる時間を必要以上に
  増やさない

## スコープ外

- `frontend`（React移植）のコンテナ化
- 既存の`backend/Dockerfile`（ECS本番デプロイ用）自体の構成変更
- CI/CDパイプラインでのdocker-compose利用
