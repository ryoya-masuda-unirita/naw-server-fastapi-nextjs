# 02_基本設計

## 変更対象

- ルートのdocker-compose定義
- backendの開発用コンテナ構成（既存の本番用Dockerfileとは別に用意する）
- frontend-angularの開発用コンテナ構成（新規）
- frontend-angularのプロキシ転送先の切り替え機構

## 画面 / API変更概要

- 画面・APIの仕様自体に変更はない。起動方法（ローカル環境の構築手段）のみが変わる
- ブラウザからのアクセス先（`http://localhost:4201`）・APIのURL体系は変更しない

## 影響範囲

- ローカル開発環境のセットアップ手順（新しい起動方法が選択肢として増える）
- frontend-angularのプロキシ設定（転送先アドレスの決定方法）
- 既存のCI（GitHub Actions）はdocker-composeを使わない構成のままとし、影響を受けない

## 移植方針

- 移植元（Spring Boot / secuaigent-client）にはこのモノレポ構成に対応するものがないため、
  完全に新規設計とする
- backendは既存の本番用`Dockerfile`をそのまま使わず、開発用途に適した別構成
  （ソースディレクトリのボリュームマウント・`--reload`起動）を用意する
- frontend-angularも同様に、開発用途に適した新規コンテナ構成
  （ソースディレクトリのボリュームマウント・`ng serve`のホットリロード）を用意する
- frontend-angularのプロキシ転送先は、環境変数で切り替えられるようにし、コンテナ起動時は
  docker-compose側からコンテナ間通信用のアドレスを注入する。ホストで直接起動する既存の
  運用では、指定しない場合のデフォルト値（現状のホスト向けアドレス）にフォールバックする
- backendからPostgreSQL・Redisへの接続も同様に、コンテナ環境向けの接続情報を
  docker-compose側から注入する
