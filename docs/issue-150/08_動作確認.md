# 08_動作確認

## 確認環境

- `docker compose up -d --build` でPostgreSQL・Redis・backend・frontend-angularの4サービスを起動
- 確認方法: AIエージェントが`docker compose`コマンド・`curl`・ファイル編集で確認した

## 確認結果

### Step 1: 4サービスが一括起動すること

```
Container naw-fastapi-postgres  Healthy
Container naw-fastapi-redis     Healthy
Container naw-fastapi-backend   Started
Container naw-fastapi-frontend-angular  Started
```

✅ `docker compose up -d --build`一発でPostgreSQL・Redis・backend・frontend-angularが
   すべて起動した

### Step 2: backendのホットリロード

`app/main.py`のFastAPIタイトルを一時的に変更したところ、以下のログが出力された。

```
WARNING:  WatchFiles detected changes in 'app/main.py'. Reloading...
INFO:     Shutting down
INFO:     Started server process [21]
INFO:     Application startup complete.
```

`/openapi.json`のtitleを確認したところ、変更後のタイトル（`naw-server FastAPI
(hot-reload-test)`）が反映されていた。

✅ コンテナ再起動なしにソースの変更が反映されることを確認した（確認後、変更は元に戻した）

### Step 3: frontend-angularのホットリロード

ログイン画面テンプレート（`login.component.html`）の`alt`属性を一時的に変更したところ、
数秒後に以下のログが出力された。

```
Component update sent to client(s).
```

✅ コンテナ再起動なしにソースの変更（HMR）が反映されることを確認した
   （反映まで数秒のタイムラグあり。確認後、変更は元に戻した）

### Step 4: ブラウザ（frontend-angular）からbackendへの疎通

`http://localhost:4201/auth/login`（frontend-angularのプロキシ経由）へPOSTしたところ、
`http://localhost:8001`へ直接叩いた場合と同じレスポンス（`session_id` Cookie発行含む）が
返った。

```
HTTP/1.1 200 OK
set-cookie: session_id=...; HttpOnly; Max-Age=7200; Path=/; SameSite=lax
{"id":"admin","name":"管理者","role":"ADMIN","loginStatus":"SUCCESS",...}
```

✅ frontend-angular（コンテナ）→backend（コンテナ、コンテナ間通信経由）のプロキシが
   正常に機能することを確認した

### Step 5: ホスト直接起動フローとの併存

- `docker-compose.yml`への追加は既存の`postgres`・`redis`サービス定義に影響しない
- `proxy.conf.local.js`は`BACKEND_PROXY_TARGET`環境変数が未設定の場合、従来通り
  `http://localhost:8001`にフォールバックすることを`node -e`で確認済み（実装時に確認）
- `backend/Dockerfile.dev`・`frontend-angular/Dockerfile.dev`はいずれも新規ファイルであり、
  既存の`uvicorn --reload`（ホスト直接実行）・`npm start`のコマンド自体は変更していない

✅ 既存のホスト直接起動フローに影響がないことをコードレビューで確認した
