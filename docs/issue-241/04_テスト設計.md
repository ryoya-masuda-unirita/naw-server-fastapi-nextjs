# 04_テスト設計

## テスト方針

CI 定義の追加のため、自動テストコードは追加しない。手元で CI と同じコマンドを実行して通ることと、PR 上で実際にワークフローが起動・成功することで確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 依存インストール | lockfile どおりにインストールする | 成功する |
| 2 | lint | lint スクリプトを実行する | 指摘 0 件で成功する |
| 3 | 型チェック | type-check スクリプトを実行する | エラー 0 件で成功する |
| 4 | 単体テスト | test スクリプトを 1 回実行モードで実行する | 全件成功する |
| 5 | ビルド | build スクリプトを実行する | 成功し成果物が出力される |
| 6 | ワークフロー定義 | 定義ファイルを YAML として読み込む | 構文エラーがない |
| 7 | PR トリガー | ワークフロー自身を含む PR を develop 向けに作成する | 新しいワークフローが起動し、チェックが成功する |
