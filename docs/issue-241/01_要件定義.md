# 01_要件定義

## 背景

- 2026-11-12 に開発方針が「バックエンドとフロントエンドを並行して進める」に変わり、フロントエンドの PR が増える
- 現状、フロントエンドの検証（lint・単体テスト・ビルド）は develop へのマージ後に走るデプロイワークフローの中でしか行われない。壊れた変更がマージされてから初めて気づく（しかもデプロイが止まる）
- 型チェックはどの CI でも実行されていない（ビルドの中で一部行われるのみ）

## 機能要件

| No | 要件 |
|---|---|
| 1 | フロントエンドに変更がある PR（向き先: develop / main）で CI が自動実行されること |
| 2 | develop への push（PR のマージを含む）でフロントエンドに変更がある場合も CI が実行されること |
| 3 | CI では、依存のインストール（lockfile どおり）・lint・型チェック・単体テスト・ビルドを実行すること |
| 4 | いずれかが失敗した場合、PR のチェックが失敗として表示されること |
| 5 | フロントエンドに変更がない PR / push では実行されないこと（CI ワークフロー自身の変更は除く） |
| 6 | 実行するコマンドは、フロントエンドのパッケージ定義のスクリプトと揃え、手元でも同じコマンドで再現できること |

## 非機能要件

- 既存のバックエンド CI と書き方（トリガーのパス指定、ランタイムのバージョン指定、依存キャッシュ、日本語コメント）を揃える
- ランタイム（Node）のバージョンはデプロイワークフローと同じにする
- シークレットを使わずに実行できること
- ワークフローのトークン権限は読み取りのみに絞る

## スコープ外

- E2E テスト（ブラウザを使ったテスト）の CI 化
- カバレッジの計測・閾値チェック
- ブランチ保護（required checks）への登録（リポジトリ設定のため、必要ならユーザーが行う）
- デプロイワークフローの処理内容の変更
