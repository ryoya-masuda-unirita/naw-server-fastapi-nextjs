# 05_テスト詳細設計

テスト名は英語、意図は日本語 docstring（1 行）。偽物は次のとおり。

| 偽物 | 差し替える対象 | 使うテスト |
|---|---|---|
| `FakeRuntime` | 検索アダプタが呼ぶ `CoreRetrievalRuntime`（リクエストを記録し結果を返す） | `retrieval-adapter/tests/test_app.py` |
| `FakeSearchClient` / `FixedEmbedding` | `CorePostgreSqlSearchClient`（DB）とクエリの埋め込み | core の provider・hybrid、エミュレーター |
| `FakeConnection` / `FakeCursor` | `psycopg` の接続（SQL とパラメータを記録） | SQL の形のテスト |
| `FakeGateway` / `FakeOperations` | `PgroongaSearchGateway`（PGroonga の入口と準備状況） | hybrid |
| `FakeGraphClient` | AGE への問い合わせ | hybrid・Graph |
| `ScriptedChat` | リランクの LLM 呼び出し | リランク |
| `respx` | Azure AI Search・埋め込み API の HTTP | Azure・埋め込み |

## 重要なケース

| ケース | 期待 |
|---|---|
| 出力モード 0 | `"a"\t"b"\n` を `OUTPUT_DIR/<ビュー名>` に書く。core には PostgreSQL・件数・接続先・埋め込み設定が渡る |
| 出力モード 1 | `schemaVersion:1`・`contexts`（`sourceFilePath` は安全なときだけ）。stale/deleted の ID は出さない。21 件目以降・9000 文字の本文は切る |
| Graph の根拠 | `A --BUSINESS_RELATIONSHIP(ev-1)--> B` が `path` のノード/エッジ交互になる。深さが合わない・`graphOnly` のものは除く |
| 失敗の例外 | `PGROONGA_UNAVAILABLE [RETRIEVAL_READINESS_PGROONGA]: …`、それ以外は `RETRIEVAL_CORE_FAILURE` |
| 必須プロパティ | PostgreSQL は 12・41・42・43・44、SecuAiGent は 0・1・2・3 が足りなければ名前を並べて失敗 |
| Graph/Hybrid + 非 PostgreSQL | `available only for PostgreSQL(PGVector)` で失敗 |
| PGroonga の準備 | 拡張なし/インデックスなし/実行計画で未使用 → それぞれ `PGROONGA_*` の失敗（ベクトルだけの成功にしない） |
| Graph の失敗 | データなし `GRAPH_DATA_MISSING`、業務上の関係なし `BUSINESS_GRAPH_DATA_MISSING`、AGE/graph 不可 `GRAPH_UNAVAILABLE`、他は `GRAPH_QUERY_FAILURE` |
| リランク | 適用 / 失敗・空・不正順は `degraded`（ベクトルだけの並びに戻す）/ 設定不正は `RERANK_PROVIDER_CONFIGURATION_INVALID` |
| 秘密 | 失敗の要約・ログにパスワード・API キー・応答本文が出ない |
| エミュレーター | 設定の検証（予約名・同時指定・未知の名前・不正値）、`rag-context.json` が index 6、許可ルートがジョブのディレクトリ、ログの順序 |
