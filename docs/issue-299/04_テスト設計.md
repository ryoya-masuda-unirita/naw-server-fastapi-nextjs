# 04_テスト設計

## 方針

- 実際の DB・Azure・LLM には接続しない。DB への問い合わせ（検索クライアント・PGroonga・AGE・接続）と HTTP（`respx`）、チャットはテストの中で偽物に差し替える
- 移植元の Java のテストのうち、今回の範囲に当たる振る舞いを Python のテストに移す（各テストファイルの先頭に、どの Java のテストに当たるかを書く）。ソースの文字列を読むテスト・依存の向きを見るテスト（`*DependencyBoundaryTest`・`*ScopeGuardTest` など）は移さない
- 実 DB のテストは `NAW_RETRIEVAL_REAL_DB` を設定したときだけ動く（通常は skip）。手元の `onprem/vector-db` と同じ構成の Docker で確かめ、結果を 08 に貼る
