# 01_要件定義

## 背景

学習データ詳細画面の「学習データを追加」でファイルをアップロードすると、常に 422 エラーになる。画面はファイル本体だけを multipart/form-data のボディで送り、`name`・`displayName`・`reference`・`splitLength` は URL のクエリパラメータで送っている。一方、バックエンドはこれらを multipart のフォーム項目からしか読み取らないため、必須の `name` が無いと判定している。

移植元（Spring Boot）のファイル追加・更新 API は、リクエスト項目を `@ModelAttribute`（`UpdateFileRequest`）で受け取る。`@ModelAttribute` は Servlet のリクエストパラメータ（クエリ文字列と multipart / フォームのボディ項目の両方）から値を取るため、クエリで送られても、ボディで送られても同じように受け付ける。

ファイル更新（PATCH）も同じ受け取り方になっており、画面はファイル未添付のメタデータ更新時に `displayName` 等をクエリで送る。現状のバックエンドはこれを読み取れないため、エラーにはならないが更新内容が黙って無視される。

## 機能要件

- ファイル追加 API（POST）で、`name`・`displayName`・`reference`・`splitLength`・`status` をクエリパラメータ・multipart フォーム項目のどちらで送っても受け付けること
- ファイル更新 API（PATCH）でも同様に、どちらで送っても受け付けること
- 同じ項目がクエリとフォームの両方にある場合は、フォーム項目の値を優先すること
- ファイル追加時に `name` がクエリ・フォームのどちらにも無い、または空文字の場合は 400 エラーとすること
  - 当初は従来どおり 422 とする設計だったが、code-review で「依存関係の解決中に 422 を返すと認証（401/403）より先にエラーになる」と指摘されたため、認証後のサービス層で検証し、置換更新時の `name` 必須チェックと同じ 400 に揃えた（`code-review.md` 参照）
- 未認証のリクエストは、入力内容にかかわらず従来どおり 401 となること
- 既存のフォーム項目での送信は従来どおり動作すること

## 非機能要件

- DB スキーマ変更を伴わないこと
- レスポンス形式は変更しないこと

## スコープ外

- フロントエンド（`frontend-angular/`・`frontend/`）の変更
- 上流 client の最新版（NAW-1290 以降）はファイル追加時に `name` を送らない。移植元でも `files.name` は NOT NULL のため、`name` 無しの追加は失敗する（移植元では保存時のエラー、本対応後のバックエンドでは 400）。`name` 未指定時の補完は移植元にない仕様のため、本 Issue では扱わない
- 移植元の `splitLength` の範囲検証・分割長変更時の再学習（コンテンツ分割・埋め込みの移植範囲）
- 移植元の「添付ファイルなしの更新で `name` を指定したら 400」の検証
