# 04_テスト設計

## テスト方針

ファイル追加・更新 API を結合テスト（インメモリ SQLite・一時ディレクトリのストレージ）で呼び出し、画面と同じ送り方（ファイル本体はボディ、その他はクエリ）で受け付けられることを検証する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 追加（クエリ送信） | ファイル本体をボディ、`name`・`displayName`・`reference` をクエリで送る | 200 で追加され、送った値が保存される |
| 2 | 追加（`name` 未指定・空文字） | ファイル本体のみ送り `name` をどこにも指定しない／`name` を空文字で送る | 400（`name` が必須） |
| 2-2 | 認証の優先 | 未認証で `name` を指定せずに送る | 401（入力エラーより認証エラーが先） |
| 3 | 追加（両方に指定） | 同じ項目をクエリとフォームの両方に異なる値で送る | フォームの値が採用される |
| 4 | 更新（クエリ送信） | ファイル未添付で `displayName`・`reference`・`status` をクエリで送る | 200 で各値が更新される |
| 5 | 既存動作の維持 | 既存のフォーム送信のテスト | すべて成功する |
