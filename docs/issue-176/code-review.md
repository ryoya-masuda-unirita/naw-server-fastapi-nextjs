## 詳細

### 1. 認証より先に 422 が返る（🔴 致命的）→ 対応済み

依存クラスの `__init__` での例外送出をやめ、`name` の必須チェックを `FileService.create_file` の先頭に移した。サービスは認証・認可の依存の解決後に呼ばれるため、未認証なら 401、権限なしなら 403 が先に返る。置換更新（`update_file`）の `name` 必須チェックと同じく 400（`ファイルをアップロードする場合、nameは必須です。`）で返す。

`test_upload_without_name_and_auth_returns_401` を追加し、対応前の実装では失敗する（422 になる）ことを確認した。

### 2. 入力エラーがまとめて返らない（🟡 注意）→ 対応済み

1 の対応で依存クラスから例外を送出しなくなったため、FastAPI 標準の入力検証（`file` 欠落等）は従来どおりまとめて返る。

### 3. フォーム優先が移植元と異なる（🟡 注意）→ 対応しない

移植元で同じ項目をクエリとボディの両方に送るとカンマ連結された値になるが、これは Servlet のパラメータ結合による副作用であり、画面・テストとも意図して使っていない。連結値（`query,form`）は表示名・参照として意味を持たないため、再現はせず「ボディ優先」を明示的な仕様とした。

### 4. 定義の重複（🔵 提案）→ 対応済み

`name` の必須チェックをサービスへ移したことで両クラスの受け取り方が同一になったため、`FileUploadForm` を `FileUpdateForm` の派生クラスにして定義を 1 か所にまとめた。

### 5. 汎用依存への置き換え（🔵 提案）→ 対応しない

`Request` から読む汎用依存にすると、OpenAPI 上で項目と型が見えなくなり、FastAPI の宣言的な入力定義から外れる。現時点で同様の受け取り方が必要なのはファイル追加・更新のみのため、明示的な `Form()`/`Query()` 宣言を維持する。

### 6. エラーの `loc` が実態と合わない（🔵 提案）→ 対応済み

1 の対応で手作りの `RequestValidationError` を廃止し、「`name` は必須」という日本語メッセージの 400 に変えたため、送り方（ボディ・クエリ）に依存しないエラーになった。

### 7. 空文字 `name`（🟡 注意）→ 対応済み

`create_file` のチェックを `if not form.name` とし、未指定（None）と空文字の両方を 400 で拒否する。`test_upload_with_empty_name_returns_400` を追加した。
