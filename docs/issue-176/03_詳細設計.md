# 03_詳細設計

## 実装対象ファイル

| ファイル | 変更内容 |
|---|---|
| `backend/app/schemas/file.py` | `FileUpdateForm` の各項目を `Form()` と `Query()` の両方で宣言し、フォーム優先で採用する。`FileUploadForm` は受け取る項目が同じため `FileUpdateForm` を継承する |
| `backend/app/services/file_service.py` | `create_file` の先頭で `name` の必須チェック（未指定・空文字なら 400）を行う |
| `backend/tests/integration/test_files.py` | クエリパラメータで送った場合のテストを追加 |

ルーター（`routers/files.py`）は、`form.name` 等の属性名を変えないため変更不要。

## 実装内容

- 各項目を「フォーム側引数（`Form(alias=...)`）」と「クエリ側引数（`Query(alias=...)`）」の 2 つで受け取り、`_prefer_form(form_value, query_value)` でフォームの値（`None` でなければ）を優先する
  - alias は移植元の項目名（`name`・`displayName`・`reference`・`splitLength`・`status`）とする
- `FileUploadForm` の `name` 必須チェックは依存クラスでは行わず、`FileService.create_file` の先頭で `if not form.name` を判定して 400（`ファイルをアップロードする場合、nameは必須です。`）を返す
  - 依存クラスの `__init__` で例外を送出すると、ルーター引数の並び順により認証の依存（`get_verified_tenant_id`・`require_admin_or_group_admin`）より先にエラーが返り、未認証でも 401/403 にならないため（code-review 🔴 指摘）
  - 置換更新（`update_file`）の `name` 必須チェックと同じ 400 に揃える
- 属性名（`self.name`・`self.display_name`・`self.reference`・`self.split_length`・`self.status`）は変えない

## 移植元の根拠

- `server/src/main/java/com/example/naw/api/FileController.java` の `uploadFile` / `updateFile`（`@ModelAttribute UpdateFileRequest dto`）
- `server/src/main/java/com/example/naw/request/UpdateFileRequest.java`（`name`・`displayName`・`reference`・`splitLength`・`status`・`file`）
- `server/src/test/java/com/example/naw/integration/FileIT.java`（`.param("name", ...)` 等で送信）
- 上流 client `training-api.service.ts` の `uploadFile` / `updateFile`（`file` のみ `FormData`、その他は `params:`＝クエリ）
