# 02_基本設計

## 変更対象

- ファイル追加・更新のリクエスト受け取り（リクエストスキーマ）

## 画面 / API 変更概要

| API | 変更内容 |
|---|---|
| `POST /api/admin/indexes/{indexId}/files` | `name`・`displayName`・`reference`・`splitLength`・`status` をクエリパラメータでも受け付ける |
| `PATCH /api/admin/indexes/{indexId}/files/{id}` | 同上 |

- ファイル本体（`file`）は従来どおり multipart のボディで受け取る
- 値の優先順位: multipart フォーム項目 → クエリパラメータ
- レスポンス・エラー形式は変更しない（`name` 未指定時は従来と同じ 422 の `missing` エラー）

## 影響範囲

- ファイル追加・更新 API の入力の受け取り方のみ。業務ロジック（保存・置換・論理削除等）は変更しない
- 既存のフォーム項目での送信（テスト・他クライアント）はそのまま動く

## 移植方針

- 移植元 `FileController.uploadFile` / `updateFile` は `@ModelAttribute UpdateFileRequest` で受け取る。`@ModelAttribute` はクエリ文字列とボディのどちらのリクエストパラメータからもバインドするため、FastAPI 側でも両方を受け付ける
- 移植元 `FileControllerTest`・`FileIT` も `MockMvc` の `.param(...)`（リクエストパラメータ）で `name` 等を送っており、送り方を区別していない
