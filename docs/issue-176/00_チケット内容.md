# 学習データファイルの追加がバックエンドとのパラメータ不一致で常に失敗する

## 概要

GitHub Issue #176 の内容を転記する。

## 説明

### 概要
学習データ詳細画面で「学習データを追加」からファイルをアップロードすると、常にHTTP 422エラーとなりファイルが追加されない。

### 原因
- `frontend-angular/src/app/features/admin/management/training-data/services/training-api.service.ts`の`uploadFile()`（95〜102行目）が、`file`のみを`FormData`のボディに含め、`displayName`/`name`/`splitLength`/`reference`はHTTPクエリパラメータ（`params:`）として送信している
- バックエンド`backend/app/routers/files.py`の`upload_file`は`form: FileUploadForm = Depends()`を受け取るが、`FileUploadForm`（`backend/app/schemas/file.py`36行目〜）の各フィールドは`Annotated[str, Form()]`でmultipart/form-dataのボディフィールドとして定義されている
- クエリパラメータとして送られた`name`等はFastAPI側のフォームフィールドにバインドされず、必須の`name`フィールドが未指定として扱われ`{"detail":[{"type":"missing","loc":["body","name"],"msg":"Field required","input":null}]}`という422エラーになる

### 発見経緯
Issue #166（E2Eテスト自動化）の17_学習データカテゴリ実装中、「学習データを追加」のE2Eテスト（`frontend-angular/e2e/learning-data.spec.ts`）作成時に発見。実際にファイルアップロードダイアログから追加操作を行うと、ネットワークタブで422エラーが確認できる。

### 対応方針案
`uploadFile()`で`displayName`/`name`/`splitLength`/`reference`を`params`ではなく`FormData`に`formData.append(...)`で追加し、multipart/form-dataのボディとして送信するよう修正する。

### 本Issueでは対応しない
Issue #166はE2Eテスト自動化基盤の整備が目的のため、本バグの修正はこのIssueのスコープ外とする。学習データ追加に関連するE2Eテストケース（項番6・28・31）は`test.skip`としてこのIssueへの参照コメントを残す。
