# 01_要件定義

## 背景

Bedrock（Claude）を使う RAG は、回答の生成で「JSON（`answer` と `id`）」で返すようモデルに頼み、その JSON を読んで、参照元の ID を確かめ、さらに検証の呼び出しで回答の正しさを確かめてから、画面に返す。OpenAI 系は、JSON 形式の出力をプロトコルで指定できるため、必ず純粋な JSON が返る。Bedrock の Messages API にはその指定がなく、Claude は JSON をコードフェンスで包んだり、頼んでいないキーを足したりして返す。そのため、中身が正しくても、読み取りに失敗して却下される。

## 機能要件

| No | 要件 |
|---|---|
| F1 | Bedrock の RAG の回答の返答が、前後にコードフェンス（`` ```json ``・`` ``` ``）を持っていても、中の JSON を読んで、回答と参照 ID を取り出せる |
| F2 | 返答の JSON に、頼んでいないキー（例: `question`）があっても、読める（`answer` と `id` を使う） |
| F3 | 検証（`rag-validation`）の返答も、同じ形式の揺れ（フェンス付きなど）があっても、読める |
| F4 | JSON の前後に、短い説明文があっても、中の JSON オブジェクトを取り出せる |
| F5 | 本当に読めない返答（JSON がない、`answer` や `id` がない・型が違う）は、従来どおり却下する（検証を通らない回答を通さない） |
| F6 | 通常のチャット（RAG でない回答）の本文は、変えない（フェンスを取り除かない） |
| F7 | OpenAI 系・Azure・SecuAiGent の読み取りの挙動は、変えない |

## 非機能要件

- 既存のテスト（Bedrock・OpenAI 系・RAG の検証）の結果が変わらない
- Bedrock の部品は、目印（`bedrock-ext`）つきの範囲に収め、取り除いても既存のテストが通る（#436 と同じ）
- 追加・変更する関数に、日本語の NumPy 形式の docstring を書く。テストのメソッド名は英語、意図は日本語の docstring
- 外部通信を行うテストはモックで行い、本物の Bedrock には接続しない

## スコープ外

- Anthropic の構造化出力（JSON の形式の強制）やツール呼び出しへの切り替え（Bedrock Mantle の対応を確認できていないため。別の Issue で検討する）
- RAG のプロンプトの変更（モデルの従順さに頼らず、読み取り側で対応する）
- 回答の品質の評価、検索の改善
