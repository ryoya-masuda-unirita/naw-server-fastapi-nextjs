## 変更の中身

### `json_payload(text)`

```python
_FENCE = re.compile(r"^```[A-Za-z0-9_-]*[ \t]*\n?(?P<body>.*?)\s*```$", re.DOTALL)

def json_payload(text: str | None) -> str | None:
    if text is None:
        return None
    stripped = text.strip()
    fenced = _FENCE.match(stripped)
    if fenced is not None:
        stripped = fenced.group("body").strip()
    if _is_json(stripped):
        return stripped
    start, end = stripped.find("{"), stripped.rfind("}")
    if 0 <= start < end and _is_json(stripped[start : end + 1]):
        return stripped[start : end + 1]
    return stripped  # 読めないものは、そのまま渡す（従来どおり、読み取りで却下される）
```

- `_is_json(text)`: 既存の `loads_with_raw_numbers`（`openai_compatible.py`）で読めるかを返す。例外（`ValueError`）は、読めないものとして `False` にする。読み取りと同じ関数で判定するため、数値の扱い（`RawNumber`）が食い違わない
- 純粋な JSON は、そのまま返す（変えない）
- フェンスは、言語名つき（`` ```json ``）と、なし（`` ``` ``）の両方を取り除く
- 前後の説明文は、最初の `{` から最後の `}` までを取り出す。取り出したものが JSON として読めたときだけ使う
- 読めないものは、前処理をしても読めないため、従来どおり `parse_rag_answer`・`validation_passed` が `None`・`False` を返し、却下される（検証を通らない回答を通さない）

### `rag` での使い方

```python
answer = parse_rag_answer(json_payload(extract_text(answer_body)))
...
validation_text = json_payload(extract_text(validation_body))
```

- 参照 ID の範囲の確認（`references_in_range`）、検証の呼び出し、`CoreChatResult` の作り方は変えない
- `余分なキー`（`question` など）は、`parse_rag_answer` が `answer` と `id` だけを見るため、前処理なしでも読める。テストで確かめる
