# Bedrock の RAG の回答がコードフェンス付きの JSON で返り、形式の検証で却下される

## 概要

Bedrock（Claude）の RAG の回答が、形式の検証で却下され、検索で文書が見つかっているのに、定型文「提供された情報からは答えが分かりませんでした。別の情報媒体で調べてみてください。」が返る。Claude の返答の読み取りを、形式の揺れに強くする。

## 説明

- オンプレの実機で、検索はできている（`contexts=1`）が、回答の段階で `rag answer rejected: provider=Bedrock` になる。`rag-answer` の呼び出し 1 回のあと、検証（`rag-validation`）の呼び出しがない
- コンテナの中で、実際の経路を再現し、Claude の返答の生の文字列を確かめた。中身は正しい（`"answer": "パスワードは12文字以上にする必要があります。"`、`"id": [1]`）が、`` ```json `` と `` ``` `` のコードフェンスに包まれ、頼んでいない `"question"` キーも付いている
- 回答を読む処理は、純粋な JSON だけを受け付けるため、フェンス付きの返答を読めず「回答なし」として却下する。OpenAI 系は JSON 形式の出力を指定できるが、Anthropic の Messages API には同じ指定がなく、Claude が自然な形（フェンス付き）で返す
- 画面では、学習データを使った回答が得られない
