# 04_テスト設計

## テスト方針

外部通信はモックで行い、本物の Bedrock には接続しない。実機の返答（#454 の再現で得た文字列）を、そのままテストの入力に使う。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 純粋な JSON | 前後にフェンスも説明もない JSON | 変わらずに返る |
| 2 | フェンス（言語名つき） | `` ```json `` と `` ``` `` で包まれた JSON | 中の JSON が返る |
| 3 | フェンス（言語名なし） | `` ``` `` と `` ``` `` で包まれた JSON | 中の JSON が返る |
| 4 | 前後の説明文 | 「次のとおりです。」＋ JSON ＋「以上です。」 | 中の JSON が返る |
| 5 | 文字列の中の括弧 | `answer` の値に `{`・`}` を含む JSON（フェンス付き） | 中の JSON 全体が返る（値の途中で切れない） |
| 6 | 読めない返答 | JSON を含まない文章 / 閉じていない `{` | 前処理後も読めず、そのまま返る（読み取りで却下される） |
| 7 | 空・None | `None` / 空文字 | `None` は `None`、空文字は空文字 |
| 8 | RAG の成功（実機の返答） | 回答の返答が、実機のフェンス付き＋余分な `question` キーの文字列で、検証の返答が `{"answer":true}` | 検証が呼ばれ、回答が成功になり、参照元が付く |
| 9 | RAG の検証の返答がフェンス付き | 検証の返答が `` ```json {"answer": true} ``` `` | 検証を通り、回答が成功になる |
| 10 | RAG の却下（形式の誤り） | フェンス付きだが `id` がない / `answer` がない | 従来どおり、回答なしになる |
| 11 | RAG の却下（検証が偽） | 検証の返答がフェンス付きの `{"answer": false}` | 回答なしになる |
| 12 | 通常のチャットは変えない | チャットの返答が、フェンス付きのコードを含む文章 | 本文がそのまま返る（フェンスを取り除かない） |
| 13 | 回帰 | 既存のテストをすべて実行する | Bedrock・OpenAI 系・RAG の既存のテストの結果が変わらない |
