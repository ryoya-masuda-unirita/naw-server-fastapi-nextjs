## スキーマ（`PasswordResetRequest`）

- フィールドの型（`str`）とエイリアス（`loginId` / `username`）は変えない
- `model_validator(mode="before")` で、フィールドの型チェックより前に次の順で検査する。最初に見つかった不備で `ValueError(メッセージ)` を送出する
  1. `loginId`（なければ `username`）→「ログインIDの入力は必須です。」
  2. `oldPassword` →「旧パスワードの入力は必須です。」
  3. `newPassword` →「新パスワードの入力は必須です。」
- 値が `None`・未指定・文字列で `strip()` 後に空ならエラー。文字列以外（数値など）はここでは判定せず、後続の型チェックに任せる
- `field_validator` は未指定のフィールドに対して実行されないため、未指定も同じメッセージにするために `model_validator(mode="before")` を使う
- `ValueError` は共通ハンドラ（`app/core/errors.py`）で 400・メッセージそのまま（`Value error, ` の接頭辞を除去）になる
- `username` と `loginId` の両方がある場合は Pydantic の `AliasChoices` と同じく `loginId` を優先して判定する

## 設定（`PasswordResetSettings`）

移植元 `PasswordResetProperties`（`password-reset.*`）に対応。`Settings` とは別クラス（`LlmCreditSettings` と同じ理由）。

| フィールド | 環境変数 | 既定値 |
|---|---|---|
| `max_failure_attempts: int`（1 以上） | `PASSWORD_RESET_MAX_FAILURE_ATTEMPTS` | 5 |
| `lockout_minutes: int`（1 以上） | `PASSWORD_RESET_LOCKOUT_MINUTES` | 15 |

0 以下だと全員が常にロック中になる、またはロックが掛からなくなるため、`ge=1` で起動時に拒否する（code-review #4）。

`get_password_reset_settings()` は他と同じく `lru_cache` 付き。

## 失敗記録（`app/core/password_mismatch_store.py`）

移植元 `PasswordResetAttemptService` + `PasswordMismatchHistoryRepository` に相当。`session_store.py` と同じく `core/` に置く（`auth_service` から呼ぶため。service から service は呼ばない規約）。

- キー: `password_mismatch:{tenant_id}:{user_id}`（sorted set）
- メンバー: 失敗ごとの一意な ID（`uuid4().hex`）、スコア: 失敗時刻（UNIX 秒、float）

| 関数 | 処理 |
|---|---|
| `is_locked_out(user_id, tenant_id, max_attempts, lockout_minutes, redis_client) -> bool` | スコアが `now - lockout_minutes*60` より大きい（移植元 `createdAtAfter` と同じく境界を含まない）件数を `ZCOUNT` で数え、`max_attempts` 以上なら `True` |
| `record_failure_and_check_lockout(...) -> bool` | トランザクション付きパイプラインで `ZADD`（今回の失敗）・`ZREMRANGEBYSCORE`（ロック時間より古い記録を削除）・`EXPIRE`（ロック時間）・`ZCOUNT` を実行し、`ZCOUNT` の結果が `max_attempts` 以上なら `True` |
| `clear_failures(user_id, tenant_id, redis_client) -> None` | キーを削除 |

## サービス（`AuthService.reset_password`）

引数の末尾に `redis_client: redis.Redis` を追加。処理順は移植元 `PasswordResetService.resetPassword` に合わせる。定数 `INVALID_CREDENTIALS_MESSAGE = "ログインIDまたは旧パスワードが正しくありません。"`、`PASSWORD_RESET_LOCKED_MESSAGE` をサービスに置く。

1. ユーザー取得。なければ 403 `INVALID_CREDENTIALS_MESSAGE`（失敗は記録しない。移植元はユーザーIDがないため記録できない）
2. `is_locked_out` が `True` なら 429 `PASSWORD_RESET_LOCKED_MESSAGE`
3. 最新のパスワード履歴がなければ 403 `INVALID_CREDENTIALS_MESSAGE`（失敗は記録しない。移植元どおり）
4. 旧パスワード不一致なら `record_failure_and_check_lockout`。`True` なら 429、`False` なら 403 `INVALID_CREDENTIALS_MESSAGE`
5. テナント取得・ポリシー・履歴チェック・保存（既存のまま）
6. コミットの直前に `clear_failures`。移植元は同一トランザクションの最後で削除し、削除に失敗すれば再設定ごと取り消す。コミット後に消すと Redis 障害時に「パスワードは変わったのにエラー応答」になるため、コミット前に消す（code-review #5）
7. コミット

例外は `HTTPException(status_code=..., detail=...)` で送出する（共通ハンドラが `{"timestamp", "message"}` に変換する）。

## ルーター

`reset_password` は既に `redis_client` を受け取っている（セッション発行用）ので、それを `AuthService.reset_password` に渡すだけ。
