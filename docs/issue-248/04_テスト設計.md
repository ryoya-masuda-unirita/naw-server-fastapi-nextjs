# 04_テスト設計

## テスト方針

自動テスト（単体・結合）で確認する。Redis はテスト用のインメモリ実装を使う。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 必須チェック | ログインID・旧パスワード・新パスワードのいずれかが未指定・null・空・空白のみ | 入力エラー。メッセージは移植元どおり |
| 2 | 必須チェック | 別名（username）で空のログインIDを送る | ログインIDの必須エラー |
| 3 | 必須チェック | 複数の項目が空 | ログインIDの必須エラー（先頭の 1 件） |
| 4 | 必須チェック（API） | 空のログインIDで再設定 | 400 と「ログインIDの入力は必須です。」 |
| 5 | 必須チェック（API） | ログインIDなしで再設定 | 400 と「ログインIDの入力は必須です。」 |
| 6 | 失敗記録 | 失敗なし | ロックされていない |
| 7 | 失敗記録 | 上限回数まで失敗を記録 | 上限未満ではロックされず、上限で初めてロックされる |
| 8 | 失敗記録 | ロック時間を過ぎた失敗 | 数えない |
| 9 | 失敗記録 | 記録の削除 | ロックが解除される |
| 10 | 失敗記録 | 別ユーザー・別テナント | 互いの回数に影響しない |
| 11 | 失敗記録 | 記録の有効期限 | ロック時間で自動的に消える設定になる |
| 12 | サービス | ロック中 | 旧パスワードが正しくても 429 とロックメッセージ |
| 13 | サービス | 旧パスワード誤りで上限に達した | 429 とロックメッセージ |
| 14 | サービス | 旧パスワード誤り（上限未満） | 403 と認証失敗メッセージ。失敗が記録される |
| 15 | サービス | ユーザーが存在しない | 403 と認証失敗メッセージ。失敗は記録されない |
| 16 | サービス | パスワード履歴がない | 403 と認証失敗メッセージ。失敗は記録されない |
| 17 | サービス | 成功 | 失敗記録が消える |
| 18 | API | 旧パスワードを上限回数誤る | 上限未満は 403、上限回目で 429 とロックメッセージ |
| 19 | API | ロック後に正しい旧パスワード | 429 で再設定されない |
| 20 | API | 何回か誤ったあと成功し、再度誤る | 成功で回数がリセットされ、上限未満の間は 403 |
| 21 | API | 存在しないログインIDと、存在するログインID + 誤った旧パスワード | どちらも 403 で同じメッセージ（ログインIDの有無が分からない） |
| 22 | API | 存在しないログインIDで上限回数以上再設定 | ずっと 403（存在しないユーザーの失敗は数えない） |
| 23 | 設定 | 未設定 | 5 回・15 分 |
| 24 | 設定 | 環境変数で指定 | 指定値になる |
| 25 | 回帰 | 既存の単体・結合テスト | すべて成功 |
