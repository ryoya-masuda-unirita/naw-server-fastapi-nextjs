# 01_要件定義

## 背景

- 画面の自動巡回（axe）で、#471〜#474 のあとにも、アクセシビリティの違反が残っている
- 違反の多くは、共通部品（行のメニュー、スイッチ、入力欄、並び替え）の不備で、1 か所を直すと、多くの画面から消える
- 一部（文字色）は、デザイントークンの変更で、デザインの判断が要る

## 機能要件

- 行の「…」メニューのトリガーに、名前（スクリーンリーダーが読める文言）を付ける。メニューを開いているかも伝える。名前は、呼び出し側が上書きできる
- メニューのパネルの中の項目が、メニューの項目として扱われるようにする（`menuitem`）。`ContextMenu` を使うすべての画面で
- スイッチに名前を付ける。見出し（`label`）があれば、それを名前にする。専用の名前（`switchLabel`）があれば、そちらを優先する
- タイトルの編集ボタン（鉛筆）に、名前を付ける
- 見出しつきの入力欄は、`inputId` がなくても、見出しと入力欄が結ばれるようにする
- 並び替え入力のモバイル（ドロワー）の選択肢が、メニューの項目として正しい親（`group`）の中にあるようにする
- 翻訳（日本語・英語）を足す
- 修正後、実画面で axe を再実行して、上の違反が消えることを確かめる

## 非機能要件

- 見た目・操作は変えない（名前・role・id を足すだけ）
- 既存の自動テストが通る。role の変更に伴うテストの修正は、最小限にする
- 呼び出し側を変えずに直せるものは、共通部品で直す

## スコープ外

- **文字色のコントラスト（`color-contrast`）**: デザイントークン（`--color-status-error`・`--color-status-caution`・`--color-text-lighter`）の変更で、デザインの判断が要る。この Issue では変えず、WCAG AA を満たす最小限の色の案を、PR に書く
- #471〜#474 で直した違反
- 画面幅 375px のはみ出し・「操作しても何も起きない」の疑い（原因未確認のため、別途）
- 「コードで確認」の 2 件（複数選択のチップの入れ子、モバイルの表の行の入れ子）は、axe が検出するかを確かめてから、扱いを決める（02 の「決定」に書く）
