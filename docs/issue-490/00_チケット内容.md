# #490 残っているアクセシビリティ違反を直す（axe）

## 概要

#471〜#474（axe の違反の修正）のあとに、E2E 探索（`e2e-explorer`、axe-core 4.14）の再実行でも残った違反を直す。#471〜#474 の PR（#484〜#487）で原因を特定できなかった、またはデザインの判断が要るため見送ったもの。

## 説明

### Issue の内容（要約）

- `button-name`（critical）: `/admin/tenant` の `.rounded`（8 件）、`/admin/users` の `button[data-e2e-explorer-id=21・23]`（3 件）。原因の要素は未特定
- `label`（critical）: `/admin/tenant` のテキストエリア（`.leading-[1.7]`、2 件）
- `aria-toggle-field-name`（serious）: `/admin/assistants` の `.app-switch`
- `aria-required-children`（critical）: `/admin/users` の `.p-4`
- `color-contrast`（serious）: エラー色（`#e92345`）の文字、`text-text-lighter` など（5 グループ）。デザイントークンの変更になるため、デザインの判断が要る
- `multi-select` のチップ削除ボタンが `combobox` の中にある入れ子（コードで確認）
- モバイル表示の表の行が `role="button"` で、中にチェックボックスがある入れ子（コードで確認）

期待する動き: ボタン・フォーム要素に名前がある。役割が必須の子要素・属性を満たす。文字色が WCAG AA（4.5:1）を満たす。操作要素を入れ子にしない。

### 原因の特定（調査して確認した事実）

E2E 探索の全体の再実行はせず、デモ環境（`docker-compose.demo.yml`。別プロジェクト・別ポート）に、Playwright + axe（`@axe-core/playwright` 4.14。探索と同じ）で、ページごとにボタンを順に操作して、状態ごとに走査した（デスクトップ 1280px・モバイル 375px）。違反の要素と HTML で、原因を特定できた。

| 原因 | 違反 | 場所 |
|---|---|---|
| A. 共通の `ContextMenu` のトリガー（行の「…」ボタン）に、名前がない | `button-name`（30 件超） | ユーザー、アシスタント、カテゴリ、テナントの API 設定の行 |
| B. `ContextMenu` のパネルが `role="menu"` なのに、呼び出し側の項目が `menuitem` でない（`button` のまま） | `aria-required-children` | ユーザーの行メニュー（デスクトップ・モバイル） |
| C. `FormSwitch` が、`label` を持つのに、スイッチ本体（`role="switch"`）に名前を渡していない（`switchLabel` が空） | `aria-toggle-field-name` | アシスタントの新規作成ダイアログ（履歴の送信） |
| D1. `page-header` のタイトル編集ボタン（鉛筆アイコン）に名前がない | `button-name` | `/admin/tenant`（ワークスペース名） |
| D2. `FormInput` が、`label` を持つのに、`inputId`・`id` がないと `label` と `input` を結ばない | `label` | テナントの名前変更ダイアログ |
| E. 並び替え入力のモバイル（下からのドロワー）で、`menuitemradio` の親に `role="menu"` がない | `aria-required-parent`（7 件） | `/admin/users`・`/admin/assistants` の並び替え（375px） |
| F. 文字色のコントラスト不足 | `color-contrast` | エラー色 `#e92345`（4.38:1）、注意色 `#929200`（3.31:1）、`text-text-lighter` の `#adadad`（2.24:1） |

- Issue が「`.p-4`」とした `aria-required-children` は、`ContextMenu` のパネル（B）。「`.leading-[1.7]` のテキストエリア」は、実際は `FormInput` の `input`（D2）
- 移植元（Angular）の `ContextMenu` のテンプレートには、`aria-*` がまったくない。つまり、移植元から引き継いだ不備で、#471〜#474 と同じ種類の改善
- このプロジェクトの流儀: `ContextMenu` のパネルは `role="menu"` で、呼び出し側の項目に `role="menuitem"` を付ける（チャットのヘッダー、`page-header` はそうなっている）。付いていない呼び出し側が違反
- `ContextMenu` の利用箇所は 10 か所。`menuitem` が付いていないのは、テナントの API 設定、ライブラリ（項目・タグ）、アシスタントの行、フィードバック（正確・満足度）、ユーザーの行、テンプレートの 8 か所
