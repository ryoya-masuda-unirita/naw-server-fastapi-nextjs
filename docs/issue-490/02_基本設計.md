# 02_基本設計

## 変更対象

- 共通部品: 行のメニュー（`ContextMenu`）、スイッチ（`FormSwitch`）、見出しつきの入力欄（`FormInput`）、ページ見出し（`page-header`）、並び替え入力（`form-sort-input`）
- 呼び出し側: `ContextMenu` を使う 8 か所（メニュー項目に `menuitem` を付ける）
- 翻訳（日本語・英語）
- 自動テスト（共通部品と、変更した呼び出し側）

## 画面 / API 変更概要

- 画面の見た目・操作は変えない。スクリーンリーダーが読む名前・役割・関連付けを足すだけ
- API の変更はない

## 影響範囲

- 行のメニューを使うすべての画面（ユーザー、アシスタント、カテゴリ、テンプレート、ライブラリ、学習データ、フィードバック、テナントの API 設定）
- 見出しつきの入力欄を使うすべての画面（`id` がなかった入力欄に、自動で `id` が付く）
- スイッチ、ページ見出し、並び替え入力

## 移植方針

移植元（Angular）にはこれらの `aria-*` がない（移植元から引き継いだ不備）。#471〜#474 と同じく、移植先で改善する。

| 原因 | 方針 |
|---|---|
| A. メニューのトリガーに名前がない | `ContextMenu` に `triggerLabel`（任意）を足し、既定は翻訳の「メニューを開く」。`aria-expanded` も付ける |
| B. 項目が `menuitem` でない | `role="menu"` のパネルは変えず、呼び出し側の項目に `role="menuitem"` を付ける（チャットのヘッダー・`page-header` と同じ流儀） |
| C. スイッチに名前がない | `FormSwitch` が、`switchLabel` が空なら `label` を、スイッチ本体の名前にする |
| D1. タイトル編集ボタン | `aria-label` に、既存の翻訳「名前を変更」を使う |
| D2. 見出しと入力欄が結ばれない | `FormInput` が、`inputId`・`id` がなければ、`useId` で作った一意な id を使う |
| E. 並び替えのモバイル | ドロワーの選択肢の入れ物に `role="menu"` を付ける（デスクトップと同じ。axe の aria-required-parent を満たすため。背景の有無でデスクトップと区別する） |
| F. 文字色 | 変えない。最小限の色の案を PR に書く |

## 決定（全自動での判断）

- B は、`ContextMenu` の側で子要素の role を書き換える方法（DOM の操作）は取らず、呼び出し側に `role="menuitem"` を付ける。既存のテスト・チャットの実装と同じ流儀で、意図が明確なため
- F は、デザインの判断が要る（Issue の本文にもある）ため、この Issue の範囲外にする
- 「コードで確認」の 2 件は、実装の最後に、axe で検出されるかを確かめ、検出されるものだけを直す。検出されないもの・操作の設計の変更（行を押す動作の作り直し）が要るものは、直さず、PR に理由を書く
