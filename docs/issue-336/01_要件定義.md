# 01_要件定義

## 背景

移植した backend（FastAPI）と frontend（React）は、画面を見るだけでも、DB・Redis の起動、マイグレーション、seed の投入、backend と frontend の起動を手作業で行う必要がある（README の「ローカル疎通確認」は複数の手順に分かれ、ポートや環境変数の上書きも要る）。ユーザーが手元の Mac で画面を動かして理解するには、1 コマンドで起動できる環境が要る。

また、既存の `backend/seed.sql` は E2E の動作確認用（「〇〇確認用」という名前の行が中心）で、見て意味の分かる業務データになっていない。さらに、#307（ライブラリ本文を `library_contents` に分離）の後に `seed.sql` が更新されておらず、そのままでは流すと失敗する。

## 機能要件

- 1 コマンドで、DB・Redis・AWS の偽物・マイグレーション・seed・backend・frontend が起動する
- 起動後、`http://localhost:5173` でテナント ID・ユーザー ID・パスワードでログインし、管理画面を見られる
- 管理画面 9 画面（ユーザー・チーム・アシスタント・テンプレート・ライブラリ・学習データ・フィードバック・チャット履歴・ワークスペース）に、見て分かる架空の業務データが出る
- デモデータの投入は何度流しても増えない（`backend/seed.sql` の規約: `ON CONFLICT DO NOTHING`）
- SECURE のチャットを試すために `onprem/` をつなぐ手順を示す
- README に、ログイン情報・起動・停止のコマンド・見られる画面・困ったときの確認を短く書く
- `seed.sql` を、現在のスキーマ（`library_contents`）で流せるようにする

## 非機能要件

- 既存のローカル環境（`naw-fastapi-*` コンテナ、ポート 5433・6380・8001・5173、ボリューム `naw_fastapi_*`）と、コンテナ名・ボリューム・データが混ざらない
- ホストに公開するのは画面と backend のポートだけにし、ポートは環境変数で変えられる
- compose のコメントは、各サービスが何を表すかの 1 行だけにする（ユーザーの指示）

## スコープ外

- チャットの送信先（Azure OpenAI など）の実接続。接続先はダミーで、画面から新しい質問を送っても答えは返らない
- 学習データの取り込み処理・ベクトルDB の実接続
- 未移植の画面（チーム詳細など、現時点で枠だけの画面）の移植
- 本番・dev/staging 環境への展開
