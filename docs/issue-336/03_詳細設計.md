## docker-compose.demo.yml

- `name: naw-demo`。`container_name` は付けない（既存の `naw-fastapi-*` と衝突させない）。ボリュームは `pgdata` のみ（`naw-demo_pgdata`）
- backend のイメージは `backend/Dockerfile`（`--reload` なし、依存はロック済み）。`migrate` と `backend` が同じイメージ（`naw-demo-backend`）を使う
- `migrate`: `uv run --no-sync alembic upgrade head`
- `seed`: `postgres:18` のイメージの `psql` で `seed.sql` → `seed-demo.sql` の順に流す（`ON_ERROR_STOP=1`）。`backend` は `seed` の正常終了を待つ
- backend の環境変数: DB・Redis・localstack を compose のサービス名で指す。`CORS_ALLOWED_ORIGINS` は `http://localhost:${DEMO_FRONTEND_PORT:-5173}`
- frontend の環境変数: `VITE_API_URL=http://localhost:${DEMO_BACKEND_PORT:-8001}`（ブラウザから見た backend の URL。`frontend/.env` の `http://localhost:8000` を環境変数で上書き）
- ホストへの公開は `127.0.0.1` のみ。`postgres`・`redis`・`localstack` は公開しない（既存環境のポートと衝突しない）
- コメントは各サービスの上に「何を表すか」の 1 行だけ（ユーザーの指示）。ファイル先頭の説明は、既存の `e2e-explorer/docker/compose.yml` と同じく環境全体の説明として最小限にした

## backend/seed-demo.sql

- 規約は `seed.sql` と同じ。`\set ON_ERROR_STOP on`、固定 ID、`ON CONFLICT DO NOTHING`
- ID は 32 桁の hex（`d` + 種別 2 桁 + 連番）。ユーザー・ライブラリは UUID（`00000000-0000-4000-8000-0000000002NN`・`…0003NN`）
- 追加ユーザーの `password_histories` は、`admin` と同じ bcrypt ハッシュ（`admin@1234`）を使う。ユーザーごとに存在しないときだけ入れる
- 接続先は、学習データ用に `seed.sql` が作った `e1000…` のエンドポイント（LOCAL_SERVER・VDB・AZURE_OPENAI_EMBEDDING）と、デモ用に足した `AZURE_OPENAI_CHAT` 1 件を使う
- チャット履歴の更新日時は、`seed.sql` のルームより新しい順に並ぶよう、流した時刻の数秒先にずらす。クレジットの利用履歴は当月内に収まるよう数分前〜数時間前にする
- 管理者のライブラリ画面は自分のライブラリだけを出すため、ライブラリは管理者所有にする（元のチャットのルーム・メッセージも管理者のもの）

## backend/seed.sql の修正

#307 で `libraries.content` を `library_contents` に分けたが、`seed.sql` が更新されておらず `column "content" of relation "libraries" does not exist` で失敗していた。`libraries` の INSERT から `content` を外し、`library_contents (library_id, tenant_id, content)` の INSERT を足した（`ON CONFLICT (library_id) DO NOTHING`）。
