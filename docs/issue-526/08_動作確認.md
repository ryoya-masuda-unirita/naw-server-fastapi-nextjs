実際に確認した内容だけを書く。

## 再現（修正前の原因）

ボードの項目は、201 件（`--limit 1000` で数えた件数）。#526 の項目を、上限を変えて探した。

```
limit 200 : ''
limit 1000: 'PVTI_lAHODGxZQ84Bb8MszhL0Lw4'
```

`--limit 200` では見つからず、`--limit 1000` では見つかった。#524 では、Actions の「Reviewへ移動」が、`Project item for issue #524 was not found.` で失敗した（`gh run view --log-failed` で確認）。

## 修正後

| 確認 | 結果 |
|---|---|
| `bash -n`（2 つのスクリプト） | 文法に問題なし |
| `project_status_sync.sh --issue 526 --status "In Progress"` | `Updated issue #526 to 'In Progress'.` |
| `next_todo_issue.sh` | `519`（Todo の最小の番号）を返した |

## 最初の修正では Actions が直らなかった

最初の修正（`.claude/skills/` の 2 つのスクリプト）で PR #527 を作ると、Actions の「Reviewへ移動」が、`Project item for issue #526 was not found.` で失敗した。`project-status-sync.yml` を読むと、Actions は `.codex/skills/naw-issue-workflow/scripts/project_status_sync.sh`（Codex CLI 用のコピー）を実行していた。`.codex/` の 2 つのスクリプトにも、同じ修正を入れた（`grep -rn "limit 200" .codex .claude` で、残りが `gh issue list` だけであることを確認）。

## 確認していないこと

- 修正前のスクリプトで `#526` の同期を実行して `was not found` を再現すること。実行したが、`gh` が別のエラー（`unknown owner type`）で止まった（一時的な通信の失敗とみられる。同じエラーは、ほかの時にも数回出た）。原因の特定は、上の `item-list` の比較と、#524 の Actions のログで行った
- Actions での実行の結果は、PR を開き直したあとの「Reviewへ移動」と、マージ後の「Doneへ移動」で確かめる（結果は PR に書く）
