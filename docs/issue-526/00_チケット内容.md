# Projects のボードが 200 件を超えて状態の自動同期が失敗するのを直す

## 概要

GitHub Projects のボードの項目が 200 件を超えたため、新しい Issue の状態の自動同期が失敗する。スクリプトの取得件数の上限を引き上げる。

## 説明

- `project_status_sync.sh`（`start_issue.sh` と、Actions の `project-status-sync.yml` が使う）は、`gh project item-list --limit 200` でボードの項目を探す。ボードが 200 件を超えると、新しい Issue の項目が取得に入らず、`Project item for issue #N was not found.` で失敗する
- #524 で、Issue 着手時の `In Progress` と、PR 作成時の `Review`（Actions の「Reviewへ移動」）が失敗した。マージ後の `Done` も同じ原因で失敗する
- `next_todo_issue.sh`（naw-issue-loop が `Todo` を選ぶ）も、同じ `--limit 200` で、200 件目より後の `Todo` を見落とす

## その他

- 発見: #524。スコープ外: ボードのアーカイブ運用、`gh issue list --limit 200`（ラベル付き Issue の一覧）
