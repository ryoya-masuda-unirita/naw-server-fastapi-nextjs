# 01_要件定義

## 背景

onprem が渡す AZURE_OPENAI_API_VERSION を、エミュレーターが読まない。認証キーの .env.example のプレースホルダーが、日本語の文言で、コピーしたまま起動すると、その文字列がキーとして通る。AZURE_APP_* が ECS のタスク定義にない。e2e-spec の README の同時起動の例が Waha のポートと衝突する・前提が足りない。ほか、README・コメントの食い違い。

## 機能要件

- onprem の compose と .env.example から、効かない AZURE_OPENAI_API_VERSION を削除する
- waha-emulator・server-local の .env.example の認証キーのプレースホルダーを空にし、空のままだと起動時にエラーで止まる（設定の min_length=1）ことを書く
- secuaigent-infra の README に、AZURE_APP_*（Azure の利用料金の取得 API）が ECS に渡っておらず dev・staging では使えないことと、使うときの手順を書く
- e2e-spec の README: 同時起動の例のポートを 10 以上離し、Waha のポート（画面 +1〜+5）と E2E_SPEC_WAHA_PORT を書き、前提（uv・vector-db のビルド）を足す
- e2e-explorer の README のファイル一覧に errors.ts・types.ts を足す
- generative-ai-adapter の mypy のコメントに embedding-adapter を足し、README の VENDOR に 97（Bedrock）を足す
- server-local の download_file の docstring に、移植元と同じ挙動であること（500・RuntimeError）を明記する

## 非機能要件

- 既存の動作・自動テストを壊さない

## スコープ外

- e2e-spec と e2e-explorer の環境変数の接頭辞の統一（低）
- AZURE_APP_* を ECS に渡す実装（使う場合に別途）
