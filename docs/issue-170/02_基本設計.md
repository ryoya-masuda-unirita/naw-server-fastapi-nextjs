# 02_基本設計

## 変更対象

- バックエンド: 管理者向けテンプレート一覧取得 API（ルーター・サービス・リポジトリ）

## 画面 / API 変更概要

| API | 変更内容 |
|---|---|
| 管理者向けテンプレート一覧取得 | クエリパラメータ `sort`（任意、既定値 `updatedAt,desc`）を追加する。形式は `<項目>,<向き>` |

`sort` の解釈:

| 指定 | 並び順 |
|---|---|
| 未指定・空文字 | 更新日時の降順 |
| `name,asc` / `name,desc` | テンプレート名の昇順 / 降順 |
| `updatedAt,asc` / `updatedAt,desc` | 更新日時の昇順 / 降順 |
| 向きの省略（例: `name`） | 昇順 |
| 項目・向きの前後の空白 | 無視する |
| 対応外の項目 | 更新日時（向きは指定どおり） |

同じ値が並んだときは、テンプレート ID の昇順を第2キーにして順序を一意にする。

## 影響範囲

- 管理コンソールのテンプレート一覧画面: 並べ替えの選択が表示順に反映されるようになる。
- 管理コンソールのチーム詳細「テンプレート追加」モーダル: 同じ API を使い、上流 client は同じ形式で `sort` を送る。並べ替えの選択肢は「追加日時順（`addedAt`）」と「名前順（`name`）」。`name` は指定どおりに並ぶようになる。テンプレート自体には追加日時の項目がないため、`addedAt` は対応外の項目として更新日時順になる（既定の `addedAt,desc` は更新日時の降順で、従来の並びと同じ）。移植元はこの項目を並べ替えに使えず例外になるが、移植先では一覧が出なくならないよう更新日時順に倒す。
- 一般ユーザー向けテンプレート一覧 API: 変更なし。

## 移植方針

- 移植元の管理者向けテンプレート一覧は Spring Data の `Pageable` で `sort` を受ける。FastAPI では、既存のグループ一覧・アシスタント一覧と同じく文字列の `sort` クエリパラメータで受け、サービスで項目と向きに分け、リポジトリで並べ替え列に対応づける。
- 移植元は `sort` 未指定のとき並べ替えなし（DB 任せ）だが、移植先では従来の挙動と画面の初期値に合わせて更新日時の降順を既定にする。
