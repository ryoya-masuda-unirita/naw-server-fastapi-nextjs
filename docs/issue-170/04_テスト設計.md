# 04_テスト設計

## テスト方針

管理者向けテンプレート一覧 API を実際に呼び出す結合テスト（インメモリ SQLite）で並び順を確認する。サービスの単体テストでは、`sort` の分解結果がリポジトリへ渡ることを確認する。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 名前の昇順 | `sort=name,asc` | テンプレート名の昇順で返る |
| 2 | 名前の降順 | `sort=name,desc` | テンプレート名の降順で返る |
| 3 | 更新日時の昇順 | `sort=updatedAt,asc` | 更新日時の昇順で返る |
| 4 | 既定の並び順 | `sort` 未指定 | 更新日時の降順で返る（従来どおり） |
| 5 | 並べ替えとページング | `sort=name,asc`・1ページ2件で2ページ目 | 名前順の3〜4件目が返る |
| 6 | 向きの省略 | `sort=name` | 昇順で返る |
| 7 | 対応外の項目 | `sort=unknown,asc` | エラーにならず更新日時の昇順で返る |
| 8 | 同じ値の並び | 同名テンプレートが複数 | ID の昇順で一意に並ぶ |
| 9 | サービスの引数受け渡し | `sort=name,DESC` | リポジトリに項目 `name`・向き `desc` が渡る |
| 10 | 既存機能の回帰 | 既存テスト一式 | すべて成功する |
