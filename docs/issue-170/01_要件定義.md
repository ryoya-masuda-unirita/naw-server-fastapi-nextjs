# 01_要件定義

## 背景

管理コンソールのテンプレート一覧で並べ替え（テンプレート名順/更新日時順 × 昇順/降順）を選んでも、表示順が更新日時の降順のまま変わらない。

調べた結果、Issue 本文の想定とは原因が一部異なっていた。

- 画面（`frontend-angular`、上流 `secuaigent/client` と同じ実装）は、並べ替えの選択内容を一覧取得 API に `sort=<項目>,<向き>` の形（例: `name,asc`、`updatedAt,desc`）で**すでに送っている**。store の state に保持された値は、画面のフィルタ変更イベント経由で API サービスに渡され、クエリパラメータ `sort` に変換される。
- 移植元のバックエンド（Spring Boot）は、管理者向けテンプレート一覧 API でページング指定（Spring Data の `Pageable`）を受け取っている。そのため `sort=<プロパティ名>,<asc|desc>` を受け付け、指定どおりに並べ替える。
- 移植先のバックエンド（FastAPI）は `sort` を受け取っておらず、常に更新日時の降順で返していた。**原因はバックエンドだけにある。**

## 機能要件

1. 管理者向けテンプレート一覧取得 API は、クエリパラメータ `sort` を `<項目>,<向き>` の形式で受け付けること（移植元 Spring Data の `sort` パラメータと同じ形式）。
2. 項目は画面の選択肢にある「テンプレート名（`name`）」と「更新日時（`updatedAt`）」に対応すること。
3. 向きは `asc`（昇順）と `desc`（降順）に対応すること。大文字・小文字は区別しない（Spring Data と同じ）。向きを省略した場合は昇順とする（Spring Data と同じ）。
4. `sort` を指定しない場合は、従来どおり更新日時の降順とすること（画面の初期値「更新日時順・降順」と同じ）。
5. 並べ替えは検索・チームフィルタ・除外グループフィルタ・権限による絞り込みと組み合わせて使え、ページングの前に適用されること。
6. 並べ替えの値が同じテンプレートが複数あっても、ページをまたいで同じテンプレートが重複したり抜けたりしないよう、順序を一意に決めること。

## 非機能要件

- 既存のレスポンス形式（ページング形式）は変更しない。
- DB スキーマは変更しない（マイグレーションなし）。

## スコープ外

- フロントエンド（`frontend-angular/`・`frontend/`）の変更。送信側は対応済みのため不要。
- 一般ユーザー向けテンプレート一覧 API（チャット画面のテンプレート選択用）への `sort` 対応。上流 client はこの API に `sort` を送らないため、今回は対応しない。
- 画面の選択肢にない項目（説明・システムプロンプトなど）での並べ替え。指定されても更新日時順として扱う（既存の他一覧 API と同じ方針）。
