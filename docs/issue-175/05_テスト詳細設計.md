# 05_テスト詳細設計

## テスト対象ファイル

- `backend/tests/integration/test_files.py`（`TestFilesRouter.TestList`）

## テストケース

| No | テストメソッド | 準備 | 操作 | 検証 |
|---|---|---|---|---|
| 1, 2 | `test_sort_by_user_id` | ユーザー ID が確定した順になるよう固定 UUID のユーザーを 2 名作成し、各ユーザーのファイルを 1 件ずつ DB に直接登録（ID の小さいユーザーのファイルを更新日時が新しくなるようにし、更新日時順とは逆の結果になるようにする） | `sort=userId,asc` と `sort=userId,desc` で一覧取得 | 返却された `userId` の並びがそれぞれ昇順・降順であること |
| 3, 4 | `test_sort_by_status` | 状態が `ENABLE` のファイルを更新日時が新しく、`DISABLE` のファイルを古くなるよう DB に直接登録 | `sort=status,asc` と `sort=status,desc` で一覧取得 | `status` の並びが `[0, 1]`・`[1, 0]` であること |
| 5 | 既存テスト | - | `uv run pytest` | 全件成功 |

- 未知の並べ替えキーは更新日時順にフォールバックするが、並べ替え方向（asc/desc）はそのまま適用される。そのため「更新日時の順」と「期待する順」が昇順・降順のどちらでも逆になるデータにし、並べ替えキーが無視された場合にテストが失敗するようにする（修正前のコードで 2 件とも失敗することを確認済み）
