# 03_詳細設計

## 実装対象ファイル

| ファイル | 変更内容 |
|---|---|
| `backend/app/repositories/file_repository.py` | `_ORDER_BY_COLUMNS` に `"userId": File.user_id`・`"status": File.status` を追加。`find_page` の docstring（`sort_col_name` の説明）を更新 |
| `backend/tests/integration/test_files.py` | `TestList` に並べ替えのテストを追加 |

## 実装内容

```python
_ORDER_BY_COLUMNS: dict[str, InstrumentedAttribute] = {
    "displayName": File.display_name,
    "updatedAt": File.updated_at,
    "userId": File.user_id,
    "status": File.status,
}
```

- `FileService.list_files` の `sort` 分解（`"列名,方向"`）と、`find_page` の `order_by` 組み立ては既存のまま使う
- 未知の列名は従来どおり `File.updated_at` にフォールバックする
- （code-review 対応）`order_by` の第 2 キーに `File.id.asc()` を追加し、同順位の行の順序を確定させる。並べ替え方向は移植元 `Direction.fromString` と同じく大文字小文字を区別しない

## 移植元の根拠

- `server/src/main/java/com/example/naw/api/FileController.java` の `search(..., Pageable pageable, ...)`
- `server/src/main/java/com/example/naw/service/FileService.java` の `searchFiles` → `fileRepository.findAll(spec, pageable)`
- `server/src/main/java/com/example/naw/domain/file/File.java` の `userId`（`user_id` 列）・`status`（`@Enumerated` 未指定 = 序数）
- 上流 client `training-data-files.helper.ts` の `mapFileSortFieldToApi`（`updatedBy` → `userId`、`status` はそのまま）
