# 01_要件定義

## 背景

学習データ詳細画面のファイル一覧で「更新者順」「学習設定順」を選んでも、表示順が更新日時の降順から変わらない。画面は並べ替え条件を `sort` クエリ（`userId,asc` / `status,desc` 等）で送っているが、バックエンドのファイル一覧 API が並べ替え可能な列として「表示名」「更新日時」しか受け付けておらず、それ以外は既定の更新日時順に置き換えている。

移植元（Spring Boot）のファイル一覧 API は Spring Data の `Pageable` で並べ替え条件を受けるため、ファイルエンティティの項目名（`userId`・`status` を含む）をそのまま並べ替えキーとして使える。

## 機能要件

- ファイル一覧 API の並べ替えキーに `userId`（更新者）を指定した場合、ファイルの登録ユーザー ID で並べ替えること
- ファイル一覧 API の並べ替えキーに `status`（学習設定）を指定した場合、ファイルの状態で並べ替えること
  - 状態の並び順は移植元と同じく保存値の順（有効 → 無効 → 削除済み）とする
- 並べ替え方向（`asc` / `desc`）が反映されること
- 既存の並べ替えキー（`displayName`・`updatedAt`）と、未知のキーを指定したときの既定動作（更新日時順）は変えないこと

## 非機能要件

- DB スキーマ変更（マイグレーション）を伴わないこと
- 移植元と同じ API 仕様（クエリパラメータ名・値）で動作すること

## スコープ外

- 更新者の「名前」での並べ替え。移植元は `userId`（ユーザー ID 列）で並べ替えており、ユーザー名との結合は行っていないため、移植元に合わせる（Issue 本文の対応方針案「User.name での JOIN ソート」は採用しない）
- 移植元 `Pageable` が受け付ける上記以外の項目（`name`・`createdAt` 等）への並べ替え対応
- フロントエンド（`frontend-angular/`・`frontend/`）の変更
