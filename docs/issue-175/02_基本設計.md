# 02_基本設計

## 変更対象

- ファイル一覧取得のリポジトリ層（並べ替えキーと DB 列の対応表）

## 画面 / API 変更概要

| API | 変更内容 |
|---|---|
| `GET /api/admin/indexes/{indexId}/files` | `sort` に `userId,{asc\|desc}`・`status,{asc\|desc}` を指定できるようにする |

リクエスト・レスポンスの形式は変更しない。

## 影響範囲

- ファイル一覧 API の並べ替え結果のみ。絞り込み条件・件数・レスポンス項目には影響しない
- 並べ替えキー未指定時・未知のキー指定時の既定動作（更新日時順）は維持する

## 移植方針

- 移植元 `FileController.search` は `Pageable` を受け、`FileService.searchFiles` で `fileRepository.findAll(spec, pageable)` を呼ぶ。`Pageable` の並べ替えはエンティティの項目名で解決されるため、`userId` は `files.user_id` 列、`status` は `files.status` 列（JPA の `@Enumerated` 未指定 = 序数保存）での並べ替えになる
- FastAPI 版はすでに `File.status` を移植元と同じ序数（`ENABLE=0, DISABLE=1, DELETED=2`）で保存しているため、列の値でそのまま並べ替えれば移植元と同じ順序になる
- 移植元と同様、ユーザー名との結合は行わない
