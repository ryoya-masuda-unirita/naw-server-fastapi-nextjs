# 学習データ詳細画面の並べ替え(更新者順/学習設定順)がAPIに反映されずupdated_at降順固定になる

## 概要

GitHub Issue #175 の内容を転記する。

## 説明

### 概要

学習データ詳細画面（`/admin/training-data/:id`）のファイル一覧並べ替えUIで「更新者順」「学習設定順」を選択しても、実際の表示順が更新日時降順のまま変化しない。

### 原因

- フロントエンド: `frontend-angular/src/app/features/admin/management/training-data/utils/training-data-files.helper.ts` の `mapFileSortFieldToApi` は `updatedBy` を `userId` に、`status` はそのまま送信している。
- バックエンド: `backend/app/repositories/file_repository.py` の `_ORDER_BY_COLUMNS`（11〜14行目付近）が `displayName`・`updatedAt` のみに対応しており、`userId`（更新者順）・`status`（学習設定順）はマッピングに存在しない。該当キーで `sort` が指定された場合、フォールバックにより `updated_at` 降順で処理され、フロントの選択操作が実質無視される。

### 発見経緯

Issue #166（結合テストE2EのPlaywright自動化、17_学習データカテゴリ）で並べ替え機能をテスト中に発見。結合テスト項目書（`docs/issue-163/25DA61_結合テスト項目書_md/17_学習データ.md` 項番20・21）では「更新者順」「学習設定順」を選択した際にその順で表示されることが期待されているが、実際には常にupdated_at降順のまま変化しない。

### 対応方針案

- バックエンド: `_ORDER_BY_COLUMNS` に `userId`（更新者名でのJOINソートが必要）・`status` のマッピングを追加する
- 更新者順は `File.user_id` に紐づく `User.name` でのソートになるため、`FileRepository` 側でJOINを伴うクエリ組み立てが必要になる点に留意する

### 本Issueでは対応しない

Issue #166 のスコープはテスト自動化基盤であり、アプリ本体の修正は行わない。該当のE2Eテストは実際の挙動（並べ替え操作をしても表示順が変わらない）に合わせ、`test.skip` として記録した。
