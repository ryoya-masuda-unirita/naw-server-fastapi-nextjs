# #239 issue-239 入力チェックのエラーメッセージを移植元と同じ日本語の文言にする

## 概要

#228 でエラー応答の形を移植元と同じ `{timestamp, message}` にし、入力チェックのエラーを 400 にした。ただし、フレームワーク組み込みの制約（文字数の上限・必須など）のメッセージは、Pydantic の英語の既定文言のまま（例: `String should have at most 32 characters`）。

移植元は項目ごとに日本語のメッセージ（`@Size(message = "...")` など）を指定している。

## 説明

- 移植元の Request クラスの Bean Validation のメッセージを洗い出し、backend の対応するスキーマで同じ文言を返す
- 移植元にメッセージ指定がない制約は、移植元の実際の応答（Spring の既定文言）を確認して揃える
- 全スキーマに手で書くか、共通の仕組みにするかは設計で決める

### 依頼時の補足

- まず移植元の全 Request の制約とメッセージを一覧化し（docs に表で残す）、backend の対応スキーマと突き合わせる
- 移植元にメッセージ指定がない制約は、Spring の既定文言（例: 日本語ロケールの「空白は許可されていません」等）が返るかを移植元の設定（messages.properties、ValidationMessages、ロケール設定）で確認して決める。確認できなければ英語のまま残し docs に明記
- 実装方式（各フィールドに書く / 共通のマッピングにする）は保守性で判断し、02_基本設計.md に理由を書く
- 移植元に対応がない backend 独自の制約は変えない
- 主要な項目ごとに、メッセージを検証するテストを書く
