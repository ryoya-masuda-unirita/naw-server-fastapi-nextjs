## 実装内容

### `app/core/validation_messages.py`

```python
NOT_BLANK_DEFAULT_MESSAGE = "空白は許可されていません"
NOT_NULL_DEFAULT_MESSAGE = "null は許可されていません"
NOT_EMPTY_DEFAULT_MESSAGE = "空要素は許可されていません"


@dataclass(frozen=True)
class ValidationMessages:
    """項目の型注釈に添える、制約ごとの文言（移植元の注釈の message に相当）。"""

    not_blank: str | None = None        # @NotBlank
    not_null: str | None = None         # @NotNull
    not_empty: str | None = None        # @NotEmpty
    size: str | None = None             # @Size
    min_value: str | None = None        # @Min / @DecimalMin / @PositiveOrZero
    max_value: str | None = None        # @Max / @DecimalMax
    iso8601_instant: str | None = None  # @ISO8601Instant

    def message_for(self, error: ErrorDetails) -> str | None: ...
    def __get_pydantic_core_schema__(self, source, handler) -> CoreSchema: ...


class RequestModel(BaseModel):
    @model_validator(mode="wrap")
    @classmethod
    def _replace_missing_messages(cls, data, handler): ...
```

#### `ValidationMessages.message_for`（置き換えの規則）

上から順に判定し、最初に当たったものを返す。指定が無ければ `None`（置き換えない）。

1. 独自チェックのエラー（`value_error`・`assertion_error`）→ `None`
2. `missing`、または入力が `None` → 必須の文言（`not_blank`・`not_null`・`not_empty` のうち指定されたもの）
3. `string_too_long`・`too_long` → `size`
4. `string_too_short`・`too_short` → `not_blank` または `not_empty`（`not_null` は空文字・空配列を拒否しないため対象外）
5. `greater_than`・`greater_than_equal` → `min_value`
6. `less_than`・`less_than_equal` → `max_value`
7. 入力が空白のみの文字列 → `not_blank`（日時の項目に空文字を送った場合など）
8. `datetime_` で始まる種類 → `iso8601_instant`

#### 項目単位の置き換え（`__get_pydantic_core_schema__`）

- 項目のスキーマを wrap validator で包み、内側の検証が `ValidationError` を送出したら、位置が項目自身（`loc == ()`）のエラーを `message_for` で置き換える
- 配列の要素・入れ子のモデルの中のエラー（`loc` が空でない）は置き換えない（入れ子のモデルは自身の項目の指定で置き換える）
- `Field()` の前後どちらに書いても、`Field()` の制約のエラーを包む（試作で確認済み）
- クエリパラメータの型注釈（`Annotated[int, Query(ge=0), ValidationMessages(...)]`）でも同じに動く

#### 欠落の置き換え（`RequestModel`）

- モデルの wrap validator で、`missing` かつ位置が 1 段（モデル直下の項目）のエラーについて、その項目の `ValidationMessages`（`FieldInfo.metadata` から取得）の必須の文言に置き換える
- 位置は別名で出るため、項目名・`alias`・`validation_alias`（文字列、`AliasChoices` の各文字列）のどれでも引けるようにする
- 置き換えたエラーが無ければ元の例外をそのまま送出する

#### エラーの作り直し

- 置き換えたエラーを含む全エラーを、種類（`type`）・位置・入力を保ったまま作り直し、`ValidationError.from_exception_data` で送出する。置き換えたエラーは `PydanticCustomError(type, 文言)`、置き換えない Pydantic 組み込みのエラーは元の種類と `ctx` のまま作り直す（独自の種類は `PydanticCustomError` で作り直す）
- 項目名・別名から `ValidationMessages` を引く表はモデルごとに一度だけ作る（`functools.cache`）
- 文字数・範囲の文言の上限値は、制約と同じ定数から組み立てる（文言は移植元と同じ文字列になる）
- 種類を保つため、`app/core/errors.py` の「`value_error` の接頭辞を外す」処理・ログ（位置と種類）はそのまま動く。`errors.py` は変更しない

### スキーマの書き方

```python
class LibraryTagCreateRequest(RequestModel):
    name: Annotated[
        str,
        Field(max_length=NAME_MAX_LENGTH),
        ValidationMessages(
            not_blank=_NAME_REQUIRED_MESSAGE,
            size="タグ名は255文字以内で入力してください",
        ),
    ]
```

- 空白のみを拒否する既存の独自チェックはそのまま残し、文言は同じ定数を使う
- 既定値のある項目は `Annotated[...] = 既定値` と書く

### 独自チェックの文言の変更

| スキーマ | 変更前 | 変更後 |
|---|---|---|
| フィードバック（ユーザー）sortField | sortField は updatedAt, name, count, review1〜review5 のいずれかです | ソート項目は updatedAt, name, count, review1, review2, review3, review4, review5 のいずれかを指定してください |
| フィードバック（メッセージ）sortField | sortField は updatedAt, name, accuracy, add, folder のいずれかです | ソート項目は updatedAt, name, accuracy, add, folder のいずれかを指定してください |
| フィードバック（ルーム）sortField | sortField は updatedAt, chat, name, level のいずれかです | ソート項目は updatedAt, chat, name, level のいずれかを指定してください |
| フィードバック（3種）sortOrder | sortOrder は asc または desc です | ソート順は asc または desc を指定してください |
| トークン使用量 期間の前後 | fromはto以前の日時を指定してください | 開始日時は終了日時以前である必要があります |
| トークン使用量 期間の長さ | 期間は31日以内で指定してください | 指定期間は31日以内である必要があります |
| トークン使用量 orderBy | orderByは('createdAt', 'totalTokens')のいずれかを指定してください | ソート項目は createdAt または totalTokens のいずれかを指定してください |
| 埋め込み input | inputは必須です | input は必須です |
| アシスタント更新 name | アシスタント表示名は空白にできません | アシスタント表示名は空白にできません。 |

### `backend/.claude/CLAUDE.md`

「バリデーション」の項を、次の方針に書き換える。

- 組み込みの制約（文字数・範囲など）は `Field()` で宣言し、移植元の注釈の `message` は `ValidationMessages` で項目に添える。添えたモデルは `RequestModel` を継承する
- 移植元にメッセージ指定が無い制約は既定文言の定数を使う
- 単純な制約で表せないロジック（空白のみの拒否、相関チェック）は従来どおり `field_validator` / `model_validator`
