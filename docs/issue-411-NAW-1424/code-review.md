## 詳細

### 1. 名前の取得が終わるまでの誤表示（🔴 致命的）→ 対応済み

確かめた。名前を引くフックは、一覧とは別の問い合わせで、応答が返るまでは空の対応を返す。そのため、一覧が先に描画されると、実在のユーザーの行も「削除されたユーザー」と出ていた。変更前は、名前を引けないときにログイン ID を出していて、この誤表示はこの変更が入れた。

修正: 移植元と同じく、名前を引いてから行を作る形にした。ローカルの一覧の取得（`useTrainingDataFiles`）の中で、一覧を取った後に、表示ページのログイン ID だけでユーザーを引き、`updatedBy` に入れてから返す。名前を引くフック（`useLocalUpdaterNames`）は廃止した。これで、描画される行は、名前が引けた後のものだけになる。`keepPreviousData` で前のページが残るときも、前のページの行は、そのページの名前が入ったままで、誤表示にならない。

### 2. 取得失敗時の誤表示（🟡 注意）→ 対応済み

確かめた。1 の修正で、ユーザー一覧の取得に失敗すると、一覧の取得の失敗になる（移植元と同じ「ユーザー一覧が取れないときは、誤った更新者に見えないよう、ファイル一覧の取得の失敗として扱う」）。HTTP のエラーは共通のエラートーストが出し、それ以外はローカル用サーバーの失敗と同じトーストが出る。

### 3. 取得中の表示のテスト（🟡 注意）→ 対応済み

2 件のテストを足した。ユーザーの応答を止めている間は、更新者の欄も「削除されたユーザー」も出ないこと、応答を返すと名前が出ること。ユーザー一覧が 500 のとき、「削除されたユーザー」が出ないこと。
