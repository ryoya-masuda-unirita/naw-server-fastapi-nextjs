# 04_テスト設計

## テスト方針

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | 絞り込みが無い | ファイル一覧の絞り込み領域を表示する | 更新者の選択肢が出ない。検索・期間・ページ送りは出る |
| 2 | API の条件 | 一覧の条件から API のクエリを作る | 更新者の条件（`userId`）が含まれない |
| 3 | クラウドの名前 | API が更新者名を返すファイル | その名前が出る |
| 4 | クラウドは全ユーザーを取らない | クラウドのフォルダの一覧を開く | ユーザー一覧の API が呼ばれない |
| 5 | 名前が無い（クラウド） | API の更新者名が無い | ID を出さず「削除されたユーザー」が出る |
| 6 | 更新者の ID が無い | ファイルに更新者の ID が無い | 「Unknown」が出る |
| 7 | ローカルの名前 | ログイン ID でユーザーを引ける | 表示名が出る（#390 の動作が保たれる） |
| 8 | ローカルで引けない | ログイン ID でユーザーを引けない | ログイン ID を出さず「削除されたユーザー」が出る |
| 9 | 正規化 | API の更新者名が無い | 更新者名は空（ユーザーの ID にならない） |
| 10 | 画面での確認 | クラウド・ローカルのフォルダ詳細 | 絞り込みが無く、更新者の欄が上記どおり出る |
