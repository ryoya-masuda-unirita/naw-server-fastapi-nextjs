# 03_詳細設計

## 変更ファイル（すべて `client/` 配下。`server/` の変更は無い）

| ファイル | 内容 |
|---|---|
| `src/types/training-data.types.ts` | `TrainingDataFileFilter` から `userId` を削除。`TrainingDataFileUpdater`（`USER`・`DELETED`・`UNKNOWN`）と `TrainingDataFileRow`（`TrainingDataFile` に `updater` を足したもの）を追加 |
| `src/store/training-data-store.ts` | ファイル一覧の初期条件から `userId` を削除 |
| `src/components/features/admin/training-data/training-data-files-helper.ts` | `toFileListApiParams` から更新者の条件と `currentUserId` を削除。`buildFileUserFilterOptions`・`resolveFileUpdatedByNames`・`resolveLocalFileUpdatedByNames` を削除し、`resolveFileUpdaters(files)`（`updatedBy` と `userId` から 3 種を決める）を追加 |
| `src/components/features/admin/training-data/training-data-api-normalize.ts` | 更新者名が無いとき、ユーザーの ID にしない（空にする） |
| `src/hooks/use-training-data-detail.ts` | `useTrainingFilterUsers`（全ユーザー最大 1000 件の取得）と定数を削除。`useTrainingDataFiles` の `currentUserId` 引数を削除。ローカルの一覧は、取った後に表示ページのログイン ID でユーザーを引いて `updatedBy` に入れてから返す（`useLocalUpdaterNames` は廃止）。名前を引けなかったときは一覧の取得の失敗とする |
| `src/components/features/admin/training-data/training-data-filters.tsx` | 更新者の選択肢（`SelectWithSearch`）と関連 props を削除 |
| `src/components/features/admin/training-data/training-data-files-view.tsx` | 全ユーザーの取得と選択肢の組み立てを削除。`resolveFileUpdaters` で行を作る |
| `src/components/features/admin/training-data/training-data-table.tsx` | 更新者の欄を `updater` の種類で出し分ける（`data-testid="training-data-file-updated-by"`） |
| `public/i18n/ja.json`・`en.json` | `LEARNING_DATA.UPDATED_BY_DELETED`（削除されたユーザー）・`UPDATED_BY_UNKNOWN`（Unknown）を追加。使われなくなった `LEARNING_DATA.ALL_USERS` を削除 |

## 変更しないもの

- 並べ替えの項目としての `updatedBy`（`userId` への変換）は、#392 の暫定対応のまま残す
- ローカルのログイン ID での検索（`loginIds`）の呼び先は #390 のまま。呼ぶ場所を、画面の別のフックから、一覧の取得の中に移す（名前を引く前の行を出さないため）
- backend（更新者名を返す API）

## 注意点

- 更新者の種類の判定: ID が無ければ `UNKNOWN`、名前があれば `USER`、ID はあるが名前が無ければ `DELETED`
- フィードバックの追加学習（#391）が `use-training-data-detail.ts` を同時に変更している。マージ時のコンフリクトは、後からマージする側で解消する
