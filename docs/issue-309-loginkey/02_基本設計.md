# 02_基本設計

## 変更対象

- ユーザーの応答（一覧の行・プロフィール）
- ユーザー作成・更新の応答
- グループのメンバー一覧の行
- ユーザー作成・更新・プロフィールの API の応答ヘッダー・null 項目の扱い

## 画面 / API 変更概要

| API | 変更前 | 変更後（移植元と同じ） |
|---|---|---|
| GET・PATCH `/api/users/profile` | `loginKey`（保存値）、`totalCredits: null` | `hasLoginKey`、`totalCredits` は null なら出さない |
| GET `/api/admin/users` | 行に `loginKey`（保存値） | 行に `hasLoginKey` |
| POST `/api/admin/users` | `loginKey`（保存値）、`totalCredits: null` | `loginKey`（このリクエストで設定したキー、無ければ null）・`hasLoginKey`、`totalCredits` なし、`Cache-Control: no-store` |
| PATCH `/api/admin/users/{loginId}` | 同上 | 同上 |
| GET `/api/admin/groups/{id}/users` | 行に `loginKey`（保存値） | `loginKey` を出さない |

画面は変更しない。React の型（`UserProfile`・`UserApiItem`・`UserCreateApiResponse`・`UserUpdateApiResponse`）はすでに変更後の形。

## 影響範囲

- 応答から `loginKey` を読むところは React・server-local に無い（検索で確認）
- 作成・更新の `loginKey` は、現在の backend では管理者が自分で指定した値の折り返しになる。移植元は「サーバーが発行したキー」だが、発行方式は 2 本目の PR で入れるため、この PR では「このリクエストで設定したキー」を同じ位置で返す

## 移植方針

- 移植元 `UserResponse`・`UserCreateResponse`・`UserUpdateResponse`・`GroupMemberUserResponse`・`UserController`（c14a2485 NAW-1342 AC-03 以降の形）に合わせる
- 作成・更新の応答は、移植元と同じく一覧の行（`UserResponse`）とは別の型にし、`totalCredits` を持たせない
