# #309 issue-309 backendの応答の形を移植元serverに揃える（loginKeyの露出を含む）

## 概要

#279（PR #304）で、React に移植した API の型と backend の実際の応答を突き合わせた差分の一覧が `docs/issue-279/api-backend-diff.md` にある。差分の一部は backend の移植遅れ（移植元 Spring Boot の方が新しい）が原因。**移植元 `server/` の Response/Request を正として**、backend を揃える。

## 説明

### 優先（セキュリティ）

- `/api/users/profile`・`/api/admin/users`・`/api/admin/groups/{id}/users` が `loginKey`（秘密情報の保存値）を返している。移植元は `hasLoginKey` だけを返す

### そのほか（一覧の「1. 形が違うもの」の各行）

- 認証の `groups` が `{id,name}` で空固定（移植元は `{groupId, groupAdmin}`）
- ユーザー一覧のページングが `page`（移植元は `number`）、ユーザー更新の `loginKeyAction`
- shares の `{data}` 包み、rooms・messages（assistants の `includeHistory`・`model`、endpoints の `model`）・assistants（`category` の形、`endpoints[].label`）・テナント・学習データ・ファイルなどの項目

### 進め方

- 各行を、移植元 `server/` の Controller と Response/Request のクラスで確かめる。移植元の client の型が古い・モック専用で、移植元 server と違う場合は **移植元 server に合わせる**
- 移植元 server にない API（一覧の「2.」）は作らない（#281・#282 と同じ判断）
- 規模が大きければ、セキュリティの項目を先に別 PR にしてよい
