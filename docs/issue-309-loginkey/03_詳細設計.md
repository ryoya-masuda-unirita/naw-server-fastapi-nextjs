# 03_詳細設計

## 移植元の根拠（`secuaigent-ref/server`）

| 移植元 | 内容 |
|---|---|
| `response/UserResponse.java` | `hasLoginKey`（`loginKeyHash != null`）。`@JsonInclude(NON_NULL)` |
| `response/UserCreateResponse.java`・`UserUpdateResponse.java` | `id`・`loginId`・`name`・`role`・`loginKey`（発行したキー）・`hasLoginKey`・`isRequiredPasswordReset`・`initialPassword`・`passwordExpiredAt`。NON_NULL なし（`loginKey: null` も出る） |
| `response/GroupMemberUserResponse.java` | `loginKey` なし（c14a2485 で削除） |
| `api/UserController.java` | 作成・更新は `Cache-Control: no-store`。プロフィールは `UserResponse.convertFromUser` |

## 変更ファイル

| ファイル | 変更 |
|---|---|
| `backend/app/schemas/user.py` | `UserResponse.loginKey` → `hasLoginKey`。作成・更新の応答を `_UserMutationResponse` を基にした別の型にし、`from_user(user, 初期パスワード, 期限, 設定したキー)` で作る。全クラスに docstring |
| `backend/app/services/user_service.py` | 作成・更新の応答を `UserCreateResponse.from_user`・`UserUpdateResponse.from_user` で作り、`req.loginKey` を渡す。docstring を NumPy 形式に変換・`UserService` に docstring |
| `backend/app/routers/users.py` | 作成・更新で `Cache-Control: no-store`。プロフィール取得・更新に `response_model_exclude_none=True`。全関数に docstring |
| `backend/app/schemas/group.py` | `GroupMemberUserResponse.loginKey` を削除。docstring の無いクラスに追加 |
| `backend/app/services/group_service.py` | メンバー一覧の組み立てから `loginKey` を削除。docstring を NumPy 形式に変換・不足分を追加 |

## 判断

- 作成・更新の `loginKey` に入れる値: 移植元は「このリクエストで発行したキー」。backend はまだ管理者がキーを指定する方式なので、「このリクエストで指定したキー（`req.loginKey`）」を入れる。保存済みのキーは返さない。2 本目の PR で発行方式に置き換える
- プロフィールの null 項目: 移植元 `UserResponse` は NON_NULL のため、プロフィールも一覧（既に `response_model_exclude_none=True`）と同じく null を出さない
- docstring: ユーザー指示（2026-11-13）により NumPy 形式。触ったファイル内の Google 形式は変換した（`backend/.claude/CLAUDE.md` は Google 形式と書いているが、指示を優先）
