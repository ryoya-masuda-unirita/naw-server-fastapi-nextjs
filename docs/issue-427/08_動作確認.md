# 08_動作確認

## 確認環境

- ローカル（macOS）、Python 3.14（`uv`）、SQLite（インメモリ）。AWS・インフラには触れていない（費用なし）
- ブランチ: `feature/issue-427`（`develop` から作成。別の作業と衝突しないよう、別の worktree で作業した）

## 確認結果

| No | 確認内容 | 結果 |
|---|---|---|
| 1 | **実装前の失敗** | 新規テスト 28 件のうち **11 件が失敗**（ライブラリ・利用履歴・フィードバック（メッセージ・ルーム）・チャット履歴（管理者）・自分が見られるルーム）。ID の逆順に挿入した場合が中心 |
| 2 | 実装後 | 新規テスト **28 件すべて成功**（重複なし・漏れなし・ID の昇順） |
| 3 | 全体 | `server/` の `tests/unit`・`tests/integration` 全件成功（1457 件）。統合テスト（804 件）を 12 回繰り返しても、すべて成功 |
| 4 | 品質 | `ruff format`・`ruff check`・`mypy app` エラーなし |

## 確認の途中で分かったこと

- 既存の `test_returns_feedback_message_with_assistant_name_and_content` が、同じ更新日時の行の先頭（`[0]`）に頼っており、実装後に不安定になった（修正前は 6 回とも成功、修正後は 3 回中 2 回失敗）。順番が ID（ランダム）で決まるようになったため。質問の内容で行を探す形に直した。直した後は、12 回の繰り返しで失敗なし
- SQLite は、数字だけの 32 桁の 16 進文字列の UUID を数値として保存し直して壊すため、テストの UUID は先頭を英字にした

## 未確認事項・限界

- **フィードバック（ユーザー）** は、SQLite では GROUP BY の結果が元から ID 順に出るため、実装前に赤にできなかった。PostgreSQL での効果は確認していない
- **ライブラリのタグ** は、名前が一意なので、実装前から通る（同じ値の行を作れない）。確認できるのは「並びが変わらないこと」だけ
- **PostgreSQL では実行していない**。SQLite のテストと、移植元の同じ変更に合わせた実装
- 既存のほかのテストで、同じ値の行の順番に依存しているものが、まだ隠れている可能性がある（全件・12 回の繰り返しでは見つからなかった）
- **デプロイ**: マージすると `Deploy` の `backend` ジョブが動く。旧環境向けのため、途中で止まると推測しているが、確認していない
