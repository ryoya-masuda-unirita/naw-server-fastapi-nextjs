# 01_要件定義

## 機能要件

### 画面全体
- ヘッダー（`ADMIN.LIBRARY.TITLE`）とタブ（コンテンツ一覧・タグ管理）。タブは `?tab=contents|tags` で保持する（未指定・不正値は contents）
- 一般ユーザー（テナント管理者でない）にはタブを出さない。URL で `tags` を指定しても contents を表示し、URL も contents に直す
- `/library` は全ログインユーザーが入れる（ガードは `RequireAuth` のみ。#277 で定義済み）

### コンテンツ一覧タブ
- 検索（タイトル、入力から 300ms 後に反映）・フィルター（ユーザー: 全て／自分のみ／他ユーザーのみ、タグ）・並べ替え（更新日時順／コンテンツ名順、昇順／降順）
- 1 ページ 5 件、件数表示（`1-5件 / 7件`）と上下のページ送り。条件を変えたら 1 ページ目へ
- 行: タイトル・タグ（`#名前`）・更新日時、操作（メニュー・詳細へ移動の `>`）
- メニュー: 「コンテンツの設定を編集」「共有リンクをコピー」「ライブラリから削除」。編集・削除は自分が作成したライブラリだけ
- 編集設定ダイアログ: 名前・設定するタグ・共有するチーム、共有リンクのコピー、保存・キャンセル。保存に失敗したらトースト
- 削除確認ダイアログ。NAW のライブラリを削除したあと、ローカルサーバーに本文があれば削除する（失敗は無視）。削除に失敗したらトースト
- 読み込み中はスケルトン。最終ページの最後の 1 件を削除したら最終ページへ戻す

### タグ管理タブ
- 並べ替え（更新日時順／タグ名順、昇順／降順）・1 ページ 25 件・件数表示・上下のページ送り
- 行: チェックボックス・更新日時・タグ名・説明（なければ `-`）・メニュー（編集・削除）
- 全選択（PC・モバイルで別のヘッダー行）、選択時は「選択を解除」「削除」、未選択時は「タグを新規作成」。モバイルは画面下に固定のボタン
- 作成・編集ダイアログ: 名前（必須・255 文字以内）・説明（任意）。名前が空白だけ・255 文字超なら保存できない
- 削除確認ダイアログ（1 件・選択した複数件）

## 入力チェック（移植元どおり）
- コンテンツの名前: 画面側のチェックなし（backend が必須・255 文字以内を検査し、失敗はトースト）
- タグの名前: `trim` して空でない・255 文字以内（`FormInput` の `maxLength` が入力を切り詰めるため、エラー文言は通常出ない）

## 非機能
- 文言は i18n 辞書（移植元のクローン）を使い、キーを足さない
- API の形は backend の実際の応答に合わせる（03 を参照）
