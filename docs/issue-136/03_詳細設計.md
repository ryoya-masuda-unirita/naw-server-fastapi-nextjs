# 03_詳細設計

## API（backend の実応答との差と画面での吸収）

`docs/issue-279/api-backend-diff.md` と `backend/app/routers/libraries.py`・`library_tags.py`・`schemas/library*.py` を確認した。

| API | 形 | 移植元との差と対応 |
|---|---|---|
| `GET /api/libraries` | `{ data: { content, totalElements, number, size } }` | 差なし。`createdBy`・`excludeCreatedBy` は backend が **ログインID**（`login_id`）で絞るので、移植元どおり認証ユーザーの `id`（= `login_id`）を渡す。`tagIds` は同じキーの繰り返し（api-client が配列に対応） |

| `DELETE /api/libraries/{id}` | 204 | 差なし。削除前に `GET /api/libraries/{id}` で `assistant` を取る（失敗なら null） |

| `GET /api/users/profile` | `UserResponse`（`id` は UUID、`loginId`） | 差なし。所有者判定は移植元どおり、一覧の `userId` とプロフィールの `id`（UUID）の一致 |

## 状態

### `useLibraryListStore`
`title`・`userMode`・`tagId`・`sortField`・`sortOrder`・`page`。条件を変えると `page = 1`。コンテンツタブをアンマウントしたら `reset()`。

### `useLibraryTagsStore`
`sortBy`（空は更新日時）・`sortOrder`・`page`。作成後は `goFirstPage()`。タグタブをアンマウントしたら `reset()`。選択は画面の `useState`（ページ・並べ替えを変えたら解除）。

## 画面の挙動（移植元との同一点・差）

- 検索: 入力を `useDebouncedValue`（300ms）で反映。ストアのタイトルと同じなら何もしない（移植元の `distinctUntilChanged`）
- 並べ替え: 項目をクリアしたら API の `sortBy` は `updatedAt`、`sortDir` は選択値（空なら送らない）
- 件数表示（`0件`、`1-5件 / 7件`）・並べ替えの項目名（`更新日時順`・`コンテンツ名順`）・テーブルのヘッダー（`コンテンツ名`・`タグ`・`更新日時`）は移植元でもハードコードの日本語。i18n キーが辞書にないため、そのまま移した
- 読み込み中は `isFetching` の間スケルトン（移植元は `doLoad` の間 `isLoading`）
- タグ編集は取り直さず、返ってきた 1 件で一覧を差し替える（移植元 `updateTag`）
- タグ削除は確認を押した時点でダイアログを閉じてから削除（移植元どおり）。失敗の通知は api-client の共通トースト

## 移植元と変えた点（理由）

1. **画面を離れたら条件を捨てる**（`store.reset()`）。移植元は root の singleton ストアに条件が残る一方、タブを作り直すと検索欄・フィルターは初期値に戻るため、見えない条件で絞り込まれる。#124 と同じ判断
2. **最終ページの補正**を、削除後の再取得ではなく「取得成功後に `page > totalPages` なら最終ページへ」で行う（結果は同じ）
3. **フォーカスでの再取得をしない**（`refetchOnWindowFocus: false`）。移植元は開いたときと操作したときだけ読み込む
4. 共有リンクのコピー失敗は `console.error` に残す（移植元は結果を待たない `void` で、失敗しても「コピー済み」を出す。表示は同じ）
5. 詳細への `>` ボタンは移植元の文言なしのまま。テスト用に `data-testid` を付けた

## 移植元の不具合をそのまま移したもの（クローンを保つ。申し送り）

- タグの作成・更新失敗のトースト `ADMIN.LIBRARY.TAGS.CREATE_FAILED`・`UPDATE_FAILED` は**移植元の辞書にもキーがない**ため、画面にはキーの文字列が出る
- コンテンツの名前に画面側の入力チェックがなく、空にして保存すると backend の 400 → トースト
- タグ編集で説明を空にしても消えない（上表）
