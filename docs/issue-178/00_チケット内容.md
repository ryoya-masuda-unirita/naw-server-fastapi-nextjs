# 学習データファイルを削除しても一覧から消えない（論理削除がフィルタされていない）

## 概要

GitHub Issue #178 の内容を転記する。

## 説明

### 概要
学習データ詳細画面でファイルを削除（個別削除・一括削除）すると、削除APIは成功（204）を返すが、一覧を再取得しても削除したファイルが一覧に表示され続ける。

### 原因
- `backend/app/services/file_service.py`の`delete_file()`（404行目〜）は論理削除時（`physical_delete=False`）に`file.status = FileStatus.DELETED`を設定するのみで、レコード自体は残す
- `backend/app/repositories/file_repository.py`の`find_page()`（97行目〜、132〜137行目）は`status`パラメータが指定された場合のみ`File.status == status`でフィルタするが、`status`が`None`（フィルター未指定＝通常の一覧表示）の場合に`FileStatus.DELETED`を除外する条件が一切ない
- そのため、削除（論理削除）したファイルが通常の一覧表示に永続的に残り続ける

### 発見経緯
Issue #166（E2Eテスト自動化）の17_学習データカテゴリ実装中、「行メニューから学習データを削除する」「複数選択後「削除」で確認後に削除する」のE2Eテスト作成時に発見。削除APIレスポンスは204で成功しているにもかかわらず、一覧の再取得APIレスポンスに削除済みファイルがそのまま含まれていることを確認した。

### 対応方針案
`find_page()`のベースクエリに`File.status != FileStatus.DELETED`（またはstatusフィルター未指定時のデフォルト条件）を追加し、論理削除済みファイルを一覧から除外する。

### 本Issueでは対応しない
Issue #166はE2Eテスト自動化基盤の整備が目的のため、本バグの修正はこのIssueのスコープ外とする。該当のE2Eテストケース（行メニューからの個別削除・複数選択後の一括削除）は`test.skip`としてこのIssueへの参照コメントを残す。
