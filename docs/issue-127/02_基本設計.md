# 02_基本設計

## 変更対象

- 画面: アシスタント管理（`/admin/assistants`）。2 タブの親、アシスタント一覧タブ、カテゴリ管理タブ
- ダイアログ: アシスタントの追加・編集、カテゴリの追加・編集、削除の確認
- 通信: アシスタント・カテゴリの一覧・作成・更新・削除、接続先 API・モデル・学習先フォルダ・グループの選択肢

## 画面 / API 変更概要

- 一覧の取得は、アシスタントはサーバー側のページング・絞り込み・並べ替え、カテゴリは全件取得して画面側で並べ替え・ページ分け（移植元と同じ）
- 作成・更新・削除のあとは再取得して一覧を最新にする（移植元は手元で書き換えるが、並び順・ページの境目をサーバーに任せる。#124 と同じ判断）
- ダイアログの選択肢（接続先 API・モデル・カテゴリ・チーム・学習先フォルダ）は、画面を開いたときにまとめて取得する。取れなかった選択肢は空として続ける（移植元と同じ）

## 影響範囲

- 共通ファイルは MSW の既定ハンドラーの登録のみ
- 他画面への影響なし。query key の先頭 `assistants` はサイドバーの無効化の対象

## 移植方針

- 移植元の 2 つの add/edit ダイアログは差が小さい（編集の ID 欄・モデル欄・フォルダ欄の出し分け）ため、React では 1 つのダイアログにまとめ、差は props（編集対象の有無）で出し分ける。カテゴリの add/edit は移植元のテンプレートが同一なのでこちらも 1 つ
- 2 つのタブメニューは編集項目の文言以外が同じなので共通の行メニューにする
- 移植元の `FormGroup`・Validators は、値の state と同じ判定の関数（required は空文字のみ、maxLength）で置き換える（#124 と同じ）
- 文言・選択肢のラベルのうち、移植元が日本語を直書きしているもの（接続サーバー名・「カテゴリなし」・「所属チームなし」・件数表示）は、辞書に対応するキーがないため同じ文言をそのまま持つ
