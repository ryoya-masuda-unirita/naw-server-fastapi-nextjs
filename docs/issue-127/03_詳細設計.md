# 03_詳細設計

## 構成

- `routes/admin/assistants/assistant-list.tsx`: `AdminAssistantListPage`。`PageHeader`（タブ付き）＋ `useTabQueryParam`（`assistant`・`assistant-category`）
- `components/features/admin/assistants/`: `assistant-tab`・`category-tab`・`assistant-form-dialog`・`category-form-dialog`・`assistant-row-menu`・`assistant-list-actions`・`assistant-list.constants`
- `hooks/use-assistant-list.ts`: 一覧・カテゴリ・選択肢の取得、作成・更新・削除
- `store/assistant-list-store.ts`: アシスタント・カテゴリの絞り込み・並べ替え・ページ（`pageIndex` は移植元と同じ 0 始まり）
- `mocks/handlers/admin-assistants.ts`: MSW の既定（空の一覧・選択肢なし）

## 状態

- 絞り込み・並べ替え・ページは Zustand（移植元の store の state 部分）。選択は各タブの state（移植元はコンポーネントの signal）
- 選択の判定は移植元どおり（全選択＝選択数が表示件数と等しい）
- 検索は 300ms のデバウンス（移植元は `debounceTime(300)` + `distinctUntilChanged`）

## 一覧の取得（アシスタント）

- 移植元 `toAssistantParams` と同じ: `page`・`size`・`sort`（`項目,順`）・`type`・`categoryId`・`groupId`・`search`・`excludeGroupId`。値がなければ送らない
- 「カテゴリなし」「所属チームなし」の値は `NONE`（backend が未設定・未所属の絞り込みとして扱う）
- 読み込み中は前の一覧を出したままにする（移植元と同じ）。0 件の表示は読み込み中でないときだけ

## 追加・編集ダイアログ

- 追加・編集で共通: 入力チェックは表示名（必須・32 文字）・説明（1000 文字）・接続サーバー・接続先 API・モデル（必須）、学習先指定では学習先フォルダが必須（空白のみも不可）。エラー文言は触った（blur した）項目か、確定を押した後に出る。誤りのある最初の項目へスクロールしてフォーカスする
- 接続サーバーを変えると接続先 API・モデル・学習先フォルダを空に戻し「触っていない」状態に戻す。接続先 API を変えるとモデルを空に戻す（移植元の `reset('')`）
- 学習先フォルダのエラーは、フォルダか接続サーバーを触っていれば出す（移植元 `folderError`）
- 追加だけ: 接続サーバー未選択のとき、サービス ID の入力欄（値を持たない）と、無効のモデル選択を出し、学習先フォルダも出す。ラジオの並びの gap は 2
- 編集だけ: アシスタント ID（無効の入力欄）とコピーボタン、説明の補足文、ラジオの並びの gap は 3、学習先フォルダは学習先指定のときだけ
- 送信の本文は移植元 `mapFormToApi` と同じ（`NONE` を除く、学習先指定以外の `indexId` は空文字、`endpoints` は 1 件）。表示名・説明は trim しない（移植元どおり）
- 編集の初期値は移植元 `onEditAssistant` と同じ（接続先は `LOCAL_SERVER`／`CHAT` を含むものを優先し、選択肢にないものは空にする）
- 確定中は確定ボタンを読み込み中にし、二重送信しない

## カテゴリ

- 全件取得し、並べ替え（項目未指定・順未指定は更新日時の降順）とページ分けは画面側（移植元 `applyFilter`）。日時は `yyyy/MM/dd HH:mm`（ローカル）
- 作成・更新は名前・説明を trim して送る

## backend との差の吸収

`docs/issue-279/api-backend-diff.md` と backend のコードを読んで確かめた結果。

1. `endpoints[].label` が backend の応答にない（移植元 Spring Boot は接続先の表示名を返す）。一覧の「生成 AI モデル」列は、`label` があればそれ、なければ接続先 API の選択肢（`GET /api/admin/assistants/endpoints/{type}` の `endpointName`、移植元が label に入れる値と同じ）から引く
2. `description`・`iconColor` が null の場合がある。説明は空なら出さない。`iconColor` は空文字に直して送る
3. 並べ替えの項目（`name`・`includeHistory`・`updatedAt`）・絞り込み（`type`・`categoryId`・`groupId`・`search`・`NONE`）は backend が対応済み。吸収不要
4. 削除が使用中のとき backend は 409（`HTTPException`）を返す。画面は 409 のトーストを出す
5. グループの選択肢（`GET /api/admin/all-groups`）の `size` は、移植元は渡さず既定の 20 件（21 件目以降のチームが選べず、一覧の所属チームが空になる）。React は backend の上限の 100 件まで取る（判断と理由の 11）

## 判断と理由（移植元との差）

1. 一覧の更新: 移植元は作成・更新・削除のあと store を手元で書き換える（作成・更新はアシスタントだけ再取得）が、React は TanStack Query で `['assistants']` を無効化して再取得する。並び順・ページの境目は常にサーバーの結果になる（#124 と同じ判断）
2. 画面を離れたら絞り込み・並べ替え・ページを初期に戻す。移植元の store は `providedIn: 'root'` で残り続け、戻ると検索欄だけ空で一覧が絞られたままになる。タブを切り替えて戻ったときも、検索欄はストアの値から始める（#124 と同じ判断）
3. 最後のページの行をすべて消したとき、最終ページへ戻す（移植元は空のページに留まる）
4. 「接続先 API」などの選択を × で消したとき、移植元は `null` が入って以降の判定が崩れる。React は空文字にそろえる
5. 追加ダイアログの接続サーバー未選択時のサービス ID 入力欄は、移植元では値が結び付いていない。同じく値は使わない（入力はできる）
6. カテゴリ行メニューの「カテゴリの設定を編集」は、移植元が日本語を直書きしているが、同じ文言の辞書キー（`ADMIN.ASSISTANT.EDIT_CATEGORY`）を使う
7. 編集のコピーボタンの `tabindex=-1` は共通の `Button` に対応する prop がないため付けていない
8. ダイアログの `showDivider` は共通 `Dialog` が持たない（#278 の方針）。幅は移植元の `800px`
9. ルートは移植元と同じくテナント管理者のみ（#277 の `RequireTenantAdmin`）。そのためグループ管理者の見え方（タブなし）は画面に残してあるが、現状は到達しない
10. 移植元の `ASSISTANT_SERVER_OPTIONS` などの直書きの日本語は、辞書にキーがないため同じ文言をそのまま持つ
11. グループの選択肢は 100 件まで（移植元は既定の 20 件）。100 件を超えるテナントは後続 Issue で全件取得を検討する
12. 編集ダイアログを開くとき、選択肢が未取得なら取得してから開く（初期値の接続先・モデルが空にならないように。テンプレート管理の `loadGroups` と同じ）
13. 接続先 API とモデルの選択肢は、同じ接続先一覧から作るので一覧の取得は 1 回にまとめた（移植元は 2 回）
