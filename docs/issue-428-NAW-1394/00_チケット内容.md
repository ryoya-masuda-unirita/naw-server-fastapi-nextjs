# NAW-1394 学習先フォルダの削除で、中のファイルのストレージ実体も消す

## 概要

Issue #428（NAW-1394 の移植、`server/` 側）。学習先フォルダ（インデックス）を削除したとき、中の学習データのファイルの実体（ストレージ）も消す。

## 説明

現状、`IndexService.delete_index` は DB の行を消すだけ。学習データの行は外部キー（`ON DELETE CASCADE`）で一緒に消えるが、ストレージ上のファイルが残る。残ったファイルには、フォルダが無いので、画面から触れない。

### 移植元の挙動（`IndexService.deleteIndex`、コミット 203a487cc・c6bb9b852・a401595f9）

1. LOCAL 型のフォルダは、学習データがローカル用サーバーにあり、クラウドには無いので、今までどおりフォルダの行だけを消す
2. それ以外は、中のファイルを 1 件ずつ物理削除（`FileService.deleteFile(physical=true)` 相当。ストレージの実体と DB の行を消す）してから、フォルダを消す
3. 論理削除済み（`DELETED`）のファイルは、削除したときにストレージの実体を消し済みなので、スキップする（もう一度消しに行くと、外部の都合で失敗するようになる）
4. 途中で失敗したら、フォルダは消さずに失敗させる（中身が残ったままフォルダだけ消えると、残ったものに触れなくなるため）
5. 1 件ごとに、別のトランザクションで確定する（途中で失敗したとき、ファイルを消した行だけが戻って一覧に残るのを防ぐ）
6. ベクトル（Azure AI Search）の削除も、移植元は同時に行う。**こちらには、ベクトルを削除する仕組みがなく（`vector_store.py` は検索のみ）、対象外**
