# 03_詳細設計

## 1. `FileRepository.find_by_index_id_and_tenant_id`（`server/app/repositories/file_repository.py`）

インデックス ID・テナント ID で、状態にかかわらず学習データを全件取る。ID の昇順（処理順を決めるため）。

## 2. `IndexService.delete_index`（`server/app/services/index_service.py`）

引数に `storage: FileStorage` を足す（`session` の前）。

1. インデックスを取得。なければ何もしない（冪等）。可視性チェック（`_ensure_visible`）は、今までどおり
2. `index.type != LOCAL` のとき、`find_by_index_id_and_tenant_id` で全件取り、`status == DELETED` を除いて、1 件ずつ `FileService.delete_file(index_id, file_id, tenant_id, True, storage, session)` を呼ぶ
   - `delete_file` は、ストレージの実体を消し、行を物理削除して、1 件ごとにコミットする。これが移植元の「1 件ずつ別のトランザクションで確定」に当たる
   - 例外は、そのまま上に出す（握りつぶさない）。`IndexRepository.delete` には進まない
3. `IndexRepository.delete` でフォルダを消す

`expire_on_commit=False` なので、1 件ごとのコミットのあとも、`index` はそのまま使える。

## 3. ルーター（`server/app/routers/indexes.py`）

`delete_index` に `storage: FileStorage = Depends(get_file_storage)` を足し、サービスに渡す。
