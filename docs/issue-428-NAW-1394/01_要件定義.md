# 01_要件定義

## 背景

- フォルダの削除で、ストレージのファイルが残る。残ったファイルは、フォルダが無く、画面から消せない（容量・費用・情報の残存）
- 画面からの学習データの削除は、すでに、ストレージの実体を消している（`FileService.delete_file`）。フォルダの削除も、同じ処理を使えばよい

## 機能要件

1. `DELETE /api/admin/indexes/{id}` で、フォルダが SAAS_GLOBAL 型のとき、中の学習データを 1 件ずつ物理削除（ストレージの実体と DB の行）してから、フォルダを消すこと
2. 状態が `DELETED` の学習データは、スキップすること（ストレージに問い合わせない）
3. LOCAL 型のフォルダは、今までどおり、フォルダの行だけを消すこと（ストレージに触れない）
4. 途中で失敗したら、フォルダは消さずに失敗させること。それまでに消せた学習データは、消えたまま確定していること（行とストレージの実体がずれない）
5. 存在しないフォルダは、今までどおり何もしない（冪等）。可視性のチェック（グループ管理者）も、今までどおり
6. API の入出力・ステータスコード（成功は 204）は変えないこと

## 非機能要件

- `ruff`・`mypy`・既存のテストが通ること
- 費用: なし

## スコープ外

- ベクトルの削除（こちらにその仕組みがない）
- フォルダ内の学習データが多いときの性能（1 件ずつ順に処理する。移植元と同じ）
- 失敗後の再実行の工夫（もう一度削除すれば、残りから続きが消える）
- `client/` 側の変更
