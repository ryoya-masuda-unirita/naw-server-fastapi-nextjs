## 振り分けの規則

- 一覧: LOCAL は `listLocalFiles` を呼び、応答を既存の `normalizeTrainingDataFileListBody` に通す。クラウドは変えない
- 追加: LOCAL は `name`（`file.name`）・`displayName`・`reference`・`splitLength`（`toSplitLength`）・`userId`・`creationServiceName`（`folder.add`）を multipart で送る
- 更新: LOCAL はファイルが付けば作り直し、付かなければ表示名とリンクだけ。`name` はファイルがあるときだけ。`deletionServiceName`（`folder.delete`）も送る。学習の ON/OFF（`status`）は送らない
- 削除: LOCAL は 1 件ずつの DELETE を並列に送る。一部が失敗しても、成否を問わず一覧を読み直す（今の動作と同じ）
- 同期: LOCAL は 3 秒待ってから `syncLocalFolder`（今の待ち時間を維持）
- 更新者名: LOCAL の `updatedBy` はログイン ID。表示ページの行のログイン ID だけで、ユーザー一覧 API の `loginIds`（#372）を使って引く。クラウドは全ユーザー取得のまま
- エラー: 接続先が取れないときは `Error` を投げ、ローカル用サーバーへも、クラウドのファイル API へも送らない。画面にはエラーを表示する（HTTP 以外の失敗でも表示が出ること）

## 注意点

- `apiClient.delete` は本文を送れる（`ApiRequestOptionsWithBody`）。移植元の確認項目だった DELETE の本文は問題ない
- 絶対 URL への 401 でセッションを破棄しないことは、`apiClient` のコメント上の記述。テストで確かめる
- ブラウザから直接ローカル用サーバーを呼ぶため、`server-local` の CORS（全許可）と、接続先が http のときの混在コンテンツ（https の画面からは呼べない）に注意する
- 更新者名の解決（`loginIds`）の呼び先と、一覧の行から更新者のログイン ID を取り出す箇所は、実装時にコードを読んで確定し、この文書に追記する
