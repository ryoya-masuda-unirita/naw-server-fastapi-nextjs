# 01_要件定義

## 背景

ローカルの学習先フォルダのファイルは、ローカル用サーバーが持つ。クラウドの API サーバーは、ローカルのフォルダへのファイルの追加・更新・削除を断る。移植元は、ローカルのフォルダなら、画面からフォルダの接続先へ直接送るようにしている。こちらの React 版は、ローカルのフォルダでも常にクラウドへ送るため、追加・更新・削除ができない。

## 機能要件

- ローカルのフォルダの学習データ詳細で、次の操作を、フォルダの接続先（ローカル用サーバー）へ直接送って行う
  - 一覧の表示（検索の語・期間・ページ送り）
  - ファイルの追加（複数ファイルは 1 件ずつ順に送る）
  - ファイルの更新（表示名・参照資料のリンク・チャンクサイズの変更、ファイルの差し替え）
  - ファイルの削除（1 件・複数件。物理削除で送る）
  - 一括同期
- 接続先の URL と API キーは、操作のたびにクラウドの API から取り直す（設定変更後に古い値を使わない）
- 接続先が取れないとき（未登録・URL や API キーが無い）は、クラウドへ送らずに失敗させ、利用者にエラーを表示する
- ローカル用サーバーの認証エラー（401）では、クラウドのログインを切らない
- ローカル用サーバーが受け取らない条件（更新者・並べ替え・ファイル名の検索・学習設定）は送らない
- クラウドのフォルダの動作は変えない

## 非機能要件

- 接続先のパスを持つ URL（`https://host/secuaigent` など）でも、パスを残して結合する
- 一覧の終了日は、ローカル用サーバーが「その日の 0:00 以前」で比べるため、翌日の日付を送る
- 更新者名は、ローカル用サーバーが持たないため、表示ページの更新者のログイン ID だけでユーザーを引いて表示する（backend の `loginIds` は #372 でマージ済み）

## スコープ外

- フィードバックの追加学習の送り分け（#391）
- ローカルのフォルダのダウンロード（移植元も画面に出さない。ローカル用サーバーも未実装）
- 並べ替え（#392）、更新者の絞り込みの削除（#375・#372 で扱う）
- 実際のローカル用サーバー（Java）との通信確認（ブラウザからの CORS・混在コンテンツの確認は、移植先の server-local で行う）
