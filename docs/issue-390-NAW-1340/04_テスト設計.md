# 04_テスト設計

## テスト方針

接続先の取得・URL・送る内容・認証ヘッダーの正しさ、LOCAL とクラウドの振り分け、失敗時の扱いを、自動テストで確かめる。実際のローカル用サーバーとの通しは、手元の `server-local` で確かめる。

| No | 観点 | 条件 | 期待結果 |
|---|---|---|---|
| 1 | URL の結合 | 接続先がパスを持つ・持たない・末尾が `/` | パスが残り、二重の `/` にならない |
| 2 | 期間の変換 | 期間の終了日が月末・年末・うるう日 | `yyyy-MM-dd`。終了日は翌日（繰り上げが正しい） |
| 3 | 一覧の条件 | 更新者・並べ替え・ファイル名・学習設定を指定した条件 | `page`・`size`・`updatedAtFrom`・`updatedAtTo`・`displayName` だけが送られ、空は省かれる |
| 4 | 一覧の送り先 | LOCAL のフォルダの一覧 | ローカル用サーバーへ GET が送られ、クラウドのファイル API は呼ばれない |
| 5 | 認証ヘッダー | ローカル用サーバーへの全リクエスト | `X-Server-Auth-Key` と `X-Tenant-ID` が付く |
| 6 | 追加 | LOCAL で 2 ファイルを追加 | 1 件ずつ順に POST され、`file`・`name`・`displayName`・`reference`・`splitLength`・`userId`・`creationServiceName` を含む。クラウドへは送られない |
| 7 | 更新（ファイルなし） | LOCAL で表示名だけ変更 | PATCH に `file`・`name` が無く、`deletionServiceName`・`creationServiceName` が付く。`status` は送られない |
| 8 | 更新（差し替え） | LOCAL でファイルを選んで保存 | PATCH に `file` と `name` が付く |
| 9 | 削除 | LOCAL で複数件を削除 | 件数分の DELETE が JSON（`deletionServiceName`・`physicalDelete: true`）で送られる。一部失敗でも一覧が読み直される |
| 10 | 同期 | LOCAL で同期 | `userId` と `syncServiceName` を JSON で POST する |
| 11 | クラウドは不変 | クラウドのフォルダで一覧・追加・更新・削除 | これまでどおりクラウドの API が呼ばれ、ローカル用サーバーへは送られない |
| 12 | 接続先が無い | `localServerEndpointId` が無い、または `endpoint`・`apiKey` が空 | どこにも送らずに失敗し、エラーが表示される |
| 13 | 接続先の取り直し | 同じ操作を 2 回、間に接続先を変える | 2 回目は新しい接続先へ送られる（キャッシュしない） |
| 14 | 401 | ローカル用サーバーが 401 を返す | クラウドのログインは切れない |
| 15 | 更新者名 | LOCAL の一覧に更新者のログイン ID がある | 表示ページのログイン ID だけで `loginIds` を使ってユーザーを引き、名前が表示される |
| 16 | 画面での確認 | `server-local` につないだデモで追加・編集・削除・同期 | 画面から操作でき、一覧に反映される |
