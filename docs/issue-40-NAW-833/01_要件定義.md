# 01_要件定義

## 背景

Assistant（アシスタント）にカテゴリを持たせたいという要望（NAW-833）に対応するため、アシスタントカテゴリを管理するドメインを新設する。

これまでGroup・Assistant・PromptTemplate・TenantEndpointの管理系ドメインを移植してきたが、Assistantにカテゴリを付与する機能はカテゴリ自体のマスタが存在しないため実現できていない。本チケットではまずカテゴリ自体のCRUD機能を用意し、Assistantとの紐付けは別チケットで対応する。

## 機能要件

- テナント管理者が、自テナント内でアシスタントカテゴリを作成・一覧取得・単体取得・更新・削除できる
- カテゴリは以下の項目を持つ
  - カテゴリ名（必須、16文字以内）
  - 説明（任意、255文字以内）
- 作成・更新時にカテゴリ名・説明のバリデーションを行い、不正な場合はエラーとする
- 一覧取得は自テナントに属する全カテゴリを返す（検索・ページネーションは不要。移植元も同様）
- 更新・削除は、対象カテゴリが自テナントに属さない場合は404として扱う
- 更新・削除操作を行ったユーザーIDを記録する

## 非機能要件

- 既存の管理者向けエンドポイントと同様、テナント管理者のみアクセス可能とする（一般ユーザーはアクセス不可）
- RLS（テナント分離）により、他テナントのカテゴリを参照・操作できないようにする
- 一覧取得において関連データの取得によるN+1問題は発生させない（本ドメインは他テーブルとの結合を伴わないため該当なし）

## スコープ外

- Assistant側からのカテゴリ紐付け（Assistantにカテゴリを設定する機能、中間テーブルの追加）は別チケットで対応する
- カテゴリによるAssistant一覧の絞り込み機能
- フロントエンド対応（本チケットはバックエンドのみ）
