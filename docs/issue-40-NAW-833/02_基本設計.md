# 02_基本設計

## 変更対象

- アシスタントカテゴリを管理するテーブルを新規作成する（マイグレーション追加）
- アシスタントカテゴリ管理用のモデル・スキーマ・リポジトリ・サービス・ルーターを新規作成する
- 既存のAssistant関連のモデル・API・DBスキーマへの変更は行わない（紐付けは別チケット）

## 画面 / API 変更概要

管理者向けCRUD APIを5本追加する（一般ユーザー向けエンドポイントはなし）。

| メソッド | パス | 概要 |
|---|---|---|
| POST | `/api/admin/assistant-categories` | 作成 |
| GET | `/api/admin/assistant-categories` | 自テナントの全件一覧取得（検索・ページネーションなし） |
| GET | `/api/admin/assistant-categories/{id}` | 単体取得 |
| PATCH | `/api/admin/assistant-categories/{id}` | 更新 |
| DELETE | `/api/admin/assistant-categories/{id}` | 削除 |

- いずれもテナント管理者専用（一般ユーザーからのアクセスは不可）
- 作成・更新時はカテゴリ名（必須・16文字以内）・説明（任意・255文字以内）をバリデーションする
- 更新・削除は、対象が自テナントに属さない場合404を返す
- 作成・更新時、操作したユーザーのIDを記録する

## 影響範囲

- 新規ドメインのため、既存の画面・APIへの直接的な影響はない
- 既存のAssistant一覧・詳細APIのレスポンスへの変更もない（カテゴリ紐付けは別チケットのスコープ）
- フロントエンド（`frontend-angular`/`frontend`）側の画面追加は本チケットの対象外

## 移植方針

- 直近のPromptTemplate管理API（issue-36）のadmin向けルーター実装パターン（専用の管理者向けルーター、テナントID解決・管理者権限チェックの依存関係の使い方）を踏襲する
- 移植元は一覧取得が検索・ページネーションなしの全件取得のみのため、ページネーション付きレスポンス形式は使わず、シンプルなリストで返す
- レイヤー構成（router / service / repository / model / schema）は既存ドメイン（Group・PromptTemplate等）と同じ構成に揃える
- 中間テーブル（Assistantとの紐付け）は本チケットでは作成しない。カテゴリ本体のテーブルのみ新規作成する
