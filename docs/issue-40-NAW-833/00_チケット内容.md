# アシスタントカテゴリ管理APIの実装

## 概要

NAW-833「管理者はアシスタントにカテゴリを持たせたい」の移植。アシスタントカテゴリ（AssistantCategory）管理APIをFastAPIで実装する。

## 説明

### 背景

issue-24（Group管理API）実装時、AssistantエンティティはAssistantCategoryとのM2M関連（`assistant_category_mappings`）を持つ想定だったが、AssistantCategoryドメイン自体が未実装だったためスコープ外としていた（[assistant.py](../../backend/app/models/assistant.py) のコメント参照）。

issue-36（PromptTemplate管理API）までで、Group・Assistant・PromptTemplate・TenantEndpoint系の管理APIが完了した。今回は次のドメインとしてAssistantCategoryを移植する。

移植元のAssistantCategoryドメインを調査した結果、以下の構成であることが判明した。

- `assistant_categories`（本体：`id`, `tenant_id`, `name`（最大16文字）, `description`（最大255文字、任意）, `created_at`, `updated_at`, `updated_user_id`）
- `AssistantCategoryController`が持つのは管理者向けCRUDの5エンドポイントのみ（一般ユーザー向け参照系エンドポイントは存在しない）
- Assistant側へのカテゴリ紐付け（`assistant_category_mappings`、複合PK `assistant_id`+`category_id`）は本チケットのスコープ外

### やること（今回のスコープ）

移植元 `~/Documents/naw-server` の `AssistantCategoryController` のうち、以下のエンドポイントをFastAPIに移植する。

- `assistant_categories`テーブル・モデルを新規作成する（`id`, `tenant_id`, `name`, `description`, `created_at`, `updated_at`, `updated_user_id`）
- `POST /api/admin/assistant-categories`（作成。テナント管理者専用）
- `GET /api/admin/assistant-categories`（テナント内の全カテゴリ一覧取得）
- `GET /api/admin/assistant-categories/{id}`（単体取得）
- `PATCH /api/admin/assistant-categories/{id}`（更新）
- `DELETE /api/admin/assistant-categories/{id}`（削除）

バリデーション: `name`必須・16文字以内、`description`は任意・255文字以内。

### スコープ外（後続チケット）

- Assistant側へのカテゴリ紐付け（`assistant_category_mappings`相当）。issue-24→issue-30（Group→紐付け）、issue-36→後続（PromptTemplate→紐付け）と同様に、本体CRUD完了後に別チケットで対応する
- カテゴリでのAssistant絞り込み等、Assistant一覧APIへの影響
