# 08_動作確認

## 確認環境

- ローカルDB: `docker compose`起動済みの`naw-fastapi-postgres`（PostgreSQL、ポート5433）
- マイグレーション: `uv run alembic upgrade head`（007→008、`assistant_categories`テーブル作成）を実行
- サーバー: `uv run uvicorn app.main:app --port 8001`
- シードデータ: `backend/seed.sql`にアシスタントカテゴリの動作確認用データ（テナント`test-tenant`、カテゴリ名「業務効率化」）を追加し投入
- 認証: `create_access_token("admin", "test-tenant")`（テナント管理者）・`create_access_token("user01", "test-tenant")`（一般ユーザー）で発行したJWTを`Authorization: Bearer`ヘッダーに付与してcurlで直接呼び出し

## 確認手順・結果

| # | 操作 | 結果 |
|---|---|---|
| 1 | `GET /api/admin/assistant-categories`（管理者、シードデータあり） | 200、シード投入した「業務効率化」カテゴリが1件返る |
| 2 | `POST /api/admin/assistant-categories`（管理者、正しいリクエスト） | 201、`id`・`name`・`description`・`updatedAt`を含むレスポンスが返る |
| 3 | `GET /api/admin/assistant-categories/{id}`（作成した2の`id`） | 200、作成時と同内容が返る |
| 4 | `PATCH /api/admin/assistant-categories/{id}`（名前・説明を変更） | 200、変更後の内容が返り`updatedAt`が更新される |
| 5 | `POST /api/admin/assistant-categories`（`name`が空白のみ） | 422、`カテゴリ名は必須です`のバリデーションエラー |
| 6 | `GET /api/admin/assistant-categories`（一般ユーザー`user01`） | 403、`Access Denied` |
| 7 | `DELETE /api/admin/assistant-categories/{id}`（2で作成したデータ） | 204 |
| 8 | `GET /api/admin/assistant-categories/{id}`（7で削除済みの`id`） | 404、`Assistant category not found` |
| 9 | `POST /api/admin/assistant-categories`（既存と同名「業務効率化」で作成、一意制約違反） | 500（`IntegrityError`が未ハンドリングのため）。移植元Java側も同種の重複名エラーを明示的にハンドリングしておらず、DB制約違反時に生の例外が伝播する挙動は同じであるため、本チケットでは想定通りの挙動として扱う |
