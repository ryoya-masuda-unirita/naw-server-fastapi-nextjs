## テーブル定義

移植元Liquibase（`assistant_categories`のchangeset-001・002）に準拠しつつ、既存FastAPI側の`tenant_id`外部キーの慣例（`ondelete="CASCADE"`）に合わせる。

| カラム | 型 | 制約 |
|---|---|---|
| `id` | `varchar(32)` | PK、`uuid4().hex`をデフォルト生成 |
| `tenant_id` | `varchar(32)` | NOT NULL、FK→`tenants.id` `ON DELETE CASCADE` |
| `name` | `varchar(32)` | NOT NULL |
| `description` | `text` | NULL可 |
| `created_at` | `timestamptz` | NOT NULL、`server_default=now()` |
| `updated_at` | `timestamptz` | NOT NULL、`server_default=now()`、`onupdate=now()` |
| `updated_user_id` | `uuid` | NOT NULL（`users.id`へのFKは移植元でも未付与のため本チケットでも付与しない） |

- 一意制約: `(tenant_id, name)`（移植元の`uq_assistant_categories_tenant_id_name`を踏襲）
- DBカラム長は移植元Liquibase通り32文字とするが、APIバリデーションは移植元Java（`@Size(max=16)`）に合わせて`name`を16文字以内とする（DBは将来の拡張余地、API制約はJava側の実仕様に合わせる）

## API仕様

ベースパス: `/api/admin/assistant-categories`（テナント管理者専用、`require_admin`依存関数を全エンドポイントに適用）

| メソッド | パス | リクエスト | レスポンス | 異常系 |
|---|---|---|---|---|
| POST | `` | `AssistantCategoryCreateRequest` | 201 `AssistantCategoryResponse` | バリデーション失敗時422 |
| GET | `` | - | 200 `list[AssistantCategoryResponse]` | - |
| GET | `/{id}` | - | 200 `AssistantCategoryResponse` | 対象なし・他テナント時404 |
| PATCH | `/{id}` | `AssistantCategoryUpdateRequest` | 200 `AssistantCategoryResponse` | 対象なし・他テナント時404、バリデーション失敗時422 |
| DELETE | `/{id}` | - | 204 | 対象なし・他テナント時404 |

### スキーマ

```python
class AssistantCategoryCreateRequest(BaseModel):
    name: str  # 1〜16文字、前後空白のみは不可
    description: str | None = None  # 255文字以内

class AssistantCategoryUpdateRequest(BaseModel):
    name: str
    description: str | None = None

class AssistantCategoryResponse(BaseModel):
    id: str
    name: str
    description: str | None
    updatedAt: datetime
```

- 移植元`AssistantCategoryGetResponse`に`tenantId`が含まれないため、レスポンスも`id`/`name`/`description`/`updatedAt`のみとする
- `name`のバリデーション（必須・前後空白のみ不可・16文字以内）と`description`のバリデーション（255文字以内）は`pydantic.field_validator`で実装する
  - **設計判断**: 本プロジェクトの既存スキーマ（`GroupCreateRequest`等）にはこの粒度のフィールドバリデーションが実装されていないが、移植元Javaが`@NotBlank`・`@Size`で明示的にテストしている挙動のため、本チケットで新たにpydantic側の検証を追加する
  - バリデーション失敗時のステータスはFastAPI標準の422とする（移植元Javaは400だが、本プロジェクトにHTTPステータスを400に上書きするグローバルハンドラの前例がないため、既存の`RequestValidationError`のデフォルト挙動に合わせる）

## サービス層

`PromptTemplateService`と同様、`@staticmethod`によるクラス構成とする。

```python
class AssistantCategoryService:
    @staticmethod
    async def create_assistant_category(tenant_id, current_user, req, session) -> AssistantCategoryResponse: ...

    @staticmethod
    async def get_assistant_categories(tenant_id, session) -> list[AssistantCategoryResponse]: ...

    @staticmethod
    async def get_assistant_category(category_id, tenant_id, session) -> AssistantCategoryResponse: ...
        # 見つからない場合 HTTPException(404)

    @staticmethod
    async def update_assistant_category(category_id, tenant_id, current_user, req, session) -> AssistantCategoryResponse: ...
        # 見つからない場合 HTTPException(404)

    @staticmethod
    async def delete_assistant_category(category_id, tenant_id, session) -> None: ...
        # 見つからない場合 HTTPException(404)
```

- 作成・更新時、`updated_user_id`に`current_user.id`（UUID）を設定する（移植元のSecurityContext解決ロジックはFastAPI側では不要。JWT認証で得た`current_user`をそのまま使う）
- 404判定はルーターではなくサービス層で行う（issue-36のcode-review指摘を踏襲した既存方針）

## リポジトリ層

```python
class AssistantCategoryRepository:
    @staticmethod
    async def create(category: AssistantCategory, session) -> AssistantCategory: ...

    @staticmethod
    async def find_by_tenant_id(tenant_id, session) -> list[AssistantCategory]: ...

    @staticmethod
    async def find_by_id_and_tenant_id(category_id, tenant_id, session) -> AssistantCategory | None: ...

    @staticmethod
    async def delete(category: AssistantCategory, session) -> None: ...
```

一覧・単体取得のみで関連テーブルとのJOINがないため、N+1問題は発生しない。
