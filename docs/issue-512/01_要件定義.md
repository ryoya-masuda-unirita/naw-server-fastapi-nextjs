# 01_要件定義

## 背景

移植元は `X-Tenant-ID` ヘッダを任意にし、無ければ認証したテナントを使う。こちらは、サブドメインを廃止し、ログイン画面で入力したテナント ID を `X-Tenant-ID` で送る方式で、ヘッダを必須にしている。差分として残るが、意図的な判断である。

## 機能要件

| No | 要件 |
|---|---|
| R-01 | 「ヘッダ必須のまま据え置く」判断と理由を、プロジェクトの方針文書（`CLAUDE.md`）に記録する |
| R-02 | 調査エージェントが、この差分を未移植として検出・Issue 化しないよう、記録の位置と書き方を既存の除外（サブドメイン）と並べる |

## 非機能要件

- コード・API の挙動は変えない

## スコープ外

- ヘッダを任意にする実装
- ヘッダ必須の挙動を確かめる追加のテスト（既存の `get_verified_tenant_id` のテストの範囲）
