# 02_基本設計

## 変更対象

- ベクトルDBクライアント層（新規、`core/`配下）
- メッセージ送信サービス（`stream_message_content`のRAG分岐追加）
- ファイル取得リポジトリ（複数ファイルIDでの一括取得メソッド追加）
- 依存パッケージ（Azure AI Search Python SDK追加）

`llm_chat_service.py`は変更対象外（01_要件定義.md参照）。

## 画面 / API 変更概要

`POST /api/messages/content`（メッセージ送信、SSEストリーミング）のリクエスト・レスポンス形式（`MessageContentCreateRequest`/`MessageContentResponse`）自体は変更しない。既存の`context`・`referencePaths`フィールドが、SAAS_RAGアシスタントの場合に実際の値で埋まるようになる。

アシスタント種別が`SAAS_RAG`の場合に400エラーとなっていた既存の制約を撤廃し、`SAAS_RAG`の場合はRAG検索を行ったうえで応答を生成するよう変更する。`SECURE`タイプは引き続き非対応（400）のまま据え置く。

## 影響範囲

- `backend/app/services/message_service.py`: `stream_message_content`のアシスタント種別チェック分岐、RAGコンテキスト構築処理の追加
- `backend/app/repositories/file_repository.py`: 複数ファイルIDの一括取得メソッド追加（N+1回避）
- `backend/app/core/vector_store.py`（新規）: Azure AI Searchへの類似検索クライアント
- `backend/pyproject.toml`: `azure-search-documents`依存追加
- 既存テスト`tests/unit/test_message_service.py`の`test_raises_400_when_assistant_type_is_not_saas_chat`は、SAAS_RAGが400を返す前提のテストのため、SECUREのみを検証する内容に修正する

## 移植方針

- ベクトルDB製品（Azure AI Search）・接続情報の解決方法（テナントのVDBタイプエンドポイント）・インデックス名（VDB接続情報が属するテナントID）・検索結果のメタデータキー（`fileUniqueId`）は移植元の挙動をそのまま踏襲する。
- 移植元Spring AIの`AzureVectorStore`はインデックススキーマの自動作成も行うが、本Issueではスキーマ作成を行わず、既存インデックスへの検索のみ実装する（01_要件定義.mdのスコープ外を参照）。Azure AI Search Python SDK（`azure-search-documents`）の非同期クライアントを直接使用し、フィールド名は移植元のSpring AI標準スキーマ（`content`・`metadata`・`embedding`）を踏襲する。
- 埋め込みモデルのデプロイ名は移植元同様、テナントエンドポイントのモデル設定を参照せず固定値`text-embedding-ada-002`を使う（移植元`MessageService.EMBEDDING_MODEL_NAME`定数に対応）。
- チャット応答のトークン使用量クレジット計算に使う`token_weight`は、移植元`buildRagContext`の戻り値に合わせてSAAS_RAGの場合は固定値`1.0`を使う（SAAS_CHATはAIモデルの`token_weight`を使う点と異なるが、移植元の挙動をそのまま踏襲する）。埋め込みトークンのクレジット換算には、埋め込み用AIモデル（`AZURE_OPENAI_EMBEDDING` + `text-embedding-ada-002`）が存在すればその`token_weight`を、存在しなければ`1.0`を使う（移植元`AIModelService.resolveTokenWeight`の「見つからなければ1.0にフォールバックする」挙動に合わせる）。
- ベクトル検索結果の本文連結は区切り文字なしで連結する（移植元`contentBuilder.append(doc.getText())`の挙動をそのまま踏襲する）。
- ベクトルDB・埋め込みAPIの呼び出しはいずれもストリーミング開始前に行い、失敗時は400エラーとする（既存のSAAS_CHATにおけるエンドポイント/AIモデル解決と同じ方針）。
