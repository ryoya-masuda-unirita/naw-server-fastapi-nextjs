# 03_詳細設計

## 実装対象ファイル

### 新規: `backend/app/core/vector_store.py`

Azure AI Searchへの類似検索を行うクライアント層。`services/`からはこのクラスのみをモックすればテストできるようにする（`AzureLlmChatClient`/`AzureLlmEmbeddingClient`と同じ配置方針）。

```python
FILE_UNIQUE_ID_METADATA_KEY = "fileUniqueId"  # 移植元 VectorStoreFactory.CustomMetaField.File_Unique_ID
DEFAULT_TOP_K = 4  # Spring AI SearchRequest のデフォルト値を踏襲

@dataclass(frozen=True)
class VectorSearchResult:
    content: str
    file_unique_id: str | None

class AzureAiSearchVectorStoreClient:
    @staticmethod
    async def similarity_search(
        endpoint: str,
        api_key: str,
        index_name: str,
        query_vector: list[float],
        top_k: int = DEFAULT_TOP_K,
    ) -> list[VectorSearchResult]:
        """Azure AI Searchへベクトル類似検索を実行する。

        Raises:
            HTTPException: Azure AI Searchへの接続・検索に失敗した場合は400。
        """
```

- `azure.search.documents.aio.SearchClient` + `azure.search.documents.models.VectorizedQuery` を使用し、`fields="embedding"`のベクトルフィールドに対して`k_nearest_neighbors=top_k`で検索する。`select=["content", "metadata"]`のみ取得する。
- 検索結果の`metadata`列（JSON文字列）から`fileUniqueId`をパースする。
- `azure.core.exceptions.HttpResponseError`・`azure.core.exceptions.ServiceRequestError`を捕捉し、`HTTPException(400, "Failed to connect to vector database")`へ変換する（移植元「データベースと接続できません」に相当）。

### 変更: `backend/app/services/message_service.py`

- モジュール定数`EMBEDDING_MODEL_NAME = "text-embedding-ada-002"`を追加（移植元`MessageService.EMBEDDING_MODEL_NAME`に対応）。
- `stream_message_content`のアシスタント種別チェックを、`SECURE`のみ非対応とするよう変更する（`SAAS_RAG`は許可する）。
- 新規プライベートメソッド`_build_rag_context`（staticmethod）を追加し、`SAAS_RAG`の場合のみ呼び出す。

```python
@staticmethod
async def _build_rag_context(
    tenant_id: str,
    assistant: Assistant,
    user_input: str,
    session: AsyncSession,
) -> tuple[str, list[str], int, float]:
    """RAGコンテキスト(context文字列, 参照ファイルパス一覧, 埋め込みトークン数, 埋め込みcredit換算用token_weight)を構築する。

    Raises:
        HTTPException: インデックス未紐付け・埋め込みエンドポイント未検出・
            ベクトルDB接続情報未検出の場合は400。
    """
```

処理順序:

1. `assistant.index_id`が`None`、または`IndexRepository.find_by_id_and_tenant_id`で解決できない場合、400「No index found for this assistant」。
2. `IndexRepository.find_tenant_endpoints_grouped_by_index_ids([index.id], tenant_id, session)`で取得したテナントエンドポイントから`type == AZURE_OPENAI_EMBEDDING`のものを1件選ぶ（複数ある場合は`id`最小を採用し、`AssistantEndpointRepository.find_chat_endpoint`と同様の決定的な選び方にする）。無ければ400「No embedding endpoint found for this index」。
3. `TenantEndpointRepository.find_by_tenant_id_and_type(tenant_id, EndpointType.VDB, session)`の先頭要素をVDB接続情報とする。無ければ400「No vector database connection found for this tenant」。
4. `AzureLlmEmbeddingClient.create_embedding(embedding_endpoint.endpoint, embedding_endpoint.api_key, EMBEDDING_MODEL_NAME, user_input, dimensions=None)`でユーザー入力をベクトル化する。
5. `AzureAiSearchVectorStoreClient.similarity_search(vdb.endpoint, vdb.api_key, index_name=vdb.tenant_id, query_vector=embedding_result.embedding, top_k=DEFAULT_TOP_K)`を実行する（インデックス名はVDB接続情報のテナントID。02_基本設計.md参照）。
6. 検索結果から`file_unique_id`一覧を重複除去して収集し、`FileRepository.find_by_ids_and_tenant_id`で対象ファイルを1クエリで取得、`id`をキーにした辞書を作る。
7. 検索結果を順番に処理し、辞書に存在するファイルのみ`content`を区切り文字なしで連結し、`file.reference`（Noneでなければ）を参照ファイルパスへ追加する。
8. 埋め込みモデル(`AZURE_OPENAI_EMBEDDING` + `EMBEDDING_MODEL_NAME`)の`AIModel`を`AIModelRepository.find_by_endpoint_type_and_name`で取得できれば`positive_token_weight(model.token_weight)`、できなければ`1.0`を埋め込み用`token_weight`として返す。
9. `(rag_context, reference_paths, embedding_result.tokens, embedding_token_weight)`を返す。

`stream_message_content`本体では、`SAAS_RAG`の場合のみ`_build_rag_context`を呼び出し、`rag_context`が空でなければ`ChatMessage(role="system", content=f"以下のコンテキスト情報を参考にして回答してください:\n\n{rag_context}")`を`chat_messages`の先頭に追加する。また、`_persist_message_content`へ渡す`context`・`file_paths`（`referencePaths`をカンマ結合）、`_persist_token_usage`へ渡す`embedding_tokens`・チャット`token_weight`（RAGの場合は固定`1.0`。02_基本設計.md参照）を、SAAS_RAGかどうかで出し分ける。

`_persist_message_content`・`_persist_token_usage`は、`context`・`file_paths`・`embedding_tokens`・`embedding_credits`を保存できるよう引数を拡張する（デフォルト値でSAAS_CHATの既存呼び出しに影響を与えない）。
