# 05_テスト詳細設計

## `backend/tests/unit/test_vector_store.py`（新規）

`azure.search.documents.aio.SearchClient`をモックして検証する。

- `test_similarity_search_returns_content_and_file_unique_id`: `client.search`が`content`・`metadata`（`{"fileUniqueId": "f001"}`のJSON文字列）を含む結果を返すとき、`VectorSearchResult(content=..., file_unique_id="f001")`のリストが得られること
- `test_similarity_search_returns_none_file_unique_id_when_metadata_missing`: `metadata`が空/`fileUniqueId`を含まない場合、`file_unique_id=None`になること
- `test_similarity_search_raises_400_on_http_response_error`: `client.search`が`HttpResponseError`を送出した場合、`HTTPException(400)`に変換されること

## `backend/tests/unit/test_message_service.py`（追加・修正）

既存の`TestStreamMessageContent`クラスへ以下を追加する。ヘルパーとして`_index()`・`_index_endpoint(type=EndpointType.AZURE_OPENAI_EMBEDDING)`・`_vdb_endpoint()`・`_rag_assistant(index_id="index-1")`を追加する。

- `test_raises_400_when_secure_assistant_type`: 既存の`test_raises_400_when_assistant_type_is_not_saas_chat`を、`SECURE`アシスタントで400になることを検証する内容に置き換える（SAAS_RAGは非対応でなくなったため）
- `test_raises_400_when_rag_assistant_has_no_index_id`: `assistant.index_id is None`の場合400になること
- `test_raises_400_when_rag_index_not_found`: `index_id`はあるが`IndexRepository.find_by_id_and_tenant_id`が`None`を返す場合400になること
- `test_raises_400_when_rag_embedding_endpoint_not_found`: インデックスに紐づくテナントエンドポイントに`AZURE_OPENAI_EMBEDDING`タイプが含まれない場合400になること
- `test_raises_400_when_rag_vector_db_endpoint_not_found`: `TenantEndpointRepository.find_by_tenant_id_and_type`が空リストを返す場合400になること
- `test_rag_streams_with_context_from_vector_search`: `AzureLlmEmbeddingClient.create_embedding`・`AzureAiSearchVectorStoreClient.similarity_search`・`FileRepository.find_by_ids_and_tenant_id`をモックし、検索結果2件（いずれも解決可能なファイル）から区切り文字なしで連結したコンテキストがSSE `complete`イベントの`context`に含まれ、`chat_messages`（`AzureLlmChatClient.stream_chat`への呼び出し引数）の先頭にRAGシステムメッセージが追加されていること、`MessageContentRepository.save`に渡される`context`・`file_paths`が期待通りであることを検証する
- `test_rag_skips_files_not_found_in_tenant`: 検索結果2件のうち1件が`FileRepository.find_by_ids_and_tenant_id`の戻り値に含まれない場合、コンテキスト・参照ファイルパスに反映されないことを検証する
- `test_rag_no_system_message_when_search_returns_empty`: ベクトル検索結果が空の場合、`chat_messages`にRAGシステムメッセージが追加されないことを検証する
- `test_rag_persists_embedding_tokens_and_credits`: `TokenUsage`保存時（`session.add`の引数）に`embedding_tokens`・`embedding_credits`が期待通りの値になることを検証する

いずれも既存の`_mock_new_session`・`_consume`・`_AsyncChunkIterator`ヘルパーを再利用する。RAG用のモックは`@patch("app.services.message_service.IndexRepository...")`等、既存パッチと同じ形式で対象モジュール内のインポート名を指定する。
