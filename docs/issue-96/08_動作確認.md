# 08_動作確認

## 確認環境

本Issueは`naw-issue-loop`スキル（全自動モード）での対応のため、ブラウザでの実操作確認は行わず、自動テスト（pytest）の実行結果で動作確認を代替する。

## 確認手順

```bash
cd backend
uv run ruff check .
uv run pytest tests/unit -q
docker compose up -d   # backend/../docker-compose.yml のPostgreSQLを起動
uv run alembic upgrade head
uv run pytest -q       # unit + integration
```

## 確認結果

- `uv run ruff check .` : `All checks passed!`
- `uv run pytest tests/unit -q` : `169 passed`
- `uv run pytest -q`（integration含む全体）: `635 passed`
- 新規追加テスト（`tests/unit/test_vector_store.py` 4件、`tests/unit/test_message_service.py` の `TestStreamMessageContentRag` 6件、既存の`SAAS_RAG非対応`テストを`SECURE`向けに修正した1件）はすべて成功した
- `mypy`はこのリポジトリで既存のSQLModel/SQLAlchemyの型不整合による大量の既存エラー（本Issue着手前の`develop`時点で415件）が残っているため、本Issueの変更による新規エラーの有無のみ差分確認した。差分は`file_repository.py`の`find_by_ids_and_tenant_id`（`.in_()`呼び出し）由来の2件のみで、いずれも同ファイル内の既存メソッドと同種のmypy誤検出であり、実質的な型エラーではない
