# 03_詳細設計

移植元は `~/Documents/unirita-develop-pj/secuaigent-ref/client/src/app/`（以下 `app/`）。移植先は `frontend/src/`（以下 `src/`）。

## 1. ルート定数 `src/lib/constants/routes.ts`

`app/core/constants/routes.config.ts` を同じ名前・同じ値で移す（`ROUTE_SEGMENTS`・`AUTH_PATHS`・`APP_PATHS`・`ROUTES`）。

- `AUTH_PATHS.PW_RESET = 'password/reset'` → `ROUTES.AUTH.PW_RESET = '/auth/password/reset'`
- 持たないもの（使われていない、または非表示機能）: `LEARNING_DATA`・`DATA_SOURCE`・`GLOSSARY*`・`CHAT_MEDICAL`・`CHAT_INVENTORY`・`CHAT_RECRUITMENT`・`CHAT_SECUAIGENT`・`CHAT_HISTORY`（管理外の `/chat-history`）・`CHAT_PATHS`・`ROUTE_SEGMENTS.USER`
- `CHAT_SEARCH: '#'`・`ADMIN_CONSOLE_HOME`（`/admin/management`）はサイドバーの設定で使うため残す

## 2. ルート定義 `src/routes/index.tsx`

`app/app.routes.ts`・`features/admin/admin.routes.ts`・`features/auth/auth.routes.ts`・`features/chat/chat.routes.ts` を 1 つのルート配列にする。

- ログイン・パスワードリセットは即時読み込み（既存テストを同期のまま保つ）。それ以外は `lazyPage()`（`React.lazy` + `Suspense fallback={null}`）で遅延読み込み
- 構成

```
/auth/login            RequireNoAuth > LoginPage
/auth/password/reset   PwResetPage
/auth                  → /auth/login
/chat/viewer/:chatId   RequireAuth > ChatViewerPage            （レイアウトなし）
/chat/share/:shareId   RequireAuth > ChatSharedPage            （レイアウトなし）
/                      RequireAuth > AdminLayout
  index                → /dashboard
  dashboard            ChatNewPage
  users, users/new, users/:id, users/:id/edit   RequireAdmin > 旧ユーザー管理
  reports, settings    RequireAdmin
  admin                RequireAdminConsole > Outlet
    users              RequireTenantAdmin > AdminUserListPage
    groups             GroupListPage
    groups/:id         RequireGroupAccess > GroupDetailPage
      index → users / users / templates / assistants
    groups/:id/members RequireGroupAccess > GroupMembersPage
    tenant・chat-history・chat-history/:roomId・assistants・templates・feedback・training-data・training-data/:id
                       RequireTenantAdmin
  library, library/:id
  chat                 → /dashboard
  chat/new, chat/assistant, chat/:roomId
  chat-shared-history/:roomId, feedback-preview/:roomId
  *                    → /dashboard
```

- `/chat` は移植元では `CHAT_ROUTES` の `'' → /admin/chat/new` にリダイレクトされるが、`/admin/chat/new` に一致するルートはなく `ADMIN_ROUTES` の `'**' → dashboard` で最終的に `/dashboard` になる。React では直接 `/dashboard` へリダイレクトする
- React Router はパスの具体度で優先順位を決めるため、`/chat/viewer/:chatId`・`/chat/new` は `/chat/:roomId` より優先される（Angular の宣言順による一致と同じ結果）
- 既存の `ProtectedRoute`・`PublicRoute` は `guards.tsx` の `RequireAuth`・`RequireNoAuth` に置き換えて削除。`routes/app/dashboard.tsx` とテストは削除（ダッシュボードは新規チャット画面）

## 3. ガード `src/routes/guards.tsx`

`app/core/guards/*.ts` を移す。全ガードは `{ children: ReactNode }` を受け取り、条件を満たさなければ `<Navigate replace>` を返す。

| React | 移植元 | 実装 |
|---|---|---|
| `RequireAuth` | `authGuard` | 未認証 → `ROUTES.AUTH.LOGIN` |
| `RequireNoAuth` | `noAuthGuard` | 認証済み → `ROUTES.APP.DASHBOARD` |
| `RequireAdmin` | `adminGuard` | 未認証 → ログイン、非管理者 → `null`（Angular の `return false` = 遷移取り消し） |
| `RequireAdminConsole` | `adminConsoleGuard` | 未認証 → ログイン、`!canAccessAdminConsole` → `ROUTES.APP.CHAT_NEW` |
| `RequireTenantAdmin` | `tenantAdminGuard` | `isAdmin` → 通す、`isGroupAdmin` → `ROUTES.APP.ADMIN_GROUPS`、他 → `CHAT_NEW` |
| `RequireGroupAccess` | `groupAccessGuard` | `isAdmin` → 通す、`useParams().id` が `adminGroupIds` に含まれる → 通す、他 → `ADMIN_GROUPS` |

`glossaryAdminRouteMatch`・`glossaryUserRouteMatch`・`roleGuard`（未使用）は移植しない。

## 4. 認証ストア `src/store/auth-store.ts`

`app/core/stores/auth.store.ts` の computed を派生状態として追加する。

- `deriveAuthState(user)` を export（テストで状態を組み立てるため）: `isAuthenticated`・`isAdmin`・`isGroupAdmin`（`groups.some(groupAdmin)`）・`isGroupAdminOnly`（`!isAdmin && isGroupAdmin`）・`canAccessAdminConsole`（`isAdmin || isGroupAdmin`）・`adminGroupIds`・`userName`
- `ensureInitialized`: sessionStorage から復元したユーザーのグループを控え、`GET /api/auth` の結果にグループがなければ控えたグループを引き継ぐ（移植元 `initializeSession` と同じ。backend の `GET /api/auth` はグループを返さないため、これがないと再読み込みでグループ管理者の権限が消える）

## 5. レイアウト設定 `src/lib/constants/layout.ts`・型 `src/types/layout.ts`

- `ADMIN_LAYOUT_CONFIG`: `app/shared/layouts/layout.config.ts` の `ADMIN_LAYOUT_CONFIG` を移す（移植元はログイン済みユーザー全員がこの設定を使う。`USER_LAYOUT_CONFIG` は未使用のため持たない）。`sectionGroups` は移植元と同じく用語集・データソースをコメントアウト扱い（持たない）
- `ADMIN_MENU_SECTIONS`・`GROUP_ADMIN_MENU_SECTIONS`: `layouts/admin-layout/components/admin-sidebar/admin-sidebar.component.ts` の `FULL_MENU_SECTIONS`・`GROUP_ADMIN_MENU_SECTIONS`
- `SCREEN_USE_BACK_SIDEBAR`・`PARENT_OF_SCREEN_USE_BACK_SIDEBAR`: `core/constants/global.config.ts`
- 型: `MenuItem`・`SectionGroup`・`UserMenuAction`・`LayoutConfig`・`AdminMenuItem`・`AdminMenuSection`・`SidebarMode`。既存の `USER_MENU_ACTIONS` は `ADMIN_LAYOUT_CONFIG.userMenuActions` に置き換えて削除

## 6. サイドバーのモード `src/components/layouts/sidebar-mode.ts`

`resolveSidebarMode(pathname, config): SidebarMode`

- `adminTitleMap` のいずれかのキーで始まる → `'admin'`（`isAdminManagementRoute`）
- `SCREEN_USE_BACK_SIDEBAR` のいずれかを含み、`PARENT_OF_SCREEN_USE_BACK_SIDEBAR` のどれとも一致しない → `'back'`（`checkUseBackSidebar`）
- それ以外 → `'default'`

サイドバーの挙動（`sidebar.component.ts`）:

- 遷移ごと（初回描画を除く。移植元は `NavigationEnd` の購読）: `closeMobileSidebar()`、`/dashboard`・`/chat/new` なら `queryClient.invalidateQueries({ queryKey: ['assistants'] })`・`['prompt-templates']`、管理モードでグループ管理者だけのユーザーが `ADMIN_GROUPS` 以外にいれば `ADMIN_GROUPS` へ（この 3 つ目は初回描画でも行う。移植元は `ngOnInit` でも `checkAdminRoute` を呼ぶ）
- ユーザーメニュー: `password` → `${ROUTES.AUTH.PW_RESET}?username=<user.id>`（移植元は router state で渡す。React のパスワードリセット画面はクエリから読むためクエリで渡す）、`logout` → `window.confirm`（#278 の確認ダイアログができたら置き換え）、`switch-role` → 管理モードなら `CHAT_NEW`、それ以外は管理者なら `ADMIN_TENANT`・グループ管理者なら `ADMIN_GROUPS`、`check-credit` → `UsageDialog` を開く
- `switch-role` の表示文言: 管理モード → `USER_MENU.SWITCH_TO_CHAT`、グループ管理者だけ → `USER_MENU.SWITCH_TO_TEAM_MANAGEMENT`、他 → `USER_MENU.SWITCH_TO_ADMIN`。`canAccessAdminConsole` でないときは隠す（移植元は `hidden` クラス）
- セクション開閉: 各セクションの `collapsed` を state に持つ。高さは `!collapsed || sidebarCollapsed` なら `items.length * 36px`、それ以外は `0`
- Ranabase: `window.open(externalSiteUrl, '_blank')`

移植元にあり移植しないもの: `pageTitleKey`・`hideHeader`・言語切り替え・`mobileMenuOpen`（テンプレートで未使用）、`handleGroupAdminAccessRevoked`（条件が常に偽）、ルーム一覧・並び替え・削除・リネーム（#285）。
