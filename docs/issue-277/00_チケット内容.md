# #277 issue-277 管理画面レイアウト・サイドバーのナビ・権限ガード・ルート規約をReactに移植する

## 概要

React の画面移植の土台。各画面の Issue より先に完了させ、並列移植でのファイル衝突を防ぐ。

## 説明

### 対象（移植元）

- `layouts/admin-layout`、`shared/layouts/admin-page-shell`、`shared/layouts/sidebar`（ナビ・権限別メニューの枠。ルーム一覧は別 Issue）
- `core/constants/routes.config.ts`（全画面のパス定数）、`app.routes.ts`・`features/admin/admin.routes.ts` のルート構成（全画面の枠だけ先に定義し、未移植の画面は仮の画面にする）
- `core/guards`（authGuard・adminGuard・adminConsoleGuard・tenantAdminGuard・groupAccessGuard・glossary の出し分け）と AuthStore の `canAccessAdminConsole`・`adminGroupIds`
- i18n 辞書 `public/i18n/ja.json`・`en.json` を丸ごと移植し、各画面がキーを足さなくて済むようにする
- PW リセットのパスを移植元と同じ `/auth/password/reset` に揃える
- 移植先のディレクトリ規約（`routes/admin/` 等）を決めて `frontend/.claude/CLAUDE.md` に書く

### 方針

- 目標は移植元（Angular `~/Documents/unirita-develop-pj/secuaigent-ref/client`）の完璧なクローン。見た目・文言（i18n）・操作・ルートのパス・入力チェックまで揃える。意図的な差分はテナント識別にサブドメインを使わないことだけ（ルート CLAUDE.md 参照）
- 移植先は `frontend/`（React、Vite + React Router）。規約は `frontend/.claude/CLAUDE.md`

### 追加指示（コーディネーター）

- この Issue は他の画面移植（9〜15 件を並列で作る）の土台。各画面のエージェントが `routes/index.tsx`・ルート定数・サイドバーを触らずに済むよう、全画面のパスとルートの枠（未移植画面は「未移植」と分かる仮の画面）・サイドバーのナビ項目（権限別）を先に全部定義する
- 「画面を足すときは、どのファイルに何を書くか」を `frontend/.claude/CLAUDE.md` に手順として書く
- 用語集（`/glossary`・`/glossary/:glossaryId/term-words`・`/assistants`）は移植元でも server 側が未実装で、サイドバーでもコメントアウトされた非表示機能（移植元コミット cce18504「用語辞書とデータソースを非表示」）。サイドバーに出さず、ルートの枠も作らない（#280・#292 は not planned でクローズ済み）。データソースなど、移植元のサイドバーで非表示・コメントアウトされている項目も出さない
