# 04_テスト設計

先にテストを書き、実装前に失敗することを確認する。MSW で、件数が 20・50・1,000 を超える一覧をモックする。

| No | 観点 | 期待結果 |
|---|---|---|
| 1 | `fetchAllPages` | 複数ページの全件・順序・重複なし、ちょうど 1 ページ分で空ページを取りに行かない、0 件、`total` に届かず空ページで止まる、ページサイズの指定、途中失敗は失敗のまま |
| 2 | テンプレートメニュー | 2,500 件が出る。`size: 0` を送らない |
| 3 | フィードバックのアシスタント候補・学習先フォルダ候補 | 2,500 件が出る |
| 4 | チーム詳細の追加候補（ユーザー・アシスタント・テンプレート） | 2,500 件が出る。ユーザーは `excludeGroupId` を毎ページ送る。途中で失敗したら、候補なし |
| 5 | アシスタント管理のチーム候補 | 100 件ずつ 3 ページ（上限を超えると 422 のモック） |
| 6 | チャット履歴の利用者の絞り込み | 2,500 人が出る。`includeUsage` は false |
| 7 | `needsNameLookup` | 名前が揃っていれば要らない、ID も名前もなければ要らない、管理者・ユーザー・アシスタント・テンプレートの名前がなければ要る、アシスタントの名前の件数が合わなければ要る |
| 8 | `useNameLookup` | 無効のあいだは取らない。有効なら、3 種を、1,000 件を超えても全ページ取る |
| 9 | チーム管理一覧（画面） | 名前が揃っていれば対応表を取らない。ID だけの項目があれば、対応表の応答を止めたままでも、一覧が出て、取れたら名前になる |
| 10 | 既存・全体 | `vitest` 全件、`tsc`、`eslint`、`vite build` |
