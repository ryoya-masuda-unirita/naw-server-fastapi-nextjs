# 02_基本設計

## 変更対象

1. **共通関数（新規）**: `client/src/lib/utils/fetch-all-pages.ts` に `fetchAllPages`・`FETCH_ALL_PAGE_SIZE`
2. **各 hook**: 00 の表の #1・#2・#4〜#10 を、`fetchAllPages` に置き換える（#3 は変えない。要判断 A）
3. **`useUsageFilterUsers`（`use-tenant.ts`）**: ユーザーの全件取得を、共通のユーザー取得（`fetchAllUsers` 相当）にまとめ、チャット履歴の利用者の絞り込みでも使う
4. **テスト**: `fetchAllPages` の単体テストと、各 hook の、21 件目以降（またはページが複数）の候補が出るテスト

## 画面 / API 変更概要

- 画面の見た目は変えない。候補・一覧の選択肢が、全件出る
- API は、候補のために呼ぶ回数が増える（1 ページ → 件数に応じて複数ページ）。呼ぶ API・パラメータの種類は変わらない

## 影響範囲

- 各画面の候補・対応表の取得が、件数が多いテナントで、時間がかかる（1,000 件ごとに 1 回）
- テンプレートメニューは、`size: 0` の特例（server が 0 を 20 に戻す）をやめ、通常のページングにする。server は変えない（`size=0` を受ける挙動は、ほかの呼び出しのために残す）
- 既存のテスト（各 hook・画面）が、1 ページを前提にしたモックだと、影響を受ける（確認する）

## 移植方針

- 移植元の `fetchAllPages` と同じ止め方（`total` に届く・空のページ）と、失敗の扱い（途中で失敗したら失敗のまま）
- 1 ページの件数は引数にして、server の上限が小さい `/admin/all-groups`（100）にだけ、100 を渡す
- 各所の失敗時の扱い（候補なし・ID 表示・共通エラートースト）は、今のまま
