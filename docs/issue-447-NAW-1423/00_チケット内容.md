# NAW-1423 候補の一覧が 20/50 件で切れる問題を直す

## 概要

Issue #447（NAW-1423〈NAW-1430〜1434〉の移植、`client/` 側）。選択肢・候補の取得が 1 ページ分で止まり、21 件目以降（箇所により 51 件目以降）が出ない。全ページを順に取る共通関数を作り、各所に適用する。

## 移植元の対応

- 新規 `shared/utils/fetch-all-pages.ts`: `fetchAllPages(fetchPage)`。0 ページ目から順に 1,000 件ずつ取り、空のページか、`total` に届いたら止める。途中で失敗したら、取れた分だけで候補を作らず、失敗のまま返す
- 適用先（移植元で `fetchAllPages` を使う箇所）
  1. テンプレートメニュー（`prompt-templates.service.ts`）
  2. アシスタント管理のチーム候補（`assistant-list-api.service.ts` の `getGroupOptions`）
  3. フィードバックのアシスタント候補・学習先フォルダ候補（`feedback-list-options.service.ts`・`feedback-message-api.service.ts`）
  4. チーム詳細の所属追加の候補（ユーザー・アシスタント・テンプレート）
  5. チーム管理一覧の名前の対応表（ユーザー・アシスタント・テンプレート）
  6. チャット履歴の利用者の絞り込み（`fetchAllUsers`。利用量を集計しない全ユーザー一覧）
- チーム管理一覧は、名前の対応表を、一覧 API が名前を返さない項目があるときだけ、画面ごとに 1 回読み込む（一覧の表示を、対応表の取得を待たせない）
- 利用状況タブの利用者絞り込み（NAW-1421）は、#426 / #432 で直し済み（対象外）

## こちらの現状と、server の上限

| # | 場所（`client/src/hooks/`） | 現状 | 呼ぶ API | server の `size` の上限 |
|---|---|---|---|---|
| 1 | `use-prompt-templates.ts` | `size: 0`（server が 0 を既定の 20 に戻すので、20 件で切れる） | `GET /prompt-templates` | 1000 |
| 2 | `use-assistant-list.ts`（チーム候補） | `size: 100` の 1 ページ | `GET /admin/all-groups` | **100** |
| 3 | `use-assistant-list.ts`（学習先フォルダ候補） | `size: 1000` の 1 ページ | `GET /admin/indexes` | 1000 |
| 4 | `use-feedback.ts`（アシスタント候補） | 既定の 20 件 | `GET /admin/assistants` | 1000 |
| 5 | `use-feedback.ts`（学習先フォルダ候補） | 既定の 20 件 | `GET /admin/indexes` | 1000 |
| 6 | `use-group-users.ts`（追加候補） | `size: 50` の 1 ページ | `GET /admin/users`（`excludeGroupId`） | 1000 |
| 7 | `use-group-assistants.ts`（追加候補） | `size: 50` の 1 ページ | `GET /admin/assistants`（`excludeGroupId`） | 1000 |
| 8 | `use-group-templates.ts`（追加候補） | `size: 50` の 1 ページ | `GET /admin/prompt-templates`（`excludeGroupId`） | 1000 |
| 9 | `use-group-list.ts`（名前の対応表 ×3） | `size: 1000` の 1 ページ（1,000 件で切れる） | users・assistants・prompt-templates | 1000 |
| 10 | `use-chat-history.ts`（利用者の絞り込み） | 直近 20 件の履歴から利用者を推定 | `GET /admin/users`（`includeUsage` 既定 false） | 1000 |

- **移植元の 1,000 件ずつを、そのまま持ち込めないのは #2 だけ**（`/admin/all-groups` の上限が 100）。そのため、`fetchAllPages` は、1 ページの件数を引数で渡せるようにする（既定 1,000）
- 利用量を集計しない（`includeUsage=false`）は、server の既定が false なので、何も送らなくてよい。既存の `useUsageFilterUsers`（#426）は、`includeUsage: false` を明示して送っている
- `GET /admin/users` などは、並び替えの最後に ID を足してある（#427 のマージ後）ので、ページをまたいでも、重複・漏れは起きない
