## 詳細

### 1. グループ管理者（対応しない）
`/api/admin/users` は、こちらの server で `require_admin`（テナント管理者のみ）。ただし、client のガードで、グループ管理者は `/admin/chat-history` を開けず、グループ一覧へ移る（`routes/guards.test.tsx`）。同じ利用者が、画面を開けない。利用状況タブ（#426）も、同じ `/admin/users` を使っている。

### 2・3・6. 移植元と同じ挙動（対応しない）
移植元の `fetchAllUsers`・`fetchAllPages` は、現在のユーザー一覧から作り、途中のページが失敗したら、一部だけの候補を作らず失敗のまま返す。チーム管理一覧の対応表も、1 つでも失敗したら、全部空にして ID のまま表示する（既存の挙動）。一部だけの候補を出すと、そこにないものを選べない・間違った名前を出す、という別の問題になるため。

### 4. 判定のずれ（対応済み）
指摘の例（管理者の ID 2 件に、名前 1 件）は、`toViewModel` が、名前があれば対応表を使わずにそれを出す作りのため、対応表を取っても表示は変わらない（指摘の前提は違った）。ただし、2 つの判定の取捨選択がずれる危険は本物なので、「対応表を要らないと判定した項目は、対応表の有無で表示が変わらない」ことを、7 パターンで確かめるテストを足した。

### 5. キャッシュ（対応しない）
`useNameLookup` は、`staleTime` が既定の 0 で、画面を開き直すと取り直す（以前と同じ）。ウィンドウのフォーカスでは取り直さない（`refetchOnWindowFocus: false`、以前と同じ）。

### 7. 終わらない取得（対応しない）
1 回ごとに、項目が 1 件以上増え、`total`（有限）に届くか、空のページが来たら止まる。`page` を無視するサーバーでも、`total / 件数` 回で終わる。メモリは、`total` で上限が決まる。
