### `MessageContentRepository.save`

```python
@staticmethod
async def save(content: MessageContent, session: AsyncSession) -> MessageContent:
    """メッセージ内容を新規追加・コミットする。呼び出し元は保存専用の新規セッションを渡すこと。"""
    session.add(content)
    await session.commit()
    await session.refresh(content)
    return content
```

### `AssistantEndpointRepository.find_chat_endpoint`

単一アシスタントについて、`AZURE_OPENAI_CHAT`タイプのテナントエンドポイントとその紐付け（デプロイ名を保持する`AssistantEndpoint.model`）をあわせて取得する。既存の`find_endpoints_grouped_by_assistant_id`・`find_tenant_endpoints_grouped_by_assistant_id`はいずれも複数アシスタントの一括取得用（N+1回避目的）で、`api_key`と`model`（デプロイ名）を同時に返す用途に合わないため新設する。

```python
@staticmethod
async def find_chat_endpoint(
    assistant_id: str, tenant_id: str, session: AsyncSession
) -> tuple[AssistantEndpoint, TenantEndpoint] | None:
    """アシスタントに紐づくAzure OpenAI Chatエンドポイントを解決する。

    複数紐づく場合は`AssistantEndpoint.id`が最小のものを採用する
    （`LlmChatService.stream_chat`のテナントエンドポイント複数時の採用方針に合わせる）。
    """
    stmt = (
        select(AssistantEndpoint, TenantEndpoint)
        .join(TenantEndpoint, TenantEndpoint.id == AssistantEndpoint.endpoint_id)
        .where(
            AssistantEndpoint.assistant_id == assistant_id,
            AssistantEndpoint.tenant_id == tenant_id,
            TenantEndpoint.tenant_id == tenant_id,
            TenantEndpoint.type == EndpointType.AZURE_OPENAI_CHAT,
        )
        .order_by(AssistantEndpoint.id)
    )
    result = await session.execute(stmt)
    row = result.first()
    return (row[0], row[1]) if row else None
```

## サービス追加（`MessageService`）

`stream_message_content(tenant_id, current_user, req, session) -> StreamingResponse` を追加する。処理の骨子:

1. `MessageRepository.find_by_tenant_id_and_id(tenant_id, req.messageId, session)` でメッセージ解決。存在しなければ404。
2. `require_owned_room(tenant_id, current_user, message.room_id, session)` でルーム所有権チェック（403/404はここで送出）。
3. `message.assistant_id`が`None`、または`AssistantRepository.find_by_id_and_tenant_id`で解決できなければ400（`Invalid assistant`）。
4. `assistant.type != AssistantType.SAAS_CHAT` なら400（`Unsupported assistant type`。RAG/SECUREはスコープ外である旨をエラーメッセージに含める）。
5. `enforce_within_quota(tenant_id, session)` （超過時429、Issue #88実装済みをそのまま利用）。
6. `AssistantEndpointRepository.find_chat_endpoint(...)` でエンドポイント解決。`None`なら400。
7. `AIModelRepository.find_by_endpoint_type_and_name(AZURE_OPENAI_CHAT, assistant_endpoint.model, session)` でAIモデル解決。`None`なら400。
8. `historyMessages` を `ChatMessage` のリストへ変換し、末尾に `userInput` を `ChatMessage(role="user", content=userInput)` として追加。`_apply_additional_prompt`（Issue #88と同一ロジックをprivate関数として複製、または`llm_chat_service`から再利用可能ならインポートして共有）で`additionalPrompt`を前置。
9. ストリーミング開始前に必要な値（`endpoint_url`, `api_key`, `deploy_name`, `token_weight = positive_token_weight(...)`, `model_name`, `message_id`, `room_id`, `tenant_id`, `user_id`, `question_text = userInput`）をクロージャ変数として確定する。
10. `event_stream()` 非同期ジェネレータ内で `AzureLlmChatClient.stream_chat` を呼び出し、`text_delta`をSSE配信、最終チャンクで`input_tokens`/`output_tokens`を確定し`message_stop`を配信。
11. 例外発生時は`error`イベントを配信し、`status=ERROR`で永続化。正常終了時は`status=OK`で永続化。
12. `finally`相当の後処理として、新規セッション（`get_session_maker()`）で`MessageContent`を保存し、`Room.updated_at`を更新し、`TokenUsage`を保存（0件時はスキップ、Issue #88と同じ方針）。保存結果から`MessageContentResponse`相当のdictを組み立て`complete`イベントを配信する。

`_apply_additional_prompt`は`llm_chat_service.LlmChatService._apply_additional_prompt`をそのままインポートして再利用する（`ChatMessage`型を共有しているため流用可能。重複実装を避ける）。

## 実装時の補足（code-review対応）

- `AzureLlmChatClient.stream_chat`呼び出し時の`temperature`・`max_tokens`は、`MessageContentCreateRequest`に対応するフィールドを設けていない（本Issueのスコープ外）ため、Issue #88の`LlmChatRequest`のデフォルト値に合わせて`temperature=0.0`・`max_tokens=None`の固定値で呼び出す。モデルごとに調整したい場合は将来的に`AIModel`側にデフォルト値を持たせる形での対応を検討する。
- ステップ12の永続化は、実装上は`try/except`の外の逐次処理ではなく`finally`節で行う。クライアント切断時にStarletteが`event_stream()`に対して`aclose()`を呼び`GeneratorExit`（`except Exception`では捕捉されない）を送出しても、Azureで既に消費したトークンの記録・`MessageContent`の永続化が必ず行われるようにするため（code-review指摘対応）。ただし`GeneratorExit`処理中は`yield`できないため、`complete`イベントの送出はストリームが正常完了/エラー終了した場合のみ行う。
- 例外発生時、それまでに`text_delta`で配信済みの回答本文（`answer_text`）は例外メッセージで上書きしない。ストリーミング済みの内容を保持したまま`status=ERROR`で永続化する（code-review指摘対応。内部の例外メッセージがクライアントへの`complete`イベントや保存データの回答内容として露出・永続化されるのを防ぐため）。

## ルーター追加（`app/routers/messages.py`）

```python
@router.post("/content")
async def create_message_content(
    req: MessageContentCreateRequest,
    x_tenant_id: str = Depends(get_verified_tenant_id),
    current_user: User = Depends(get_current_user),
    session: AsyncSession = Depends(get_session),
) -> StreamingResponse:
    """メッセージ送信（アシスタント応答生成・SSEストリーミング）"""
    return await MessageService.stream_message_content(
        x_tenant_id, current_user, req, session
    )
```

パスは移植元と同じ`/api/messages/content`（単数形）。既存の内容一覧取得`/api/messages/contents`（複数形）とは名前が異なるため衝突しない。
