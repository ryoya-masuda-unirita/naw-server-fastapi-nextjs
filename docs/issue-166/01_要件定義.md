# 01_要件定義

## 背景

Issue #163で構築したPlaywright E2E基盤（`frontend-angular/e2e/`）を使い、`25DA61_結合テスト項目書_md/`の残り19カテゴリを順次自動化する。

## スコープ

### 対象

`04_ログアウト.md`〜`22_Waha!生成AI検索.md`（19カテゴリ、約604項目）のうち、自動化可能な項目。

### 進め方（規模への対応）

604項目を一度に実装するのは非現実的なため、カテゴリ単位で以下のサイクルを繰り返す。

1. 対象カテゴリのテスト項目書を読み、自動化可能／対象外を仕分ける（Issue #163の`04_テスト設計.md`と同じ形式）
2. 必要なテストデータを`backend/seed.sql`に追記する
3. `frontend-angular/e2e/`にspecファイルを追加し、実装・実行・PASS確認する
4. アプリ側の不具合を発見した場合は`test.skip`＋追跡Issue化（本Issueでは修正しない）
5. カテゴリ完了ごとに`docs/issue-166/`のタスクリストにチェックを入れ、コミットする

### 着手順序

`02_サマリ.md`の項目数が少ないカテゴリから着手し、認証まわり（`04_ログアウト`・`05_パスワード再設定`）はログインと関連が深いため優先する。

```
04_ログアウト(10) → 05_パスワード再設定(38) → 08_チャット検索(15) → 12_ワークスペース設定(16)
→ 10_チャットルーム(16) → 20〜22_Waha!生成AI(11) → 06_レイアウト(29) → 19_テンプレート(29)
→ 13_ユーザー管理(24) → 16_チャット履歴(25) → 09_ライブラリ(41) → 17_学習データ(47)
→ 15_アシスタント(48) → 18_フィードバック管理(52) → 07_チャット送信(55) → 14_チーム管理(71)
→ 11_チャット詳細(77)
```

（1カテゴリごとに動作確認・コミットを行うため、順序は目安であり進行中に調整してよい）

### 対象外（毎カテゴリ共通で適用する除外基準）

- ログイン試行回数上限等、他のテストに影響しうる状態変化を伴う項目
- 外部サービス（Waha!生成AI等）との実連携が必要で、モックや専用環境がないと検証できない項目
- 専用データ・専用実装の準備コストが大きい項目

これらはカテゴリごとの実装時に個別判断し、対象外とした理由を記録する。

## 完了条件

- 19カテゴリのうち、自動化可能な項目についてE2Eテストが実装され、`npx playwright test`で全件PASSすること
- カテゴリごとの自動化状況（対象/対象外の仕分け）が`docs/issue-166/`に記録されていること
- 発見したアプリ側の不具合が、追跡Issueとして起票されていること
