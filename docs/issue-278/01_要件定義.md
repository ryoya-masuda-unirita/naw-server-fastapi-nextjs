# 01_要件定義

## 背景

React への画面移植を進めるにあたり、管理画面・チャット画面で共通に使う UI 部品が React 側にない（ボタンと簡易な入力欄だけ）。
各画面の Issue がそれぞれ部品を作ると重複し、見た目もずれるため、移植元の共通部品を先にまとめて移植する。

## 機能要件

- 移植元の共通部品（shared/components）を React の部品として用意する
  - 一覧: 表（並べ替え・選択・モバイル表示）、リスト型の表、ページ送り
  - ダイアログ: 確認・入力用のダイアログ（ボタン構成・幅・閉じ方を移植元と同じ指定で変えられる）
  - 通知: トースト（種類ごとの色・アイコン・表示時間）、確認ダイアログの状態、ドロップダウンを 1 つだけ開いておく仕組み
  - 選択: 単一選択、検索付き単一選択、分割読み込みの選択、複数選択、チップ表示の複数選択コンボボックス
  - 入力: テキスト入力（パスワード表示切替・エラー表示）、複数行入力、スイッチ、ラジオ、並べ替え付き入力、コンボボックス、検索入力
  - その他: チェックボックス、ラジオ、スイッチ、タブ、ページ見出し、操作メニュー（デスクトップはドロップダウン、モバイルは下からのドロワー）、ファイルの選択・ドロップ・チップ、期間フィルター、スケルトン、ローディング表示、「任意」ラベル、アイコン、アイコンボタン
- 移植元のグローバル CSS（色・文字サイズ・共通クラス）をそのまま React に移す
- 見た目（クラス・DOM 構造・アイコン）、文言（i18n キー）、操作（キーボード・クリック・開閉の動き）、入力チェックを移植元に揃える
- 部品ごとに単体テストを付ける
- 各部品の使い方（props と例）を README にまとめる

## 非機能要件

- lint（警告 0）・型チェック・単体テスト・ビルドがすべて通ること
- 既存の画面（ログイン・パスワード変更）の挙動を壊さないこと

## スコープ外

- 画面（ページ）の移植、レイアウト・ルート（#277）、API の型・util（#279）
- 翻訳ファイルの全体同期（部品が使うキーは既にあるか、移植元にも無いキーのみ）
- 機能固有の部品（チャットの要約・アバターのアップロード）と、移植元でどこからも使われていないアイコン部品（並べ替え・コピー・ライブラリのアイコン）、ダイアログの見本ページ
