# 04_テスト設計

## テスト方針

- 部品ごとに単体テスト（Vitest + Testing Library + user-event）を付ける
- 利用者の操作（クリック・キー入力・ファイル選択・ドロップ）と、その結果の表示・通知（props のコールバック）を検証する
- 見た目は移植元のクラスが付いていることで検証する（色・大きさ・状態のクラス）
- 時間に依存するもの（トーストの自動消去・期間の計算）はタイマー・時刻を固定する
- モバイル表示は画面幅を変えて検証する
- 既存のログイン・パスワード変更のテストが通り続けることを確認する

## テスト観点

- 初期表示（既定値・文言の i18n キー・クラス）
- 開閉（トリガー・外側クリック・Esc・背景クリック・閉じるアニメーション後に消える）
- 選択・入力（値変更の通知、クリア、全選択・中間状態）
- キーボード操作（矢印・Enter・Esc）
- 無効状態・読み込み中
- 並べ替え・ページ送り（URL のクエリ）
- モバイルのボトムドロワー
