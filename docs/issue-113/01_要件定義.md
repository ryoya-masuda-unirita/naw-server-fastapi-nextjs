# 01_要件定義

## 背景

- アシスタント削除API（`DELETE /api/admin/assistants/{assistant_id}`）は、削除対象アシスタントがいずれかのルームのデフォルトアシスタント（`rooms.default_assistant_id`）として使用中の場合、DB側のFK制約（`ON DELETE RESTRICT`）違反により `IntegrityError` が発生する
- 現状のFastAPI実装はこの `IntegrityError` を捕捉し、HTTP 400 Bad Requestとして返している
- 移植元（Spring Boot）では同じ状況をHTTP 409 Conflictとして返しており、意味的にも「使用中のリソースを削除しようとした」ことを表す409のほうが適切
- issue-42実装当時はRoomドメイン自体が未移植だったため、この409判定は意図的にスコープ外とされていたが、Roomはissue-45で移植済みのため前提が崩れている

## 機能要件

- アシスタント削除時、いずれかのルームのデフォルトアシスタントとして使用中の場合、HTTP 409 CONFLICTを返す
- レスポンスのエラーメッセージは移植元 `AssistantInUseException.MESSAGE` の文言「このアシスタントはルームのデフォルトアシスタントとして使用されているため削除できません」に揃える
- 上記以外の理由（存在しない、権限なし等）によるエラーレスポンスは現状の挙動を変更しない

## 非機能要件

- 既存の回帰テスト（PR #115 で追加された、メッセージが削除されず `assistant_id` が `NULL` になることを確認するテスト等）に影響を与えない
- `rooms.default_assistant_id` のFK制約（`ON DELETE RESTRICT`）は変更しない

## スコープ外

- Room・Message以外のドメインでアシスタントを参照している箇所の409化（現状 `rooms.default_assistant_id` 以外に該当するFK制約は存在しないため対象外）
- フロントエンド（`frontend/` React移植）側の対応
