# 02_基本設計

## 変更対象

- アシスタント削除サービス処理（バックエンドのみ、`backend/`）

## 画面 / API 変更概要

- `DELETE /api/admin/assistants/{assistant_id}` のレスポンス
  - 変更前: デフォルトアシスタントとして使用中の場合 400 Bad Request
  - 変更後: デフォルトアシスタントとして使用中の場合 409 Conflict
  - エラーメッセージを移植元の文言に統一する
  - 存在しない場合の404、正常系の204は変更なし

## 影響範囲

- 削除APIを呼び出すフロントエンド（`frontend-angular/`）側のエラーハンドリングに影響する可能性があるが、本Issueのスコープはバックエンドのみ。フロントエンド対応要否はユーザーに確認する
- 既存の統合テスト（`test_delete_assistant_returns_400_when_used_as_default_assistant_of_room` 等）の期待値更新が必要

## 移植方針

- 移植元 `AssistantService.delete`（`DataIntegrityViolationException` → `AssistantInUseException` → 409）と同様の構造を、FastAPI側は例外クラスを新設せず `HTTPException(status_code=409, detail=...)` を直接送出する形でシンプルに移植する（既存の `delete_assistant` の実装パターン踏襲）
- docstringの「room未移植のため409は行わない」という記述を削除し、実装済みである旨に更新する
