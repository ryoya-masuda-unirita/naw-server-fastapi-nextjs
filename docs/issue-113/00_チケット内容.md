# #113 issue-113 アシスタント削除時、デフォルトアシスタント使用中なら409を返す

## 概要

アシスタント削除時、いずれかのルームでデフォルトアシスタントとして使用中の場合、移植元と同様にHTTP 409 CONFLICTを返すよう修正する。

## 説明

issue-42（アシスタント管理API）実装当時はRoomドメインが未移植だったため、削除時の409判定は意図的にスコープ外とされていた。しかしRoomは既にissue-45で移植済み（`backend/app/models/room.py` に `default_assistant_id` あり）で、前提が崩れたまま放置されている。

- 移植元: `~/Documents/naw-server/src/main/java/com/example/naw/service/AssistantService.java`（`delete`メソッド, L287-294）が `DataIntegrityViolationException` を捕捉し `AssistantInUseException` を投げ、`APIControllerAdvice.java`（L112-117）でHTTP 409 CONFLICTにマッピングしている
- FastAPI側: `backend/app/services/assistant_service.py` の `delete_assistant` は `IntegrityError` をHTTP 400として返しており、docstringに「room（チャット本体）ドメインが未移植のため...409はここでは行わない」と明記されたまま

## その他

- 関連Issue: #42（スコープ外節を参照）
- 参照調査: `docs/調査結果/20260711.md`（5章3項目）
- 移植元エラーメッセージ: `AssistantInUseException.MESSAGE` = 「このアシスタントはルームのデフォルトアシスタントとして使用されているため削除できません」
