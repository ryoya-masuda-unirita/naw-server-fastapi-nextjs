# 02_基本設計

## 変更対象

- グループAPI（プロンプトテンプレート紐付け関連の3エンドポイント）
- グループ×プロンプトテンプレート中間テーブルに対するリポジトリ（グループ起点のクエリ）

## 画面 / API 変更概要

| メソッド | パス | 概要 |
|---|---|---|
| POST | `/api/admin/groups/{groupId}/prompt-templates` | 指定プロンプトテンプレートをグループに一括追加（204） |
| DELETE | `/api/admin/groups/{groupId}/prompt-templates/{templateId}` | 指定プロンプトテンプレートをグループから除外（204） |
| GET | `/api/admin/groups/{groupId}/prompt-templates` | グループに紐づくプロンプトテンプレート一覧をページネーション取得（200） |

一覧レスポンスの各要素には紐付け日時（`addedAt`）を含める。デフォルトソートは `addedAt,desc`（Angular側の初期状態に合わせる）。

## 影響範囲

- 中間テーブルのモデルは既存の `GroupPromptTemplate`（`app/models/prompt_template.py`）をそのまま利用し、新規モデル追加は不要
- グループAPIルーター・サービスに新規エンドポイント/メソッドを追加
- リポジトリにグループ起点のクエリメソッド（一覧・単体取得・追加・削除）を追加

## 移植方針

- レイヤー構成・実装パターンは既存のグループ×ユーザー紐付け（`add_group_users`/`remove_group_user`/`list_group_users`）を踏襲する
- 権限チェックは既存の `GroupService._assert_can_manage_group`（テナント管理者 or グループ内管理者）をそのまま再利用する
- レスポンススキーマは既存の `PromptTemplateResponse` に `addedAt` フィールドを追加して流用する（新規スキーマは作らない）
- 検索は名前・説明の部分一致（既存の `PromptTemplateRepository._apply_search` と同様のLIKE検索）
- 一覧取得はテンプレートと中間テーブルをJOINして1クエリで取得し、N+1を避ける
