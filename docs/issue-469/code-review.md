## 詳細

### 1. 複数の worker（🔴 重要）→ 対応済み

起動の前に、そのポートの `/version` が応答するかを確かめ、応答すれば、起動せずに借りる（`_borrowed`）。借りた先が落ちて、呼び出しが失敗したら、借りた状態を戻し、次の呼び出しで、自分で起動する。本番の `CMD` は、`uvicorn` を 1 つだけ動かす設定で、この状況は、通常は起きない。テストを 2 件足した。

### 2. ステータスの区別（🔵 提案）→ 対応済み

422（解析できない文書）と 415（未対応の形式）は、ファイルの問題として 400。Tika の 5xx（子の JVM のメモリ不足など）は 502、接続の失敗・起動の失敗・設定がない場合は 503 に変えた。モニタリングで、ファイルの問題と、インフラの障害を、区別できる。

### 3. ファイル名の渡し方（🔵 提案）→ 対応不要

実際の Tika（3.1.0）で、`filename*=UTF-8''…` を `resourceName` に正しく読み、日本語のファイル名が復元されることを、確かめた。

### 4・5. 終了処理と状態（🔵 提案）→ 対応済み

`lifespan` で、リスナーを止めたあと、`finally` で `TikaClient.shutdown()` を呼ぶ。`shutdown` が、ロックと借りた状態も初期化する（次のイベントループで作り直す）。

### 6・7. 対応不要

`ruff check` は通っている。無関係のファイルは、コミットしていない。
