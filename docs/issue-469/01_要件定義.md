# 01_要件定義

## 背景

学習データの登録は、ファイルから本文を取り出し、分割・埋め込み・保存する。移植元は、取り出しに Apache Tika を使い、PDF・Office 文書などに対応する。移植先は、テキスト系だけ。

## 機能要件

| No | 要件 |
|---|---|
| F1 | サーバーのコンテナに、JRE と Tika 3.1.0 のサーバーの jar を入れる。jar は、ビルドのときに取得し、固定した SHA-512 で検証する（実行時のダウンロードはしない） |
| F2 | 設定 `TIKA_SERVER_JAR`（jar のパス）があるとき、サーバーが、必要になったときに（遅延起動）、同じコンテナの中で、`127.0.0.1` に jar を子プロセスとして起動する。起動を待ち、複数のリクエストが同時に来ても、1 回だけ起動する |
| F3 | 設定 `TIKA_URL` があるときは、そのサーバーを使う（子プロセスは起動しない） |
| F4 | `TIKA_SERVER_JAR`・`TIKA_URL` のどちらもなければ、今のテキスト系の取り出しにする（既存の環境は変わらない） |
| F5 | Tika が使えるときは、すべての形式を Tika で取り出す（`PUT /tika`、本文は `text/plain`）。ファイル名と Content-Type を渡し、形式の判定は Tika に任せる |
| F6 | Tika の失敗（起動できない・応答しない・解析できない・未対応の形式）は、分かるメッセージで 400 にする。ファイルの中身やパスは、メッセージ・ログに出さない |
| F7 | 子プロセスが落ちたとき、次のリクエストで、起動し直す。アプリの終了時に、子プロセスを止める |
| F8 | JVM のヒープに上限を付ける（既定 256MB、設定 `TIKA_HEAP` で変えられる） |
| F9 | 取り出した本文が空のときは、従来どおり、ファイルの記録だけを作る |
| F10 | ローカルの docker compose（`Dockerfile.dev`）でも動く |

## 非機能要件

- Tika を使わない環境（設定なし）で、既存のテストの結果が変わらない
- 外部通信（Tika のサーバーへの HTTP）は、テストでは、モックの通信で行う。実機の確認は、実際のコンテナで行う
- 追加する関数に、日本語の NumPy 形式の docstring を書く。テストのメソッド名は英語、意図は日本語の docstring

## スコープ外

- 画像解析（画像を LLM で説明する機能）、PDF の代替抽出
- 本番のインフラ（`secuaigent-infra/`）のメモリ・CPU の見直し（影響を、PR に書く）
